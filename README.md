# 編成プロトタイプ

「捨てられた駒に役割を与えて噛み合わせる」が面白いかどうかだけを確かめるための実験装置。
グラフィックも演出も無い。確認したいのは編成の手応えだけ。

## 主の物差しは単発戦（2026-08-27・第15期）

**基本（メイン）は単発戦。会戦もありえる、というくらいの位置づけ。**

これは第5期以降の枠組みの位置づけを変える。**捨てないが、主ではなかった。**

**代金（払った HP の割合）は、会戦でしか意味を持たない。** 単発戦では HP が毎回リセット
されるので、90% 削られて勝つのと 20% で勝つのは同じ価値になる——**代金という概念そのものが
成立しない。** 第5〜9期はその代金を物差しにして波を作り、第12〜14期はその会戦の突破度に
対して「地力」を分解していた。

| 期 | 内容 | 単発が主なら |
|---|---|---|
| 第1〜4期 | 会戦の機構（`EngagementEngine` ほか） | オプションモードの土台として残る |
| 第5〜8期 | 代金の向き（範囲/単体） | **会戦専用** |
| 第9期 | 自傷率と代金 | **会戦専用** |
| 第10〜11期 | 行動パターン・チャージ | **単発でも効く**（勝敗に直接効く） |
| 第12〜14期 | 突破度に対する地力の分解 | **会戦専用の目的変数**に対する分解だった |

裏付けもある。**単発戦の平均勝率と突破度の相関は 主 r 0.15 / 従 r 0.33 しかない**
（第14期 Phase EB）。会戦で測っていた序列は、単発戦の序列とほとんど別物だった。

### 単発が主なら、狙うものが変わる

出発点は「波が易しすぎる」だった。会戦はその答えの一つとして始まったが、単発が主なら
別の答えが要る。狙うのは配分判断ではなく:

> **波によって最適な編成が違うこと（編成 × 波の交互作用）**

「この波にはこの編成」が成立すれば、それだけで編成パズルになる。第6〜8期がずっと探していた
「向き」は、**突破度ではなく波ごとの勝率に対して測るべきだった。**

第15期の測定（`wave`）の答えは **交互作用は実在する。ただし何が起こしているかは分からない。**
詳細は「検証で分かったこと」の第15期の4項。

## 構成

    BattleCore/     戦闘ロジック。UI を一切参照しない
    BattleSim/      コンソール総当たりシミュレータ（Windows以外でも動く）
    PrototypeApp/   WPF。編成を組んで結果を眺めるだけ
    docs/           BattleSim が吐く生成物。手で編集しない

BattleCore は net8.0 の素のクラスライブラリで、
INotifyPropertyChanged も ObservableCollection も入っていない。
本番を Godot / Unity にする場合も、このプロジェクトはそのまま参照できる。

**ここにだけは戦闘ルールを書かないこと。** ViewModel やコードビハインドに
ダメージ計算が漏れた瞬間に移植できなくなる。

## 動かす

    dotnet run --project PrototypeApp        # 編成UI（Windows）
    dotnet run --project BattleSim -c Release 1   # 総当たり（引数はステージ番号 0-4）

## 特性を足すには

Traits.cs で Trait を継承し、TraitId に列挙子を足して TraitCatalog に登録する。
特性はすべて「イベントに反応するハンドラ」なので、
意図していない組み合わせでも勝手に噛み合う。そこが狙い。

    public sealed class ThornsTrait : Trait
    {
        public override TraitId Id => TraitId.Thorns;
        public override void OnDamaged(BattleContext ctx, UnitState self, int dmg, UnitState? src)
        {
            if (src is not null) ctx.ApplyDamage(src, dmg / 3, self);
        }
    }

### 勝率だけでは見えないものを測る（`chain` / `ablate`）

`compare` の勝率だけでは「2枚で人並みに勝つ編成」と「5枚が畳みかけて無双する編成」が
同じ100%に見える。この2つの道具は勝率とは別の軸を測る。

    dotnet run --project BattleSim -c Release 0 chain > docs/chain.md
    dotnet run --project BattleSim -c Release 0 ablate [絞り込み] > docs/ablation.md

`chain` は「1ターンで味方が何体倒したか」の最大値（連鎖深度）と、勝利した試行だけの
決着ターン数を編成ごとに出す。同じ勝率でも連鎖深度が高いほど「畳みかけている」。

`ablate` は編成からメンバーを1体ずつ抜いて勝率の下がり方を見る。差が大きいほど
「そのメンバーが強さの源」、差がほぼ0またはプラス（抜いたほうが勝率が上がる）なら
入れ得の疑いがある。絞り込みは `reseat` と同じ書式（カンマ区切りの部分一致）。
全編成だと30秒前後かかるので、勝率表では判断がつかない場面（差し替え候補の勝率が
拮抗している、「消してはいけない」判定の根拠を疑いたい）で個別に回す。定型の
バランス調整フロー（CONTRIBUTING.md）には含めていない。

### 編成の出力は受け手側から測る（2026-08-26・第13期）

**これは `power` の話ではなく、今後の計測すべてに効く原則。**

味方の `UnitTally.DamageToEnemy` / `Kills` を合計すると、**帰属を持たない削りが丸ごと落ちる。**
`TickStatuses` は `ApplyDamage(u, poison, null)` と source を渡さずに呼ぶので、
毒・燃焼のダメージは `ApplyDamage` の `source is not null` 分岐にも
`HandleDeath` の `killer is not null` 分岐にも入らない。誰の手柄でもないので誰にも付かない。

**敵側から数えれば穴が塞がる。** どの経路で削っても敵の `DamageTaken` には必ず載る。

    与ダメ = 敵全員の DamageTaken − 敵の TakenFromAlly   （後者は敵同士の巻き込み）
    撃破   = 敵の死亡数（誰が仕留めたかを問わない）

実測でどれだけ落ちていたか（チャージ台・31編成・seed 200）:

| 編成 | 与ダメ 旧 → 新 | 撃破 旧 → 新 |
|---|---|---|
| 毒 (グザ×ミオ×ラウ) | 33 → 187（**×5.66**） | 0.94 → 3.00（**×3.20**） |
| 毒+ベニ+ラウ | 61 → 222（×3.63） | 1.33 → 3.85（×2.89） |
| 毒+耐久 (ベニ×トウ) | 38 → 127（×3.38） | 0.98 → 3.05（×3.12） |
| 澱み喰い (グザ×ヴィオ) | 122 → 225（×1.84） | 2.36 → 3.62（×1.54） |
| （非毒軸の20編成） | ×1.00 | ×1.00 |

**`BattleCore` は1行も触っていない。** 毒の出どころを `UnitState` / `StatusKeys` に
持たせて駒単位の帰属を復元する案は採らなかった——「部隊で協力して撒いて拡散して濃くする」が
コンセプトなので**駒単位の帰属は粒度が細かすぎる**（編成単位で足りる）し、
直せば `pulse` の表が動く。エンジンではなく読み方を変えるほうが安い。

読むときの2つの注意:

- **過剰殺傷（オーバーキル）を含む。** HP は 0 で止まるが tally は振り切った量を数える。
  味方側の `DamageToEnemy` も同じ行で同じ `amount` を足しているので**新旧で扱いは変わらない**。
  `与ダメ効率 = 与ダメ ÷ 撃破` はオーバーキルの指標なので、過剰分が入っているほうが正しい。
- **`干渉`（`Interventions`）には受け手側の対応物が無い。** あれは「誰が起点になったか」を
  数える量なので、出どころを持たない毒は原理的に載らない。**`docs/pulse.md` の毒軸の
  `干渉` の行は依然として過小**で、そこだけは穴が残っている。

検算は `power` の出力に出る（敵の `TakenFromAlly` の総和 0 / 勝った部隊戦で敵の死亡数が
投入数と合わなかった件数 0 / 味方と敵の `Def.Id` 衝突 0 件）。**3つとも 0 でなければ、
受け手側から数えるという方法そのものが成立していない。**

### 相関を読む前に、半割で「上限」を測る（2026-08-26・第13期）

**台間の相関が 1.00 未満でも、それだけでは何も言えない。** 乱数のばらつきだけで 1.00 は割る。
「どれくらいなら動いたと言えるか」の基準がいる。

**同じ台を seed で半分に割り、両半分で編成の序列の相関を取る。** これが「同じ条件を2回
測ったときの一致度」＝**測定の信頼性の上限**で、どんな比較もこれを超えられない。

    dotnet run --project BattleSim -c Release 0 bench

割り方は2通り出す（前半後半 = seed 0..99 / 100..199、および偶奇）。片方だけだと、
`DeriveSeed(seed, battleIndex)` の作り方に構造があったときに半割の値そのものが嘘になる。
半割は 100 seed 同士なので 200 seed の測定より一致度が低く出る——Spearman-Brown の
補正 `r(2n) = 2r(n) / (1 + r(n))` を掛けた値を「200 seed 相当の上限」として併記してある
（補正は「両半分が同等・誤差が独立」を仮定するので、生の値も必ず併記する）。

**実測の上限（突破度・31編成・seed 200・補正後 ρ）は 0.991〜0.997。**
seed 200 で編成の序列はほぼ完全に再現する。**この 0.99 が、第4期以降の順位相関を
読み直すときの物差しになる**——0.83〜1.00 の壁は、上限 0.99 に対しての値だった。

`余地 = 上限 − 実測の相関` が、**測定のばらつきでは説明できない入れ替わりの量。**

### 同語反復を候補から外す基準（2026-08-27・第14期）

**`power` に特徴量を足すときは、まずこの基準を通す。** 通していない特徴量が上位に来ると、
発見ではなく算術を発見と読むことになる（第13期の `撃破/戦` r² 0.90 で実際にやった）。

基準は「**突破という結果の言い換えになっていないか**」の**1本だけ**。
**「信頼できるか」を混ぜてはいけない**——混ぜると基準が二重になり、次に特徴量を足すときに
使えなくなる。`干渉/戦` は毒軸で構造的に過小だが、それは信頼性の問題なので候補には残してある。

言い換えが入り込む経路は2つある。

| 経路 | 中身 | 外すか |
|---|---|:-:|
| **分子経路** | 量そのものが突破の定義に含まれる（部隊を全滅させる＝その部隊を突破する） | **外す** |
| **分母経路** | 味方1部隊では `部隊戦数 = 突破数 + 1`。`/戦` の量はすべて「目的変数 + 1」で割っている | 残す |

**外すのは分子経路だけ。** 分母経路は平均を取る操作であって、量の中身を突破の写しに
変えるわけではない。**比**（`自傷率`・`与ダメ効率`）は分子分母が同じ部隊戦数で割られるので、
**分母経路が丸ごと打ち消える**。静的特徴量はどちらの経路も持たない（戦わずに決まる量なので）。

分母経路が実際にどれだけ目的変数を運んでいるかは、**言い張らずに測って出す**（`power` の検算）。
`部隊戦数 ÷ 試行` を突破度に当てると 主 r **+0.72** / 従 r **+0.89**——恒等式なので当然だが、
**各特徴量と分母の相関は最大でも −0.50**（`与ダメ効率`・従）で、分母が特徴量を支配してはいない。

判定の例（第14期の実測）:

| 特徴量 | 判定 | 理由 |
|---|:-:|---|
| `撃破/戦` | **除外** | 分子経路。全抜きした編成の値は 13 ÷ 3 = 4.33 に固定される。測定ではなく算術 |
| `与ダメ/戦` | **除外** | 分子経路。敵の総HPを削り切ることが突破。突破度の小数部も分子そのもの |
| `被ダメ/戦`・`回復/戦` | 残す | 分母経路だけ。分子（殴られた量・回復した量）は突破の定義に入らない |
| `自傷率` | 残す | 比なので分母経路が打ち消える。分子は味方同士の削り |
| `与ダメ効率` | 残す | 比。**台で符号が反転する**（主 +0.49 / 従 −0.49）——言い換えなら反転しない |
| `干渉/戦` | 残す | 分子は「誰が起点になったか」。過小なのは信頼性の問題で、基準を混ぜない |
| 静的8種 | 残す | 戦わずに決まるので、どちらの経路も持たない |

判定表と検算は `dotnet run --project BattleSim -c Release 0 power` の出力にある。

### 編成 × 波の交互作用を測る（`wave`・2026-08-27・第15期）

**単発戦が主の物差しになったので、波の評価も単発の勝率でやる。**

    dotnet run --project BattleSim -c Release 0 wave [絞り込み]

既存5波 + 第5〜10期に診断のローカルへ散らばっていた候補波 34 を**1箇所に集めてある**
（`wave` モードの `waves` 配列がその1箇所）。`EnemyCatalog.Stages` / `Columns` には足していない
——採用が決まっていない波をカタログに入れると `compare` / `dump` が動いて `docs/` に差分が出る。

集め方が写しになっていることは**毎回検算する**。`MeasureCost` を同じ関数のまま呼び直して、
`gradient` / `aim` / `flip` / `bridge` が出す 代金・向き・ターン数 と突き合わせる
（ずれ 0 件でなければ写し間違い）。

**評価に寄与しない波を先に落とす。**

| 指標 | 意味 |
|---|---|
| **天井率** | 勝率 100.0% の編成数。同値塊なのでその中の編成は区別できない |
| **床率** | 勝率 0.0% の編成数。同じく同値塊 |
| **残存度** | 全試行の平均（生存数 ÷ 出撃数。負けた試行は 0）。**天井で潰れない連続量** |

線は「天井率 + 床率 < 50%」に置いてあるが、**これは測定から出た線ではない**ので、
生の天井・床の数字を同じ表に併記して、線を引き直せるようにしてある。

判定は §2-4 の3行から**数字で機械的に選ぶ**（`bench` と同じ作法）。天井・床の扱いで
結論が変わりうるので、**3通り全部を出す**——(a) 半割が計算できた波・勝率、
(b) 寄与する波だけ・勝率、(c) 全波・残存度。

> **(a) の読み方は当てにならない。** 天井の波は順位がほぼ全部同値塊なので、半割 ρ が
> 1.00 に張り付き、他の波との ρ は同値塊のせいで 0 付近まで落ちる。結果として
> `余地` が 1.0 を超える——**上限を超えて一致しない**という意味不明な値になる。
> (b) を置いてあるのはこのため。

半割（測定の信頼性の上限）は**第13期の 0.99 を借りずに測り直す**。目的変数が突破度から
勝率に変わっているので、上限も変わりうる（実測: 補正後 ρ の中央値 0.987）。

## 仕込んである噛み合わせ

- ボルグ（巻き込み） × ムド（被弾強化）……隣接スロットに置くと事故が燃料に変わる
- セロ（後衛特化＋臆病）……戦闘中に一度後退してから後列にいると攻撃力が2倍になる（最初から後列に置いても発動しない）
- ネル（呪詛漏れ） × ガルド（支援拒否）……漏れは味方全体に及ぶが、ガルドだけは受け付けない（隣接は関係ない）
- リィカ（墓守） × ムグ（分裂） × ヴェル（蘇生） × ゴルム（壁）……死を回し続けて積み上げる。
  短期決戦では間に合わないが、長期戦のステージでは最上位になる

## 調整メモ

- 継ぎ接ぎのヴェル: 代償は「蘇る側」ではなく「蘇生する側」が払う。
  蘇生される駒が弱体化するだけでは編成にとってのコストにならない。
  さらに同じ駒は二度縫えない（`sewn` カウンタ）。この制限が無いと、
  蘇生は死亡時効果を持つ全ての駒にとって唯一の正解になる。
- 墓守リィカ: 層は毎ターン1つ減衰する。放っておいても味方はいずれ死ぬので、
  減衰が無いと墓守は無条件に伸びてしまう。
- 爆ぜるゾト: 固定ターンではなく「倒れたとき」爆発。味方も巻き込む。
  どれだけ早く死なせるかがプレイヤーの操作対象になる。
- 会戦（Engagement）: 部隊戦（Battle）を連結し、勝った側は生存駒の状態を持ち越して
  次の部隊と戦う（`EngagementEngine`、判断の全文は design/ENGAGEMENT_PLAN.md）。
  持ち越すもの: HP・最大HPの損耗・蘇生回数（charges/sewn）・墓守の層（境界で1減衰）・
  下がった実績（HasFallenBack）と終了時のスロット。境界で消えるもの: 状態異常の
  全カウンタ（`StatusKeys.All`）と `AtkBonus`——恒久と一時が同じ int に混ざっていて
  分離できないので一律 0 にし、恒久分は各特性の `Trait.OnCarryOver` が再構成する。
  戦闘中に湧いた駒（胞子）は持ち越さない（儚い）。敵の部隊列は既存5波をそのまま
  並べたもの——新しい敵を作らず、持ち越しの効き目だけを測るため。
  仮置き（引き分けは味方が退く / 墓守の境界減衰は1層 / 境界回復なし）の見直し条件は
  design/ENGAGEMENT_PLAN.md §3.2。

## 状態異常・反撃の足しかた

毒は `StatusKeys.Poison` カウンタで持ち、`BattleContext.TickStatuses` が
ターン開始時にまとめて処理する。新しい状態異常はキーを1つ足して
TickStatuses に処理を書けば、特性側は「カウンタを積む」だけでよい。
キーは `StatusKeys.All` にも必ず足すこと（会戦が部隊戦の境界で消す一覧。
漏らすとその状態異常だけが会戦を跨いで持ち越される）。

燃焼（`StatusKeys.Burn`）は毒と対になる形で、**カウンタが「量」ではなく「残りターン」**。
固定量・非スタックなので、特性側はカウンタを直接触らず `ctx.Ignite(...)` を呼ぶ。
再付与を「加算」ではなく「持続のリセット」にする意味をここに閉じ込めてある。
規則は `BurnRules`（ダメージ量と持続ターン）。

反撃は `ctx.Reaction(...)` で包む。包まないと反撃が反撃を呼んで無限に落ちる。

## ログの色

`LogLine` は `LogKind` を持つ。UI は種類で色を引くだけで、文字列は一切解析しない。
新しい種類を足すときは `LogKind` に列挙子を追加し、
`MainWindow.xaml.cs` の `Palette` に1行足す。

見せ場（`Highlight` = 破裂・覚醒）だけを明確に浮かせ、
それ以外は静かに保つこと。全部が目立つと何も目立たない。

2箇所に置くと必ず片方が腐るため（この節には長らく8編成分の古い表が残っていて、
コード側に24編成あることに誰も気付かなかった）。

### 勝率表は「配置を固定した値」であることに注意

    dotnet run --project BattleSim -c Release 0 layout > docs/layout.md

`compare`（勝率表）は編成ごとに**ひとつの配置に固定**して全波を通した数字で、
その配置は全波平均を最大化するように選んである。実プレイは波ごとに組み替えられるので、
**苦手な波の勝率は「その編成の限界」ではなく「平均最良の配置がその波で出した値」にすぎない。**
この差を読み違えると「勝率表は54%なのに手元では勝てる／勝てない」という混乱になる。

`layout` は各編成をメンバー固定のまま全配置に展開し、平均最良の上位と現行配置に加えて、
**波ごとの最良配置**も出す。ある波の勝率が低いとき、それが編成の限界なのか配置の都合なのかは
そちらの表で判断する。探索は seed 50 で行い、**選ばれた配置は seed 200 で測り直してから載せる**
（720通りの最大値をそのまま報告すると、運の良かった配置を実力と読んでしまうため）。

同じく、ユニット・特性・ステージの一覧は [docs/units.md](docs/units.md)。

    dotnet run --project BattleSim -c Release 0 dump > docs/units.md

どちらも BattleSim の出力そのものなので、手で編集しない。
更新手順は [CONTRIBUTING.md](CONTRIBUTING.md) を参照。

## 検証で分かったこと

- 積み上げ系（墓守）が必要とするのは戦闘の「長さ」ではなく「死の密度」。
  層が毎ターン減衰する以上、敵の火力が低い長期戦では逆に立ち上がらない。
  第四波（硬いが一撃が軽い）でリィカは 14.1% しか出なかった。
- 定数デバフ（呪詛）は敵の攻撃力が低いほど相対的に強くなる。
  第四波で呪詛官ネルが 57.3% と突出。割合デバフに変えるか、ステージ側で調整が要る。
- 範囲攻撃の値は「敵の数 × 値」で評価する必要がある。
  ゾトの破裂は20だが、敵5体なら実質100。
- ステージの難易度は敵の攻撃力で調整し、HPでは調整しない。
  敵HPを上げると、勝ち切れる編成と勝ち切れない編成に二極化して全滅が急増した
  （HP1.4倍で全滅14編成）。攻撃力を上げた場合は勝率が連続的に下がるため、
  中間帯を残したまま難易度を上げられる。
- ステージの良し悪しは平均勝率ではなく分布で見る。
  通過3〜6・中間4以上・全滅8以下を目安にする。平均だけ見ていると
  「4編成が100%で残りが全滅」という判別力ゼロの構成を良判定してしまう。
- 攻撃パターンを4種すべて含めると、単体前提の防御（庇う・標的）に頼る編成が自然に落ちる。
  第五波はこの形で作っている。
- **貫きは前列の数だけ威力が落ちる。** 減衰が無いと、前列を並べることが貫きに対して
  何の意味も持たない。ただしこの規則は味方の狙撃にも等しくかかるので、
  逃亡兵セロの火力に依存していた編成（耐久・毒→被弾強化・隊列崩し・突き出し）は
  まとめて弱くなる。これは想定内で、**「3体の壁越し」に後列を撃ち抜けることが
  そもそも強すぎた**、という判断。
- **後列を守る手段は「庇う（単体限定）」とは別に用意する必要がある。**
  `RearGuard` は薙ぎ・全体には割り込むが、レーン化した貫きには割り込めない
  （貫きは標的選択を通らずレーン単位で解決される）。貫きへの防御は
  「レーンを深くして減衰させる」という配置側の手段に移った。
  攻撃パターンを増やすなら、そのパターンに対する防御手段を同時に用意しろ。
  片方だけ増やすと系統が消える。
- **純粋な防御役は編成の火力を殺す。** `RearGuard` 単独・攻撃3で試すと、
  守っているのに勝率が落ちる（26.0% → 12.0%）。被弾強化を併せ持たせて、
  耐えるほど打点が育つ形にして初めて成立する。
  分かちのドハで同じ失敗を一度している。**耐久役には必ず見返りの経路を付けろ。**

- **非スタックの状態異常は、変換役が読むものを変えないと成立しない（2026-08-22、測定済み）。**
  燃焼（固定量・非スタック・持続3ターン）を足した。毒の変換役が実際に何を読んでいるかを見ると、
  ヴィオ・ラウは**量**（層の数）、ベニ・ミオは**数**（毒を負った駒の数）で、どちらも燃焼には無い。
  燃焼は層を持たないので量が存在せず、**数を読む形にするとミオと同じ穴**（撒き役がいる時点で
  飽和し、出力が「ボルグがいるかどうか」だけで決まる）に落ちる。

  残るのは時間・事象・自分の状態で、熾火（ホタ）は**自分の状態**を読む型にした。
  自分では着火できず、ボルグの火の粉は隣接した味方にしか移らないので、
  **ボルグの隣に置くことが発動条件そのもの**になる。庇い・後備えの「配置でマイナスが消える」の逆で、
  配置で条件を取りにいく形。

  | | 第1〜5波 |
  |---|---|
  | 燃焼 (ボルグ×ホタ) | 100/100/98.0/81.0/48.0 |
  | 同じ編成でボルグをゴルムに差し替え | **100/0/0/0/0** |

  着火役を外すと第2波から全滅する。**入れ得の正反対で、依存は絶対。**
  reseat の上位20配置すべてがホタをボルグの隣に置いており、非隣接は一件も残らなかった。

  火の粉をボルグに持たせた副作用として、ボルグを含む既存2編成も動いた。波及はこの2つだけ。

  | 編成 | 前 | 後 |
  |---|---|---|
  | 速攻 (ボルグ×ムド) | 100/94.0/96.5/100/27.5 | 100/99.5/99.5/100/33.0 |
  | 毒→被弾強化 (グザ×ムド) | 100/95.0/40.0/0/0 | 100/98.5/57.0/0/0 |

  燃焼ティックは `source` を持たない（`ApplyDamage(u, dmg, null)`）ので、
  被弾強化（ムド）は毒ティックと同様に反応する。**「ボルグの火でムドを育てる」という
  当初の着想はそのまま動く**が、第4波以降が 0% のままなのは前回記録したグザの非減衰毒が原因で、
  燃焼を足しても解けない。

- **状態でゲートする定数の見返りは、累積するコストに必ず負ける（2026-08-22、測定済み）。**
  熾火の初版は「燃えている間だけ攻撃力4倍」だけの形で、第1〜3波は 100/99.5/87.0 と通るのに
  **第4波が 11.0%** だった。ホタは毎ターン 燃焼6＋巻き込み9＋敵の攻撃 を払うが、
  見返りは攻撃24の**定数**。コストは戦闘が長いほど積み上がり、見返りは伸びないので、
  硬くて長い第四波では比が必ず負ける。第4波の4ターン目に落ちていた。

  同じ巻き込みを浴びるムドが成立しているのは、払った分が**永続加算**になるから。
  「積み上げは積んだ量に比例するコストを持つべき」の裏返しで、
  **累積するコストには、伸びる見返りか、伸びない代わりに広がる見返りを付ける必要がある。**

  燃えている間は攻撃が薙ぎに変わる（火は広がる）形にしたら第4波 11.0% → 81.0%。
  倍率を単に上げるのではなく出口の幅を変えたのは、第四波が重装兵3枚を横に並べる波で、
  単体火力を膨らませるより届く枚数を増やすほうが「炎」として素直だったため。

  倍率の感度は急峻で、着地帯は狭い。

  | `PyreTrait.Multiplier` | 燃焼 (ボルグ×ホタ) 第1〜5波 |
  |---|---|
  | 3 | 100/100/93.5/40.0/18.5 |
  | **4（採用）** | **100/100/98.0/81.0/48.0** |
  | 5 | 100/100/99.5/99.0/69.5 |

  ×5 は第4波99%・第5波69.5%で全30編成中3位になり、新軸が既存を押しのける。×3 は第4波40%で
  軸として立たない。**×3 と ×5 の間で第4波が 40 → 99 と動く**ので、ここは数値ではなく
  出口の形（薙ぎ化）で調整したほうが安全な帯。

  この表は旧配置（前1ガルド/前2ホタ/前3ムド/中ボルグ/後1ノノ）で振ったもの。
  配置を確定した後の ×4 は 100/100/100/83.0/60.0 で、表の値とは一致しない。
  倍率の相対比較として読むこと。

- **`confirm` の差が閾値ぎりぎりに乗ったら、もう1本別の seed 帯で確かめる。**
  燃焼 (ボルグ×ホタ) の配置差し替えは seed 200..599 で +2.1pt と、2pt の線を 0.1pt しか
  超えなかった。seed 600..1399 の800試行でも +2.3pt・内訳（第4波 -3、第5波 +13）まで
  同じ形で再現したので採った。**差の大きさではなく、波ごとの内訳が再現するかで見る。**
  平均だけ見て通すと、たまたま同じ平均に着いた別物を採ってしまう。

- **非スタックの状態異常は、撒き役1枚で供給が飽和する。2枚目の火種は0ダメージ。**
  燃焼軸の2枚目として「味方に燃え移る火を引き取り、燃えている間は攻撃した相手に着火する」
  駒（燠喰いのガイ）を作って測ったが、第4波 0.5% で成立しなかった。ログを追うと理由は明快で、
  **味方は全員おおむね同じ敵（前列）を殴るので、2枚目が着火する相手はすでに燃えている。**
  非スタックなので再着火は持続のリセットにしかならず、追加ダメージはゼロ。
  着火を本業にした駒は、engine の「攻撃1回につき特性は1度・主目標のみ」と合わせて
  出力が構造的に0に張り付く。**火種が「本業のついで」でしか成立しないのはこのため**で、
  ボルグが機能しているのは薙ぎ18の副産物として撒いているから。
  敵の数が増えて狙う先が割れるまで、この軸の供給役は1枚が上限。

- **燃焼軸の受け皿は「加算で伸びる型」では間に合わない（測定済み・3案とも没）。**
  ターン開始時に隣接する味方の火を奪って攻撃力を加算する案は、獲得量を3→6→10と振っても
  第4波が 0.0 → 2.0 → 6.5 しか動かなかった。係数ではなく構造の問題で、
  **コストを1ターン目から線形に払い、収入を2ターン目から線形に得るので追いつかない。**
  さらに収入源は「燃えている味方」で、その味方は燃えているぶん先に落ちる。
  ホタが成立しているのは見返りが初手から大きい定数（×4＋薙ぎ）だから。

- **`OnTurnStart` で状態異常を取り上げても、肩代わりにはならない。**
  ターンの進行は tick（燃焼ダメージ）→ `OnTurnStart` → 行動 の順なので、
  味方はその ターンぶんを払い切ってから火を取り上げられる。撒き役が毎ターン点け直す限り
  味方の出血は1点も減らず、取り上げた側のぶんが上乗せされるだけになる。
  肩代わりを作るなら `ctx.Ignite` の中で着火先を差し替える（付く前に横取りする）こと。
  tick の順序を動かせば直るが、溜め・号令・縛めが全部1tickずれるので触らない。

- **配置の差し替えは「全体が伸びた」とは限らない。**
  上の差し替えの中身は第4波を約3pt 差し出して第5波を約13pt 買う入れ替えで、
  平均は上がるが第4波は確実に落ちる。平均最良の配置を採るという方針から出た当然の結果だが、
  「第4波が落ちた」を後からバグとして追いかけないよう、交換したことを配置のコメントに残す。

- **会戦は「波が易しすぎる」を敵を1体も触らずに反転させた（2026-08-25、engage 初回計測）。**
  独立5戦の勝率の積（理論全抜き率）が 100% の編成（逆しま改）でさえ、持ち越しありの
  会戦では 200/200 試行が突破ちょうど2部隊で止まる。全31編成で全抜き 0%、3部隊目に
  届いたのは移動改の 3/200 だけ（docs/engage.md）。難度の源泉は敵の強さから消耗へ移り、
  「1部隊で何部隊抜けるか」（期待突破数 1.00〜2.00）が編成の新しい序列になった。
  数値は一切調整していない——この計測が調整の起点になる。

- **会戦の序列は「勝ち方のきれいさ」（chain の残存）とよく重なる。**
  期待突破数の上位は 逆しま改・逆しま+後備え・後衛特化+後備え（2.00）・燃焼（1.99）・
  逆しま（1.95）で、いずれも残存の多い耐久系。残存＝次の Battle の初期戦力なので、
  きれいに勝つことがそのまま突破力になる。逆に AtkBonus の積み上げで勝つ編成
  （速攻 1.08・惨禍×被弾強化 1.04）は境界で強化が消えるため沈む。
  **畳みかける強さと会戦を渡る強さは別の軸**で、chain が測っていた「勝ち方の質」に
  初めて実利が付いた。

- **リィカの持ち越しはコンセプト通りに出る。ただし軸としては中位（期待突破数 1.84、7位）。**
  死の連鎖の第2 Battle の開始盤面には、リィカが攻5→35・薙ぎ（覚醒維持）・HP51/55 で載り、
  ヴェルは最大HP 46→11（2回縫った損耗）。「ここからは私の仕事」の絵はシステムから
  自然に発生する。ただし死の燃料（ゾト・ムグ・蘇生残量）は第1 Battle でほぼ尽きるので、
  第2部隊戦の後半で層の減衰が積み上げを追い越す。墓守の境界減衰（1層）が重すぎるかは
  まだ判定できない——全編成が同じ第3波の壁で止まっており、壁の原因は共通の消耗
  （HP非回復）側にあるため。

- **回復は独立5戦では難易度上げだったが、会戦では初めて軸になった。**
  耐久 (ガルド×ノノ) は独立積 7.4%（下位）なのに期待突破数 1.58 で中位に浮上。
  HP の持ち越ししか回復手段が無い世界では、Battle 中の回復がそのまま次の Battle の
  戦力になる。ノノの相対価値は上がったが跳ねてはいない（境界回復なし＝T4 は当面維持でよい）。

- **特攻隊（第1削りだけ高い編成）は現在の部隊列では測れない。**
  第1波は全編成が必勝なので `第1削り` が一律 100% になり、列として無情報。
  勝てない相手から始まる部隊列（強い波を先頭に並べ替えるだけでよい。敵の新造は不要）を
  作ってから測り直す（未解決の課題）。
  **→ 第2期（2026-08-25）で逆順列を足して解決。** 結果は下の逆順の項。

- **2部隊にしても5波の壁は越えられない（engage2）。** 全31編成で2部隊の全抜きも 0%。
  ただし削り残しを拾う非線形は実在する——速攻は 1部隊 1.08 → 2部隊 2.52（2.3倍）で、
  第1部隊が半壊させた第2波を第2部隊が拾って先へ進む。逆しま改は 3.85 で 171/200 が
  第4波に到達。「何部隊投入すればこの地点を落とせるか」という戦略判断の素材は既に出ている。

- **第3波の壁は消耗が原因（(B)）。入場戦力の計測で初めて数字の裏が付いた（2026-08-25、第2期）。**
  第2戦へは全編成が 200/200 で到達する（入場 49〜88%）のに、第3戦の入場は最良でも
  逆しま改の 4.0体 45%、次点 31%、以下は全編成 40% 未満（docs/engage.md の入場戦力）。
  逆しま改は独立5戦なら第三波に 100% で勝つ編成で、それが 45% 入場から 200/200 で落ちる。
  健在で着いて落ちる編成は一つも無いので、(A) 第三波が単発で重い、ではない。
  ただし壁は均一ではない——第3戦の到達率は 0/200〜200/200、入場%は 3〜45% に割れており、
  「第3戦にどれだけ持ち込めるか」自体は既に編成の序列として機能している。
  **→ 第3期: 壁が現れるのは第3戦だが、代金を課しているのは第二波（下の追記）。**

- **列の長さは壁の原因ではない（地点列＝順路の先頭3波）。** 第1期では「全編成が第3波で
  止まる」と記録したが、5波を3波に切り詰めても同じで、1部隊の全抜きは 30/31 編成が 0%
  （移動改のみ 3/200 = 1.5%）。「全抜きできる編成」は列を短くしただけでは出なかった。
  出るのは部隊を積んだとき——同一編成2部隊（engage2・診断）では地点の突破率が 0〜100% に
  散る（逆しま・逆しま改・後衛特化+後備え・逆しま+後備え・燃焼 100% / 速攻 51.5% /
  惨禍×被弾強化 5.5% / 毒・反撃改2・追撃×毒 0%）。全抜きの序列は「編成の強さ」ではなく
  「この地点に何部隊差し出すか」の軸に立つ。

- **逆順列で特攻隊が見えた。** 強い波（第五波）を先頭にすると `第1削り` が 59〜100% に

  追撃×毒 は逆順の期待突破数 0.00（200/200 が 0 抜き）なのに削り 80% で、engage2 の

  独立積 7.4%（下位）に対して削り 82% と同じ形。「勝てないが、次の部隊への繋ぎとして
  価値がある」編成は実在する。

- **部隊列ごとに最適な編成が違う（順路 vs 逆順で序列が入れ替わる）。**
  後衛特化+後備え は期待突破数が順路 2.00（同率1位）→ 逆順 0.59（中位）、燃焼も
  1.99 → 0.67 と沈む。逆に 毒+ベニ+ラウ は 1.11（中位）→ 0.99（2位タイ）、
  死の連鎖+後備え も 1.33 → 0.99 と浮上する。「どの列に当てるか」で編成の価値が変わる＝
  最強の5人が存在しない（コンセプト §6）は、数値調整ではなく部隊列の側から既に成立し
  始めている。地点は順路と同じ先頭3波なので1部隊の序列は変わらない（変わるのは
  投入部隊数の軸）。

- **行動パターンの仕組みを入れた。`Actions` が null なら従来どおり（2026-08-26・第10期、Phase AA）。**

  手番に「攻撃するか溜めるか」を持たせる層（`ActionKind` / `UnitAction` / `UnitDef.Actions`）を
  足した。攻撃型（`AttackPattern` ＝ 攻撃がどう届くか）とは別軸で、こちらは
  **その手番に攻撃するのかどうか**。パターンを増やしていないので「4つまで」の監査は要らない。

  後方互換の作りにしてある。`Actions` が null の駒（既存の味方31編成・敵の大半）は
  ターンループの分岐前とまったく同じ経路を通る。受け入れ確認は14モードすべてで出力が
  1バイトも動かないこと（`compare` / `chain` / `pulse` / `ablate` / `dump` / `engage` /
  `seats` / `handoff` / `cost` / `gradient` / `aim` / `flip` / `bridge` / `bill`）。

  倍率を `double` ではなく **int の百分率**にしたのは、ダメージ計算が `SecondaryPercent`(60)・
  `PierceDecayPercent`(25) と同じ `x * pct / 100` の整数演算で一貫しているため。
  ここに double を1本だけ通すと、丸めの規則がこの1箇所だけ違うものになる。
  倍率は `PerformAttack` の引数に置いて `CurrentAttack` 自体は変えない（`AtkBonus` と
  混ざると会戦の境界処理と墓守の層の再適用に衝突する）。**手番外の攻撃（反撃・軋み・
  追い打ち）には倍率が掛からない**——呼び出し側が渡さないので自動的に 100 になる。
  倍率は手番の行動に属する、という切り分け。

  **要点は「攻撃もして回復もする」にしないこと。** 攻撃を消費しないなら、それは
  `OnTurnStart` を別の場所へ書き写しただけで、選択肢が1つも増えない。
  「回復と攻撃のどちらを取るか」があって初めて、いつ撃つかが選択になる。

  移行は2体だけ（継ぎ当てのノノ / 澱みのミオ）で、どちらも `[Skill]` 1つの周期。
  こうすると挙動の差が「攻撃3 / 攻撃2 が出なくなる」だけに絞れる。
  実際に動いたのは**ノノかミオを含む9編成だけ**で、残り22編成は全15診断モードで
  値が1つも動かない（動いたのは他編成の順位など、9編成から派生した集計だけ）。

  - 発火がターン頭から自分の手番へ移る。ノノ（速さ6）より速い味方が殴られた**後**に
    繕いが入るようになり、痺れ・縛めで手番を失えばその周期の繕いも出ない
  - ミオの濃縮は毒の判定（`TickStatuses`）との前後が**変わらない**。tick はターン頭、
    濃縮はその後ろ、という関係は移す前と同じなので、毒のダメージがターンごとずれることはない。
    変わるのは同じターンに味方が積んだ毒まで拾えるようになることだけ

  継ぎ当て（`Mender`）は味方のノノと**敵の従軍司祭長**が共有している。司祭長は行動
  パターンを持たないので、`OnTurnStart` を無条件に `OnAction` へ移すと**司祭長の回復
  だけが静かに消える。** `gradient` / `aim` の候補波 3b がそのまま踏んだ。

  `Trait.ActsOnPattern`（行動パターンに `Skill` を載せているか）で分岐させ、移行が
  終わっていない駒はターン頭の無条件発火のまま残す。アクティブ/パッシブの全面分離が
  済めばこの分岐は要らなくなる。**症状が「機能が消える」であって「値が変わる」ではない
  ので、勝率表を眺めていても気付けない。** 特性の保持者を数える側から確かめること。

  | 分子経路 | 敵の全滅＝突破（`撃破/戦`・`与ダメ/戦`） | **1つ増える**——味方の全滅＝敗北（`被ダメ/戦`） |

  **`被ダメ/戦` は突破度に対しては分母経路だけだったので残していたが、単発の勝率に対しては
  言い換え側に回る。** `与ダメ/戦`（勝てば敵の総HPを払い切る）の鏡像で、勝ち側だけ外して
  負け側を残すと基準が非対称になる。

  検算で出るのは**露骨な算術の署名を持つのは `撃破/戦` だけ**（`撃破/戦 ÷ 敵体数 × 勝率` の
  r 0.82〜0.98）で、`与ダメ/戦` と `被ダメ/戦` の署名はどちらも弱いこと。**鏡像だから同じように
  薄まる**（過剰殺傷と、勝った/負けた試行の中でのばらつきに薄められる）。
  **外す根拠は構造であって相関の大小ではない。**

  再現は `dotnet run --project BattleSim -c Release 0 wave`。

  **机上のシナジーは、変換先が生き延びられるかまで見ないと成立しない。**

  | 20% | 33/33 | 7.1pt | 62pt |

- **二つの伸びる量を競争させると、崖ではなく傾斜になる（2026-08-21、測定済み）。**
  毒喰らい（ベニ）に「味方が負った毒は2倍に効く」というマイナスを足した。
  回復量は毒に侵された敵の数に比例するので敵が減るほど落ちるが、味方の毒は瘴気で
  積み上がり続ける。**減衰を外から与えなくても、時間が経つほど収支が反転する。**

  | 倍率 | 毒+耐久 (ベニ×トウ) 第5波 | 毒+ベニ+ラウ 第5波 |
  |---|--:|--:|
  | x1（もとの形） | 92% | 100% |
  | x1.5 | 90% | 100% |
  | **x2（採用）** | **66%** | **99%** |
  | x3 | 18% | 76% |

  同じ「毒を薄める」でも浄化（司祭が毎ターン味方の毒を -N）とは形が違う。
  浄化は毎ターンの増分と直接引き算になるので、増分を超えた瞬間に全ゼロになる
  （-4 という最小に近い刻みで 毒 の第2波が 98% → 0%、-10 と -20 は完全に同値）。
  **引き算は崖、競争は傾斜。** 対策を足すときは、どちらの形になっているかを先に見ること。

  浄化の測定で分かったこと（採用は見送り）:

  - 選択性は高い。毒軸 -43pt に対し毒軸以外 -6pt。全体回復（司祭が味方を癒す）は
    毒軸 -42pt / 毒軸以外 -40pt で、ほぼ全編成に等しく効く。**回復は調整ではなく難易度上げ。**
  - 「祓う者は自分を祓えない」形にすると司祭を毒で落とす経路が残り、耐えられる編成は
    司祭を焼き切ってから戦える（第4波 44% → 98%）。ただし崖は消えない。
  - **層を別の資源に変換している編成（ベニの回復・ヴィオの攻撃力化）だけが浄化を渡る。**
    層のまま持っている編成が全滅するので、最強編成が無傷で中位が刈られる形になった。

- **発火しない特性は、量ではなく発火条件を疑うこと（2026-08-21、測定済み）。**

  最初の一体が落ちる前に味方が全滅していたため。層をいくら増やしても発火しない。

  味方の死骸からも飛ぶようにしたら、**これまで最悪の出来事だった味方の全滅が拡散の起点に
  変わった。** 第五波は3ターン目に味方が一斉に落ちる波なので、そこが一番効く。

  | | 毒 (グザ×ミオ×ラウ) | 毒×死の連鎖 (ラウ×リィカ) |
  |---|---|---|
  | 敵の死のみ | 100/90/96/84/**6** | 100/18/0/0/0 |
  | 味方の死でも発火 | 100/98/98/94/**34** | 100/**49**/3/0/0 |

  死の密度が高い編成ほど働くので、毒軸と死の軸がここで初めてつながった。

  却下した案（測定値は `ContagionTrait` のコメント参照）:

  - **拡散先を敵味方の区別なしにする**: 拡散量は死んだ駒の層の半分で、終盤の敵は1体あたり
    20〜60層。その半分がミオ(HP42)に乗ると1〜2ティックで溶ける（毒軸の第2波 90% → 14%）。
    反対側だけ 1/8 に落とすと今度はほぼ無害（82%）。**痛いか無害かの二択にしかならない。**
  - **隣接する味方に毒を移す（毎ターン+1 / 拡散時に同量）**: 毒軸は素直に下がる
    （第4波 84% → 60% / 26%）が、澱み喰い（ヴィオ）がいる編成では逆に上がる（+7pt）。
    ヴィオはターン開始時に味方の毒を全部吸い上げるので、マイナスが燃料に反転する。
    **形は正しいが量が大きすぎ、「ヴィオを入れるかどうか」の二択になって判断にならない。**

- **毒軸が死んでいたのは層の量ではなく変換の向きだった（2026-08-21、測定済み）。**
  毒の層は減衰せず、毎ターン層の数だけ削る。累積は時間の二乗で効くので、
  毒軸は「間に合うかどうか」の勝負になる。第三波では4ターン目に敵の総層数96まで積んだ時点で
  味方が全滅していた（敵は5体とも生存）。**足りなかったのは層ではなく時間。**

  内訳を取ると、第三波2ターン目の33層の出どころは グザ +10 / ミオ +20 / スィド +3。
  **スィドは9%しか出しておらず、ミオの20は全部グザ依存だった**（澱みは「毒が積まれた敵の数」に
  比例するので、深さではなく広さに反応する）。グザがいる限り広さは飽和していて、
  スィドを敵の両隣へ拡散させても動かない（第3波 2% → 4%）。重複しない役割は濃さと体しかない。

  そこでスィドを「殴られると殴ってきた相手に毒を積む」に変えた。**耐えている時間が
  そのまま収入になるので、長期戦が毒軸にとって不利ではなく有利に反転する。**
  硬くて一撃が軽い第四波は 0% → 84%、決着は5ターン全滅から7ターン勝利に変わった。

  - **毒中は挑発**: 第三波が 75% → 68% と悪化した。第五波は薙ぎ・単体・単体・貫き・全体の

    恒常減衰の起動キーに変わる形で、静的なマイナスを無償収入に変換する号令の穴と同型。**
  - **盤面全体の毒ダメージ2倍（味方も倍）**: 第五波 85%。名目は対称だが、実測で味方の総層数は
