# 編成プロトタイプ

「捨てられた駒に役割を与えて噛み合わせる」が面白いかどうかだけを確かめるための実験装置。
グラフィックも演出も無い。確認したいのは編成の手応えだけ。

## 構成

    BattleCore/     戦闘ロジック。UI を一切参照しない
    BattleSim/      コンソール総当たりシミュレータ（Windows以外でも動く）
    PrototypeApp/   WPF。編成を組んで結果を眺めるだけ
    docs/           BattleSim が吐く生成物。手で編集しない

BattleCore は net8.0 の素のクラスライブラリで、
INotifyPropertyChanged も ObservableCollection も入っていない。
本番を Godot / Unity にする場合も、このプロジェクトはそのまま参照できる。

**ここにだけは戦闘ルールを書かないこと。** ViewModel やコードビハインドに
ダメージ計算が漏れた瞬間に移植できなくなる。

## 動かす

    dotnet run --project PrototypeApp        # 編成UI（Windows）
    dotnet run --project BattleSim -c Release 1   # 総当たり（引数はステージ番号 0-4）

## 特性を足すには

Traits.cs で Trait を継承し、TraitId に列挙子を足して TraitCatalog に登録する。
特性はすべて「イベントに反応するハンドラ」なので、
意図していない組み合わせでも勝手に噛み合う。そこが狙い。

    public sealed class ThornsTrait : Trait
    {
        public override TraitId Id => TraitId.Thorns;
        public override void OnDamaged(BattleContext ctx, UnitState self, int dmg, UnitState? src)
        {
            if (src is not null) ctx.ApplyDamage(src, dmg / 3, self);
        }
    }

## 検証コマンド

    dotnet run --project BattleSim -c Release 2          # 第三波を総当たり
    dotnet run --project BattleSim -c Release 2 rica     # リィカを含む編成に絞る

### 勝率だけでは見えないものを測る（`chain` / `ablate`）

`compare` の勝率だけでは「2枚で人並みに勝つ編成」と「5枚が畳みかけて無双する編成」が
同じ100%に見える。この2つの道具は勝率とは別の軸を測る。

    dotnet run --project BattleSim -c Release 0 chain > docs/chain.md
    dotnet run --project BattleSim -c Release 0 ablate [絞り込み] > docs/ablation.md

`chain` は「1ターンで味方が何体倒したか」の最大値（連鎖深度）と、勝利した試行だけの
決着ターン数を編成ごとに出す。同じ勝率でも連鎖深度が高いほど「畳みかけている」。

`ablate` は編成からメンバーを1体ずつ抜いて勝率の下がり方を見る。差が大きいほど
「そのメンバーが強さの源」、差がほぼ0またはプラス（抜いたほうが勝率が上がる）なら
入れ得の疑いがある。絞り込みは `reseat` と同じ書式（カンマ区切りの部分一致）。
全編成だと30秒前後かかるので、勝率表では判断がつかない場面（差し替え候補の勝率が
拮抗している、「消してはいけない」判定の根拠を疑いたい）で個別に回す。定型の
バランス調整フロー（CONTRIBUTING.md）には含めていない。

## 仕込んである噛み合わせ

- ボルグ（巻き込み） × ムド（被弾強化）……隣接スロットに置くと事故が燃料に変わる
- セロ（後衛特化＋臆病）……戦闘中に一度後退してから後列にいると攻撃力が2倍になる（最初から後列に置いても発動しない）
- ネル（呪詛漏れ） × ガルド（支援拒否）……漏れは味方全体に及ぶが、ガルドだけは受け付けない（隣接は関係ない）
- リィカ（墓守） × ムグ（分裂） × ヴェル（蘇生） × ゴルム（壁）……死を回し続けて積み上げる。
  短期決戦では間に合わないが、長期戦のステージでは最上位になる

## 調整メモ

- 継ぎ接ぎのヴェル: 代償は「蘇る側」ではなく「蘇生する側」が払う。
  蘇生される駒が弱体化するだけでは編成にとってのコストにならない。
  さらに同じ駒は二度縫えない（`sewn` カウンタ）。この制限が無いと、
  蘇生は死亡時効果を持つ全ての駒にとって唯一の正解になる。
- 墓守リィカ: 層は毎ターン1つ減衰する。放っておいても味方はいずれ死ぬので、
  減衰が無いと墓守は無条件に伸びてしまう。
- 爆ぜるゾト: 固定ターンではなく「倒れたとき」爆発。味方も巻き込む。
  どれだけ早く死なせるかがプレイヤーの操作対象になる。

## 状態異常・反撃の足しかた

毒は `StatusKeys.Poison` カウンタで持ち、`BattleContext.TickStatuses` が
ターン開始時にまとめて処理する。新しい状態異常はキーを1つ足して
TickStatuses に処理を書けば、特性側は「カウンタを積む」だけでよい。

燃焼（`StatusKeys.Burn`）は毒と対になる形で、**カウンタが「量」ではなく「残りターン」**。
固定量・非スタックなので、特性側はカウンタを直接触らず `ctx.Ignite(...)` を呼ぶ。
再付与を「加算」ではなく「持続のリセット」にする意味をここに閉じ込めてある。
規則は `BurnRules`（ダメージ量と持続ターン）。

反撃は `ctx.Reaction(...)` で包む。包まないと反撃が反撃を呼んで無限に落ちる。

## ログの色

`LogLine` は `LogKind` を持つ。UI は種類で色を引くだけで、文字列は一切解析しない。
新しい種類を足すときは `LogKind` に列挙子を追加し、
`MainWindow.xaml.cs` の `Palette` に1行足す。

見せ場（`Highlight` = 破裂・覚醒）だけを明確に浮かせ、
それ以外は静かに保つこと。全部が目立つと何も目立たない。

## 系統ごとの比較

総当たりは駒が増えるほど爆発するので、系統の当たり外れはこちらで見る。

    dotnet run --project BattleSim -c Release 0 compare > docs/balance.md

**最新の勝率表は [docs/balance.md](docs/balance.md)。** ここには貼らない。
2箇所に置くと必ず片方が腐るため（この節には長らく8編成分の古い表が残っていて、
コード側に24編成あることに誰も気付かなかった）。

### 勝率表は「配置を固定した値」であることに注意

    dotnet run --project BattleSim -c Release 0 layout > docs/layout.md

`compare`（勝率表）は編成ごとに**ひとつの配置に固定**して全波を通した数字で、
その配置は全波平均を最大化するように選んである。実プレイは波ごとに組み替えられるので、
**苦手な波の勝率は「その編成の限界」ではなく「平均最良の配置がその波で出した値」にすぎない。**
この差を読み違えると「勝率表は54%なのに手元では勝てる／勝てない」という混乱になる。

`layout` は各編成をメンバー固定のまま全配置に展開し、平均最良の上位と現行配置に加えて、
**波ごとの最良配置**も出す。ある波の勝率が低いとき、それが編成の限界なのか配置の都合なのかは
そちらの表で判断する。探索は seed 50 で行い、**選ばれた配置は seed 200 で測り直してから載せる**
（720通りの最大値をそのまま報告すると、運の良かった配置を実力と読んでしまうため）。

同じく、ユニット・特性・ステージの一覧は [docs/units.md](docs/units.md)。

    dotnet run --project BattleSim -c Release 0 dump > docs/units.md

どちらも BattleSim の出力そのものなので、手で編集しない。
更新手順は [CONTRIBUTING.md](CONTRIBUTING.md) を参照。

## 検証で分かったこと

- 積み上げ系（墓守）が必要とするのは戦闘の「長さ」ではなく「死の密度」。
  層が毎ターン減衰する以上、敵の火力が低い長期戦では逆に立ち上がらない。
  第四波（硬いが一撃が軽い）でリィカは 14.1% しか出なかった。
- 定数デバフ（呪詛）は敵の攻撃力が低いほど相対的に強くなる。
  第四波で呪詛官ネルが 57.3% と突出。割合デバフに変えるか、ステージ側で調整が要る。
- 範囲攻撃の値は「敵の数 × 値」で評価する必要がある。
  ゾトの破裂は20だが、敵5体なら実質100。
- ステージの難易度は敵の攻撃力で調整し、HPでは調整しない。
  敵HPを上げると、勝ち切れる編成と勝ち切れない編成に二極化して全滅が急増した
  （HP1.4倍で全滅14編成）。攻撃力を上げた場合は勝率が連続的に下がるため、
  中間帯を残したまま難易度を上げられる。
- ステージの良し悪しは平均勝率ではなく分布で見る。
  通過3〜6・中間4以上・全滅8以下を目安にする。平均だけ見ていると
  「4編成が100%で残りが全滅」という判別力ゼロの構成を良判定してしまう。
- 攻撃パターンを4種すべて含めると、単体前提の防御（庇う・標的）に頼る編成が自然に落ちる。
  第五波はこの形で作っている。
- **貫きは前列の数だけ威力が落ちる。** 減衰が無いと、前列を並べることが貫きに対して
  何の意味も持たない。ただしこの規則は味方の狙撃にも等しくかかるので、
  逃亡兵セロの火力に依存していた編成（耐久・毒→被弾強化・隊列崩し・突き出し）は
  まとめて弱くなる。これは想定内で、**「3体の壁越し」に後列を撃ち抜けることが
  そもそも強すぎた**、という判断。
- **後列を守る手段は「庇う（単体限定）」とは別に用意する必要がある。**
  `RearGuard` は薙ぎ・全体には割り込むが、レーン化した貫きには割り込めない
  （貫きは標的選択を通らずレーン単位で解決される）。貫きへの防御は
  「レーンを深くして減衰させる」という配置側の手段に移った。
  攻撃パターンを増やすなら、そのパターンに対する防御手段を同時に用意しろ。
  片方だけ増やすと系統が消える。
- **純粋な防御役は編成の火力を殺す。** `RearGuard` 単独・攻撃3で試すと、
  守っているのに勝率が落ちる（26.0% → 12.0%）。被弾強化を併せ持たせて、
  耐えるほど打点が育つ形にして初めて成立する。
  分かちのドハで同じ失敗を一度している。**耐久役には必ず見返りの経路を付けろ。**

- **非スタックの状態異常は、変換役が読むものを変えないと成立しない（2026-08-22、測定済み）。**
  燃焼（固定量・非スタック・持続3ターン）を足した。毒の変換役が実際に何を読んでいるかを見ると、
  ヴィオ・ラウは**量**（層の数）、ベニ・ミオは**数**（毒を負った駒の数）で、どちらも燃焼には無い。
  燃焼は層を持たないので量が存在せず、**数を読む形にするとミオと同じ穴**（撒き役がいる時点で
  飽和し、出力が「ボルグがいるかどうか」だけで決まる）に落ちる。

  残るのは時間・事象・自分の状態で、熾火（ホタ）は**自分の状態**を読む型にした。
  自分では着火できず、ボルグの火の粉は隣接した味方にしか移らないので、
  **ボルグの隣に置くことが発動条件そのもの**になる。庇い・後備えの「配置でマイナスが消える」の逆で、
  配置で条件を取りにいく形。

  | | 第1〜5波 |
  |---|---|
  | 燃焼 (ボルグ×ホタ) | 100/100/98.0/81.0/48.0 |
  | 同じ編成でボルグをゴルムに差し替え | **100/0/0/0/0** |

  着火役を外すと第2波から全滅する。**入れ得の正反対で、依存は絶対。**
  reseat の上位20配置すべてがホタをボルグの隣に置いており、非隣接は一件も残らなかった。

  火の粉をボルグに持たせた副作用として、ボルグを含む既存2編成も動いた。波及はこの2つだけ。

  | 編成 | 前 | 後 |
  |---|---|---|
  | 速攻 (ボルグ×ムド) | 100/94.0/96.5/100/27.5 | 100/99.5/99.5/100/33.0 |
  | 毒→被弾強化 (グザ×ムド) | 100/95.0/40.0/0/0 | 100/98.5/57.0/0/0 |

  燃焼ティックは `source` を持たない（`ApplyDamage(u, dmg, null)`）ので、
  被弾強化（ムド）は毒ティックと同様に反応する。**「ボルグの火でムドを育てる」という
  当初の着想はそのまま動く**が、第4波以降が 0% のままなのは前回記録したグザの非減衰毒が原因で、
  燃焼を足しても解けない。

- **状態でゲートする定数の見返りは、累積するコストに必ず負ける（2026-08-22、測定済み）。**
  熾火の初版は「燃えている間だけ攻撃力4倍」だけの形で、第1〜3波は 100/99.5/87.0 と通るのに
  **第4波が 11.0%** だった。ホタは毎ターン 燃焼6＋巻き込み9＋敵の攻撃 を払うが、
  見返りは攻撃24の**定数**。コストは戦闘が長いほど積み上がり、見返りは伸びないので、
  硬くて長い第四波では比が必ず負ける。第4波の4ターン目に落ちていた。

  同じ巻き込みを浴びるムドが成立しているのは、払った分が**永続加算**になるから。
  「積み上げは積んだ量に比例するコストを持つべき」の裏返しで、
  **累積するコストには、伸びる見返りか、伸びない代わりに広がる見返りを付ける必要がある。**

  燃えている間は攻撃が薙ぎに変わる（火は広がる）形にしたら第4波 11.0% → 81.0%。
  倍率を単に上げるのではなく出口の幅を変えたのは、第四波が重装兵3枚を横に並べる波で、
  単体火力を膨らませるより届く枚数を増やすほうが「炎」として素直だったため。

  倍率の感度は急峻で、着地帯は狭い。

  | `PyreTrait.Multiplier` | 燃焼 (ボルグ×ホタ) 第1〜5波 |
  |---|---|
  | 3 | 100/100/93.5/40.0/18.5 |
  | **4（採用）** | **100/100/98.0/81.0/48.0** |
  | 5 | 100/100/99.5/99.0/69.5 |

  ×5 は第4波99%・第5波69.5%で全30編成中3位になり、新軸が既存を押しのける。×3 は第4波40%で
  軸として立たない。**×3 と ×5 の間で第4波が 40 → 99 と動く**ので、ここは数値ではなく
  出口の形（薙ぎ化）で調整したほうが安全な帯。

  この表は旧配置（前1ガルド/前2ホタ/前3ムド/中ボルグ/後1ノノ）で振ったもの。
  配置を確定した後の ×4 は 100/100/100/83.0/60.0 で、表の値とは一致しない。
  倍率の相対比較として読むこと。

- **`confirm` の差が閾値ぎりぎりに乗ったら、もう1本別の seed 帯で確かめる。**
  燃焼 (ボルグ×ホタ) の配置差し替えは seed 200..599 で +2.1pt と、2pt の線を 0.1pt しか
  超えなかった。seed 600..1399 の800試行でも +2.3pt・内訳（第4波 -3、第5波 +13）まで
  同じ形で再現したので採った。**差の大きさではなく、波ごとの内訳が再現するかで見る。**
  平均だけ見て通すと、たまたま同じ平均に着いた別物を採ってしまう。

- **非スタックの状態異常は、撒き役1枚で供給が飽和する。2枚目の火種は0ダメージ。**
  燃焼軸の2枚目として「味方に燃え移る火を引き取り、燃えている間は攻撃した相手に着火する」
  駒（燠喰いのガイ）を作って測ったが、第4波 0.5% で成立しなかった。ログを追うと理由は明快で、
  **味方は全員おおむね同じ敵（前列）を殴るので、2枚目が着火する相手はすでに燃えている。**
  非スタックなので再着火は持続のリセットにしかならず、追加ダメージはゼロ。
  着火を本業にした駒は、engine の「攻撃1回につき特性は1度・主目標のみ」と合わせて
  出力が構造的に0に張り付く。**火種が「本業のついで」でしか成立しないのはこのため**で、
  ボルグが機能しているのは薙ぎ18の副産物として撒いているから。
  敵の数が増えて狙う先が割れるまで、この軸の供給役は1枚が上限。

- **燃焼軸の受け皿は「加算で伸びる型」では間に合わない（測定済み・3案とも没）。**
  ターン開始時に隣接する味方の火を奪って攻撃力を加算する案は、獲得量を3→6→10と振っても
  第4波が 0.0 → 2.0 → 6.5 しか動かなかった。係数ではなく構造の問題で、
  **コストを1ターン目から線形に払い、収入を2ターン目から線形に得るので追いつかない。**
  さらに収入源は「燃えている味方」で、その味方は燃えているぶん先に落ちる。
  ホタが成立しているのは見返りが初手から大きい定数（×4＋薙ぎ）だから。

- **`OnTurnStart` で状態異常を取り上げても、肩代わりにはならない。**
  ターンの進行は tick（燃焼ダメージ）→ `OnTurnStart` → 行動 の順なので、
  味方はその ターンぶんを払い切ってから火を取り上げられる。撒き役が毎ターン点け直す限り
  味方の出血は1点も減らず、取り上げた側のぶんが上乗せされるだけになる。
  肩代わりを作るなら `ctx.Ignite` の中で着火先を差し替える（付く前に横取りする）こと。
  tick の順序を動かせば直るが、溜め・号令・縛めが全部1tickずれるので触らない。

- **配置の差し替えは「全体が伸びた」とは限らない。**
  上の差し替えの中身は第4波を約3pt 差し出して第5波を約13pt 買う入れ替えで、
  平均は上がるが第4波は確実に落ちる。平均最良の配置を採るという方針から出た当然の結果だが、
  「第4波が落ちた」を後からバグとして追いかけないよう、交換したことを配置のコメントに残す。

## 未解決の課題

- **ミオ（澱み）のマイナスは保留。会心の導入とまとめてやること（2026-08-21、測定済み）。**
  ミオは「毒が積まれた敵の数」×4 なので、グザが全体に撒いた時点で最大値が出る。
  **深さも位置も関係なく、グザがいるかどうかだけで出力が決まる。**
  他者に及ぶマイナスが無く、マイナス×マイナスの材料になっていない。

  4つの方向を測ったが、**どれも採らなかった。**

  | 案 | 結果 | 落とした理由 |
  |---|---|---|
  | 味方にも毒を積む（+1〜+4） | 毒+耐久 94/98/99/78 → 23/12/0/0（+2） | 層が減衰しないので味方側の累積が二次関数で伸びる。+2 で壊滅 |
  | 毒状態の味方は癒えにくい（-50%） | 毒+耐久 第5波 78% → 0% | **変換先が一枚も無い。** 回復量の減少は `AtkBonus` を経由しないのでウツも反応しない |
  | 毒状態の味方の攻撃力を下げる（-1〜-3） | ミオ×ウツ×ネルだけ 14% → 23% と上がる | 唯一符号が反転したが、追撃×毒 が 82% → 37% と直撃する。着地帯が -1 付近しかない |
  | 会心率を下げる（新要素） | 下記 | 着想は正しいが、戦闘系の追加になる |

  **受け皿の有無を先に確かめること。** 「味方に毒を積む」は理屈の上ではムド（`RageTrait` は
  `source` を見ないので毒ティックでも発火する）・ヴィオ・ドハ・ラウが受け皿になるはずだった。
  だが実際に編成を組むと、ムド版は**マイナスを足す前の時点で第2波14%**、ドハ版は0%だった。
  低火力の変換役は、変換元が育つまで生き延びる手段を持っていない。
  **机上のシナジーは、変換先が生き延びられるかまで見ないと成立しない。**

  **会心（クリティカル）の導入は保留にしてある。** 毒に侵された駒の会心率を下げる形は、
  ミオの背景（毒の霧を濃くする）に合い、盤面全体の性質を変える役割をミオに与えられる。
  試作では狙いどおり動いた（会心20%で毒軸 72/62 → 97/98、追撃×毒 67/32/20 → 84/74/74）。
  逆しま（ウツ）を会心率アップ側に置く案も背景に合う。

  ただし現在の攻撃は完全に決定的（`int dealt = atk;`）で、乱数は特性の判定と標的選択だけ。
  会心はすべての攻撃に分散を入れるので、**系の性格そのものが変わる。**

  | 素の会心率 | 動いた編成 | 平均変動 | 最大変動 |
  |---|--:|--:|--:|
  | 20% | 33/33 | 7.1pt | 62pt |
  | 10% | 33/33 | 2.7pt | 27pt |

  10% まで下げても全編成が動く。大きく動くのはカド系（反撃改3 が 27pt）で、
  **カドの反撃は自分の攻撃力の2倍を返すので、会心が乗ると4倍近い返しになる。**
  断罪で付けたばかりの傾斜が崩れる。

  入れるなら全5波の再調整・全配置の再探索・測定 seed 数の見直し・カドの再調整が要る。

- **二つの伸びる量を競争させると、崖ではなく傾斜になる（2026-08-21、測定済み）。**
  毒喰らい（ベニ）に「味方が負った毒は2倍に効く」というマイナスを足した。
  回復量は毒に侵された敵の数に比例するので敵が減るほど落ちるが、味方の毒は瘴気で
  積み上がり続ける。**減衰を外から与えなくても、時間が経つほど収支が反転する。**

  | 倍率 | 毒+耐久 (ベニ×トウ) 第5波 | 毒+ベニ+ラウ 第5波 |
  |---|--:|--:|
  | x1（もとの形） | 92% | 100% |
  | x1.5 | 90% | 100% |
  | **x2（採用）** | **66%** | **99%** |
  | x3 | 18% | 76% |

  同じ「毒を薄める」でも浄化（司祭が毎ターン味方の毒を -N）とは形が違う。
  浄化は毎ターンの増分と直接引き算になるので、増分を超えた瞬間に全ゼロになる
  （-4 という最小に近い刻みで 毒 の第2波が 98% → 0%、-10 と -20 は完全に同値）。
  **引き算は崖、競争は傾斜。** 対策を足すときは、どちらの形になっているかを先に見ること。

  浄化の測定で分かったこと（採用は見送り）:

  - 選択性は高い。毒軸 -43pt に対し毒軸以外 -6pt。全体回復（司祭が味方を癒す）は
    毒軸 -42pt / 毒軸以外 -40pt で、ほぼ全編成に等しく効く。**回復は調整ではなく難易度上げ。**
  - 「祓う者は自分を祓えない」形にすると司祭を毒で落とす経路が残り、耐えられる編成は
    司祭を焼き切ってから戦える（第4波 44% → 98%）。ただし崖は消えない。
  - **層を別の資源に変換している編成（ベニの回復・ヴィオの攻撃力化）だけが浄化を渡る。**
    層のまま持っている編成が全滅するので、最強編成が無傷で中位が刈られる形になった。

- **発火しない特性は、量ではなく発火条件を疑うこと（2026-08-21、測定済み）。**

  | 巻き込みを対象HP比へ | 3% で 0.0 / 10% で 100.0（傾斜にならない） |

  理由はカドの盤面への関与が反撃しかないこと。攻撃力が閾値を超えれば敵を倒し切って
  ほぼ無傷で勝ち、超えなければ何もできないまま惨禍で味方が溶けて負ける。
  成長は加算で毎ターン一定量入るので、**閾値に到達するのは時間の問題か永遠に来ないか**
  のどちらかにしかならず、中間の勝率が構造的に存在しない。
  **係数を刻むのをやめ、敵の対抗特性（痺れ）で解く方針に切り替えた。**
  棘の反撃をターン外行動ゲートに載せたのは、その第一歩。

  |--:|--:|--:|
  | 0（無料） | 80.5% | 77.8% |

  | 10 | 76.4% | 70.0% |
  | 30 | 70.9% | 63.9% |

  **数字だけならコスト0が正解だが、それは「反動」という有限資源の縛りを実質無くすことに
  なり、連鎖に自制を持たせるという設計意図そのものが消える。** コスト5はコスト0との差が
  1〜3pt程度に収まる帯なので、勝率をほぼ落とさずに反動というフレーバーと制約を残せる
  ところを採った。

- **範囲攻撃に対する受け手を足した（砕け盾のヒビ、2026-08-23、測定済み・採用）。**
  タンクを置いても前衛が壊滅するという指摘を追ったら、機構の穴だった。
  **庇う・後備え・標的の介入はすべて `SelectTarget`（標的選択）で働く。** つまり主目標を
  差し替えているだけで、範囲攻撃の巻き込みは `PerformAttack` の中で個別に
  `ApplyDamage` されるので誰も肩代わりしていない。貫きに至っては `ResolvePierce` が
  レーンを直接走るので標的選択を通らない。実測で敵の攻撃力に占める範囲の割合は
  第四波15% / **第五波53%**で、そこが丸ごと素通りしていた。

  対処する駒は damage の層に置く必要がある。条件は `source.CurrentPattern != Single` で
  取れるので、**`ApplyDamage` の引数を増やさずに済んだ**。毒・燃焼は `source` が null なので
  自然に外れる。庇うのちょうど裏返し（あちらは単体だけ、こちらは範囲だけ）になり、
  「庇う・標的は Single にしか効かない」という設計の中核の反対側が埋まる。

  見返りは**破片（アーマー）**。HPの前に削られるプールで、回復とも攻撃力とも別資源。
  `ctx.Heal` は `AcceptsSupport` を見るのでガルド（`Stoic`）には一切届かないが、
  破片は damage 側で消費されるだけなので**「誰の助けも届かない」駒に唯一届く支援**になる。

  **予想外の噛み合いが出た。** ボルグの薙ぎは味方も巻き込むが、その巻き込みも
  `CurrentPattern != Single` なのでヒビの変換対象になる。**今日測った「被弾の19.8%が
  味方由来」という負債が、初めて資源として使える形になった**（pulse でボルグは味方に20与え、
  それが破片に変わっている）。配置は reseat 1位（94.7%）ではなく、この隣接を保つ狙いを
  優先して据え置いた（92.2%）。

  **数値は3回振り直した。1回目は配置探索を飛ばしていて読み違えた。**

  | 変換率（手置き配置） | 第1〜5波 |
  |--:|---|
  | 50 | 100/100/100/100/94.0 ← 総合98.8%、全編成中2位 |
  | 25 | 100/99.5/99.0/96.0/62.5 |
  | 15 | 100/98.0/99.0/**40.0**/39.5 ← 第四波が崖 |

  編成の強さを過小評価していたと判明した。CONTRIBUTING の「配置の再探索を飛ばすと
  変更を過大にも過小にも読み違える」がそのまま出た形。正しい配置で振り直すと、

  編成の composition だった**（ドルガ 攻38 が完走できるようになったこと）。

  HPがそのまま天井になる。

  | ヒビのHP | 第1〜5波 | 総合 | 残存 |
  |--:|---|--:|--:|
  | 118 | 100/100/100/100/100 | 100% | — |
  | 70 | 100/100/100/90.5/88.0 | 95.7% | 2.8/5 |

- **溜め改からクグを抜いても勝率がほぼ動かない。** これは棚卸し（§4「消してはいけないもの」）

  係数を振ると ÷2 と ÷4 の間が崖になる（第五波平均 34.4 / 23.1 / 22.9 で ÷4 と ÷6 はほぼ同値）。
  上昇量を刻むより、**出口の倍率（`Multiplier` = 2、`SplashPercent` = 60）を下げてから
  上昇量を戻す**方が素直。巻き込んで育つ役が付いた以上、素の反撃が最強である必要はない。
- **積み上げ系が第五波を支配している（2026-08）。** 上位は 溜め98.0 / 溜め改93.0 /
  毒+耐久92.0 / 反撃改2 87.5。`AtkBonus +=` を持つ特性は10箇所あり、多くが上限も逓減も持たない。
  **積み上げは「積んだ量に比例して増えるコスト」を持つべき**で、上限の有無はその結果でしかない。
  被弾強化のコストはHP（積むほど死に近づく）なので有限だが、
  溜めのコストはテンポで、積んだ量と独立している。だから最も長い波で実質無料になる。
  号令とカドの件（`SurrendersTurn`）で一件片付いたが、残りは未監査。
  特に `BindTrait`（縛め・毎ターン +16）は号令と同じ「毎ターン収入」の形で、
  縛め・号令・据えが**同じ1回の「動かない」を三重に売っている**（溜め改）。
- **空き枠がデメリット回避の道具になっている。** 5体を6枠に入れる限り必ず1枠空くので、
  「デメリットの隣を空ける」が常に最適解になる。再探索後の空き枠は後2に10件偏り、中衛は一度も空かない。
  出撃を6体にして空き枠自体を無くすのが最も根本的な対処。
