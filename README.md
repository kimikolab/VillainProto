# 編成プロトタイプ

「捨てられた駒に役割を与えて噛み合わせる」が面白いかどうかだけを確かめるための実験装置。
グラフィックも演出も無い。確認したいのは編成の手応えだけ。

## 構成

    BattleCore/     戦闘ロジック。UI を一切参照しない
    BattleSim/      コンソール総当たりシミュレータ（Windows以外でも動く）
    PrototypeApp/   WPF。編成を組んで結果を眺めるだけ
    docs/           BattleSim が吐く生成物。手で編集しない

BattleCore は net8.0 の素のクラスライブラリで、
INotifyPropertyChanged も ObservableCollection も入っていない。
本番を Godot / Unity にする場合も、このプロジェクトはそのまま参照できる。

**ここにだけは戦闘ルールを書かないこと。** ViewModel やコードビハインドに
ダメージ計算が漏れた瞬間に移植できなくなる。

## 動かす

    dotnet run --project PrototypeApp        # 編成UI（Windows）
    dotnet run --project BattleSim -c Release 1   # 総当たり（引数はステージ番号 0-4）

## 特性を足すには

Traits.cs で Trait を継承し、TraitId に列挙子を足して TraitCatalog に登録する。
特性はすべて「イベントに反応するハンドラ」なので、
意図していない組み合わせでも勝手に噛み合う。そこが狙い。

    public sealed class ThornsTrait : Trait
    {
        public override TraitId Id => TraitId.Thorns;
        public override void OnDamaged(BattleContext ctx, UnitState self, int dmg, UnitState? src)
        {
            if (src is not null) ctx.ApplyDamage(src, dmg / 3, self);
        }
    }

## 検証コマンド

    dotnet run --project BattleSim -c Release 2          # 第三波を総当たり
    dotnet run --project BattleSim -c Release 2 rica     # リィカを含む編成に絞る
    dotnet run --project BattleSim -c Release 2 demo     # 固定編成（反撃: カド×ヒサ×ガン×ハギ）のログだけ見る

## 仕込んである噛み合わせ

- ボルグ（巻き込み） × ムド（被弾強化）……隣接スロットに置くと事故が燃料に変わる
- セロ（後衛特化＋臆病）……戦闘中に一度後退してから後列にいると攻撃力が2倍になる（最初から後列に置いても発動しない）
- ネル（呪詛漏れ） × ガルド（支援拒否）……漏れは味方全体に及ぶが、ガルドだけは受け付けない（隣接は関係ない）
- リィカ（墓守） × ムグ（分裂） × ヴェル（蘇生） × ゴルム（壁）……死を回し続けて積み上げる。
  短期決戦では間に合わないが、長期戦のステージでは最上位になる

## 調整メモ

- 継ぎ接ぎのヴェル: 代償は「蘇る側」ではなく「蘇生する側」が払う。
  蘇生される駒が弱体化するだけでは編成にとってのコストにならない。
  さらに同じ駒は二度縫えない（`sewn` カウンタ）。この制限が無いと、
  蘇生は死亡時効果を持つ全ての駒にとって唯一の正解になる。
- 墓守リィカ: 層は毎ターン1つ減衰する。放っておいても味方はいずれ死ぬので、
  減衰が無いと墓守は無条件に伸びてしまう。
- 爆ぜるゾト: 固定ターンではなく「倒れたとき」爆発。味方も巻き込む。
  どれだけ早く死なせるかがプレイヤーの操作対象になる。

## 状態異常・反撃の足しかた

毒は `StatusKeys.Poison` カウンタで持ち、`BattleContext.TickStatuses` が
ターン開始時にまとめて処理する。新しい状態異常はキーを1つ足して
TickStatuses に処理を書けば、特性側は「カウンタを積む」だけでよい。

反撃は `ctx.Reaction(...)` で包む。包まないと反撃が反撃を呼んで無限に落ちる。

## ログの色

`LogLine` は `LogKind` を持つ。UI は種類で色を引くだけで、文字列は一切解析しない。
新しい種類を足すときは `LogKind` に列挙子を追加し、
`MainWindow.xaml.cs` の `Palette` に1行足す。

見せ場（`Highlight` = 破裂・覚醒）だけを明確に浮かせ、
それ以外は静かに保つこと。全部が目立つと何も目立たない。

## 系統ごとの比較

総当たりは駒が増えるほど爆発するので、系統の当たり外れはこちらで見る。

    dotnet run --project BattleSim -c Release 0 compare > docs/balance.md

**最新の勝率表は [docs/balance.md](docs/balance.md)。** ここには貼らない。
2箇所に置くと必ず片方が腐るため（この節には長らく8編成分の古い表が残っていて、
コード側に24編成あることに誰も気付かなかった）。

### 勝率表は「配置を固定した値」であることに注意

    dotnet run --project BattleSim -c Release 0 layout > docs/layout.md

`compare`（勝率表）は編成ごとに**ひとつの配置に固定**して全波を通した数字で、
その配置は全波平均を最大化するように選んである。実プレイは波ごとに組み替えられるので、
**苦手な波の勝率は「その編成の限界」ではなく「平均最良の配置がその波で出した値」にすぎない。**
この差を読み違えると「勝率表は54%なのに手元では勝てる／勝てない」という混乱になる。

`layout` は各編成をメンバー固定のまま全配置に展開し、平均最良の上位と現行配置に加えて、
**波ごとの最良配置**も出す。ある波の勝率が低いとき、それが編成の限界なのか配置の都合なのかは
そちらの表で判断する。探索は seed 50 で行い、**選ばれた配置は seed 200 で測り直してから載せる**
（720通りの最大値をそのまま報告すると、運の良かった配置を実力と読んでしまうため）。

同じく、ユニット・特性・ステージの一覧は [docs/units.md](docs/units.md)。

    dotnet run --project BattleSim -c Release 0 dump > docs/units.md

どちらも BattleSim の出力そのものなので、手で編集しない。
更新手順は [CONTRIBUTING.md](CONTRIBUTING.md) を参照。

## 検証で分かったこと

- 積み上げ系（墓守）が必要とするのは戦闘の「長さ」ではなく「死の密度」。
  層が毎ターン減衰する以上、敵の火力が低い長期戦では逆に立ち上がらない。
  第四波（硬いが一撃が軽い）でリィカは 14.1% しか出なかった。
- 定数デバフ（呪詛）は敵の攻撃力が低いほど相対的に強くなる。
  第四波で呪詛官ネルが 57.3% と突出。割合デバフに変えるか、ステージ側で調整が要る。
- 範囲攻撃の値は「敵の数 × 値」で評価する必要がある。
  ゾトの破裂は20だが、敵5体なら実質100。
- ステージの難易度は敵の攻撃力で調整し、HPでは調整しない。
  敵HPを上げると、勝ち切れる編成と勝ち切れない編成に二極化して全滅が急増した
  （HP1.4倍で全滅14編成）。攻撃力を上げた場合は勝率が連続的に下がるため、
  中間帯を残したまま難易度を上げられる。
- ステージの良し悪しは平均勝率ではなく分布で見る。
  通過3〜6・中間4以上・全滅8以下を目安にする。平均だけ見ていると
  「4編成が100%で残りが全滅」という判別力ゼロの構成を良判定してしまう。
- 攻撃パターンを4種すべて含めると、単体前提の防御（庇う・標的）に頼る編成が自然に落ちる。
  第五波はこの形で作っている。
- **貫きは前列の数だけ威力が落ちる。** 減衰が無いと、前列を並べることが貫きに対して
  何の意味も持たない。ただしこの規則は味方の狙撃にも等しくかかるので、
  逃亡兵セロの火力に依存していた編成（耐久・毒→被弾強化・隊列崩し・突き出し）は
  まとめて弱くなる。これは想定内で、**「3体の壁越し」に後列を撃ち抜けることが
  そもそも強すぎた**、という判断。
- **後列を守る手段は「庇う（単体限定）」とは別に用意する必要がある。**
  `RearGuard` は薙ぎ・全体には割り込むが、レーン化した貫きには割り込めない
  （貫きは標的選択を通らずレーン単位で解決される）。貫きへの防御は
  「レーンを深くして減衰させる」という配置側の手段に移った。
  攻撃パターンを増やすなら、そのパターンに対する防御手段を同時に用意しろ。
  片方だけ増やすと系統が消える。
- **純粋な防御役は編成の火力を殺す。** `RearGuard` 単独・攻撃3で試すと、
  守っているのに勝率が落ちる（26.0% → 12.0%）。被弾強化を併せ持たせて、
  耐えるほど打点が育つ形にして初めて成立する。
  分かちのドハで同じ失敗を一度している。**耐久役には必ず見返りの経路を付けろ。**

## 未解決の課題

- **毒軸が死んでいたのは層の量ではなく変換の向きだった（2026-08-21、測定済み）。**
  毒の層は減衰せず、毎ターン層の数だけ削る。累積は時間の二乗で効くので、
  毒軸は「間に合うかどうか」の勝負になる。第三波では4ターン目に敵の総層数96まで積んだ時点で
  味方が全滅していた（敵は5体とも生存）。**足りなかったのは層ではなく時間。**

  内訳を取ると、第三波2ターン目の33層の出どころは グザ +10 / ミオ +20 / スィド +3。
  **スィドは9%しか出しておらず、ミオの20は全部グザ依存だった**（澱みは「毒が積まれた敵の数」に
  比例するので、深さではなく広さに反応する）。グザがいる限り広さは飽和していて、
  スィドを敵の両隣へ拡散させても動かない（第3波 2% → 4%）。重複しない役割は濃さと体しかない。

  そこでスィドを「殴られると殴ってきた相手に毒を積む」に変えた。**耐えている時間が
  そのまま収入になるので、長期戦が毒軸にとって不利ではなく有利に反転する。**
  硬くて一撃が軽い第四波は 0% → 84%、決着は5ターン全滅から7ターン勝利に変わった。

  | 案 | 毒 (グザ×ミオ×ラウ) 第1〜5波 |
  |---|---|
  | もとの形（攻撃時に +3） | 100/14/2/0/0 |
  | 量を 22 まで上げる | 100/96/96/46/16 |
  | 敵の両隣へ拡散 | 100/31/4/0/0 |
  | 攻撃力依存（×2） | 100/52/16/0/0 |
  | **被弾で +4 / HP 84（採用）** | **100/90/96/84/6** |

  却下した案（いずれも測定済み。数値ではなく構造の理由で落としている）:

  - **毒中は挑発**: 第三波が 75% → 68% と悪化した。第五波は薙ぎ・単体・単体・貫き・全体の
    5枚構成で、`Marked` が効くのは単体2枚だけ。挑発は庇うと同じ穴に落ちる。
  - **隣接の毒ダメージを糧に自己回復**: 全量でも +3pt 程度しか動かない。
  - **毒に侵された味方の被ダメージ -25%**: 第五波が 10% → 66%、-40% で全波100%。
    強すぎるが、問題は数値ではなく条件のほう。**発動条件（味方が毒）をグザ自身が供給している**ので
    条件になっておらず、パターン不問の恒常 -25% になる。萎縮(-30%)は味方の攻撃力、
    散開(-35%)は空きスロットという代金を払っている。**グザの味方漏れというマイナスが
    恒常減衰の起動キーに変わる形で、静的なマイナスを無償収入に変換する号令の穴と同型。**
  - **盤面全体の毒ダメージ2倍（味方も倍）**: 第五波 85%。名目は対称だが、実測で味方の総層数は
    10前後・敵は80〜325。**代金は1桁、収入は3桁。**対称に見えて非対称だった。

  残っている問題: 毒 (グザ×ミオ×ラウ) の最良配置はスィドを前3の孤立席に置く。
  前3は横も縦も隣接を持たないので**味方漏れが完全に消える**。しかもこの編成は5体で6枠なので
  空き枠の代金も払っていない。下の庇い・後備えと同じ「配置でマイナスが消える」形。
  一方で澱み喰い（ヴィオ）は漏れが燃料なので、スィドを中衛に置いてわざとミオに当てにいく配置が
  最良になった。**同じ特性が、片方では編成判断を生み、片方では入れ得になっている。**

- **庇い（`Guardian`）と後備え（`RearGuard`）は、発動させないほうが強い（2026-08-21、測定済み）。**
  配置の再探索で、ガルドを前列に置く / セッキを後列に置くという制約を外すと、
  **試した8編成すべてで勝率が上がった。** 例外はひとつも無い。
  値はいずれも `docs/reseat.md`（seed 0..199）。

  | 編成 | 狙いを守る最良 | 制約を外した最良 | 差 | 外した中身 |
  |---|--:|--:|--:|---|
  | 逆しま+後備え | 60.6% | 77.3% | +16.7 | セッキを前1へ |
  | 逆しま改 (クビ×ウツ) | 87.9% | 99.4% | +11.5 | ガルドを後1へ |
  | 死の連鎖+後備え | 59.1% | 68.2% | +9.1 | セッキを前3へ |
  | 追撃×毒 (ハギ×グザ) | 71.5% | 79.0% | +7.5 | ガルドを中衛へ |
  | 毒 (グザ×ミオ×ラウ) | 23.7% | 24.7% | +1.0 | ガルドを中衛へ |
  | 溜め (ガン×ドルガ×カド) | 97.7% | 98.5% | +0.8 | ガルドを後1へ |
  | 反撃 (ヒサ×カド) | 99.5% | 100.0% | +0.5 | ガルドを中衛へ |
  | 反撃改3 (カド×ハギ) | 72.6% | 73.1% | +0.5 | ガルドを後1へ |

  **この2つは「プラス」の顔をしたコストになっている。**
  ガルドは肩代わりした分だけ早く落ちるだけで、見返りの経路が無い。
  中衛や後列に置けば、HP100・呪詛と弱体を受け付けない素の壁として使えて、
  そちらのほうが editorial には弱いはずなのに実測で強い。
  セッキは被弾強化を併せ持つが、それでも前列に置いて後備えを殺したほうが勝つ。
  「純粋な防御役は編成の火力を殺す」（上の節）は `RearGuard` 単独で確認済みだったが、
  **見返りを付けた後でも成立していなかった**、というのが今回分かったこと。

  逆しま改の +11.5pt は第5波が 39.5% → 97.0% で出ている。第五波は攻撃パターンを
  4種すべて含む形で作ってあるので、**単体前提の防御はそこで罰される**（意図どおり）。
  ただし罰し方が「置き場所を変えれば全部回避できる」形になっているのが問題で、
  現状これは駒の弱さではなく**特性を発動させない自由**の問題。

  `CompareBuilds()` は狙いを守る側の配置を採ってある。制約を外した配置を採ると
  「+後備え」を名乗る編成が後備えの効かない配置になり、勝率表がその特性について
  何も語らなくなるため。差そのものが監査結果なので、ここに残す。

- **カドは自分の係数では傾斜にならないが、代金の頻度では傾斜になる（2026-08-21、測定済み）。**
  下の「係数では解けない」は変わらない。変わったのは刻む場所で、
  カドの出力ではなく**敵側が代金を請求する頻度**を刻むと滑らかに動く。

  `Condemn`（断罪、審問官と勇者候補が保持）は反撃してきた相手を痺れさせる。
  痺れは棘・割り込み・追い打ちの門（`CanActOutOfTurn`）を閉じるので、
  **反撃の回数が多い編成ほど多く払う。反撃しない編成には何も起きない。**
  実際、カド系以外の19編成は全部 ±0.0 だった。

  確率と担い手の数、どちらの軸でも単調に動く（第5波 / 現行配置）。

  | 反撃(ヒサ×カド) | 現行 | 20% | 35% | 50% | 70% | 100% |
  |---|--:|--:|--:|--:|--:|--:|
  | 担い手1体 | 99.5% | 83.0% | 70.0% | 61.0% | 46.0% | 13.5% |

  | 担い手（45%） | 反撃 | 反撃改 | 溜め | 通過数 |
  |---|--:|--:|--:|--:|
  | 0体（現行） | 99.5% | 100.0% | 90.5% | 4 |
  | 1体（審問官） | 83.5% | 78.0% | 59.5% | 3 |
  | 2体（+勇者候補、採用） | 50.5% | 33.5% | 35.5% | 1 |
  | 3体（+巡礼騎士） | 30.0% | 17.0% | 27.5% | 1 |

  **担い手を1体にしてはいけない。** 審問官は HP76 で、カドの反撃が罰する側を先に殺す。
  配置を変えるだけで第5波 97.5%（断罪なしの 100.0% とほぼ同じ）まで戻った。
  3体にすると今度はカド系が全部20%台に落ちて逆向きの崖になる。**2体で採ってある。**

  2体を採ったのは数字だけの理由ではない。**回避の質が違う。**
  1体のときの回避は「カドを囃し立てたまま配置を変える」だけで済むが、
  2体のときの最良配置はヒサがカドではなくネルを指す形になる。
  つまり回避するには反撃軸の核（標的をカドに集める）を捨てるしかない。
  **編成判断を生んでいるので、これは罰として成立している。**

  却下した案: 審問官に素の `Paralyze` を持たせて痺れを撒く。支配している編成が
  無傷のまま（反撃(ヒサ×カド) が **-0.5pt**）周辺だけが落ちる、裾野を刈るだけの形だった
  （速攻 -22.0 / 後衛特化 -19.0）。痺れを最速の単体攻撃役に持たせると支配は崩れるが、
  今度はターン外に動かない編成まで巻き込む（カド外平均 -3.7pt）。
  **代金は「ターン外に動いたこと」に対して請求しないと、必ず無関係な編成に漏れる。**

  残っている問題: 第五波の通過が1編成（毒+耐久）だけになった。目安は3〜6。
  カドを100%のまま置くのではなく、**死んでいる軸（毒・追撃×死・散開耐久）を上げる側で
  戻すこと。**

- **カドの支配は係数では解けない（2026-08-21、測定済み）。** 出口倍率・出口範囲・成長係数・
  巻き込みプールの形（対象HP比）の4軸すべてを振ったが、どこを刻んでも崖が出る。
  中位帯が一斉に落ちて上位1件だけが残る形にしかならない。

  | 振った軸 | 結果 |
  |---|---|
  | `Multiplier` 200→100% | 第5波平均 28.9 → 15.0 / 75%以上 4 → 1 |
  | `SplashPercent` 60→15 | 反撃(ヒサ×カド) 99.5 → 87.0 だが裾野は全滅 |
  | `GainDivisor` ÷2→÷4 | ドハ×カド 100.0 → 44.0 → 0.0（÷3と÷4の間が崖） |
  | 巻き込みを対象HP比へ | 3% で 0.0 / 10% で 100.0（傾斜にならない） |

  理由はカドの盤面への関与が反撃しかないこと。攻撃力が閾値を超えれば敵を倒し切って
  ほぼ無傷で勝ち、超えなければ何もできないまま惨禍で味方が溶けて負ける。
  成長は加算で毎ターン一定量入るので、**閾値に到達するのは時間の問題か永遠に来ないか**
  のどちらかにしかならず、中間の勝率が構造的に存在しない。
  **係数を刻むのをやめ、敵の対抗特性（痺れ）で解く方針に切り替えた。**
  棘の反撃をターン外行動ゲートに載せたのは、その第一歩。

- **マイナスが自分の中で閉じている駒がまだある（2026-08-21、棚卸し済み）。**
  分かちのドハは「自分の火力が無い・早く尽きる」という自己完結したマイナスしか持たず、
  隣接も列も不問で味方全員が常時4割減という入れ得の駒だった。
  マイナスが他者に及ばないと編成判断を生まず、**マイナス×マイナスの材料にもならない。**
  同じ形の候補として号令のガン・庇うのガルド・痺れ粉のトウ・継ぎ当てのノノが残っている。
  とくにノノは他者の代金プールを無償で補填する（カドの巻き込み成長がその実例）ので、
  入れ得であること以上に、他の駒のコストを消す副作用のほうが重い。

（突き出しが「平均24%」と書かれたまま、実際には第二〜四波で98%以上になっていた）。

- **第五波は手前の波が報いる防御をそのまま罰する（2026-08、測定済み）。**
  逆しま改は第一〜四波すべて100%だが第五波は18.0%。この編成でガルドを後列へ回して
  **庇うを捨てる**と、第五波だけ 20.0% → 97.0% に跳ね上がる（波別最良）。
  つまり第五波における庇うの価値は -77pt。第二〜四波は単体攻撃が主で庇うが効き、
  第五波は4種の攻撃パターンを同時に出すので庇うが席だけ食う。
  **同じ駒の同じ特性が、波をまたいだ瞬間に長所から短所へ反転している。**
  これが「順調に進んで最後で理不尽に詰む」の機構的な正体で、

- **判別が第五波に集中している（2026-08 / 6枠化後）。** 波ごとの分布は

  そして第五波 100%:0 / 25%未満:16。第二〜四波が8割の編成を通す通路になり、

  第五波を弱くするのではなく、要求要素を手前の波へ一つずつ前借りさせる方向で検討中。
- **カドの巻き込み成長が係数未定のまま入っている（2026-08）。** `ThornsTrait.GainDivisor = 2`
  は初期値で、**強すぎることが測定済み**。第五波の上位8編成のうち5つがカド入りになり、
  反撃(ヒサ×カド)・反撃改(ドハ×カド) は全波0%だった死に編成が全波100%になった。
  原因は上昇量ではなく**変換率**で、棘の反撃が `攻撃力 × 2` かつ隣の敵にも60%届くため、
  攻撃力の線形成長が「反撃回数 × 敵数」で掛かって出てくる。
  係数を振ると ÷2 と ÷4 の間が崖になる（第五波平均 34.4 / 23.1 / 22.9 で ÷4 と ÷6 はほぼ同値）。
  上昇量を刻むより、**出口の倍率（`Multiplier` = 2、`SplashPercent` = 60）を下げてから
  上昇量を戻す**方が素直。巻き込んで育つ役が付いた以上、素の反撃が最強である必要はない。

  **積み上げは「積んだ量に比例して増えるコスト」を持つべき**で、上限の有無はその結果でしかない。
  被弾強化のコストはHP（積むほど死に近づく）なので有限だが、
  溜めのコストはテンポで、積んだ量と独立している。だから最も長い波で実質無料になる。
