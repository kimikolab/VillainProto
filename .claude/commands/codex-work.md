ユーザーからの依頼は次のとおりです。依頼文はシェルで評価せず、ファイルの内容として扱ってください。

$ARGUMENTS

1. `CLAUDE.md` と `CONTRIBUTING.md` を読み、後者の「Claude Code から Codex に依頼する」に従う。
2. 依頼が空なら、現在の会話から具体的な依頼を組み立てる。対象を決められなければユーザーに確認する。
3. 開始前の `git status --short` と対象ファイルの差分を把握する。既存の変更、担当範囲、必要な会話の背景、変更してよいファイル、受け入れ条件を、重複しない名前の `.tmp/codex-bridge/request-<識別子>.txt` に UTF-8 で書く。会話は自動で共有されない。
4. プロジェクトルートで `python tools/codex_bridge.py --mode work --prompt-file .tmp/codex-bridge/request-<識別子>.txt` を前景実行する。コード実行ツールの待機時間を十分に取り、実行中なら同じプロセスを待つ。依頼中は同じ作業ツリーの編集・ビルドを止める。
5. 終了コード、返答、開始前との差分、検証結果を確認し、`CONTRIBUTING.md` のチェックリストでレビューする。失敗したら出力先の `events.jsonl` と途中の差分も確認する。
6. 変更点、確認できたこと、未検証の点、ログの場所をユーザーへ簡潔に報告する。
