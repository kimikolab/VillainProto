# VillainProto Demo

`BattleCore` を**そのまま参照する** Godot 4 C# のデモです（第123期にリポジトリへ取り込んだ）。

> **同梱されていた `BattleCore` のスナップショットは削除した。**
> 渡された `VillainProtoDemo` は第110期前後の写しで、改行を正規化した差分が
> `BattleEngine` 510 / `Traits` 466 / `Models` 140 / `Presets` 76 / `UnitCatalog` 31 行あった
> ——第116期の `Overload`（据えのバン）が存在しない盤面を見ることになる。
> **写しを持つと必ずずれる**（第94期に手写しの表で 29 件の誤り／第97期 D6 で `GodotApp` が写しをやめた）。
> いまは `..\BattleCore\BattleCore.csproj` を `<ProjectReference>` で引いているので、
> **画面に出る1文・数値・席は `docs/` の生成物と常に同じものである。**

`VillainProto.sln` には**入れていない**（root の `dotnet build` を非 Windows でも通すため。
理由は `DemoApp.csproj` のコメントに書いてある）。

## 遊び方

> **第169期から、編成画面の「作戦マップへ」は検証用マップ 1-1（`Map11Main.tscn`）に入ります。**
> 下の 1〜5 は**自由移動の作戦マップ（`CampaignMain.tscn`）**の遊び方で、
> いまは `--campaign-smoke` などの検証コマンドと、シーンの直接指定からだけ入ります。
> 1-1 の遊び方は「検証用マップ 1-1」の節を見てください。

1. 作戦マップで左クリックまたは左パネルから味方部隊を選び、地面を右クリックして移動させます。
2. 拠点の範囲内に3秒留まると制圧できます。敵部隊も拠点へ進軍し、味方を見つけると迎撃します。
3. 敵部隊と接触すると会戦画面へ移れます。左のロスターから5体を選び、戦場の席へドラッグして配置します。
4. 「この配置で出撃」で BattleCore の実戦を再生します。勝敗は作戦マップへ持ち帰られます。
5. 戦闘中は Space で一時停止、1〜4キーで再生速度を変更できます。

作戦マップは WASD で移動、Q/E で回転、マウスホイールでズームできます。
作戦時間は上部のメニュー、または `0: 停止 / 1: ×0.5 / 2: ×1 / 3: ×2` で変更できます。

## 検証用マップ 1-1（第169期に追加）

**第168期 部B で3つの線を同時に通した1点（`S4/S4` × 道中の回復 50%）を、そのまま遊べる形に写したもの。**
数値・敵・隊は第168期から1つも変えていません。報告書は `design/PHASE169_MAP11_DEMO.md`。

- 拠点1つ・道2本・道ごとに敵部隊2つ。**手前を抜かないと奥に当たれません。**
- 北の道 ＝ **第二波・先遣**（後1 の施しの司祭長を抜いた4体）→ **第三波**
- 南の道 ＝ **第四波・先遣**（後1 の詠唱兵を抜いた4体）→ **第五波**
- 隊は3つ固定（**この期では組み直しなし**）。カド隊 `反撃 (ヒサ×カド)` ／
  ハネ隊 `突き返し (ハネ×ウツ)` の前3 をヨミに ／ 控え隊 `死軸×ヒヨ (ゾト×火選り)`
- **どの隊をどの道へ送るかも、控えをいつ・どこへ出すかもプレイヤーが決めます。**
- 接敵すると敵部隊の**名前／盤面ルール1行／体数／残り HP** が出ます。「戦う」で戦闘画面へ
  ——**編成画面は挟みません**（傷も死者もそのまま持ち込みます）。
- **勝った隊だけが、次の戦闘の前に HP を 50% 戻します。** 死者は戻りません。
- 4部隊すべて抜けば踏破。3隊とも消えれば撤退。結果画面に seed が出ます。
### 情報の層（第170期に追加）

**仕組みは1つも足していません。読むだけ。**

- 左のパネルに**その隊の勝ち筋**（1行）と、**隊の中身**が常に出ています
  ——席 / 名前 / HP / 攻 / 速 と、**「何をする」**（`UnitDef.PlusText` / `MinusText`。
  `docs/units.md` の生成元そのもの）／**「どの道で」**（第164〜168期で書けた4枚だけ）。
- 右のパネルの**敵部隊を押すと中身が出ます**。**敵の `UnitDef` には説明文が1つも無い**ので、
  こちらは**札ごとの1行**（`Map11Info.TraitLines`・手書き）で埋めています。
  盤面ルールの保持者には **★ この駒が倒れるとルールが消える** が付きます。
- **用語は括弧の中が主、名前が従**です（「ターン外の行動が止まる（粛）」）。
  隊の勝ち筋も**同じ語**を使っています——「ターン外の行動」＝粛 ／「回復」＝渇き ／「1発」＝軛。
- **出撃前の相性の警告は出しません。** 隊の勝ち筋と敵のルールを並べて見せるだけです。
- 画面下に**戦闘の記録**（戦闘1回につき1行）。**盤面ルールが実際に何をしたか**が
  `BattleResult` の帳簿から数字で添きます（0 のルールは出しません。評価の言葉は書きません）。
- 結果画面の生存枚数は**「盤上に残った枚数」と「未出撃を含む枚数」の2つ**を出します。

先遣隊の定義は `EnemyCatalog.Vanguards` で、**`Stages` / `Columns` には載っていません**
（`compare` は 1 セルも動きません）。

### 検証

```
Godot_console.exe --path DemoApp --headless -- --map11-phase0          # 説明文の出どころ・帳簿を実装から引く（第170期）
Godot_console.exe --path DemoApp --headless -- --map11-verify          # 進行を 800 seed 回して第168期と突き合わせる
Godot_console.exe --path DemoApp --headless --quit-after 60000 res://Map11Main.tscn -- --map11-flow-smoke   # 画面を通して1マップ
Godot.exe --path DemoApp --quit-after 400 res://Map11Main.tscn -- "--map11-capture=out.png[,detail|encounter]"
```

`--map11-verify` は **`Map11State`（遊ぶ側と同じクラス）だけ**を器具と同じ自動規則で回します。
第168期 部B の 5 つの量が**差 0.0pt で一致**することが受け入れ条件です。

`--map11-phase0` は手書きの `Map11Info.TraitLines` に抜けがあれば**名指しで落ちます**
（実際に `Executioner` の抜けを1件捕まえました）。

> **`--map11-flow-smoke` の合否は `MAP11_FLOW_SMOKE_COMPLETE` の有無で読んでください。**
> **終了コードは 0 になりません**——すべての出力の後に `System.GC.RunFinalizers` で
> `Fatal error. 0xC000001D` が出ます。1プロセスで5〜6回シーンを往復する走行で
> 静的に抱えた Godot のリソースが engine の後片付けと競っている形で、
> **第169期のコミットでも同じ**です（第170期が入れたものではありません）。

ヘッダの「編成プリセット」から **`Presets.Compare` 61 行 ＋ `Presets.Cross` 12 行 ＝ 73 行**を選べます。

## 2.5D 作戦マップ

- 草原、丘、川、道、砦は3Dで構成し、透視投影カメラ・霧・影で奥行きを出しています。
- 部隊は2Dのビルボード画像で、歩行中の上下動、向き、影、選択リングを加えています。
- 味方2部隊・敵2部隊・3拠点を同時に運用できます。
- 敵編成は同梱した BattleCore の EnemyCatalog を参照し、接敵した敵ごとに対応ウェーブを選びます。
- 作戦状態はシーン切り替え中も保持され、勝利した敵部隊はマップから除かれます。
- 部隊選択・移動命令の直後と敵が5m以内へ近づいた瞬間は、約2秒だけ実効速度が30%になる「指揮スロー」が入ります。
- 敵の通常移動速度も従来版から抑え、接敵前には「敵影接近」の予告を表示します。

## 戦闘表示

- 編成画面から出撃すると、草地・丘・樹木・霧・透視投影カメラで構成した3D戦場へ切り替わります。ユニットは背景を抜いた2Dビルボードです。
- 2Dユニットには待機の呼吸、攻撃時の踏み込み、被弾の揺れ、撃破時の沈み込み、召喚・蘇生の出現動作があります。
- 薙ぎは扇状の斬撃、貫きはレーンを通り抜ける槍線、全体攻撃は複数の着弾線で表示します。
- 攻撃時はカメラがわずかに寄り、攻撃型ごとに異なる地面リングと衝撃光を表示します。
- ダメージ表示の `攻 / 薙 / 貫 / 全` は攻撃型、`反撃` は手番外攻撃、`巻込` は味方への攻撃です。
- `毒 / 燃焼` は継続ダメージとして専用色で表示し、通常攻撃のダメージと区別します。
- `転倒` は駒が地面へ傾いた姿勢を次の手番まで保ち、手番を失う拍では暗い手番輪と足元の×印で行動不能を示します。
- ポップアップにはダメージ量と攻撃者名を、右側の戦況ログには省略しない完全な内訳を表示します。

### 手番の外（第125期）

**手番の中と手番の外を同じ流れで流しません。** 画面左上の帯がいまの「拍」を出します。

- `▷ ターン頭 —— 誰の手番でもない時間` —— `TurnStart` から最初の手番の行動まで。
  ターン頭に一括で走る味方 19 体（大喰らい・置き去り・墓守・逸らし・尾灯 ほか）はここに落ちます。
- `▶ 手番: <駒名>` —— いま自分の番の駒。足元に**金の輪**が常設で出ます。
- `⚡ 割り込み / 肩代わり / 介入` —— 手番の外。**手番の主の輪が暗く落ち**、割り込んだ側に輪と札が出ます。

出来事の側の描き分けは3つです。

- **追加攻撃**（棘・仇討ち・軋み）—— 台本の `Reaction`。割り込んだ駒を青い輪郭と先行する残像で
  先に示し、その駒の名前を載せた細い `EXTRA ATTACK` 帯を消してから着弾します。
- **肩代わり**（巨躯ゴルム・分かちドハ）—— 台本の `Relayed`。
  **本来の標的から中継した駒へ太い線**が引かれ、1発が分けられたことが見えます。
- **介入**（庇う・後備え・棘守り・殉教・標）—— 第125期に台本へ足した `Intercept`。
  **本来の標的から割り込んだ駒へ、途中で折れる線**が出ます（攻撃の直線と形で割っています）。

戦績パネル（T キー）の `庇い` 列は割り込んだ回数、`肩代` 列は中継が実際に受けた量です。

### 画面下の固定の一覧（第125期）

味方5体の **席 / 名前 / HPバー / 攻撃力と攻撃型 / 状態異常**を画面下に固定で出します。
**盤面の札は駒と一緒に動く**ので、逃亡・後退・突き飛ばし・かき回しが走るたびに読む位置が変わりますが、
ここは**席が変わっても動きません**（並びは開幕の席の順で固定）。手番の主は名前が金になります。
盤面上のゲージは今までどおり出ています。戦績（T）を開いている間だけ隠れます。

### そのほか（第125期）

- **ゾトの破裂**を敵の全体攻撃と同じ絵（上から降る線）で描き、人数ぶんの着弾を同時に出します。
- **溜め**は次の倍率と攻撃型を予告し（`▲ 次 ×2 単`）、その一撃が来たときに「溜めた一撃」と出します。
- **回復**の数字をダメージと同じ大きさにしました。
- **薙ぎ**を標的ごとの細い線から1枚の弧に変えました（散弾に見えていたため）。

## 起動

### 粛の封鎖演出

`Sealed`（粛）を受けた駒に、保持者から鎖を繋ぎます。初回の封鎖以後は薄く残り、
次の封鎖で光って張り詰めます。追加攻撃と同じ青い輪郭・残像が先行し、途中で引き戻されて粒に散ります。
保持者の `Death` でその保持者の鎖が砕け、蘇生で戻ります。対象は実際の台本から拾い、
特性名から封鎖対象を推測しません。複数保持者・両陣営・移動・召喚・再生し直しに対応しています。

2倍速以上でも不発の一連の動きに約0.54秒を残しています。粛の頭上の「封じ」「★ 粛」は
鎖へ置き換えました。渇き・軛は従来表示のまま、粛を観察してから演出を決めます。

開発用の `SealEffectCheck.tscn` は2倍速の不発・解放・正常発動を表示し、
複数保持者・死亡・蘇生・移動・再開を検査して終了します。

```powershell
dotnet build DemoApp/DemoApp.csproj
godot --path DemoApp res://SealEffectCheck.tscn
```

通常の戦闘で確認する場合は第二波・反撃編成を使います。

```powershell
godot --path DemoApp -- --demo-autoplay --demo-preset=反撃 --demo-stage=1 --demo-seed=0
```

### 通常起動

追加攻撃の暗転は試作として既定 ON。戦闘中の **F8** で ON/OFF を切り替え、
`--demo-no-super-flash` を付けて起動すると従来版で開始します。
発動者の周囲だけ明るさを残し、青い横閃光・外から発動者へ加速して流れ込む集中線と紺青の暗転を重ねます
（2倍速で約0.3秒、既存のカットイン時間内）。粛による不発には暗転を出しません。

- Godot 4.7.x Mono で `project.godot` を開いて実行
- または `godot --path C:\works\VillainProto\DemoApp --editor`
- 起動シーンは `Main.tscn`（編成画面）。**検証用マップ 1-1 へは編成画面の「作戦マップへ」から入る**
- 自由移動の作戦マップ（`CampaignMain.tscn`）へはシーンを直接指定して入る

## ベニ・ミオの演出観察

`design/CODEX_BRIEF_BENI_MIO.md` の2-1〜2-8を通常再生へ接続済み。
毒の泡・火の粉が紅を経て緑白金に変わり、刻みの数字は合算せず積み上がる。
実際の最後の刻みを強め、連続部分の待ち時間は1倍速で最大0.96秒（2倍速で0.48秒）へ圧縮する。
死亡による途中打ち切りも台本から読む。BattleCoreの計算は変えない。
ベニと隣接味方の足元には紅紫の結界。現在の席と生存状態に従い、移動・死亡・蘇生で付け替える。
火の拍は紅い火の粉、毒の拍は垂れる紫の雫。対象は手番に続く付与イベントから取り、周期を再計算しない。
回復の反転は淡い光の到着後に紫黒の渦へ変え、通常の刃・被弾音を出さない。
啜りは溢れた味方からベニへ紅い雫が加速して戻る。
ミオの濃縮は濁った水滴と毒アイコンの脈動、印は中心から周囲・ミオから味方へ広がる渦。
印の残量は状態アイコンの点の数で残し、付与時の残量とターン頭の写しを加算しない。

```powershell
Godot_console.exe --path DemoApp res://BeniMioCheck.tscn
# 1倍速と2倍速を交互に観察。-- --once --double なら2倍速で1周して終了。
Godot_console.exe --headless --path DemoApp res://BeniMioCheck.tscn -- --verify
```

検査は関連プリセット120戦の台本と、通常再生2編成の件数・最終HPを照合する。
最初から再生したときの件数、結界の移動・死亡・蘇生、印の残量更新・死亡・再開時の消去も検査する。

### 踏込とスマッシュ

現行のヨミとハネは表示専用の `Advances` を有効にし、主目標へ踏み込んでから席へ戻ります。
ヨミの薙ぎには広い三日月状の面と白い刃先を追加し、単体の細い一閃と描き分けます。
ハネの吹っ飛ばしは短い溜め、星形の衝撃、カメラの揺れ、高速射出と回転で表現します。
台本の被弾者だけが少し遅れて左右へ弾け、主目標は台本の `Move` の着地点へ接続します。

### 燃焼軸の演出

`FireLevel` / `FireArmor` の表示専用通知を `Main.Fire.cs` で受け、
`FirePresentation` が段・放つ・爆炎・焼き尽くす・火の雨・残り火の連撃を対応する次の `Attack` に結ぶ。
`BattleCore` の規則やHPは書き換えない。火勢の色と燃焼残りターンの大きさは別に管理する。
立ち絵差分10枚を接続し、炎は `FireFx` / `FireUltimateFx` のシェーダーで重ねる。
焼き尽くすは掲剣→巨大な炎剣の振り下ろし→大火柱・螺旋・地面の衝撃波。
大火柱は敵の並び幅に合わせた炎の壁と各標的の噴火を重ね、敵陣全体を覆う。
段2は橙の鋭い火槍、段3は一拍溜める白金の大火槍。段3には螺旋・衝撃輪・着弾の火柱を足す。
台本の火の雨は高速の連続噴火として描き、通常攻撃の後隙を挟まない。
旧版の放つは溜め→踏み込み→巨大な三日月。規定の爆炎は鎧への圧縮→全方向への解放→敵全体の噴火。
味方への爆炎は、その区間の台本の癒し・反転・ダメージを読み、身体のオーラと被災の炎に分ける。
満タンでHealが出ない場合も「火の癒し」「火の変換」から癒しを表示する。独りの爆炎も同じ処理を通る。
残り火・連撃は1件につき1発を素早く叩き込み、1体への5連撃も各着弾とHP表示を揃える。
あぶれた火は青白い光を武器へ凝縮し、くべられる火は赤い熾を強める。火勢は変えない。
攻撃中はステータスの上に技名と「一撃の攻」を表示する。倍率込みのAttack.Amountをそのまま読み、
ターン頭のStatSnapshotへ再び倍率を掛けない。次の行動・ターン・死亡・勝利で表示を消す。
焼き尽くすの大火柱は爆炎・大火槍より大きい演出を引き継ぐ。攻撃回数・順序は維持する。
ギフト、盾、放熱の印、敵の侵食、味方の無害な上昇オーラも描画する。
ターンギフトはヒヨから受け手へ流れる二筋の炎の帯と時計の光紋で手番の受け渡しを示す。
実際の「ギフトの手番」で針が一周し、「追加手番」の表示と身体の炎の発光を続く行動へ繋ぐ。
味方のオーラは `FireMantleFx` が現在の立ち絵のシルエットから描く。
肩・腕・装備に沿う短い炎と衣服の上を流れる火の筋で力を纏わせ、味方の地面には炎を出さない。
味方の纏う炎は火勢1→4で厚みと伸びを段階的に増やす。描画余白とUVを同時に広げ、身体への密着を保つ。
ポーズ差分と左右反転に追従する。敵の燃焼は足元からの侵食として区別する。
大技には暗部・地形への照り返し・HDR発光を使い、UIの操作を遮らない。
SEは指定の掲剣音、大剣＋爆発2、火柱・爆炎・ギフト・凝縮などの専用素材を使用する。
大技の4層は独立した音枠で保護し、連続する着火で余韻が切れないようにする。
再生速度に合わせて音の末尾をフェードし、ピッチは原音。素材と音量は `assets/audio/se/SOURCES.md`。

```powershell
dotnet build DemoApp/DemoApp.csproj
Godot_console.exe --path DemoApp res://FireCheck.tscn
Godot_console.exe --headless --path DemoApp res://FireCheck.tscn -- --replay
Godot_console.exe --headless --path DemoApp res://FireCheck.tscn -- --replay --solo
Godot_console.exe --headless --path DemoApp res://FireCheck.tscn -- --audio
Godot_console.exe --path DemoApp res://StagingEffectCheck.tscn -- --effect=fire-tick
Godot_console.exe --headless --path DemoApp res://StagingEffectCheck.tscn -- --effect=fire-tick --verify
```

前者は左右・段1〜4・ギフト・大技・死亡と再戦の描画を検証し、`outputs/fire-check/` に画像を保存する。
後者は `golm,hisa,borg,hota,hiyo`・第四波・HP400%/攻300%・seed 0を二度再生し、
炎の通知・攻撃・火の雨・爆炎・残り火の発数と最終HPが台本どおりであることを検査する。
`--solo` はヒヨをシオに替え、独りの爆炎と味方側の癒し・被災を同じ入口で検査する。

`fire-tick` はターン頭の毒と燃焼を駒ごとの一拍で表示する。毒と火の数字は同時に出し、
複数刻みの数字は合算、小さな火の弾けだけを実際の刻み数ぶん出す。
反転・火の変換・火の癒しはオーラ、燃焼ダメージは焼かれる絵にする。
台本は元の順で通し、死亡・延焼・別の駒への割り込みの前で区間を切る。
手番中の起爆と爆炎は従来の再生を使う。`--verify` は本番の再生経路も二度通し、
駒ごとの拍数・合算数字の数・元の通知件数・最終HPを検査する。
