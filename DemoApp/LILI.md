# 施しのリリの演出

`design/CODEX_BRIEF_LILI.md` §2〜5と、追加依頼の儀式演出。戦闘判定を追加せず、`Kiss` / `StatusTransfer` / 聖痕の `StatusGain` と状態の写しを読む。

- 正面・右向きの立ち絵は配置済みの `lili.png` / `battle/lili_idle_right.png` を利用。`design/art/lili/` の採用原本とハッシュ一致。ヒールは変更していない。
- 敵から薔薇色の精気と状態アイコンを杯へ吸い、杯から受け手へ運ぶ。自己回復も同じ杯から自分へ戻す。通常の殴打や付与の説明札は重ねない。
- 複数の状態は並列に運ぶ。到着の一拍で元の状態を消し、受け手を `StatusRemaining` に更新する。火・毒・呪い・竦み・痺れ・標・破片などの本体の表示も更新する。
- 聖痕は雫の印と状態アイコン。ターン頭でも保持し、儀式の終わり・死亡・勝利で消す。
- 溢れは桃色の薄い殻と破片の状態表示。
- 通常の一連の待ちは吸う0.26秒＋打点0.04秒＋運ぶ0.32秒＋回復0.10秒＝0.72秒（2倍で0.36秒）。状態数では伸びない。途中に台本の死亡・反撃・還りが割り込む場合は、その出来事の尺を別に取る。
- 単発の祝福の還りは倒れた敵→杯→受け手。儀式内の還りは収束中の光へ合流する。

## 祝福の儀

第206期: 柱の幅は `Rite.Amount`（名目総量）と各 `RiteDrain.Amount`（その敵への割当量）から決める。5体等分時を1として `sqrt(5 × 割当量 / 総量)`、幅は1〜2.5倍に制限する。5体で1倍、3体で約1.29倍、2体で約1.58倍、1体で約2.24倍。白い芯と外側の光を同じ比率で太くし、着弾の光も少し広げる。実ダメージや残りHPは幅に使わないため、瀕死の敵へのとどめも細くならない。総量の無い旧台本は従来幅。演出の尺は変えない。

通常の吸い取りとは別の `LiliRite3D` を使う。短い鐘とともに背景の照明を落とし、敵全員の聖痕が浮く。敵の頭上から白桃色の光柱が差し、光が強まったところでダメージと死亡を反映する。その後、敵がいた位置から薔薇色の帯が杯へ一斉に集まり、杯の上へ雫が浮かぶ。一拍置いて味方へ柔らかな光と花びらを渡し、照明が戻る。味方には光柱を落とさない。文字の見出しは戦闘ログだけに残す。

`Rite` から同じ書き手の `RiteEnd` までの台本を参照し、吸う・施す光をそれぞれ一度だけ表示する。HP・死亡・回復・破片の通知は元の順に処理し、人数分の演出待ちを重ねない。別の駒の反撃などは従来の演出を保つ。

儀式の区間に既存の `FinishSoundCue` が示す最後の敵の退場が含まれる場合、敵がいた位置の光柱の残照、収束の静止、祝福の余韻を延ばす。通常は約1.36秒、決着は約1.85秒（2倍で約0.68秒／0.93秒。他の駒の割り込みは別）。勝利表示はこの余韻を待つ。再戦・編成画面へ戻る操作で光、鐘、照明の変更を解除する。

## 確認

```powershell
dotnet build DemoApp/DemoApp.csproj
Godot_console.exe --headless --path DemoApp res://LiliCheck.tscn -- --verify
Godot_console.exe --path DemoApp res://LiliCheck.tscn
Godot_console.exe --headless --path DemoApp res://LiliRiteCheck.tscn -- --verify
Godot_console.exe --path DemoApp res://LiliRiteCheck.tscn
Godot_console.exe --path DemoApp --fixed-fps 60 res://LiliRiteCheck.tscn -- --widths
```

`--verify` は実台本の件数・最終HP・再再生・複数状態の同時更新を確認する。表示単体では聖痕の継続と消去、毒残量、呪いの染み、左右両陣営、自己回復を確認する。

通常起動は1倍・2倍、左右両陣営を順に再生して終了する。画像を保存する場合は `--fixed-fps 60` と `-- --capture-dir=<存在する絶対パス>` を付ける。

`LiliRiteCheck` は通常／決着の実台本を各2回再生し、儀式と降光の件数・最終HP・暗転の解除を確認する。表示確認では1倍／2倍・左右・通常／決着の8場面と、演出途中の再戦を通す。
