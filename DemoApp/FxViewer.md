# 演出ビューア

リポジトリ直下の `FxViewer.bat`、または次のコマンドで起動する。

```powershell
Godot_console.exe --path DemoApp res://FxViewer.tscn
```

「駒カタログ」を先頭に表示する。味方は `UnitCatalog.All`、敵は通常波に出る種類を自動走査し、
駒ごとに待機・攻撃・被弾・撃破を用意する。駒の節は既定で閉じ、開閉状態は選び直しても維持する。
「駒」「軸」「検索」は基本動作と登録済みの演出の両方を絞り込む。

味方の実戦は第1・第2波を各1本。編成は試遊 → 版 → 比較の順に本人のいる最初の行を使い、
見つからなければ中央に本人、残りを現役の先頭から埋める。敵の実戦は初登場の波を1本、試遊の先頭編成で回す。
実戦行の右の「見せ場 n」は、本人の個体IDが書き手または対象になっているイベントの件数。
ターン開始と能力・状態の写しを除く。見せ場0の行も残す。集計した台本をそのまま再生する。

再生・停止、速度、左右反転、撮影は第1段と共通。待機は空台本のまま3秒間保持し、停止時間を数えず、速度変更に追従する。
「次の見せ場」は繰り返しOFFなら終端で止まり、ONなら最初の見せ場に戻る。
「視点を調節」でカメラを調整できる。初期ズームは一覧の幅に合わせて0.85倍。
撮影は `design/art/_viewer/<cueId>.png` に保存する。

リィカは「死・リィカの覚醒」に、通常0–2層・霊刃3–5層・大剣6–8層・覚醒9層以上の
攻撃と待機を登録している。検索に「リィカ」、または駒の選択を使う。
攻撃は頭上からのシャベル打ち・溜めて加速する回転薙ぎ・切り上げと斬り返し・突きから回転斬りと落下斬り。
0–2層の命中は金属の衝撃光・短い止め・「金属叩き」のSE。3–5層は全身14姿勢で背面から正面へ横回転する。
回転薙ぎは命中後も刃を奥から反対側へ振り抜き、徐々に減速して構えへ戻る。振り終わりの光点も薄れて消える。
初回の踏み込みは4段階別の移動構え。到着後は待機絵を挟まず攻撃へ入り、連撃中の移動は振り抜きから次の構えへセルを進める。
シャベルを芯にした武器と身体のオーラは、キャラの連番とは別に動く。
武器は白熱した芯と青紫の光。9層以上では回転斬りから高く跳躍し、空中でためてから落下斬りで着地する。
9層以上の踏み込み・三連撃は待機絵の成人体格へ全20姿勢を描き直し、頭頂〜顎の寸法で全身セルの表示倍率を校正する（v14）。
膝を畳んだ姿勢は全身の高さで拡大せず、同じ頭の大きさを保つ。制作記録と比較動画は `design/art/rica/proportions-v14/README.md`。
6層以上の待機は幅のある大剣。9層以上ではさらに幅広くし、攻撃の突きだけ槍へ変化する。
剣閃は6–8層で太く大きく、9層以上では交差する3本の弧・着地の光輪・閃光を重ねる。
剣先の短い残光と接触時の弧・細い軌跡・火花も、停止と速度変更へ追従する。
回転薙ぎと空中回転は、腰の周りを一周する立体の軌跡を描く。奥は身体の後ろ、手前は身体の前を通る。
移動する光点と薄く残る一周の線で、回転方向を確認できる。命中側には短い閃光と火花を置く。
別候補の連番と追跡データがある段は「B候補」も表示する。左右反転・速度・停止・繰り返しは共通。

直接開く場合は `--fx-cue=rica.stage3.attack` のように指定できる。
`--fx-rica-verify` は4段の攻撃・待機を両陣営で再生し、B候補も確認する。
`--fixed-fps 30 -- --fx-rica-idle-capture` は通常を含む待機4段を各8秒撮影する。
最長の待機も2周を確認でき、武器と身体のオーラを含む実描画を `output/rica-fxviewer-idle/` へ保存する。
`--fixed-fps 30 -- --fx-rica-flow-capture` は各段を同じ駒のまま10秒・300コマ（30fps）連続で撮影する。
攻撃前の待機2秒を加え、踏み込み・段別の全連撃・帰還後の待機を `output/rica-fxviewer-flow/` へ保存する。
6–8層の二連撃、9層以上の三連撃は各打の間の踏み替えにも全身セルを再生する。
速度0.25倍で、振り抜き→武器を次の構えへ運ぶ動き→次の斬撃を確認できる。
つなぎの3本は接触を発生させず、攻撃の件数はそれぞれ2打・3打のまま。
振りかぶりでは武器のオーラだけを維持し、剣先の斬撃軌跡は出さない。次の実攻撃から新しく追跡を始める。
二連撃の2撃目は、両手を頭上に構える→刃が正面を通る→斜め下へ振り抜く。
全身差分でつなぎ、実際の刃から残光を描く。命中時は独立した円弧を出さず、刃上に短い閃光を置く。
2撃目は頭上で溜め、振り出しから4コマで命中、6コマで低く振り切る。
1撃目と同じ白い芯・青紫の縁・細い二重の残光を同じ剣先の弧に重ね、振り終わりまで色と太さを保って消す。
一段だけ撮り直す場合は `--fx-rica-flow-capture --fx-rica-flow-stage=2` のように0〜3を指定できる。
`encode_flow_preview.py` で追従拡大と盤面全体の4分割比較動画にできる。
制作・素材・検証の詳細は `design/art/rica/attack-motion-v1/README.md`。

## 実装

- `FxCatalog.Generated.cs`: `AllUnits`／`ForUnit` と共通の盤面・台本の雛形。駒ごとの登録は不要。
- `FxLivePlayback.cs`: engine で実戦台本を作り、開始時の盤面と engine が振った個体IDを対応付ける。
- `FxViewer.Catalog.cs`: 折りたたみ・絞り込み・実戦台本と見せ場数のキャッシュ。
- 既存の手組み Cue と Check はそのまま。再生は基本動作も実戦も `Main.ApplyEvent` を通す。

生成CueのIDは `unit.<id>.idle`／`attack`／`hit`／`death`／`live.<stage>`。
`FxCatalog.All` は登録済み → 自動生成の順、画面は駒カタログを先頭に並べる。
基本攻撃の対象とHPは試写用の固定台本で、特性の判定や威力の減衰は再計算しない。
特殊行動は実戦の台本で確認する。背景・演出・購入済み素材は本編の導入済みのものを再利用する。

## 検証

```powershell
dotnet build DemoApp/DemoApp.csproj
Godot_console.exe --path DemoApp res://FxViewer.tscn --headless -- --fx-smoke
Godot_console.exe --path DemoApp res://FxViewer.tscn -- --fx-generated-capture
```

`--fx-smoke` は生成を含めた全Cueを一巡し、味方全駒の基本4本、敵の基本動作、
カタ・バサ・ゴルムの見せ場数、絞り込み、開閉状態、待機の時計、シーク、終端と繰り返しを検査する。
生成に失敗した駒は `FX_VIEWER_SMOKE_SKIP <id> <理由>` で報告し、他の駒へ進む。
成功時の `FX_VIEWER_SMOKE_OK` に登録済み・生成・スキップの件数を出す。
合否は従来どおり `_OK` の行で読む（Godot終了時のリソース解放警告とは分ける）。

`--fx-generated-capture` は一覧の全体と、カタ・バサ・ゴルムの基本攻撃と実戦、
巡礼騎士・戦斧兵の基本4本を撮影する。第1段の `--fx-capture` は登録済みの5本だけを撮影する。
