### 4-2. Almoner × 渇き の同時成立

**同時に立つ会戦列は存在しない。** 挙動修正はしていない（報告のみ）。

根拠は 3 つ:

1. **保持者が別の波にいる。** 施しの司祭長（`Almoner` / `chaplain_g`）は
   `Stages[1]`（第二波）の後1 のみ。渇きの祭司（`Droughter`）は `Stages[2]`（第三波）の中央のみ。
   `TraitId.Alms` / `TraitId.Drought` を持つ `UnitDef` はそれぞれ `UnitCatalog.cs` の 1 行だけで、
   **味方側ロスターにも他の敵にも保持者はいない。**
2. **会戦列はどれも Stages の並べ替え／切り出し。** `Columns` の 3 本
   （順路 = `Stages`・逆順 = `Stages.Reverse()`・地点 = `Stages.Take(3)`）は
   いずれも `Stages` の要素をそのまま並べるだけで、**波の中身を混ぜる列は 1 本も無い。**
   したがって同一 `Formation` に両者が入ることはない。
3. **渇きは波をまたがない。** 判定は `BattleContext.Heal` の入口で
   `AllUnits.Any(u => u.IsAlive && u.HasTrait(TraitId.Drought))` を毎回評価する
   その場限りの盤面状態で、`DroughtTrait` は `OnCarryOver` を持たない。
   逆順列（第五波 → 第四波 → **第三波 → 第二波** → 第一波）で渇きの直後に施しの波が来るが、
   **部隊戦の境界で盤面が入れ替わるので重なりはゼロ。**

**したがって「渇きの下で施しが無効化される」状況は現行のどの列でも発生しない。**
将来 1 つの `Formation` に両者を入れる（あるいは渇きを持ち越し可能にする）場合は、
渇きが `ctx.Heal` の入口で止めるので **施しは完全に無効化される**（施しは自分が減らないので
代金すら発生せず、司祭長が完全な置物になる）点だけ先に記録しておく。
