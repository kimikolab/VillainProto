# 第32期 実装指示書 —— 第五波に行動順反転の波ルールを立てる

対象ブランチ: `master`（第31期の測定コミット以降から作業）
背景: 第31期の測定で、第五波は固有の勝者0・固有の敗者1本まで痩せ、3×5相関 +0.56 が現在最大の波間重複と確定した。処方は `board-rule-units.md` の本命案「行動順の反転」を、粛の成功パターン（駒ではなく波にルールを置く）で第五波に適用すること。合否テスト1（両陣営で触る駒を数える）は同文書で通過済み。

**設計フェーズの優先順位を再確認**: これはバランス調整ではなく、第五波に「その波にしかない失敗と成功の形」を作る仕事。勝率の水準よりも固有の勝者・敗者が湧くかを見る。

## Phase 1: 3×5 相関 +0.56 の行レベル分析（実装前・測定のみ）

+0.56 を作っている行を特定する。既存の `docs/balance.md` のデータだけで計算できる。

1. 第3波・第5波の勝率ベクトルについて、**各行を1行ずつ除外したときの r の変化**（leave-one-out）を出し、相関への寄与が大きい行の上位5〜8行を挙げる。
2. その行たちが両波を「同じ理由」で抜けている／落ちているのかを、**駒で**書く（規則5）。渇きは `ctx.Heal` の入口だけを塞ぐ。第五波の何がそれと重なる資源を課金しているのかの仮説を1つ立てる。
3. この仮説は Phase 2 の予測の基礎になる。**仮説が立たない場合もそのまま報告して先へ進んでよい**（反転の導入判断は相関分析の結果に依存しない——第五波の痩せ自体が十分な理由）。

## Phase 2: 駒ベース予測（実装前に書き切る）

### 2-1. 第五波の敵ロスターの列挙

第五波の敵構成（ユニット名・速さ・特性・配置）を表にする。`board-rule-units.md` の速さ分布は敵ロスター全体の話で、**第五波に実際に誰がいるかは列挙されていない**。予測はこの表から書く。特に:

- 勇者候補（速14・Executioner）が第五波にいるか。いるなら反転で最後に回り、序盤撃破の雪だるまが潰れる＝**味方側に広く追い風**
- 詠唱兵（速5・Charge→全体200%）がいるか。いるなら大技が早く落ちる＝**向かい風**
- 断罪持ちの速さと、反転後の行動位置

### 2-2. 42行の予測表

compare 全42行について、第五波の勝率が「上がる／下がる／不動」の3値予測を書く。**主判定17行＋速さの極端な駒（速≦4 または 速≧11）を含む行は、根拠を駒名と速さで1行ずつ**書くこと。軸名だけの根拠は不可（規則5）。目安となる素材:

- **上がる側の候補**: ドルガ38（速遅）・ゴルム3・ガルド4・カド4・バン2・セッキ2・ドハ3 を含む行。「遅いから外された」層が先に動く
- **下がる側の候補**: トウ11（痺れ——相手が動いた後に縛っても遅い）・セロ12・ササ12・ヒサ10・クグ10 を含む行
- **要注意**: カドは `Immobile` で手番自体を放棄しているので「先に動ける」利得が乗らない可能性。反撃はターン外なので反転の影響外。予測に明記すること
- 亡者（Wight 速4）・分裂の胞子など**戦闘中に湧く駒**の行動位置も変わる。リィカ軸の予測に織り込む

予測表は報告書に**実測より前のセクションとして**残す（後から書き直さない。外れは外れとして残す——反証が本体）。

## Phase 3: 実装

### 3-1. ルール定義

- **第五波の波ルールとして**、その波の間だけ手番の順序を**速さ昇順**にする（同速のタイブレークは現行のまま。タイブレーク乱数化は別残件であり、ここでは触らない）
- 実装位置は粛と同じ波ルール機構に載せる（5本目の波ルール）
- 断罪（既存の第五波の性質）は**そのまま残す**。置き換えではなく追加。過剰なら次の期に外す判断をする——まず足して測る
- 会戦列（順路・逆順・地点）では、第五波のステージが現れる位置にルールも付いて回る（粛と同じ挙動のはず。確認して報告書に1行書く)

### 3-2. 監査チェックリスト（実装前に grep で確認し、結果を報告書に残す）

1. 手番順を構築している箇所をすべて列挙（`OrderBy` 等で Speed を読む場所）。反転はその1箇所（のはず）だけに効かせる
2. **ターン外の経路4本**（棘/仇討ち/軋み/追い打ち、第27期に確定済み）が反転の影響を受けないこと
3. 行動パターン（`ActionKind` のインデックス進行）・痺れのインデックス非進行・`IdleTurn` の意味論が順序変更で壊れないこと
4. 「最速」「最遅」を明示的に読む特性・敵AIが存在するか（存在すれば挙動を報告。修正は勝手にしない）
5. 戦闘中に湧いた駒（亡者・胞子・増援）の挿入位置が昇順の下で自然か
6. 各ラウンドで順序が再計算されるか、開戦時に固定か——現行仕様を確認し、反転はその仕様を変えないこと

### 3-3. ルール名

波ルール名の候補: **遡り**／顛倒／覆し。デフォルトは「遡り」で実装し、ポンの指定があれば差し替え（識別子は差し替えやすい形にしておく）。「逆しま」は既存の軸名（ネル×ウツ）と衝突するので使わない。

## Phase 4: 測定

1. compare 全42行 × 全5波、**seed 0..199 の同一条件**で実行。docs 再生成
2. **回帰チェック（最重要）**: ルールは第五波限定なので、**第一〜第四波の 42×4=168 セルは全行 ±0.0** でなければならない。1セルでも動いたら実装が波の外に漏れている——そこで停止して原因を特定
3. 波間相関6ペア（全行版・情報行版・r と max|Δ| 併記）を再計算
4. 固有の勝者・敗者を再集計（閾値90/10、厳密版=100/=0も併記）
5. 第五波の分布（平均・100%数・0%数・中間帯・標準偏差）の前後比較
6. 予測表との照合: 42行の的中/外れを数え、**外れは全件、駒で説明**する

## 受け入れ基準

- [ ] 第一〜第四波 168セルが全行 ±0.0
- [ ] 第五波に**固有の勝者が1以上、固有の敗者が1以上**湧いている（閾値90/10）
- [ ] 3×5 相関が低下している（水準の目標値は置かない。低下量と、それを作った行の駒レベル説明があること）
- [ ] 予測表が実測より前に書かれた形で報告書に残り、外れが駒で説明されている
- [ ] 監査チェックリスト6項目の結果が報告書にある
- [ ] BattleCore の変更は波ルール機構＋順序構築の最小限で、diff の要約が報告書にある
- [ ] 報告書は `design/PHASE32_REVERSAL.md`

### 停止条件（コミット前にこちらへ報告）

- 第五波の平均が **35% を下回る**、または 0% の編成が 42行中 **15行を超える**場合は、コミットせず数値を持って停止（探索段階の許容を超えて波が壁になっている可能性。緩和ではなく設計の見直しをこちらで判断する）
- 逆に第五波の平均が **75% を超えた**場合も停止（勇者候補の無力化が効きすぎて波が溶けた形。断罪との足し引きを見直す）
