## 1. Phase 0（**実装前に確認して報告に貼る**）

### 1-1. セロの型と位置

`突き出し (セロ×ヨミ)` の会戦を `verbose: true` で1回回し、**セロについて次を時系列で出す**。

1. **各 Battle の開始時と終了時のスロット**（`BattleOpening` の値と、`Run` 後の `UnitState.Slot`）
2. **`HasFallenBack` がいつ真になったか**
3. **`CurrentPattern` の推移**
4. **`SwapSlots` が走った回数と、そのとき誰と入れ替わったか**

**確認したいのは2点**:

- **カードの型ラベルが更新されないことだけで説明が付くか**
  （`Piece.Pattern` は `LoadBattle` で `o.Pattern` から1回読むだけ。`StatSnapshot` は
  `Amount`＝現在の攻撃力しか運んでいない）
- **第1戦の終了スロットと第2戦の開始スロットが一致しているか**
  （`Engagement.cs` は「Slot・HasFallenBack は境界で触らない。再配置もしない」と明記している。
  **一致しないなら engine 側の問題**なので、そこで止めて報告すること）

**型ラベルだけで説明が付くなら、盤面には触らない。** 説明が付かない場合は §2 に進む前に相談。

### 1-2. 戦闘中に型が変わる駒の全数

`ModifyPattern` を実装している特性を**全部**列挙する（`grep -n "override AttackPattern ModifyPattern"`）。
**指示書の一覧を信用せず数え直すこと**（第84期でカド 8→11 行、第85期で呼び出し口 6→10、
第95期で `StatusKeys` 7→8、第96期でドルガが薙ぎ、の訂正が出ている）。

分かっているのは 逃亡兵セロ（後退後）／熾火のホタ（燃焼中）／軋みのヨミ（軋みが閾値超え）／
鱗のウロ（破片を纏っている間）。**全部いまカードに出ていない。**

### 1-3. 会戦と単発の敵が同じか

- **`EnemyCatalog.Stages`**（`compare` が各波を独立に測るのに使う5波）と
  **`EnemyCatalog.EngagementColumn`（＝`Columns[0]` の `Squads`）**（画面が使う会戦の部隊列）が
  **同じ敵編成の同じ順序か**を突き合わせる。
- **違うなら、V4 の単発モードは `Stages` を使う**（`docs/balance.md` と突き合わせられるようにするため）。

## 2. やること

### V1. カードの型ラベルを毎ターン更新する（**最優先**）

- **`StatSnapshot` に `Pattern` を載せる**（`BattleEvent.Pattern` は既にある。**新しいフィールドを足さない**）。
  emit している箇所で `u.CurrentPattern` を入れるだけ。
- `GodotApp` の `BuildState` で `StatSnapshot` を適用するとき、`Piece.Pattern` も更新する。
- **§1-2 で数えた駒が全部、条件が立った瞬間にカードのラベルが変わること**を確認する。

**これは表示専用の変更。`verbose: false` の `compare` は `Events` を積まないので判定は動かない。**
**`compare` 305 セル 0 件で示すこと。**

### V2. 線を減らす

**溜めるのをやめる。** いま画面に出す線は、**直前の1回の攻撃ぶんだけ**にする。

- **1回の攻撃で複数の着弾がある型（薙ぎ・貫き・全体）は、まとめて1つとして同時に描く**
  ——扇・数珠つなぎ・盤面が光る、はそのまま。**形が読めることがこの画面の要点**
- **`StatusGain` の細い線は既定でオフ。** トグルを1つ置いて、必要なときだけ出せるようにする
- **`ShotLife` を短くするのではなく、本数を絞る。** 薄れて消える演出は残してよい

**判断の目安**: **同時に画面に出ている線が、1回の攻撃の着弾数を超えないこと。**

### V3. 再生の既定を手送りにする

- **既定は停止状態で、1イベントずつ手で送る。** 自動再生は副次機能に降ろす
- **速度に 0.25× を足す**（現在の最低は 0.5×）
- **「次のターンへ」に加えて「次の攻撃へ」を足す**
  （`Attack` イベントまで飛ぶ。`StatusSnapshot` / `StatSnapshot` は飛ばす）

### V4. 単発戦モードを足す（**この期の本体**）

**画面の上部に「会戦 / 単発」の切り替えを置く。**

| モード | 中身 |
|---|---|
| **会戦**（現行） | `EngagementEngine.Run(..., EnemyCatalog.EngagementColumn, seed: 0)`。5部隊連戦・HPと攻撃力を持ち越し |
| **単発**（新） | `BattleEngine.Run(formation, stage.Enemy, seed)` を**波ごとに独立に**。毎回フルHPから |

- **単発モードでは波を選べるようにする**（第一波〜第五波）。
- **seed を選べるようにする**（既定 0）。`compare` と**同じ条件**で回すこと
  ——`verbose: true` 以外の引数を変えない。
- **画面に「いま見ているものが `docs/balance.md` のどのセルか」を出す**
  （編成名 / 波 / seed）。**測っている値と見ている絵が突き合わせられることがこのモードの目的。**

**注意**: `verbose: true` は `Events` を積むだけで判定を変えない。
**同じ編成・同じ波・同じ seed で、`verbose` の有無によって勝敗が変わらないこと**を1回確認して報告する。

## 7. 申し送り（**第99期の入口**）

### 課題リスト（**ポンが画面を見て挙げたもの。この期では直さない**）

1. **泥人形ムドが育つ前に落ちる。** 被弾で育つ駒を前列に置くと集中砲火を受ける。
   第79期の「撃破で育つ機構は育ったあとに振る手番が無い」と同型。
   第96期で呪いが落ちたときも**供給者自身が最大の受益者**だった
2. **散開のササが面白くない。** 条件が損失（味方の死）で、払い出しが防御の係数。
   **防御の係数は、ロスターで一番地味な通貨。切り替わっても事象にならない。**
   第97期の実測では**73行の会戦で一度も成立しない**
3. **回避という通貨。** 軽減（HPと同じ通貨）ではなく二値。
   確率を使わない書き方が2つ——**回数制**（1戦にN回）と**条件制**（単発N以上を無効）。
   条件制は第四波の軛（単発上限25）の裏返しで、**敵の攻撃型で価値が変わる**
4. **ターンギフト。** 手番を配る駒がいない（買う側はガン・バンがいる）。
   **強さの正体は「対象を選べること」**なので、マイナスは量ではなく**選べなさ**に置く。
   「最も遅い味方に渡す」なら、**遅いから外された層**（ドルガ・ゴルム・ガルド・カド・バン・セッキ）が
   自動的に受け取り、速い駒を入れると渡し先が変わるので**可変コスト型**になる

### 器具の話

- **単発と会戦の乖離。** `compare` は各波を独立に測り、画面は会戦を再生する。
  **96期ぶんの測定は「各波を単独で戦ったときの勝率」。** §4 の副産物で差の大きさを1回見る
- **ノイズ床の定義**（第89期）は engine の規則と相性が悪い（第96期: 11.87pt）。
  **規約を変えたくなったときは自分の都合を疑う**
- **残っているもの**: 見境のミサ／`AcceptsSupport` の統一／3分の器具の再設計／
  情報セルと測れる席の帯の不整合
