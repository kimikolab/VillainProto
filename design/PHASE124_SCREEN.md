### Q0-2. `TallyByUnit` は `verbose` に依存するか

**依存しない。** `BattleContext.TallyOf` は `_verbose` を1度も見ず、`Emit` / `Log` のような
`if (!_verbose) return;` の門を持たない。`compare`（`verbose: false`）でも全部積まれる
——だから `pulse` / `chain` / `ablate` がこの値で表を作れている。

**段1 の設計はここに乗っている**——判定を1つも通さずに数字を出せる。

### Q0-3. **庇い・肩代わりの計数はあるか** → **無い**

- 庇い（`Guardian` ガルド）・後備え（`RearGuard` セッキ）は `SelectTargetChain` で
  **主目標を差し替えるだけ**なので、`UnitTally` に「庇った回数」の欄が1つも無い。
- 分かち（`Sharer` ドハ）は `ApplyDamage` の中で肩代わりするが、増えるのは
  **肩代わりした側の `DamageTaken`** で、素の被弾と区別が付かない。
- `BattleContext.NoteGuardPick`（第120期）は `GuardFires[]` を持つが、
  **`WoundCensus` が真のときだけ・味方側だけ・`UnitTally` ではなく `BattleContext` に積む**
  ——診断専用で、駒には載らない。

> **P5 の前提はそのまま成り立った。** ガルド・ドハ・セッキは `被` が増えるだけで、
> 「庇ったから増えた」と「殴られたから増えた」が数字から分けられない。

### Q0-4. **付与の計数はあるか** → **キー別は無い。7キー合計なら<u>ある</u>**

**P1 の前提が半分外れた。** 第105期が `UnitState.SetCounter` → `NoteStatusGain` → `NoteCarry` の道に
**書き手への帰属**を1つ置いている:

```
if (key >= UnitTally.CarryPoison && key <= UnitTally.CarryIdle)   // 毒/燃/痺/標/破片/傷/手番
{
    UnitState? writer = Mark.Owner;                                // 第94期 (T2) の印
    if (writer is null) TurnStatusNone++;
    else if (InOwnTurn(writer)) TallyOf(writer).StatusOutInTurn++;
    else                        TallyOf(writer).StatusOutOffTurn++;
}
```

**`CarryMark`（標）はこの範囲に入っている**ので、「標を付けた回数」は
`StatusOutInTurn + StatusOutOffTurn` の**中に含まれている**。ただし:

- **キー別の内訳は無い。** 「標だけを何回付けたか」は引けない
- **減算は1件も数えない。** `SetCounter` の `delta > 0` だけが通るので、
  **止めが標を食う・断ちが傷を食う・繕いが傷を塞ぐ**は帳簿に残らない（第99期 §F の「減算の窓口」）

実測（`tempo tables`・73 行 × 5 波 × seed 0..199）:

| 駒 | 状態外% | 意味 |
|---|:-:|---|
| 逸らしのソラ | 100.0% | **書いている**（標を外し → 自分に付け → 敵に付ける） |
| 囃し立てのヒサ | 100.0% | 書いている |
| 止めのトメ | **—** | **1件も書いていない**。止めは標を**読んで消費する**駒で、消費は減算なので残らない |

> **だから P1 は「トメ」については当たり、「ソラ」については外れる**（§2 で判定する）。

## 3. 段0 —— `docs/rules.md` の自己参照を切った

`DvPhaseCell` の出力から「（k 期）」を落とした。**初出（`ph[0]`）は残す**

- 動いたのは `docs/rules.md` の `期` 列 **86 セル**だけ。
  検算: HEAD の `docs/rules.md` に `s/期〜（[0-9]+ 期）/期〜/` を当てると**再生成物と1文字も違わない**
  ——**既定値の列は1文字も動いていない。**
- **`derive rules` を2回続けて回して差分 0**（受け入れ条件 A3）
- **ノブの既定値そのものは1つも変えていない**

> **なぜ先にやるか**——この期は「305 セル 0 件差分」と「`docs/` 再生成で差分なし」が
> 主要な安全網なのに、**k のせいで後者が原理的に成り立たなかった。**
> 規約 (G8) の必須3「触っていないノブの既定が動いていない」を `docs/rules.md` の差分で示す、が
> **毎期偽になる**——検算の側が壊れていた。

### 4-4. `干渉 0` の注記（A6）

`docs/pulse.md` に既にある文を**そのまま画面に載せた**:

> **`干渉 0` は「価値が無い」ではない。** 呪詛（ネル）・萎縮（クビ）・庇い（ガルド）は
> ダメージを経由せずに盤面を変えるので、この列には最初から出ない。
