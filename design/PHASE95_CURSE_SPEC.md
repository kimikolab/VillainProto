## 1. (S1) 交差の空白表を機械で引き直す

### 1-1. やり方

`derive scan` は `(TraitId, StatusKey, 読み/書き, 対象)` の観測を持っている。
**そこから直接、軸の交差を数える。**

- **軸 = `TraitKeyMap` の 11 キー**（`Whet` / `Dull` / `Poison` / `Burn` / `Stun` / `Mark` /
  `Armor` / `Wound` / `Idle` / `Hit` / `Move`）。**新しい軸の定義を作らない**
- **11 キーから 55 組。** 各組について次を出す:
  1. **繋いでいる機構が実在するか**（1つの特性 or engine の規則が両方のキーに触っているか）
  2. **`compare` 61行に何行あるか**
  3. **交差帯12行に何行あるか**

### 1-2. 第92期との差分を明示する

> **第92期は「機構が実在するのは 12組」「空白かつ機構があるのは 毒×傷 の1組だけ」と結論した。**
> **表を直した後の数を出し、どの組が増減したかを名指しする。**

**増えた組があれば、それは「9期のあいだ見えていなかった交差」である。**
**第92期の交差帯12行の選定（規則4を緩めて選んだ）が、いま見ても妥当かを1行で書く。**

### 1-3. engine の規則も軸として数える

第94期の観測は engine の読み書きも拾う（`ApplyDamage` の中など）。
**滲み則・巻き込み則・着火・引き取りは `TraitId` を持たないが、キーの交差は作っている。**
**特性による交差と engine の規則による交差を、表で分けて出すこと。**

## 3. (S3) 形を選ぶ（**選定規則を先に固定する**）

### 3-1. 候補3つ

**どれも閾値を使わない**ので、第93期の壁（**閾値型は同じ通貨の消費型の読み手と構造的に同居できない**）
には当たらない。

| | 形 | 供給源 |
|---|---|---|
| **形1** | **背負っている汚れの種類だけ効きが重くなる** | 既存の汚れ全部（毒・傷・燃焼・痺れ・標・破片・なまり） |
| **形2** | **呪いを持つ駒に汚れが書かれると、隣へ伝播する** | 汚れの書き込み事象 |
| **形3** | **他の汚れが消えるときに発動する** | **減算の読み手**（(S2) の 3） |

### 3-2. 選定規則（**測る前に固定。数字を見てから動かさない**）

> **上から順に当てて、最初に全部を満たしたものを採る。**
>
> 1. **供給が駒に紐づいていること。** 第93期は供給の 95% が engine の規則で、
>    **2×2 に置ける駒が存在しなかった**（規約 (G5)）。
>    **供給の過半が engine 側になる形は選ばない。**
> 2. **交差が2本以上増えること。** (S1) の引き直した表で数える。
>    **1本しか増えない形は、この期には選ばない**（第92期のとおり空白は機構の空白なので、
>    1本ずつ埋めると期が足りない）。
> 3. **既存駒が1文も増やさずに読み手になること**（第90期の滲み則・第93期の自傷と同じ構造）。
> 4. **新しいキーを作るなら、`Kinds` の分母と `Stoic` の扱いを1行で説明できること**（(S2) の 4・5）。
>
> **全部を満たすものが無ければ、最も多く満たしたものを採り、満たさなかった項を明記する。**
> **どれも 1 を満たさないなら、この期は (S1)(S2) だけで閉じる。**

### 3-3. 各形について、選ぶ前に書くこと

**選定規則を当てる材料として、3つとも次を出す**（**選んだものだけ書くのではない**）:

- **供給の内訳**（駒ごと／engine ごとの回数の見込み。(S2) の数え物から）
- **増える交差の本数**（(S1) の表で数える）
- **読み手になる既存駒の顔ぶれ**
- **紙のスループット**（**門にしない。出力として出す**。規約 (G7)）
  **分子について3つを先に書く**——**線形か二次か／門ではなく出力／分母を削るか**
