### Q0-4. 自傷を `ApplyDamage` に通すと何が割り込むか

`ApplyDamageBody` を上から読んで列挙した（`source: self, isFriendlyFire: true`）。

| 段 | 割り込むか | 根拠 |
|---|---|---|
| 棘守り（カド）の上限 | **しない** | `target.HasTrait(ThornGuard)` ＝ ヒビは持たない |
| **脆弱（`FrailTrait`）** | **する（+50%）** | `t.ModifyIncomingDamage(target, amount)` をヒビ自身の札が通る |
| 惨禍・据え・散開・萎縮 | する | 味方全体にかかる増減の層 |
| **巨躯（ゴルム）** | **する** | 条件は `u.HasTrait(Colossus) && u != target && u != source`。ヒビは巨躯を持たないので壁が立つ |
| **分かち（ドハ）** | **する（40%）** | `u.HasTrait(Sharer) && u != target`。**`isFriendlyFire` を明示的に引き受ける**（コメントに明記） |
| 庇う・後備え・標的 | **しない** | 介入の鎖は `SelectTarget` の層。`ApplyDamage` を直接呼ぶ経路は通らない |
| 破片（`Armor`） | する（ヒビの在庫があれば） | ただしヒビは**自分には配らない**ので通常 0 |
| 受け流し（ガルド） | **しない** | `source.TeamId != target.TeamId` と `!isFriendlyFire` で二重に落ちる |
| 軛（第四波） | する | 出口の 25 上限 |

**脆弱は外さない**（指示書 §2-3）。代金が 1.5 倍になるが、**配る量は「実際に減った HP」なので
配る側も 1.5 倍になる**——「浴びるほど配れる」という現行の設計言語がそのまま自前の鍵に移る。

**巨躯・分かちが割り込むと、ヒビの HP が減らないぶん配る量も減る。**
これは「代金を肩代わりさせると機構そのものが縮む」形で、**自弁率（§4-1）が必ず要る**。

`spillWound` の既定は `true` だが、**`SpillWoundRule.Enabled` は第122期に `false` へ降りている**ので
どちらでも盤面は動かない。意図を明示するため `spillWound: false` を渡す。

`DamageRoute` の分類は `source == target` → **`Self`（自傷）**。
（ワタの `HpCostPerDull` は `source: null, isFriendlyFire: true` で同じ `Self` に落ちる。
自弁率の取り方＝`TallyOf(x).DamageTaken` の差分も**ワタの前例をそのまま使う**。）

### Q0-5. `lethal: false` で HP1 に張り付くか → **張り付くが、そこで供給が自然に止まる**

```csharp
if (!lethal) amount = Math.Min(amount, Math.Max(0, target.Hp - 1));
if (amount <= 0) return;
```

HP1 では `amount` が **0 になって即 return** する。
配る量を「実際に減った HP」にしてあるので、**ヒビが HP1 になった時点で配布も 0 になる**
——「払えなくなったら供給が止まる」は**規則を1本も足さずに出てくる**。
（`OnDamaged` も走らないので、他の被弾読みを空振りさせることもない。）

## 2. 予測（**実装前に書いた。外れても消さない**）

**予測が読む量を実装で1回たどった**（第130期の則）:
`ScaleWornTurns` を増やすのは **`ScaleTrait.OnTurnStart` の1箇所だけ**で、
条件は「ウロ自身の `Armor` がターン頭に 0 より大きい」。供給は砕けと味方の死（`GainPerDeath = 4`）の両方。
**`OnTurnStart` の前後は席順（スロット昇順）で決まる**（第61期）ので、
`鱗改`（ヒビ中央=2 / ウロ後3=4）と `破片×被弾`（ヒビ中央=2 / ウロ後1=3）は
**どちらもヒビが先**——新方式で配った破片は**同じターンの纏い判定に間に合う**。

1. **`鱗改 (ウロ×ヒビ)` と交差帯の `破片×被弾 (ヒビ×ウロ×セロ)` が最も大きく動く。符号はプラス。**
   ウロは破片を読んで貫きになる（`ModifyPattern`）＝**変換率が最も高い受け手**で、
   かつ席順の都合で供給が同ターンに間に合う。`ScaleWornTurns` ÷ `ScaleAliveTurns`（纏い率）が伸びる。
   ただしウロは振るたび剥がれる二重支出（`ScaleSpentAttack` / `ScaleSpentHit`）なので**線形には伸びない**。
2. **`範囲耐性 (ヒビ×ボルグ)` は小さくしか動かない、あるいは下がる。**
   ボルグの薙ぎの巻き込みでヒビは開幕から砕けている（`鱗改` の preset コメントが明記）ので
   **この行では現行の鍵が既に近い**。新方式は自傷ぶんヒビが早く死ぬので下振れしうる。
3. **`仇討ち×砕け (ヒビ×ザン)` は上がる。** 敵の範囲を待たずに供給が出る。
4. **ヒビの死亡率は上がり、生存T は下がる。** 自傷ぶん。**これは代金なので、下がること自体は不採用の理由にしない。**
5. **ガルドを含む行では、受け流しの在庫と破片の soak が食い合わず、破片が先に吸うぶんガルドが長持ちする。**
   破片は `ApplyDamage` の中で受け流しより**手前**にあり（Q0-4 の段表）、
   破片が吸い切ると `amount <= 0` で return するので**受け流しの在庫が減らない**。
   逆に「破片が無駄撃ちになる」方向もありうるので、**どちらに出たかを必ず切り分ける**。
6. **既定（`Passive` / `SelfCostPerTurn = 0`）では `compare` 61行 × 5波の 305 セルが 0 件差分。**
7. **巨躯（ゴルム）・分かち（ドハ）と同席する行では自弁率が落ち、落ちたぶん配布量も減る。**
   `仇討ち×砕け` はゴルム中央なので**自弁率がいちばん低い行になる**と予測する
   （`弱体×被弾` はドハ中央なので次に低い）。

**受動の鍵は1ターンに1回を超えて発火していた**——敵の範囲は薙ぎ・貫き・全体で
**1ターンに複数回飛ぶ**ので、範囲の厚い台では **1.43〜1.51 回/ターン**。
一方 `OnTurnStart` の自前の鍵は**構造的に 1 回/ターンが上限**で、
しかも分母がヒビの生存T（平均 3.24T・死亡率 94.2%）に固定される。

> **鍵を「敵依存」から「自前」に変えると、供給の分母が
> 「敵が振る回数」から「自分が生きたターン数」に変わる。**
> **前者は 1 ターンに複数回来るので、"遠い鍵" のほうが発火が多かった。**

**V1 が勝った 2 つは、どちらも V0 の発火が 1 回/ターンを下回っていた台**（0.49 / —）。
ただし `仇討ち×砕け`（0.61）は V1 が −14.5 で負けるので、**この比だけでは符号が決まらない**
——あの行のヒビは前3 の壁で、自傷ぶん早く落ちると隊列が崩れる。**1変数では説明できない。**

### 3-6. 線は届くのか（第135期の則を強い形で踏んだ）

掃引点の外まで振ると、**物差しは届く**:

| 台 | cost=3 | cost=6 | cost=10 | cost=16 |
|---|---:|---:|---:|---:|
| 台1 変換 Δ | −11.8 | **+2.9** | **+16.6** | **+27.3** |
| 台1 変換 物差し | 0.54 | 0.89 | **1.28** | **1.70** |
| 台2 素通り Δ | −12.4 | **+24.6** | **+28.9** | **+34.5** |
| 台2 素通り 物差し | 0.59 | **1.09** | **1.40** | **1.66** |

**物差し 1.0 に要るのは cost 6〜10 で、掃引点の中心 2 の 3〜5 倍**。
第135期は「紙で引くと N ≈ 2.2 で、N の決め方が許す上限 2 の**すぐ外**」だったが、
**今回は桁が1つ違う**——**器具が線に届かないことが、偶然ではなく構造的に決まっていた。**

外れた理由は §3-5 そのもの:
**掃引の中心を「現行の配布総量 ÷ 生存T」で引いた式は、「新しい鍵も現行と同じ回数だけ発火する」を暗黙に仮定していた。**
実際には発火が 1.4〜1.5 回/ターン → 1 回/ターンへ落ちるので、**1回あたりの量を同じだけ増やさないと総量が合わない。**

> **第136期の則の裏返し**:
> あちらは「**在庫が毎ターン戻る**機構では、1戦の総量から引いた N は**過剰**になる」。
> こちらは「**発火が1ターン1回に落ちる**機構では、1戦の総量から引いた cost は**過小**になる」。
> **どちらも「1戦の総量 ÷ 何か」で強度を引く式が、実装の発火周期を勘定に入れていなかったのが原因である。**

**cost 6〜10 は採らない。** §5 と規約 (G16) が「強度を決めた集合と採否を判定する集合を同じにする」ことを要求しており、
**結果を見てから掃引点を広げるのは第64期が禁じた「もっともらしい理由で条件を緩める」に当たる。**
（参考として、cost=16 ではヒビの代金が 20.0/戦・生存 1.50T で**自爆兵**になり、
台1 が 92.2% ＝ 天井へ寄って情報セルも落ちる。**同じ駒の別の設計であって、鍵の差し替えではない。**）

ただし**この物差しを次期以降そのまま使ってはいけない**:
分子（吸った量）は味方4枚に配った破片の合計、分母（ヒビの被弾）は1枚ぶんなので、
**「1枚の代金 対 4枚の利益」を 1.0 で比べている。** 枚数で割るか、分母を「編成が失った総量」にするかを先に決めること。

### 3-9. 副産物 —— 読み手の稼働率は上がり、供給は落ちた

| 台1 変換 | ウロが砕けから | ウロが死から | 纏い率 |
|---|---:|---:|---:|
| V0 現行 | 11.2 | 11.2 | 47.4% |
| V1 cost=1 | **2.0** | 12.2 | **62.9%** |
| V1 cost=2 | 5.5 | 11.9 | 64.1% |
| V1 cost=3 | 7.0 | 11.8 | 60.8% |

**ウロが砕けから受け取る量は 11.2 → 2.0（−82%）に落ちるのに、纏い率は 47.4% → 62.9% へ上がる。**
自前の鍵は「毎ターン少量」なので**在庫が切れている時間が短くなる**——
ウロの読みは `Armor > 0` の**二値**（`ModifyPattern`）なので、**稼働率だけ見れば改善している。**
それでも勝率が落ちるのは、破片のもう半分の値打ち（**ダメージを吸う量**）が一緒に落ちるから。

> **二値で読む機構の「稼働率」と、その通貨の「総量」は逆を向きうる。**
> **稼働率が上がったことを機構の改善と読んではいけない**——第114期「強化の価値は積んだ量ではなく
> 受け手が振った回数で決まる」の**逆側**で、こちらは**回数が増えて量が落ちた。**
