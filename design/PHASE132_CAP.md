## 1. Phase 0 の答え（Q0-1〜Q0-8）

### Q0-1 —— `checkup` が止まっていた原因

分類表は **`BattleSim/Program.cs` の `hcLabel`**（`focusId == "checkup"` の先頭・
第119期に置いた手書きの辞書）で、そこに `GradeStep` が無かった。
`hcUnlabeled` に落ちると `checkup` は
「**ロスターの札に分類の無いものがある: `GradeStep`。止める**（第117期）」の1行を出して `return` する
——**`phase0` も `check` も (a) 以降に1行も到達しない。**

**1行足すだけで済んだ。** 分類は **プラス**（`Overload`・第116期と同型。読む値も閾値も共有し、
違うのは上がる先の段だけ）。足したあと `checkup phase0` / `checkup check` は最後まで走る（**7.6 秒**）。

### Q0-2 —— `derive rules` の「〜」の生成元

`DvPhaseCell(name)` が `design/PHASE*.md` を**全文検索**して、その型名が現れるファイルの
期番号の集合 `ph` を作り、**`ph.Length == 1` なら「第nn期」、2 以上なら「第nn期〜」**を返していた。
つまり**指示書を `design/` に置いた瞬間に、そこで名前を挙げたノブの「〜」が立つ**
（第131期に `EmberRule` が 第130期 → 第130期〜 で実測済み）。

落とすと動く行は **91 行**（内訳は §3）。
**`docs/rules.md` の該当行は「初出」しか出さなくなる**ので、指示書が既存のノブに言及しても差分が出ない。

### Q0-4 —— `yoke` 診断の現状

`yoke`（引数なし = 5版の対照）／ `yoke sweep`（Cap 12〜50 の掃引）／ `yoke log`（1戦の監査）。
**どれも「勝率」と「ログの文字列」しか見ておらず、「何が何点切られたか」は1つも出さない。**

### Q0-5 —— 軛の保持者

**`EnemyCatalog.Stages` の第四波の中央に 1 体だけ。他の4波には 0 体。**

**P4 は当たった**（指示書 §5 の「撃破数で説明が付いたか」に対して ○）。ただし**前提の半分は外れている**ので、
則は指示書の文言のままでは立てられない。実測に合わせて書き直す:

> **上限は「1発の大きさ」ではなく「1発の<u>上側</u>」を平準化する装置なので、
> 上限の下では<u>体数の多い型</u>が有利になる。**
> **ただし「切られる総量」で序列を作ってはいけない**——総量は
> 「1発がどれだけ超えるか × 何発振るか」なので、**振る機会の少ない型は総量では最小になる。**
> 見るべきは **切られた率**（全体 100.0% / 薙ぎ 33.6% / 貫き 21.4% / 単体 11.8%）と
> **撃破/一撃**（全体 0.259 / 薙ぎ 0.107 / 型なし 0.087 / 単体 0.061 / 貫き 0.052）の2つで、
> **この2つは同じ向きに並ぶ**——**いちばん切られる型が、いちばん撃破する型である。**
>
> 機構は**過剰分**にある。上限なしの過剰率は 全体 22.5% / 薙ぎ 15.9% / 単体 9.6% だが、
> 上限ありでは 11.4% / 5.9% / 4.8% に落ちる。**上限は捨てられていた打点を回収する装置**で、
> 「1体を溶かしきる」型から「複数体を同時に削る」型へ価値を移す。

**第128期の第四波の跳ね（責め苦 1.0 → 65.5 / 仇討ち 18.5 → 94.0）はこれで説明が付く**
——2×2 の相乗は **+5.2pt（24 行平均）**、全体が主型の2行では **+31.5 / +75.0**。
**仇討ちでは上限が無ければ段の値打ちがほぼゼロ（+0.5pt）**で、**上限の下でだけ +75.5pt になる。**

### 次期のボルグの倍率案への含意

**第四波では伸びないと予測できる**（指示書 §5 の分岐どおり）。倍率は**1発を大きくする方向**で、
ボルグは**薙ぎ**（切られた率 33.6%・1撃あたり 19.3 点で既に上限の近く・`惜しい` が 1.68 回/戦 と全型で最多）。
**上限の下で伸びるのは「1発を大きくする」ではなく「当たる体数を増やす」ほうである。**

ただし歯止めを1つ書いておく——**倍率が「燃えている敵の数」に比例する案は、体数の側にも効く**
（燃えている敵が多いほど当たる体数も多い盤面になる）ので、
**Phase 0 で「倍率が1発の大きさを動かす分」と「当たる体数を動かす分」を分けて数えること。**
