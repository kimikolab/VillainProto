## 0. この期の性格

**HEAD は第132期**（`checkup` の復帰・`derive rules` の「〜」除去・上限の地図）。

**この期は盤面を動かす。** 第128期のドルガ以来の機構の追加になる。

### 0-1. 埋める穴

`StatusKeys.Burn` を読んでいる駒は**2枚しかない**:

- **熾のホタ**（`Pyre`）＝**自分が**燃えている
- **火選りのヒヨ**（`Favor`）＝**味方が**燃えている

> **敵が燃えていることを読む駒が1枚も無い。**

一方、**燃焼を敵に撒いているのはボルグ**である（`Cinder`・毎ターン。ゾトは `OnDeath` で 1.00回/戦）。
**唯一の常時着火役が、撒いた火に一切の価値を持っていない。**

**案**（ポンの発案から）:

> **焼け残りのボルグ: 燃えている敵が多いほど、一撃が重くなる。**

- **着火と発揮が1ターンずれる**ので自給にならない（間に敵が落ちれば無駄になる）
- **薙ぎなので複数体に届き**、「燃えている敵が何体いるか」が威力になる
- **上限が自然に付く**——ボルグが着火できるのは1振りにつき主目標1体、燃焼は3ターンで消えるので、
  **自分だけで作れる火は最大3体ぶん**（Phase 0 で確認）
- **ゾトの破裂（`BlazeRule` 既定 `Both`）も火を供給する**ので、着火役を増やす動機になる

### 0-2. **実装が形を1つに決めている（重要）**

`Trait.ModifyAttack` の署名は `(UnitState self, int atk)` で、**対象を受け取らない。**
`FinisherTrait`（トメ）の doc に明記されている:

> **`Trait.ModifyAttack` では書けない**——あちらは対象を受け取らないので「相手が標を持つか」で分岐できない。
> **攻撃の解決時**（`PerformAttack` が `atk` を作った直後）に掛ける。

> **したがって「標的が燃えていれば威力が上がる」は `ModifyAttack` では書けない。**
> **書けるのは「盤面の燃えている敵の数を読む」形だけ**である（`UnitState.Board` を読む前例が
> `OverbearTrait` にある——「条件はフラグで固定しない。`ModifyAttack` は毎回 `Board` から読み直す」）。

**これは制約ではなく、むしろ望ましい。**
盤面を読む形なら、**ボルグが着火した後に他の駒が敵を倒すと威力が下がる**——
条件が単調に増えないので、第123期からポンが言っている「戦闘中に変化が見える」に噛む。

**engine に窓口を足さない。** トメの倍率が engine 側にあるのは
「駒ごとのフックでは書けない機構」だからで、**この案は `ModifyAttack` で書ける。**

### 0-3. 第132期の則が、この期の予測を先に決めている

> **上限は1発の上側を平準化する装置なので、上限の下では撃破効率の高い型が有利になる。
> 切られる総量と結果は逆を向く。**（第132期）

実測で **薙ぎは上限に最も課税されている型**だった（切られた総量 57.6・4型で最大）。
**ボルグは薙ぎである。**

> **したがって第四波（軛・単発上限25）では伸びないと予測できる**（P3）。
> **伸びなくても「効かなかった」ではない。** 第二・三・五波で伸びていれば機構は効いている。

### 0-4. 順序 —— 倍率が先、伝播は後

第130期の**ホタの火配り**（`EmberRule`）は**不採用で `Off` 残置**されている。
落ちた理由は「**配る先の変換率が低かった**」——
乗算4倍の受け手（ホタ）から**倍率の無いボルグ**へ実効を移していた。

**この期でボルグが倍率を持てば、その前提が変わる。**

> **倍率が先。効いたら次の期で `EmberRule.On` を測り直す。**

**この期では `EmberRule` に触らない**（`Off` のまま）。§8-1。

### 0-5. やらないこと（明示）

- **`EmberRule` を `On` にすること**（§0-4）
- **ボルグが燃えるようにすること。** `CinderTrait` の `ally == self` は第130期の結論どおり残す。
  **(i) ボルグを強くする**と**(ii) ヒヨでボルグを強化する**は別の話で、この期は (i) だけ
- **ボルグの能力値（HP60 / 攻18 / 速8）の変更**
- **巻き込み先への着火**（現在は主目標のみ。engine の規則「攻撃1回につき特性は1度」による）。§8-2
- **engine への窓口の追加**（§0-2）
- **代金・上限の追加**（第118・126・127・128・130期と同じ。**素の効き方を先に測る**）
- **`DemoApp`**（Codex の担当）／作戦マップ

## 2. 予測（実装の前にここに書いてある。後から書き換えない）

### P1 —— **同時に燃えている敵は平均2体前後**

Q0-4 のとおり、ボルグ単独で作れるのは**主目標に1体/振り × 3ターン持続**。
敵が落ちれば減るので、**平均 1.5〜2.5体**に収まるはず。
**3体を超えるならゾトなど別の供給があり、1体を切るなら敵が早く落ちすぎている。**

**これが強度を決める分母である。** 「燃えている敵1体につき +N」なら、実効は **+2N 前後**。

### P2 —— **発火率は高い。ボルグが振れば大抵1体は燃えている**

ボルグは毎ターン着火するので、**2ターン目以降はほぼ常に1体以上燃えている**はず（発火率 80% 超）。
**第127期の「強化は段で来る（0% か 100%）」とは違う形**——
**連続量として効く**ので、閾値ではなく係数で設計する。

### P3 —— **第四波（軛）では伸びない**

§0-3。**薙ぎは上限に最も課税されている型**（切られた総量 57.6）。
一撃を大きくしても上限25で切られるので、**第四波の伸びは他の波より小さいはず**。
**伸びなくても機構は否定されない。**

### P4 —— **ボルグを含む行だけが動く**

Q0-6 が挙げる行が上がる。**ボルグを含まない行は ±0.0**（回帰の確認）。
**ゾトを含む行**（Q0-7）は、ボルグがいなければ**ボルグの札が無いので動かない**。

### P5 —— **`燃焼 (ボルグ×ホタ)` が最も伸びるとは限らない**

直感では燃焼軸が伸びそうだが、**ホタの攻4倍はボルグの火とは無関係**（ホタは自分が燃えていることを読む）。
**むしろ `速攻 (ボルグ×ムド)` のような、ボルグが主火力の行のほうが伸びる**はず。
**燃焼軸が最も伸びたら、理由を調べる。**

### P6 —— **戦闘中に威力が上下する**（単調に増えない）

盤面を読むので、**他の駒が燃えている敵を倒すとボルグの威力が下がる**。
**この上下が実測に出るか**を数える（振りごとの倍率の分散）。
**分散が 0 なら、条件がフラグ同然になっている**＝盤面を読む意味が無い。

### 3-1. 段1 —— ローカル台（`BattleCore`・盤面不変）

**台の作り方は第130期の教訓に従う**——第126期の案Cは「第117期の台をそのまま使った」せいで
**入力が 0 になる穴**を踏んだ。**この期の台は「敵が確実に燃える台」にする。**

- **ボルグ1枚＋土台**（全版で同一）
- **敵は複数体**（燃えている数が変わることが条件なので、単体の敵では測れない）
- **供給が届いているかを毎版で計数する**——**同時に燃えている敵の数の平均**（P1）。
  **0.0 なら測定不能として止める**（第126期・第130期の陰性対照と同じ作法）

**版**:

| 版 | 内容 |
|---|---|
| V0（対照） | 何も載せない |
| V1 | **燃えている敵1体につき攻撃力 +N**（加算） |
| V2 | **燃えている敵1体につき攻撃力 ×(1 + M)**（乗算） |
| V3 | **燃えている敵が1体でもいれば ×K**（二値。`Overload` と同型） |

**測るもの**:

- **同時に燃えている敵の数**（平均・最大・分散。P1・P6）
- **発火率**（燃えている敵が1体以上いた振りの割合。P2）
- **実際に乗った倍率**（振りごと。分散を出す。P6）
- **与ダメージ（敵）／撃破/戦／決着T／勝率**
- **上限に切られた量**（第132期の `Yoke` の計数がそのまま使える。P3 の下準備）

**強度は外から差す**（Q0-8。`OverbearRule` と同じ作法。**書き換え可能な static のノブを置かない**）。

**代金を付けない。閾値を掃引しない。**

### 3-2. 段2 —— 載せる（`BattleCore`）

段1 で**最も素直に効いた版**を1つ選んでボルグに載せる。

- **1版だけ。2版を同時に採らない**
- **`PlusText` に1節足す。** 現行は「一振りが横に薙ぎ、斬った相手に燃焼を移す」。
  **`MinusText`（同じ一振りが自分の両隣の味方も巻き込み、隣の味方にも火が移る）と `Flavor` は変えない**
- **`checkup` の分類表に1行足す**（Q0-9・A6）
- **能力値・席・`Presets` は触らない**

**選び方の基準**（段1 の結果から。優先順）:

1. **P6 の分散が出ている版**（盤面を読む意味がある）
2. **加算 > 乗算**（第132期の則。**乗算は1発を大きくするので上限に食われる**。
   加算のほうが上限の下でも素直に効く可能性が高い）
3. **単純な版**（同じ効き方なら V3 の二値より V1 の加算のほうが説明が短い、とは限らない。
   **説明の短さではなく、上下する余地があるほう**を採る）

## 8. この期では決めない・記録して次期へ渡すもの

1. **`EmberRule.On`（ホタの火配り）の測り直し。**
   第130期に不採用で `Off` 残置。落ちた理由は「配る先の変換率が低かった」で、
   **ボルグが倍率を持てば前提が変わる**。**この期が採用で終わったら次の期の第一候補**
2. **ボルグの薙ぎが巻き込み先にも着火するか。**
   現在は主目標のみ（engine の規則「攻撃1回につき特性は1度」）。
   **着火が3倍になれば燃えている敵の数が跳ねる**が、engine の規則に触るので独立した判断が要る
3. **ガルドのパリィ案。**
   一文「その傷のぶん強くなる」は**実装されていない**——`GatherRule` は傷を移すだけで
   `AtkBonus` は1も動かず、**第122期に既定オフ**。
   案は「庇った攻撃を1戦にN回だけ受け流す」（確率ではなく回数）。
   **Phase 0 で「ガルドが受けたダメージの攻撃型別の内訳」を先に取る**——
   庇いは Single にしか効かないので、範囲で削られているならパリィの回数が来る前に落ちる
4. **盤面ルールの対称性を数値で確かめる**（第132期の最大の発見）。
   軛は「両陣営に等しくかかる」のに、実測は **敵 7.68回/174.3点 対 味方 0.07回/0.4点** ＝
   **実質プレイヤー専用の税**。**逆位・渇き・粛は未確認**で、
   とくに**渇きは敵に回復役（従軍司祭・渇きの祭司）がいるので、敵のほうが得をしている可能性**がある。
   `yoke map` と同じ形の計数を3つのルールに当てるだけなので**1期まるごと使わずに済む**
5. **破片の行別の量が未測定**（第132期の P5 は「機構は確認したが 2.19点/戦」で止まった）。
