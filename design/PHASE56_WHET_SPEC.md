## 0. この期の主題

**攻撃力を上げる側に共通窓口を作る。**

第42期に、攻撃力を**下げる**側は `ctx.Dull` に統一した。5経路を1つの入口に通したことで、
その後の第44期（誹り）・第46期（驕り）・第52期（カリ）が**全部その窓口に接続でき**、
1つの通貨に読み手3枚（ウツ＝攻撃力／ウケ＝アーマー／ワタ＝敵へ転嫁）が競合する構造が成立した。

**上げる側にはそれが無い。** 第52期の Phase 0-1 で「共通窓口が無く直接フィールドを叩いている」
と判明したが、そのときは対処を見送った。

指示書を書いた側で数えた結果は次のとおり（**Phase 0-1 で数え直すこと**）。

| 分類 | 本数 | 経路（把握） |
|---|--:|---|
| **他者を強化する** | **6〜7** | 駆り立て（カリ）／号令（ガン・開戦時）／号令（毎ターン）／縛め（クグ・+16）／移り木（シオ）／分かち（ドハ）／吐き戻し（ゴルム・engine 側） |
| 自己を強化する | 8 | 怒り（ムド）／庇う（ガルド）／墓守（リィカ・2本）／断罪者（敵）／棘（カド）／澱み喰い／軋み（ヨミ） |

### 通すのは「他者を強化する」経路だけ

第42期の `Dull` が通した5経路は**すべて「他者への弱体」**だった（自傷型の弱体は無かった）。
対称にするなら、強化側も**他者強化だけ**を通す。

**自己強化を窓口に通してはいけない理由**が具体的にある。窓口は将来の横取りの立ち位置になる
（`Dull` の中でウケとワタが横取りしている）。**ムドの怒り（自分の被弾で自分が強くなる）を
他人が横取りできるのは設計として破綻している。**

### この期は窓口だけを作る

**読み手も駒も作らない。** 第42期は窓口・台・集約を1期でやったが、
**残り枠が2なので駒の追加は次期に回す。**

窓口ができれば診断で「強化の総量と経路別の内訳」が初めて測れる。
**その分布を見てから、次に何を作るかを決める**——
第42期が弱体で「供給4・読み手1」を数えて読み手を足したのと同じ順序である。

## 2. 実装

### 2-1. 窓口 `BattleContext.Whet(UnitState target, int amount, WhetRoute route)`

**名前を `Whet`（研ぐ）にするのは `Dull`（鈍らせる）の対義語だから。**
コード上で一対と読めることを優先している。**より良い名前があれば変えてよいが、
`Dull` と対になっていることが分かる名前にすること。** 変えた場合は理由を書く。

**やることは2つだけ**（`Dull` と対称に作る）。

1. 集計を更新する（`WhetTotal` / `WhetByRoute`）
2. `target` の `AtkBonus` に `amount` を加算する

**やらないこと:**

- **`AcceptsSupport` の判定を窓口に入れない。** 呼び出し側の既存の扱いをそのまま残す
  （Phase 0-3 で不揃いと分かるはずだが、統一すると既存56行が動く）。
  **第42期の `Dull` と同じ判断**にすること
- **横取りの仕組みを作らない。** ウケ・ワタに相当する読み手はこの期では作らない。
  **ただし将来そこに立てられる形にしておくこと**（`Dull` が横取りをどこに置いているかを見て、
  同じ位置に何も置かない状態で作る）
- **`OnEmpowered` のようなフックを作らない。** 読み手が0枚の段階でイベントを作るのは早い
- **ログの文言を変えない。** 各経路のログは呼び出し側に残す
  （「号令」「縛め」「返した」は駒の個性であって窓口の責務ではない）

### 2-2. `WhetRoute` の列挙

`DullRoute` と同じ形で、**経路ごとに1つずつ**。把握では以下だが Phase 0-1 で確定させる。

```
Other,          // 札を付け忘れた呼び出し（現状ゼロであること）
Goad,           // 駆り立て: カリ → 隣接する最高攻撃力の味方・毎ターン（第52期）
RallyOpening,   // 号令: ガン → 開戦時
RallyTurn,      // 号令: ガン → 毎ターン
Bind,           // 縛め: クグ → 縛った味方 +16
Drifter,        // 移り木: シオ → 動かされた味方
Sharer,         // 分かち: ドハ → （Phase 0-1 で確定）
Regurgitate     // 吐き戻し: ゴルム → 守った相手（engine 側の唯一の経路）
```

**`DullRoute` に倣って、各行に「誰が誰を・いつ」をコメントで書くこと。**
`DullRoute` のコメントが第44期以降の判断で繰り返し使われている。

### 2-3. 自己強化は触らない

8本の自己強化（怒り・庇う・墓守2本・断罪者・棘・澱み喰い・軋み）は**`AtkBonus` を直接叩いたまま残す。**

**これは意図的な非対称であり、報告書に明記すること。**
理由は §0 に書いたとおり——窓口は将来の横取りの立ち位置になるので、
自己強化を通すと「自分の被弾で自分が強くなる」が他人に横取りされる形になる。

## 3. 診断モード `whet`

`BattleSim` に追加する。**出力は `docs/` に置かない**。
`CompareBuilds()` / `Stages` / `Columns` を触らないこと。

**この期の実質的な成果はこの診断である**（窓口は挙動不変なので `compare` は動かない）。

| 列 | 中身 |
|---|---|
| 強化総量 | 1戦あたりの `Whet` の総量 |
| **経路別** | 内訳（`WhetRoute` ごと） |
| **受け手** | **誰が強化を受けたか**の内訳（上位10体） |
| 弱体総量 | 参考として `Dull` の総量（既存の集計） |
| **収支** | 各駒について `Whet − Dull` の正味 |
| **死蔵** | **強化を受けたのに一度も攻撃しなかった駒への付与量** |
| 逆しま | **ウツが受けた強化の量**（逆しまの半減側に落ちた回数） |

**「強化総量」と「死蔵」を分けること。** 第42期以降、
生成量ではなく効いた量で判断するのが標準になっている
（アーマーは吸った量、転嫁は効き、貫きは後列到達、駆り立ては対象が与えたダメージ）。
**渡した量は成果ではない。**

**「収支」がこの期の主要な出力。** 同じ `AtkBonus` に対して
上げる側と下げる側の両方が動いているので、**駒ごとの正味が初めて見える。**
第52期に「カリはウツの呪いを『治して』殺す」（与ダメ 127.7 → 28.5）が観測されたが、
あれは診断を1つ作って初めて見えた。**窓口ができれば全駒について常時見える。**

**陽性対照を必ず置く**（第55期の `audit` の作法）:
**経路を1本わざと窓口から外した版**を作り、`whet` がその経路の欠落を検出できることを確認する。
**「0件でした」が検出器の故障と区別できない**ため。

## 4. 予測（実装の前に書き、報告書に当否を載せる）

窓口は挙動不変なので、予測するのは**分布**である。

1. **強化総量の経路別の内訳。** どの経路が最大か。
   把握では**縛め（クグ・+16）が1回あたり最大**だが、
   **号令（毎ターン）と駆り立て（毎ターン）は回数が多い**。**総量でどれが勝つか**
2. **受け手の偏り。** 第44期に「敵由来の供給は肩代わりの網が決める」、
   第52期に「なまりは守られた駒に乗る」が出ている。
   **強化も網の影響を受けるか**——吐き戻し（ゴルム）と分かち（ドハ）は
   「守った相手」に乗るので、**受け手が網で決まるはず**
3. **収支が負になる駒がいるか。** `Dull` の受け手と `Whet` の受け手が重なる駒は、
   正味でどちらに振れるか
4. **死蔵率。** 強化を受けたのに攻撃しない駒——**不動のカド・据えのバン・
   オーラ型の駒**が受け手に入っていれば死蔵する
5. **ウツへの強化量。** 第52期でカリがウツを殺したが、
   **他の経路（号令・移り木）もウツを殺しているはず**。何回起きているか

**予測を外したら、外した理由を報告書に書く。**

## 6. 実装上の注意（既知の落とし穴）

1. **`Dull` と対称に作る。** 引数の形・集計の持ち方・`AcceptsSupport` の扱いを揃えること。
   **非対称にすると、次に読み手を作るときに2つの窓口の差を毎回思い出す必要が出る**
2. **`Dull` は `amount <= 0` で早期 return している**（把握）。
   `Whet` も同じにするか、**負の値を渡せるようにして `Dull` と統合するか**を判断すること。
   **指示書の推奨は「統合しない」**——1つの関数が符号で挙動を変えると、
   横取りの立ち位置が2つの意味を持ってしまう。**判断と理由を書くこと**
3. **ウツ（逆しま）の符号の検算。** `AtkBonus` が正か負かで攻撃力が3倍にも半減にもなる。
   **窓口を通しても符号が変わる瞬間がずれないこと**を、
   ウツを含む行の `compare` が1セルも動かないことで確認する
4. **engine 側の1本（吐き戻し・ゴルム）も通すこと。**
   `BattleEngine.cs` にあるので見落としやすい。
   **`Dull` も engine 側の1本（分かちのなまり）を通している**ので対称
5. **`Other` ルートが0件であることを確認する。**
   `DullRoute.Other` は「現状ゼロ」とコメントされている。同じ状態にすること
6. **長時間ジョブはフォアグラウンドで1ツール呼び出し内に収める。** 背景に回さない。
   第55期の実測では `reseat` が367秒・全生成物で603秒なので、
   **`docs/` の再生成が要る場合は2分割の手順に従うこと**
