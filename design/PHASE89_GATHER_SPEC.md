## 0. 主題

### 0-1. 何を変えるか

**廃棄聖騎士ガルド（`GuardianTrait`）が、庇ったときに隣の味方の傷をひとつ引き受ける。**

現行の `PlusText`: 「**味方への攻撃を肩代わりし、その傷のぶん強くなる**」
新: 「**味方への攻撃も傷も肩代わりし、その傷のぶん強くなる**」

**1文のまま。** 今の文にある「傷」はダメージのことだが、**状態異常の傷も肩代わりする**ようにすれば
語を足さずに済む。**新しい `TraitId` を作らない**（ガルドは `Guardian` ＋ `Stoic` の2つのまま）。

### 0-2. なぜ今それが候補か（**すべてリポジトリで確認できる事実**）

1. **第85期の採用で、味方の傷の供給と読み手が両方とも盤面に常設された。**
   供給＝巻き込み則（`SpillWoundRule`・書き手6枚）、読み手＝縫いのハリ（`SutureRule.Both`）。
   **したがってこの変更は第88期 §8-3 の「規則どうしの AND ゲート」に当たらない**
   ——鎖の両端が既にあり、足すのは**中継1枚**である。

2. **足りていないのは深さである。** 第86期の実測: リィカ（開戦時1回の供給）は
   **「載る率 82.1% で2位なのに深さ 1.30 で最小」**。
   > **供給の周期は「載る率」と「深さ」を別々に決める。一回きりの供給は広く浅く、毎ターンの供給は狭く深い。**

   味方の傷を読む唯一の駒（ハリ）は**深さを読む**（`PerWound` × 傷の数）。
   **浅く広い在庫を、深い在庫に変える装置がロスターに1つも無い。**

3. **ガルドは構造的にその置き場に向いている。**
   - `Stoic` により**1体を選ぶ回復・強化を受け取れない**ので、**ハリの繕い先には絶対にならない**
     （`MostHurtAlly` の `AcceptsSupport` の濾しで落ちる。第86期の自己検査 (e) で 0 回を確認済み）。
     **傷を集めるが、自分は治らない。** 集めた傷を使うのは必ず他人になる。
   - **ガルド自身は傷を1つも読まない。** 自己完結しない。
   - HP100 でロスター最高クラス。**傷の貯蔵庫として落ちにくい。**

4. **役割が topology の3段にそのまま嵌まる。**
   **源**（巻き込み則の6枚・広く浅い）→ **中継**（ガルド・集約して深さを作る）→ **終端**（ハリ・深さを回復に変える）。

### 0-3. この期に片付ける2つの後始末（**本編より先に。どちらも baseline を動かす**）

第88期が次期の入口として残したものが2つあり、**どちらも測定の土台を動かす**ので本編の前に閉じる。

- **(P1) 第87期（ミオの着火）の再判定。** 事前登録した規約では落ちたが、事後の別読みでは通った。
  **同じデータで覆さない**——増分尺度の物差しを規約として先に固定し、**別の標本で測り直す**（§1-1）。

### 2-2. 書き方

`GuardianTrait` に `OnDamaged` を override する（**`RedirectGainTrait` には置かない**）。

```
guarded = self.Counter(PendingKey) > 0        // ★ base より先に読む（base は冒頭で 0 に落とす）
base.OnDamaged(ctx, self, dmg, source)         // 現行の育ちはそのまま
if (!ctx.Gather.Enabled || !guarded || !self.IsAlive) return
donor = 隣接する生存味方（self を除く）のうち Wound が最も深い者   // 同数は ctx.PickOne
if (donor is null || donor.Wound <= 0) return
donor.Wound -= 1 ; self.Wound += 1
ログ（引き受けたことが分かる文言・LogKind.Trigger）
```

- **1回の庇いにつき1つ。** 傷の数にも `dmg` にも比例させない（第84期の単価の壁に自分から入らない）。
- **移すのであって増やさない。** 盤面の総量は保存する。**自己検査で総量の一致を確認する。**
- **`dmg` を発生させない。** `AtkBonus` が動かないこと、`ctx.Heal` を通らないことを守る。
- **隣接の窓口は `Stoic` が使っているものと同じにする。** 新しい隣接の読み方を作らない。
- **`ctx.Gather` を `BattleContext` / `BattleEngine.Run` に省略可能引数で通す。** 既存の作法どおり。
- **ガルドは傷を1つも読まない。** この期にガルドへ読み手を足さない（自己完結させない）。

### 2-3. 表の更新（**採用したときだけ**）

  **`Where.Ally` ではない**（他人には配らない）。

- **`MartyrTrait` には何も足さない。**

## 7. 実装の注意

- **`RedirectGainTrait` を触らない。** 庇う（ガルド）と殉教（敵）は1行も違わない実装を共有していて、
  そこに手を入れると敵側にも生える。**`GuardianTrait` の override だけで閉じる。**
- **`PendingKey` を base より先に読む**（§2-2 の ★）。base は冒頭で 0 に落とす。
- **`OnCarryOver` を増やさない。** 引き取った傷は `StatusKeys` なので既存の境界の掃除に乗る。
- **`ctx.PickOne` は候補 0 個・1 個では `Roll` を消費しない。** 同数のタイブレークに使ってよい
  （乱数列が動かないことは第34期の p=50 同値検証で確認済みの性質）。
- **破片（`Armor`）が全額吸って `OnDamaged` まで届かない場合がある**（`OnCarryOver` の doc に記載）。
  **そのとき印は立ったままなので、引き取りも走らない。** これは仕様として維持し、実測で回数を出す。
- **ヴェルの蘇生で戻った駒の傷。** 既存の扱いに従い、**新しい持ち越し規則を作らない。**
