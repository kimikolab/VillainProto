## 0. 指示書からの差分（2件・どちらもこちらの判断）

### (1) §1 のマイナスを差し替えた（ポンの指示）

    旧: 敵から受けたダメージは灰にならない。味方が味方を傷つけない編成では、攻3の体でしかない
    新: 灰を溜めたまま倒れると、その灰が隣接する味方に降る（等分）。敵から受けたダメージは灰にならない

あわせて §1-1 のノブに **`AshRule.FalloutOnDeath`（既定 true）** を足した
——**マイナスを 0 にする対照**が無いと、新しいマイナスの代金を測る手段が1つも無くなるため。

### (2) キリを `Presets` からは外さなかった

指示書 §1 の「枠」は「キリは `UnitCatalog` に残し、`All`／`Presets` から外す」だが、
**`Presets` から外すと §2-1 の回帰（ススを含まない行が `docs/balance.md` と 0 件差分）が
原理的に成立しない**（キリを含む `compare` 2 行が消える／差し替わるため）。

**第139期のエグとまったく同じ扱いにした**——`All` から `Retired` へ移し、`Presets` には残す。
`All` は「編成に選べる 52 枚」の定義であって `Presets` が参照できる集合ではない（第108期）ので、
**差し替えだけでは盤面は1ビットも動かない**。これが自己検査 (a) の中身である。

### (3) `AshRule` は `Run` の引数を1本増やした

指示書 §1-1 は「`Run` の引数を増やさず、既存の規則の束にフィールドとして足す（第154期・第178期の作法）」
と書いているが、**あの2期はどちらも<u>自分の期のノブを自分の型に</u>足している**
（第154期 = `WardRule` ／ 第178期 = `EmberRule`）。**この期には置き場になる自分の型が無い。**

他人の型（`ShrapnelRule` など）にフィールドを足すと **`docs/rules.md` のその行の既定値が動く**ので、
**規約 (G8) の必須3「触っていないノブの既定が動いていない」がそのまま偽**になる。
第138期が `ShrapnelRule` に畳んだ理由（`Run` の引数を2本増やすと `compare` がスタックを踏む）は
**第139期に `Prog.Body` / `Entry.Main` の側で解けている**ので、**1本だけ増やした**。

実際に `docs/rules.md` の差分は**新しい行1本と本数の2行だけ**で、既存のノブの既定値は1つも動いていない。

### 実装の置き場所

**溜める側だけが engine にある**——`ApplyDamage` が `target.Hp -= amount` を実行した直後の
`NoteAsh` **1箇所**。惨禍・据え・散開・萎縮・肩代わり・破片・受け流し・猶予・身構え・上限を
**すべて通った後の実額**で溜まるので、帳簿の `DamageTaken` と定義上ずれない（第115期）。
**死亡判定より手前**に置いてあるので「最後の一撃だけ灰にならない」という穴が無い。

**撒く側・降らす側は `AshTrait` の中**にある（`OnAction` / `OnDeath`）。**engine には規則を1本も足していない。**
保持者が盤上にいなければ `AshBinding`（`_ashHolders.Count > 0`）の比較1つで抜ける
——軛の `Cap` 判定・粛の保持者走査と同じ短絡の作法。

**新しい窓口**: `StatusKeys.Ash`（`All` に足したので会戦の境界で消える）／`AshRule`（4ノブ）／
`UnitTally` の計数 7 本（`AshGained` / `AshFires` / `AshSpent` / `AshPeak` / `AshDry` / `AshAtDeath` / `AshResidual`）。

**「全体攻撃は体数ぶん得」は灰が敵1体のHPを下回るあいだしか成り立たない。**

## 10. ポンが遊んだ後に答える問い（指示書 §5 そのまま）

1. ススを誰の隣に置いたか。灰は読めたか（「今投げると大きい」が分かったか）
2. 燃焼軸は「脆い」から抜けたか。カド隊は「味方もろとも」から抜けたか
3. 強すぎたか。どの隊で、どの波で
4. 体数の多い敵（先遣4体・M5）と少ない敵で、使い分けたくなったか
5. 「自傷を投げ返す」絵は、連鎖として気持ちよかったか

**数字の側から先に1つ言っておく**——変化表の **6 行中 4 行が第2〜5波すべて 100.0%** に張り付いた。
**強すぎる可能性がいちばん高いのは `死軸×ヒヨ`**（77.9 → 100.0・1回に 109 の灰を撒く）で、
弱めるなら触る順は **`Multiplier`（既定 100）→ 速さ（6）→ `CountDot`** の順になる
——**`FalloutOnDeath` は代金として効いていない**ので、そこを触っても何も変わらない（R286）。
