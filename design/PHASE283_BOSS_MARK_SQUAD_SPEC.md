## 0. 背景と本期の狙い

第282期（design/PHASE282_TOME_NO_CONSUME.md）の結論:

- 消費廃止（T1n）で爪痕は 626 → 1,400（ドハ壁・R377「供給と保存の効きは掛け算」）
- それでも勝率 0%。**残る律速は隊の寿命**（規定の寿命では T3〜T4 で崩れる）
- 寿命だけ伸ばした仮想版では **ソラザン台 × T1n は寿命×2 で 100%（T6）**

つまり R375（到達 ＝ 恒久の削りの速さ × 寿命）の速さ側は解決済みで、残るは寿命側。
そして寿命側には**機構を足さない手**がある——台にヒーラー・守りの駒を挿す編成探索。
本期はそれを測る。届けば「標軸がボスを割る」が**プレイヤーの編成判断の範囲**で成立する。
届かなければ、火力側の残件（炸裂の連射化・標の引き継ぎ）へ進む根拠が確定する。

**ポンの制約（本期の憲法）**: **ヒーラーは台に1枚まで。** ツギとリリの同時編成は禁止。
理由は「軸に関係なく強すぎる」——ヒーラー2枚で届いても、それは標軸の到達ではない。

## 2. 段1 —— ボスの標台の寿命探索

### 2-1. 台の形

- **固定枠**: トメ（T1n・砲）＋ ザン（供給）。第282期の実測より、供給が立つ壁（ドハ）または
  ソラザン系が土台。
- **探索枠**: 残り3枠を {壁・守り・ヒーラー} の候補から組む。
  - 寿命側の候補（ヒーラー以外）: ヒサ（守りの標＝被ダメ半減）・ドハ（分担）・バン（範囲の盾）・
    ゴルム（巨躯）・セッキ・ガルド ほか、Phase 0 で棚卸しした守りの駒
  - ヒーラー候補: ツギ・リリ・シオ・ベニ ほか、**回復供給を持つ駒を Phase 0 で機械的に列挙**し、
    その集合から**最大1枚**（0枚の版も必ず測る）
- 探索は格子（候補 × 席）を `bosswave` で回し、seed 帯で検証。台数が多すぎる場合は
  寿命の机上換算（§2-3）で足切りしてよいが、足切りの基準は測る前に書くこと。

### 2-2. 対照（傷軸の検死の適用・最重要）

届いた台（勝率が 0% を離れた台すべて）に対し、**トメをドルガに差し替えた版**を同条件で測る。

- ドルガ版も届く → 勝たせているのはヒーラー・守りであって標の機構ではない（傷軸の死因と同型）。
  その台は「到達」と数えない
- ドルガ版が 0% に落ちる → 爪痕由来の到達。これが本期の勝利条件

### 2-3. 机上の寿命換算（実装前に書く）

第282期の実測（規定寿命で T3〜T4 崩壊・×2 で足りる）を基準に、候補ごとの寿命寄与を先に数える:

- ヒサ: 守りの標の被ダメ半減が何割の被弾に掛かるか（ボスは全体攻なので対象1体のみ）
- ツギ: 板（最大HP×40%）がボスの全体攻で1ターンに何回剥がれるか
- リリ・シオ・ベニ: 回復量／ターンと、ボスの攻の天井（12+11t）と交差するターン
- 「×2 相当」に届く組があるかを宣言してから測る

## 3. Phase 0（実装前の調査）

1. **ヒーラーの機械的定義**: 「味方への回復供給（`ctx.Heal` の書き手）を持つ味方駒」を grep で列挙。
   境界（ゴルムの還し＝倒れたとき1回・ベニの反転結界 等）をどちらに数えるかを先に決めて明記。
2. 守りの駒の棚卸し（被ダメを減らす・肩代わりする・逸らす駒）。R374 の 0化（受け流し・庇い）で
   ザンの仇指しを殺す駒はその旨を注記（ガルドが先例）。
3. ツギの板・リリの吸い・シオの退避がボス（1体・全体攻）で機能するかのコード確認。
4. ボスの全体攻に対する各候補の挙動（全体は庇えない・標に引かれない等、介入の前提確認）。
5. `bosswave` の台数上限と実行時間の見積もり。
6. `design/` を grep（ボス向けの台探索・ヒーラー枚数制約の過去の扱い）。

## 4. 予測（実装前に宣言・候補の実数を数えて書き直すこと）

- ヒーラー1枚＋ヒサ入りの台が最有力（半減が寿命×2に最も近い）。
- ヒーラー0枚の版は ×2 に届かず 0% のまま。
- 届いた台のドルガ対照は 0%（爪痕が無いと回復に押し返される）——これが出れば標機構由来の証明。
- 本編 `compare` は本期で1セルも動かない（台は bosswave 専用・ロスターと規定は段0以外触らない）。

## 6. 受け入れ基準と採否

- 到達の定義: **ヒーラー1枚以下の台で勝率が 0% を離れ、かつドルガ対照が 0% に落ちる**こと。
- 届いた場合: その台を標準の標台として design/BOSS_SUMMARY.md を更新。
  残件（炸裂の連射化・標の引き継ぎ・火付けの矢）は「火力はもう足りている」前提で優先度を下げて記録。
- 届かない場合: 寿命の不足量（×いくつ相当足りないか）を数値で残す。
  次期は火力側——**炸裂の連射化（累積読み: 書かれた延べ回数＝発数。R376 の影響を受けない）**が
  筆頭候補になる旨を残件に記す。
- 採否分岐: **A3 = 届いた台を標準化 ／ B3 = 届かず・火力側へ**——結果が決めるが、確定はポン。
