## 0. この期の主題

**ロスターに存在しない「役」を作る。**

第48期の棚卸しで、10通貨すべてについて厚みを数えた。そこで見えたのは、
**すべての軸が「同じ通貨を厚くする」方向を向いている**ということだった。
毒を5枚、死を9枚、弱体を5枚——**幅を要求する駒が1枚もない。**

この期で作るのは、**味方が背負っている状態異常の「種類数」を読む駒**である。

- **量ではなく種類を読む。** 量を読むと、供給が最も厚い通貨（毒・死）に吸われて
  実質そちらの軸の駒になる。第41期に突き返しが喧噪だけに食われたのと同じ形
- **敵ではなく味方に付いている種類を読む。** 敵に載せる型は毒軸が既に持っているので、
  そちらだと既存の下位互換になる。味方側なら**マイナス特性の多様性そのものが力になる**
- **閾値は威力ではなく振る/振らないを切る。** 種類数をダメージに変換すると、
  多様性が単調な量に潰れる（第46期に「集合を1つの値に潰す操作は単調になる」が出ている）。
  **閾値を跨ぐと効果の種類が変わる**形にする

第38期にナタの閾値が「傷2つ開くまで振らない」という定数規則になり、
分散ゼロでプレイヤーに読める形になったのが前例である。

## 2. Phase 0（実装の前に必ず走らせる。**数える対象の確定がこの期の設計の半分**）

結果は報告書の冒頭に数字で書くこと。

1. **味方に載りうる状態異常を、経路つきで全部列挙する。**
   `SetCounter(StatusKeys.X, ...)` と `ctx.Ignite(..., friendly)` の全呼び出しを走査し、
   **対象が味方（`ally` / `self` / `victim` / 味方チームの駒）になっているものだけ**を抜き出す。

   指示書の把握では以下だが、**必ず数え直すこと**。特に `Wound` は
   味方に載る経路が無い可能性がある。

   | 種類 | 味方に載る経路（把握） |
   |---|---|
   | `Poison` | 瘴気（グザ）の味方漏れ／毒撃（スィド）の隣への漏れ |
   | `Marked` | 囃し立て（ヒサ）が隣接する味方に付ける |
   | `Stun` | 縛め（クグ）／仇討ち・責め苦・抉りの**自分に課す反動**／敵の断罪3体 |
   | `Burn` | `ctx.Ignite(target, friendly: true)` の呼び出し元 |
   | `Wound` | **無い可能性が高い**（裂き・刻みは敵向け） |

   **この一覧が「種類数の分母」**になる。分母が4か5かで閾値の設計が変わる。

2. **`Armor` と `IdleTurn` を数える対象から外す判断を確認する。**
   - `Armor` は damage 側で消費される**プラスの資源**。数えると
     ヒビ1枚で種類数を稼げる抜け道になる
   - `IdleTurn` は**痺れると engine が自動的に立てる**（`BattleEngine.cs` の
     `Stun > 0` の分岐）。数えると1経路で2カウントになる

   **指示書の指定は「両方とも数えない」。** ただし Phase 0 で engine の実装を確認し、
   `Stun` と `IdleTurn` が本当に同時に立つかを検算すること。**違っていたら報告する**

3. **状態異常の寿命を確認する。** 毒・燃・痺・標がそれぞれ何ターン残るか、
   `TickStatuses` でどう減るか。**種類数が同時に成立する時間窓**の計算に使う（予測1）

4. **状態異常の「肩代わり」が既に存在しないことを確認する。**
   第48期の別表2では、状態の肩代わりは弱体専用の2枚（集約・渡し）だけだった。
   **状態異常そのものを移す経路が無い**ことがこの駒の前提になる

5. **`docs/balance.md` の現在値を控える**（50行 × 5波 = 250セル）。§6 の回帰チェックの分母

6. **残り枠を確認する。** 第48期の判断では `UnitCatalog.All` の47が分母で残り5。
   **この期で1枚使うので残り4になる**ことを報告書に書くこと

## 3. 実装

### 3-1. 特性 `TraitId.Scapegoat`（業）

```
Scapegoat,   // 業: 味方の呪いを引き取って歩く。種類が揃うと、溜め込んだものを殴った相手に返す
             // （引き取るほど自分が壊れる。1つの動作の表と裏）
```

**プラス・マイナスのどちらのブロックにも入れない。**

可動部は3つ。第47期の鱗（供給・発揮・消費）と同じ構成で、**1枚の中で1サイクルが閉じる**。

#### (1) 引き取り —— `OnTurnStart`

生存する味方（自分を除く）が持つ状態異常のうち、
**自分がまだ持っていない種類を1つ**選び、**その味方から自分へ移す**。

- **「移す」であって「複製する」ではない。** 味方からは減り、自分に増える
- 移す量は **1**（カウンタを1だけ移す。相手が1しか持っていなければ相手は0になる）
- **自分がまだ持っていない種類を優先する**のが要点——種類数を増やす方向に働き、
  閾値へ向かう。候補が複数あれば `PickOne`
- 自分が持っていない種類が無ければ**何もしない**（既に持っている種類は増やさない）
- **`AcceptsSupport` を見ない。** 呪いを引き取るのは支援ではない。
  ただし**そう判断したことを報告書に明記する**（第42〜44期で扱いが不揃いなまま来ている）

#### (2) 発揮 —— `OnAfterAttack`

自分が背負っている**種類数**が `Threshold` 以上のとき、
攻撃した相手に**自分が背負っている全種類を1ずつ付ける**。

- **種類を選ばない**（全部付ける）。選択を入れると可動部が増え、
  第46期の教訓（1変数に絞ったから切り分けられた）に反する
- **閾値未満のときは何もしない。** 段階を2つ作らない
- 付ける先は攻撃した相手1体のみ

#### (3) マイナス —— 引き取ったものは自分に効く

**特別な実装は不要。** 引き取った毒は自分を削り、痺れは自分の手番を奪い、
燃焼は自分を焼く。**引き取るほど自分が壊れるのがこの駒の代金**である。

- **代金を軽くする細工をしないこと。** 痺れの耐性や毒の軽減を持たせると、
  引き取りが無償の防御になって符号が反転しなくなる

### 3-2. 強度のノブ —— **候補を2つ挙げる。Phase 0 の後に選ぶこと**

第41期と第47期は**律速でない項にノブを付けて掃引が空振り**した。
今回は**先に収支を出してから**決める。

| 候補 | 定義 | 何を切るか |
|---|---|---|
| **A: `Threshold`** | 発揮に必要な種類数（掃引 2 / 3 / 4） | **どれだけ幅を要求するか。** 閾値に到達しなければこの駒は完全に無力なので、律速項である可能性が高い |
| B: 引き取りの量 | 1回に移すカウンタ量（掃引 1 / 2 / 3） | 引き取りの速度。ただし**種類数は量に依存しない**（1でも種類は1）ので、閾値には効かない |

**指示書の推奨は A。** B は「種類を読む」という設計の律速項ではない——
1カウント移せば種類は成立するので、量を増やしても閾値到達時刻は変わらない。
**Phase 0 の予測（§5-1）で到達時刻を計算し、A が律速であることを確認してから確定すること。**
確認の結果 B のほうが律速なら B を採ってよい。**判断と根拠を報告書に書く。**

```
public readonly record struct ScapegoatRule(int Threshold)
{
    public static ScapegoatRule Default => new(3);
}
```

`BattleEngine.Run` の引数に足す（既存の各 `Rule` と同型）。**static のノブは置かない**。

### 3-3. 駒 `UnitCatalog.Gou`（業のゴウ）

```
Id = "gou", Name = "業のゴウ", MaxHp = 88, Attack = 7, Speed = 4,
Traits = { TraitId.Scapegoat }, Pattern = AttackPattern.Single
PlusText  = "毎ターン味方の状態異常を1つ引き取る。種類が3つ揃うと、殴った相手に全部返す"
MinusText = "引き取った呪いは自分に効く。味方が綺麗なら何も起きない"
Flavor    = "他人の呪いを引き取って歩く。溜め込んだものは、いつか誰かに返す。"
```

数値は探索段階の初期値。**掃引の対象はノブ1つだけ**で、HP・攻・速は振らない。
速4 と遅めにしてあるのは、痺れを引き取っても失うものが小さいため。

### 3-4. compare への追加 —— **2行**（供給の種類を変える）

```
("業 (ゴウ×◯)", ...)      ← 種類が揃いやすい台（呪いの供給源を3種類以上入れる）
("業改 (ゴウ×◯)", ...)    ← 揃いにくい台（1〜2種類しかない）
```

- **2行の狙いは「閾値に届く台と届かない台」を両方持つこと。**
  第47期に「未纏は全10セル 0.0%」が出たように、**届かない台がどう潰れるか**も情報である
- 相方は Phase 0-1 の経路一覧から選ぶ。**毒（グザ・スィド）／標（ヒサ）／痺（クグ・反動3枚）／
  燃（ボルグ）**が候補
- **予算壁に注意。** 供給を3枚積むと払い出しが3枠になり、直近の実測では
  4枠の払い出しは 20% 台に潰れる。**土台と兼ねる駒を選ぶこと**
- 配置は §1 の作法で決める

**既存50行は1つも触らない。**

## 4. 診断モード `scapegoat`

`BattleSim` に追加する。**出力は `docs/` に置かない**。
`CompareBuilds()` / `Stages` / `Columns` を触らないこと。

| 列 | 中身 |
|---|---|
| 引き取り | 回数/戦・**種類ごとの内訳**・取った相手の内訳 |
| 空振り | 引き取れる種類が無くて何もしなかった回数/戦 |
| **種類数** | ゴウが背負っている種類数の 最大 / 平均 |
| **到達** | **閾値に初めて達したターン**（達しなかった試行は別途カウント） |
| 成立率 | 閾値を満たしていたターン数 / ゴウの生存ターン数 |
| 転写 | 発揮した回数/戦・**付けた種類の内訳** |
| **転写の効き** | **付けた状態異常が、その後どれだけダメージ／効果に変わったか** |
| 自傷 | ゴウが引き取った呪いで受けたダメージ・失った手番 |
| 味方の救済 | **引き取りによって味方が受けずに済んだダメージ**/戦 |

**「転写」と「転写の効き」を分けること。** 第42期は「生成したアーマー」ではなく
「実際に吸った量」、第43期は「流した量」ではなく「効き」、第47期は「貫き」ではなく
「後列到達」で判断した。**付けた回数は成果ではない**——
敵が次のターンに死ぬなら毒を付けても意味がない。

**「自傷」と「味方の救済」を両方数えること。** この駒は
**引き取りが防御でもあり自壊でもある**ので、収支がどちらに振れるかが性格を決める。

**陽性対照を必ず置く**: **同数値・特性なしの素体**を診断のローカルに置いた版。
第47期に `ScaleRule(0)` が陽性対照にならなかった（消費だけ止めて供給も発揮も止めない）
という失敗があるので、**ノブを 0 にする形の対照は使わない**。

**発火しなかったことは盤面の値に痕跡を残さない**ので、ログか `Events` から数えること。

## 5. 予測（実装の前に書き、報告書に当否を載せる）

**軸の名前ではなく、窓口を通る駒の在庫で書くこと。**
第44・46・47期は3期連続で**「供給が実際に流れるか」を数え損ねて**外している。

実装の前に以下を書き出す。

1. **2つの台それぞれの「到達ターン」を計算する。** ——**ノブの選択（§3-2）はこの計算に依存する。**
   引き取りは1ターン1種類なので、**閾値3なら最短3ターン**。
   ただし**味方がその種類を持っていなければ引き取れない**ので、
   Phase 0-1 の経路と Phase 0-3 の寿命から、**各ターンに盤面に何種類あるか**を出すこと
2. **状態異常の寿命と引き取り速度の関係。**
   引き取る前に消えてしまう種類があるはず（燃焼は数ターンで切れる）。
   **同時に3種類が成立する時間窓があるか**
3. **自傷と味方の救済の収支。** 引き取った毒・燃焼で1戦にいくら失うか
4. **転写の効き。** 付けた状態異常が実際に効くのは、
   **敵側にその状態を読む駒がいるか、単純にダメージになる場合だけ**。
   第48期の棚卸しで**敵側の読み手は10通貨すべてで0**と確定しているので、
   **転写が効くのは毒と燃焼（継続ダメージ）だけのはず**。
   標・痺は敵に付けても読み手がいない——**痺は行動を止めるので効くが、標は効かない可能性**
5. **閾値に届かない台がどう潰れるか。** 第47期の「未纏は全10セル 0.0%」と同じになるか
6. **`seats2` で2行の席がどうなるか**（隣接を使わないので対照値として記録）

**予測を外したら、外した理由を報告書に書く。** 当てることが目的ではない。

## 6. 受け入れ基準

**分母を必ず書くこと**（「食い違い 0 件」ではなく「250 セル中 0 件」）。

   50行 × 5波 = 250 セル中の食い違い件数を書く
2. **ゴウを入れない行が `ScapegoatRule` の値に対して不変**
3. **引き取りが実際に走っている**（`scapegoat` の「引き取り」が 0 でない）。
   2行とも 0 なら台の組み方が間違っているので報告して止める
4. **閾値に到達している**（「到達」が記録されている台が最低1つ）。
   2行とも未到達なら閾値かノブの設計が間違っているので報告して止める
5. **新2行が崖になっていない。** 5波の勝率が 0.0 と 100.0 だけで構成されていないこと

### 採否の判断材料（落ちても差し戻しではない）

6. **「転写」に対する「転写の効き」の割合。** 低ければ、
   **敵に読み手がいない以上、状態異常を敵に付けても意味が薄い**ことになる。
   その場合は「種類数を読む」方向は残したまま、発揮先を変える案を残件に書く
7. **自傷と味方の救済の収支。** どちらが大きいかでこの駒が攻撃型か防御型かが決まる
8. **閾値に届く台と届かない台の差**。届かない台が 0.0% に潰れるなら、

9. **ノブの掃引の全幅。** 第41期（`ShoveRule`）と第47期（`ScaleRule`）は
   ともに全幅1pt未満で空振りした。**3度目なら、ノブの選び方に構造的な問題がある**ので

10. `seats2` で2行の席（参考値）
11. 波間相関6ペア。**2行足すので組成効果が出る。50行と52行の両方で測り直して比べること**
12. **第五波の平均**と**主判定17行に固定した第二波の平均**。
    行集合に依存する量は参考値として併記するだけ
13. 固有の勝者・敗者の増減。**厳密版（=100 / =0）と緩い版（90/10）のどちらを使ったか毎回書く**

## 7. 実装上の注意（既知の落とし穴）

1. **`Armor` と `IdleTurn` を種類に数えない**（§2-2）。数えると抜け道になる。
   **ただし Phase 0 で engine の実装を確認してから確定すること**
2. **標（`Marked`）を引き取ると敵の標的が自分になる。** これは仕様
   （身代わりとしてテーマに合う）だが、**ゴウが集中攻撃を受けて早く落ちる**可能性がある。
   `scapegoat` の「自傷」と、ゴウの生存ターン数を必ず記録すること
3. **痺れを引き取ると自分の手番が飛ぶ。** 発揮は `OnAfterAttack` なので、
   **手番が飛ぶと転写もできない**。引き取りと発揮が同じ資源を奪い合う——
   これは設計として正しいが、**成立率が高いのに転写が少ない**という形で出るはず。
   潰さずに測って記録する
4. **引き取りは味方から減らす。** 味方の毒を引き取ると味方の毒が減るので、
   **味方側の毒を読む駒（澱み喰いなど）の燃料を奪う**可能性がある。
   台に入れる場合は干渉を診断で確認すること
5. **`ctx.Ignite` は専用の窓口を持つ**（`friendly` 引数）。
   燃焼を引き取る/転写するときは `SetCounter` を直接叩かず、
   **既存の窓口を通すか、通さない理由を書くこと**
6. **乱数列がずれる。** `PickOne` は候補2個以上で `Roll` を消費する。
   帰属は**素体との対照**で取る（§4）。ノブを 0 にする形の対照は使わない
7. **長時間ジョブはフォアグラウンドで1ツール呼び出し内に収める。** 背景に回さない

## 8. 手順

1. Phase 0（§2）を走らせ、結果を報告書の冒頭に書く。
   **2-1（味方に載る種類の分母）が確定しないと閾値が決まらない**
2. 予測（§5）を書き出す。**実装より先に**
3. **予測1 の到達ターンの計算を見てノブを確定する**（§3-2）。判断と根拠を書く
4. 実装（§3-1〜3-3）
5. **受け入れ基準1・2を検算する**。通らなければ先へ進まない
6. compare に2行足す（§3-4）。配置は §1 の作法で決める
