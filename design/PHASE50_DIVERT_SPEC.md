## 3. 実装

### 3-1. 特性 `TraitId.Divert`（逸らし）

```
Divert,      // 逸らし: 味方に向いた視線を引き剥がし、敵1体へ向け直す。
             // ただし引き剥がした視線は自分にも刺さる（1つの動作の表と裏）
```

**プラス・マイナスのどちらのブロックにも入れない。**

#### 発火点 —— `OnTurnStart`

1回の発火で以下を順に行う。

1. **外す**: 生存する味方（自分を除く）が持つ `Marked` を**全部 0 にする**
2. **自分に付ける**: 自分の `Marked` を 1 にする
3. **敵に付ける**: 敵陣の生存駒のうち **`TargetCount` 体**に `Marked` を 1 付ける

**選び方は決定的にする。** 敵の選択は
**現在HPが最も高い生存駒から順に `TargetCount` 体**。
同値が並んだ場合のみ `PickOne`。

- **最も硬い敵を選ぶのは意図的。** 集中砲火の意味が最大になり、
  プレイヤーが「どの敵が焦点になるか」を読める
- **`TargetCount` が複数のときは上位から順に**（乱数で散らさない）

#### この形が「1つの動作の表と裏」である理由（実装者向け）

- **味方の標を外す**のはプラス（矛先が減る。第五波でカドが生き延びる）
- **自分に標を付ける**のはマイナス（自分が矢面に立つ。`MarkPullPercent = 75` で狙われる）
- **敵に標を付ける**のはプラス（味方の攻撃が集中し、硬い敵を先に割れる）

**マイナスに特別な実装は不要。** 標を負うこと自体が代金である。
**代金を軽くする細工をしないこと**（回避率や被ダメ軽減を持たせない）。

#### 注意

- **標を「消す」のはこの駒が初めて**（Phase 0-3）。既存の駒は付けるだけなので、
  **ヒサの囃し立てを打ち消す唯一の手段**になる。
  ヒサとの同居が意味を持つか（打ち消し合って何も起きないか）を必ず測ること
- 味方に標が1つも無くても、**自分と敵への付与は行う**（外す対象が無いだけ）

### 3-2. 強度のノブ —— **候補を2つ挙げる。Phase 0 の後に選ぶこと**

第41期（`ShoveRule`）・第47期（`ScaleRule`）は律速でない項にノブを付けて空振りした。
第49期は閾値2→4で転写が 0.58→0.00 と完全に消えたので**ノブ自体は律速項に当たっていた**
（機構が小さかっただけ）。**その診断ができたのはノブを確定させずに渡したから**なので、今回も同じにする。

| 候補 | 定義 | 何を切るか |
|---|---|---|
| **A: `TargetCount`** | 敵に標を付ける数（掃引 1 / 2 / 3） | **焦点の鋭さ。** 1なら集中、3なら分散して効果が薄れる |
| B: 自分に標を付けるか | 代金の有無（対照として 有/無） | マイナスの寄与。ただし**掃引ではなく2値**なので、ノブというより対照 |

**指示書の推奨は A。** ただし B は**対照として必ず1本測ること**——
「味方の標を外す」だけの効果と「自分が矢面に立つ」代金を分離できないと、
符号反転の帰属先が分からない。

```
public readonly record struct DivertRule(int TargetCount)
{
    public static DivertRule Default => new(1);
}
```

`BattleEngine.Run` の引数に足す（既存の各 `Rule` と同型）。**static のノブは置かない**。

### 3-3. 駒 `UnitCatalog.Sora`（逸らしのソラ）

```
Id = "sora", Name = "逸らしのソラ", MaxHp = 96, Attack = 6, Speed = 8,
Traits = { TraitId.Divert }, Pattern = AttackPattern.Single
PlusText  = "毎ターン味方に向いた視線を引き剥がし、いちばん硬い敵へ向け直す"
MinusText = "引き剥がした視線は自分に刺さる。毎ターン狙われ続ける"
Flavor    = "誰かが見られている限り、代わりに見られてやる。それしか取り柄がない。"
```

数値は探索段階の初期値。**掃引の対象はノブ1つだけ**で、HP・攻・速は振らない。
HP96 と厚めにしてあるのは、毎ターン標を負うため。

### 3-4. compare への追加 —— **2行**（カドの有無で分ける）

```
("逸らし (ソラ×カド)", ...)    ← 残件Aの符号反転を再現する台
("逸らし改 (ソラ×◯)", ...)     ← カドを含まない台
```

- **2行をカドの有無で分けるのがこの期の設計。**
  残件Aの符号反転が**カド固有なのか、標の移動そのものによるのか**を分離する。
  これが分からないと「標を操作可能にした」意味が測れない
- カドを含まない台は、標の移動と「敵に焦点を作る」効果だけが残る
- **予算壁に注意。** ソラは攻6 の払い出しなので、土台は打点を持つ駒で組むこと
- 配置は §1 の作法で決める。**採用した席で発火回数が 0 になっていないことを確認する**

**既存50行は1つも触らない。**

## 4. 診断モード `divert`

`BattleSim` に追加する。**出力は `docs/` に置かない**。
`CompareBuilds()` / `Stages` / `Columns` を触らないこと。

| 列 | 中身 |
|---|---|
| 発火 | 逸らしの発火回数/戦。**0 になっていないこと**（§1 の作法） |
| 外し | 味方から外した標の回数/戦・**外した相手の内訳** |
| 焦点 | 敵に付けた回数/戦・**付けた敵の内訳** |
| **焦点の効き** | **標を付けた敵が受けた攻撃の割合**（味方の全攻撃に対する） |
| **撃破順** | **焦点の敵が倒れたターン**（対照との差） |
| 自傷 | ソラが受けた被弾/戦・**標が原因で引いた分**の推定 |
| 寿命 | ソラが倒れたターン（倒れた試行の平均） |
| カド | **カドの生存ターンと反撃回数**（残件Aの再現・カド入り台のみ） |

**「焦点」と「焦点の効き」を分けること。** 第42期は「生成したアーマー」ではなく
「実際に吸った量」、第43期は「流した量」ではなく「効き」、第47期は「貫き」ではなく
「後列到達」、第49期は「転写」ではなく「転写の効き」で判断した。
**標を付けた回数は成果ではない**——味方がそちらを殴らなければ意味がない。

**「撃破順」が本命の指標。** 焦点の狙いは「硬い敵を先に割る」ことなので、
**対照と比べて撃破ターンが早まっているか**で効いたかどうかが決まる。

**陽性対照を3本置く**:
1. 同数値・特性なしの素体（**ノブを 0 にする形は使わない**）
2. `DivertRule` の候補B「自分に標を付けない」版（代金の分離）
3. ソラを外した同じ編成

**発火しなかったことは盤面の値に痕跡を残さない**ので、ログか `Events` から数えること。

## 7. 実装上の注意（既知の落とし穴）

1. **標を消すのはこの駒が初めて。** `SetCounter(StatusKeys.Marked, 0)` が
   既存に1つも無いことを Phase 0-3 で確認してから実装する。
   **消す側の窓口を engine に作らないこと**——この駒の中で完結させる
2. **敵に標が付くのもこの期が初めて。** `MarkPullPercent` が
   両陣営で対称に働くかは Phase 0-2 で確認する。**片側専用なら設計を変える必要がある**ので、
   実装前に分かるようにしておく
3. **庇い・介入との優先順位。** 標と庇いのどちらが先に解決されるかで、
   焦点の効きが変わる。第五波の殉教者（庇う75%）とは特に干渉するはず
4. **ヒサとの打ち消し。** ヒサの囃し立ては開戦時1回、ソラは毎ターン。
   **ソラが後に走れば必ず打ち消す**ので、同居は意味を持たない可能性が高い。
   潰さずに測って記録する
5. **ザン（仇討ち・標にされた味方が殴られると割り込む）との干渉。**
   ソラが味方の標を全部剥がすので、**ザンの燃料を奪う**。
   標の相互唯一ペア（ヒサ⇔ザン）を両方無効化する駒になりうる。測って記録する
6. **乱数列がずれる。** `PickOne` は候補2個以上で `Roll` を消費する。
   帰属は**素体との対照**で取る
7. **長時間ジョブはフォアグラウンドで1ツール呼び出し内に収める。** 背景に回さない
