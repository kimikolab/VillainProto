## 前提の訂正

指示書との食い違いはいずれも**止めずに進めた**。4 件ある。

### 1. 規則 N の「選ぶ」乱数を別系列にすると、抽選そのものが偏った（**測定前に発見して直した**）

最初の実装は指示書 §2-1 の「提示のみ乱数」を守るために、
**提示を `Random(2_000_000 + i)`・N の選択だけを `Random(3_000_000 + i)`** と2本に分けた。
phase0 で N の「攻7以上の期待枚数」が**超幾何の 2.25 に対して 2.36** になった
——10 万標本の標準誤差 0.0034 の **32 倍**で、乱数のばらつきでは説明が付かない。

原因は **`new Random(seed)` が seed の近い2本のあいだで相関すること**
（.NET は互換性のために旧アルゴリズムを使い続けている。2本の seed は定数 1,000,000 差で並走していた）。
**選択も提示と同じ系列から順に引く**ように直したら、超幾何と小数第2位まで一致した（下の §1-2）。

**代償は N の提示が2枚目以降 P/S とずれること**だが、**N は対照であって対標本ではない**ので構わない。
**P と S は同じ系列を共有したまま**なので、S − P の1枚目の提示は完全に同じである。

### 2. 表D は「Q1 を満たした版」ではなく「**その波設定の3規則すべて**」を出した

指示書 §2-3 は表D を「Q1 を満たした版でのみ」と書くが、**Q5 は「S で r が上がるはず」**を問うので、
**1版だけでは答えられない**（比べる相手が無い）。**測る前にコードへ固定した規則**は:

> Q1 を満たした版があればその版の波設定、無ければ**中間帯が最大の版の波設定**を採り、
> **その波設定の3規則すべて**を出す。

結果として Q1 は 0 版だったので、**中間帯が最大の Pw の波設定＝弱い波**で N / P / S の3つを出した
（1版あたり 1,760,000 戦 × 3）。**結果を見てから対象を選んでいない。**

### 3. 表E は6版すべてを出した（**戦闘は1回も足していない**）

指示書 §4 は表E も「Q1 を満たした版のみ」と書くが、**表E は主表の集計だけで作れる**
（新しい戦闘が 0）。判定の対象は Q1 を満たした版という規則を守ったうえで、
**第70期の「弱い波では燃が3本目」の再現**を全6版で確かめるために全部並べた。

### 4. 回収量の分母は5波と第2〜5波で違う（**両方を出した**）

指示書 §0-1 が引く「35pt」は**5波の平均勝率**の差（32.09% 対 67.2%）である。
一方 §0-3 は「中間帯も平均勝率も**第2〜5波**で数える」と決めている。
**同じ実行の中で理想61行を両方の切り方で測り直して併記した**
（第2〜5波 **59.43%** / 5波 **67.54%**。後者は `docs/balance.md` の 67.2% と、
行の重みの取り方だけが違う——`balance.md` は行ごとの平均、こちらは行×波の平均）。

なお**表A・表E の版名は最初 `N（N（無作為） × 既存5波）` と規則名が二重に出ていた。**
実行後に**表示だけ**直してある（`d3RuleBare` を足した1行）。**この報告書の表は直した後の表記で、数値は1つも動いていない。**

## 8. 読めること

### 8-1. 噛み合わせの枚数は、噛み合わせの値段ではない

**S は共有キーの組数を 1.59 → 2.89 に増やし（理想 2.43 を超え）、理想61行との r も上げた。
それでも勝率は下がった。** 第70期は「差 35pt はまるごとシナジーである」と書いたが、
**この期の測定は「シナジー」を『同じキーを共有すること』と定義したときに、その定義が値段と結び付かないことを示した。**

**理想61行の 2.43 という値は、61 行が噛み合わせを 2.43 組ぶん持っているという事実であって、
2.43 組持てば強いという意味ではない。** 61 行はそのうえで**どのキーを・どの向きに・どの席で**噛ませるかを
60 期かけて選んでいる。**S はそのうちの「何組か」だけを再現した。**

### 8-2. キーは通貨の名前であって、通貨の値段ではない

表E の傾きは**キーごとに +19.4 から −15.6 まで 35 pt の幅**がある。
**「共有するキーの数」はこの幅を1ビットも見ていない。**
第69期が「枚数を増やして良くなるキーは 11 本中 2 本（移動・被弾）だけ」と測り、
第70期が「弱い波では燃が3本目」と足したのに、**S の規則はその表を参照していない。**

**次にドラフトの選択規則を作るなら、キーの数ではなくキーの符号を読ませること。**
（この期は設計判断をしないので、そういう規則を作るかどうかは決めない。）

### 8-3. 「キーを共有する駒が多いキー」ほど、規則が連鎖して買ってしまう

傷は5枚・痺は5枚・弱体は8枚が互いに共有する。**1枚引くと残りが全員「共有キー 1」の候補になる**ので、
**保持者の多いキーほど雪だるま式に集まる。** 被弾は 10 枚と最多なのに減ったのは、
**同点のときの判定が攻撃力**で、被弾持ちに攻2〜3 の駒が多いため。

> **共有キー数を最大化する規則は、「キーの保持者数」と「同値判定の軸」の2つで実際の選好が決まる。
> 規則が3行でも、効いているのはロスターの分布のほうである。**

### 8-4. 攻撃力を数えることの価値は、この台では圧倒的に大きい

**P − N は10セルすべて正**（既存波 +4.84〜+13.06 / 弱い波 +15.63〜+24.00）で、
**S − P の 4〜14 倍。** 第70期の「ロスターの 54.9% が攻6以下」という分布がそのまま出ている
——**この台では、まず殴れる駒を確保することが他のすべてに優先する。**

### 8-5. 台はまだ無い（Q1 は3期連続で落ちている）

第69期 17.9%（無作為・第2〜5波）→ 第70期 57.1%（選択 × 弱い波）→ **第71期 57.1%（同じ版が最大）。**
**選択規則を強くする方向では線に届かなかった**——Sw は 54.6% で Pw より低い。
**残っている軸は「敵の攻撃力」か「味方の枚数」**（第70期 §8 の指摘。HP を下げても T_die は伸びない）。

### 8-6. 器具の側で1つ拾った —— 近い seed の `Random` を2本並走させない

前提の訂正 1 のとおり、**`new Random(2_000_000 + i)` と `new Random(3_000_000 + i)` を並走させると
抽選が偏る**（攻7以上の期待枚数が 2.25 → 2.36・標準誤差の 32 倍）。
**phase0 に超幾何との照合を置いていたから測定前に見つかった。**
第69・70期の抽選は**1本の系列**だったので影響を受けていない（実測でも 2.25 / 37.9 / 328 が完全一致）。
