## 0. 主題

### 0-1. 第92期が出した答え

**交差の空白は、台の空白ではなく機構の空白だった。**
11キー55組のうち、繋いでいる機構が実在するのは **12組だけ**。
**足りないのは台ではなく、軸をまたぐ機構そのもの。**

> **この期は交差を引く。1本の規則で3本引く。**

### 0-2. 何を作るか

**傷が3つ溜まると束ねられて「深手」になる。深手を負った駒は、動くたびに傷口が開く。**

| | 規則 |
|---|---|
| **束ね** | 傷が **3** に達すると、傷を 0 に戻して**深手**を 1 立てる。**深手は 0 か 1 の二値** |
| **自傷** | 深手を持つ駒が**実際に行動した**とき、**4** の自傷。**`lethal: true`** |
| **上乗せ** | 深手を持つ駒に**新しく傷が書かれたら、溜まらずその場で 4 のダメージになる** |
| **読み手から見た扱い** | 深手を持つ駒は、**傷の読み手から見て「傷を持っている」**。滲み則は **+1 ではなく +2** |
| **解除** | **この期では解けない**（§0-4） |

**両陣営に等しくかかる。** 第85期の巻き込み則が既定なので味方も傷を負う。
**非対称なのは「こちらは規則を知って編成を組める」の一点だけで、マイナスを別に足さない。**

### 0-3. これで交差が3本増える

| 交差 | 誰が読み手になるか | 1文も増やさない |
|---|---|---|
| **傷 × 被弾** | 憤怒のムド／廃棄聖騎士ガルド／分かちのドハ／後備えのセッキ | ○ |
| **傷 × 死** | 墓守のリィカ／継ぎ接ぎのヴェル／追い打ちのハギ／破裂のゾト／疫みのラウ | ○ |
| **傷 × 毒（強化）** | 滲み則が +1 → +2 | ○ |

**engine の規則1本で既存駒が読み手になる**——第90期の滲み則と同じ構造。
**新しい `TraitId` ゼロ・駒ゼロ。** `StatusKeys` に1本足すだけ。

### 0-4. 設計上の判断（**すべて測る前に固定。振らない**）

1. **深手化で傷が 0 に戻るのは「消えた」のではなく「器が変わった」。**
   だから**深手は傷の読み手から見て傷を持っている扱い**にする。
   これが無いと、深手化した瞬間に 抉り・断ち・縫い・継ぎ当て・ミオの着火・滲み則が
   **全部止まる**。現象としても説明がつかない。
2. **深手の上に書かれた傷が無駄にならない。** 傷口がもう塞がらないので新しい刃がそのまま通る。
   **量は自傷と同じ 4**（定数を2つ作らない）。
3. **`lethal: true`。** HP1 でどれだけ深手でも動き続けられるのは現象として変。
   死軸に繋がるので接続も最大になる。
4. **自傷は巻き込み則を通さない。** 通すと **深手 → 自傷 → 傷 → 深手** の閉じたループになる。
5. **解けない形で測る。** 解除を同じ期に足すと変数が2つになる。
   **重すぎたら次期にノノの解除を足す**（§9）。

### 0-5. 3期越しの予測 —— **この機構では初めてノミが上位に来る**

第87期（ミオの着火）と第91期（滲み則）はどちらも **キリ ≫ ノミ** だった。
どちらも「傷を持つか」の二値を読むので、**撒くキリが有利で、1体に積むノミは活きなかった。**

**深手は深さ 3 を要求する。** キリは打点1で前列の的を毎ターン変えるので3つ積みにくく、
ノミは執着（`FixateTrait`）で1体に食いつくので**ノミだけが深手を作れる。**

> **同じ資源の長短2つの入口に、3期越しで逆向きの用途がつく。**
> **予測が外れたら、執着の読みか深手の閾値のどちらかが違う。**

## 1. Phase 0

### 1-1. 門 —— 鎖が繋がっているか（**大きさではない。第90期の規約**）

**この機構の最大のリスクは「傷が 3 に届かない」こと。**
第91期の実測では敵側の傷は薄く、断ち（0に戻す）・縫い（1引く）・継ぎ当て（1引く）が消費する。

> **W0（規則オフ）で、版に依らない計数を足して数える。**
> 1. **傷が 3 に達した回数/戦**（敵側・味方側それぞれ。波別）
> 2. **達した駒がその後に行動した回数**（＝自傷が払い出される機会）
> 3. **達した駒に、その後さらに傷が書かれた回数**（＝上乗せの機会）
>
> **3つとも 0 より大きいことを確認してから実装する。**
> **どれかが 0 なら、そこが切れている場所を書いて閉じる。**

**1 が敵側で 0 に近い場合**、この機構は味方側専用になる（第90期の滲み則と同じ形）。
**そのときは §4 の交差帯とローカル台で敵側を測る**——**理想61行だけで結論しない**（第91期）。

### 1-2. 事実の確定（**戦闘0回**）

1. **傷を書く箇所の全数。** `grep -n "StatusKeys.Wound" BattleCore/*.cs` で列挙し、
   **加算／減算／上書き／読みに分類する。**
   加算だけを新しい窓口（§2-2）に通す。**指示書の数を信用せず数え直すこと**
   （第84期でカド 8→11 行、第85期で呼び出し口 6→10、第90期で `Where` の訂正、
   第92期で `TraitEntryMap` の欠落2・過剰1 が出ている）。
2. **`StatusKeys.All` と `ScapegoatTrait.Kinds` の扱い。**
   `Kinds` は `All` から `Armor` と `IdleTurn` を除いたもので、**深手を足すと分母が動く。**
   **業（`Scapegoat`）がロスターと敵の波のどちらにも居ないことを確認する。**
   居なければ盤面への影響は無いが、**分母が動いたことを報告書に書く。**

   分かち（ドハ・4割肩代わり）・巨躯（ゴルム）・転嫁 の中継に拾われるか。
   **拾われるなら仕様として残す**（代金を誰かが肩代わりできるのは編成の選択肢）が、**回数を出すこと。**
   **庇い（`SelectTargetChain`）には拾われない**はず——標的選択ではないので。**確認する。**
4. **`compare` 61行・交差帯12行のうち、深手が発生しうる行を名指しする。**
   **ノミを含む行／キリを含む行／巻き込み則の書き手が密な行（ゴルム・ボルグ）。**
   **拒否権が立つ候補を測る前に書く**（第91期 (G4): 分母を必ず書く）。
5. **紙のスループット**（**門にしない。表に出すだけ**。第90期の規約）。

       深手由来の出力/戦 = 深手化回数 × その後の行動回数 × 4 ＋ 上乗せ回数 × 4

   分母は**その台の総与ダメージ/戦**（敵側）と**総被ダメージ/戦**（味方側）に分けて出す。
   **分子が線形か二次かを先に書く**（第87期は二次で 2.26 倍、第89期は線形と書いて 1.59 倍で外した）。

### 予測（**測る前に書く。編成表の駒を数えて書くこと**）

- **ノミ ≫ キリ**（§0-5）。**この機構で初めて向きが逆転する。**
- **味方側のほうが深手化が速い。** ゴルムの吸いは毎ターン全隣接に書く（第90期に 13.91回/戦 ＝
  全61行平均の 48 倍）。**3ターンで深手に届く。**
- **痺れ・まどろみは深手の駒を延命させる。** 自傷は**実際に行動したとき**だけ走るので、

- **`追撃×毒 (ハギ×グザ)` と 燃焼系の行が下がる。** どちらも味方に傷が載る台。

  **ガルドの引き取りは深手化の前にしか働かない**——集約が「深手化を1体に集める」意味になる。

## 2. 変更の定義（**測る前に固定**）

### 2-1. ノブ

```csharp
public readonly record struct DeepRule(bool Enabled)
{
    public static DeepRule Default => new(false);      // 測定中はここ
}
```

**定数は3つとも振らない。**

    Bundle   = 3     // 束ねる傷の数
    DeepBite = 4     // 自傷の量／上乗せの傷1つが化けるダメージ
    深手は 0 か 1 の二値（上限1）

**`DeepBite = 4` の根拠**: 抉りの単価が傷1つ = 3点でロスターの基準値。
深手は傷3つを束ねたものなので投資が大きく、**回収は行動回数ぶんに分割される。**
決着までの残り行動が 2〜3 回なので、1回あたり 3〜4 点で投資に見合う。**丸めて 4。**

### 2-2. 傷の窓口を1つ作る（**第90期の毒と同じ作法**）

傷は現在まとまった窓口が無く、各所が `SetCounter` を直接叩いている。
`BattleEngine` に窓口を1つ足し、**加算だけをそこへ通す。**

```csharp
public void Wound(UnitState target, int amount, UnitState writer)
{
    if (!target.IsAlive || amount <= 0) return;

    // **計数は規則の分岐より手前**（第86期の X1P・第90期の作法）。紙の分子を W0 から取るため。
    TallyOf(writer).WoundWrites += amount;

    if (!Deep.Enabled)
    { target.SetCounter(StatusKeys.Wound, target.Counter(StatusKeys.Wound) + amount); return; }

    if (target.Counter(StatusKeys.Deep) > 0)
    {
        // 上乗せ。傷は溜まらず、その場でダメージになる。**巻き込み則を通さない。**
        for (int i = 0; i < amount; i++) ApplyDamage(target, DeepBite, writer, spillWound: false);
        return;
    }

    int w = target.Counter(StatusKeys.Wound) + amount;
    if (w >= Bundle) { target.SetCounter(StatusKeys.Wound, 0); target.SetCounter(StatusKeys.Deep, 1); ログ }
    else             { target.SetCounter(StatusKeys.Wound, w); }
}
```

- **通すのは加算だけ。** 減算（断ちの 0 戻し・縫いの 1 引き・継ぎ当ての 1 引き）と
  **ガルドの引き取りの donor 側**は通さない。**ガルドが受け取る側は通す**（3 に届けば深手になる）。
- **`w >= Bundle` で 0 に戻す**——余りを繰り越さない（**深手は二値なので繰り越す先が無い**）。
- **ログの文言は各特性の側に残す。** 深手になったときだけ1行足す（第90期の作法）。

### 2-3. 自傷

**行動順ループの中、その駒が実際に行動した直後**に置く。

- **`Attack` / `Skill` / `Charge` のいずれかを通ったときだけ。**
  痺れ・まどろみ・`CanAct` 偽で `IdleTurn` が立った駒は**自傷しない。**
- **`ApplyDamage(self, DeepBite, source: self, spillWound: false)`。`lethal: true`。**
- **`isFriendlyFire` は false**（自分で自分を裂いている。味方の刃ではない）。

### 2-4. 読み手から見た扱い

**`target.Counter(StatusKeys.Wound) > 0` を見ている箇所を全部洗い、
「傷 > 0 または 深手 > 0」に読み替える。**

- **滲み則（`ctx.Poison`）**: 深手なら **+2**、傷だけなら **+1**（第90期のまま）。
  **深手の数に比例させない**（二値なので比例のしようが無いが、明記する）。
- **抉り・断ち・縫い・継ぎ当て・ミオの着火**: **深手を「傷1つぶん」として読む**
  （深さを 3 と数えない——**深手化した瞬間に読み手の出力が3倍になるのを避ける**）。
- **ナタの閾値2**: 深手だけでは届かない（1ぶんなので）。**これは仕様。**

### 2-5. 表の更新（**採用したときだけ**）

- `UnitTally` に `CarryDeep` を足し、`NoteStatusGain` の分岐に加える。
- **`TraitEntryMap` / `TraitKeyMap` は触らない**——深手は engine の規則で `TraitId` ではない。
  **ただし第92期に見つかった欠落2・過剰1 を直す作業とは混ぜないこと**（別の期の仕事）。
