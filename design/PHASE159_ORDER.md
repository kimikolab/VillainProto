### Q0-2. 単発帰属が列によって違うのはなぜか —— **不具合ではない。仕様**

指示書が挙げた3択のうち **「単発帰属が列の一部の波だけを使っている」** が答え。
`StageDiag.IndepDegree` を逐語で読むと、**各戦は毎回新品の編成で戦うが、ループは
`if (lostP) break;` で止まる**:

```csharp
for (int b = 0; b < col.Len; b++)
{
    var p = BattleEngine.Materialize(f, ...);      // ← 毎戦新品（持ち越しはここで抜けている）
    ...
    if (clearedE) cleared++;
    if (lostP) break;                              // ← **最初に負けた時点で列が切れる**
}
return cleared >= col.Len ? col.Len : cleared + attr;
```

**これは正しい対照である**——会戦版との差が「持ち越しだけ」になるように、
`EngagementEngine.Run` のループから持ち越しだけを抜いた形にしてある（停止規則は同じ）。
**止まる規則が順序を読むので、1戦ずつ独立に測っても列の順序で値が変わる。**

**戦闘0回で検算できる**（`docs/balance.md` の波別独立勝率 pᵢ から期待抜き数を引く）:

| 量 | 式 | 順路 | 逆順 |
|---|---|--:|--:|
| 期待抜き数の平均（61 行） | Σₖ ∏ⱼ≤ₖ pⱼ | **3.498** | **2.289** |
| 同 SD | | 1.337 | 1.554 |
| **全抜き確率** | ∏ pⱼ | **順序に依らない**（61 行すべて一致） | 同左 |

**積（全抜き）は順序不変・部分和（期待抜き数）は順序依存**——第2期が
「順路と逆順で独立積が違ったら実装がおかしい」と検算に使ったのと同じ性質の、部分和の側である。

### 4-1. 判定 —— **(A) で ×・(B) で ○。線が2つの量を指している**

指示書 §4 は線2 を「**SD÷列長 ≥ 0.162**」と書き、その根拠として
「`地点2 × R0` の**台SD÷列長** 0.162」を挙げている。ところが第158期 Q0-6 が固定した主の読みは
**帰属SD÷列長**で、**`順路5 × RFull` の 0.808 ÷ 5 も偶然ちょうど 0.162** である。
**第158期は「結論は読みに依らない」と書けたが、この期は依る。**

    読み (A) 帰属SD（駒 52 体の差）  → 線2 は 240 点すべて ×。**本丸 ×**
    読み (B) 台SD（61 行の差）      → `P43125 × BCarry` が線1・線2 を同時に通る。**本丸 ○**

**この期はどちらかを選ばない**（結果を見てから線を動かさないため。第64期）。
**記録としては (A) を主とする**——第158期が測る前にそう固定しており、かつ
線の名前が「**駒の差**が立っている」だからである（台SD は編成の差であって駒の差ではない）。
**(B) の1点は §9 の種として残す。どちらを正とするかはポンの判断。**

### 4-2. ρ を下げているのは「難しい波を先頭に集める」ことで、SD を上げるのとは別の並び

    帰属SD の最大 P21354（第二波→第一波→…）   ρ(全) 0.906  ← **ρ はむしろ対照より高い**
    ρ の最小   P43125（第四波→第三波→第一波…） ρ(全) 0.607  ← **SD は対照の 1.36 倍止まり**

> **`P43125` は第四波・第三波という重い2戦を先頭に置く並び**で、
> **多くの編成が2戦目までに落ちる**（平均 2.13 戦）。

> 同時に多くの枠の帰属が小さくなって SD が伸びない。**
> **逆順（P54321）をひとつ緩めた形**であって、別の軸ではない。

## 8. この期で見つかったこと

### 8-1. 判定の線が2つの量を指したまま2期走った。**片方が偶然 0.162 だったせいで気付けなかった**

第158期 Q0-6 は「(A) 帰属SD ÷ 列長」と「(B) 台SD ÷ 列長」の**両方が 0.162 になる**ことを見つけ、
**(A) を主と固定したうえで「結論は読みに依らない」と書いた。**
**この期は依る**——(A) で 0 / 240、(B) で 1 点が本丸を通る。

> **同じ数値になる2つの量を線に置くと、線が効かない期のあいだは食い違いが見えない。**
> **線を引くときは、値ではなく<u>量の定義</u>を1つに決めること。**
> 規約 (G4)（分母を必ず書く）の**分子の側**であり、
> 第121期「判定の線は計数の<u>名前</u>ではなく実装が数えている出来事に当てる」の**線の側の版**。

### 8-2. 「1戦ずつ独立」でも、止まる規則が順序を読めば順序が効く

指示書 Q0-2 は「単発戦は1戦ずつ独立に測るのだから、順序で平均が変わるのはおかしい」と書いたが、
**`IndepDegree` は最初に負けた時点で止まる**ので順序が効く（§1-2）。
**そしてそれは正しい対照である**——会戦版との差を「持ち越しだけ」にするには停止規則を揃えるしかない。

> **「独立」は<u>戦闘が独立</u>という意味であって、<u>評価が独立</u>という意味ではない。**
> 検算は「**積は順序不変・部分和は順序依存**」で戦闘0回で取れる（第2期が同じ性質を検算に使っている）。

### 8-3. 教習波を先頭に置くと、列の 5 分の 1 が情報ゼロになる

第一波は全編成必勝（`docs/balance.md` の第1波が 61 行すべて 100%）なので、
**順路5 では `1戦で決着` が 0.0%**——**第1戦は誰も落ちない。**
第一波を2戦目へ1つずらすだけで帰属SD÷列長 は **0.064 → 0.098（1.54 倍）**、
`BCarry` と合わせると **0.119（1.87 倍）**になる。

> **測る台としては、順路5 は先頭の1枠を捨てている。**
> **本編のステージの並びとは別の話である**——教習波が先頭にあるのは教える順序の問題で、
> **「駒を測る列」と「遊ばせる列」を同じ並びにする理由は無い。**

### 8-4. 候補を代理の量で選ぶと、本番の量の上位を取り逃がす

段A は台SD で上位4点を選んだが、**線2 が読むのは帰属SD** で、
`P41325`（台SD 3位）は帰属SD で 13 位、`P43125`（台SD 4位）はさらに下である。

段B の候補に1つも入らなかった。**

> **相関 +0.838 は「代理に使える」を意味しない。**
> **安い走査で候補を絞るときは、その走査が<u>線が読む量そのもの</u>を出しているかを見ること。**
> この期は 822 秒で全数走査できたので、代理は要らなかった。

### 8-5. ρ を下げる並びと SD を上げる並びは、盤面では別の出来事である

    SD を上げる = 「誰も落ちない戦」を減らす      → 先頭に中難度の波（P2134x）
    ρ を下げる  = 「単発では弱い駒が効く戦」を増やす → 先頭に重い波（P43125・平均 2.13 戦）
