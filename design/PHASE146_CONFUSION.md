## Q0-2. `isFriendlyFire`（engine 33 行 / `Traits.cs` 14 行）の分類

### (A) 事故の帳簿 —— **札を立てない。理由は下記**

経路の分類（`2830` / `2840`）・介入の分類（`2953`）・`DamageToAlly`（`5099`）・
`NoteHarm`（`5125`）は、いずれも **`isFriendlyFire || source.TeamId == target.TeamId`** と
**論理和**で書かれている。つまり

> **混乱した一撃は、札を立てなくても `TeamId` の一致だけで「味方の刃」として正しく帳簿に載る。**

**だから `isFriendlyFire: true` は渡さない。** 渡すと `SpillWound`（巻き込み則・`5161`）の
条件 `isFriendlyFire && !relayed && source is not null` が成立して、
**混乱の一撃が味方に傷を書き始める**——第122期に既定オフへ降ろした規則が、
ノブを触らないまま裏口から復活する。**混乱は事故ではなく敵の妨害の結果**であり、
「味方を巻き込んでしまった」の帳簿に混ぜない。

### (B) 肩代わりの除外 —— **4 枚は反応し、4 枚は反応しない**

| 機構 | 陣営を見るか | 混乱の一撃に対して |
|---|---|---|
| 庇い（ガルド）・後備え（セッキ）・標的・殉教・棘守り | **見ない**（鎖は `foes` の中だけで完結） | **庇う** ← §0 の狙いどおり |
| 巨躯（ゴルム・`4741`） | `u != source` のみ | **庇う**（混乱した本人が壁なら自分の一撃は庇わない） |
| 分かち（ドハ・`4816`） | 見ない。コメントに「**味方同士の巻き込みも引き受ける**」と明記 | **庇う** |
| 身構え（ササ・`5006`） | 見ない | **上限 7 で切り、切り落としを配る** ← §0 の表どおり |
| **受け流し（ガルド・`4918`）** | **`source.TeamId != target.TeamId`** | **弾かない** ← **§0 の表が偽** |
| 棘（カド・`2261`）・仇討ち（ザン・`4656`）・毒の反撃（`1465`）・断罪（`5657`） | **見る**（`source.TeamId == self.TeamId` で return） | **反撃しない** |

**含意**: 混乱した一撃はガルドに素通りで刺さる。しかも
**ガルドは庇いが 100%（第136期 段1）なので、混乱した味方の一撃を進んで引き受ける。**
「ガルドで空振りする」どころか **ガルドが混乱の最大の被害者になる。**
一方で**棘・仇討ちは反応しない**ので、混乱の一撃は反撃の連鎖を一切起こさない。

## Q0-4. 撃破イベントは「敵を倒した」を前提にしているか

`OnKill` の発火（`5501`）は **`killer is not null && killer.IsAlive` だけ**で、陣営を見ない。

| 読み手 | 味方を倒したとき |

## Q0-5 / Q0-6. 「動かされた」の窓口と、両陣営の在庫

### 窓口は `SwapSlots` の `Notify` 1 箇所（`BattleEngine.cs:6180`）

`NoteCarry(u, UnitTally.CarryMove, 1)` まで既にある。**混乱の鍵はここに 1 行置けば足りる。**

### 呼び出し元は **6 箇所（全部 `Traits.cs`）・札は 7 枚**

**`SwapSlots` の箇所を数えると 6 だが、札で数えると 7**——`ShoveRules.Shove`（`7259`）は

**そして散開の保持者はいま 0 枚**（第143期の転生でササが `Loose` を失った）ので、
実際に動く札は **6 枚**に戻る。**「窓口の数」と「札の数」と「保持者のいる札の数」は全部違う。**

| 呼び出し元 | 誰が動くか | 保持者 |
|---|---|---|
| `CowardTrait`（逃亡・`441`） | 味方（自発）＋押しのけられた味方 | セロ（味方） |
| `ThornGuardTrait`（棘守り・`2491`） | 味方 | カド（味方） |

| `ShoveTrait`（突き返し・`2927`） | **敵** | ハネ（味方） |

| `LooseTrait`（散開・`7259`） | 味方 | **保持者 0 枚**（第143期の転生でササが `Loose` を失った） |
| `BraceTrait`（身構えの弾き・`7394`） | 味方 | ササ（味方）——**`ShoveRules.Shove` を散開と共有**するので `SwapSlots` の箇所は同じ 1 つ |

### **庇いの前出は `SwapSlots` を呼ばない**

鎖（`SelectTargetChain`）は**主目標を差し替えるだけ**で駒を 1 ミリも動かさない。
**よって指示書 §1-1 の `CountGuardStep` ノブは存在理由が無い。落とす。**
（第124期 Q0-7「移動は engine が起こしていない。`.Slot =` は `SwapSlots` の 2 行だけ」の再確認。）

### **合否テスト1（両陣営に動かす機構があるか）は、波では通らない**

**敵側の移動源は告発人（第五波）1 枚だけで、それが動かすのは味方である。**
つまり **敵の駒が動く経路は、プレイヤーが ハネ か バサ を連れてきたときしか存在しない。**

| 波 | 敵側の移動源 | 敵が混乱しうるか |
|---|---|---|
| 第一〜四波 | **0 枚** | プレイヤーが ハネ／バサ を入れたときだけ |
| 第五波 | 告発人（曝き）——ただし**動かすのは味方** | 同上 |

**これは第134期が粛について書いた「在庫」型の非対称そのもの**
（窓口は両陣営に開いているが、片側がそれを一度も問い合わせない）。
**「波ルールなら両陣営に等しくかかる」は、この機構については成り立たない。**

**ただしこれは欠陥ではなく、そのまま可変コストの実体である**——
混乱の向きを決めているのは**波ではなくプレイヤーのロスター**で、
セロ・ササ・カドを入れれば自分が混乱し、ハネ・バサを入れれば敵が混乱する。
**測るべきはこの符号の割れであり、波はその舞台にすぎない。**

## 段A の設計（Phase 0 の答えから確定した形）

```csharp
public readonly record struct ConfusionRule(bool Active)
```

- `Active = false` が既定（`compare` 305 セル 0 件差分の基準）
- **`CountGuardStep` は落とす**（Q0-6。庇いは席を動かさない）
- 鍵は `StatusKeys.Confused` を 1 つ足す（**痺れ・転倒を流用しない**。読み手が混ざる）
  ——`StatusKeys.All` にも足す（会戦の境界で消す一覧。漏らすと混乱だけが波を跨ぐ）
- 立てる場所は **`SwapSlots` の `Notify`** 1 箇所（`NoteCarry` の隣）
- 読む場所は **`SelectTargetChain` / `TargetPool` / `SecondaryTargets` の 3 箇所**
  （`ResolvePierce` は `entry.TeamId` を見ているので追従する）
- **`isFriendlyFire` は渡さない**（Q0-2 (A)）
- 落とす場所は `PerformAttack` の主目標の解決後——**1 回で落ちる**
- **`Charge` の溜めの次の一撃は混乱する**（溜めも `PerformAttack` を通るので、
  混乱を落とすのは「標的選択を通った回数」で数える。**攻撃型で例外を作らない**
  ——第58期の熾火の除外を入れなかったのと同じ理由で、対象集合に例外ができると
  規則が 1 行で説明できなくなる）
