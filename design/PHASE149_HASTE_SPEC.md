# 第149期 指示書 —— 「行動順」という通貨にいくらの値が付くかを測る

**HEAD 前提: 第148期の完了時点。**

**この期の一文**:
> **駒も代金も作らない。** 「毎ターン味方1体を行動順の先頭に出す」だけを掛けて、
> **行動順という通貨の値段**を測る。値が付かなければ、そこで終わる。

本書は自己完結している。リポジトリ外の文書は参照しない。

## 0. なぜこれをやるか

### 第148期が残した「値札」

バサの手番を `[Skill]` に移して落ちた。損の実体は**攻7だけ**だった:

| 版 | 帰属 |
|---|--:|
| V2 ターン頭のまま在庫だけ外す（攻撃は続ける） | +0.4〜+3.1 |
| **V1 手番（攻撃を全部捨てる）** | **−5.9〜−23.0** |
| V3 周期 `[Attack, Skill]` | −18.3〜−32.9 |

> **バサの手番に何を置くにせよ、台によっては +23pt の価値が要る。**

さらに号令の実測が示したのは、**通貨が違えば値が付かない**こと——
`[Skill]` のバサは号令から 3.53 量/戦を受け取って**死蔵 100%**。
「値段が安い」のではなく**市場そのものが成立しない**。

### だから駒を作る前に通貨を測る

採用された2枚は、**自分が既に扱っている通貨で手番を払っている**:

| 駒 | 手番で買うもの | 元々扱っている通貨 |
|---|---|---|
| ガルド（第136期） | 無効化の在庫 | 被弾 |
| ササ（第143期） | 単発上限 ＋ 破片供給 | 被弾 |

バサが扱っているのは**席と順序**。席はターン頭で無料で手に入っているので
（第148期が落ちた一因）、残るのは**順序**。

**しかし順序にいくらの値が付くかは一度も測っていない。**
- **行動順を動かす札はロスターに 0 枚**。速さを変える札も 0 枚
- 逆位（`TraitId.Inversion`）は**波全体の反転**として第22期・第32期に測り、**二度棄却**
  （どちらも「波を易しくする」方向に出た）。**1体だけ・1ターンだけの版は一度も測っていない**

> **第137期の失敗（鍵の密度を測る前に設計を積み上げて外した）と逆の順番でいく。**
> 値段が分かれば、**どこに載せるかは後から選べる**（バサに決め打ちしない）。

### Q0-1. 行動順の確定箇所を読む（**1箇所に集約されている**）

`BattleEngine.cs:6595` 付近。Web 側が読んだ形（**確認すること**）:

```csharp
bool inverted = ctx.AllUnits.Any(u => u.IsAlive && u.HasTrait(TraitId.Inversion));

var speedGroups = ctx.AllUnits.Where(u => u.IsAlive)
    .GroupBy(u => (u.Def.Speed, u.TeamId));

var order = (inverted ? speedGroups.OrderBy(...) : speedGroups.OrderByDescending(...))
    .ThenBy(g => g.Key.TeamId)
    .SelectMany(g => { var tie = g.ToList(); ctx.Shuffle(tie); return tie; })
    .ToList();
```

**確認すること**:
- **毎ターン振り直している**こと（開戦時1回ではない）
- `ctx.Shuffle(tie)` が**乱数を消費する**こと——**先頭へ出す駒を群から抜くと、
  その群の要素数が変わってシャッフルの乱数消費が変わり、盤面全体がずれる**。
  **これがこの期の最大の実装上の罠。** §1-2 の指定に従うこと
- `ThenBy(TeamId)` の陣営タイブレークを**触らない**

### Q0-2. 乱数をずらさずに「1体だけ先頭へ出す」方法を決める

**盤面のずれと通貨の値段を混ぜないために、乱数列は1ビットも動かしてはいけない。**

推奨する形:

```
order を今までどおり作る（Shuffle もそのまま走らせる）
        ↓
規則がオンなら、order の中から対象を1体選び、List から Remove して先頭に Insert する
```

- **`Shuffle` の入力と呼び出し回数を変えない**ので、乱数列は完全に同じ
- 対象の選び方は `order` が確定した**後**に決める（§1-1）
- **規則がオフのときは `order` に一切触らない**——`compare` 305 セル 0 件差分の根拠

**別の形を採るなら、乱数列が同一であることを実測で示すこと**（V0 と規則オフ版で全文一致）。

### Q0-3. 「先頭へ出す」の意味を確定する

- **敵より先か、味方の中で先か。** `order` は両陣営が混ざった1本のリストなので、
  **先頭へ出せば敵全員より先に動く**。これが測りたいものでよいか確認して書く
- **同じターンに2回動くわけではない**（`Remove` してから `Insert` するので延べ回数は不変）。
  **`TurnLoopCalls` が版間で一致する**ことが検算になる
- **既に先頭にいる駒を選んだ場合**は何も起きない（それでよい）

### Q0-4. 対象の選び方を2点に絞る

| 版 | 選び方 | 狙い |

| **A（強い）** | 生存味方のうち `CurrentAttack` が最大。同値は同上 | 単純な火力の前倒し |

- **`PickOne` を新たに使わない**（必須4）。同値の解決は `order` の並びを使う
- **決定的に選ぶ**（乱数を引かない）。第130期の則（乱数で選ぶと何に課金したか分離できない）

## 3. 予測（**実装前に書き切って報告書に残す。外れたら消さずに残す**）

1. **`Slowest` のほうが `Strongest` より大きい。** 速い駒は元々先に動いているので前倒しの余地が小さく、
   遅い駒は余地が大きい（第144期の「**効き方は生の pt ではなく余地に対する取り分で見る**」）
2. **遅い駒を含む行だけが動き、含まない行はほとんど動かない。**
   動くなら、それは「敵より先に動く」ことの効果であって「遅い駒の前倒し」ではない
3. **第五波（断罪＋殉教者）で最も効く。** 決着が長引く波ほど順序の1ターンが効く
4. **`Strongest` は第144期の逆位と同じ理由で伸びない可能性がある**
   ——逆位が「波を易しくする」と出たのは**味方ロスターに遅い層が厚い**からで、
   `Strongest` はその構造を使わない
5. **`TurnLoopCalls` が版間で一致する**（延べ手番数は変わらない）

**この期は「いくら」を測るのが目的なので、方向の予測より
「値が付くか付かないか」の線を先に引く**（§4）。
