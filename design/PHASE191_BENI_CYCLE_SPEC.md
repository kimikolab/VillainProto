報告は `design/PHASE191_BENI_CYCLE.md`。診断は第190期の `BattleSim/Modes/Beni.cs` に版を足す（`beni run / ledger / check`）。

## 1. 目的

第190期（`design/PHASE190_BENI.md`）で、反転の結界は機構としては通った。ただし回復量が足りなかった。

- 旧ベニは1戦で味方全体を約149回復していた。新ベニは隣の2枚に17だけ
- 毒は1層ずつしか積もらないので、回復が育つ前にベニが倒れる（25行中18行で1戦あたり0.9回以上倒れる）

今期は**手番を周期にして初速を足す**。燃焼は1手番目から毎ターン6の固定量なので、それを反転で回復に変える。

## 2. 変更

### 2.1 ベニの手番を周期にする（本体）

`Actions` を次の3要素の周期にする。

| 周期 | 手番 | 内容 |
|---|---|---|
| 1 | 火を分ける | 隣接する生存味方全員に着火（`Ignite(target, friendly: true, source: ベニ)`） |
| 2 | 澱みを分ける | 隣接する生存味方全員に毒 +1 層（第190期の `Taint` のまま） |
| 3 | 澱みを分ける | 同上 |

- 燃焼は付与で残り3ターン、ターン頭ごとに1減る。周期3なので、**切れる直前の手番で点け直す**＝燃焼が途切れない（ベニが手番を失わない限り）
- 周期の位置は `CanAct` を通った後に進む（既存の仕組み）。ベニが痺れ・竦み・粛で手番を失うと周期が止まり、火が切れる。**これはマイナスとしてそのまま残す**
- 札の形は Phase 0 で決めてよい。候補は (a) `Taint` の中で `action.Label` を見て火と毒を分ける、(b) 火を別の札（例 `Kindle` 系の名前は既存と衝突しないか確認）に割る。**(b) を推奨**——外せば「毒のみ」の版が組める
- 着火は支援ではないので、支援拒否（ガルド）にも点く。ホタは燃えても焼かれない（`Ember.Fireproof`）が、**燃えている扱いにはなる**（攻×4・貫きが立つ）
- 反転・反転の裏（`Inverse` / `InverseLeak`）は1文字も触らない

### 2.2 ヴェルの読み違いを直す（付随の修正）

第190期で見つかった件: ヴェル（`Stitch`）は、ベニの隣で回復がダメージに変わった手番を「渇きに止められた」と読み、そのうえ攻撃する。

- 反転の裏でダメージに変わった回復は、**回復を行った手番として扱う**（攻撃に落ちない）
- 渇きで本当に止められた場合の挙動は変えない
- ベニを含まない行で差分が出ないこと（ヴェルが隣にいない行は1ビットも動かない）

### 2.3 触らないもの

- HP・攻・速（HP64 のまま）。倒れやすさは今期の数字を見てから別途扱う
- 反転の対象（毒・燃焼の刻み・起爆の味方側）
- 自己回復持ち（ゴルム・リィカ・ムド）がベニの隣で自傷する件（R302）——**配置のフックとして残す**

## 4. 診断

版は **第190期（毒のみ）／ 周期 ／ 周期・マイナスなし（`InverseLeak` を外す）／ 素体**。

1. `compare` のベニの在席行（第2〜5波・第一波は実行して除外）
2. 差し替え表（第190期 5.2 と**同じ25行・同じ席**）。Δ素体 と、第190期版との差を併記
3. 帳簿（1戦あたり）:
   - 反転の回復を**毒と燃焼に分けて**、さらに**1〜3ターン目とそれ以降に分けて**
   - 回復を受けた味方の延べ人数と最大同時人数
   - ベニが倒れたターンの平均、周期が止まった回数（手番を失った回数）
   - 隣が燃えている間のホタの与ダメ（ホタが隣にいる行があれば）
4. 診断台は第190期で3つとも床に張り付いたので**今期は回さない**

## 5. 予測（実装前に宣言してコミット）

方向だけ。数は Q0-3 の実駒を数えてから入れる。

- ベニを含まない行は ±0.0（ヴェルの修正込みで）
- 反転の回復は第190期より大きく増え、増分の大半は1〜3ターン目の燃焼
- 差し替え表の Δ素体 の平均は第190期（−3.5）より上がる
- ゴルムがベニの隣にいる行の代金は第190期（−10.7）より縮む（燃焼の回復が吸いの自傷を相殺する）
- ベニが倒れる頻度は大きくは変わらない（HP を触っていないため）
