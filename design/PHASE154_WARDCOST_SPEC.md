## 0. この期の狙い

### 0-1. 第153期で分かっていること（前提）

`design/PHASE153_WARD.md` を読むこと。要点は3つ。

1. **プラス側（預かり）は効きすぎるほど効いている。** 帰属 +24.8 / +50.0 / +21.9 / +5.0。
   落ちたのは**代金の形**であって出力ではない
2. **没収（`Forfeit`・預かりを抱えたまま倒れると敵全体へ回復）は定数型のマイナスだった。**
   4台とも負で符号が1つも反転しない
3. 札・状態キー・`WardRule`・診断（`ward`）・段0 の台5つはすべて**残置されている**

### 0-2. 没収が定数になった理由（この期の出発点）

**代金が「敵への回復」という通貨で払われていた。味方ロスターにその通貨の読み手が1体もいない。**
だからどの編成を組んでも変換できず、定数の損にしかならなかった。

没収の量を決めていたのも「味方が何体倒れたか」ではなく**「返せなかった比率」**で、
最大は死軸ではなく支援拒否のタンク（返却率 17.4%）だった。
**倒れた回数と預かりの残高は別の量である。**

### 0-3. この期でやること

**プラス側（`Ward`）は1ビットも変えない。代金の札だけを2本、新しく並べて測る。**
変数は代金の形だけに閉じる。

## 1. 作るもの

### 1-1. 代金の札を2枚足す（`Forfeit` は残置したまま）

`BattleCore/Traits.cs` に追加。**`TraitId.Forfeit` は消さない**（第64期の作法。対照として残す）。

| 札 | 内容 |
|---|---|
| `TraitId.Burden` | **預かりを抱えている間、その味方の被ダメージが増える**（`Percent` 指定） |
| `TraitId.Laden` | **預かりの量に応じて、その味方の攻撃力が下がる**（`Per` ごとに −1、下限 1） |

いずれも**預かりを抱えている味方本人**にかかる。ノチ自身ではない。

```csharp
public enum WardCost { Forfeit, Burden, Laden }
```

`WardRule` に `Cost` を1本足す。既定は `Forfeit`（第153期と1ビットも違わない状態を保つ）。

### 1-2. `Burden` の実装位置（**ここを間違えると測れない**）

`BattleEngine.ApplyDamage` の**入口**（`ModifyIncomingDamage` の族）に置く。
出口（受け流し・軛・猶予）ではない。

理由: **ササの `Brace` が上限で切るのは入口より後**である
（`Brace.Cap` の判定は `ApplyDamage` の中ほど、`Yoke` の直前）。
`Burden` を出口に置くと、**ササが切り落とす超過が増えない**——
この期で測りたい変換がまるごと消える。

> **実装したら必ず1戦のログで確認すること**——ササが預かりを抱えている状態で
> 「身構えて一撃を N から Cap に抑えた」の N が `Burden` のぶん増えていること。

### 1-3. `Laden` の実装位置

`ModifyAttack` に置く。**下限は 1**（0 にすると攻撃そのものが消えて、
「攻撃しない駒と同じ」になってしまい、枝の意味が消える）。

**`CurrentAttack` を参照する既存の札との順序**を Phase 0 で確認すること
（号令・鬨・縛め・逆しま・強化の読み手）。

### 1-4. 触らないもの

- `TraitId.Ward` の本体（積む窓口・返す窓口・`Burst` / `Drip`）
- `WardRule.Percent` / `Threshold` / `Drip` の**既定値**（掃引はするが既定は動かさない）
- `UnitCatalog.All`（ノチは `All` の外のまま）
- `Presets`（`sweep` は回さない）

### Q0-2. 変換器を実装から数え直す（**この期の核心。指示書の表を信じないこと**）

**`Burden`（被ダメ増）を実利に変える駒**を、`BattleCore/Traits.cs` を読んで列挙する。
判定は次の2つを分けて書くこと。

- **量に比例するか**（被ダメが2倍になったら得も2倍になるか）
- **回数に比例するか**（被弾回数は `Burden` では増えないので、回数依存の札は変換器ではない）

Web 側が事前に読んだ範囲では次のとおりだが、**必ず自分で確かめて、違っていたら報告書に書くこと**。

| 駒 | 事前の読み |
|---|---|
| ササ `Brace` | 量に比例（切り落とす超過が増える＝破片の供給が増える） |
| ムド `Rage` | 量に比例（`dmg/2` が攻撃力になる）。ただし攻撃力は遅い通貨 |
| ガルド `Parry` | 回数制。1回あたりの無効化量は増えるが、受け流した分は HP が減らない＝**預かりも積まれない** |
| カド `Thorns` | **比例しない**（`Multiplier = 2` × 自分の攻撃力・`OnDamaged` は1被弾1回）＝純損 |
| ヒビ `Frail` | 純損（既に被ダメ1.5倍） |
| リィカ `Necro` | 読むのは味方の死。自分の被弾ではない |

**`Laden`（攻撃力減）が無料になる駒**も同様に列挙する
（手番で通常攻撃を振らない駒・`CanAct` が偽の駒・`Immobile` の駒）。

## 3. 予測（実装前に書き切る。外れても消さない）

**Q0-2 と Q0-3 が出てから、台の編成表を実際に開いて駒を数えて書くこと。**
以下は方向の素案。**数値は数えてから入れる。**

1. **`Burden` は台1（ササ）でだけ代金が小さく、台3 で最大になる。** 符号までは反転しないかもしれないが、
   **台1 と台3 の代金の差が `Forfeit` の4台のばらつき（−0.6 〜 −9.0）より大きい**なら前進
2. **`Laden` は台2（カド）でほぼ 0 の代金になる。** 攻撃しない駒には払うものが無い
3. **`Laden` は台3 で `Burden` より重い。** 殴る駒だけの台では攻撃力がそのまま出力
4. **`Burden` は自己強化のループを作る**（被弾 → 預かり → 被ダメ増 → 被弾）。
   台3 で**積んだ量が `Forfeit` 版より増える**はず。増えていなければループは効いていない
5. ノチ非在席（台5）は全波 ±0.0
6. **`Burden` は返却率を上げる**（`Burst` の閾値に早く届く）。`Laden` は返却率を動かさない

### 段B —— 3枝の比較

**版は7つ。** 同じ台・同じ seed（0..199）・第2〜5波。

| 版 | 内容 |
|---|---|
| V0 | 素体（ノチの席を特性なしの同数値の素体に差し替え） |
| Vp | **預かりのみ**（代金の札なし）＝プラス側の上限 |
| V1 | `Ward` + `Forfeit`（第153期の再現。**値が一致することを確認する**） |
| V2 | `Ward` + `Burden` |
| V3 | `Ward` + `Laden` |

**代金の値段は `Vn − Vp`** で取る（第153期と同じ器具）。

**帳簿**（1戦あたり）:

- 積んだ／返した／代金で失った／残額（収支が閉じること）
- **`Burden`**: 増えた被ダメの総量／そのうち**ササが切り落とした量**（＝変換できた分）
- **`Laden`**: 下がった攻撃力の総量／**実際に振られなかった打点**（攻撃しない駒では 0 になるはず）
- 返却率（`Burst` の閾値到達回数）

> **`Burden` の帳簿は「増えた被ダメ」と「変換できた分」を必ず分けて取ること。**
> 第153期は「返せなかった比率が代金を決める」を後から気づいた。同じ形の取りこぼしを防ぐ。

### 段C —— プラス側を帯へ下ろす

第153期のプラスは帰属 +50.0（取り分 0.871）で**強すぎる**。
このままでは代金の符号を見る前に天井で潰れる。

**`Percent` と `Threshold` を同率で下げる。** 第153期 §5-3 は
「効いているのは `供給 ÷ 閾値` 1つ」と結論したが、**それは返却率についてであって、量については2次元ある**：

```
返した量 ＝ Percent × 返却率
返却率   ＝ 供給 ÷ 閾値 が決める
```

`Percent 25 / Threshold 20` は `Percent 50 / Threshold 40` と**同じ返却率で量が半分**になるはず。
**5点ほど掃引して、Vp の帰属が +15 〜 +25 の帯に入る点を採る**。
その点で段B をもう一度回して、代金の符号を見る。

> **掃引で返却率が保たれることを実測で確認すること。** 保たれないなら
> 「供給 ÷ 閾値」の読み自体が間違っているので、そう報告する。

## 5. 採否の条件

| # | 条件 | 線 |
|---|---|---|
| 1 | **符号が編成で反転する**（本丸） | いずれかの枝で、**変換器在席の台で代金が正（資産）、変換器なしの台で負** |
| 2 | 1 に届かない場合の次善 | 変換器在席と非在席で**代金の差が 10.0pt 以上**（`Forfeit` の4台のばらつきは 8.4pt だった） |
| 3 | 拒否権 | −10.0pt 以上のセルが 0 |
| 4 | 特異性 | ノチ非在席が ±0.0（全セル） |
| 5 | 収支が閉じる | 1点もずれない |
| 6 | 情報セル | 減ったら**天井側か床側かを分けて**記録する |

**条件1 か条件2 のどちらかが通れば前進とみなし、ポンに報告して判断を仰ぐ。**
両方落ちたら、**預かりという機構は代金を付けられない**ということなので、
§7 の「次に試すもの」へ進む判断材料として報告する。

**採用が決まった場合のみ**、キリを `Retired` へ移し、`compare` の
`裂き (キリ×エグ)` と `裂き×責め苦 (キリ×エグ×シガ)` の2行を差し替える
（第153期 指示書 §5 の手順がそのまま使える。`Presets` に触るので `sweep` 込み）。
