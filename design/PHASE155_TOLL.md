## 0. この期でやったこと（要約）

**回復役の5枚目**として「贖いのアガ」を作り、**`UnitCatalog.All` の外**で測った
（第138期の礫のガレ・第153期のノチと同じ扱い）。

- **札は3枚に分けた**——`Indulgence`（免罪・前借り）／`Toll`（取り立て・代金）／`Brand`（焼き・出力）。
  `checkup` の `yP`（マイナスを外した版）は `Traits` の配列から `Toll` を抜くだけで作れる（第74期の作法）。
- **`Brand` は `Toll` の下流**なので、`yP` では燃料が1点も溜まらない
  ——**これは正しい挙動である**（代金を外すと、その代金から生まれる出力も消える）。
- **engine に規則は1本も足していない。** 足したのは
  状態キー1本（`StatusKeys.Debt`）／ノブ1本（`IndulgenceRule`）／計数専用の帳簿
  （`IndulgenceLedger`）／`MostHurtAlly` に候補の絞りを掛けたオーバーロード（`filter` が
  `null` なら既存の版と1ビットも違わない）だけ。
- **`Run` の引数は1本だけ増やした**（`IndulgenceRule? indulgence`）。第138期の則どおり
  2本以上になるノブは1つの `record struct` に畳んである。

### Q0-3 —— 踏み倒しの削りは肩代わりされるか（**実測**）

`TollTrait.OnAllyDeath` は `ctx.ApplyDamage(self, debt, self, ...)` を呼ぶ。
**庇い（`Guardian`）・後備え（`RearGuard`）・標的は `SelectTarget` の差し替えなので通らない**
（`ApplyDamage` を直接叩くと標的選択そのものが走らない）。
**巨躯（ゴルム）・分かち（ドハ）は `ApplyDamage` の中で肩代わりするので通りうる。**

| 台 | 踏み倒しの回数 | 引き受けた負債（名目） | **アガの HP が実際に減った量** | 差 |
|---|---:|---:|---:|---:|
| 台1 速い | 0.11 | 2.82 | 2.56 | 0.26 |
| 台2 遅い | 0.06 | 1.77 | 1.34 | 0.43 |
| 台3 タンク (ゴルム) | 0.18 | 5.33 | 2.04 | **3.29** |
| 台4 回復同席 (ノノ) | 0.12 | 4.13 | 2.90 | 1.23 |
| 台5 陰性対照 | 0.00 | 0.00 | 0.00 | 0.00 |

**差は 0 ではない。** ゴルムのいる台3 では引き受けた 5.33 のうち**アガが払ったのは 2.04（38%）**で、
残り 3.29 は巨躯が飲んでいる——**第153期の実例（リィカの代償 8 のうち本人が払ったのは 1）と同じ形。**
ゴルムのいない台でも差が 0.26〜1.23 出るのは **HP の下限（0）で切れている**分
（アガの残り HP より負債が大きいと、その超過は帳簿に出ない）。
**指示書 Q0-3 の指示どおり、この期では塞がない。測定値の読みが変わることだけ記録する。**

## 2. 予測（**実装後・段B を1度も回す前**に書いた。外れても消さない）

**Q0-2 と Q0-6 が出てから、台の編成表を開いて書いた**（指示書 §3）。

1. **`Toll` の代金は決着の速さで符号（大きさ）が割れる。これがこの期の本丸。**
   代金 ＝ `V1 − Vp`。**台1（決着 7.05T）は −8pt 以内、台2（決着 12.04T）は −20pt 以上**で、
   **差は 10.0pt 以上**（条件1 の線）。
2. **第三波（渇き）ではアガが無害化される。** 前借りの空振りのほぼ全部が渇きで、
   積まれる負債は他の波の 1/3 以下。V1 と Vp の第三波の差は **±3pt 以内**。
3. **`Single` は第四波（軛・単発上限 25）で焼きの大半が切られる。**
   焼きの名目のうち軛で切られる割合は **`Single` で 40% 以上**、`All` ではその半分以下。
   **取り立ての側も同じ波で切られる**（取り立ても `ApplyDamage` を通るので）。
4. **`All` が `Single` より強い。** 4 台すべてで `V2 > V1`。
5. **`Contracts = 1` は前借りの回数が減り、取り立て1回あたりの燃料は変わらない**
   （閾値が同じなので1回の取り立ての大きさは `Threshold` で決まる）
   ——**指示書の「取り立て1回あたりの燃料は大きくなる」は成り立たないと読む。**
6. **アガ非在席（台5）の4版は 1 ビットも違わない。**
7. **`Advance` は強度のノブとして働く**（`Percent` と違って整数除算の崖が無いので、
   第153期の `Percent` の失敗は持ち越されない）。ただし**閾値に対する比しか効かない**ので、
   `Advance` と `Threshold` は独立なノブにならない（第153期 §5-3 と同じ形になる）。

## 6. では代金は何で決まっていたか —— **出口**

**6点すべて・4台すべてで `All` の代金が `Single` より小さい**（はしご 6/6・段B は 3/3 ＋ 天井1）。

| | 取立(実HP) | 焼き(実HP) | 代金 |
|---|---:|---:|---:|
| 台3 Single | 49.51 | 24.70 | −8.9 |
| 台3 **All** | 39.51 | **68.22** | **−2.0** |
| 台2 Single | 69.83 | 31.48 | −16.5 |
| 台2 **All** | 49.91 | **73.06** | **−4.8** |

**`All` は取り立てる量がむしろ<u>少ない</u>のに代金が小さい。**
取り立てた HP は同じ資源で、違うのは**それをいくつの体へ叩き込めるか**だけ
——`All` の焼きは主目標に全額・他の敵に 60% なので、
**同じ燃料が 2.5〜3.1 体へ届く**（当たり体数 1.00 → 3.01 / 1.30 → 3.12）。

> **代金は「取り立てが味方をどれだけ削ったか」ではなく、
> 「取り立てた分をどれだけ出力に換えられたか」で決まっていた。**

これは第154期「変換器は分子を増やすが、分母は1枚も減らない」の**裏返し**である。
第154期の荷は**代金を払う側と変換する側が別の駒**だったので、ササを入れても分母（掛かる相手）が縮まなかった。
アガは**変換器を自分で持っている**ので、**変換効率を上げると代金そのものが縮む。**

### 代金が正になる点が実在する

`Contracts = 1` ＋ `All` は **4台中3台で代金が正**（台1 は `Vp` が天井なので読めない）。

| 台 | ノブ | Vp | 勝率 | 帰属 | **代金** | 焼き(実HP) | 無制限＋All の焼き |
|---|---|---:|---:|---:|---:|---:|---:|
| 台2 遅い | `Contracts 1` + `All` | 76.6 | 83.4 | **+41.8** | **+6.8** | 88.44 | 73.06 |
| 台3 タンク | `Contracts 1` + `All` | 67.4 | 72.1 | **+16.3** | **+4.8** | 86.74 | 68.22 |
| 台4 回復同席 | `Contracts 1` + `All` | 72.2 | 74.2 | **+25.3** | **+2.0** | 84.33 | 59.21 |
| 台2 遅い | `Threshold 30` + `All` | 85.1 | 88.0 | **+46.4** | **+2.9** | 109.05 | 73.06 |

**「取り立て」というマイナスの札が、盤面では足すと勝率が上がる札になっている。**
`Contracts = 1` は指示書 §1-6 が「**駒として一番綺麗**だが回復役として弱すぎる懸念」と書いた枝で、
**実測は逆**——負債が1枚に集中するので閾値に早く届き、**取り立ての回数も燃料も増える**。

## 7. 段C —— 掃引（`0 toll sweep [contract|advance]`）

**`Vp` は点ごとに測り直した**——`Advance` と `Contracts` は前借りの側も動かすので、
既定の `Vp` を分母にすると代金にノブそのものの効きが混ざる（**規約 (G12)**）。

### `Threshold`（取り立てが来る速さ）

## A-4. `Contracts = 0`（無制限）の実装（§1-3）

`IndulgenceTrait.Pick` は次の形である。

```csharp
if (rule.Contracts <= 0) return ctx.MostHurtAlly(self);
int carriers = ctx.LivingMembers(self.TeamId).Count(a => a.RawCounter(StatusKeys.Debt) > 0);
if (carriers < rule.Contracts) return ctx.MostHurtAlly(self);
return ctx.MostHurtAlly(self, a => a.RawCounter(StatusKeys.Debt) > 0);
```

**無制限では絞りが1度も走らない**——`MostHurtAlly` が負債の有無を1ビットも見ないので、
**既に負債を抱えている相手には上乗せするだけ**（指示書が言う「前者」）。
**枠の概念は `Contracts >= 1` のときだけ効く。**

なお**枠が開くのは負債が 0 になったときだけ**で、`Vp` にはその経路が無い
——`carriers` は `LivingMembers` を数えるので、**`Vp` で枠が開くのは借り手が倒れたときだけ**である。

| §6「**代金が正になる点が実在する**」 | **取り下げない。ただし範囲を狭める。** `Contracts = 1` ＋ `All` の3点は上の内訳のとおり2点が baseline の崩れ。**残るのは `Threshold = 30` ＋ `All`（台2・+2.9）**で、こちらは **`Contracts = 0`（枠が一度も塞がらない）**なので artifact では説明できない |
| §6「**代金は取り立てた分をどれだけ出力に換えられたかで決まる**」（`All` < `Single`） | **取り下げない。** 枠の話と独立に**はしご6点すべて・4台すべて**で出ている（`Contracts` は既定の 0） |
| §11「機構そのものは完全に動いている。帰属 +3.3〜+39.0pt」 | **取り下げない。** 帰属の分母は `V0`（素体）で、`Contracts` は既定の 0 ＝ 枠は一度も塞がらない |
| §11 の推奨「既定を `(30, 60, 1, All)` にする」 | **取り下げる。** `Contracts = 1` を既定にする根拠が消えた。**推奨は `(30, 60, 0, All)`**（下の A-6。`Contracts` だけを戻す） |

## A-6. §2 のどれが筋か —— **(c) を推す**

**`Contracts` を既定 0（無制限）に固定し、1 と 2 はノブとして残置する。**

理由を4つ。

1. **`Contracts` の「面白い設定」は1つしか無く、それが器具の baseline を壊す。**
   `Contracts = 1` は `Vp` を「1体にしか癒せない版」に化けさせる（`異なり(貸)` 1.00〜1.05）。
   既定に据えると、**この駒について以後に測るすべての `yP` に同じ注釈が付く**
   ——`checkup` の 52 枚は `Traits` の配列から札を抜いて `yP` を作るので、
   **ノブで壊れた baseline を器具の側から検出する手段が無い。**

2. **(b)（`Vp` を「取り立て量 0」で作る）は `checkup` と噛み合わない。**
   第74期の切り出し（`ThinBlade` / `Await` / `Seal`）は**札を分けるだけで挙動は同じ**という作法で、
   `yP` は**配列から `TraitId` を抜く**ことで機械的に作られる。
   量を 0 にする `yP` は**ノブを渡す必要がある**ので、52 枚に一般化できない
   ——**1枚のために器具の作り方を変えることになる。**

3. **(a)（枠の開放を `Indulgence` へ移す）は、移す価値がまだ測れていない。**
   取り立てが実際に開けている枠は **`異なり(貸)` 1.01 → 1.28（台2）/ 1.05 → 1.35 / 1.00 → 1.38** で、
   **1戦あたり 0.3 体ぶん**しかない。
   しかも「一定の条件で枠が空く」の素直な実装は**「常に空く」＝ `Contracts = 0`** である
   ——(a) は結局 (c) に手数を足した形になる。**開放に値段が付くことを先に測ってから作るべき。**

4. **(c) でも駒は死なない。** `Contracts = 0` の代金は −0.1 / −4.8 / −2.0 / −1.9 と負のままだが、
   **帰属は +10.1〜+39.0**（`All`・4台）で、
   **`All` < `Single` という符号の割れ方**も `Threshold = 30` ＋ `All` の正の点も残る。

> **推奨の既定: `IndulgenceRule(Advance: 30, Threshold: 60, Contracts: 0, Blast: All)`**
> ——**`Contracts` だけを 1 → 0 に戻し、他は第155期の既定のまま**にする。
>
> **`Threshold` を 30 へ下げるのは推さない。** 代金が正になる唯一の artifact でない点は
> そこ（台2 +2.9）だが、**それは台2 1台だけの話**で、他の3台では
> **代金が −0.1 → −1.0 / −2.0 → −2.8 / −1.9 → −1.9 と悪化するか動かない。**
> 帰属も台2 が +38.8 → +46.4 と跳ねるだけで、他の3台は +39.0 → +38.1 / +10.1 → +9.4 / +24.0 → +24.0。
> **1台でだけ跳ねるノブを既定にすると、第58期の `Gain`（ホタ専用のノブ）と同じ形になる。**

## A-7. この追補で分かった則

> **マイナスの札を外して `yP` を作る器具では、「外すと開かなくなる門」がないかを先に数える。**
> `Toll`（取り立て）を外すと負債が永久に残るので、**`Contracts` の枠が二度と開かない**
> ——`yP` は「マイナスを外した版」ではなく**「プラスの出口が1つ塞がれた版」**になっていた。
> 症状は**手番の空振りではなく集中**で、実測では
> **前借りの回数も癒した総量も増えているのに勝率だけが 8.5pt 落ちる。**
> **「`yP` のほうが回数が多い」は健全さの証拠にならない。**
> **数えるのは回数ではなく<u>到達した相手の異なり数</u>である**（1.01 対 2.15）。
>
> 第119期「**マイナスを外した版は駒の半分には作れない**」（1つの札が両義の 28 体）の
> **ノブ側の版**で、あちらは**札が分けられない**ケース、こちらは
> **札は分けたのにノブが2つの札を結び直している**ケースである。
