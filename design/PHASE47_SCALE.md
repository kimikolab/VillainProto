## 前提の訂正（指示書とリポジトリの食い違い）

指示書の作法どおり、**止めずに進んで**ここに列挙する。全4件。

1. **「敵に範囲攻撃が無い波では、ヒビの台の供給はゼロになるはず」（§5-1）は成立しない。**
   `ShatterTrait.OnDamaged` は `source.CurrentPattern == AttackPattern.Single` で早期 return する
   ——つまり**貫きも範囲として数える**。第二波（狙撃手）・第四波（詠唱兵）も供給源を持つので、
   **5波すべてに最低1枚の供給源がある**（Phase 0-3 の表）。
   さらにヒビの台では**味方のボルグの薙ぎの巻き込み**が毎ターン供給になるので、
   実際の律速は敵の範囲ではない。

2. **`StatusKeys.All` の要素は 7 個で指示書の把握どおりだが、`IdleTurn` は状態異常ではない。**
   `TickStatuses` は Poison / Burn しか進行させず、Marked / Stun は engine の別の場所、
   `IdleTurn` / `Armor` / `Wound` は「時間で進まない記録」。**読み手の数え方をキーごとに
   揃えられない**ので、Phase 0-1 の表は「engine が読む場所」と「Trait が読む場所」を分けてある。

3. **§4 の「ログか `Events` から数えること」は採らず、`BattleContext` の計数を足した。**
   第41〜46期（`ShoveFired` / `BearSoaked` / `SlanderTotal` / `OverbearFired` …）が
   全部この形で、**盤面には一切影響せず `verbose` にも依存しない**。
   指示書の意図（盤面の値から推定しない）は満たしている。ログ文字列は1つも数えていない。

4. **味方ロスターは 46 枚**（指示書は枚数を書いていないが「貫きは常時では0枚」は正しい）。
   `Def.Pattern` は 単体 43 / 薙ぎ 3（ボルグ・ドルガ・ハギ）/ **貫き 0 / 全体 0**。
   `ModifyPattern` の既存実装は把握どおり **3つ**（後衛特化＝貫き / 墓守＝薙ぎ / 熾火＝貫き）。

    if (source is null || source.CurrentPattern == AttackPattern.Single) return;

## 1. 予測（実装の前に書いた）

### 予測1: 2つの台の「初纏い」ターン

- **死軸台**: 第一波は死亡 1.3件/戦しかないので **半数以上の試行で一度も纏わない**と予測。
  第2〜5波は死亡 4.4〜5.8件/戦・決着 5〜7ターンなので、初纏いは **T2 前後**（T1.8〜T2.6）。
- **ヒビ台**: 供給は敵の範囲 + **味方ボルグの薙ぎの巻き込み**。ボルグは速さ8で毎ターン振るので
  **T1 に立つ**と予測（T1.0〜T1.4）。第四波だけは詠唱兵が溜めるが、ボルグが供給するので変わらない。
- **したがって「供給の時間分布が違う2つの台」という設計の狙いは成立する**
  （死軸は死ぬまで待つ・ヒビは開幕から出る）。

### 予測2: 纏い率（`Armor > 0` のターン割合）

収支で見る。獲得は死1件につき4（死軸台で 4.5件 × 4 ≒ **18/戦**）、支出は
攻撃 1回につき 1（`CostPerAttack=1`・ウロは速さ7で毎ターン振るので **約6/戦**）と**被弾**。
**被弾側が圧倒的に大きい**——敵の1発は 11〜38 で、**アーマー4はどの敵の一撃にも足りない**。
つまり獲得した4は**次に殴られた1回で必ず全部消える**。

したがって **纏い率は「殴られない時間の割合」に近づく**と予測: **25〜45%**。
**支出・攻 : 支出・被 は 1 : 3 以上**で、**律速は被弾側**＝この駒は「攻撃型」ではなく
構造的に「防御型」の側に落ちる。枯渇回数 ≒ 獲得回数（毎回使い切る）。

### 予測3: 後列到達 ÷ 貫き

貫きはレーンを前から走って**生きている全員に当たる**ので、
**敵の後列が生きていれば必ず届く**。落ちるのは2通りだけ:
(a) 第一波は敵が3体（前1・前3・中央）で**後列が存在しない** → 到達 0、
(b) 敵の後列が先に落ちている試行。

予測: **第一波 0% / 第2〜5波 70〜90% / 全波平均 55〜75%**。
**ただし到達しても威力は薄い**——ウロの攻9 がレーンの3体目に届くと減衰50%で **4**。
「後列に手が届く」は成立するが「後列を削る」には足りないと予測する。

### 予測4: `CostPerAttack` 0 / 1 / 2

0（維持型）が最も強い。ただし**差は小さい（0 と 1 の差は 2pt 未満）**と予測する。
理由は予測2——**支出の主役が被弾側なので、攻撃の支出を 0 にしても纏い率はあまり伸びない**。
**もし 0 が 5pt 以上明確に強ければ、このノブは性質ではなく強度しか切っていない**（第41期と同じ結末）。

### 予測5: 第四波・第五波の値

土台の値は 死の連鎖 (リィカ軸) = 100/100/100/**11.0**/**47.5**、
範囲耐性 (ヒビ×ボルグ) = 100/100/100/**68.0**/**18.0**。
ウロは攻9・HP70 の中位の駒で、抜く駒（ヴェル＝蘇生2回 / リィカ＝墓守）より弱い。
予測: **死軸台 第4波 5〜20% / 第5波 25〜45%**、**ヒビ台 第4波 45〜70% / 第5波 10〜25%**。
**どちらも後半2波に「届く」（0% にならない）が、土台を超えはしない。**

### 予測6: `seats2` の席の分散

**隣接を1つも読まない**ので、第45期の対照（隣接も列も読まない駒＝最頻率 65%）に近いはず。
ただしウロは**貫きを持つ**ので、**列（レーン）の効果**が入る余地がある
——第45期の分類でいう「列を読む駒」に近づく可能性がある。**65〜80%** と予測する。

### 判断1: `AcceptsSupport` を見ない（§3-1 のとおり）

砕けと揃えた。**アーマーは damage 側で消費されるプールで、回復でも強化でもない**ので、
弱体の窓口（`ctx.Dull`）の作法ではなく砕けの作法に従う。
第42期からの持ち越し（`AcceptsSupport` の扱いが5経路で3通りに割れている）には触っていない。

### 判断2: 召喚枠（儚い駒）の死も供給に通す（§7-6）

**通す。** 理由は3つ。

1. **供給が無限に近くならない。** 胞子は胞子を産まない（`SplitterTrait` は儚い駒には効かない）ので、
   ムグ1体につき最大3件で打ち止め。`ReviverTrait` が儚い駒を除外しているのは
   「一度きりの効果を持つ駒の価値を蘇生が無制限に掛け算する」を止めるためで、こちらは掛け算にならない
2. **設計として、胞子の死骸も「倒れた味方」である。** 鱗のフレーバーそのもの
3. **量は測って報告できる。** `ScaleGainEphemeral` を別に持たせた

**実測: 死軸台の獲得 18.2 のうち 7.4（40.7%）が儚い駒の死から来ている。**
除外していれば供給は 4割減っていた。ヒビ台は 0.0（胞子を含まない編成）。

### 判断3: 計数は `BattleContext` に置き、ログ文字列は数えない

前提の訂正 3 のとおり。`gullet log` / `yoke log` / `sever` が文字列を数えているのは
「発火しなかったことが盤面の値に痕跡を残さない」ためだが、
鱗は**計数を engine とトレイトに埋めれば同じことが精密にできる**（第41〜46期と同じ形）。
盤面には一切触らず、`verbose` にも依存しない。

## 5. 主表

`素体` = **ウロと数値・型・速さが1つも違わず特性だけを持たない駒**に差し替えた版
（診断のローカルの def。カタログには載せない）。

> **`ScaleRule(0)` は陽性対照にならない。** 指示書 §4 は `ScaleRule(0)` とウロ抜きの2本を
> 指定しているが、**`CostPerAttack = 0` は消費を止めるだけで供給も発揮も止めない**
> ——あれだけでは「鱗が効いたのか、ただ 70/9/7 の体が入っただけか」が割れない。

## 7. 採否の判断材料（§6 の 6〜13）

### 7-1（基準6）: 「貫き」に対する「後列到達」の割合 —— **89.5% / 92.6%**

**発揮先の選び方は間違っていなかった。** 第2〜5波では**貫いたら必ず後列に当たる**（到達率 100.0%）。
全波の平均が 100% を割るのは第一波（敵3体・後列なし）ぶんだけ。

ただし**当たった量は薄い。** 死軸台で 1.71 回 / 12.6 量 ＝ **1回あたり 7.4**。
ウロの攻9 がレーンの2〜3体目に届くと 25〜50% 減衰するので、素の値でこれが上限になる。
**「後列に手が届く」は成立したが、「後列を削り切る」には足りない**
——効いているのは打点ではなく、**後列にいる支援役（施しの司祭長・詠唱兵）に
毎ターン確実に触れること**のほうだと読むのが妥当。

### 7-2（基準7）: 二重支出の内訳 —— **律速は被弾側**

理由は単純で、**獲得の刻み（死1件につき4）が敵の1発（11〜38）より小さい**——
纏った破片は、次に殴られた1回でほぼ必ず全部消える。
**この駒は「攻撃型」ではなく、構造的に「殴られるたび刃をしまう防御型」。**

死蔵は 3.8% / 14.4% と小さい。**第42期の集約（死蔵 2.5%）と同じ結論**——
アーマーは死蔵しない通貨で、生成率より消費率のほうが常に高い。

### 7-9（§7-1 の干渉）: 破片で受け切った被弾では被弾トリガーが呼ばれない

`ApplyDamage` は破片で受け切ると `if (amount <= 0) return;` で抜けるので、
**`OnDamaged` も反撃も走らない**（doc に明記されているとおり）。

実測: ウロへの被弾のうち**受け切ったのは 3.21 回/戦（死軸）／ 1.21 回/戦（ヒビ）**。

**この2行では実害が出ていない**——ウロ自身が `OnDamaged` を持たず、
死軸台にもヒビ台にも被弾トリガーの駒（被弾強化のムド・棘のカド・毒撃のスィド）がいない。
ヒビ（砕け）は `OnDamaged` を持つが、**受切はウロへの被弾しか数えていない**ので無関係。

**ただし「ウロの隣に被弾強化を置く」編成では 3.21 回/戦ぶんの収入が消える。**
これは鱗が作った穴ではなく**アーマーという資源が元から持っている性質**
（砕けが味方全体に配っている時点で同じことが起きている）だが、
**読み手ができたことで初めてこの干渉が編成の判断になる。** 残件に置く。

## 8. 採否 —— **採用する**

必須基準5つを全部通し、機構が素体に対して **+11.7pt / +16.2pt** の帰属を持ち、
`ablate` の入れ得も無く、既存48行は 240 セル中 0 件で不変。

**アーマーは7つの盤面状態キーの中で唯一「書き手が2つあるのに読み手が0枚」だった資源で、
そこが埋まったこと自体がこの期の成果。** 傷（第28期）が
供給→維持攻→消費→維持防 と四役揃うのに4期かかったのに対し、
アーマーは**書き手が既に2つあった**ので1期で読み手が立った。

同時に、**ノブは失敗している**（§7-4）。`CostPerAttack` は性質ではなく強度しか切っていない。
**採用するのは駒と機構で、`ScaleRule` は診断の窓口としてだけ残す**
（既定 `CostPerAttack = 1`。`ShoveRule` / `BearRule` / `RelayRule` と同じ扱い）。

### この期で言えるようになったこと

1. **アーマーに読み手が付いた。** 供給（砕け・集約・鱗）2 → 3、読み手 0 → 1
2. **ロスターに条件付きでない貫きが初めて近づいた。** 既存3実装の条件は
   「後退済み かつ 後列」（セロ）・「燃えている間」（ホタ）で、どちらも
   **編成の外の条件**。鱗は**資源の残高**が条件なので、条件そのものが編成の中で動く
3. **「性質を切るノブ」は律速の項に付けないと強度ノブに落ちる**（§7-4）
4. **「隣接を読まない」は席を分散させる十分条件ではない**（§7-5）。
   分散させるのは「行と列のどちらにも依存しないこと」
5. **供給源の違いが効いたのは「いつ来るか」ではなく「どれくらい細かく来るか」**（§7-3）
