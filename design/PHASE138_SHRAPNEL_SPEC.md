# 第138期 指示書 —— 破片に「出口」を作る（新規駒・礫）

**HEAD 前提: 第137期 `70bca99`**（`ShatterRule` を `Passive` 既定で残置した期）。

**この期の一文**:
> 破片（`StatusKeys.Armor`）を**消費して敵全体へ叩きつける**新規駒を1枚入れ、
> **溜めた破片の総量に意味が生まれるか**を測る。

## 0. なぜこれをやるか

第137期は「砕け（ヒビ）の供給の鍵」を動かして不採用だった。その過程で分かったこと:

| 実測 | 意味 |
|---|---|
| 破片が実際に吸った量は **33.9/戦**（ヒビ被弾 61.8 の **0.55 倍**） | 破片は既に半分は働いている。足りないのは供給ではない |
| ウロの纏い率は 47.4% → 62.9% に上がったのに勝率は落ちた | **二値で読む機構の稼働率と、通貨の総量は逆を向く** |

**破片の出口は `ApplyDamage` が黙って吸うだけ**で、ウロの貫き（`Armor > 0` の二値）以外に読み手がいない。
二値でしか読まれないので、**溜めた量に意味が無い**。第137期が「稼働率が上がったのに負けた」と出たのはここ。

> この期に足すのは供給ではなく**出口**。破片を「量で読む」駒を1枚入れる。

同時に、**ロスター初の全体攻撃**になる（`Def.Pattern` は単体43／薙ぎ3。貫きすら常時は0枚）。

## 1. 設計 —— 礫のガレ（新規1枚）

### 1-1. 駒

| 項目 | 値 | 備考 |
|---|---|---|
| Id / Name | `gare` / **礫のガレ** | 名前は仮。ポンが改名する可能性がある |
| MaxHp | 62 | 仮置き。**この期では振らない** |
| Attack | 9 | 効果が参照するので中位。**振らない** |
| Speed | 6 | **振らない** |
| Pattern | 単体（既定） | 全体になるのは `Skill` の効果であって `Def.Pattern` ではない |
| Traits | `TraitId.Shrapnel` | |
| Actions | `[Skill]`（1要素） | Q0-4 の理由で周期にしない |

- **PlusText**: 「盤面で最も破片を纏っている1体を砕き、砕いた量と自分の攻撃力ぶん、敵全体を撃つ」
- **MinusText**: 「砕かれた駒は、砕かれた量と同じダメージを受ける ／ 砕ける破片が無いターンは何もできない」
- **Flavor**: 守りを剥がして弾にする。味方の装備が次々に無くなるので部隊から追い出された。

### 1-2. 効果（`ShrapnelTrait`）

手番（`OnAction`）で:

```
1. 対象を選ぶ: 両陣営の生存駒のうち Armor が最大の1体。
   - 自分は除外する（ヒビが自分に配らない／ウロが自分の死で発火しないのと同じ作法）
   - 同値が並んだ場合だけ PickOne（乱数を使うのはここだけ）
   - Armor が 0 しかいないなら発火しない（§1-3 の CanAct で手前で落ちる）
2. その駒の Armor を全部 0 にする。砕いた量を shards とする
3. 敵全員に shards * Multiplier + self.CurrentAttack のダメージ
4. 砕かれた駒に shards * SelfDamagePercent / 100 のダメージ（lethal: false）
```

**陣営で絞らない。** 「破片を最も多く纏っている1体」とだけ書く。

> **理由**: 現状、敵に破片を持つ駒は1体もいないので、**この期では必ず味方が選ばれる**。
> だが次期の「場の回復を破片に変える」対称ルール（§7）を入れると敵側にも破片が湧き、
> **礫を1バイトも触らずに敵側の分岐が点灯する。**
> 味方を砕く（自陣の資源を消費する）のと敵を砕く（敵の防御を剥がしつつ撃つ）のは
> **コストの符号が逆**なので、そこで初めて「どちらを砕くか」が編成の判断になる。
>
> **この期の報告書に「敵側分岐の発火 0 件」を回帰値として残すこと。** 次期の点灯確認に使う。

**ダメージ式に攻撃力を足す理由**: `Skill` は通常攻撃を消費するので、
合否テストが自動的に「その駒の通常攻撃 < その効果か？」になる。
攻撃力を式に含めておけば、**「通常攻撃を全体化した上に破片ぶんを上乗せした」**という読み方で
テストが最初から満たされる（攻9 は「攻撃力が本物」の帯なので、無条件に無料にはしない）。

### 1-3. `CanAct` —— 破片が無いターンは撃てない

```
CanAct(kind == Skill) は、盤面（両陣営・自分を除く）に Armor > 0 の駒が1体もいなければ 偽
```

- これが**マイナスの本体**。供給が無い編成では**手番を丸ごと捨てる駒**になる
- 同時に、`IdleTurn` の市場（号令・据え・責め苦）に**原料を供給する**。
  `IdleTurn` が立つのは現状 痺れ／まどろみ／`CanAct` 偽 の3経路しかなく、市場は枯れている

**攻撃力ぶんだけでも撃てるようにはしない。** そうすると破片を1点も読まない全体攻撃駒になり、
この期の問い（溜めた量に意味が生まれるか）が測れない。

### 1-4. ノブ（`ScaleRule` / `BearRule` / `ShatterRule` と同じ作法）

```csharp
public readonly record struct ShrapnelRule(int Multiplier, int SelfDamagePercent)
{
    public static ShrapnelRule Default => new(2, 100);
}
```

- `BattleContext` に `public ShrapnelRule Shrapnel { get; }`。**static のノブにしない**
- **この期に振るのは `Multiplier` だけ**（1変数）
- `SelfDamagePercent = 100` は定数扱いで固定する。
  **根拠**: 破片は元々ダメージを吸うプールなので、100% なら「吸うはずだった分を先に受ける」になり、
  等価交換として説明が1行で済む。ただし**超過分は素通りする**（必ず全部が使われたわけではない）ので
  完全に無料ではない。ここを振るのは次の期

### 1-5. 触らないもの

- ヒビ・ウロ・ウケの定義と特性（`ShatterRule` は `Passive` 既定のまま）
- `compare` 61行 ／ 交差帯 12行 ／ `Presets`
- 既存駒との差し替え（採用後・次期）
- ガレの数値（HP62／攻9／速6）

## 2. 予測（**実装前に書き切って報告書に残す。外れたら消さずに残す**）

Q0-1 の実測を入れてから確定させること。方向だけ先に書く。

1. **ヒビと同席する台で最も大きく動く。** 供給がそこにしか無い
2. **ウロと同席すると取り合いになる。** 礫は「最大保持者」を選ぶので、
   **破片を溜めたウロが真っ先に砕かれ、`Armor > 0` が切れて貫きが単体に戻る**。
   `鱗改` 型の台では**ウロの纏い率が下がる**と予測する。符号は**負**
3. **供給が無い台では手番を捨て続ける。** `IdleTurn` の発生回数が礫の生存Tに近づく
4. **敵側分岐の発火は 0 件**（現状、敵に破片を持つ駒がいない）
5. **ガレを編成に入れない既存の 61行 ＋ 12行は ±0.0**
6. **第四波（軛・単発上限25）で全体攻撃が切られる。** `shards * Multiplier + 攻撃力` が
   25 を超えると上限に当たるので、**Multiplier を上げるほど第四波では伸びが鈍る**と予測する
7. **第137期の逆が起きる。** あちらは「稼働率↑・総量↓」で負けた。
   こちらは**総量を出口に変える**ので、**纏い率（稼働率）が下がっても勝率は上がる**と予測する。
   この2つが同時に観測できれば、§0 の読みが正しかったことになる

> **予測が読む量が実装のどこから来るかを1回たどること**（第130期の則。同じ形で3回踏んでいる）。
> 今回なら「ウロの纏い率を増やすのは誰か」「軛の上限がどこで効くか」をコードで確認してから予測に使う。

## 5. 採否

### 採用の条件

1. **溜めた量に意味が出ている**: `ShrapnelDealt` のうち**破片由来の割合**（`shards × Multiplier`）が
   攻撃力由来を上回る掃引点が存在する。ここが逆なら「ただの全体攻撃駒」であって出口ではない
2. **供給の有無で符号が割れる**: 供給ありの台で上がり、**供給なしの台で下がる**。
   両方で上がるなら破片を読んでいない
3. **特異性**: ガレを含まない 73 行が ±0.0

### 強度の決め方についての縛り（第135・136・137期の則）

> **強度を決めた集合と採否を判定する集合を同じにすること。**
> **結果を見てから掃引点を広げない**（第64期）。掃引点の外で線に届いたことは
> **参考として報告書に書いてよいが、採用の根拠にはしない**（第137期がこれを正しく守った）。

**壊れ気味は許容する。** この段階の優先順位は「新しい編成・シナジーが生まれるか」であって
勝率を揃えることではない。**盤面が成立しなくなるレベル**（供給なしの台も含めて全台が天井に張り付く、
第四波以降が全行100%になる等）でなければ、強すぎる側に倒れていても採用してよい。

### 不採用でも残置する
`ShrapnelTrait` と `ShrapnelRule` は削除せず、**ガレを `UnitCatalog` に残したまま**にする
（測って採らなかった機構は対照として残置、の規約）。

## 7. この期では決めないこと（次期以降の地図）

### 7-1. 次期の本命：**場の回復を破片に変える**（対称ルール）

> 場で回復が起きると、**回復は起きず**、同じ量の破片になる。

**これが礫の敵側分岐のイネーブラになる。** ルールは両陣営に等しくかかるので、
敵の回復役（Q0-7 の `Almoner`・第二波・毎ターン14）の回復が**敵の破片**に変わる。
そこで初めて礫が「敵を砕く」を選べるようになり、**どちらを砕くかが判断になる。**

設計上の勘所（次期の指示書で詰める）:

- **過剰回復が消えない。** 回復は上限で溢れるが破片は溢れないので、**同じ量でも実質増える**
  ——つまり**このルールは敵の回復役を強くする**。それが対称ルール駒の正しい形で、
  礫がその答えになる
- **ガルドに初めて回復が届く。** `Stoic` は `AcceptsSupport` で支援を全部弾くが、
  破片はそれを貫通する。第136期で主力になった壁に、変換を経由して届くようになる
- **第三波の渇き（回復封じ）との順序**が設計判断になる。
  渇きが先に殺すならこの駒は第三波で死に、封じられた回復を拾うなら**渇きの波でだけ光る駒**になる
- **まず波ルールとして第二波で試してから駒に移す**（board-rule 系の標準手順）。
  第二波は 52行中22行が100%で飽和しているという診断が出ているので、課税を1本足す先としても筋が通る
- 実装は `ctx.Heal` にフック1本。**回復を止める場所は `ctx.Heal` の入口1箇所**という
  既存の規則をそのまま使う
