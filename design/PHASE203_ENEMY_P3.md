## 1. Phase 0（実装前・戦闘0回）

出力の全文は `dotnet run --project BattleSim -c Release 0 ep3 phase0`。要点だけ書く。

### Q0-1 敵の隊に陣形を持たせる入口

- `BattleEngine.Materialize(Formation, team)` は**陣営を問わず** `formation.Shape` を駒へ写し、枠 i を `Shape.PlayableSlots[i]` の席に立てる。
  **第200期の味方用の口がそのまま使える**（敵の倍率も同じ `Materialize` で掛かる）
- 貫きの経路は**撃たれる側の陣形**で引き、どちらの2レーンかは**撃つ側の席の格子のレーン**（`GridLane(attacker.Slot)`）で選ぶ。
  撃つ側の陣形は読まないので、X 字の味方もパターン2の味方も、そのまま §2 の「撃つ味方の席のレーン」になる
- 足すのは `FormationShape` のパターン3（一般規則 `BuildGrid` で作る）と、写しの波2本だけ

**いちばん大きいのは殉教**。判定は `SelectTargetChain` の `f.HasTrait(Martyr) && f.Row == Row.Front && f != target`。
パターン3の殉教者は C（○前2 ＝ 前列）に立ち、**C が生きている間、味方の単体の主目標は C だけ**（`PoolOf` は前列の生存者）
——**主目標が殉教者自身なので `f != target` で外れる**。庇いが立つのは、主目標が C 以外になる経路（標の引き寄せ・止め）だけになる。
**「唯一の前衛が庇い持ち」は、この engine では「庇う相手がいない」形である。**

### Q0-3 敵の召喚・分裂

- 第三波・第五波の駒で `ctx.Summon(` を持つ札: **0 体**
- 敵陣に湧くのは味方の背かれ（ソム）の餌だけ（`FodderSlot = 7` 決め打ち）。パターン3では 7 に C が立つので陣形の召喚枠へ落ちる。
  **ソムは `compare` 61 行に 0 行**（主表には出ない）
- **決め: パターン3の召喚枠は 前1 → 前3 → 中央 → ○後2**（編成に使っていない4マス・前から）。X 字の餌が ○前2（前列）に立つのと同じく、餌は前列に立つ

### Q0-6 DemoApp の再生

`BattlefieldView3D.PawnPosition(team, slot)` は陣営を問わず 0〜8 の9席すべてに座標を持つ。**描き足しは要らない見込み**。
要るのは「写しの波で戦を始める口」（`--demo-enemy-p3`）だけ。

### 形の読み（Phase 0 から・予測の根拠）

| | X 字（元） | パターン3（写し） |
|---|---|---|
| 最初に単体が触れる | 前1・前3 の2体 | C の1体 |
| 薙ぎ（開幕） | 前1 を薙ぐ → 前1・前3・中央（3体） | C を薙ぐ → C・B・E（3体） |
| 薙ぎ（前が落ちた後） | 中央を薙ぐ → **中央だけ**（X 字の表は「同じ列＋中列」） | B か E を薙ぐ → **中衛2枚＋後衛2枚（4体）**（一般規則は「同じ列＋1つ後ろの列」） |
| 貫き | 前 → 中央 → 後（3体） | C → 中衛 → 後衛（3体） |

- **貫きは開幕から後ろへ届く点は X 字も同じ**（X 字の貫きも前 → 中央 → 後を抜く）。貫きが「相対的に上がる」理由は形からは出てこない
- **薙ぎは前が落ちた後に X 字より強くなる**（1 → 4 体）
- 第三波: 勇者候補（処刑・攻20・速14）が前列から中衛へ下がる。X 字では最初の2体の片方、パターン3では C を割った後の2体の片方
  ——**勇者候補が長く生きる**。一方で渇きの祭司は X 字では前の2体を割るまで触れず、パターン3では C を割れば触れる——**渇きは早く解ける**
- 第五波: **殉教の庇いが消える**（Q0-2）。前列の HP は X 字 142（殉教者 52 ＋ 勇者候補 90）→ パターン3 52（殉教者だけ）
