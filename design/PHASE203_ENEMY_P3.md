### Q0-1 敵の隊に陣形を持たせる入口

- `BattleEngine.Materialize(Formation, team)` は**陣営を問わず** `formation.Shape` を駒へ写し、枠 i を `Shape.PlayableSlots[i]` の席に立てる。
  **第200期の味方用の口がそのまま使える**（敵の倍率も同じ `Materialize` で掛かる）
- 貫きの経路は**撃たれる側の陣形**で引き、どちらの2レーンかは**撃つ側の席の格子のレーン**（`GridLane(attacker.Slot)`）で選ぶ。
  撃つ側の陣形は読まないので、X 字の味方もパターン2の味方も、そのまま §2 の「撃つ味方の席のレーン」になる
- 足すのは `FormationShape` のパターン3（一般規則 `BuildGrid` で作る）と、写しの波2本だけ

**「唯一の前衛が庇い持ち」は、この engine では「庇う相手がいない」形である。**

### 形の読み（Phase 0 から・予測の根拠）

| | X 字（元） | パターン3（写し） |

| 最初に単体が触れる | 前1・前3 の2体 | C の1体 |

## 3. 実装

### 3-1 足したもの

| 場所 | 何を |

**engine の判定は1行も足していない**——敵の陣形は第200期の味方の口（`Materialize` が `formation.Shape` を写す）をそのまま通り、
貫きの選び方は第202期の `Facing`（撃つ側の席の格子のレーン）がそのまま効く。

### 3-2 実装で踏んだ穴 —— 背かれの餌が1度も湧かない

`BattleContext.Summon(def, team, at: 7)` は `IsSummonSlot(7) && free` のときだけ湧き、**そうでなければ null を返す**（召喚枠の走査へは落ちない）。
パターン3では 7 に C が立つので、ソムの餌は**パターン3の敵に対して1度も湧かない**状態だった。
Phase 0 は「走査へ落ちる」と読んでいて、`ep3 check` (4) の最初の版も「編成の席に湧いた 0」「C の席に湧いた 0」で **○** を出していた
——**湧いた回数そのものが 0** だったのを見て気づいた（R034 の再発・§5）。
直し: 餌の席を `FodderSlotOf(陣形)` で引く（X 字は 7 のまま）。検査に「湧いた回数 > 0」を足した。直した後は 100 戦で 354 回・すべて前1。

もう1つ、帳簿の最初の版は**駒の `InstanceId` を `Run` の前に引いていた**（番号は `Run` の中の `BattleContext.Add` で振られる）ので、
前列の被弾・貫き・薙ぎの列が全部 0.00 で出た。勝率の列は `InstanceId` を使わないので影響していない。

「前列」は開幕に前列に立っていた敵（元は前1・前3 の2体、写しは C の1体）。

| 三 | 元 | 6.14 | 94.1% | 3.39 | 6.32 / 1.75 / 0.53 / 0.07 | 0.63（0.61） | 2.14 | 1.25 | — | 618 / 296 |

| 五 | 元 | 6.37 | 91.1% | 3.21 | 5.59 / 1.39 / 0.38 / 0.07 | 0.47（0.44） | 2.09 | 1.40 | **1.204** | 563 / 132 |
| 五 | 写し | 6.00 | 97.7% | **1.79** | 2.74 / 0.76 / 0.23 / 0.00 | 0.24（0.23） | 2.83 | **2.83** | **0.000** | **0 / 623** |

読める出来事は3つ:

1. **前列は早く崩れる**——前列の HP が1体ぶんしか無いので、全滅するターンが 三 3.39 → 2.57・五 3.21 → **1.79**。
   崩れた後は中衛2枚が同時に一番前の列になる
2. **崩れた後の薙ぎが 1.25〜1.40 体 → 2.75〜2.83 体**。X 字の表は中央を薙いでも中央しか巻き込まない（`SweepTable[2]` は召喚枠だけ）が、
   一般規則は「標的の列＋1つ後ろの列」なので、**中衛を薙ぐと中衛2枚と後衛2枚に届く**。薙ぎの群を持ち上げた本体はこれだと読む（Phase 0 の読みどおり）
3. **殉教の庇いは 1.204 → 0.000 回/戦（61 行すべてで厳密に 0）**。Q0-2 の読み（主目標が殉教者自身になって `f != target` で外れる）に加えて、
   主目標が C 以外になる経路（標の引き寄せ・止め）は**鎖の標の段で先に返る**ので殉教の段まで来ない。
   **「唯一の前衛が庇い持ち」は、この engine では庇いを捨てる形である**

貫きは「開幕から C の後ろまで届く」が、**届いた回数はむしろ減った**（0.61 → 0.37 ／ 0.44 → 0.23）——前列が早く崩れるので、
「前列が生きている間に撃つ貫き」の機会そのものが減る。元の形でも写しでも、貫きが抜くのは同じ3体である。
