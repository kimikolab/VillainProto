## 1. 画面の変更（第97期からの差分）

| どこ | 前 | 今 |

### V2 の判断の目安（指示書 §2）

**同時に画面に出ている線が、1回の攻撃の着弾数を超えないこと。**
実装は「組」で切っている——**ダメージの組の番号は直前の `Attack` の位置**なので、
薙ぎの巻き込みも貫きの各段も同じ組に入り、**扇と数珠つなぎは崩れない**。
`Attack` を持たない出来事（毒燃の刻み・状態異常・移動・反撃）は**1件ずつ独立した組**になる。

**浮く札（数字）は消していない。** 段違いに出しているので重ならないし、
「いま何点入ったか」は次の攻撃と並べて読めたほうがいい。

### V4 の単発モードは `compare` と同じ呼び出し

    compare      BattleEngine.Run(編成, 波, seed, verbose: false)
    単発モード    BattleEngine.Materialize してから Run(UnitState 版, seed, verbose: true)

`Run(Formation, …)` は中で `Materialize` を呼んで `Run(UnitState 版, …)` に渡すだけなので、
**この2つは同じ経路**。開始盤面（`BattleOpening`）を組むために `UnitState` の側が要る
（`InstanceId` は `ctx.Add` が `Run` の中で振るので、**`Run` の後に**record にする——
`EngagementEngine` と同じ手順）。**他のノブは1つも渡していない**（既定で回る）。

## 5. 実装（表示専用であることの根拠）

### 5-1. BattleCore（1箇所だけ）

`EmitStatusSnapshot` の `StatSnapshot` の emit に **`Pattern = u.CurrentPattern` を1行足した**。

- **新しいフィールドは足していない**（`BattleEvent.Pattern` は `Attack` / `Damage` が既に使っている）
- `Emit` は **`verbose` のときしか積まない**ので、`compare`（`verbose: false`）は1件も作らない
- **盤面にも計数にも触っていない**——`u.CurrentPattern` を読むだけ

### 5-2. GodotApp

`Main.cs` だけ。**盤面の幾何（レーンの奥行き・X字・列の並び）は1行も動かしていない。**

- `Script` 型を足して**会戦と単発の違いを1箇所に閉じた**（`Battles` / `Openings` / `StageIx` / `SquadIx`）。
  再生のコードは1本のまま
- `BuildState` の `StatSnapshot` で `Piece.Pattern` も更新（V1）
- `GroupOf(idx)` で「1回の攻撃＝1組」を作り、組が変わったら `_shots` / `_flashes` を消す（V2）
- `_showGainLines`（既定 `false`）・`NextAttack()`・`0.25×`・モード切り替えの UI（V2/V3/V4）
- カードの右上を `FormationRules.SeatNames[slot] + 型` に（0-1 の 2）
