### Q0-2. `Actions` を持たせたときの周期の穴

| 問い | 実装 |
|---|---|
| `ActionIndex++` は `CanAct` の前か後か | **後**（偽なら `IdleTurn` を立てて `Stalled` で返る） |
| バサの `Actions` | **`[Skill]` の1要素**（`ActionIndex % 1` が常に 0 ＝ 周期は止まらない） |
| `CanAct` 偽のとき `IdleTurn` | **立つ** |
| 号令・据えが買えるか | `Trait.SurrenderedTurn` は **`ActionKind.Attack` で問う**ので、`kind != Skill` で早期 return すれば**買える** |

### Q0-3. 二重掛けを避ける

`ShuffleStagger` は **None / Advanced / Both / Confuse / ConfuseOnAction** の5枝になった。
`ConfuseOnAction` のとき、ターン頭の `Settle` は**印を置いて早期 return する**（混乱は1件も立てない）。
`ConfuseUses` は**この枝では読まない**（`Derange` の引数 `useStock` で分ける・上限は手番そのもの）。
`ConfusePercent` は**読む**（撃ったが外した手番を作れる）。

### Q0-4. 手番で狙う相手の選び方

| 項目 | 決め |
|---|---|
| 候補 | そのターン**行が前に変わった敵**（印 `ShufflerTrait.AdvancedTurnKey` ＝ `ctx.Turn`） |
| 既に混乱している敵 | **候補から外す**。他に候補が無ければ撃たずに `IdleTurn` |
| 複数いたら | `Roll` で1体（**`PickOne` は新たに使わない**・必須4） |
| 記憶 | **立てられる側にターン番号**。`InstanceId` を跨がないので `OnCarryOver` が要らない |

**`CanAct` と `OnAction` は同じ述語（`Fresh`）を見る。**
これで「撃つ」か「手番を差し出す」かのどちらかしか起きず、受け入れ条件（§4-2）が成り立つ。

## 予測（`tumult2 run` を回す前に書いた。外れても消さない）

1. **供給が増える。** 在庫3回から「毎ターン1回（撃てるとき）」になるので、混乱の発火は
   **3 → 5〜7 回/戦**。ただし撃てないターンがあるのでターン数ぶんには届かない
2. **与ダメ0の影響は小さい**（第143期のササと同じ形）
3. **被弾変換が厚い台が最も伸びない**——敵の攻撃が敵に向くと餌が減るので、混乱が増えるほど損も増える。
   **負に転じる可能性もある**
4. **手番市場（据え）の台で `IdleTurn` が買われる。** 撃てないターンが据えの −50% の収入になる
5. **号令同席の台では、号令の +8 がバサに流れて丸ごと死蔵になる**（Q0-8）。
   V0（通常攻撃のバサ）では死蔵しないので、**この台だけ V1 の帰属が他より低く出る**
6. **遅延が計数に出る。** 速い敵（勇者候補14・槍騎兵12・狙撃手11）に立てた混乱は次のターンに持ち越すので、
   「立てた回数 > そのターンに発火した回数」になる
7. **ササ同席で供給に化けない**（混乱は敵→敵）。化けたら味方も混乱している＝実装の穴
8. **バサを含まない行は ±0.0**
