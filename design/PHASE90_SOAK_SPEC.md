## 0. 主題

### 0-1. まず器具を1つ直す —— 紙の停止条件を門から外す

第88期で「大きさは線にしない」と主判定を作り替えたのに、**Phase 0 の停止条件
（紙 ÷ 総被ダメージ ≥ 5%）という大きさの線を門のところに残していた。** 指示書の欠陥である。

第89期がそれで落ちた。**鎖は全部つながって動いていた**——隣に傷のある率 99.9%、
ガルド1体の深さ 平均 2.69・最大 8、ハリの糸口の深さ 2.53 → 3.05、
**理想台の勝率 70.2 → 73.6%（+3.4pt）**。それでも紙は 0.82% で門に弾かれた。

**線が版をまたいで持ち運べない**ことも、2期分の実測で分かる。

| 期 | 出力の増分 | 勝率 |
|---|--:|--:|
| 第87期（ミオ・攻撃側） | **+8.3%** | +1.0pt |
| 第89期（ガルド・防御側） | **+0.82%** | **+3.4pt** |

**変換率が 30 倍違う。** 攻撃側の出力と防御側の出力では勝率への効き方が別で、
**固定の % で門を作れる量ではなかった。**

> **【規約の変更】紙のスループットは今後も Phase 0 で必ず出すが、門にはしない。**
> **門は「鎖が繋がっているか」で判定する**（§1-3）。紙の値は表に出し、実測との照合
> （自己検査）にだけ使う。**2×2 は5〜6分なので、門で節約できる計算量はほとんど無い。**

### 0-2. 何を作るか —— 滲み則

**傷を持つ相手には、状態異常が深く入る。**

- **毒**: 傷を持つ相手に毒を書くとき、**層が +1 される**
- **燃焼**: 傷を持つ相手に火を点けるとき、**残ターンが +1 される**（3 → 4）

**両陣営に等しくかかる。** 味方も第85期の巻き込み則で傷を負うので、
**傷を負った味方はグザの毒漏れ・ボルグの火の粉を深く受ける。** 非対称なのは
「こちらはその規則を知って編成を組める」という一点だけ。**マイナスを別に足さない。**

### 0-3. なぜこれが候補か

1. **単価の壁を構造的に回避する。** 第84・86・89期は3回とも
   **「傷1つ = 3点」という一撃で払い切る形**で落ちた。滲み則の払い出しは
   **層と残ターン**——毎ターン刻む通貨なので、1回の書き込みが残りターン数ぶん払い出す。
   **第87期（ミオの着火）が唯一その壁を越えて採用された形の一般化である。**

2. **既存の駒が1文も増えずに読み手になる。** engine 側の規則なので、
   **グザ・スィド・ラウ（毒）とボルグ（燃焼）が、定義を1文字も変えずに傷の読み手になる。**

3. **AND ゲートに当たらない**（第88期 §8-3）。傷の供給（キリ・ノミ）も、
   毒・燃焼の書き手も、**両方すでに盤面にある**。足すのは変換の規則1本だけ。

4. **傷の意味が変わる。** いまの傷は「後で殴るための貯金」で、
   **持ち主が落ちれば投資が消える**（第85期の実測: 未読の傷は味方側 84% / 敵側 78%）。
   **脆弱性なら、その場で使い切られるので消えない。**

### 0-4. 範囲を絞った理由（**測る前に固定**）

**深さを持つ状態異常は毒と燃焼だけ。**

- **痺れ**は `SetCounter(StatusKeys.Stun, 1)` の二値で、深くしようがない。
  **確率を上げる案は別の機構**（トウの確率を触ることになる）。**この期では触らない。**
- **破片（`Armor`）**は味方に書くもので、「傷を持つ相手」の枠に入らない。**触らない。**
- **標**は深さを持たない。**触らない。**
- **ミオ（`AmplifierTrait`）は対象外。** 第87期で既に傷を読んでいる（着火）。
  **同じ駒に2本目の傷の読みを足すと二重取りになる。**

→ **実際に読み手になるのは グザ・スィド・ラウ・ボルグ の4枚。**

### 1-1. (P1) ガルドの再判定（**本編より先に。別コミット**）

第89期は**紙の門で止まったので 2×2 を1戦も回していない**。§0-1 で門を外したので、
**同じ機構を第88期の特異性の規約で測り直す。** `GatherRule` は残置されているので実装コストはゼロ。

- **A ＝ ガルド**に固定。B ＝ 残り50体。**情報帯（第88期 §4-1）を当てる。**
- **ノイズ床は第89期 §1-1 の規約**（同じ実験の中の意図しない相手の \|Δ相乗\| の 95 パーセンタイル）。
- **意図した相手** ＝ ハリ・ゴルム・ボルグ・カド・ナラ・リィカ・ゾト の7枚。

- **情報帯の割合を必ず併記する**（第88期 §8-5。ガルドは攻9・HP100 なので床は薄いはず。
  **ミオの 56.5%・カドの 65.2%・ハリの 70.1% と並べる**）。

**通れば `GatherRule.Default` を `true` にし、ガルドの `PlusText` を
「味方への攻撃も傷も肩代わりし、その傷のぶん強くなる」に直し、
`TraitEntryMap.Supplies[Guardian]` に `(CarryWound, Where.Self)`、

**採用する場合、本編は採用後の盤面の上で測る。** 順序を報告書に明記すること。

**機構が1回も発火しなくても乱数列がずれた**（`compare` 17セル/10行）。

> **同数のタイブレークに `PickOne` を使うと、機構が発火しなくても盤面が動く。**
> **RNG 中立が要る場面では決定的なタイブレーク（席番号の昇順など）を使う。**

**ガルドの引き取り先の選び方を決定的なタイブレークに直し、
`compare` が Z0 と ±0.0 になることを確認してから (P1) を測ること。**
（**これは第89期の実装の訂正であって、機構の変更ではない。**）

## 2. 変更の定義（**測る前に固定**）

### 2-1. ノブ

### 2-2. 毒 —— 窓口を1つ作る

**毒には現在まとまった窓口が無く、各特性が `SetCounter` を直接叩いている。**
`BattleEngine` に薄い窓口を1つ足し、**範囲内の書き手だけをそこへ通す。**

```csharp
public void Poison(UnitState target, int amount)
{
    if (!target.IsAlive || amount <= 0) return;
    int add = amount;
    if (Soak.Enabled && target.Counter(StatusKeys.Wound) > 0) add += 1;   // 傷の数に比例させない
    target.SetCounter(StatusKeys.Poison, target.Counter(StatusKeys.Poison) + add);
    // ログは現行の各特性の文言を保つ（差分を読めるようにするため）
}
```

**通すのは 瘴気（グザ・敵と味方漏れの両方）／毒（スィド）／疫み（ラウ）の3つだけ。**
**ミオ（`AmplifierTrait`）は通さない**——増幅も着火も既に傷を読んでいる（第87期）。

- **足すのは定数 1。傷の数に比例させない**（第84期の単価の壁に自分から入らない）。
- **味方漏れも同じ窓口を通す**（両陣営に等しくかかるのがこの規則の要点）。
- **既存の呼び出しの意味を変えない。** `SetCounter` の加算量・ログ・計数は現行のまま。
  **`Soak.Enabled` が false のとき、盤面が W0 と1セルも違わないこと**を自己検査で示す。

### 2-3. 燃焼 —— 窓口は既にある

`BattleEngine.Ignite` の1本だけ。

```
turns = BurnRules.Turns
if (Soak.Enabled && target.Counter(StatusKeys.Wound) > 0) turns += 1
target.SetCounter(StatusKeys.Burn, turns)
```

- **点け直し（`relit`）でも同じ**。非スタックなので残ターンを戻すだけだが、**戻す先が 4 になる。**
- **`BurnLit` / `BurnRelit` / `FirstBurnTurn` の計数の意味を変えない**（第57期の計数）。
- **`friendly: true` の経路も同じ**（味方の火の粉も深くなる）。

### 2-4. 表の更新（**採用したときだけ**）

滲み則は engine の規則で `TraitId` ではないので、**`TraitKeyMap` は触らない。**
`TraitEntryMap.Reads` に **`Miasma` / `Venom` / `Contagion` / `Cinder` へ
`(UnitTally.CarryWound, Where.Foe)` を足す**（4枚が傷の読み手になったことの記録）。
**第80〜83期の派生値が動く。数え直しはしないが、動いたと書く。**

## 7. 実装の注意

- **`BurnRules.Turns` を書き換えない。** 滲み則は `Ignite` の中で局所的に +1 するだけ。
  **static のノブにしないこと**（Trait は共有シングルトンで layout は戦闘を並列実行する。
  `ColossusRule` / `YokeRule` / `HushRule` と同じ判断）。
- **毒の新しい窓口は「加算の入口」だけを担う。** 減算（ベニの啜り・ヴィオ）や
  上書き（ミオの着火 `SetCounter(Poison, 1)`）は通さない。
- **ログの文言を変えない。** 差分を読めるようにするため、各特性の現行のログを保つ。
  **滲みで深くなったときだけ1行足す。**
- **`ctx.PickOne` を使わない。** この機構に同数のタイブレークは無いはずだが、
  必要になったら**決定的なタイブレーク（席番号の昇順）**にする（第89期 (h)）。
- **敵側にも毒・燃焼の書き手がいないか確認する。** いれば滲み則は敵側でも走る。
  **それは仕様**（両陣営にかかる）だが、**回数を出すこと。**
- **蘇生・会戦の境界。** 毒も燃焼も `StatusKeys` なので既存の掃除に乗る。**新しい規則を作らない。**

## 8. 申し送り（**第91期の入口**）
