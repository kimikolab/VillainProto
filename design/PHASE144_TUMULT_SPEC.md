# 第144期 指示書 —— バサの転生（敵陣を掻き回し、前に出した敵を転ばせる）

**HEAD 前提: 第143期 `f341c01`。**

**この期の一文**:
> 喧噪のバサを**「隊列を乱す。敵味方を問わない」**駒に作り直す。
> 毎ターン**敵2体**と**味方2体**をそれぞれ入れ替え、**行が前に変わった敵は転んで次の手番を失う**。
> 併せて、第143期で拒否権3が立った `置き去り×分散回復` の席を `confirm` の上で差し替える。

本書は自己完結している。リポジトリ外の文書は参照しない。

## 0. なぜこれをやるか

### 現行のバサは期待値ゼロの駒

「毎ターン味方2体の位置を**無作為に**入れ替える」は、「傷ついた前衛が下がる」と「無傷の後衛が前に出る」が
半々で起きるので**入れ替えそのものの期待値がゼロ**。読み手（ヨミ・シオ・ハネ）がいない編成では何も生まない。
第106期の `LooseRule` の doc に「**喧噪のバサ −1.4**」（ササの弾きと同席させても伸びない）とある通り。

### 「最も傷ついた⇔最も無傷」の交代型は落とした

期待値をゼロでなくする案として検討したが、**他人の被弾を自分に集める駒は仕事をするほど下げられる**
（ゴルム・ドハ・セッキと構造的に噛まない）ので採らない。

### 採るのは「敵を乱す」＋「前に出した敵は転ぶ」

- **敵側には隣接表を読む特性が無い**ので、敵の入れ替えは**標的選択だけを動かす最も安い介入**
- ただし**入れ替えだけでは勝率は上がらないと予測する**（ポンの見立て）——現行の波には
  「前列が突出して硬く後列が厄介」という構造が薄く、しかも無作為
- そこで**転倒**を足す。第143期に engine 側へ入った手番喪失の窓口（`StatusKeys.Stagger`／`TakeTurnCore`）を
  **敵に向ける**。味方に使ったときは「宛先を選べないので最悪の相手に当たる」で落ちたが、
  **敵に使えば「選べない」は敵側の分散**であって代金ではない
- **「行が前に変わった敵だけが転ぶ」**ので方向が付く——後列から引きずり出された祭司・狙撃手は
  **露出した上に1ターン動けない**。同じ行の入れ替えでは転ばないので自己制動が効き、
  無作為が「当たり／外れ」として読める
- **第五波の殉教者（庇い 75%）とは噛まない**ことが最初から分かる。庇いは単体にしか効かず席を読まないので、
  殉教者の手番が消えても庇いは止まらない

### マイナスは現行のまま「味方も乱れる」

味方2体の入れ替えは現行どおり残す。理由:

- 「**喧噪は敵味方を問わない**」で一文が閉じる
- 味方側の入れ替えは「後列前提の駒や庇う駒の配置を自分で壊す」と分かっている**実在の代金**
- **移動軸の供給が消えない**（ヨミ・シオ・ハネの餌はバサからも出続ける）
- ササ（第143期・前1で固めて隣を弾く）と同席すると、**ササの切り落としの宛先をバサが毎ターン飛ばす**
  ——2枚の乱れ方が干渉する編成判断になる

対案「バサ自身が騒いだ次のターン息切れする（`IdleTurn` を売る）」は、第36期の則
「**安い手番は売っても安い**」に当たる（バサの手番は攻7しか無い）ので採らない。

## Phase 0（実装前に必ず全部答える。答えを報告書に転記する）

### Q0-0. `git fetch` して origin から behind でないことを確認する
**毎期の最初の項目。**

### Q0-1. `SwapSlots` は敵陣営で動くか（**最優先**）

Web 側が読んだかぎり `SwapSlots(self, destSlot, by)` は `self.TeamId` で相手を探すので**陣営を問わない**。
`OnMoved` の通知も「動いた側の陣営の味方」へ流れる（敵側に読み手はいないので空振りするだけ）。
**確認すること**:

- `LivingMembers(self.TeamId)` 以外に `PlayerTeam` を決め打ちしている箇所が `SwapSlots` 周辺に無いか
- `HasFallenBack` が敵にも立つが、それを読む規則が敵側の標的選択・後退に影響しないか
  （第124期の `Advances` と同じ「表示専用か判定に効くか」の確認）
- 敵の `Formation` も **5枠 X字**（`ENEMY_FORMATION` 系の構想では敵専用の9枠は未実装）。
  召喚枠（5–8）に敵が立っていることがあるか。**あれば入れ替えの対象から外す**（`PlayableSlots` だけを見る。散開・逃亡と同じ作法）

### Q0-2. 会戦の持ち越しが敵の席の移動でずれないか

`Engagement.cs` の doc は「会戦を跨いで駒を同定する手段は `(TeamId, Slot)`」と書いている。
一方で「`UnitId` 同定する——Slot がずれたか測る診断で Slot を同定キーに使えないため」ともある。
**敵の席を戦闘中に動かしたとき、次の部隊戦で持ち越された敵が正しく同定されるか**を
`engage` で1組だけ確かめる（バサ在席の会戦行を1つ選び、持ち越し前後の敵の `Def.Id` と席を目視）。
**ずれるなら、この期は敵の入れ替えを会戦の境界で戻す（`Slot` を初期化する）か、
会戦を測定から外すかを決めて報告する。** 実装で直そうとしない。

### Q0-3. 転倒は敵の手番でも立つか

第143期の転倒は `TakeTurnCore` で `actor.RawCounter(StatusKeys.Stagger) > 0` を見て `Stalled` を返す。
**敵の手番も同じ経路を通るか**を確認する。通らないなら、通す変更は engine 側で1箇所のはずだが、
**それが味方の転倒の挙動（第143期の残置）を変えないこと**を `brace` の (a') 検査で確かめる。

また **`IdleTurn` が敵に立ったとき、それを読む味方の機構が無いか**
（号令・据え・責め苦は味方の `IdleTurn` を読む。敵側の `IdleTurn` を読む駒があれば列挙する）。

### Q0-4. 各波の敵の配置と「後列にいる特性持ち」の一覧（**段B の予測の根拠**）

`EnemyCatalog.Stages` から、第1〜5波それぞれについて **席順（前1/前3/中央/後1/後3）と特性**の表を作る。
特に:

- **後列（後1・後3）と中央に、特性を持つ敵がいる波はどれか**（施しの司祭長・渇きの祭司・詠唱兵・狙撃手・殉教者・勇者候補…）
- **前列が「突出して硬い」波はどれか**（HP・肩代わり）
- 第五波の殉教者はどの席か

**この表から「転倒が効くはずの波」と「効かないはずの波」を Phase 0 の時点で書き分ける。**
第143期の反省（分布を見ずに予測を書いた）を繰り返さない——**この表が出るまで §3 の予測を確定させない**。

### Q0-5. `置き去り×分散回復` の席の `confirm`（段0）

第143期の持ち越し。`docs/reseat.md` の粗順4（**前1 ササ／前3 ガルド／中央 セロ／後1 ドルガ／後3 ナラ**）が

- **MinusText**: 「入れ替える相手は選べない。後列前提の駒や庇う駒の配置を自分で壊す」（現行のまま）
- **Flavor**: 現行のまま

### 1-2. `ShufflerTrait` の改修

`OnTurnStart` で:

```
1. 味方: 現行どおり。自分を除く生存味方から2体を Roll で選び SwapSlots（1文字も変えない）
2. 敵（Foes が真のとき）: 敵の生存駒（PlayableSlots 上）から2体を Roll で選び、
   入れ替える前に両者の Row を控える → SwapSlots(a, b.Slot, self)
3. 転倒（Mode が None でないとき）: 入れ替えた2体のうち
   - Advanced: DepthOf(新しい Row) < DepthOf(元の Row) の敵に Stagger を 1 立てる
   - Both: 2体とも（対照・採用候補ではない）
```

**`SwapSlots` は触らない。** 前に出たかは特性の側で `FormationRules.DepthOf` を比べて決める
（`HasFallenBack` は「後ろへ動いた」しか記録しないので使わない）。

**乱数は `ctx.Roll` のみ**（現行の味方側と同じ）。`PickOne` を新たに使わない（必須4）。

### 1-3. `ShufflerRule`（`ScaleRule` / `BraceRule` と同じ作法・static にしない）

```csharp
public enum ShuffleStagger { None, Advanced, Both }
public readonly record struct ShufflerRule(bool Foes, ShuffleStagger Stagger)
```

- `(false, None)` ＝ 現行（段0・回帰の基準）
- `(true, None)` ＝ 段A
- `(true, Advanced)` ＝ 段B（採用候補）
- `(true, Both)` ＝ 段C（上限の測定）
- **既定は最終的に採用した値**。回帰は「バサを含まない行が ±0.0」で取る

### 1-4. 触らないもの
- `SwapSlots`／`OnMoved` の通知順序／`Stagger` の engine 側（Q0-3 で通す必要が出た場合の1箇所を除く）
- 味方側の入れ替えの規則（Roll・自分を除く・2体）
- ササ（`BraceRule`）・受け流し・軛
- バサの数値（HP56／攻7／速8）

## 3. 予測（**Q0-4 の表が出てから確定させる。実装前に書き切り、外れても消さない**）

方向だけ先に書く。**波の名指しは Q0-4 の表で差し替えること。**

1. **段A はほぼ動かない**（±3pt 以内）。上がるとすれば「後列に回復役がいる波」だけ
2. **段B は「後列・中央に特性持ちがいる波」で上がり、「前列だけの波」「殉教者の波」で動かない**。
   後列の特性持ちが前に出る確率は無作為で決まるので、**波ごとの上がり幅は
   「後列にいる特性持ちの数 × その手番の価値」に比例する**（Q0-4 の表から見積もりを書く）
3. **段C は段B より大きく上がるが、全波で一様に上がる**（方向が消えるので波の性格が見えなくなる）。
   これが「採用候補ではない」の証拠になる
4. **読み手なしの台で段B が正になる**ことがこの期の合否。読み手ありの台だけで上がるなら、
   敵側の機構は働いていない
5. **肩代わり同席の台は現行と同じだけ下がる**（味方側の入れ替えは1文字も変えていない）
6. **バサを含まない行は ±0.0**

## 5. 採否

### 採用の条件
1. **読み手なしの台で段B が正**（敵側の機構が単独で働いている）
2. **波ごとの符号が Q0-4 の表と一致する**（効くはずの波で上がり、効かないはずの波で動かない）。
   全波一様に上がるなら「乱す」ではなく「手番を削る」だけの駒なので、段C と区別がつかない
3. **肩代わり同席の台が現行より悪化していない**（マイナスが増えていない）
4. **特異性**: バサを含まない行が ±0.0

**壊れ気味は許容する**。ただし段B で**全台が天井に張り付く**なら、転倒の対象を
「前に出た敵のうち1体（席番号最小）」に絞る版を1点追加して報告する（採用はしない）。

### 不採用のとき
`ShufflerRule` は残置（`(false, None)` が現行と同値）。**段A（敵の入れ替えだけ）が正なら、それだけ採る**という部分採用も可。
