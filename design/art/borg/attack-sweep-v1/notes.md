# ボルグ・攻撃開始の差分からの薙ぎ（試作 v1・Claude Code・2026-10-11）

ユーザー要望: 手番の攻撃で、なるべく動きのある感じで大剣を薙ぐモーション。ユーザーが攻撃開始の差分を描いた（`../borg-sweep-windup-v1.png`・1536×1024・透過）。
ここから剣を大きく振るう単発の動画を作る。**ゲーム未適用。**
先行の試作（Codex）は `../attack-i2v-v1/`（通常絵からの I2V・候補 D を推奨）・`../attack-keyframe-comfy-v1/`（始点終点・刃が円弧に曲がる／剣が消える）・`../attack-keyposes-v2,v3/`（構えと振り切りの静止差分）。

## 方法（先行との違い）

- 起点を**ユーザーの攻撃開始の差分**にした（剣が既に後ろへ引かれている → 振り抜きから始まる）。
- 振る方向（右）にだけ余白を足した: 右 768・上 128・左 128 → 2432×1152 の緑の板 → 1280×608・49 コマ（約 3 秒）。
- 待機ループの道具の節点を使い回し、`VP Idle Loop Find` は外して全コマを透過（BiRefNet_toonout × VP Green Key Alpha）。
- プロンプトで力の順番（前膝 → 腰 → 肩 → 腕 → 刃）と、刃が「一枚のまっすぐで硬い鋼の板・曲がらない・消えない・両手は柄」を指定。
  円・円弧の語は使わない（先行で刃そのものが曲がった）。炎・剣閃は書かない（ゲーム側で重ねる）。
- A: 腰の高さで右へ大きく薙いで振り抜きを保つ。B: 後ろ足で押して全身をひねり、低く薙いで右上へ振り抜く。seed 2022 / 5055。
- 再現: `D:/comfyui/venv/Scripts/python.exe design/art/borg/attack-sweep-v1/run.py A,B 2022,5055`（プロンプト全文は `manifest.json`）、
  確認: `inspect_sweep.py <tag>`（4 コマおきの帯・等速/2 倍速 GIF・枠に触れるコマ・足元）。出力は `D:/comfyui/output/VillainProto/attack_motion/`。

## 結果

4 本とも: 刃の湾曲・消失・枠からのはみ出し 0、足元 588〜592px（固定）。**最初の 17〜23 コマは構えのまま止まる**（使うときは振り始めの 3 コマ前から切る）。振りは約 8 コマ（0.5 秒）で一気に通る。

| 候補 | 振り始め | 動き | 気になる点 |
|---|---|---|---|
| A-2022 | 17 | 左後ろ → 正面を横切って右へ。踏み込んで刃を前へ突き出した姿勢で止まる | 終わりが「薙ぎ」より「突き」に見える |
| A-5055 | 20 | A-2022 と同系。28 コマで刃が体の前を横切るのが見える | 刃の赤い亀裂が途中から薄れる。終わりは突き |
| B-2022 | 23 | 刃を低く通して右下の斜めへ振り下ろして終わる（振り抜き感が最も重い） | 28 コマで体が正面（カメラ）を向く。36 コマで刃が短く見える |
| B-5055 | 20 | A-5055 とほぼ同じ（同じ seed） | 終わりは突き |

比較 GIF: `D:/comfyui/output/VillainProto/attack_motion/borg_sweep_compare4.gif`（振り始めの少し前から・等速）。採否はユーザーの確認待ち。

## 案3: 振り抜いた後の姿勢をプロンプトで書く（C / D）

ユーザー評価（v1）: 最後が突きの形、刃の側面でひっぱたいている感じ。→ 振り抜き後の姿勢と「刃の縁で斬る・側面で打たない」を書き、
負のプロンプトに「突き・剣を前へ向けて止まる・刃の側面・ひっぱたく」を足した。C/D はキャンバスを 2560×1536（左 256・上 512・右 768）→ 1280×768 に広げた。

| 候補 | 結果 |
|---|---|
| C-2022（水平に体の向こうへ巻き込む） | 刃が体の後ろを抜け、後半は体の前で立てたまま胴と重なる。薙ぎに読めない |
| C-5055 | 最後はまた突きの形 |
| **D-2022（肩の上へ振り抜く）** | 体の前を薙いでから刃が向こう肩の上へ上がり、頭の後ろで止まる。突きは消えた。頭の後ろを通る 36〜44 コマは刃がほぼ隠れて短く見え、腕の交差もやや不自然 |
| D-5055 | 薙がずに頭上へ振りかぶって止まる（振り下ろしの準備に見える） |

## キーフレーム（ユーザーが添付した振り切りの差分 2 枚）

添付 1 枚目 = `../attack-keyposes-v3/borg_attack_followthrough_arms_v5.png`（頭上）、2 枚目 = `../attack-keyposes-v2/borg_attack_contact_right.png`（低い振り切り）。
**構えと頭上の差分は刃がどちらも左上を向くので、2 枚だけで始点終点にすると最短経路（腕を上げるだけ）に省略されるおそれがある**（先行の試作でも指摘）。
そこで低い振り切りを中継に、S1: 構え → 低い振り切り、S2: 低い振り切り → 頭上 の 2 区間に分けた。

- `keyframes.py`: 3 枚を同じキャンバス（1920×1472）に、足底から腰布の上端までの高さで倍率を合わせ（低 1.024・頭上 0.885）、
  **腰（腰布の上端の中央）と足底で位置を合わせた**。後ろ足で合わせると胴が 250px 左右にずれ、体ごと滑る動きになるため。重ね合わせは `keyframes-overlay.jpg`。
- `flf.py`: Wan2.2 Fun Inp 14B（20 steps・CFG 3.5・shift 5）・1040×800・25 コマ（約 1.5 秒）。刃は硬い板・縁で斬る、の文は案3 と同じ。
- `join.py`: 2 区間を 1 本に（S1 の全 25 コマ ＋ S2 の 2 コマ目以降 = 49 コマ・継ぎ目の差 2.39）。

| 区間 | 2022 | 5055 |
|---|---|---|
| S1 構え → 低い振り切り | **刃が左上から体の脇を下り、右下へ約 8 コマで振り抜ける** | 4 コマで終点へ跳ぶ（途中が無い） |
| S2 低い振り切り → 頭上 | 4 コマで終点へ跳ぶ | **右下 → 水平 → 垂直 → 向こう肩の上 → 頭の後ろへ連続して回る**（剣先が 11〜15 コマで上端にわずかに触れる） |

採用候補: `borg_flf_join_a`（S1-2022 ＋ S2-5055・49 コマ）。比較 GIF `borg_sweep_compare_D_vs_key.gif`（左 D-2022・右 キーフレーム）。採否はユーザーの確認待ち。
**始点終点の区間は seed によって「途中を省略して終点へ跳ぶ」ことがある**（4 本中 2 本）。区間ごとに 2 seed 回して動いた方を選ぶ。

## 採用: F-5055（2026-10-12）

ユーザーが F-5055 を採用。指摘: 「振り切る前に元の位置に戻っている。振り切ってから元の位置に戻るようにしたい」。

- 原因 1（連番の中）: 3〜4 コマで胴と腕が前へ約 90px（連番の画素）踏み込み、5〜6 コマで元の位置へ引き戻されてから右下へ振り切る
  （終点の絵＝低い振り切りが元の位置にあるので、生成が途中で戻す）。
  → `export_clip.py` が胴（腰布の上端から 200px 上の帯）の x の累積最大との差を `forward` としてコマごとに書き、
  再生側がその分だけ前へずらして**踏み込んだ位置を振り切りまで保つ**。最後のコマを見せる 0.3 秒で元の位置へ滑らかに戻る。
- 原因 2（汎用の攻撃）: 敵の前へ踏み込む駒は、命中の直後に席へ戻っていた → **連番が終わってから席へ戻る**（`ReturnAfterAttackClip`）。
- 連番の名前を `attack_clip/borg_sweep/` にし、**既定で使う**（`--borg-attack-clip=none` で従来の差分絵）。F-2022 はゲームから外した（生成物は残る）。
- 検証: `BorgAttackClipCheck`（既定で連番・足底・振り切りまで前へ出たまま・汎用の攻撃で振り切ってから席へ戻る・倒れたら停止）、
  FireCheck --replay / --audio、IdleLoopCheck、PortraitStateCheck、MovementPortraitCheck、SoraDeflectCheck、SusuPortraitCheck、
  `--demo-autoplay`（`火選り (ヒヨ×ホタ)`・第三波）→ すべて OK。StagingEffectCheck は既存の「状態一覧の網羅」（Grappled・Web のアイコン無し）で途中停止。
- 画面: `outputs/borg-attack-clip/borg_attack_adopted_ingame.webp`（前半: 燃焼攻撃の入口・後半: 通常の攻撃）。
