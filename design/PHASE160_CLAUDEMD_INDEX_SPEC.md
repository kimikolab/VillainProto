# 第160期 指示書 —— `CLAUDE.md` の一般則を索引化する

**HEAD 前提: 第159期の master（push 済み）。第159期の完了後に着手する。**

**この期は文書だけを触る。** `BattleCore` / `BattleSim` / `docs/` を1行も変えない。
**測定も行わない。**

---

## 0. なぜ

`CLAUDE.md` が **232.7k 文字**で、Claude Code の 150k 制限を超えている。

### 0-1. 原因は1箇所に特定できている

| 節 | 文字数 | 割合 |
|---|--:|--:|
| **指示書を書くときに当てる一般則** | **181,617** | **44%** |
| コマンド | 79,662 | 19% |
| アーキテクチャ | 72,063 | 17% |
| 現状値 | 54,526 | 13% |
| 知見の索引 | 37,613 | 9% |
| その他5節 | 26,353 | 6% |

**一般則の節は 248 段落のフラットな平文**で、小見出しが1つも無い。1段落あたり中央値 702 字。
**期ごとに増え、一度も消えない。**

### 0-2. 第112期のスリム化がなぜ効かなかったか

第112期は「則の根拠になった実測を `design/LESSONS_*.md` へ出した。**本文は1文字も変えていない**」とある。
**根拠だけを外に出して則の本文を全部残した**ので、本文が長い（702字）以上は容量が減らない。

しかも 248 段落が平坦に並んでいるので、**必要な則を探すには全部読むしかない**。
**長いのに引けない**という一番悪い形になっている。

### 0-3. この期の目標

> **一般則を「1則1行の索引」に変え、本文を `design/` へ出す。**
> **181,617 → 約 15,000 字。`CLAUDE.md` 全体で 232.7k → 約 67k。**

`知見の索引` 節（37k）で既に成立している形を、一般則にも適用するだけである。

## 1. やること

### 1-1. 則に ID を振る（**これが本体**）

一般則の 248 段落に、`CLAUDE.md` での出現順に **`R001`〜`R248`** を振る。

> **ID は永続する。** 一度振った番号は**欠番になっても再利用しない**。
> 以後、報告書や指示書から則を指すときはこの ID を使う。

### 1-2. 本文を `design/RULES_*.md` へ逐語で移す

**1文字も変えない**（第112期と同じ作法）。ID 順に、**1則1小見出し**で並べる。

```markdown
### R045 — reseat の1位を採否の根拠にしてはいけない

（元の段落をそのまま。1文字も変えない）
```

**小見出しの要旨（`—` の後）は新しく書く**が、**本文には一切手を入れない。**

**1ファイル 50,000 字を超えないよう ID 範囲で機械的に分ける**
（`design/RULES_001_060.md` のように。分け方は**主題ではなく ID 範囲**——主題で分けると判断が入る）。

### 1-3. `CLAUDE.md` に索引表を置く

一般則の節を、次の表だけに置き換える。

| ID | 則（1行） | 期 | 主題 | 詳細 |
|---|---|---|---|---|
| R045 | `reseat` の1位は採否の根拠にならない。使うなら次数 | 45 | 席 | `RULES_041_060.md` |

- **則（1行）は 60 字以内。** 「何を禁じ／何を要求する則か」だけを書く
- **期** は則が出た期（複数あれば全部。§1-4 参照）
- **主題** は `知見の索引` の主題別表と**同じ語彙**を使う（傷軸／毒・燃焼／弱体・強化／標／被弾・移動・隣接・席／手番と行動順／ボス／庇いと肩代わり／器具・判定 など）
- 節の冒頭に「**本文は `design/RULES_*.md`。ID で grep すること**」と1行

### 1-4. 再発の例を1行に畳む（**成長を止める本体**）

現在の一般則には、**同じ則を別の期が言い直した段落**が複数ある。
「第123期の再発・**5例目**」「第157期 §1-1・**11例目**」のような表現がその印である。

> **同じ則の段落が2つ以上あるときは、ID を1つにまとめ、索引の「期」欄に期番号を並べる。**
> **本文は `design/RULES_*.md` の同じ小見出しの下に、元の段落を全部そのまま並べる**（削らない）。

**これは判断が入る作業なので、次の手順を守ること。**

1. まず 248 段落を**全部 ID を振って移す**（判断なし・機械的）
2. そのあとで、**畳む候補**を一覧にする（「この ID とこの ID は同じ則」）
3. **明らかなもの（本文が同じ則を名指ししている・「N例目」と書いてある）だけを畳む**
4. **迷うものは畳まない。** 候補として報告書に残し、この期では触らない

### 1-5. 新しい則の書き方を `CLAUDE.md` に明記する

索引表の直後に置く。

> **新しい則を足すとき**: `design/RULES_*.md` の末尾に次の ID で本文を書き、
> `CLAUDE.md` の索引に1行足す。**`CLAUDE.md` に本文を書かない。**
>
> **既存の則が再発したとき**: **新しい ID を作らない。**
> 既存の小見出しの下に段落を足し、**索引の「期」欄に期番号を足すだけ**にする。

## 2. やらないこと

- **本文の書き換え**（要約・短縮・言い換え。**1文字も変えない**）
- **則を消すこと**（古く見えても消さない。索引から外すのも今回はしない）
- **迷う畳み込み**（§1-4 の手順4）
- **他の節の整理**——`コマンド`（79k）・`アーキテクチャ`（72k）・`現状値`（54k）は**触らない**。
  一般則だけで目標に届く
- 実装・測定
