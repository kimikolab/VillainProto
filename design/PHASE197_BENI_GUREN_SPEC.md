## 1. 目的

ポンが遊んだ感想: **ベニは隣の溢れを啜っても、なお満タンのことが多い。** 啜りで埋まらない余りが捨てられている。
その余りを、**敵を焼く大技**に変える。

### 1.1 像と絵コンテ

ベニの立ち絵（鬼娘版）は、火の赤と毒の紫をアクセントに、**火を強めにして映える**ように描かれている。
黒紫の花から、炎の花びらが奔流になって流れ出る絵がある。

1. 隣の味方の毒と火が、ベニの結界で薬に裏返る
2. 満たされたベニから、それでも溢れた澱みが、胸の花に紅蓮として溜まっていく
3. 満ちた瞬間、ベニが腕を振ると、**炎と澱みの花びらの奔流が敵の列を呑み込み、全員が紅と紫に染まる**（火が点き、毒が積もる）

「毒を薬にする者」が、満ちたら敵を焼き、蝕む側に回る。**毎手番ではなく、満ちたときだけ出る大技**にする。
立ち絵のアクセントカラー（火の赤・毒の紫）と、放つものが一致する。

## 2. 変更

### 2.1 紅蓮を溜める

- 第193期の啜り（`InverseSip`）で、隣の溢れをベニに流したあと、**ベニが満タンで入りきらなかった分**を「紅蓮」として溜める
  - 紅蓮 ＝ 溢れの量 − ベニの HP が実際に増えた量
- 紅蓮は状態キー（例 `StatusKeys.Guren`）で持つ。上限は置かない
- 渇き・支援拒否で止められた回復は、第193期と同じく溢れではない（紅蓮にならない）
- ベニ自身の刻みの反転（自分に入った回復の溢れ）は、今までどおり流さない（紅蓮にもならない）

### 2.2 紅蓮を放つ

- **ベニの手番の頭**（周期の火・毒の拍より前）に、紅蓮が **`GurenThreshold`（= 12）以上**なら放つ
  1. **生きている敵全員に火を点ける**（`Ignite(target, friendly: false, source: ベニ)`）
  2. **溜めた紅蓮を、生きている敵全員で等分し、その数だけ毒の層を積む**（端数は切り捨て、切り捨てた分は捨てる。0 なら積まない）。毒は窓口（`ctx.Poison`）を通す
  3. 紅蓮を 0 に戻す
- 放ったあと、その手番の周期（火→毒→毒）はいつもどおり続ける（周期の位置は進む）
- 手番を失った（痺れ・竦み・粛など）手番では放たない（溜まったまま次の手番へ）
- 乱数を引かない

### 2.3 ノブと版

| 版 | 内容 |
|---|---|
| 無 | 紅蓮なし（第196期の盤面） |
| **毒**（規定） | `GurenThreshold = 12`・着火＋等分した毒の層 |
| 直撃 | `GurenThreshold = 12`・着火＋等分した**直撃ダメージ**（毒の代わり。比較用） |
| 低閾 | 毒の版で `GurenThreshold = 6`（頻度が上がる） |
| 全額 | 毒の版で**等分せず全員に満額の層**（参考。強すぎる上限の目安） |

- 規定の版（`docs/` に載る版）は **毒**
- すべて `const` で切り替える

### 2.4 燃焼との重なり（今の規則のまま）

- 敵の毒と燃焼は、ミオの濃縮の印（刻み 1+n 回）の対象になる。奔流で毒を得た敵には、ミオの手番の +4 層も乗る
- 奔流の後、敵全員が毒と燃焼の両方を帯びるので、カタの起爆が倍で効く
- スィドの痺れ毒の印がある敵は、層が深まるぶん与ダメージがさらに下がる
- 敵全体に毒を撒くのはグザの役と重なる。グザは毎ターン薄く、ベニはたまに火と一緒に、で住み分ける
- ヒヨ・ホタなど燃焼を読む札への影響は Phase 0 で列挙する

## 5. 予測（実装前に宣言してコミット）

方向だけ。数は Q0-1・Q0-2 を数えてから入れる。

- ベニを含まない行は ±0.0
- 紅蓮は序盤（隣もベニも満タンの時期）に溜まり、初めて放つのは序盤〜中盤
- 毒の版は直撃の版より上（等分の直撃は1体あたり数点にしかならず、毒の層は毎ターン削り続けるため）
- ミオが同じ行にいると、奔流で毒を得た敵に +4 と印が乗り、差が大きくなる
- 低閾は放つ回数が増えるが、1回に積む層は薄い

### `units.md` の文面（案）

- 特性: 自分と隣接する味方は、毒と燃焼で削られる代わりに癒える。隣で溢れた分は自分が啜り、それでも余れば紅蓮として溜める。紅蓮が満ちると、敵全体に火と澱みを放つ / 手番で、隣接する味方全員に火→毒→毒の順で分け与える
- マイナス: 自分と隣接する味方は、回復を受けるとかえって傷つく / 自分では攻撃しない
- フレーバー: 「紅い澱みを分け与え、その余りを啜って生きている。満ちれば、花は燃え、腐らせる。」（ポンが差し替える前提）
