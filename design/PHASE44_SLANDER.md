## 2. 予測（実装の**前**に書いた）

今回の窓口は「保持者の攻撃対象」なので、供給は**攻撃順と前後関係**で決まる。

### 2-1. 誹りの発火回数の上限（＝保持者の生存ターン数 × 1）

誹りの保持者は**前3・HP75・速7**。第二波は決着が速い波（100% 行が19行）で、
前列は開幕から集中的に殴られる。**生存 3〜5ターン**と読む。
発火は **3.5〜4.5 回/戦**（保持者が振れないターン＝痺れ・撃破直後を引いて）。

### 2-2. 誰が誹られるか

敵の標的選択は**前列が生きている限り後列を狙わない**（`SelectTargetCore` の pool）。
したがって**前列2枠に偏る**。さらに庇う（ガルド・28行に在籍）が単体攻撃を
自分に引き寄せるので、**ガルドがいる行では誹りの過半がガルドに乗る**。

ウツの席で受け取る量が何倍違うか:
- **前1のウツ**（分かち×逆しま）: 直接狙われる席。ただし同行の前3にガルドがいるので
  庇うに吸われる。**受け取りは中程度**
- **中央のウツ**（突き返し）: `Row.Mid`。前列2枠が生きている間は狙われない。**少ない**
- **後1/後3のウツ**（逆しま3行）: **ほぼゼロ**

前列ウツ ÷ 後列ウツ ≈ **5倍以上**と読む（後列は前列全滅後の数ターンしか窓が無い）。

### 2-4. 読み手を持たない41行の被害

目減り総量 ≈ 発火 4.0 × Penalty 2 = **8/戦**（Penalty 2 のとき）。
これは第二波の敵の総攻（24+24+11+7+18 = 84）に対して小さいが、
**受け手が偏る**ので効き方は一様でない。

- **支援役の目減りはほぼ無害**（第36期「安い手番は売っても安い」の弱体版が成立する）
  ——クビ攻3・ドハ攻4・ノノ攻3 は殴っても 3〜4 しか出ていない
- **痛いのは受け役**——ガルド攻9 は庇うで誹りを集めるので **5発で 0**。
  ガルドは 28行に在籍していて、そこでは「肩代わりして育つ」（`RedirectGainTrait`）の
  伸びしろまで削られる

41行の第二波平均は **−2〜−5pt** と読む。

### 2-5. 味方の攻撃力が 0 になる回数

**0 ではない。**Penalty 2 で **0.5〜1.5 回/戦**。
内訳の筆頭は**ガルド**（攻9・庇うで集める）、次いで**ノノ（3）・ヒサ（2）・グザ（2）**。
**打点役（攻15以上）は 0 回**——ドルガ38 は19発、ボルグ18 は9発、ハギ16 は8発必要で、
発火 4回/戦の上限に構造的に届かない。

### 2-6. 第二波の 100% の行が何行剥がれるか

19行のうち **2〜4行**が剥がれ、情報セルは **23 → 25〜27** と読む。
剥がれるのは「攻撃力の低い駒で辛うじて削り切っている」行——
`耐久 (ガルド×ノノ)`（攻9+3）と `追撃×据え (ハギ×バン)` が候補。

### 2-7. 符号が反転する行の名指し

- **得をする行: `突き返し (ハネ×ウツ)` 53.0 → 62**（ウツ×3倍・かつ天井から遠い唯一の読み手行）
- **損をする行: `耐久 (ガルド×ノノ)` 100.0 → 90 台**（総攻 9+3+α で削り切っている行に
  誹りが直撃する。しかも庇うで誹りを自分に集める）

## 3. 実装

`SlanderRule.Default` は**無効（`Penalty = 0`）のまま**。

| 置いた場所 | 中身 |

### 3-1. `AcceptsSupport` をどう実装したか（指示書 §2-1・§6-4 の明記事項）

**誹りは `AcceptsSupport` を見ない。判定せずに `ctx.Dull` を呼ぶ**（＝ガルドの `Stoic` にも通る）。
第43期までの5経路と扱いが揃わないが、揃えると既存48行が動くのでこの期では揃えない。

窓口を通る7経路の現状:

| 経路 | `AcceptsSupport` の扱い |
|---|---|
| なまり（分かち） | 無検査 |
| 呪詛の敵側 | 無検査（敵に `Stoic` 持ちがいない） |
| 呪詛の味方漏れ | `SupportTargets` で隣へ流す |
| 突き返しのよろけ | 自前で弾く（隣へ流さない） |
| 萎縮 | `SupportTargets` で隣へ流す |
| 渡しの転嫁 | 無検査（宛先は敵） |
| **誹り（第44期）** | **無検査** |

実測でも**ガルドが誹りの最大の受け手**（67.10 / 戦・全48行合計）になっており、
この判断はそのまま効いている。

### 3-2. engine に足した計数（盤面には一切影響しない）

- `DullTakenByRoute[]` —— 横取りされた量を**経路別**に割る。既存の `BearTaken` /
  `BearPassed` は全経路の合算なので、供給源が複数ある行（誹り＋なまり＋萎縮）では
  「敵が撒いたぶんの何割が資産に変わったか」が引けなかった
- `DullZeroed` / `DullZeroedWho` —— 崖の検算。`CurrentAttack` は 0 で底を打つが
  `AtkBonus` は打たないので、**「0 になった瞬間」は代入の前後でしか観測できない**

### 3-3. 粛（`Hush`）との干渉（指示書 §6-6 の確認事項）

**問題なし。** `Dull` の中の横取り（集約・転嫁）は `Trait.CanReact` も
`ctx.CanActOutOfTurn` も見ていない——コードを読んで確認したうえで、**第二波は粛を持つ波**
なので実測が直接の証拠になる: `引き受け (ウケ×ドハ)` の横取り率 **100.0%**、
`渡し (ワタ×ドハ)` の横取り率 **100.0%**。粛の下でも1つも止まっていない。

これは CLAUDE.md の「肩代わりはダメージの再分配であって行動ではない」と同じ理屈で、
**状態の肩代わりも行動ではない**。

## 8. この期で分かったこと（設計の言葉で）

### 8-1. 敵側に供給源を置くと、供給量と「受け取る側の強さ」が負に相関する

味方側の供給源（なまり・萎縮・突き返し）は**自分の編成の一部**なので、
編成が強ければ長く生きて多く供給する。**敵側に置くと符号が逆になる**——
強い編成ほど供給源を早く割るので供給が減り、弱い編成ほど長く浴びる。

実測: 保持者の早逝 **2.70T**・78% が決着前に落ち、発火は敵の振りの **12.6%** 止まり。
**「敵を早く割れば止まる」勾配（曝きから引き継いだ設計）は、
供給機構に対しては勾配ではなく上限として働く。**

第40期の曝きが機能したのは、曝きが撒くのが**移動**（1回で盤面が変わる離散的な出来事）
だったからで、誹りが撒くのは**蓄積する量**——蓄積は時間を必要とし、
その時間を持てるのは味方が弱い試行だけになる。

### 8-2. 「供給は殴られる駒に落ちる」——第43期の系がもう1本立った

第43期は「隣に置きたい駒は『弱体を受けると困る駒』ではなく『**弱体を受ける駒**』」を出した。
敵側の供給ではこれがもっと強く効く: **誹りの受け手は敵の標的選択が決める**ので、
**肩代わり役に 73% が集中し、読み手には落ちない。**

系: **読み手が「自分の身に来たぶんだけ」を読む型（ウツ）だと、敵側の供給は届かない。**
届いたのは**横取りを持つ2枚（ウケ・ワタ）だけ**で、そこでは横取り率 **100.0%**。

> 第43期の「増幅ゼロでも、届く範囲のほうが出力になる」の**敵側版**:
> **敵からの供給に対しては、範囲を持つ読み手だけが受け取れる。**
> 供給の落ちる席を選べないので、席で受けるしかない読み手は構造的に飢える。

### 8-3. 「情報セルが増える」は「波が分離した」ではない

第二波は情報セル 23 → 25 で改善に見えるが、剥がれた2行は**そのまま固有の勝者**だった
（12 → 10）。**天井を平らに削る操作は、必ずこの形になる**——
天井の行を一様に下げれば情報セルは増え、その波でだけ 100% を取っていた行は消える。

**採否は情報セルではなく固有の勝者で読むこと。** 情報セルは「その波が誰かを区別しているか」を
測るが、**誰を区別しているかは測っていない。**

### 8-4. 肩代わりで育つ駒は、肩代わりで集めた弱体では沈まない

ガルドは誹りの最大の受け手（67.10 / 戦）なのに、攻ゼロへの寄与は **+0.18** しかない。
`RedirectGainTrait`（肩代わりした傷のぶん強くなる）が、**弱体を集めるのと同じ動作で
弱体を打ち消している。** ゴルム（+1.55・見返りを持たない肩代わり）と対照的で、
**「肩代わり役に弱体を撒く」は、見返りの有無で結果が正反対になる。**
