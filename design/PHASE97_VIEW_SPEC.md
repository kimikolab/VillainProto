# 第97期 —— 見える化（何が起きているかを画面で読めるようにする）

起点: 第96期（`hex`・呪いは測って不採用・`SoakRule` に `DullPerKind` を統合・
`compare` 61行・交差帯12行・主判定19行・`docs/` 10ファイル）

**この期は勝率を測らない。盤面の判定に一切触れない。**
**受け入れはポンが画面を見て行う**（§5）。Claude Code は実装と「見るための手順書」を出す。

**クオリティは求めない。** 目的は「ゲームがどんな感じになるか分かる」こと。
凝った演出より、**何が起きたかが1目で区別できる**ことを優先する。

**この指示書は自己完結させてある。** リポジトリの外にある文書を参照しないこと。

## 0. 主題

### 0-1. 見えないと評価できない

第96期の「盤面に書き込まない駒」の列挙で、**ヒビとキリは動きを見たことがないので評価できない**という結論が出た。
第84期から13期かけて採用した機構（巻き込み則・滲み・引き取り・着火・ノノの傷読み・なまりの滲み）は、
**画面に1つも出ていない。**

`CLAUDE.md` の最優先項目は **「このマイナス特性、どうやって使うんだ？」と試行錯誤できるか**。
**試行錯誤するには、起きたことが見えなければならない。**

### 0-2. 今の画面で見えないもの（`GodotApp/Main.cs` を読んだ結果）

| 見たいもの | 現状 | 原因 |
|---|---|---|
| **攻撃型**（単体／薙ぎ／貫き／全体） | 全部同じ線1本 | `Pattern` は `Attack` イベントにしか載っておらず、線を描く `Damage` イベントに無い |
| **状態異常のダメージ**（毒の刻み／燃焼の刻み／直撃） | フィードに文字が出るだけ。盤面では区別できない | `Status` イベントを線でも数字でも描いていない |
| **状態異常が付いた瞬間** | 次のターン頭の `StatusSnapshot` まで出ない | 書き込みのイベントが無い |
| **移動** | フィードに「〜が動いた」の1行 | カードが動かない。**しかも編成一覧に移動軸の駒が1体もいない** |
| **状態異常の名前** | `poison3 wound2` | `StatusKeys` の生の文字列 |
| **条件の成立**（散開・燃焼中の化け・後退時） | 出ない | 事象として emit されていない |
| **編成一覧** | 7つの手写し | `CompareBuilds()` の写し。**第94期の教訓どおり必ずずれる** |

## 1. やること（**上から順に。下は間に合わなければ落としてよい**）

### D1. 攻撃型を線で描き分ける

**`Damage` イベントに `Pattern` を載せる**（§2-1）。そのうえで `PushShot` / `PaintShots` で描き分ける。

| 型 | 描き方（案。**見分けがつけば形は問わない**） |
|---|---|
| **単体** | 今のまま1本線 |
| **薙ぎ** | 主目標への線＋巻き込んだ先を**横に繋ぐ**（扇の形になる） |
| **貫き** | レーンを**前から後ろへ走る太い矢印**。当たった駒を順に通す |
| **全体** | 線を引かず、**敵盤面全体を一瞬明るくする** |
| **反撃**（棘・仇討ち・報い） | 単体と同じ線だが**逆向き**（被弾側から刃側へ）。色を変える |
| **巻き込み**（`FriendlyFire`） | 今の紫のまま |
| **中継**（`Relayed`） | **破線** |

**凡例パネルを1つ置く。** 線の形と色が何を意味するかを画面の隅に出す。

### D2. 状態異常のダメージを盤面で見せる

`Status` イベント（毒・燃焼が「働いた」）を、**線ではなくカードの上に浮く数字**で描く。

- **色を通貨で分ける**（毒＝緑系／燃焼＝橙系）。直撃の数字（`Damage`）は今の赤のまま
- **数字はカードの上に 0.4 秒ほど浮いて消える**。線を引かない（誰からでもないので）

### D3. 状態異常が付いた瞬間を見せる

**`StatusGain` イベントを1つ足す**（§2-2）。**付いた瞬間にカードの端に短い札を出す**（「+傷」「+毒2」など）。
`ActorId` が分かる場合は、**刃の線とは別の細い線**を書き手から引く（ハリの糸・ガルドの引き取り・ミオの着火が見える）。

### D4. 状態異常の名前と色

`StatusText` の `poison3` を **日本語の短い札**に変える。**色を通貨で固定する**（D2 と揃える）。

| キー | 札 |
|---|---|
| `poison` | 毒N |
| `burn` | 燃N（残ターン） |
| `wound` | 傷N |
| `stun` | 痺 |
| `marked` | 標 |
| `armor` | 破片N |
| なまり（`AtkBonus` の負の側） | すでに「攻11→6」で出ている。**そのまま** |

**`StatusKeys` の全数を実装から取ること**（第95期に「7本ではなく8本」の訂正が出ている）。
**手で書かずに `StatusKeys` を列挙して札を当てる**。知らないキーは生の文字列のまま出す（落とさない）。

### D5. 移動を見せる

- `Move` イベントで、**カードを旧スロットから新スロットへ滑らせる**（`Slot` フィールドがある）。
  難しければ**旧位置→新位置の矢印を overlay に 0.5 秒描く**で足りる
- **編成一覧に移動軸の行を足す**。バサ（押し出し）・ハネ（突き返し）・シオ（怯み）・ヨミ（軋み）・
  セロ（後退）・ウケ（引き受け）を含む行を `CompareBuilds()` から**そのまま**持ってくる（§1 D6 と併せる）

### D6. 編成一覧を手写しにしない

**`Builds()` の7つの手写しをやめて、`CompareBuilds()` 61行と `CrossBuilds()` 12行を直接引く。**

BattleSim は実行ファイルなので GodotApp から参照できない。
**`CompareBuilds()` / `CrossBuilds()` の本体を `BattleCore` 側の静的クラス（例: `Presets`）に移し、
BattleSim はそれを返すだけにする。** これは機械的な移動で、**`docs/` 全ファイルが差分0**であることを示す。

**移した後、画面に「編成を選ぶ」一覧が 73 行出るようにする**（名前で選べれば十分）。

**間に合わなければ**: 手写しのまま、移動軸を含む行を4つ足す（**行名を `CompareBuilds()` と一致させる**）。

### D7. 条件の成立を見せる（**できれば**）

**`Highlight` イベントは既にある**（覚醒・破裂で使っている）。次の2〜3箇所で emit を足す:

- **散開のササ**: 隣が空いて `Loose` が成立した瞬間（`ApplyDamageCore` で被弾ごとに評価している）
- **熾火のホタ**: 燃えている間の攻撃が化けた瞬間（`ModifyAttack` が4倍を返したとき）
- **逃亡兵セロ**: 後退して貫きになった瞬間

**Traits.cs を触る**ので、`compare` 305 セル 0 件を必ず確認する。**3つとも Highlight の emit だけ**で、分岐に触らない。

## 2. BattleCore 側の変更（**表示専用。判定に触れない**）

**`Events` は `verbose: true` のときだけ積まれる。`compare` は `verbose: false` で回っているので、
ここを変えても判定は動かないはず。** それを §5 の自己検査で示す。

### 2-1. `Damage` に `Pattern` を載せる

`BattleEvent.Pattern` は既にある（`Attack` で使っている）。**`Damage` の emit 時にも入れる。**
`ApplyDamage` が呼ばれる時点で攻撃型が分かるか確認し、**分からない経路（反撃・状態異常の刻み・共有）は
`Pattern = null` のまま**にして、表示側で「型なし」として扱う。

### 2-2. `StatusGain` イベントを足す

**第93〜95期で作った窓口から emit する**。窓口が無い通貨は**この期では出さない**（触る範囲を広げない）。

| 通貨 | 窓口 | emit |
|---|---|---|
| 傷 | `BattleContext.Wound`（第93期） | ○ |
| 毒 | `BattleContext.Poison`（第90期） | ○ |
| 燃焼 | `BattleEngine.Ignite` | ○ |
| なまり | `BattleContext.Dull` | ○ |
| 痺れ・標・破片 | **窓口が無い** | **出さない**（次期以降） |

```
BattleEventKind.StatusGain
  TargetId = 付いた駒
  ActorId  = 書き手（分かれば。engine の規則なら null）
  Amount   = 付いた量
  Text     = キー名
```

**`NoteStatusGain` の計数には触らない。** emit を並べるだけ。

### 2-3. `Presets`（D6）

`BattleCore/Presets.cs` に `Compare` / `Cross` の2つの静的プロパティ。
BattleSim の `CompareBuilds()` / `CrossBuilds()` はそれを返す。**行名・順序・中身を1文字も変えない。**

## 7. 申し送り（**第98期の入口**）

- **ポンの主観の課題リスト。** 手順書を見ながら「編成してみたくならない駒」を挙げてもらう。
  第96期の A（プラス側が定数）の基準は**マイナス特性を数えていた**ので作り直しが要る——
  **A は「その駒のプラス側の効果が戦闘中に一度も切り替わらない」駒**
- **ササは B だった**（味方が倒れると散開が成立する。第82期に +2.61 の実測）。
  **効果が動いても、動いたことが見えなければ装備と同じに感じる**——D7 で確かめる
- **痺れ・標・破片の窓口。** `StatusGain` を全通貨で出すには窓口が要る。
  第90・93期と同じ形（加算だけを通す）で3本
- **ノイズ床の定義**（第89期 §1-1）は **engine の規則と相性が悪い**。
  意図しない相手が本物の効果で動くと床が上がる（第96期: 11.87pt）。**規約を変えたくなったときは自分の都合を疑う**
- **残っているもの**: 見境のミサ／`AcceptsSupport` の統一／3分の器具の再設計／
  情報セルと測れる席の帯の不整合
