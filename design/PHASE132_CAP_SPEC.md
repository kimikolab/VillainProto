### 0-1. なぜ上限の地図を先に埋めるか

**第131期が、私（指示書側）の未測定の主張を弾いた。**

> 候補のうち1本は取り込んでいない——「型ごとに上限との相性が逆を向く（第128期）」は
> `design/PHASE128_GRADE2.md` に**「軛」の語が1件も無く、測っていない主張**だった。

これは正しい判断である。**私はこの主張を第129〜131期の指示書 §8 に3回書き継いでいた**が、
根拠は第128期の目視のスクショ（責め苦で城塞の重装兵が被309 を受けて立っていた）**からの推測**でしかない。

一方、**第130期は対になる半分を実測している**:

> **上限を持つ波に固定量の継続ダメージを持ち込むと、上限の外側だけが素通りで効く。**
> 燃焼 6/T は上限 25 に一度も触れない——だからいちばん落ちたのが第四波（−79.0）。

**片方だけが規約にあると、もう片方を「同じ話だから」で推測してしまう。実際にそうなった。**

そして**次にやるボルグの倍率案（燃えている敵を薙ぐと威力が上がる）は、一撃を大きくする方向**である。
第四波で切られるなら**倍率を足しても伸びない**。地図が無いまま測ると、
「効かなかった」の原因が倍率なのか上限なのか分からない。

> **順序: 上限の地図（この期） → ボルグの倍率（次期）。**

### 0-2. **地図の半分は既にコードに書いてある**（Phase 0 の出発点）

`BattleEngine.ApplyDamage` の上限のすぐ手前に、こう書かれている:

> **破片（`Armor`）はこの上より前で引かれる別資源なので、上限の外側で効く。**
> **肩代わり（巨躯・分かち・後備え・棘守り）で分割された各段はそれぞれ別の `ApplyDamage` 呼び出しなので、
> 段ごとに独立して切られる——分割は上限を回避する経路になる。
> これは意図した帰結で、「重い一撃は分けて受けろ」が肩代わり役の存在理由になる。**

上限の実装はこうなっている:

```csharp
if (Yoke.Active && amount > Yoke.Cap
    && AllUnits.Any(u => u.IsAlive && u.HasTrait(TraitId.Yoke)))
{ amount = Yoke.Cap; }
```

- **`Cap` = 25**、保持者は**軛の重装兵**（HP145 / 攻12 / 速3・第四波）
- **`ApplyDamage` の1箇所だけ**で切る
- **`amount > Cap` を先に見る**ので、25以下の一撃は保持者の探索すら走らない

**したがって、既に分かっている回避経路が3本ある**——破片・肩代わりの分割・小さい刻み。
**この期はそれを確認したうえで、まだ測られていない「攻撃型ごとの差」を埋める。**

### 0-3. 解くべき矛盾が1つある

第128期にドルガを全体化したとき、**最も跳ねたのは第四波**だった:

| 行 | 第四波 |
|---|---|
| 責め苦 | 1.0 → **65.5** |
| 仇討ち | 18.5 → **94.0** |

**全体は1発が大きいので上限に最も切られるはずなのに、上限の波で最も勝率が上がっている。**
私は目視のあとで「詠唱兵（HP70）を全体の1発で落とせるようになったから」と書いたが、**これも未測定**である。

**この矛盾を解くのが、この期のいちばんの目的**（P4）。

## 2. 予測（実装の前にここに書いてある。後から書き換えない）

### P0 —— 段0・段1 とも台本も勝敗も変えない

**`compare` の 305 セルは `docs/balance.md` と 0 件差分。**
段0 で `docs/rules.md` は大きく動く（P1）が、**既定値は1つも変わらない**。

### P1 —— 「〜」を落とすと 40行以上が一度に動く

Claude Code の見積り。**動いた行がすべて「期の範囲の表記」だけで、既定値の列が1つも動いていない**ことを示す。
**1つでも既定値が動いたら事故。**

### P2 —— 上限を回避する経路は **3本より多い**

§0-2 のコメントは破片と分割の2本を挙げているが、Q0-3 の全件走査では**それ以上出る**はず。
少なくとも**継続ダメージ（毒・燃焼）**が3本目（第130期の実測）。
**`ctx.Revive` が Hp を直接書く**という記述もあるので、回復系にも通らない経路がある。

### P3 —— **切られる総量は 全体 > 薙ぎ > 単体**

1発が大きいほど切られる。全体は同じ倍率を体数ぶん配るので、切られる総量が最大になる。
**貫きは減衰（25%/体）があるので、後ろほど切られない**——切られる総量は薙ぎより小さいはず。

### P4 —— **切られる総量が最大なのに、勝率は上がる**（§0-3 の矛盾の解）

**全体は上限に最も切られながら、第四波の勝率を最も上げる**（第128期の実測）。
理由は**撃破数**だと予測する:

- 上限は**1体あたり25**なので、**HP70 の詠唱兵は全体の1発で落ちない**が、**2発で落ちる**
- 単体で1体ずつ削ると、**過剰分（オーバーキル）が捨てられる**
- **全体は「25 を人数ぶん」配るので、上限の下では単体より効率が良い**

**つまり上限は「1発の大きさ」を平準化する装置なので、上限の下では体数の多い型が有利になる。**
「全体は軛と相性が悪い」という私の主張は**切られる総量では正しいが、結果では逆**——
**そこまで含めて1つの則にする。**

**P4 が外れたら**（撃破数で説明が付かなかったら）、
**第128期の第四波の跳ねは別の理由**なので、その理由を探すのが次の期になる。

### P5 —— 破片は上限の下で価値が跳ね上がる

破片は上限**より前**に引かれる（§0-2）。つまり**上限に切られる前の一撃を、破片が先に食う**。
**第四波でヒビの破片は、他の波より効率が良いはず。**
（ヒビは「範囲攻撃を受けると、その4分の1を破片として味方全員に配る」ので、
**第四波の薙ぎ・全体と噛み合う**。「破片がほぼ機能していない」というポンの実感の例外がここにあるかもしれない。）

## 7. この期では決めない・記録して次期へ渡すもの

1. **ボルグの倍率案（次期の第一候補）。**
   `StatusKeys.Burn` の読み手は**ホタ（自分が燃えている）とヒヨ（味方が燃えている）の2箇所だけ**で、
   **敵が燃えていることを読む駒が1枚も無い**。ボルグは唯一の常時着火役なのに撒いた火に価値が無い。
   案: **「燃えている敵を薙ぐと威力が上がる」**。
   - 着火と発揮が1ターンずれるので自給にならない
   - 薙ぎなので複数体に届き、「燃えている敵が何体いるか」が威力になる
   - **順序**: 倍率が先 → その後 `EmberRule.On`（第130期の残置）を測り直す。
     第130期でボルグを燃やして損をしたのは**ボルグが倍率を持っていなかったから**
   - **(i) ボルグを強くする**と**(ii) ヒヨでボルグを強化する**は別の話。
     ヒヨの対象は「燃えている**味方**」なので、倍率だけではヒヨの対象にならない
   - **この期の P4 が当たったら、第四波では伸びないと予測できる**
2. **ガルドのパリィ案。**
   ガルドの一文「その傷のぶん強くなる」は**実装されていない**——
   `GatherRule`（第89期）は**傷を1つ自分へ移す**だけで、コメントに
   「**ガルドは傷を1つも読まない**」「`ApplyDamage` を通さないので `AtkBonus` は1も動かない」と明記。
   **しかも第122期に `GatherRule(false)` が採用されている**ので、引き取りすら動いていない可能性がある。
   案: **「庇った攻撃を1戦にN回だけ受け流す」**（確率ではなく回数。
   確率だと敵の火力に比例して難易度カーブを平坦化する＝反射を却下した理由と同じ）。
   **Phase 0 で「ガルドが受けたダメージの攻撃型別の内訳」を先に取る**——
   庇いは Single にしか効かないので、**範囲で削られているならパリィの回数が来る前に落ちる**
3. **`checkup` を戻したら、ハギの処遇（転生 or 差し替え）の議論ができる。**
   (b) 差し替えは第119期に「**差し替えは拒否権1 が全部止める**」と記録あり
