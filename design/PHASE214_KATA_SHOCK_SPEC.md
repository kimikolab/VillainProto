置き場所: `design/PHASE214_KATA_SHOCK_SPEC.md`。報告は `design/PHASE214_KATA_SHOCK.md`。
**線は置かない**（採否はポンが遊んで決める）。

## 0. 目的

1. 3つ目の状態異常の軸を作る。**毒＝深さ（層）／燃焼＝時間とトリガー／感電＝密度（場の感電の数と並び）**
2. 触媒のカタ（第188期）を作り直す。今は `compare` 在席0枠で、ポンの実感でも「ミオ ≫ カタ」＝使う理由が無い
3. 拾い屋のススを「血詠みのアカ」に差し替える（**仕組みは変えない**。名前・文面・ログの言葉だけ）

## 1. 感電（新しい状態異常）

`StatusKeys.Shock`（表示の1字は「雷」）。

| 項目 | 決め |
|---|---|
| 値 | **0 か 1 の二値。層を持たない**（層を持つと毒と同じ軸になる） |
| 寿命 | 起爆されるまで残る。時間では消えない。会戦の境界では他の状態と同じく消える |
| 起爆 | 感電している駒が **HP に届く被弾**を受けたら起爆する。破片が受け切った一撃では起爆しない |
| 起爆しないもの | **カタの雷**（§2）・毒と燃焼の刻み（K1。刻みでも起爆する版は K2・§4） |
| 起爆したら | 感電が消え、**同じ陣営の隣接する駒すべてに放電**（1回 `ShockRule.Discharge` ＝ 8・仮） |
| 連鎖 | 放電で HP に届いた隣が感電していれば、その隣も起爆する。**1つの駒は1回しか放電しない**（感電が消えるので必ず止まる） |
| 倒れても | 起爆のきっかけの一撃で倒れた駒も放電する |
| 処理順 | 起爆の塊を席番号の順に幅優先で。**乱数は引かない** |

放電の扱い:
- **状態異常のダメージ**として扱う。行動でも攻撃でもない
  - 粛（ターン外の行動禁止）では止まらない
  - 棘・ツギの板の反射は鳴らない
  - 放電を受けた味方がベニの結界の内側なら、毒・燃焼の刻みと同じ口で**回復に反転**する
- 出どころは**放電した駒**（同じ陣営）とする。味方どうしの放電は「味方が味方から受けたダメージ」になる（＝アカの血になる）
- 撃破の帰属（ハギの追撃・エグ・処刑人などの読み手）は Phase 0 で読み手を洗い出してから決める。仮の決めは「**連鎖を起こした一撃の主**」

## 2. 雷のカタ（触媒のカタの作り直し）

| 項目 | 内容 |
|---|---|
| 名前 | 仮「雷のカタ」（名前・フレーバーはポンが決める。空欄にせず仮の文を置く） |
| 数値 | HP48・**攻 3 → 6（仮）**・速6 |
| 手番 | `[Skill]` 1要素「雷を落とした」。通常攻撃は出ない |
| プラス | 状態異常を帯びた敵に雷を落とし、**状態異常を帯びた隣の敵へ跳ねる**。1発の重さは帯びている種類が多いほど重い。**当たった敵には感電が残る** |
| マイナス | 雷を落とすたび、**カタの隣接する味方すべてに感電**が付く |

雷の細部:
- **最初の一発**: 単体攻撃の主目標の規則（前列が生きている限り前列）で選べる敵のうち、状態異常の種類が最も多い敵。同数は席番号の順。帯びた敵がいなければ主目標の規則どおりの敵に1発だけ落として止まる
- **跳ね**: 今の敵の隣接で、まだ当たっていない・状態異常を帯びた敵のうち種類が最も多い敵へ。同数は席番号の順。候補が無ければ止まる。**同じ敵には戻らない。列は無視**（隣接だけで決まる）
- **1発** ＝ 現在攻撃力 ×（1 ＋ 種類数）。**種類は命中の前に数える**——その雷で付く感電は数えず、前の手番までに付いた感電は数える
- 各命中はカタの攻撃による被弾（撃破はカタの帰属）。ただし**カタの雷は感電を起爆しない**
- **数える状態異常の一覧は Phase 0 で決める**（`StatusKeys.All` から、敵に付く「弱体の状態」だけを `derive scan` で選ぶ。破片・足場・守りの標など味方側の資源は数えない）。報告に一覧を載せる

役割の意図: **カタ＝雷で削りながら感電の道を敷く／仲間＝薙ぎ・連撃・全体で弾く。** カタが1人で「付ける→弾く」を回せないように、雷は起爆しない。

旧カタの札（`Catalyst` / `Backfire`）は**削除しない**（対照）。

## 3. 血詠みのアカ（ススの差し替え）

- **仕組み・数値・札・Id（`susu`）はそのまま**。DemoApp の立ち絵が `susu` をキーにしているので Id は変えない
- 変えるもの: `Name` ＝「血詠みのアカ」／`PlusText`・`MinusText` の「灰」を「血」へ／`Flavor`／ログの言葉
  - Flavor: 「禁術に手を出して破門された。代償を払うのが自分である必要は、どこにも書いていなかった。」
  - 文面の例: 「味方が味方から受けた傷を血として溜め、2手番に1度、溜めた血で魔法を放ち敵全体を撃つ」「血を溜めたまま倒れると、その血が隣接する味方に等分で降りかかる / 敵から受けた傷は血にならない」
- 状態キー名（`Ash`）は変えない（台本の互換）。表示の1字だけ「血」に変えてよいか Phase 0 で DemoApp 側の参照を確認し、Codex の担当ファイルに触る必要があれば触らずに報告する
- **受け入れ**: この差し替えで台本の中身（名前とログの文字列を除く）が1バイトも変わらないこと

## 7. 予測（Phase 0 の後、台の駒を数えて数値を入れてから実装前にコミット）

方向だけ先に書く:

- **P1** カタ・感電の無い行は全版で 0 セル。アカの差し替えは台本が名前とログ以外一致
- **P2** 台1・2 でカタの1回の雷は3体以上に当たり、1発の種類は2以上が主（毒・燃焼＋前の手番の感電）
- **P3** 台3 は K0 より上がる。起爆の過半は薙ぎ・連撃持ちが起こす
- **P4** K2 は K1 より起爆が増えるが、起爆のタイミングがターン頭に偏る（誰が起こしたかの内訳で読む）
- **P5** K1− と K1 の差＝マイナスの代金。台4 では符号が逆（味方側の放電がアカの血になる）
- **P6** 敵のパターン3 は X字より連鎖が小さい（中央が無い）
