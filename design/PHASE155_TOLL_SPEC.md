## 0. この期の狙い

### 0-1. 作る駒

**仮名「贖いのアガ」。** 魔族でありながら聖職者の装いをした男。
**回復役の5枚目**として入れる（既存はノノ・ベニ・シオ・ナラ）。

> **救いは無料ではない。誰もその但し書きを読まなかった。**

**いま大きく癒し、その分を後で取り立てる。取り立てた分を焼く。**

### 0-2. なぜこの形か（第153・154期からの続き）

`design/PHASE153_WARD.md` と `design/PHASE154_WARDCOST.md` を読むこと。2期で確定した則が2本ある。

1. **第153期**——代金を「味方ロスターに読み手のいない通貨」（敵への回復）で払わせると、
   どの編成でも変換できず**定数の損**になる
2. **第154期**——代金が**「抱えている全員」に掛かる**形では、変換器を何枚入れても符号は反転しない。
   ササを入れると切り落としは ×1.96 と機構は完全に動いていたが、増えた被ダメ 166.5 のうち
   ササが払ったのは 37% だけで、残りは埋め草が HP で払っていた。
   **変換器は分子を増やすが、分母は1枚も減らない**

アガはこの2本を**構造として最初から満たす**。

- 代金の払い先は**貸した本人1枚**（分母が絞られている）
- 代金の読み手は**アガ自身**（取り立てた量がそのまま焼きの燃料になる。通貨を外へ投げない）

### 0-3. 既存ヒーラー4枚との次元の違い

既存4枚は全員「HPを戻す」を発火条件だけ変えてやっている（最も傷ついた／敵の毒を数えて／
動かされた味方を／速い味方を）。アガが取るのは**「時間」**——
**いま前借りして、後で払う**。回復量ではなく回復のタイミングを動かす。

## 1. 機構

### 1-1. ループ（実装前にこの表を再現できることを確認する）

|---|---|---|---|

| ② | アガの手番・前借り | **80/80** | **30** |

| ④ | アガの手番・前借り | **50/80** | **60** |

### 1-2. 札3枚（**分けて実装する**）

| 札 | 側 | 内容 |
|---|---|---|
| `TraitId.Indulgence`（免罪） | プラス | 手番で味方1体を `Advance` だけ癒す。**実際に増えた HP を負債として積む** |
| `TraitId.Toll`（取り立て） | マイナス | 負債が `Threshold` に達した味方から全額を取り立てる。**`lethal: false`（HP1 で止まる）** |
| `TraitId.Brand`（焼き） | プラス | 取り立てた量を燃料として溜め、アガの手番で敵へ叩き込む |

**3枚に分けるのは器具の要件。** `checkup` の `yP`（マイナスを外した版）は `Traits` の配列から
代金の札を抜いて作る。1枚に畳むと (ii)（分離できない駒）になり、プラス値が測れない。
第74期に 裂き → `Rend` + `ThinBlade` を切り出したのと同じ作法で、挙動は畳んだ版と変わらない。

**`yP` は `Toll` を抜いた版**（＝取り立てが来ない＝前借りが丸儲け）になる。
**`Brand` は `Toll` の下流なので、`yP` では燃料が1点も溜まらない**——これは正しい挙動である
（代金を外すとその代金から生まれる出力も消える）。**報告書にこの点を明記すること。**

### 1-3. 決めてある設計判断（**変えないこと**）

**(a) 負債は「実際に増えた HP」で積む。**
満タンの味方に撃っても増えないので負債も積まない。`ctx.Heal` は増えた分を既に数えている。

> これにより渇き（第三波）の挙動が自動的に筋が通る——回復が0点しか通らないので負債も0。
> 「前借りできないが取り立てもされない」＝アガが無害化されるだけで、
> 第153期の預かりのような「積むだけ積んで返らない丸損」にはならない。

**(b) 取り立ては殺さない（`lethal: false`）。**
理由は2つ。(1) 殺すとアガが**死軸の駒**になり、ゾト・リィカと同じ「死ぬことが仕事」の群に合流する
——5枚目のヒーラーという枠の目的を外す。(2) リィカの `RaiseCost` が
「起こした反動で自分が倒れると代償が代償として働かない」として同じ判断を下している先例がある。

**(c) 借り手が負債を抱えたまま先に倒れたら、負債ぶん**アガ自身が削れる**（肩代わり）。**
「死んだら踏み倒し」にすると、**借金を作ってから死なせる**が最適手になり、(b) の判断が無効化される。

> **Phase 0 で必ず確認すること**——第153期の記録に
> 「ゴルムの巨躯がリィカの代償を肩代わりして、意図した代金が効かなかった」（8 のうち本人が払ったのは 1）
> という実例がある。**アガへのこの削りが庇い・肩代わりの対象外か**を実装で確かめ、
> 対象になっているなら報告書に書くこと（この期では塞がなくてよいが、測定値の読みが変わる）。

**(d) 取り立ての宛先は貸した本人。** アガが選び直さない。第154期の「代金は1枚に閉じろ」を満たす。

**(e) 前借りは固定値。割合にしない。**
第154期の副産物——`Percent` は整数除算で小さい被弾が丸ごと 0 に落ち、
0.30 倍にすると積んだ量が 0.234〜0.253 倍になった。**強度のノブとして使えない。**
掃引は `Threshold` 側で行う。

**(f) 焼きは攻撃力を経由しない。取り立てた量をそのままダメージにする。**
「攻撃力に加算する」形はこのプロジェクトで3回失敗している——
ゴルムの吐き戻し（第23期・「経路は通ったが出力の総量は動かない。攻撃力という遅い通貨に
変換しているため、使う前に戦闘が終わる」）／ムドの `Rage`（第118期）／
号令（第148期・「払い先が攻撃力なので攻撃しない駒には市場が成立しない」）。
アガは攻4・速6の回復役なので振る回数が稼げず、同じ穴に落ちる。
**取り立てた瞬間に価値が確定する形にする。**

### 1-4. 手番は `[Skill]` 単体。中身は状態で切り替える

```
Actions = [ new(ActionKind.Skill, Label: "赦しを説いている") ]
```

`Trait.OnAction` は状態を読めるので、**engine に介入口を足さずに**中身を分岐できる。

| 状態 | アガの手番 |
|---|---|
| 燃料なし | **前借り**を撃つ |
| 燃料あり（取り立て済み） | **焼く**（燃料を使い切る） |

**`[Skill, Skill2]`（周期で切り替える形）はこの期では作らない。**
まず状態切り替えで測り、効くと分かってから足す。`UnitAction.Label` を
`OnAction` 側で読めば engine を触らずに書けることは確認済みなので、後から足すコストはほぼない。

### 1-5. 焼きの型（**3枝を並べて測る**）

```csharp
public enum BrandBlast { Single, Pierce, All }
```

既定は **`Single`**。標的選択は**通常攻撃と同じ規則**（前列が生きている限り後列は狙われない）。
**ランダムにしない**——第147期に「移動する敵が無作為で読めない」が論点になっている。

| 枝 | 見どころ |
|---|---|
| `Single` | 一番素直。ただし**溜めるほど超過分が捨てられる**（敵のHP上限帯は95前後）。第四波の軛（単発上限25）でほぼ潰れるはず |
| `Pierce` | 味方に**常時の貫きは0体**。第二波の「列を選ばせる」設計が機能していない課題に効く |
| `All` | 味方に**常時の全体も0体**。溜めた量が無駄にならない。ただし**対象数を勘定に入れること**（範囲は敵の体数で価値が変わる） |

> **`Single` は `ctx.TargetPool(self)` がそのまま使える（公開されている）。**
> **`Pierce` は `SelectPierceEntry` が private なので、engine に手を入れる必要がある。**
> Phase 0 で確認し、**engine に規則を足すことになるなら `Pierce` はこの期では落としてよい**
> （`Single` と `All` の2枝で測り、落とした理由を報告書に書く）。

**焼きは `ApplyDamage` を通す**——破片・庇い・軛が正しく効く。
第四波の軛で切られるのは**意図した課税**（積み上げ機構への税）であって、欠陥ではない。

### 1-6. 契約枠（ノブ）

```csharp
public readonly record struct IndulgenceRule(
    int Advance, int Threshold, int Contracts, BrandBlast Blast)
{
    public static IndulgenceRule Default => new(30, 60, 0, BrandBlast.Single);
}
```

`Contracts` は**同時に負債を抱えられる味方の数**。`0` は無制限。

| 値 | 意味 |
|---|---|
| 1 | 一度に一人としか契約しない。**駒として一番綺麗**だが回復役として弱すぎる懸念 |
| 2 | 中間 |
| **0（無制限・既定）** | ヒーラーとして普通に機能する。ただし負債が散ると痛みも散る |

**既定を無制限にするのは、5枚目のヒーラーという枠の目的を守るため。**
1 と 2 は同じ台・同じ seed で掃引して比べる。

## 3. 予測（実装前に書き切る。外れても消さない）

**Q0-2 と Q0-6 が出てから、台の編成表を実際に開いて駒を数えて書くこと。**
以下は方向の素案。**数値は数えてから入れる。**

1. **`Toll` の代金は決着の速さで符号が割れる。** 速く終わる台では取り立てが来る前に勝つので
   `yP` との差が小さく、長引く台では大きい。**これがこの期の本丸**
2. **第三波（渇き）ではアガが無害化される**（プラスもマイナスもほぼ 0）
3. **`Single` は第四波（軛・単発上限25）で焼きの大半が切られる。** `All` はその影響が小さい
4. **`All` が3枝で最も強い。** 溜めた量が無駄にならないため
5. **`Contracts = 1` は回復役として弱くなる**（前借りの回数が減る）が、
   **取り立て1回あたりの燃料は大きくなる**
6. アガ非在席の行は ±0.0

## 4. 段取り

### 段0 —— 台の用意（Q0-6）

**この期の問いは「決着の速さで符号が割れるか」なので、台を決着の速さで切る。**

| 台 | 中身 | 見るもの |
|---|---|---|
| 台1 **速い** | 出力役を厚く（決着T が短い） | 取り立てが来る前に勝つ＝代金が小さい |
| 台2 **遅い** | 耐久寄り（決着T が長い） | 取り立てが来る＝代金が大きい |
| 台3 **タンク同席** | ガルド or ゴルム or ササ | 前借りの宛先が固定される |
| 台4 **回復が既にいる** | ノノ or シオ を1枚 | 5枚目として重複しないか |
| 台5 **陰性対照** | アガ非在席 | 回帰 |

**決着Tは台の設計変数なので、段0 で素体版の決着T を必ず出して記録すること。**
台1 と台2 の決着T が十分に離れていなければ、この期の本丸は測れない。

`Pierce` だけが例外で、要るなら落とす）。

### 段B —— 版の比較

同じ台・同じ seed（0..199）・第2〜5波。

| 版 | 内容 |
|---|---|
| V0 | 素体（アガの席を特性なしの同数値の素体に差し替え） |
| Vp | **`Toll` を外した版**（＝前借りが丸儲け・`Brand` も溜まらない）。プラス側の上限 |
| V1 | 全部載せ・`Single` |
| V2 | 全部載せ・`All` |
| （V3） | 全部載せ・`Pierce`（Q0-4 で書けるなら） |

**代金の値段は `Vn − Vp`。**

**帳簿**（1戦あたり）:

- 前借りの回数／実際に増えたHP／負債の総量
- 取り立ての回数／取り立てた量／**HP1 で止まった回数**
- **踏み倒し**（借り手が先に落ちた回数／アガが肩代わりした量）
- 焼きの回数／叩き込んだ総量／**軛で切られた量**／**超過で捨てられた量**（`Single` で敵のHPを超えた分）

> **収支が閉じること**（前借りで増えたHP ＝ 取り立てた量 ＋ 肩代わりした量 ＋ 未回収の残額）を
> 自己検査に入れる。第153・154期はここが1点もずれなかった。同じ水準を要求する。

## 8. 書き方の規約

1. **Δ と取り分（Δ ÷ (100 − V0)）を併記する。** Δ だけの表で判断しない
2. **線に条件を書いたら、その条件で分母が何行に割れるかを先に数える**
3. **数値・速さ・行数は実物を開いて確認する。** 要約や指示書の表から引かない
   ——第154期は指示書の事前の表が6枚中1枚（ヒビ）外れていた
4. **「時間を買ったか」は生の生存Tではなく決着Tで割った比で見る**
5. 予測は実装前に書き切り、外れても消さない
6. 測って採らなかった枝はノブとして残置する
