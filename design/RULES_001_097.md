### R001 — 主表の判定式を `Traits.cs` だけの grep で書くと5件落ちる

**主表の判定式を `Traits.cs` だけの grep で書くと5件落ちる。** 分かちのなまり（弱体の書き）・
引き受けの横取り（弱体の読み）・渡しの転嫁（読み＋書き）・据えの `IdleTurn` の読み・

### R002 — `reseat` の 1位 を採否の根拠にしてはいけない

**`reseat` の 1位 を採否の根拠にしてはいけない**（第45期の実測）。48行の実測で
**1位と最下位の差は中央値 44.4pt** ある一方、**1位と5位の差は 2.15pt**しかなく、
**その1位は別 seed 帯（200..599）では 48行中 28行で入れ替わる**。
席の値段のほとんどは「やってはいけない置き方」の回避で、良い置き方どうしは平坦な面。
**入れ替わるのは角どうしなので「次数」の割り当ては安定している**（追試一致率 98%）
——採否に使うなら1位の配置ではなく**次数**を使う。

### R003 — 新しい隣接機構は最初から2行以上に入れること

**新しい隣接機構は最初から2行以上に入れること。** 第41〜43期のハネ・ウケ・ワタは
**3枚とも compare に1行しか無く**、`reseat` は編成内の席しか振らないので、
**「編成によって席が変わるか」が原理的に観測できなかった**——
3期連続の「配置の判断が生まれない」は、**測っていない量についての読み**だった。

### R004 — 採用した配置で機構の発火回数が 0 になっていないことを毎回確認する

**採用した配置で機構の発火回数が 0 になっていないことを毎回確認する**（第50期から標準の作法）。
`reseat` / `confirm` は勝率を上げる席を探す道具であって、機構を活かす席を探す道具ではない。
第50期の逸らしは全 10 席で 1.56〜4.61 回/戦と 0 の席が1つも無かった（外しも焦点も
隣接・列を条件にしないため）が、第49期の業改は**配置探索が引き取りを 0.00 回/戦にする席を選んだ。**

### R005 — `OnAllyDeath` は召喚枠（`Ephemeral`）の死も通る

**`OnAllyDeath` は召喚枠（`Ephemeral`）の死も通る。** 使うときは除外するかどうかを決めて書くこと。
継ぎ接ぎ（ヴェル）は除外している（一度きりの効果を蘇生が無制限に掛け算するのを止めるため）が、
**鱗は通した**——胞子は胞子を産まないので供給は有限（ムグ1体につき最大3件）で掛け算にならない。
**実測で死軸台の獲得 18.2 のうち 7.4（40.7%）が胞子の死**なので、判断で4割動く量。

### R006 — `reseat` の採否閾値は 5.0pt

**`reseat` の採否閾値は 5.0pt**（第46期に 2.0 → 5.0 へ変更・`confirm` の `Threshold`）。
第45期の `seats2` を全48行で測ると**1位−5位の差は 中央値 2.15pt・Q3 4.65pt**で、
**+2.0pt は 26/48 行で上位帯の内部変動より小さい**（＝ほぼノイズを閾値にしていた）。作法は3段:

> **「配置の判断が生まれたか」を測るなら、席ごとの帰属（現行 − 同じ席の素体）の符号を見る。**
> 実測でこの2つは逆の答えを出す——帯が単峰の行でも、席ごとの帰属は
> **+12.2 / −2.7** や **+8.9 / −9.5** と明確に符号が割れている。
> **帯を出すときは素体の帯を必ず並べること**（第47期「素体を対照に置く」の帯版）。

### R007 — 席ごとの帰属を測るときは、床と同じだけ天井も外すこと

**席ごとの帰属を測るときは、床と同じだけ天井も外すこと**（第63期）。
「配置の判断が生まれたか」の器具は **`帰属(席) = 現行(席) − 同じ席の素体`** で、
**測れる席 = 素体の5波平均が 40% 以上**（床の規則・第61期）。**天井の規則がまだ無い。**
第63期に足した「弱体が厚い行」は素体が **93.0〜100.0%** で、
採用席（100.0%）では帰属も版の差も**定義上 0 にしかならなかった**（第24期）。
**次に器具を使うときは `40% 以上 95% 以下` の両側で切ること。**

### R008 — 素体を引いて機構を測る期では、`reseat` を配置の決定に使わない

**素体を引いて機構を測る期では、`reseat` を配置の決定に使わない**（第64期）。
`reseat` は120通り＝**他の4枚も入れ替える**ので、「同じ4枚・同じ席」を前提にした器具の族が変わる。
実測で、選定規則の族（他の4枚を元のスロットに残す）が素体 54.3〜63.6%（測れる席5）なのに対し、
`reseat` 粗2位の族は**5席とも素体が床**（24.6〜28.8%）だった。
その席の帰属 +41.6pt が測っているのは配置の判断ではなく**台が生き返ったこと**である。
**`reseat` は勝つ配置を探す道具で、素体を引く器具とは目的が逆を向いている**
——第50期「勝つ席を探す道具であって機構を活かす席を探す道具ではない」の逆側。

### R010 — 線を引く条件と、採る条件は同じ集合で書くこと

**線を引く条件と、採る条件は同じ集合で書くこと**（第113期）。第113期の指示書は

### R011 — 「計数が版に依らない」を検算にするときは、その計数の分母がターン数でないかを見ること

**「計数が版に依らない」を検算にするときは、その計数の分母がターン数でないかを見ること**（第113期）。

**灯はトモが生きている限り毎ターン点く**ので、濾しが盤面を動かして決着が伸び縮みすれば回数も動く

「出すときは必ず決着ターン数を併記する」がそのまま効いた例。

### R012 — 盤面ルールの「効いているか」を波の集計で判定してはいけない

**盤面ルールの「効いているか」を波の集計で判定してはいけない**（第110期・Q4）。
粛は**保持者が盤上に生きている間だけ** `CanActOutOfTurn` を閉じるので、伝令を割った後は譲渡が立つ。
**「第二波の譲渡が 0」は原理的に到達不能な線**だった。実証は

**段3 の粛の列が 0 でないのは第二波だけ**（0.14〜2.10・他の4波は全波 0.00）で取る。

### R013 — 判定式が読むセルが情報帯に入るかを、`run` を回す前に数える

**判定式が読む<u>セル</u>が情報帯に入るかを、`run` を回す前に数える**（第118期・**7例目**）。
第118期の Q3 は「第三波（渇き）と第四波（軛）で帰属の符号が逆」だったが、
**第四波のセルは 4 台すべてで床（0.0%）か天井（100.0%）**——現行と素体の少なくとも一方が
情報を持たないので、**符号を比べる相手が最初から存在しない。**
**× の中身は「どの波でも同じ顔だった」ではなく「片方の顔が見えなかった」。**

**台ではなく判定式の側に当てること**——第59・60・61・107・110・117期に続く。

### R014 — 門の定義と紙の定義が、同じ出来事を数えているかを先に見る

**門の定義と紙の定義が、同じ出来事を数えているかを先に見る**（第118期）。
第118期の門2（交差点）は「HP が回復を上回って減り始めた最初のターン」、
紙は「HP ÷（総攻 − 回復）」＝「**尽きるまで**」で、**別の量だった。**
実測は 16 セルすべて 2.0T に張り付き（未交差 0.0%）、**紙の 2.3〜4.2T と並べても何も読めない。**
**揃えるなら生存T のほうだが、そちらも紙と一致しない**——ムドの台では4波とも紙より長く、
カドの台では第3・4波で短い。**紙は台によって下限にも上限にもなる**（敵の標的が分散するかで向きが変わる）。

### R015 — 他の期の数値を判定の線にするときは、その数値がどの対照で出たかを書く

### R016 — 土台の選定規則が、測る対象の入力を 0 にしていないかを Phase 0 で数える

**土台の選定規則が、測る対象の入力を 0 にしていないかを Phase 0 で数える**（第117期・**6例目**）。

ウツは吐き戻しを受けるたびに攻撃力が半減して**符号が負**（−24.6pt）。
**「弱かった」のではなく「測っていない」。**

### R017 — 台を引き継ぐと、台の選定規則も一緒に引き継ぐ

**台を引き継ぐと、台の選定規則も一緒に引き継ぐ**（第126期・**9例目**）。
第126期は第117期の台（前1 死なない / 中央 育つ / 土台3枚）をそのまま使ったので、
**第117期がまさにそれで落ちた穴を、そのまま踏んだ**——埋め草の規則が
「攻撃力を書く駒」と「移動を供給する駒」を除くので、**ウツ（自己強化を1本も持たない）と
ヨミ（移動で育つ）には `AtkBonus` の供給が構造的に 1 点も来ない。**
実測でウツの到達攻は素の攻撃力とぴったり一致（9.0 = 9・閾値超のターン **0.0%**）で、
`AtkBonus` を読む機構の帰属は **16 組中 8 組で厳密に 0.00**
——**その 0.00 は「効かなかった」ではなく「測っていない」**（第61期）。
**台を再利用するときは、台の選定規則を「その機構の入力を供給するか」の側から読み直すこと。**
第59・60・61・107・110・117・118・121期に続く。

### R018 — 採否の条件に割合を使うときは、その割合の分母が版で動かないかを先に見る

**採否の条件に割合を使うときは、その割合の分母が版で動かないかを先に見る**（第126期・規約 (G12) の採否側）。
第126期の条件3「`残存` が上がる」は **× だったが、その × は機構の性質ではなく物差しの性質**である
——`残存` の分母は「勝った試行」で、案A は勝率を **25.9% → 39.3%**（分母 +52%）へ動かすので、
**今まで負けていた難しい戦が分母に入ってくる。**
分母の動かない **`残存度`（第82期・全試行が分母・負けは 0）で見ると符号が反転する**:
**`残存` 2.93 → 2.73（−0.20）／`残存度` 0.76 → 1.07（+41%）。**
**同じ機構・同じ戦で2つの「残存」が逆を向いた。**
**(G12) が判定式そのものに当たった初めての例**で、
**勝率を動かす機構では `残存` を採否の条件に使ってはいけない。**

### R019 — 「殺さない」制約は出口にしか置けない

**「殺さない」制約は出口にしか置けない**（第126期・第25期の軛の再確認）。
致死の一撃を HP1 で止める機構（猶予）を `Trait.ModifyIncomingDamage` に置くと、
**あの窓口は惨禍（+50%）・据え・散開より手前**なので、削った量を後段が押し戻して**死ぬ**。
置けるのは `ApplyDamage` の `target.Hp -= amount` の直前だけで、
**既にそこにある `lethal: false` のクランプと同じ族**である。
**一方で、割合の増減（自分だけに効くもの）は `ModifyIncomingDamage` でよい**
——脆弱（`FrailTrait`）と同じ層で、順序が入れ替わっても「1発が何点になるか」しか動かず
規則そのものは破れない（崖にならない）。**二値の制約と割合の増減で置き場所が違う。**

### R020 — 割合の軽減は、整数の切り捨てと「何発で死ぬか」の粒度に負ける

**割合の軽減は、整数の切り捨てと「何発で死ぬか」の粒度に負ける**（第126期・第96期の耐久側）。
`AtkBonus` を読んで被ダメを減らす機構は、**カドでは閾値超のターンが 47.7% あるのに
帰属が厳密に 0.00** だった——`pct = (AtkBonus − 5) / 2` と `dmg × pct / 100` が
**2重に整数で切り捨てられる**ので、1発あたりの軽減が 0〜1 点にしかならない。
**発火率を上げても、1発あたりの軽減が「何発で死ぬか」を動かさなければ盤面は 1 ビットも動かない。**
（**算術からの推定で、直接は測っていない。**）

### R021 — 判定の線は、計数の名前ではなく実装が数えている出来事に当てる

**判定の線は、計数の<u>名前</u>ではなく実装が数えている出来事に当てる**（第121期・**8例目**）。
第121期の Q2 の線「読まれずに消えた割合が 20pt 以上下がる」は × だったが、
**この計数は実装では「<u>消費されずに</u>残った割合」**で、抉り・なぞりのような**消費しない読み手が読んだ傷もここに落ちる**。
消費経路は 5.3% しか無いので、**供給を 93% 削っても構造的に 3pt しか動かない**（94.7 → 91.7）。
**同じ表の到達率（読まれた ÷ 書かれた）は 11.2% → 87.8% と 76.6pt 動いていた**
——**線が読む量を間違えると、動いている物を「動かない」と記録する。**
第59・60・61・107・110・117・118期は「判定式が読む<u>セル</u>が見えるか」だったが、
**今回は量の定義そのものが名前と食い違っていた。**

### R022 — 実装から引く索引は、引けているのに結ばれないことがある

**実装から引く索引は、引けているのに<u>結ばれない</u>ことがある**（第121期・第117/119期に続く3例目）。
`derive rules` はクラス宣言（`(?:static|sealed) class`）でファイルとモードを結ぶので、
**診断を別ファイルへ切り出して `static partial class` にすると索引から診断名が静かに消える**
——**`docs/rules.md` の `利用者` 列から5本のノブの `wound2` が落ちるだけで、エラーも警告も出ない。**
**表を生成する道具の「結び方」も、実装から引く表の一部である。**

### R023 — 対で採った機構は、片側を外すときにもう片側も再判定する

**対で採った機構は、片側を外すときにもう片側も再判定する**（第122期）。
巻き込み則（供給・第88期）は**縫いの両側読み（ハリ）と対で**採られ、
その後に中継（引き取り・第90期）と2枚目の終端（繕いの傷読み・第92期）が積まれた。
**第108期にハリをロスターから外したとき、この3本は誰にも見直されなかった**
——盤面は 14 期のあいだ、**読み手のいない在庫を毎戦 8.2 個書き続けた。**
**駒を1枚外す作業には、その駒と対で採った規則の一覧を添えること。**
**降ろすときも同じ**——供給だけを止めると、**入力ゼロの読み手が盤面に残って同じ形をもう一度作る。**
実測で **A3（3本とも降ろす）− A1（供給だけ）は 73 行すべて厳密に 0.00pt** で、
これは「2枚を降ろしても何も起きない」の証拠であると同時に
**「供給が止まった時点で2枚は既に死んでいた」の証拠**でもある。

### R024 — 採用を覆すときの「元に戻す」は、その行が採用以来ずっと同じだった場合にしか成り立たない

**採用を覆すときの「元に戻す」は、その行が採用以来ずっと同じだった場合にしか成り立たない**（第122期）。
