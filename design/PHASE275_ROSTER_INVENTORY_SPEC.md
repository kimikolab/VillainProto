# 第275期 指示書 —— 転生段の開始(ロスターの棚卸しと需要対応表)

読み手は Claude Code。レリック段(〜第274期)完了を受け、本線を**ロスターの転生・テコ入れ**に移す。
背景: 作戦マップに入る前に全駒の籍を確定させる(籍が確定しないと立ち絵の制作に回せない)。

この期は**棚卸しと対応表づくり**。転生の実装はしない。新しい戦は走らせてよいが、盤面・駒・規則は1つも変えない(読み取りのみ)。

## 0. この段の方針(記録すること)

- 転生は「✕の駒を救う」ではなく「**確定した穴(需要)に籍だけの駒を転生させて埋める**」——需要駆動
- レリックは転生の代替にしない(継続)。レリックで勝てた事実は転生の判断材料にしない
- 新しい則 **R367**(ポン承認済み): 物差しの引き直しは、理由が結果の向きからではなく定義と設計文書だけで示せる場合に限り可。旧judgmentは残し、新しい seed 帯で測り直す。`RULES_243_.md` と `RULES_INDEX.md` に登録

## 1. Phase 0 —— 評価の鮮度確認

第177期の駒別評価(✕16・△30・○6)を現在のロスターと突き合わせる:

1. 第178期以降に転生・テコ入れ・作り直しを受けた駒を列挙(`PHASE_INDEX.md`・各期報告から。移動軸 222〜232・燃焼 233〜258 ほか)
2. それらを旧評価から除いた「**未着手の✕・△のリスト**」を作る(これが棚卸しの母集団)
3. `roster_audit.md` の現在の内容と食い違いが無いか確認

## 2. 実測 —— 「籍だけ度」を数字にする

母集団の各駒について、既存の測りから読み取れる範囲で(新しい器具は作らない。足りなければ小さな集計スクリプトは可):

| 指標 | 読み取り元 |
|---|---|
| compare 61行への在席数 | 編成表 |
| 在席する行の成績(その駒がいる行の平均勝率・いない場合との比較が既存データで取れるなら) | compare の既存結果 |
| 固有の勝者・チェック波・ボスの記録への登場 | 各期の報告(grep) |
| レリックとの相互作用の記録(読み手・持ち主として) | RELIC_SUMMARY ほか |

出力: 駒ごとに1行の表(名前・旧評価・在席数・最後に触れた期・一言)。**在席 0 行の駒が最優先の棚卸し対象**。

## 3. 需要側のリスト —— 穴の確定

転生先の候補となる「確定した穴」を1つの表に(出所つき):

| 穴 | 出所 | 補足 |
|---|---|---|
| 感電の供給(カタの相方・compare に感電の行を立てる) | 帯電の足の供給待ち(第274期) | 解けると札1枚の再測もできる |
| 毒軸の強化 | 第269期からの継続 | 蝕みの読み手でもある |
| 手数特化(豆鉄砲型・攻撃力を連撃回数に変える) | RELIC_PLAN 4.6 | 被弾の燃焼・状態の弾と組む |
| `Armor` の読み手 | TURN_SLOT_PLAN(読み手 0) | 回復不能下でも届く資源 |
| `IdleTurn` の変質読み手 | TURN_SLOT_PLAN(読み手 0) | 号令の裏 |

このほか、各期の報告・引き継ぎに「読み手がいない」「供給がない」と記録された穴があれば追加する(grep)。
各穴に「埋めると何が動くか」(再測できる札・立つ行・解ける残件)を1行ずつ。

## 4. 出口 —— 対応表(ポンが選ぶための材料)

- **候補×需要の対応表**: 未着手の✕・△の駒それぞれに、向きそうな穴を0〜2個当てる(フレーバー・元の特性との接続を一言で。無理に全駒へ当てない——どの穴にも向かない駒は「向き先なし」と正直に書く)
- 対応はあくまで叩き台。決めるのはポン(この期では転生の中身を設計しない)
- 報告 `design/PHASE275_ROSTER_INVENTORY.md` に、母集団の表・需要の表・対応表の3つを載せる

## 5. 作法

- 盤面・駒・規則・札は1つも変えない。回帰は `audit` のみ
- CLAUDE.md は本線の切り替え(転生段・開始)の1行と R367 の登録のみ
- 対応表の駒名・穴は、次の期からの転生指示書で1駒(または1穴)ずつ扱う——**一度に複数駒を転生させない**(変数を1つずつ)
