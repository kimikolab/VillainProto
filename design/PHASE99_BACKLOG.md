## 0. 表示の直し（W1・W2）

### W1. レーンを行として積んだ

`Side()` の入れ子が逆で、**`EnemyLaneOrder[0] = {3,8,4}` が縦一列**になっていた
（`HBoxContainer` の中に `VBoxContainer`）。結果、

    直す前   敵の列（左→右）  後 / 中 / 前     ← 前列が右端
             味方の列（左→右） 前 / 中 / 後     ← 前列が左端
             ⇒ 前列どうしが対角に離れる。奥行きが横に転置していた

    直した後 敵（上から）   後列 / 中列 / 前列
             〔接敵面〕
             味方（上から） 前列 / 中列 / 後列
             ⇒ 接敵面をはさんで前列が隣り合い、**貫きの経路（前→中→後）が縦に走る**

**`EnemyLaneOrder` / `PlayerLaneOrder` の中身は1つも変えていない。積み方だけ。**
あわせて**各行の左に行の名前**（前列／中列／後列。`FormationRules.RowOf` から引く）を出したので、
**第98期に足した席名（カードの右上）と突き合わせて確認できる。**

### W2. 型を面で示すようにした

線の形で型を表現するのをやめた。読めなかった理由は3つとも構造的:

- 巻き込みが2体だと「扇」が2本にしかならず、単体2回と区別が付かない
- 細1本／中太／極太の差が、この密度では判別できない
- **線が駒の脇を通ると、当たっていない駒に当たったように見える**

| 出すもの | 内容 |
|---|---|
| **型名** | 攻撃した瞬間、**攻撃側のカードに枠付きの名前**（単体／薙ぎ／貫き／全体） |
| **当たった駒** | **カードの枠が光る。主目標は濃く二重、巻き込み・貫きの後続は薄く1本** |
| **線** | **主目標への1本だけ。**扇・数珠つなぎは廃止 |

巻き込み（紫）・反撃（橙・逆向き）・中継（破線）は色と形で残した。凡例も書き直した。

**あわせて「手送りのあいだは薄れさせない」ようにした。**
組（＝1回の攻撃）が変わったときに `PushShot` が丸ごと消すので溜まらない
——**1回止めれば、画面に出ているものが「その一振りだけ」になる。**

## 3. 優先順位

### 3-1. 規約 —— 会戦 0/73 は「例外」に当たるか

`CLAUDE.md` の優先順位は
**面白さの探索 ＞ 新しいシナジー ＞ キャラの個性 ＞ 実装のシンプルさ ＞ 大まかなバランス ＞ 細かな数値バランス**。
**ただし「明らかにゲームが成立しなくなるレベルの壊れ方」は例外。**

> **Claude Code の判断: 当たらない。ただし「A を測る道具が無いこと」のほうは例外に当たる。**
>
> **当たらない理由**——`compare` の 61 行はどれも壊れていない。
> 5波の平均は 100 / 69.9 / 74.8 / 61.9 / 39.5 で、**単発の物差しの上ではゲームは成立している。**
> 会戦 0/73 は**その物差しの外にある別の台の値**であって、駒や機構が壊れた結果ではない
> ——**73行すべてが第一波を抜け、42行が「落ちた波に単発では勝てる」**。
> 「勝てない」のではなく「**連戦の代金を払う設計が入っていない**」。
>
> **当たる理由**——**会戦は96期のあいだ1度も指標を持っていない。**
> 「明らかに壊れている」を検出できないのは、壊れていることと同じくらい悪い。
> 第55期に `audit` を入れたのと同じ形で、**まず数える道具が要る。**

**なので A は最優先だが、直すのではなく「測れるようにする」ところまで。**
