## 5. 後半 —— `watch` モード（地図を出す）

新しい診断モードを1本足す。**戦闘は回すが盤面は動かさない**（`verbose: true` で `compare` と同じ呼び出しをするだけ）。

    dotnet run --project BattleSim -c Release 0 watch phase0    # 盲点表（戦闘0回）
    dotnet run --project BattleSim -c Release 0 watch           # 主表（候補行 × 波 × 代表 seed）
    dotnet run --project BattleSim -c Release 0 watch cast [行名の部分一致]   # 台本の出演内訳

**出力先**: 主表と盲点表は `docs/watch.md`（規約: 手書きは `design/`、生成物は `docs/`）。
`cast` は標準出力で読むだけ。**`watch.md` を足して `audit` が落ちないかを確認**し、落ちるなら `docs/` に置かず標準出力にする。

### 5-1. 候補行

**手で並べない。** 次の和集合を実装から作る:

- `Baseline.PrimaryRows`（19行）
- Q0-9 で抜いた「第110〜122期に動いた行」

照合は**行名の完全一致**。`Presets` に存在しない名前があれば**件数つきでエラーとして出す**（0件を期待）。
主表の冒頭に**候補行数の内訳**（主判定 19 ＋ 追加 n ＝ 合計 m）を必ず出す。

### 5-2. 主表の列

行 × 波（第1〜5波。**第1波も出すが「教習」と印を付ける**）:

| 列 | 内容 |
|---|---|
| 行名 / 駒5枚 / 席 | `Presets` から。**デモのプリセット選択と同じ名前**であること |
| 波 | 1〜5 |
| 勝率 | seed 0..199。**`docs/balance.md` と一致すること** |
| 決着T | 中央値 |
| 残存 | 勝った試行の平均生存数 |
| **代表 seed（勝）** | 勝った試行のうち**決着Tが中央値に最も近い seed**。同値は seed 昇順の最小 |
| **代表 seed（負）** | 負けた試行のうち同じ規則で1本 |
| 情報帯 | 勝率が 0.0% でも 100.0% でもない波に ○ |

- 片側が存在しない波は **`—`** と書く。空欄にしない。
- 代表 seed の選び方は**決定的**であること（同じ HEAD で何度回しても同じ seed）。

  「`docs/chain.md` を横に置いて読むこと」と主表の頭に書く。**`chain.md` を文字列として解析して転記しない。**

### 5-3. 盲点表（`watch phase0`。戦闘0回）

### 5-4. 推奨の見る順（主表の末尾）

**線**: 候補行のうち、**第2〜5波のいずれかで勝率が 25.0%〜75.0% にある行**。
その行の中で **50% に最も近い波**を1つ選ぶ（同距離なら波番号の小さい方）。

**採る条件**: 線を満たした行を、`Baseline.PrimaryRows` の軸コメント（移動・燃焼・縛め・標・傷・耐久 …）で
**1軸につき1行**に絞り、50% に近い順に**上位6行**。軸コメントの無い追加行は「追加」という1つの軸として扱う。

**線と採る条件は同じ集合で書く**（(G16)）。**線は満たしたが軸の重複で落ちた行の数を必ず出力する**
（第114期の作法: 掛かっているが効かなかったことも記録する）。

出力は「行名 / 波 / 勝率 / 代表 seed（勝）/ 代表 seed（負）」の **12戦ぶん**（6行 × 勝敗2本）。
