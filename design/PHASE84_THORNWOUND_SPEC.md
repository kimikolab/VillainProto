## 0. 主題

### 0-1. 何を変えるか

**棘鎧のカドの反撃（`ThornsTrait.OnDamaged`）が、刺し返した相手に傷（`StatusKeys.Wound`）を1つ残す。**

新しい `TraitId` は足さない。**カドは既に特性4つでロスター唯一の最多**なので、5本目を足すと
第76期・第78期の「特性の総数」の外れ値がさらに外れる。**反撃の1文の中に入れる。**

### 0-2. なぜ今それが候補か（**すべてリポジトリで確認できる事実**）

1. **傷を書く経路が「手番」にしか無い。** 書き手は裂き（キリ）と刻み（ノミ）の2枚で、
   どちらも `OnAfterAttack` ＝ 自分の手番の主目標にしか刻まない。
   カドの反撃は**敵の手番に走る**（さらに棘守りで隣の味方が殴られたときにも走る）ので、
   傷の供給が初めて被弾のクロックに乗る。**カドは不動で自分からは決して攻撃しないので、
   これはロスターで唯一「手番を1つも使わない傷の供給」になる。**

2. **量に依存しない供給なので、軛（第四波・単発上限）の下でも落ちない。**
   裂きの作法どおり「1回1つ」の定数（`RendTrait.Wounds = 1`）にすれば、
   カドの反撃打点が上限で切られても供給は 1 のまま。**代金だけが切られて供給は残る。**

3. **既に噛んでいる。** 第81期の 2×2 で **カド × キリ +24.93**（共有無しの組・上位9位）。
   第80期の組の表では **カド × キリ +13.9 / +13.8**、**カド × ハリ +8.0 / +7.8**。

4. **カドは正の相乗を持つ相手が 24 体でロスター最多**（第80期）。噛む先を1本増やす価値が高い駒。

### 0-3. **この期では決めない（ポンの判断待ち）**

**味方側に傷を載せるか。** カドの反撃は隣の味方も巻き込む（`FriendlySplashPercent = 50`）ので、
そこに傷を書けば**傷が味方側に載る唯一の経路**になる。ただし §1 の Phase 0 で確定させるとおり、
**味方の傷を読む窓口はロスターに1本も無い**。読み手のいない汚れは汚れではないので、
**この期は V2 として測るだけで採用しない**（§2-1・§6）。誰に読ませるかは第85期の入口（§8）。

## 2. 変更の定義（**測る前に固定。数字を見てから動かさない**）

### 2-1. 3版

ノブは既存の作法（`ThinBladeRule` / `SeverRule` / `ScaleRule`）と同じ形で置く。
**`BattleContext` / `BattleEngine.Run` に省略可能引数として通し、既定は現行**（＝ V0）。

```csharp
public enum ThornWound { None, Foe, Both }
public readonly record struct ThornRule(ThornWound Wound)
{
    public static ThornRule Default => new(ThornWound.None);   // 第84期の測定中はここ
}
```

| 版 | 内容 |
|---|---|
| **V0（対照）** | 現行。`ThornWound.None` |
| **V1（本命）** | 刺し返した相手（`source`）に傷 1。**薙ぎで巻き込んだ隣の敵には書かない** |
| **V2（自己検査）** | V1 ＋ **巻き込んだ味方**にも傷 1 |

### 2-2. 書き方（**裂きの作法をそのまま踏む**）

`ThornsTrait.OnDamaged` の `ctx.Reaction(...)` の中、**`ctx.ApplyDamage(source, back, self)` の直後**に置く。

- **数は定数 1。** ダメージ量に比例させない（増幅は必ず加算にする）。
- **主目標のみ。** 薙ぎの巻き込み（`SplashPercent`）には書かない。
  **範囲持ちが供給を独占して非線形に伸びるのを構造的に避ける**（裂きが `OnAfterAttack` の
  主目標1回に閉じているのと同じ理由）。
- **死体には書かない。** `ApplyDamage` の後に `source.IsAlive` を取り直す（書き手側の作法）。
- **自己給餌は起きない。** カドは傷を1つも読まない。**この期でもカドに読み手を足さない。**
- ログは `LogKind.Status` で `棘が {name} に残る（傷 N）`。

V2 の味方側は、既存の巻き込みループの `ctx.ApplyDamage(ally, spill, self, isFriendlyFire: true)` の直後に、
同じ作法（生存確認 → 1つ書く）で置く。**`gained` の計算には一切触らない。**

### 2-3. 表の更新（**採用したときだけ。測定中は触らない**）

V1 を採ると `Thorns` が傷の供給者になるので、`BattleSim/Program.cs` 末尾の2つの表を直す。

- `TraitKeyMap.TraitKeys[TraitId.Thorns]` に `UnitTally.CarryWound` を足す
  → **カドのキーが `{Move, Hit}` から `{Move, Hit, Wound}` になる**
- `TraitEntryMap.Supplies[TraitId.Thorns]` に `(UnitTally.CarryWound, Where.Foe)` を足す
  → **カド × キリ の組の分類が `共有無し` から `供給→供給` へ、
  カド × エグ／ナタ／ハリ が `供給→読み` へ移る**

**これは第80〜83期の派生値（広さ・独立の広さ・組の分類）が動くということ**なので、
**報告書に「動いた」と明記する。** 数え直しはしない（この期の主判定は個数ではない）。

## 3. 判定基準（**測る前に報告書へ書く**）

### 3-1. 主判定 —— 相乗の増分（**連続量。個数を主判定にしない**）

器具は第81期・第83期の 2×2 の写しで**1文字も変えない**。

```
y11 = 両方が本物 / y01 = カド素体・B 本物 / y10 = カド本物・B 素体 / y00 = 両方が素体
相乗(カド,B) = y11 − y10 − y01 + y00
Δ相乗(B)     = 相乗_V1(カド,B) − 相乗_V0(カド,B)
```

台・席・戦闘 seed・台の抽選はすべて V0 と V1 で同一。系列は 2 本（自己検査 (g)）。

> **主判定 Q1: 傷の5枚（キリ・ノミ・エグ・ナタ・ハリ）の Δ相乗 の平均が ≥ +3.0pt。**

**線の根拠（測る前に固定）**: 第80期 表D の組の平均相乗は 供給→読み **+3.36** / 読み→読み **−1.11**。
第83期では 同キーの組 **+2.10** / 共有無し **+0.24**。
「カドが傷の供給者になった」と言えるには、増分が**供給→読みの組の平均並み**に届く必要がある。
丸めて **+3.0**。

### 3-2. 副判定（**すべて連続量**）

> **Q2: 供給量。** カドの反撃が傷を書いた回数／戦（波別）。
> **第四波が第二波より高いこと**（軛は切らない・粛は止める、という §1 の予測の検証）。
>
> **Q3: 在庫。** 敵側の傷の平均在庫（ターンあたり・波別）の V1 − V0。
> **ハリ同席時に在庫が 1 を超えるか**を明示する（第39期の「天井 1」が崩れるか）。
>
> **Q4: 読み手の出力。** 抉り・断ち・縫いの発火回数と、与ダメージ／回復量の V1 − V0。
> **断ちの `Threshold = 2` に届いた回数**を単独で出す。

### 3-3. 拒否権

1. **主判定19行（`Baseline.PrimaryRows`）の第五波平均が `Baseline.PrimaryFifthFloor` = 33.2% を下回る**
2. **カドを含む8行のうち、第五波が 95% を超える行が新たに2行以上生まれる**（情報セルが潰れる）

**Phase 0-5 が 0 行なら、V1 では拒否権1・2はどちらも原理的に立たない。**
**立たないこと自体を自己検査として報告する**——立ったら実装が「傷を書くだけ」になっていない証拠になる。

### 3-4. 自己検査（**各判定に1行ずつ**）

- **(a)** `y01` / `y00`（カド素体）のセルが V0・V1・V2 で **完全一致**すること。
  一致しないならノブが素体側に漏れている。
- **(b)** `compare` 61行が V0 と V1 で **全セル ±0.0**（Phase 0-5 の帰結）。
- **(c)** **V2 は V1 と全セル ±0.0**。味方に傷が載っても読み手が 0 なので盤面は動かないはず。
  **同時に、V2 で味方側に傷が載った回数 > 0 を計数で示す**——両方揃って初めて
  「載ったが誰も読まなかった」が言える。片方だけなら実装ミス。
- **(d)** 傷を含む5行が V1 で ±0.0（カドが1体もいないので当然。回帰確認）。
- **(e)** Q2 の第二波の供給が 0 に近いこと（粛）。0 でないなら `CanActOutOfTurn` を通っていない。
- **(f)** 傷の数が打点に比例していないこと（1反撃 = 1傷）。反撃回数と傷の書き込み回数の比が 1.00。
- **(g)** 主判定 Q1 が2系列で同符号であること。
- **(h)** Δ相乗 の分母は5枚固定。**「有意な相手が何枚あるか」を主判定に混ぜない**

## 7. 実装の注意

- **`ThornGuardTrait` の入れ替えより後に走ること。** カドの `Traits` は
  `{ ThornGuard, Thorns, Immobile, Havoc }` の順で、この順序が「入れ替え → 反撃」の実行順を作っている。

- **`ctx.InReaction` の門と `ctx.CanActOutOfTurn` の門は現行のまま。** 傷の書き込みも同じ門の内側に置く
- **`UnitState.SetCounter` が `NoteStatusGain` を呼ぶ**ので、傷の計数（`UnitTally.CarryWound`）は自動で乗る。
  **別の計数を新設しない**
- **蘇生と会戦の境界**: 傷は `SetCounter` で持つだけなので既存の扱いに従う。**新しい持ち越し規則を作らない**
- **敵側にカドはいない**（棘はプレイヤー専用）。敵の傷が味方に返る経路は生えない
- **殉教者（第五波）の介入は `source` を変えない**ので、傷は実際に殴ってきた敵に載る。**これは仕様**

## 8. 申し送り（**第85期の入口。ここで結論を出さない**）

**味方の傷を誰に読ませるか。** V2 が (c) のとおり無反応で終わったなら、次の問いはこれ1つになる。
現時点で見えている候補と、それぞれの難点を**判断せずに**記す。

1. **縫いのハリに味方の傷も読ませる。** 第83期で**唯一「切れる」判定が出た駒**（拒否権を通過した
   差し替え候補14体のうち1体）。切る代わりに繋ぐ形になる。
   **難点**: 敵の傷も味方の傷も読むと1体2文になる。味方専用にすると供給がカド1枚に絞られ、
   **書き手1・読み手1の AND ゲート**（第57期の燃焼で踏んだ形）になる
2. **カド自身に読ませる。** 自己完結するので却下の見込みが高いが、Phase 0 として測る価値はある
3. **読み手を新設して最後の1枠を使う。** 既存駒の改善を先に尽くす方針と衝突する

**あわせて第85期に残るもの**: 3分の器具の再設計／ササを広さの側で評価／最後の1枠／
ムドの呪い／台の判断（理想 vs ドラフト）／`AcceptsSupport` の統一（5経路で3通りに割れている）／
情報セルと測れる席の帯の不整合。
