## 0. 主題

### 0-1. まず名前を1つ空ける（**盤面は動かさない**）

第95期が採用した機構の実体は **「汚れているとなまりが深く入る」** で、
第90期の滲み則（傷があると毒が深く入る）と**同じ形**である。
にもかかわらず `CurseRule` という名前を取っているため、
**この期で作る呪いと名前が衝突する。**

> **(R1) `CurseRule` を `SoakRule` に畳む。**
> `SoakRule(bool Poison, bool Burn)` → `SoakRule(bool Poison, bool Burn, int DullPerKind)`。
> 既定は `(Poison: true, Burn: false, DullPerKind: 1)`——**第95期の採用状態をそのまま再現する。**
>
> **これは改名であって機構の変更ではない。`compare` 305 セルと交差帯12行が
> 全セル ±0.0 であることを示してから次に進むこと。**

滲み則は**3つの通貨に同じ形で乗る**ことになる。説明が1行で済む——
**「汚れている相手には、状態異常が深く入る」**（毒は層、なまりは種類、燃焼は**乗らない**＝第91期に不採用）。

### 0-2. 何を作るか

**呪い。単体攻撃のダメージを、呪われた駒どうしで分け合う。**

| | 規則 |
|---|---|
| **付与** | **泥人形ムドにダメージを与えた駒に、呪いが1つ付く。敵味方を問わない** |
| **呪い単体** | **何も起こさない。** ダメージもデバフも無い。純粋な盤面の記録（傷と同じ） |
| **共有** | **単体攻撃**（`AttackPattern.Single`）のダメージが呪い持ちに入ったとき、**同じ陣営の他の呪い持ち全員**に **50%** が届く |
| **範囲攻撃** | **共有しない。** 薙ぎ・貫き・全体は反応しない |
| **1ホップ** | **共有で入ったダメージは、さらに共有を起こさない** |
| **寿命** | **剥がれない**（この期では） |

**両陣営に等しくかかる。** ムドは殴られないと働かない駒なので、
**呪いの供給は敵の手番に握られている。** そして味方の刃（ボルグの余波・カドの棘・
ゴルムの吸い・ナラの置き去り・リィカの生贄・ゾトの破裂）が**ムドを叩けば味方が呪われる**。
**マイナスを別に足さない。**

### 0-3. なぜこの形か（**すべて既存の記録に紐づく**）

1. **単体攻撃43体問題に直接効く。** 味方46体の常時の攻撃型は **単体43／薙ぎ3／貫き0／全体0**。
   「殴る回数が多い」のではなく「**同じ絵が46回流れている**」のが問題の実体だった。
   **呪いは単体攻撃を条件付きの範囲攻撃に変える。駒を1体も足さずに43体の役割が変わる。**

2. **単体高火力の受け皿が既にいる。** ドルガ（攻38・「強い。ただ遅い。それだけの理由で外された」）／
   止めのトメ（標的を倍で殴る）／断ちのナタ（傷2つで大火力）。
   **1体を過剰に殺す分が無駄になる**という弱点が、共有で解ける。

3. **供給の周期が新しい。** 開戦時1回（呪詛・萎縮・生贄）／毎ターン（瘴気・吸い・縛め）／
   攻撃ごと（裂き・刻み・余波）はあるが、**「殴られるごとに相手側へ書く」を持つ駒がいない。**
   **ムドの「殴られないと働かない」という捨てられた理由が、そのまま供給のクロックになる。**

4. **ムド自身は呪いを読まない。** 得をするのは単体攻撃を振る駒全員であって、ムドではない。
   **自己完結しない**（第84期以降の原則）。

5. **増幅が線形。** 共有は**元の一撃を割合で分ける**ので、呪い3体でも総量は 2.0 倍。
   **状態異常の共有（複製）は二次になるので、この期では作らない**（§7）。

### 0-4. 設計上の判断（**すべて測る前に固定。振らない**）

1. **共有は同じ陣営に限る。** 陣営をまたぐと、ムドが敵を呪う目的（殲滅）と
   味方が呪われる副作用が**同じ経路で混ざって切り分けられなくなる**。
   マイナス側は「呪われた味方が2枚いると、敵の単体攻撃が2枚に配られる」で既に立つ。
2. **範囲攻撃は共有しない。** 薙ぎ・貫き・全体まで共有すると**範囲が二乗で伸びる**。
   ここを切るのは調整ではなく構造。**「点で刺すと呪いが繋がる」**という絵としても一貫する。
3. **1ホップ。** 共有ダメージが共有を起こすと往復する。`ThornsTrait` の `InReaction` と同じ形のガードを置く。
4. **剥がれない。** 解除を同じ期に足すと変数が2つになる。
   **ただし呪いは「呪い持ちが何体いるか」で意味が変わるので、効果は固定されない**
   ——第93期の深手（一度なると効果が固定＝ただの減点）とはここが違う。
5. **ネルは触らない。** 呪詛の味方漏れ（攻撃力 −5）は**共有軸の入力そのものを削る**
   （元の一撃が小さければ共有分も小さい）。**この自己課税を §3 の予測に書いて実測する。**

## 1. Phase 0

### 1-1. 門 —— 鎖が繋がっているか（**大きさではない**。規約 (G7)）

**呪いを付けない版（W0）で、版に依らない計数を足して数える。**

> 1. **ムドがダメージを受けた回数/戦**（＝呪いを配れる機会。敵側・味方側の内訳つき・波別）
> 2. **呪い持ちが同じ陣営に2体以上いるターンが存在する回数**
>    ——**共有は2体以上でなければ1回も起きない。ここがこの機構の急所。**
> 3. **単体攻撃が呪い持ちに入る回数/戦**
>
> **3つとも 0 より大きいことを確認してから実装する。**
> **どれかが 0 なら、そこが切れている場所を書いて閉じる。**

**2 が特に危ない。** ムドを殴る敵は前列の1〜2体に偏るはずで、**同じ陣営に2体呪われるまで時間がかかる**。
**何ターン目に2体目が立つか**を波別に出すこと。

### 1-2. 紙のスループット（**門ではなく出力**。規約 (G7)）

    共有由来の出力/戦 = 単体攻撃が呪い持ちに入った回数 × 元の打点 × 0.5 × (同陣営の他の呪い持ちの数)

**分子について3つを先に書く**（規約 (G7)）:

- **線形か二次か** —— **線形**（元の一撃を割合で分けるので、呪い体数に比例して打ち止め）
- **門ではなく出力** —— §1-1 が門
- **分母を削るか** —— **削らない**（共有は元の一撃を減らさない）。
  **第93期の「分母を削る機構では紙は上限になる」には当たらない ＝ 紙は下限のはず。**
  **外したら報告書に書く。**

## 2. 変更の定義（**測る前に固定**）

### 2-1. ノブ

```csharp
public readonly record struct CurseRule(bool Enabled, int SharePercent)
{
    public static CurseRule Default => new(false, 50);      // 測定中はここ
}
```

**`SharePercent = 50` は振らない。** 掃引はこの期に無い。

### 2-2. 付与 —— ムドに2つ目の特性を足す

**`TraitId.Rage` の中に入れない。** ムドの1文は「受けたダメージに応じて攻撃力が上がる」で、
呪いは別の話。**新しい `TraitId`（祟り）を足す。ムドは特性2つになる**（カドは4つ、ロスター唯一の最多）。

```
OnDamaged(ctx, self, dmg, source):
    if (!ctx.Curse.Enabled || source is null || source == self) return;
    if (!source.IsAlive) return;
    source.SetCounter(StatusKeys.Curse, 1);        // 二値。重ねない
    ログ（LogKind.Trigger）
```

- **二値。** 呪いは 0 か 1。**重ねる意味が無い**（共有は体数で決まる）。
- **敵味方を問わない。** 味方の刃がムドを叩けば味方が呪われる。**これがマイナス。**
- **`source == self` を除く**（自傷では呪われない）。
- **`Rage` の育ちに1文字も触らない。**

### 2-3. 共有 —— engine の規則

`ApplyDamage` の中、**HP を引いた後・死亡判定の後**に置く。

```
if (!ctx.Curse.Enabled) return;
if (!単体攻撃由来) return;                    // 薙ぎ・貫き・全体は反応しない
if (共有由来のダメージ) return;                // 1ホップ
if (target.Counter(StatusKeys.Curse) <= 0) return;

share = amount * SharePercent / 100
foreach (other in ctx.LivingMembers(target.TeamId))      // **同じ陣営だけ**
{
    if (other == target) continue;
    if (other.Counter(StatusKeys.Curse) <= 0) continue;
    ApplyDamage(other, share, source, 共有由来の印, spillWound: false);
}
```

- **`share` は元の `amount` から計算する**（共有先の HP や防御で再計算しない）。
- **`spillWound: false`。** 巻き込み則（第85期・既定 on）が呪いの共有で傷を書くと、
  **共有 → 傷 → 滲み → …** の経路が増える。**この期では切る。**
- **`lethal` は既定のまま。** 共有で倒れることは許す（死軸に繋がる）。
- **`ctx.PickOne` を使わない**（第89期 (h)。候補2個以上で `Roll` を消費する）。

### 2-4. 表の更新（**採用したときだけ**）

- `StatusKeys` に `Curse` を足し、`UnitTally` に `CarryCurse` を足して `NoteStatusGain` に加える。
- **`TickStatuses` に何も足さない**（時間で進行しない。傷と同じ）。
- `TraitKeyMap` / `TraitEntryMap` は **`derive scan` の観測に従って直す**（第94期の器具）。
  **手で書かない。**

## 7. 申し送り（**第97期の入口**）

### 状態異常の共有（**ダメージ共有が通ってから**）

**遡及コピーは作らない。**「毒10層の呪い持ちがいる状態で呪いを付与 → 新たな呪い持ちにも毒10」は、
**配る頻度 × その時点の在庫**が複製量になる。**溜めてから解き放つ**プレイになり、
Charge をクロックで棄却して event ベースに統一した判断と逆行する。

飼いならすなら **事象のみ・1つだけ・遡及なし**:

> **呪われた駒に汚れが書かれたら、同じ陣営の他の呪い持ち1体にも同じ汚れが1つ書かれる。**
> **量を写さない**（10層書かれても飛ぶのは1層）／**1体だけ**／**1ホップ**／**既にある在庫は飛ばない**

### ネルの扱い

**ネルは呪い軸の駒ではない可能性がある。** 実装は `Dull` を書く駒で、
**漏れの通貨（攻撃力）が共有軸の入力と同じ**。Q5 が予測どおりなら、
**呪いの2枚目は最後の1枠で作る**か、**ネルを触らずに置く**かの判断になる。
