## 0. 主題

### 0-1. 持ち越しがちょうど半分にしている

**会戦の第2波クリア率 33.8% に対して、単発（フルHP）は 66.7%。**
落ちた試行の **66.2% が第2波**で、**第1波で落ちる行は 0**。

境界には**回復が1点も無い**（第99期。`Engagement.cs` に `Heal` も `Hp +=` も0箇所）。
**HP・Slot・`HasFallenBack` はそのまま持ち越し、状態異常9本と `AtkBonus` は全消し、死者は戻らない。**

> **損害は持ち越し、積み上げはクリア。**

### 0-2. 会戦は3波で測れる

**5波の列と3波の列で、73行すべての突破波数が厳密に一致した**（r = +1.000）。
seed が列の長さを見ず、地点が順路の先頭3波と参照同一だから。

> **以後、会戦は地点（3波）で回す。5波を回す理由が無い。**

### 0-3. この期でやること

**境界に回復のノブを置いて掃引し、「測れる帯」に持っていく設定を探す。**
**採否はポンが決める。** この期は**測って並べるところまで。**

## 1. 規約（**測定より先にコミットする**）

> **(G10) 会戦・単発とも、判定に使う分母は第2〜5波（地点なら第2〜3波）とする。第一波を分母に入れない。**
>
> **理由**: 第一波は全行が単発で 100% 勝つ教習波で、圧勝率も 96.4%。
> 分母に入れると常に希釈される（第100期の予測2は、第一波を含めた5波通算で ×、
> 第2〜5波では 17.8% で予測どおりだった）。
> **第100期は事後に分母を変えなかったのが正しい。だからこそ、次からは事前に固定する。**
>
> **勝率・残存・圧勝率・全滅勝ちのすべてに適用する。**
> **第一波の値は「参考」として併記してよいが、判定には使わない。**

**コミットの順序で示すこと**（第88期 (g)・第92期 (d)・第100期と同じ作法）。

## 2. 変更の定義（**測る前に固定**）

### 2-1. ノブ

```csharp
public readonly record struct RecoverRule(int HpPercent, bool ReviveDead)
{
    public static RecoverRule Default => new(0, false);      // 現行。測定中はここ
}
```

**`EngagementEngine.CarryOver` の中、状態異常と `AtkBonus` を消した後**に置く。

- **`HpPercent`**: 生存している味方の HP を **`MaxHp` の割合ぶん回復**する（上限は `MaxHp`）。
  **`ctx.Heal` は通さない**——境界は戦闘の外で、渇き（第三波の波ルール）の対象ではない。
  **`Hp` を直接足す**。**理由をコードのコメントに書くこと。**
- **`ReviveDead`**: 真なら**倒れた味方も `MaxHp` で復帰**する（スロットは元のまま）。
- **敵側には一切適用しない。** 敵は波ごとに新しい部隊なので元から全快である。**確認して書くこと。**

### 2-2. 掃引

**全境界に一律で当てる。** どの境界に当てるかは振らない（§5）。

| 版 | `HpPercent` | `ReviveDead` | 意味 |
|---|--:|:-:|---|
| **R0** | 0 | × | 現行 |
| **R25** | 25 | × | |
| **R50** | 50 | × | |
| **R100** | 100 | × | **代金を HP から駒へ移す**（HP は戻るが死者は戻らない） |
| **RFull** | 100 | ○ | **対照。** 各波が単発と同じ条件になる |

**`RFull` は対照であって候補ではない。**
**この版の突破率が、単発の連勝率（各行の第1〜3波の勝率の積）と一致するはず**——
**一致しなければノブか器具のどちらかが間違っている**（§4 の自己検査）。

## 3. 測るもの

**73行**（`Presets.Compare` 61 ＋ `Presets.Cross` 12）× **seed 0..199** × **地点（3波）** × **5版**。
**約 22 万戦。数分で終わる。**

**すべて第100期の `run` の定義をそのまま使う**（新しい定義を作らない）。

| | 内容 |
|---|---|
| **突破率** | 地点を最後まで抜けた seed の割合 |
| **落ちた波の分布** | 第2波 / 第3波 |
| **入場戦力** | 各波の開始時点の生存数と HP 合計の割合 |
| **残存** | 抜けた試行の平均生存数 |
| **圧勝率** | 生存4体以上で抜けた割合 |
| **全滅勝ち** | 生存1体で抜けた割合 |

### 3-1. 判定（**測る前に固定**）

> **Q1（帯）: 73行の突破率の中央値が 5〜50% に入り、かつ突破率 0% の行が 37 行を下回ること。**
> **測れる帯**＝行のあいだに差が出る帯。**第100期は 72/73 が 0% で、順位が付かなかった。**
>
> **Q2（泥仕合）: 圧勝率が R0 より下がらないこと。**
> **回復は「削られても立て直せる」なので、消耗戦を長引かせる方向にも働きうる。**
> **突破率が上がっても圧勝率が下がるなら、方向が違う。**
>
> **Q3（独自性）: 行の順位が単発の連勝率と一致しないこと。**
> 一致したら**会戦が単発と同じものを測っていることになり、別の物差しである意味が消える。**
> **順位相関（スピアマン）を出し、`RFull` との差を見る。**

**Q1〜Q3 を同時に満たす版を「推奨」として報告する。** **無ければ「無い」と書く。**

### 3-2. あわせて見るもの（**判定ではない**）

- **R100（代金を駒へ移す）で、突破率が「勝率」と「残存」のどちらと強く相関するか。**
  **代金が駒になっているなら、残存との相関が強く出るはず。**
- **第2波クリア率が 33.8% からどう動くか**（版ごと）。単発の 66.7% に届く版はあるか。
- **育つ駒の扱いは変わらない**（`AtkBonus` は境界で全消しのまま）。
  **回復を入れても「育つ駒は会戦で二重に不利」は解消しない**ことを、実測で確認する
  （ムド・カド・ヨミ・リィカを含む行の突破率が、版をまたいでどう動くか）。

## 6. 実装の注意

- **`CarryOver` の既存の3行に触らない**（`StatusKeys.All` の削除・`ResetAtkBonus`・
  `WhetReceived = 0`・`ActionIndex = 0`・`OnCarryOver`）。**回復はその後ろに足す**
- **`OrderBy(u => u.Slot)` の並べ替えを動かさない**

- **`ReviveDead` で復帰させる駒のスロットは元のまま。** 再配置しない
  （境界で再配置しないのが現行の規則）

- **`ctx.PickOne` を新たに使わない**（第89期 (h)。候補2個以上で `Roll` を消費する）
- **`Presets` / `CompareBuilds()` / `CrossBuilds()` / `Stages` / `Columns` を触らない**

## 7. 申し送り（**第102期の入口**）

- **回復の位置**（第1波の後だけ／全境界）。**この期で量を決めてから**
- **育つ駒は会戦で二重に不利**——育つのに被弾が要り、被弾は持ち越され、育った結果は消える。
  `AtkBonus` の持ち越しは別のノブになる
- **傷軸の方針（ポンの判断）**: **(b) 傷を「他の通貨を通す鍵」として読む形を試す。**
  13期で唯一天井を越えたのが第87期のミオの着火。駄目なら (c) 単価を上げる、(d) 縮小も視野
- **泥仕合について**（第99・100期）: 連鎖の燃料が自軍の損害に偏っている
  （味方の死を読むのが4枚＝リィカ・ゾト・ムグ・ヴェル、敵の死を読むのが2枚＝ハギ・エグ）。
  **爆発が1枚の中で閉じている**（ホタ ×4・ウツ ×3・セロ ×2・カド ×2・トメ ×2・ベニ ×2 は全部1枚）
- **構想（`design/IDEAS_PENDING.md`）**: 複数部隊の運用／部隊サイズの可変化／
  作戦層（死者は作戦の終わりまで戻らない・永久ロストはしない）。
  **`Formation` は意図的に5枠固定**で、**`EngagementEngine` は味方部隊を1つしか取らない**
  （敵側は既に部隊列なので、対称化するだけ）
