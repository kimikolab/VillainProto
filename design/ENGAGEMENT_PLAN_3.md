## 0. 第2期の計測から新しく分かったこと（この作業の前提）

第2期の報告は「(B) 消耗が壁」で正しいが、`docs/engage.md` を読み直して**報告に含まれていなかった事実が3つ**見つかった。この作業はそこから出発する。

### 0-1. 消耗が起きているのは第三波ではなく**第二波**

入場戦力を辿ると、第1戦→第2戦は HP が 100%→60〜88% に落ちるだけで**駒は 5.0 体のまま**のことが多い。ところが第2戦→第3戦では `5.0体 76% → 1.6体 9%` のように駒も HP も一気に落ちる。第二波（巡礼騎士団・5体・司祭持ち）を抜く代金が、第三波に耐えられる残量を超えている。**第三波は執行者であって原因ではない。**

### 0-2. 逆順列の突破数は「第五波の独立勝率」を測り直しただけ

逆順は全編成が 0 か 1 抜きなので、初戦＝第五波の勝敗しか測っていない。実際 `docs/balance.md` の第5波と一致する。

| 編成 | 逆順の期待突破数 | 独立の第5波 |
|---|--:|--:|
| 逆しま改 | 1.00 | 100.0% |
| 死の連鎖 | 0.89 | 89.5% |
| 突き出し | 0.89 | 89.5% |
| 澱み喰い | 0.54 | 54.5% |
| 毒 | 0.38 | 43.0% |

したがって第2期報告4の「順路↔逆順で序列が入れ替わる＝列ごとに最適編成が違う」は**成立しない**。入れ替わりは「決定打になる単一の波が変わった」だけで、balance.md が既に示していたことの言い換えになっている。**逆順列の価値は第1削り列にあり、突破数の列には情報が無い。**

### 0-3. 入場 HP% は突破を予測しない

| 編成 | 第2戦の入場 | 第2戦の突破 | 独立の第2波 |
|---|--:|--:|--:|
| 突き出し (セロ×ヨミ) | 5.0体 76% | **0/200** | 100% |
| 隊列崩し (バサ×ヨミ×セロ) | 5.0体 86% | 141/200 | — |
| 死の連鎖 (リィカ軸) | 3.6体 57% | 168/200 | 100% |
| 毒 (グザ×ミオ×ラウ) | 5.0体 60% | 0/200 | 99% |

**突き出しは 5 体健在・76% で入って 200/200 落ち、死の連鎖は 3.6 体・57% で入って 84% 抜ける。** HP は説明変数として機能していない。仮説は2つ。

- **(i) Slot 持ち越し（判断 D5）が隊列を壊している。** 突き出し・隊列崩し・移動系は自軍を動かす編成なので、第1戦を終えた盤面は初期配置ではない。それを次戦に持ち込むと、設計された隊列で戦えない。
- **(ii) 積み上げ系は境界のリセットで立ち上がり直しになる。** 毒・追撃×毒・反撃改2 が該当。README に記録済みの既知の軸で、想定内。

(i) が本当なら **D5（配置を維持する）が移動系にだけ重い代金を課している**ことになり、会戦の基本ルールの再検討が要る。**この作業の最優先はその切り分け。**

## 2. Phase H — 隊列持ち越しの診断

### 2.1 何が分かればよいか

「第2戦の開始時点で、味方の駒は初期配置のどこにいるか」。移動系編成だけが崩れた配置で入場しているなら (i)、崩れていないのに落ちるなら (i) は棄却。

### 2.2 実装 — 診断モード `seats`

`BattleSim` に診断モード `seats` を足す。**`docs/` には出さない**（`engage2` と同じ扱い。標準出力に出して読むだけ）。

```
dotnet run --project BattleSim -c Release 0 seats [絞り込み]
```

やること: 各編成を順路の部隊列で `verbose: true` の会戦にかけ、`Openings` から**味方側**（`TeamId` が味方）の第2戦・第3戦の入場スロットを集計する。

出力は編成ごとに3行:

```
突き出し (セロ×ヨミ)
  初期配置    : 前1=セロ 前2=ヨミ 前3=… 中=… 後1=… 後2=…
  第2戦の入場 : 一致 12/200  ずれ 188/200   最頻: 前1=ヨミ 前2=セロ 前3=… （144/200）
  第3戦の入場 : 到達 0/200
```

集計の定義:

- **一致**: 生存している駒がすべて、その編成の `Formation` における自分の初期スロットに居る試行の数。**死んだ駒の枠が空いていることは「ずれ」に数えない**（死亡は隊列崩壊とは別の話）
- **最頻**: 生存駒のスロット割り当てとして最も多かったパターンと、その回数。パターンは `(UnitId, Slot)` の集合を並べた文字列でよい
- 到達 0 の戦は `到達 0/200` とだけ出す

**注意（実装で踏みやすい）**:

- `Openings` は `verbose: true` のときだけ入る。`seats` は `verbose: true` で回す。試行数は 200 のままでよい（`engage` が 6 秒なので問題ない）が、遅ければ 100 に落としてよい。落としたら出力にそう書く
- 会戦を跨いだ駒の同定は `(TeamId, Slot)` ではなく **`UnitId`** で行う。Slot はまさに今動いている量なので同定キーに使えない。同じ `UnitId` の駒が味方編成内に複数ある編成があれば、その編成は「同定不能」と出して集計から外す（無理に解こうとしない）
- **盤面を触らない。** 読むだけ

### 2.3 判定

| 観測 | 結論 |
|---|---|
| 移動系（突き出し・隊列崩し・移動改・移動改2・セロ/ヨミ/バサ/ササ を含む編成）だけ「ずれ」が多く、非移動系はほぼ一致 | **(i) が真。** D5 の再検討が要る |
| 突き出しの第2戦がほぼ「一致」なのに 0/200 落ちる | **(i) は棄却。** 原因は配置ではない。(ii) か別の要因 |
| 非移動系にも大きなずれがある | 想定外。**止まって報告する**（`SwapSlots` / 蘇生時のスロット割り当て / `Summon` の空きスロット探索のいずれかが、意図せず配置を動かしている可能性） |

### 2.4 追加の1点（軽いので同じフェーズで）

`HasFallenBack` は会戦を跨いで維持している（D6）。**移動系の編成で、第2戦の入場時に `HasFallenBack` が立っている駒がどれだけあるか**も 1 行出す。「下がってから本領を発揮する」性質が、会戦では第1戦の実績で第2戦の開幕から有効になっている——これは意図した挙動だが、代金を1回しか払わずに2戦目以降ずっと得をしている形なので、事実として記録しておきたい。

出力例: `第2戦の入場で後退済み: 2.4体/5.0体`

### 2.5 受け入れ条件

- `compare` / `chain` / `pulse` / `ablate` / `dump` / `engage` の差分 **ゼロ**（`seats` は読むだけの追加）
- 移動系・非移動系それぞれ数編成の実出力をコミットメッセージか報告に貼る
- §2.3 の判定表のどれに当たったかを明示

## 3. Phase I — 標準測定系の切り替え

### 3.1 なぜ

現在 `docs/engage.md` の主表は「5波順路 × 1部隊」で、全31編成が突破 0%・期待突破数 1.00〜2.00 に潰れている。一方 `engage2` の**地点列（3波）× 2部隊**は 0〜100% にきれいに散っており（逆しま系4編成+燃焼 100% / 速攻 51.5% / 惨禍×被弾強化 5.5% / 毒・反撃改2・追撃×毒 0%）、**現時点で唯一、編成の序列として機能している分布**。

コンセプト上もマップ上の1地点は敵1〜3部隊（`design/concept_wave_engagement.md` §7）。5波1本を主表に置き続ける理由が無い。

### 3.2 やること

`engage` を「列 × 投入部隊数」の表に作り替える。**新しい計測を足すのではなく、`engage` と `engage2` を1つにまとめる。**

- 投入部隊数 1・2・3（同一編成の複製。組み合わせは測らない）
- 列は 地点（3波）を**主**、順路（5波）を**参考**、逆順を**第1削り専用**とする

`docs/engage.md` の構成:

```
# 会戦
（共通の説明。持ち越すもの／消えるもの）

## 地点（3部隊） — 標準の測定系
### 突破率と期待突破数（1部隊 / 2部隊 / 3部隊）
### 入場戦力（味方・1部隊）

## 順路（5部隊） — 参考。1地点としては長すぎる
（第2期の結果と、なぜ参考に降格したかを1段落で）
### 突破率と期待突破数（1部隊 / 2部隊 / 3部隊）

## 逆順 — 第1削り専用
（**突破数の列は第五波の独立勝率の測り直しでしかないので載せない**、と明記する）
### 第1削り
```

主表の列:

| 編成 | 突破率(1) | 突破率(2) | 突破率(3) | 期待突破数(1) | 期待突破数(2) | 期待突破数(3) | 非線形(2部隊/1部隊×2) |
|---|--:|--:|--:|--:|--:|--:|--:|

**非線形の列**が要点。1部隊の期待突破数の2倍と、実際の2部隊の期待突破数の比。1.00 を超えるなら「第1部隊の削りを第2部隊が拾えている」＝複数部隊制が噛み合っている証拠になる（速攻 1.08→2.52 が既に出ている）。

### 3.3 逆順列の扱い

`EnemyCatalog.Columns` の逆順の `Note` を書き換える: `"強い波が先頭。第1削り専用（突破数は第五波の独立勝率の測り直しにしかならない）"`。**列そのものは残す**（第1削りは本物の情報を持っている）。

### 3.4 削るもの

- `engage2` モードは**削除する**（`engage` に統合されるため）。CLAUDE.md / CONTRIBUTING.md の記述も消す
- 順路の入場戦力の表は**残す**（0-1 の「第二波が代金」の根拠なので）。地点の入場戦力（1部隊）も出す

### 3.5 受け入れ条件

- `compare` / `chain` / `pulse` / `ablate` / `dump` の差分 **ゼロ**
- 統合後の `engage` で、順路×1部隊の突破分布が第2期の `docs/engage.md` と**完全一致**すること（統合で挙動が変わっていないことの検算。一致しないまま先へ進まない）
- 地点×2部隊の値が、第2期の `engage2` の出力と一致すること（同じ検算）
- 実行時間が現実的であること。列3本 × 部隊数3 で計測量は増える。**5分を超えるなら、順路と逆順は部隊数1のみに削ってよい**（主表は地点なので、参考列に3部隊は要らない）。削ったら出力にそう書く
- `CLAUDE.md` / `CONTRIBUTING.md` のコマンド一覧・生成物リストが実態と合っている
