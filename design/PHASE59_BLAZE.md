## 3. 作ったもの

**駒は1枚も作っていない。** ロスター（`UnitCatalog.All`）は 51 体のまま・残り枠 1。

### 3-1. 規則（`BlazeRule`）

```csharp
public enum BlazeTargets { None, AllyOnly, Both, FoeOnly }
public readonly record struct BlazeRule(BlazeTargets Targets)
{
    public static BlazeRule Default => new(BlazeTargets.Both);   // 採用値
    public bool Allies => Targets is BlazeTargets.AllyOnly or BlazeTargets.Both;
    public bool Foes   => Targets is BlazeTargets.Both or BlazeTargets.FoeOnly;
}
```

`BattleEngine.Run` に**引数で渡す**（static のノブは置かない）。
`FoeOnly` は指示書に無い**4つ目**で、**ノブではなく対照**（→ 3-3）。

### 3-2. 着火（`BomberTrait.OnDeath` の既存ループの中）

```csharp
foreach (UnitState foe in ctx.LivingMembersShuffled(ctx.Opponent(self.TeamId)))
{
    ctx.ApplyDamage(foe, EnemyBlast, self);
    if (blaze.Foes) ctx.Ignite(foe);
}
foreach (UnitState ally in ctx.LivingMembersShuffled(self.TeamId))
{
    if (ally == self) continue;
    ctx.ApplyDamage(ally, AllyBlast, self, isFriendlyFire: true);
    if (blaze.Allies) ctx.Ignite(ally, friendly: true);
}
```

**engine に新しい規則も窓口も1つも足していない。** 足したのは
`BattleContext.Blaze` プロパティと `Run` の引数だけ。

- **乱数列を動かさない。** `Ignite` は `SetCounter` / `Log` / 計数しか触らず `Roll` を引かない
  ——`Shuffle` が消費する乱数は着火の有無に依存しない。実測は §6。
- **巻き込みで倒れた相手には点かない**（`Ignite` が `IsAlive` で弾く）。
  意図どおりで、「破裂で死ななかった者が燃える」が火種の形になる。

### 3-3. 対照 `FoeOnly` を足した理由（指示書に無い判断）

指示書の3版（V0 / A / B）だと **B の勝率が動いた理由が割れない。**
B は「味方に在庫を作る（＝層に燃料を足す）」と「敵に打点を足す」という
**符号の違う2つの効果を1つの動作に持つ**ので、そのままでは
Q2（層に乗ったか）の因果が読めない——第41期の突き返しがまさにこの形で
「符号を測りたい効果は、その効果だけを 0 にできるノブと対にして作ること」を残している。
**`FoeOnly` は味方側だけを 0 にした版**で、`DivertRule.SelfMark` /
`FinisherRule.Consume` と同じ「ノブではなく対照」の扱い。**これが Q2 を決着させた。**

### 3-4. 駒の文（`UnitCatalog.Zoto`）

`MinusText` に**1行だけ**足した。**2文にしていない**（指示書 §2-2）。

    旧: 破裂は味方も巻き込む。生きている間はほぼ無力
    新: 破裂は味方も巻き込み、巻き込んだ全員に火が点く。生きている間はほぼ無力

### Q1 —— 火種として成立したか → **○（ただし閾値の前半だけ）**

`着火` は 7 行すべてで **A 3.79〜4.44 / B 8.11〜9.00**（V0 は全行 0.00）。前半は通った。

**捨て率の閾値（ボルグ系 35.5% 未満）は 5 行で落ちた**（37.9〜48.3%）。
ただしこれは Phase 0-3 で**測る前に予測して書いたとおり**で、原因は指示書の前提
（「破裂は一度きり」）が偽だったこと——継ぎ接ぎのヴェルを含む5行では
**ゾトが蘇生されて2回目の破裂を起こし、1回目の火（残3ターン）の上に降る。**

**ヴェルを含まない2行の捨て率は 0.0%**（`鱗` / `駆り立て改`）。
**供給の形はボルグと構造的に違う**——ボルグの 35.5% は
「毎ターン殴るたび隣接味方を再着火する」から出る**連続的な捨て札**で、
こちらは**破裂の回数ぶんしか出ない離散的な捨て札**である。
**閾値の趣旨（供給の形が違うことの確認）は満たしている**と読む。

### Q2 —— 層に乗ったか（危険） → **層には乗った。だが拒否権は発動しない**

**この期の主結果。**

**事実1: 層には乗った。** 味方側の着火は燃焼で味方を **0.27〜0.69 体/戦**余分に倒し、
リィカの `AtkBonus` を **+4〜+14** 押し上げる（A: 7.33 → 7.47 死 / +127.1 → +138.2）。
指示書が心配した経路は**実在する。**

**事実2: その層は勝率にならない。** 層を押し上げる唯一の経路（味方側の着火＝A 案）は
**7行すべてで負**（−2.9〜−24.1pt・別 seed 帯で −2.7〜−23.4 と再現）。

**事実3: B の上振れは層とは逆向きの量から来ている。** 対照 C（敵だけ）は
**燃死(味) 0.00・味方の死が V0 より減り・リィカの `AtkBonus` が V0 より低い**のに、
勝率は 7 行すべてで上がる（+1.1〜+30.2）。B の +7.2 / +8.6 は C 成分である。

指示書の Q2 は表で「**リィカを含む行が別 seed 帯でも +5.0pt 以上上振れしたら棄却**」、
本文で「**勝率が上がっても、それが「こちら都合で作れる死」を層に乗せた結果なら採らない**」
と書いている。**7行すべてがリィカを含むので、表の機械的な規則は
「勝率が上がる版はすべて棄却」と同義**になり、**しかも唯一層を太らせる A 案だけが生き残る。**
規則が意図の逆を向く。

**因果の規則（本文）を採った。** 根拠は事実3で、C という対照を足したのはそのため（§3-3）。
**B の上振れは層由来ではない**ので、拒否権は発動しない。
**機械的な規則を採るなら B と C が棄却され、残るのは A（層を最も太らせる版）になる**
——この読み替えはポンの判断で覆せるよう、両方の読みを並べて残す。

なお指示書の但し書き「A で起きて B で起きないことは無い」は**実測で逆**だった。
A のほうが層を太らせる（`AtkBonus` +138.2 対 +132.7 / 味方の死 7.47 対 7.25）
——**B では敵が先に落ちるので味方が死ぬ前に戦闘が終わる。**

## 11. この期に分かったこと

### 11-1. 「符号の違う2つの効果を1つの動作に持つ機構」は、片側を 0 にする対照が無いと因果が読めない

第41期の突き返し（効果A＝敵陣の突き崩し / 効果B＝隣接味方の弱体化）で
「**符号を測りたい効果は、その効果だけを 0 にできるノブと対にして作ること**」を残したが、
**今期はその規則を「対照を作る側」から使った。**

B（全員に着火）は「味方に在庫を作る」と「敵に打点を足す」の合成で、
**指示書の3版だけでは Q2 が決着しない**——B の +7.2 が層由来かどうかが原理的に割れない。
`FoeOnly` を足した瞬間に決まった（**C は層を細らせながら勝つ**）。

**系: 判定基準が「量が上がったか」で書かれていて、その量が2経路から来るなら、
経路ごとの版を作ってから測ること。** 版は `Run` の引数1つで足せる。

### 11-2. 判定の機械的な規則と、その規則が書かれた理由が、逆を向くことがある

Q2 の機械的な規則（リィカを含む行が +5.0pt 上振れしたら棄却）は、
**7行すべてがリィカを含む**ので「勝率が上がる版はすべて棄却」と同義になり、
**唯一層を太らせる A 案だけが生き残る。**

**分母が全部条件を満たすとき、「条件を満たす行が動いたら」は「どれかが動いたら」になる。**
指示書は「リィカを含む行」を**部分集合のつもり**で書いているが、
実測では**全体集合**だった（Phase 0-2 で「ゾトを含む7行はすべてリィカを含む」と数えていた）。

**系: 判定式の条件節が分母の何割を選ぶかを、Phase 0 で数えること。**
今期は数えていたのに、判定基準を書くときに使わなかった。

### 11-3. 「一度きりの供給」は蘇生役がいると一度きりでなくなる

指示書は「破裂は一度きりなので再着火は原理的に少ないはず」と書き、
`捨て率 < 35.5%` をその根拠に閾値へ据えたが、**継ぎ接ぎ（ヴェル）がゾトを戻すと2回目が起きる。**
実測の破裂回数は**ヴェルのいる5行で 1.51〜2.00・いない2行でちょうど 1.00**、
捨て率は **37.9〜48.3% 対 0.0%** と完全に割れた。

**供給の回数を「その機構が何回発火するか」で数えると、蘇生・召喚・分裂が入った瞬間に外れる。**
ゾトは `OnDeath` で発火するので、**死ぬ回数がそのまま供給の回数**になる。

### 11-4. 席の探索は「勝率」と「情報セル」で違う答えを出す。閾値と併せると衝突しないこともある

試験行1（死軸×ホタ）は、`reseat` の上位6通りが**すべて情報セル 1**（天井に張り付く）で、
情報セルを保つ最上位は7位。**その7位と現行の差が +4.8pt で、採否閾値 5.0pt に届かなかった。**

第46期が閾値を 2.0 → 5.0 に上げた理由は「上位帯の内部変動より小さい閾値はノイズ」だったが、
**その閾値は「勝率を最大化する席」を採り過ぎない歯止めとしても働く。**
今期は 5.0pt の壁が、情報セルを潰す席を自動的に弾いた。

**系: 席の探索に情報セルの列を出すこと**（`blaze scan`）。
`reseat` / `confirm` は勝率しか見ないので、**新しく `CompareBuilds()` に載せる行では
「勝つ席」ではなく「測れる席」を採る必要がある。**

### 11-5. 盤面ルールを採用した期は「既存行のセルは不変」が原理的に成り立たない

第40〜58期の新駒の期は「新駒を編成に入れない限り既存行は1バイトも動かない」が
回帰チェックそのものだった。**今期は既存7行のセルが動く**（それが採用の中身である）。

代わりの検算は2本立てになった——**(a) ゾトを含まない52行が `BlazeRule` の値に対して不変**
（乱数列を動かしていないことの証明）と、**(b) `BlazeRule.None` で `compare` が
採用前の `docs/balance.md` と完全一致**（規則の追加そのものが盤面を動かしていないことの証明）。
**(a) だけでは足りない**（`None` が既定でないと (b) が測れない）ので、
**規則を足した直後・既定を変える前に (b) を先に取ること。**
