## 0. この期の主題

**弱体軸に、敵側からの供給を作る。**

第40期に同じことを検討して見送っている。そのときの見送り理由は
**「読み手がウツ1枚しかないので、新しく生まれる行が1〜2行で天井になる」**だった。
その条件は満たされた。

| | 第40期の検討時 | 現在 |
|---|--:|--:|
| 弱体の読み手 | **1枚**（ウツ） | **3枚**（ウツ＝攻撃力 / ウケ＝アーマー / ワタ＝敵へ転嫁） |
| 弱体を持つ行 | 3行 | **7行**（Phase 0-2 で数え直すこと） |
| 共通窓口 | 無い | **`ctx.Dull`（第42期）** |

第40期の曝きが「読み手3枚を持つ移動軸」に敵側から供給を与えて、
**第五波に初めて固有の勝者を作った**のと、まったく同じ形が組める。

### 波に置く理由（第41〜43期の実測から）

**隣接を条件にする機構は、この盤面では値段にならないことが3期続けて出ている。**

| 期 | 機構 | 隣接の役割 | `reseat` の結果 |
|---|---|---|---|
| 41 | 突き返し | **コスト**（巻き込む数） | **角**が1位（20通り中19位まで角） |
| 42 | 集約 | 利得（守れる範囲） | **中央**が上位4通り全部。ただし非隣接が +9.1pt 強い |
| 43 | 渡し | 利得（横取り範囲） | **中央**が上位8通り全部。横取り量がほぼ同じで隣接に帰属できず |

X字5枠は角4つが次数2・中央が次数4で、**中央は全員に隣接する**。
だから隣接を利得にすれば必ず中央が、コストにすれば必ず角が正解になり、
**どちらも配置の判断が一意に決まる。**

**波ルールとして置けばこの問題を回避できる。** 第40期の曝きが機能したのもこの形である。

### 置き場所

**第二波・前3** に置く。理由は3つ。

1. **第二波は 100% の行が19行と最多**（48行中4割が天井に張り付いている）。
   情報セルは 23 で全波中最少。**天井を剥がす余地が最も大きい**
2. **前3 と 前1 に同じ `KnightG`（75/24/7・特性なし）が2体並んでいる。**
   片方を差し替えれば、**対照が同じ波の中に残る**——第40期の告発人（`Knight2` と数値同一）
   より条件が良い
3. 中央は `Husher`（粛の保持者）で埋まっている。**第一波を除く全波の中央が
   既にルール保持者**なので、そもそも中央は空いていない

**第五波には置かない。** 第五波は情報セル35で全波中最多、平均38.3で最難。ここは触らない。

## 2. 実装

### 2-1. 特性 `TraitId.Slander`（誹り）

```
Slander,     // 誹り: 攻撃した相手の攻撃力を下げる。口先で腕を鈍らせる
```

**敵側の語彙のプラス特性として扱う**（殉教・断罪・施し・曝きと同じ場所）。
盤面ルールのブロック（逆位・渇き・軛・粛）には入れない——両陣営に等しくかかる規則ではなく、
保持者から相手陣営への一方向の効果だから。

#### 発火点

**`OnAfterAttack`。** ターン頭の無条件発火にしないこと。理由は第40期の曝きと同じ。

- 保持者の手番に紐づくので、**保持者を早く割れば止まる**という勾配が自己言及的に立つ
- 攻撃はそのまま行うので、**同数値の対照に対する差分が特性1つに閉じる**

#### 効果

攻撃した対象に対して `ctx.Dull(target, Penalty, DullRoute.Slander)` を1回呼ぶ。

- **`DullRoute` に `Slander` を足すこと**（診断の経路別内訳のため）
- **`ctx.Dull` を必ず通すこと。** `AtkBonus` を直接引かない。
  窓口を通ることで**ウケの横取り（アーマー化）とワタの横取り（敵への転嫁）が自動的に走る**。
  これがこの期の設計の核心で、**敵が撒いた弱体を味方が資産に変換する経路**になる
- `AcceptsSupport`（ガルドの `Stoic`）の扱いは**呼び出し側で判定しない**。
  第42期の窓口は判定を呼び出し側に残す設計になっているので、
  **誹りは判定せずに `Dull` を呼ぶ**（＝ガルドにも通る）。
  第43期までの5経路と扱いが揃わないが、**この期では揃えない**（既存48行が動く）。
  **どう実装したかを報告書の表に明記すること**

### 2-2. 強度のノブ `SlanderRule`

```
public readonly record struct SlanderRule(int Penalty)
{
    public static SlanderRule Default => new(0);   // 既定は無効
}
```

- `Penalty` = 攻撃するたびに対象から引く攻撃力。`0` で完全に無効
- 掃引は **1 / 2 / 3**
- `BattleEngine.Run` の引数に足す（既存の各 `Rule` と同型）。**static のノブは置かない**
- **既定を無効にしておくこと。** 保持者を波に置いた状態で `compare` が
  現行の `docs/balance.md` と完全一致することが、
  「差分が規則だけに閉じている」証明になる（§5-1）

### 2-3. 保持者 `EnemyCatalog.Slanderer`（誹りの巡礼騎士）

```
// 第二波の前3に置く。同じ波の前1にいる巡礼騎士（KnightG）と
// 数値・型・速さが1つも違わない。差分は誹りを1つ足しただけ。
public static readonly UnitDef Slanderer =
    Make("knight_slander", "誹りの巡礼騎士", 75, 24, 7, TraitId.Slander);
```

`KnightG` は `Make("knight_g", "巡礼騎士", 75, 24, 7)`（単体攻撃・特性なし）。
**HP・攻撃力・速さ・攻撃パターンを1つも変えないこと。**

### 2-4. 波への配置

`Stages[1]`（第二波 / 巡礼騎士団）の `front3` を `KnightG` → `Slanderer` に差し替える。
**前1（KnightG）・中央（Husher）・後1（Almoner）・後3（ArcherG）は触らない。**

```
new Stage("第二波 / 巡礼騎士団",
    Formation.Build(front1: KnightG, front3: Slanderer, center: Husher,
                    back1: Almoner, back3: ArcherG)),
```

`KnightG` の定義は**削除せず残す**（前1で使われ続けるので自動的に残る）。

## 3. 診断モード `slander`

`BattleSim` に追加する。**出力は `docs/` に置かない**。
`CompareBuilds()` / `Stages` / `Columns` を触らないこと。

| 列 | 中身 |
|---|---|
| 誹り | 発火回数/戦・撒いた総量/戦 |
| 対象 | **誰が誹られたか**の内訳（上位5体） |
| 横取り | **ウケ / ワタ が横取りした量**/戦（＝敵の供給が資産に変わった量） |
| 素通り | 読み手に届かずただの損になった量/戦 |
| ウツ攻 | ウツの `CurrentAttack` の 開戦時 / 最大 / 終戦時 |
| **攻ゼロ** | **味方の `CurrentAttack` が 0 になった回数/戦・誰が**（崖の検算） |
| 目減り | **弱体の読み手を持たない行**での味方の攻撃力の目減り総量/戦 |
| 早逝 | 誹りの保持者が倒れたターン（＝供給が止まった時刻） |

**「横取り」と「素通り」を分けて数えること。** 第42期が「生成したアーマー」ではなく
「実際に吸った量」で判断し、第43期が「流した量」ではなく「効き」で判断したのと同じ理由。
**撒いた量は成果ではない。**

**「早逝」も必須。** 保持者は前列なので早く落ちる。
**供給の総量は保持者の生存ターン数で決まる**ので、これを見ないと
「弱すぎる」のか「早く死んでいる」のかが切り分けられない。

**陽性対照を必ず置く**: `SlanderRule(0)` での同じ計数（誹り 0.00）。

**発火しなかったことは盤面の値に痕跡を残さない**ので、ログか `Events` から数えること。

## 4. 予測（実装の前に書き、報告書に当否を載せる）

**軸の名前ではなく、窓口を通る駒の在庫で書くこと。**
第43期は7本中4本外し、そのうち最大のものは
**「なまりは守られた駒に乗るので、供給は攻撃力ではなく被弾で決まる」**の数え損ねだった。
**今回の窓口は「保持者の攻撃対象」なので、供給は攻撃順と前後関係で決まる。**

実装の前に以下を書き出す。

1. **誹りの発火回数の上限**（保持者の生存ターン数 × 1）。
   保持者は前列なので早く落ちる。**何ターン生きると予測するか**を先に書く
2. **誰が誹られるか。** 敵の攻撃対象の選び方から、**前列の駒に偏るはず**。
   ウツ（HP66・攻9）を前列に置く編成と後列に置く編成で、受け取る量が何倍違うか
3. **弱体の読み手7行それぞれの第二波の予測値。** Phase 0-2 の表に予測を書き足す。
   **現在 100% の行は上がりようがない**ので、そこは ±0.0 になるはず
4. **読み手を持たない41行の被害。** 目減り総量と、それが勝率に効くか。
   **攻撃力の低い支援役（クビ攻3・ドハ攻4・バン攻5）は数回で 0 になるが、
   もともと殴らないので損は小さいはず**——第36期の「安い手番は売っても安い」の弱体版が
   成立するかどうか
5. **味方の攻撃力が 0 になる回数**。0 でなければ誰が 0 になるか
6. **第二波の 100% の行が何行剥がれるか**（現在19行）。情報セルが 23 から増えるか
7. **符号が反転する行を1つ以上名指しする**（得をする行と損をする行を1行ずつ）

**予測を外したら、外した理由を報告書に書く。** 当てることが目的ではない。

**分母を必ず書くこと**（「食い違い 0 件」ではなく「240 セル中 0 件」）。

5. **第二波の平均が、Phase 0-6 で決めた行集合固定の基準から 10pt 以上落ちていない。**

6. **符号反転の実例が1つ以上出ること。** 同じ規則で第二波の勝率が上がる行と下がる行が

   数値ではなく設計を見直す
7. **第二波の情報セル**（現在23・全波中最少）と 100% の行数（現在19）。
   **天井が剥がれたかどうかがこの期の第2の狙い**
8. **「横取り」と「素通り」の比。** 敵が撒いた弱体のうち、
   何割が味方の資産に変わったか。**低ければ、読み手3枚がいても
   敵からの供給は受け取れないということ**になる
9. 波間相関6ペア。第43期の採用後の値と比べる。**第二波を触るので
   2×3 / 2×4 / 2×5 が動く**。2×5 は現在 −0.25、2×4 は −0.28
10. 固有の勝者・敗者の増減。**厳密版（=100 / =0）と緩い版（90/10）のどちらを使ったか毎回書く**
11. **第五波の平均**（48行時点）。**第二波しか触っていないので動かないはず。**
    動いたら組成効果か実体かを切り分ける

### 掃引（必須の 1〜5 を通ってから）

`Penalty` を **1 / 2 / 3** の3点で測る。基準として `SlanderRule(0)` の1本を置く。

**見るのは勝率ではなく「横取り／素通り」の比と、第二波の情報セル。**
第41期の掃引は「比が全点で 2.30 で動かない＝ノブは強度しか変えず性質を変えない」を示した。
**同じことが起きるかを先に疑うこと。**

## 6. 実装上の注意（既知の落とし穴）

1. **`ctx.Dull` を必ず通す。** 直接 `AtkBonus` を引くと、
   ウケの横取りもワタの転嫁も走らず、**この期の設計目的が丸ごと消える**
2. **ワタが敵に返す先を確認する。** 誹りで味方が弱体される → ワタが横取りする →
   **敵陣で最も攻撃力が高い生存駒に流れる**。第二波の最高攻撃力は
   `KnightG` / `Slanderer` の 24 なので、**誹りの保持者自身に返る可能性がある**。
   これは設計として望ましい（撒いた呪いが本人に返る）が、
   **そうなっているかを `slander` の診断で確認して報告書に書くこと**
3. **保持者は前列なので早く落ちる。** 供給の総量は生存ターン数で決まる。
   **「弱すぎる」と「早く死んでいる」を切り分けるために「早逝」を必ず数える**
4. **`AcceptsSupport` の扱いを揃えない**（§2-1）。第43期までの5経路と不揃いになるが、
   揃えると既存48行が動く。**どう実装したかを表に明記する**
5. **乱数列はずれる。** `Dull` の中の横取り判定で `PickOne` が走ると
   候補2個以上で `Roll` を消費する。帰属は必ず `SlanderRule(0)` か
   `KnightG` に戻した対照で取ること。前後比較で帰属しない
6. **第二波は粛（`Hush`）を持っている。** ターン外の行動が封じられるので、
   **横取りや転嫁がターン外の処理として実装されていると封じられる可能性がある**。
   `Dull` の中の横取りは `Trait.CanReact` を見ていないはずだが、**確認すること**
7. **長時間ジョブはフォアグラウンドで1ツール呼び出し内に収める。** 背景に回すと刈られる
