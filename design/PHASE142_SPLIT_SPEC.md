## 0. なぜこれをやるか

第140期の実測: **`BattleSim` の Release ビルドは 263〜294 秒、Roslyn（VBCSCompiler）のピークは 22.3 GB。**
`docs/` 全再生成（263 秒）と同じか、それより長い。**1回の変更あたりの待ちの過半が、いまはコンパイル。**

原因は第139期が名指しした構造そのもの:

> `BattleSim/Program.cs` の 68,000 行（現在 70,065 行）が **1つの `<Main>$`（現在は `Prog.Body`）に畳まれている。**
> 全モードの局所変数が1つのメソッドに同居する。

第139期の 256MB スタックで**実行時**の問題は消えたが、**コンパイル時**の代金はそのまま残っている。

### 型は既に決まっている

`Shard.cs` / `Parry.cs` / `Wall.cs` / `Tank.cs` / `Time.cs` / `Survive.cs` / `Wound2.cs` の7本が
既に **`static class XxxDiag { public static void Run(...) }`** の形で外に出ていて、
`Program.cs` 側は振り分けの1〜数行だけ。**第140期の報告書が「この問題を持たない」と確認している。**

### 分布は平ら —— だから手作業にしない

Web 側が `Program.cs` のブロックごとの行数を数えた（**数え直すこと**）:

| 順 | モード | 行数 | 累積 |
|--:|---|--:|--:|
| 1 | `demo` | 2,468 | 3.5% |
| 2 | `checkup` | 1,969 | 6.3% |
| 3 | `soak` | 1,661 | 8.7% |
| … | | | |
| 20 | `mender` | 948 | **35.8%** |
| 25 | `dissect` | 922 | 42.5% |

**129 本の平均は約 540 行。上位 20 本を出しても 36% にしかならない。**
特定の少数が重いのではなく数が多いので、**抜き出しは機械にやらせ、人（AI）は検算に集中する。**

### Q0-1. 基準を測る（**これが無いと成果が測れない**）

### Q0-2. `Prog.Body` の中で **ブロックの外にあるもの**を全数で列挙する

129 本の `if (focusId == "...")` ブロック**以外**に `Body` の直下にあるものが、分割の障害になる。
Web 側が見たかぎり:

- 先頭の `int stageIndex = ...` / `string focusId = ...`
- 末尾の共有ヘルパ（`CompareBuilds()` / `CrossBuilds()` / `LayoutRow` / `Pearson` / `Sd` / `Describe` /
  `FvName` / `MsHas` ほか、static ローカル関数が十数本）
- **ブロックの間に挟まっている文があるか**（あれば全部列挙する）

**共有ヘルパはどのブロックから呼ばれているかを表にする**（ヘルパ × モードの行列）。
1つのモードからしか呼ばれていないヘルパは、そのモードと一緒に出す。

### Q0-3. ブロックが**互いに**依存していないことを確認する

`if (focusId == "a")` の中で宣言した変数を `if (focusId == "b")` が読んでいる形が無いか。
C# のスコープ上は不可能なはずだが、**ブロックの外に出た変数**（Q0-2）を複数のモードが共有していれば依存になる。
**あれば列挙して、パラメータで渡す形に直す方針を書く。**

### Q0-4. 抜き出しの器具を作り、**1本で試す**

**手で 129 本を動かさない。** 次を満たす器具（スクリプトでも `BattleSim` のモードでもよい）を先に作る:

1. `Program.cs` を読んで、`Body` 直下の `if (focusId == "x") { ... }` を**中括弧の対応で**1ブロック切り出す
   （文字列リテラルと `//` コメント内の中括弧を数えない）
2. 中身を **`BattleSim/Modes/X.cs`** の `static class XDiag { public static void Run(string[] args, int stageIndex) { ... } }` に**そのまま**書き出す
   （**再インデントしない**——差分が読めなくなる。既存の7本も再インデントしていない）
3. `Program.cs` 側のブロックを `if (focusId == "x") { XDiag.Run(args, stageIndex); return; }` に置き換える
   （**元のブロックが `return` していたか、次のブロックへ落ちていたか**を確認する。落ちる形なら `return` を足してはいけない）
4. ブロックの中で `focusId` を読んでいれば `args[1]` から取り直す

**まず1本（小さいもの）で試して、ビルドが通り、そのモードが exit 0 で同じ出力を返すことを確認してから量産する。**

> **第139期の 52GB の事故を繰り返さないこと。**
> あの期は `compare` の分岐だけを**ローカル関数に包んで** `Body` の局所変数を全部クロージャに巻き上げた。
> **この期はローカル関数にしない。別クラスの static メソッドにする**（既存7本と同じ形）。
> **クラスに出す限り、外側のスコープを捕まえる経路が無い。**

### Q0-5. 第141期の持ち越し —— `sweep` の「新規」5本の所要を1回だけ記録する

## 2. 段ごとの作業

### 段1 —— 共有ヘルパを `BattleSim/Common.cs` に出す

Q0-2 の表で**2本以上のモードから呼ばれているヘルパ**を `static class Common` に移す。
**モードより先にやる**——モードを出したあとでヘルパを動かすと、全モードが同時に触られる。

**受け入れ**: ビルドが通る・`docs/` 14 ファイル全文一致・`compare` 305 セル 0 件。

### 段2 —— モードを **10 本ずつ**出す（行数の大きい順）

各バッチで:

1. Q0-4 の器具で 10 本を `Modes/` に出す
2. ビルド。**所要と Roslyn のピークを記録する**（Q0-1 と同じ測り方）
3. **出した 10 本を1回ずつ走らせて exit 0 を確認する**（`sweep` を毎バッチ回すと 2 時間かかる。
   `sweep` は最後に1回。**ただしバッチに `docs/` の生成器が含まれるなら、その生成物の全文一致をそのバッチで確認する**）
4. コミット（**バッチ1つ ＝ コミット1つ**。中で落ちたら10本を5本に割る）

**止める条件**: 時間が尽きるか、**ビルド時間の減りが1バッチで 5% を切ったら**そこで止めて残りを次期へ。
**曲線を報告書に載せる**（バッチ番号 × 累積行数 × ビルド秒 × Roslyn GB）。
