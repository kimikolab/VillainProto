## Phase 0

`dotnet run --project BattleSim -c Release 0 borgfront phase0`（所要 0.7 秒）。

### Q0-1 燃焼ダメージの経路

- **出どころを持つ一撃を燃焼として与える経路は engine に 0 件**。`ApplyDamage(…, burnTick: true)` を呼ぶのは燃焼の刻み（`BurnTickOnce`）と起爆（`DetonateOne`）の2箇所だけで、どちらも出どころ null。
  「火に焼かれない」と「ベニの反転」は `ApplyDamage` の**手前**（刻みの本体の中）で分かれている
- **最小の足し方**: 刻みの本体と同じ順（① 焼かれない ② ベニの反転 ③ それ以外）を1本の窓口 `FireSplashHit` に写した。③ は今までの巻き込みの呼び出しそのもの
- 順序: ③ に来た一撃は `ApplyDamageBody` の段をそのまま通る——**脆さ（入口の族の最後）→ 据え … 層 → 火の鎧の半減 → 巨躯 → 分かち → 破片 → 身構え → 軛**（第234期 Q0-1 の表と同じ）。
  脆さは規定（F1）で敵だけなので味方には掛からない。**① ② は `ApplyDamage` に入らない**ので、ホタとベニの結界の内側の味方は、破片も巨躯も分かちも通らない（刻みと同じ）

### Q0-2 熾火の免除とベニの反転

- 燃焼の刻み・起爆とも、**焼かれない枝が反転の枝より前**にあり、焼かれない枝は `return` する
- 実測（前1 ボルグ ／ 前3 ヒヨ ／ 中央 ホタ ／ 後1 ベニ ／ 後3 ミオ・ホタとベニは隣・6 波 × seed 50）: ホタが燃えていたターン 388・焼かれなかった刻み 864・**反転の回復が届いた刻み 0**
- **ベニの結界の内側でも、ホタには反転の回復が届いていない**（直さない。事実だけ）。燃える巻き込み（S）も同じ順にしたので、ホタには回復もダメージも届かない

### Q0-3 火の回復の経路

- `ctx.Heal` の入口の順: 支援拒否 → **渇き** → **反転の裏**（`inverted` なら素通り）→ HP を足す（上限で切る）
- ベニの反転の回復（`InverseHeal`）は `Heal(…, inverted: true)`＝**渇きには封じられ、反転の裏は通らない**
- 火の回復は `Heal(…, inverted: true, fireHeal: …)` とし、**`fireHeal` の1本で渇きだけを切り分けた**（H1a 素通り ／ H1b 封じられる）。ベニのマイナス（反転の裏）は H1a・H1b とも通らない
- 火の癒しは刻みの「焼かれない」枝の中で回復して `return` するので、**ベニの隣でも刻み1回に回復1回**（二重にも逆にもならない・自己検査で確かめた）
