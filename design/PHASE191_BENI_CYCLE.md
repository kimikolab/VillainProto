## Phase 0（実装前）

| # | 問い | 答え |
|---|---|---|
| Q0-1 | 燃焼が途切れないか | **途切れない**（下の机上の表。2〜12 ターン目の全部で燃焼の刻みがある）。1 ターン目の火は 2 ターン目の頭に初めて刻む。**滲み則の燃焼側（`SoakRule.Burn`）の既定は false**（第91期に切った）なので、傷を持つ相手でも残りは 3 のまま＝周期と噛み合わない端数は出ない。**手番を1回失うと周期がその位置で止まる**（`ActionIndex++` は `CanAct` を通った後）ので、止まった場所が「火の直前」なら次の火が1ターン遅れて**1ターンだけ火が切れる** |
| Q0-2 | 味方への着火で反応する札 | `StatusKeys.Burn` を条件として読む札は**3クラス**（下の表）——**火選りのヒヨ**（燃えている味方全員に強化・隣の燃えていない味方に弱体）、**熾のホタ**（燃えている間 攻 ×4・貫き・焼かれない）、火勢（保持者 0 枚）。engine の側は起爆（カタ）が燃焼を読む（隣がベニなら薬）。**`Ignite` の中には規則の分岐が無い**（計数と滲み則だけ）。ボルグの火の粉は燃焼を**書く**側で読まない——ベニが点けた相手に火の粉が重なっても残りを 3 に戻すだけ。**ヒヨ自身がベニの隣なら、ヒヨも燃える**（強化は自分を除く・弱体の候補から外れる） |
| Q0-3 | ベニの隣にホタ・ヒヨ | **在席2行は 0 行**。差し替え表 25 行（第190期と同じ規則で選び直した席）では**ホタが隣 2 行**（`燃焼 (ボルグ×ホタ)`・`火選り (ヒヨ×ホタ)`）・**ヒヨが隣 1 行**（`火選り代金型`） |
| Q0-4 | ヴェルの修正の入口 | `StitchTrait.OnAction` は `ctx.Heal` の前後の HP の差（`healed <= 0`）で「渇きに封じられた」を読んでいる。**`Heal` の戻り値を void から結果の列挙（`HealOutcome`）にする**——既存の呼び出し口はすべて文として呼んでいるので1本も変わらない。ヴェルは `Inverted` のときだけ「縫った手番」として扱い（縫い跡も残す）、**渇き（`Drought`）のときの挙動は変えない** |
| Q0-5 | 周期の位置 | `ActionIndex` は会戦の境界で 0 に戻る（`Engagement.cs`）。**蘇生（ヴェル）は同じ `UnitState` の HP を書き直すだけなので周期の位置は残る**（倒れる直前の続きから）。第190期は1要素なので区別が無かった |

### 実装の形（測る前に固定）

- **札を割る（(b)）**: `TraitId.Kindle`（火を分ける）を足す。`Kindle` の名前は未使用（`Brand` は別の札）。手番のラベルで分ける——`KindleTrait` は「火を分けた」の手番だけ、`TaintTrait` は**それ以外の手番**で働く
- `Actions = [Skill 火を分けた, Skill 澱みを分けた, Skill 澱みを分けた]`。着火は `ctx.Ignite(味方, friendly: true, source: ベニ)`（支援拒否にも点く・乱数なし・席番号順）
- 版: **第190期（毒のみ）** ＝ 第190期の定義（`[Inverse, Taint, InverseLeak]`・1要素）をこの診断のローカルに写す ／ **周期** ／ **周期・マイナスなし** ／ **素体**
- ヴェル: `Heal` を `HealOutcome` を返す形にし、`Inverted` なら縫い跡を残して手番を終える（殴らない）。**ヴェルがベニの隣にいない行は1ビットも動かない**
- 台本: 手番の `Skill` の `Text` が「火を分けた」「澱みを分けた」で区別できる。**反転の裏には表示専用のイベント `HealInverted` を足す**（`ActorId` 回復させた駒・`TargetId` 受けた駒・`Amount`・`Text` ＝ 裏の保持者の名前）——`Damage` の直前に1件。**盤面は読まない**
