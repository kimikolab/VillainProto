## 0. なぜこれをやるか

動機は2つあり、**どちらも同じ場所に効く**。

**(1) 単調さ（主）**: 敵も味方も毎ターン同じ行動を繰り返すので、GodotApp で戦闘を見ても展開が生まれない。

**(2) 計測側の行き詰まり（従）**: 第6〜9期で「編成によって代金が変わる軸」を探し、攻撃パターン（範囲/単体）でも自傷率でも**結果には届かなかった**。突破度の順位相関はどの条件でも 0.83〜0.94 で、**支配的な次元が編成の地力1本しかない**。

チャージは時間軸で (2) をやり直す手になる。毎ターン一定の火力なら代金は「総攻撃力 × ターン数」でほぼ決まり、編成が動かせる余地が小さい。**火力が塊で来るなら、「何ターンで終わらせるか」が代金を決める**。

- 速攻編成は大技が来る前に決着させて1回も浴びない → 代金が激減
- 耐久編成は浴びるが払える
- 回復編成は大技の前に回復を合わせられる

これは攻撃パターン軸とは別の次元で、地力とも直交しやすい。**順位相関が下がれば、9期分探して見つからなかった2本目の軸が見つかったことになる。**

## 2. Phase AA — 仕組みの導入（挙動変更ゼロ）

### 2-1. 型

```csharp
/// <summary>手番に実行する行動。攻撃型（AttackPattern）とは別軸で、
/// 「何をするか」を表す。パッシブ（Trait の反応）とは分離する。</summary>
public enum ActionKind { Attack, Charge }

/// <summary>手番の1回ぶん。倍率と攻撃型の上書きを持つ。</summary>
public sealed record UnitAction(
    ActionKind Kind,
    double AttackMultiplier = 1.0,
    AttackPattern? PatternOverride = null,
    string? Label = null);
```

`UnitDef` に追加:

```csharp
/// <summary>手番の行動を順に繰り返す。null なら従来どおり毎ターン通常攻撃。
/// 既存ユニットは全て null なので、この追加だけでは挙動が変わらない。</summary>
public IReadOnlyList<UnitAction>? Actions { get; init; }
```

`UnitState` に周期の位置（`ActionIndex`）を持たせる。

### 2-2. ターンループへの接続

`BattleEngine` のターンループ（`BattleEngine.cs:999` の `foreach (UnitState actor in order)`）で、`ctx.PerformAttack(actor)` を呼ぶ直前に行動を決める。

- `Actions` が null → **今までどおり `PerformAttack(actor)`**。分岐前と完全に同じ経路を通ること
- `ActionKind.Attack` → 倍率とパターン上書きを適用して `PerformAttack`
- `ActionKind.Charge` → 攻撃せず、周期だけ進める

**周期を進めるのは「手番が回ってきたとき」だけ。** 痺れ・`CanAct` 偽で飛ばされたターンは進めない（行動を1つ飛ばすのではなく、その手番が消えるだけ）。**この判断をコメントに残すこと。**

### 2-3. `SurrendersTurn` の扱い（重要）

**チャージは「行動できない」ではなく「構造的に行動しない」。** 麻痺・鈍足と同じ扱いにしてはいけない。カドの号令収入を直したときと同じ問題（`BattleEngine.cs:1017` のコメント参照）が敵側で再現する。

具体的には、**チャージ中のユニットに `StatusKeys.IdleTurn` を立てない**。据え（`BattleEngine.cs:1042` が参照している「前のターンに動かなかった味方」）が、敵のチャージを無償の収入として拾わないこと。

**チャージ中のユニットが「動かなかった」として扱われる経路が他にないか、`IdleTurn` の参照箇所をすべて確認して報告すること。**

### 2-4. 倍率の適用位置

`PerformAttack`（`BattleEngine.cs:468`）は `int atk = actor.CurrentAttack;` から始まる。倍率はここに掛ける。

- **`CurrentAttack` 自体を変えない。** `AtkBonus` と混ざると、会戦の境界処理（第1期 D2/D3）や墓守の再適用と衝突する
- 倍率は `PerformAttack` の引数として渡すか、`ctx` の一時状態として持つ。**`Trait` にインスタンスフィールドを足さない / static に置かない**（CONTRIBUTING の絶対ルール）
- 反撃・追い打ちなど**手番外の攻撃には倍率を掛けない**。倍率は手番の行動に属する

### 2-5. イベント

**GodotApp が再生するだけ、という構造を維持する。** 単調さの解消が本来の動機なので、シミュ側だけ作って終わりにしない。

- チャージを `BattleEvent` に出す（新しい `BattleEventKind.Charge` か、既存の仕組みで表現できるならそれでよい）
- 次のターンに何が来るかが**イベントから読める**こと。ラベル（「魔力集中」など）を載せる
- **GodotApp の表示実装はこの作業では任意。** イベントが出ていれば次の作業で作れる。時間があれば「溜め」バッジだけ出す

### 2-6. 受け入れ条件

- `compare` / `chain` / `pulse` / `ablate` / `dump` / `engage` / `seats` / `handoff` / `cost` / `gradient` / `aim` / `flip` / `bridge` / `bill` の差分 **ゼロ**（既存ユニットは `Actions` が null なので何も変わらない。**動いたら分岐前の経路と違うことをしている**）
- `IdleTurn` の参照箇所の確認結果を報告

## 3. Phase AB — 全体持ち・貫き持ちのチャージ化

### 3-1. 対象

ポン氏の指定は「厄介な全体攻撃持ちと貫通攻撃持ち」。該当する敵 def は3体。

| def | 現状 | 出る波 |
|---|---|---|
| `Chanter` 詠唱兵 70/8/5・全体 | 毎ターン全体 8 | 第三波・第五波 |
| `Archer` 狙撃手 38/14/11・貫き | 毎ターン貫き 14 | 第二波・第五波 |
| `ArcherG` （`archerG`）| 第一〜二波の練習用 | 第二波 |

**まず `Chanter` と `Archer` の2体。`ArcherG` は練習用の位置づけなので触らない**（触ると易しい波の性格が変わり、第1波の代金の基準が動く）。

### 3-2. パターン

```
Chanter: Charge → 全体（倍率 2.0）
Archer:  通常攻撃 → Charge → 貫き（倍率 2.0?）
```

**倍率は仮。§3-3 で決める。**

`Archer` を3周期にしたのはメモの案どおりだが、**戦闘長 3.9〜5.6ターンに対して3周期は長い**。大技が1回も出ないまま終わる編成が出る可能性が高いので、**2周期版（Charge → 強貫き）も候補として測る**。

### 3-3. 倍率の決め方 — 「痛い」で止め、「壊滅」にしない

**平均火力を大きく変えない**のがメモの方針なので、2周期なら倍率 2.0 が基準。ただし:

- 全体 16 は、味方後列の HP（40〜55 前後）に対しては1発では落ちないが、**`Chanter` は第五波で他の攻撃と重なる**
- 貫き 28 は後列に届くと大きい

**判定は残存で行う。** 倍率の候補を 1.8 / 2.0 / 2.2 あたりで振り、**「浴びて半壊」は可、「浴びて全滅（後列の支援が丸ごと消える）」は不可**。後者になるなら倍率を下げる。既存のステージ設計が「貫き1枚まで／全体1枚まで」で守ってきたものを、倍率でやり直さないこと。

### 3-4. 受け入れ条件

- **`compare` は動く**（第三波・第五波・第二波が変わる）。**動いてよい唯一のフェーズ**。動いた行をコミットメッセージに書く
- 動くのは `Chanter` / `Archer` が出る波（第二・三・五波）**だけ**であること。第一波・第四波が動いたら、意図しない経路に触れている
- `docs/` を再生成してコミットに含める

## 4. Phase AC — 測定

### 4-1. 測る場所

第8期で **「合計代金 136% で測ると何も見えない」**ことが分かっている。**測定台 113% の列と、既存5波の両方で測る。**

### 4-2. 指標

1. **大技の発火率（編成別）** — 戦闘中に強攻撃が実際に何回出たか。**これが最重要**。全編成で低いなら周期が長すぎて、波が半額になっただけになっている
2. **代金と、その編成間の標準偏差**（第6期以来の物差しがそのまま使える）
3. **突破度と、チャージ化前との順位相関**（第8期と同じ計算方法。**方法を変えない**）— **これが本番**
4. **ターン数** — 間延びしていないか
5. **群別の代金**: 速攻型 / 耐久型 / 回復持ち。区分は既存のものが無ければ、**どう定義したかを明記する**

### 4-3. 判定

| 観測 | 結論 |
|---|---|
| 順位相関が明確に下がり（目安 0.7 未満）、速攻/耐久/回復で代金が割れる | **2本目の軸が立った。** 味方側への展開に進んでよい |
| 発火率が全編成で低い | **周期が長すぎる。** 倍率と周期を詰め直す（波が半額になっただけ） |
| 発火率は十分だが順位相関が高いまま | 時間軸でも地力が支配している。**9期分と同じ壁**。そう記録する |
| ターン数が大きく伸びた | 間延び。**単調さの解消という本来の動機に反する**ので、そう報告する |

### 4-4. 受け入れ条件

- チャージ化前後の比較なので、**Phase AB の前の値を退避してから測る**こと（`seats` を退避したときと同じやり方）
- 順位相関の計算方法を明記

   - 味方の特性がチャージを前提にしていない形で壊れる場合（例: 「前のターンに動かなかった敵」を見る特性）
