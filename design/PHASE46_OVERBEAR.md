## 1. Phase 0

### 1-1. ヒサ（囃し立て・`MarkerTrait`）—— ロスターで唯一の非単調な隣接読み

`Traits.cs:1345`。doc と本体をそのまま写す。

```csharp
/// <summary>
/// 囃し立て。隣接する味方1体に標的を付ける。以後、敵の攻撃はそいつに集中する。
/// 「被弾で強くなる」「殴られると殴り返す」駒は、これが無いと自分から被弾できない。
/// </summary>
public sealed class MarkerTrait : Trait
{
    public override TraitId Id => TraitId.Marker;

    public override void OnBattleStart(BattleContext ctx, UnitState self)
    {
        // OrderByDescending は安定ソートなので、最大HP が同値だと元の並び＝席番号順に落ちる。
        // 同値の中は乱数で割る（鏡像の配置を同値にするため。PickOne 参照）。
        var adj = ctx.LivingMembers(self.TeamId)
            .Where(a => a != self && FormationRules.AreAdjacent(self.Slot, a.Slot)).ToList();
        int topHp = adj.Count == 0 ? 0 : adj.Max(a => a.MaxHp);
        UnitState? mark = ctx.PickOne(adj.Where(a => a.MaxHp == topHp).ToList());

        if (mark is null) { ctx.Log($"  {self.Name} は囃し立てる相手がいなかった", LogKind.Action); return; }

        mark.SetCounter(StatusKeys.Marked, 1);
        ctx.Log($"  {self.Name} が {mark.Name} を敵の前に押し出した", LogKind.Trigger);
    }
}
```

**「隣に誰がいるか」の読み方は2段になっている。**

1. 隣接集合の**統計量**（最大HP）を取る
2. その統計量を**閾値で読まない**。統計量を達成した**駒そのものを選んで効果を当てる**

**効くのは2段目。** 標的が付いた相手が壁（カド96・ガルド100）なら利得、脆い駒なら損で、
**符号が「誰に当たったか」で変わる。** 統計量そのもの（最大HP）は隣接集合について単調
（隣を1体増やせば最大HPは上がるか同じ）なので、**1段目だけを見ている限り非単調にはならない。**

**この期の設計はここを読み違えた**——驕りは1段目（隣接集合の最大攻撃力）を作ったが、
2段目を作らずに**閾値（自分の攻撃力）で読んだ。** 詳細は §7。

## 3. 実装

### 3-1. `UnitState.Board` —— 足した理由

**`Trait.ModifyAttack(UnitState self, int atk)` は `BattleContext` を受け取らない**
（既存4実装＝後衛特化・裂き・逆しま・熾火 はすべて `self` しか読まない）。
隣接は盤面の量なので、**「隣に誰がいるか」を攻撃力の条件にする特性はそのままでは書けない。**

取れた道は3つで、採ったのは3番目。

| 案 | 却下・採用の理由 |
|---|---|
| 条件を `Counters` にキャッシュし、`OnTurnStart` で更新する | **却下。** 味方が倒れて隣接が減る／隣が育って条件から外れる、という**戦闘中の揺れが消える**。揺れそのものがこの期の主題（指示書 §7-3「フラグで固定しないこと」） |
| `ModifyAttack` の引数に `ctx` を足す | **却下。** 4実装 + `UnitState.CurrentAttack` を書き換える必要があり、`CurrentAttack` 自身が盤面を知らない以上どのみち参照が要る |
| **`UnitState.Board`（`ctx.Add` が差す盤面参照）を足す** | **採用。** `ctx.Add` は `InstanceId` を振る唯一の1箇所で、そこに1行足すだけ。参照するのは `BattleContext` であって盤面の生データではないので、「BattleContext = 盤面への唯一の窓口」は保たれる |

**盤面の外で作られた `UnitState` では `null`** になるので、読む側は必ず
「隣が1人もいない」と同じ扱いにする（＝条件は成立しない）。

### 3-2. `OverbearTrait`

- **マイナス側（常時）**: `OnTurnStart` で隣接する生存味方全員に
  `ctx.Dull(ally, Drain, DullRoute.Overbear)`。**`AcceptsSupport` は見ない**
  （第44期の誹りと揃えた。ガルドの `Stoic` にも通る）。`LivingMembers` のスナップショットを走る
  （`Dull` は渡しの代金で駒を落としうる）
- **プラス側（条件を満たしたときだけ）**: `ModifyAttack` で 2倍。
  条件は「隣接する生存味方が**1人以上**いて、その**全員**が自分より弱い」。
  **0人のときは成立しない**（角に置くだけで無条件2倍になるのを防ぐ）
- **隣の攻撃力は驕りを除いて評価する**（`PlainAttack`）。驕り持ちが2枚隣り合うと
  `CurrentAttack` が互いを呼んで無限再帰するため。**現行の編成では盤面の値は1も変わらない**が、
  突き返しの再入ガードと同じ判断で先に置いた
- **召喚枠も隣接に含む**（隣接表がそう作られている。指示書 §7-7 の推奨どおり）
- 計数（`OverbearFired` / `Total` / `To` / `MetTurns` / `Turns` / `FirstTurn` / `Swings` /
  `Doubled` / `Backfire` / `BackfireHits`）は `verbose` に依存しない。
  **2倍が乗った回数は `ModifyAttack` の中では数えない**——あれは `CurrentAttack` を読むたびに
  走る（`StatSnapshot` でも走る）ので、数えると「振った回数」ではなく「読まれた回数」になる。
  `OnAfterAttack` で数える
- **逆行は窓口の前後の差で実測する**（`ctx.Dull` の直前と直後の `ally.CurrentAttack`）。
  予測でも係数でもないので、逆しま以外の経路（引き受けの横取りなど）が混ざっても正しく出る

### 3-3. `OverbearRule(int Drain)`

既定 2。`BattleEngine.Run` の**引数の末尾**に足した（static のノブは置かない）。
既存の位置引数呼び出し（診断が `null` を並べる形）はそのまま通る。

| 6 | 早い台 第2波 60〜90% / 第5波 0〜5% | 99.5% / 79.0% | **同上（台が別物）。** 遅い台 第2波 96.5%（予測 90〜100% ✓）/ 第5波 49.0%（予測 5〜20% ✗） |
| 7 | `Drain` では成立時刻も席も動かない | 成立時刻は全点 1.00 で不動。最適席の次数は 8点中7点で不変 | **当たり** |

### 外した理由

**予測1（ドルガ隣 14ターン）**: 指示書の目安式
`(隣の最高攻 − 12) ÷ Drain` をそのまま使った。**この式は「削りが条件を成立させる」を前提にしている**が、
実際には**削って下回らせた事例が0件**で、成立はすべて「隣が死ぬ」で起きた。
**式に「隣がその前に倒れる確率」が入っていない。**

**予測3（席の分散）**: 「早い台はウケのアーマー化で削りが収入になるから中央が有利」と読んだ。
実測では**早い台の中央は 47.2% で5席中最下位**——収入（横取り 3.05）より
**代金（削り 14.9・成立率 68.8% への低下）の方がずっと大きい。**
根本的な読み違いは §7。

**予測6（遅い台の第五波）**: 5〜20% と読んだが 49.0%。
土台の 分かち×逆しま は第五波 17.0% で、**ノノ（攻3・繕い）をオゴ（攻12）に替えた分の出力増**
——機構ではなく**体の値段**。§4-2 のとおり D0 でも 41.5% あるので、
上がったぶんの大半は驕りの機構によるものではない。

## 7. なぜ非単調にならなかったか（**この期のいちばんの収穫**）

### 7-1. 「隣接全員が〜」は、この盤面では必ず単調になる

**編成5枠では、中央の隣接集合はすべての角の隣接集合の上位集合。**

    前1 の隣 = {中央, 後1}          中央 の隣 = {前1, 前3, 後1, 後3}
    前3 の隣 = {中央, 後3}
    後1 の隣 = {前1, 中央}          ——中央に置いた駒は、他の4枚**全員**と隣接する
    後3 の隣 = {前3, 中央}          ——角に置いた駒は、そのうち**2枚**とだけ隣接する

「隣接する味方**全員**が P を満たす」は **AND** ＝ 集合に対する **最小値／最大値**の判定で、
**部分集合に対して必ず緩い。** したがって**中央でいちばん厳しく、どの角でも必ずそれ以下**。

**条件の厳しさが次数の単調関数になることが、盤面の形から証明できてしまう。**
「隣接数が増えるほど条件が厳しくなるから非単調」という設計意図（指示書 §3-1）は、
**単調性の向きを逆にしただけで、単調性そのものは壊していなかった。**

そして削る量（マイナス側）は隣接数にそのまま比例する（＝素直に単調）。
**プラスもマイナスも角を向くので、二択どころか一択に潰れた**
——実測の最適席は 2行とも角、上位5通りは 中央0 / 角5。

**（例外）召喚枠を入れると崩れる。** ○中1 = {前1, 後1} / ○中3 = {前3, 後3} は
**角にしか隣接しない**ので、胞子が湧くと角の隣接集合は中央の部分集合でなくなる。
実測でも中央のオゴだけが胞子を削っていない。**上位集合の関係は編成5枠に限った話。**

### 7-2. ヒサとの差は「統計量を閾値で読むか、統計量を達成した駒に効果を当てるか」

囃し立ても隣接集合の統計量（最大HP）を取る。**そこまでは驕りと同じ。**
違うのは次の1段。

| | 1段目（統計量） | 2段目 | 符号 |
|---|---|---|---|
| **囃し立て（ヒサ）** | 隣接で最大HP | **その駒に標的を付ける** | **当たった駒が壁か脆いかで変わる**（＝誰が隣かで変わる） |
| **驕り（オゴ）** | 隣接で最大攻撃力 | **自分の攻撃力と比べて 2倍にするか決める** | **統計量の大小だけで決まる**（＝1つの量に潰れる） |

**閾値で読んだ瞬間に、隣接集合は1つのスカラーに潰れる。**
そのスカラーが集合について単調（最大値は集合が大きくなれば上がる）である以上、
**閾値の向きがどちらでも席の選好は次数で決まる。**

> **非単調にしたければ、隣接集合から「1体を選んで効果を当てる」ところまで行かないといけない。**
> 「隣接**全員**が〜」「隣接の**誰かが**〜」はどちらも集合の統計量に潰れるので、必ず単調になる。

### 7-3. 条件を満たす席が、勝てない席だった

遅い台では **成立率 52.3% の席が 58.0%、成立率 0.0% の席が 86.3%** で 28.3pt の差が付く。
条件（隣に強い駒を置かない）と、勝つための配置（強い駒＝ドルガとウツを守れる位置に置く）が
**正面から衝突している。**

そして早い台は**そもそも攻12未満の駒しか置けない**ので、
**条件を満たす編成 ＝ 出力を捨てた編成**になる（§1-7 で 20.0% の台が5つ出た）。

> **「自分より弱い味方に囲まれていること」を条件にすると、
> 条件を満たすほど編成全体が弱くなる。** これは係数では直らない
> ——`Drain` をどう振っても、条件の中身（隣が弱いこと）は変わらないため。

## 8. 採否

**採用しない（棄却）。** 理由は3つで、どれも係数では直らない。

1. **席の分散を生まなかった**（基準6・この期の主眼）。最頻率 100% / 中央率 0% /
   最適席の次数は2行とも 2。**第45期に測った隣接依存6枚より固定されている**
2. **機構が勝率を1ptも生んでいない**。D2 − D0 は −1.4pt / −0.3pt で、
   削りが弱体軸の資産に変わっても（横取り率 29.2%・逆行 24.8/戦）勝率には出ない
3. **「削って条件を満たす」経路が 0 件**。成立は「もともと弱い」か「隣が死ぬ」でしか起きず、
   **マイナス側とプラス側が因果で繋がっていない**（1つの動作の表と裏になっていない）

**定義は残す**（指示書 §8-9）。`OverbearTrait` / `OverbearRule` / `UnitCatalog.Ogo` /
`DullRoute.Overbear` / 診断 `overbear` はそのまま。逆位・まどろみ・誹りと同じ扱いで、

- **`UnitCatalog.All` には載せない**（プレイヤーのロスターに出さない）
- **`CompareBuilds()` にも残さない**。測定した2編成は**診断のローカル**（`ObRows()`）に置いた
  ——`CompareBuilds()` を1行も動かさずに全部を測り直せる
- `seats2` の `隣接` 分類には `TraitId.Overbear` を登録してある（将来また盤面に載せたときのため）

**`docs/` の差分は `units.md` の1行**（`| Overbear | - |`＝保持者のいない特性）**だけ。
勝率表は 240 セル中 0 件の変化。**
