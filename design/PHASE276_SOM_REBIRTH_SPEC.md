# 第276期 指示書 —— ソムの転生(感電を帯びた裏切りの召喚)

読み手は Claude Code。転生段の1駒目。需要「感電の供給」×籍だけ度筆頭(compare 在席0行)のソムを合流させる。

## 0. 転生の形

**核は変えない**: 「毎ターン、敵陣に喚び出す。喚ばれたものは背いて敵につき、敵の前列が埋まる」——捨てられた理由はそのまま。

**足すのは1点だけ**: **喚ばれた餌が感電を帯びて立つ。**

これで従来の純マイナス(敵の体が増え、味方の攻撃が餌に吸われる)が裏返る:
- 餌は動かず○前2に立つ=単体攻撃の主目標を吸う → その被弾が**放電の起爆**になり、敵陣の隣接へ連鎖する
- カタの雷(状態異常を帯びた敵へ跳ねる)・シガ(感電中の敵2倍)の読み先が敵陣の中に生まれる
- 敵の体数増=ハギ追撃・撃破トリガーの餌、という副次の読み手もそのまま残る

1文の叩き台(命名・フレーバーの最終はポン): 「喚ばれたものは背いて敵につく。ただし、雷を纏ったまま。」

## 1. Phase 0

1. **感電の正確な規則**の確認(内部名・放電の条件・弾けと痺れ・層の意味・陣営対称か)。敵陣内の餌→隣接の敵への放電・連鎖が既存規則のまま成立するかを机上で確認
2. **付与の実装点**: `UnitCatalog.Fodder` の定義は触らず、**ソムの新特性側で Summon 直後に感電を付ける**形(旧ソム=`Betrayed` を対照残置するため、餌の定義を共有したまま差分を特性1枚に閉じる)
3. `ctx.Betray` の現在の既定(Enabled・Respawn)と、第103期ごろの背かれ実験の診断(BetrayWatch 系)が再利用できるか
4. **餌の死の扱い**: 餌は敵陣なので敵の死。敵側の Executioner・Condemn が餌の死を食わないか(勇者候補が餌を倒して雪だるまになるなら、それはそれで読み合いだが、挙動を実装前に書く)
5. 曝き(敵陣後列を引き出す)・敵陣形パターン3との相互作用(`FodderSlotOf` は対応済みと見えるが確認)
6. 類似実験の grep(`design/` 各期報告)

## 3. 測定

### 3.1 回帰(転生の安全性の実証)

ソムは compare 61行に在席0なので、**既存の全測定(compare・bosswave・checkwave・relic 系)が S1/S2 でも 0 差分**のはず。1セルでも動いたら原因を特定してから進む。

### 3.2 検証行(新設・雷の組は変えない)

ポン席の雷の組(シガ/ツギ/ベニ/カタ/ミオ)は触らず、ソム入りの検証行を2本新設:

- 検証・雷ソムA: シガ/ツギ/カタ/ミオ/**ソム**(ベニ抜き・攻め寄り)
- 検証・雷ソムB: シガ/ツギ/ベニ/カタ/**ソム**(ミオ抜き)

各行 × S0/S1/S2 × 本編第2〜5波+ボス規定形+チェック波2本。主指標は勝率と倒しT。

### 3.3 機構の実測(ログで確認)

- 餌の被弾回数 → 放電の発火数 → 連鎖で感電した敵の数・痺れの発生数(1戦平均)
- カタの雷が餌・感電した敵へ跳ねた回数(S0 との差)
- 敵(勇者候補等)が餌を倒した回数と、その撃破で伸びた量

## 4. 予測(Phase 0 の感電規則を見てから、実装前に書く)

- S1 は S0 より検証行の勝率が上がる(餌が「無駄打ちの的」から「起爆剤」へ)。ただし餌を敵が倒す経路では敵の撃破トリガーの餌にもなるので、ボスでは符号が読みにくい——どちらに出たかを機構の実測で説明できること
- 雷の組(ソムなし)の既存成績は不変
- S1/S2 の差が小さければ、感電の価値は層の深さでなく「点いているか」(R366 の感電版)——これ自体が知見

## 5. 採否(面白さ探索の基準)

- 検証行が、既存の雷の組と**違う勝ち方**をするか(餌の被弾→放電の連鎖がログで確認でき、勝因に寄与しているか)
- ソムの1文が短いまま(「喚ぶ・背く・雷を纏う」で読み切れる)か
- 勝率の高低そのものは採否にしない(強すぎ・弱すぎは許容。壊れ——検証行が全波100%で張り付く等——だけ記録)

**採用なら同じ期の中で続けて**(不採用ならここで止める):
1. compare に感電の行を1本正式追加(検証A/Bの成績が良い方。ポンの最終承認は報告で仰ぐ)
2. **帯電の足の再測**(第274期の「供給待ち」解除。`RELIC_MEASURES.md` の手続きどおり、新しい seed 帯で)
