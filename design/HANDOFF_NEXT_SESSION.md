## 3. 確定した規則（次も効くもの）

### 波と盤面ルール

- **波間相関を下げるのは共有資源の削除ではなく、非共有資源の追加**（第31期）。
  片方の波にだけ効く関門を足せば、重なる領域がその分だけ縮む
- **速さと攻撃型が相関する波では、行動順の反転は「型の順序」の反転でもある**（第32期）。
  予測を速さと打点だけで書くと最大の効果を丸ごと落とす（外れ17件のうち7件がこれ1つで説明が付く）
- **同じ規則を別の波に置き直しても、規則の向きは変わらない**（第32期）。逆位は第三波でも
  第五波でも「易しくする」方向に出た
- **盤面ルールは「保持者が生きている間」しか効かない。それが判断になることがある**（第36期）。
  渇きの祭司を先に割れば還しは解禁される——**「回避可能な課税」として働いた初の実例**

### 介入・反応・肩代わり

- **反撃は総量ではなく「誰に配られるか」で決まる**（第32期）。反撃軸の強さは
  その総量が誰に当たるかで決まっていて、行動順の反転はそこを直接動かす
- **介入（庇い）の税額は、介入者を割るターン数に比例する控除型**（第33期）。
  ただし**比例ではなく逓減**（第34期。生存T 2.1倍に対して発火は1.5倍）
- **窓を持つ機構の律速は、窓を閉じる条件のうち「動かせない方」が握る**（第34・35期）。
  庇いの窓は「庇い手が落ちる」と「守る相手が落ちる」で閉じる。**体でも密度でも後者は動かなかった**
- **自己終息する機構は、効き目の上限がそれ自身の耐久で決まる**（第33期）
- **反応系（棘・仇討ち）と割り込み系（軋み・追い打ち）は別物**（第33期）。前者は
  `ApplyDamage(source, ...)` で標的選択を通らないが、後者は `PerformAttack` なので介入の鎖を通る。
  **さらに肩代わり（庇う・分かち・巨躯・後備え・棘守り）は「行動」ですらない**ので粛を通らない

### 測定の作法

- **1変数を振るときは、その変数が他に何を一緒に動かすかを先に数える**（第34期）。
  「HP だけを振る」つもりが、HP は**波の総HP**でもあった（355 → 448 で +26%）
- **掃引には点の数だけ対照が要る**（第34期）。差し替え1回なら対照1つで足りるが、
  4点を振るなら4点ぶんの「規則を無効にした同数値の対照」が要る
- **「どれだけ動いたか」ではなく「何が動かしたか」で採る**（第35期）。
  第34期の HP145 は −25.0pt 動かしたが 82% が体で帰属できず、第35期の p75 は
  −0.4pt しか動かしていないのに1行を帰属できた
- **順位を予測するときは、予測に使う量と目的変数の順位を先に突き合わせる**（第34期）。
  素の単体打点の合計は用量反応と順位相関がほぼゼロで、効いていたのは
  **元の勝率（余裕）**——掃引の前に `docs/balance.md` から引けた量だった
- **到達可能性は目で数えず計算する**（第34・35期）。「固有の敗者になれる行は2行」と
  記憶で書いて外した（実測11行）。`他波最小` の列は掃引の前に出せる
- **冗長判定は r と max\|Δ\| を併記する**（第31期）。4点の Pearson は退化する
  ——3点が 100.0 で並ぶと残り1点だけで相関が決まって恒等的に ±1 になる
  （逆しま改 ‖ 逆しま+後備え は r=+1.000 だが max\|Δ\| は 65pt）
- **予測は軸の名前ではなく、窓口を通る駒の在庫で書く**（第27・28期。第32・33期でも再現）
- **条件で型が変わる駒は、条件が満たされるまでの時間を数えて分類する**（第33期）。
  リィカ（覚醒待ち）・ホタ（燃焼待ち）・セロ（後退待ち）は戦闘の大半で素の型

### 実装の作法

- **共有する定数は、片方だけ振りたくなった時点で分ける**（第35期）。
  `RedirectPercent` を味方ガルドと共有したままだと28行が一緒に動く。
  **分けるときは挙動を基底へ寄せて「定義は1箇所」を保つ**（`GuardianTrait` に残ったのは2行だけ）
- **介入の鎖に段を足しても乱数はずれない**（第35期）。`PickOne` は候補0個・1個で `Roll` を
  消費しないので、**段を足す変更の受け入れ条件は「`compare` が1バイトも動かない」でよい**
- **版の切り替えは `Run` への引数**（`ColossusRule` / `YokeRule` / `HushRule` / `MartyrRule`）。
  **書き換え可能な static のノブは置かない**（Trait は共有シングルトン・`layout` は並列実行）
- **測って採らなかった機構は削除せず、定義を対照として残す**（→ §4-5）

### 経済（第36期）

- **安い手番は、売っても安い。** 「毎ターン」→「〜したとき」の変換は供給側の作法にすぎず、
  **その手番がもともと安ければ売った代金も安い。** `IdleTurn` の再販が成立するには
  ①売り手の手番に失って惜しい価値があること ②**払い先が売り手以外であること** の2つが要る
- **`IdleTurn` 市場は速さで区切られる。** 据え（バン）の窓は `IdleTurn >= Turn` ＝
  そのターンの中だけ。**据えの窓より遅い売り手の眠りは構造的に買えない**
  （実測: まどろみを 0.20回/戦 足しても据えの買い取りは 1.00 のまま1回も増えない）
- **`ablate` は静的な入れ得しか弾けない。買い手が生き残る配置は `reseat` で確かめる。**
  第36期の試験台はガンを被覆の外に置いて号令の払いが 0.09回/戦 しか出ず、売却を1件も
  観測できなかった。被覆の中へ移して 1.78回/戦・換金率67%。
  **測る対象が勝率ではなく機構の発火であるときは、第21期の飽和検査に加えて
  「機構の相手役が、機構の働く時刻まで生きているか」がもう1つの検査項目になる**

## 6. 運用上の申し送り

### 6-1. 指示書は自己完結させる

**リポジトリ外の文書を参照しない。** 第32期は `board-rule-units.md` を4箇所で参照したが、
`design/` にも `docs/` にも `~/Downloads` にも存在せず、必要な情報を全部測り直す羽目になった。
**参照するなら `design/` に置いてから参照する。**

指示書の前提がリポジトリと食い違うことは実際に頻発している（第32期3件・第33期1件・第36期1件）。
**食い違いを見つけたら止めずに報告して進み、報告書の冒頭に「前提の訂正」として書く。**

### 6-2. 機構の新設前に Phase 0 を置く

**同種の機構が過去に測られていないかを、README の系譜と §4-5 の対照カタログで確認する。**
第32期は「反転」を新設しようとして、**既に `InversionTrait` として実装済み・測定済み・
不採用済み**だったものを再発明しかけた。新設していたら
`BattleEngine.Run` の同じ1行に `Inversion || Retrace` の重複条件が生まれていた。

Phase 0 で確認すること:

1. **同じ機構が `TraitId` に既にあるか**（`Traits.cs` の列挙子を全部読む）
2. **同種の実験の記録位置**（README のどの節・`design/` のどのファイル・行番号まで）
3. **その機構が触るメソッドの呼び出し元を全部数える**（渇きは「回復役は4種」と数えて外した。
   実際に `ctx.Heal` を呼ぶのは7経路で、ゴルムとリィカは説明文に回復と書いていないのに回復する）

### 6-3. 受け入れ基準の書き方

- **「固有の敗者 ≥1」は「新規に湧くこと」を明示する。** 第33期は基準を数の上では満たしたが、
  その1本（澱み喰い）は**介入の前から同じ1本**だった。**既存1本で形式的に満たせてしまう。**
  第34・35期は「規則を無効にした同数値の対照でも敗者になるか」を1行ずつ検算して直した
- **同値検証を受け入れ条件に使えるところでは使う。** 形は2つある。
  ①**保持者と数値が同一の対照に差し替える**（軛 ↔ 城塞の重装兵 / 粛 ↔ 討伐隊の新兵 /
  渇き ↔ 巡礼騎士 / 殉教 ↔ 戦斧兵）——`compare` が1バイトも動かなければ、
  差分が規則だけに閉じている証明になる。**逆位はここを分けず HP と攻も動かしたので、
  「壁が効いたのかルールが効いたのか」の切り分けに追加測定が要った。**
  ②**規則を既定で無効にして `Run` に引数で渡す**（第36期の腹・まどろみ・還し）——
  何も渡さない状態の `compare` が現行の `docs/balance.md` と一致することが検証になる。
  採用で既定が動いたら、**検算の相手も動く**（第36期は V0 → V3 に移した）
- **回帰チェックの分母を書く。** 「食い違い 0 件」ではなく「168 セル中 0 件」と書く

### 6-4. 実行の作法

- **長時間ジョブはフォアグラウンドで1ツール呼び出し内に収める。** 背景に回すと、
  起動したコマンドが返った時点で刈られる（`nohup` を付けても、同じターンの中で
  次のコマンドに移っただけでも死ぬ）
- 所要の実測（第36期・42編成 / seed 0..199）: `compare` **7.6秒** / `spread` **22秒** /
  `ablate`（全編成）**26秒** / `guard percent` **13秒** / `gullet belly4`（4版）**25秒** /
  `gullet belly` 約20秒。`reseat`（1行・120通り）は数十秒、`hush`（全版）は第31期の記録で約4分。
  **`layout` は分割できないので、一回の呼び出しで走り切れるかを先に確かめる**
- **`reseat` の120通りが 20.0% で並んだら、配置の答えではなく「台が死んでいる」の合図。**
  原因はほぼ必ず総攻（払い出しの駒の積みすぎ）。**予算は1枠ずつ返しても戻らない**ので、
  払い出しの枠数そのものを減らして組み直す
- **計測器と測定対象を同時に動かさない。** `spread` の前後比較で採否を決めるなら、
  **編成の行数を揃えて前後を測り直す**（世代で 35 → 38 → 42 と変わっている）
