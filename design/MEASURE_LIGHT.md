# 作法の変更 —— 測定を軽くする（第327期から）

置き場所: `design/MEASURE_LIGHT.md`。`CLAUDE.md` の作法の節から1行で参照する。
この文書は自己完結している。

## 0. なぜ

1期の測定が2時間を超えることが増え、ポンが「ちょっとした変更を触って次へ進む」ことができなくなっていた。主な原因:

- 過去の器具の照合（台本の指紋）が毎期増え（第317期 102本 → 第326期 140本）、しかも HEAD 用と新しいビルド用で**2回**回している
- 格子（数万台の総当たり）を1期に何本も回している
- 1期に並べる版が多く、代表台 ／ `compare` ／ 格子がすべて版の数だけ掛け算で増える

いまはプロトタイプの段階で、優先は「面白い仕組みを早く触ること」。細かい数字の確かめは、規定にする直前にまとめて行えば足りる。

## 1. 期の種類

指示書の頭に、どちらの期かを書く。書いていなければ**軽い期**。

| 項目 | **軽い期**（標準） | **重い期**（規定化・大きな仕組みの変更のときだけ） |
|---|---|---|
| 版の数 | 3〜4 個まで | 同じ |
| Phase 0 | 指示書が挙げた項目だけ・短く | 同じ |
| 予測のファイル（R397） | 3〜5 行でよい | 今どおり |
| 代表台の波 | **ボス ／ 近衛 ／ 大隊 ／ 本編 第2波 ／ 第5波** の5波 | 10 波 |
| seed | 0..99 | 0..199 |
| `compare` | 版ごとに回す（今どおり） | 同じ |
| 格子 | **回さない** | 推しの版のボスと精鋭の **2本まで** |
| 過去の器具の照合 | §2 の「変えた駒が出る器具」だけ | §2 の全本（使い回しの HEAD と比べる） |
| 試遊の台 | **版を試遊の台に出す**（DemoApp の一覧で選べるように・名前の頭に「版・」） | 必要なら |
| `sweep` | `sweep fast` | `sweep fast` |
| docs/ 再生成 | 規定を動かしたときだけ | 今どおり |
| 報告書 | 「決めたこと」「ポンに出す選択肢」「試遊の台の名前」「ボスの倒しT と精鋭の勝率」を先に・表は最小 | 今どおり |

- 軽い期で照合や格子を省いた分は、**夜間の `sweep nightly`** が拾う。翌朝 nightly で差が出ていたら、次の期の段0 で直す
- 規定化（段0）は、それだけで重い期にはしない。規定化で `compare` が想定どおりに動いたことと、§2 の照合（変えた駒が出る器具）で足りる。**仕組みの中身を変える規定化**（エンジンの規則を変えるもの）は重い期にする

## 2. 過去の器具の照合の使い回し（最初に一度だけ作る）

- **期の最後に**、新しいビルドで取った台本の指紋を保存する（例 `.tmp/digest_cache/<コミット>/`。保存先は任せる・`.gitignore` の内で）
- **次の期は、その保存を HEAD の指紋として使う**。HEAD のビルド（別の worktree）を建て直さない。保存が無いとき・HEAD が保存のコミットと違うとき（Codex のコミットが挟まったなど）だけ建て直す
- **軽い期**は、変えた駒（札 ／ 定義）が出てくる器具だけを照合する。どの器具が当たるかは、器具の名前と駒の名前の対応表（自動で引けるなら自動・引けなければ手で）で決め、照合した器具の一覧を報告書に書く
- 重い期は全本を照合する（使い回しの HEAD と比べる）

## 3. 指示書の側（Claude ／ Web）の約束

- 版は 3〜4 個まで。比べたい案が多いときは期を分ける
- 「門に届かなくても格子を回す」「念のため別の seed の帯で」は書かない（必要なら重い期にする）
- 強すぎ ／ 壊れの見張りは「1T 決着 ／ 倒しT が半分以下」程度に絞る
