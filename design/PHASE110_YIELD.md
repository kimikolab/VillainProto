## 1. この期でいちばん大きいこと

### 1-1. **V2 が埋めるはずだった穴は、譲渡の側にはなかった**

第109期は `トモ×ハギ` の門2 が 0.01〜0.26 回/戦 なのを見て
「トモは味方で最も遅いので、撃破と自分の手番のあいだにそのターンの残りが全部入る」と読んだ。
V2（敵が倒れた瞬間にターン外で譲る）はそこを直接埋める設計だったのに、

    トモ×ハギ の門3（譲渡/戦・第2〜5波）  V0 0.08 → V1 0.09 → **V2 0.23**（線は V0 + 0.5）
    Q3（1つの撃破で追い打ちと譲渡が両方立った回数）  **0.09 回/戦**（線 0.5）

段の表（表A'）を見ると、**切れているのは段1 —— そもそも死の通知が来ない。**
`トモ×ハギ` の「敵の死の通知が届いた回数」は第2〜5波で **0.13〜0.90 回/戦**しかない
（`トモ×ドルガ` は 2.92〜5.00）。

> **「条件が成立しないのは条件の書き方が悪いから」と読む前に、条件の入力が盤面に何回現れるかを数えること。**
> 譲渡を即時にしても、**倒れる敵がいなければ読むものが無い。**
> 第109期の読み（トモが遅いから間に合わない）は `トモ×ドルガ` では正しいが、
> `トモ×ハギ` では**そもそも撃破が起きていない**——ハギは `CanAct => false` で自分の手番に1度も振らず、
> 追い打ちは「味方が倒したら」なので、**撃破の起点を1つも持たない台**だった。

### 1-2. **V1（窓）は通った。条件を緩めるだけの版は単調で、下がる余地が構造的に無い**

主判定 Q2（`トモ×ドルガ` の第四波で条件成立が V0 + 0.5 回/戦 以上）は **2.17 → 2.88（+0.71）**で通った。
第四波は軛（1発の上限）で決着が伸びる波で、第109期が「1ターンに倒れる敵が減るので条件が満たされにくい」と
突き止めた場所そのもの。**窓を1ターンぶん広げると、そこがいちばん大きく動く。**

4台すべてで門2・門3・帰属が V0 以上になる（表A・表B）:

| 台 | 門2 V0 → V1 | 門3 V0 → V1 | 帰属 V0 → V1 |
|---|--:|--:|--:|
| トモ×ドルガ | 1.84 → **2.15** | 1.70 → **1.94** | +41.3 → **+46.0** |
| トモ×ムド | 1.23 → **1.59** | 0.94 → **1.08** | +24.1 → **+26.5** |
| トモ×ソム | 2.08 → **2.85** | 1.50 → **1.98** | +2.8 → **+3.4** |
| トモ×ハギ | 0.14 → **0.15** | 0.08 → **0.09** | +0.6 → **+0.6** |

**V1 は条件節を緩めるだけなので、門2・門3 は定義上 V0 以上にしかならない。**
残る危険は「増えた譲渡が損になる」ことだけで、実測では**潰れの割合も譲渡あたりの与ダメも変わらない**
（`トモ×ドルガ` で 35.0 → 34.0 / 戦・潰れ 0.68 → 0.78）。

### 1-3. **判定の線が2本、書いた時点で到達不能だった**

**Q4（V2 が粛に読まれる ＝ 第二波の門3 が 0）は、粛の実装のせいで原理的に立たない。**
粛（`HushTrait`）は **「保持者が盤上に生きている間」**だけ `CanActOutOfTurn` を閉じる
（CLAUDE.md に明記：「保持者を倒せばターン外の行動は戻る。`CanActOutOfTurn` は呼ばれるたびに評価する」）。
だから伝令を割った後は譲渡が立つのが正しい。実測は第二波で 4台合計 1.47 回/戦。

**代わりに立てた (g') が機構を直接実証した**——第二波の譲渡 55 件のうち、
**伝令を割る前に起きたものは 0 件**。段の表でも、
**段3 の「粛」の列が 0 でないのは第二波だけ**（0.14〜2.10 回/戦・他の4波は全波 0.00）。

> **判定を「その規則が閉じている間の挙動」ではなく「波の集計」で書くと、規則の解除条件に足を取られる。**
> 第59期（条件節が分母の全部を選ぶ）・第60期（条件が原理的に成立しない）・
> 第61期（分母の割合が小さすぎて発動しない）・第107期（同じ指示書の別の節が線を到達不能にする）に続く**5例目**。

**Q5（帯に入った台で帰属が下がらない）は、帯に入る台が1つも作れなかった。**
`compare` の外にローカル台を組む規則（速さ ≥ 8・`AtkBonus` を他人に書かない）の下で
**プール 12 枚から 3 枚を選ぶ 220 通りを全部測ったが、素体版の第2〜5波平均が 40〜95% に入る台は 4台中 0 台**

## 2. Phase 0（指示書 §3）

### 2-1. 器具の再現（§3 の 1）—— **完全に一致した**

旧台（第109期の土台 = ガルド / キリ / ボルグ）で V0 をノブ経由で回すと、
第109期の表A の**門1・門2・門3 が 20 セルすべて小数第2位まで一致**した。
ノブを渡さない経路との差も **0 件 / 4,000 戦**。

**ただし「譲渡の与ダメ」だけは第109期より大きく出る**（`トモ×ドルガ` 第2波で 25.7 → 45.3）。
理由は**集計の範囲**で、`TaillightYieldDamage` は `ApplyDamage` が**殴った側**の帳簿に積むので、
**第109期はパートナー1枚ぶんだけを読んでいた**（`p.TaillightYieldDamage`）。
灯はパートナーが倒れれば次に遅い味方へ移るので、**第109期の値は下限**である。
この期は味方5枚から集めている。

### 2-2. 土台の探索（§3 の 2）—— **総攻を足しても床は上がらない**

規則（測る前にコードへ固定）:

    (1) 速さ ≥ 8（`Stoic` 持ちだけは速さを問わない——灯の候補から自前で外れる）
    (2) `AtkBonus` を他人に書かない（`TraitEntryMap.Supplies` の 強化・弱体 ×〈自分以外〉と `Reviver` を外す）
    (3) 素体版の第2〜5波平均が 40〜95% に入る台が 4台中3台以上
    同点の割り方: 帯に入った台数 → 4台平均が 50% に近い → 3枚の `Def.Id` の辞書順
    席: 後3 = 範囲攻撃の攻最大 ／ 前3 = `Stoic` あればそれ・無ければ HP 最大 ／ 中央 = 残り

**プール 12 枚・220 通りを全部回して、(3) を満たす組は 0。** 上位は:

| 土台（前3 / 中央 / 後3） | 総攻 | ドルガ | ムド | ソム | ハギ | 平均 |
|---|--:|--:|--:|--:|--:|--:|
| **ガルド / ソラ / ボルグ（採用）** | 33 | **37.1** | 0.6 | 0.0 | 0.0 | **9.4** |
| ガルド / セロ / ボルグ | 38 | 25.0 | 5.5 | 0.2 | 0.5 | 7.8 |
| ガルド / セロ / ソラ | 26 | 28.4 | 0.6 | 0.0 | 0.0 | 7.2 |
| ソラ / セロ / ボルグ | 35 | 19.8 | 2.9 | 0.1 | 0.0 | 5.7 |
| （参考）ガルド / キリ / ボルグ ＝ 第109期 | **39** | 4.5 | 0.0 | 0.0 | 0.0 | **1.1** |

> **総攻が最大の組（39）が最下位で、採用した組（33）の 8.5 分の1しかない。**
> 第109期の土台がいちばん総攻が高いのに床に張り付いていた理由は**薄刃**——
> キリの攻 12 は `ModifyAttack => 1` で打点が常に 1 なので、総攻の表には出るが盤面には出ない。
> **台の強さを「総攻」で見積もると、打点を書き換える特性のぶんだけ外す。**
> 採用した組が勝っているのも攻撃力ではなく**逸らし（標）**で、
> 「敵の現在HP最大に標を付ける」が味方の単体振りを集中させている。

**指示書 §5 の分岐どおり、帯に入る台が3台に届かないので分母を明示して判定した**
——Q5 は「測れていない」、Q1〜Q4 は門の側なので分母に依存せず測れる。

### 採否 —— **V1 を採用、V2 は残置**

指示書 §5 の分岐「**V1 だけが Q2 を通り、V2 が伸びない**: V1 を採用。
V2 は『即時は前倒しであって増量ではない』として記録」にそのまま当たる。

**Q5 が測れていないまま採用してよい理由を明示しておく:**

1. **V1 は条件節を緩めるだけなので、門2・門3 が V0 を下回ることが原理的に無い**
2. **帯の外ではあるが4台とも帰属が V0 以上**（+46.0 / +26.5 / +3.4 / +0.6）
3. **拒否権は原理的に立たない**——トモは `Presets.Compare` にも `Presets.Cross` にも
   1行も入っていないので、`compare` 305 セルも交差帯12行も1セルも動かない
   （第90期の傷の引き取り〈`GatherRule`〉と同じ形。**読み手が増えれば後から動き始める**）

**V0（`YieldMode.OwnTurn`）と V2（`YieldMode.Immediate`）は削除せず対照として残置してある**
（オゴ・ゴウ・ヌキ・オノ・`ThornRule` と同じ作法）。

## 6. 器具の反省（**次の期が踏むところ**）

### 6-1. **既定を動かす期では、対照の版を `Default` で書いてはいけない**

診断の版の表を `("V0 現行", TaillightRule.Default)` と書いていたので、
**採用で既定が V1 になった瞬間に「V0 の列」が黙って V1 に化けた。**
自己検査 (h)（V0 では窓を1回も読まないはず）がそれを捕まえた——
**捕まえられたのは、「V0 だけが持つはずのない性質」を検査に書いてあったから**である。

> **版を並べる診断では、既定に頼らず3版とも明示的にモードを渡すこと。**
> **そして「その版だけが持たない性質」を1つ自己検査に置くこと**——
> 版が入れ替わっても数値は出るので、値を見ているだけでは気づけない。

### 6-2. **印刷された参照値と突き合わせるときは、同じ書式に落として比べる**

(l) は最初 `Math.Abs(実測 − 参照) > 0.005` で書いて 30 値中1件落ちた
——`トモ×ドルガ` 第4波の門3 が **0.8350** で、印刷は `0.83`。
差はちょうど 0.005 で、浮動小数では 0.0050000000000000044 になる。
`Math.Round(0.835, 2)` も**偶数丸めで 0.84 を返す**ので直らない。
**`ToString("F2")` どうしで比べる**のが正しい——参照値は「印刷された文字列」だから。

### 6-3. **計数の載る先を、窓口ではなく「誰の帳簿か」で確かめる**

`TaillightYieldDamage` は `ApplyDamage` が**殴った側**に積むので、
トモの帳簿を読むと常に 0 になる（初版はそう書いて 表A の与ダメが全セル 0.0 になった）。
第109期はパートナー1枚から読んでいたので**下限**になっていた。
**帳簿の持ち主は「その機構の保持者」ではなく「その量を生んだ駒」である。**
