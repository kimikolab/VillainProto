## 0. 主題

### 0-1. 96期のあいだ、測っていなかったものが2つある

**(1) 会戦の強さ。** `compare` 61行は各波を**独立に**測っている。
第98期の実測では**単発で5波全勝が 12/73、会戦突破が 0/73、順位すら一致しない**。
**別の物差しである。**

**(2) 勝ち方の質。** 画面で見ると、第二波以降は
**前列が倒されていって残り2体でなんとか勝つ**形がほとんどで、
**「噛み合って圧勝した」という試合が無い。**

`chain` 診断には **残存**（勝った試行の平均生存数）と **全滅勝ち**（生存1体での勝率）が既にある。
実測は残存 2.1〜2.8 / 5・全滅勝ち 15〜42%。
**測ってあったのに、96期のあいだ一度も判定に使っていない。**

### 0-2. 器具が「圧勝」を潰す側に働いていた

第83期以降、判定の土台は**情報セル**（`0 < 勝率 < 100`）だった。天井のセルは測れないので、

- 第88期の**情報帯フィルタ** —— 床と天井の台を主判定の分母から外す
- **拒否権2** —— **第五波が 95% を超える行が新たに2行以上生まれたら拒否**

**「圧勝する編成が増えること」を、明示的に拒否権にしていた。**
測定の都合としては正しいが、**ゲームとしては「噛み合ったら圧勝」がほしい。**

> **同じ懸念（情報が取れなくなる）に、フィルタと拒否権で二重に課金している。**
> **フィルタは主判定の分母の話。拒否権にする必要は無い。**

**§3 でここを直す。**

### 0-3. これから相手にするもの

最終ボス（勇者パーティー）は、**今の敵が雑魚に思える高さ**にする方針。
`design/BOSS_REQUIREMENTS.md` は3つの勝ち筋を要求していて、そのうち1本は**力押し（burst）**である。

> **相手が桁違いに強いなら、消耗戦は原理的に成立しない。**
> **「どう勝ったか」は好みの問題ではなく、勝てるかどうかを決める能力になる。**

**だからこの期で「勝ち方の質」を測れるようにしておく。**

## 1. 作るもの

新しい診断 `run` を1本足す。**既存の診断は1文字も書き換えない。**

    dotnet run --project BattleSim -c Release 0 run engage <col>   # A-1a 会戦（col = 5 / 3）
    dotnet run --project BattleSim -c Release 0 run solo           # A-1b 単発の勝ち方
    dotnet run --project BattleSim -c Release 0 run tables         # 表A〜E

### A-1a. 会戦の指標

**73行**（`Presets.Compare` 61 ＋ `Presets.Cross` 12）× **seed 0..199** で、
**5波の列と3波の列の両方**を回す。

- **5波の列** = `EnemyCatalog.Columns[0]`（現在 `EngagementColumn` が返しているもの）
- **3波の列** = `EnemyCatalog.Columns` の中の **"地点"**（`Stages.Take(3)`。
  コメントに「長さだけを変数にするため、中身も順序も順路と同じ」とある。**実装済みのものを使う**）

**列の名前と中身を実装から引いて表に書くこと**（指示書の記述を信用しない。手作り表のずれが第98期で7例目）。

出すもの（行ごと・列ごと）:

| | 定義 |
|---|---|
| **突破率** | その列を最後まで抜けた seed の割合 |
| **平均突破波数** | 落ちた波 − 1 の平均 |
| **落ちた波の分布** | 第1波で落ちた数 / 第2波 / … |
| **入場戦力** | 各波の開始時点の生存数と HP 合計の割合（第99期の Phase 0 と同じ定義） |

### A-1b. 勝ち方の質（**単発。この期の新しいところ**）

**73行 × 5波 × seed 0..199** の単発で、**勝った試行についてだけ**次を出す。

| | 定義 |
|---|---|
| **残存** | 勝った試行の平均生存数（0〜5） |
| **圧勝率** | **生存4体以上で勝った試行の割合**（勝った試行のうち） |
| **全滅勝ち** | 生存1体で勝った試行の割合（勝った試行のうち） |
| **決着ターン数** | 勝った試行の平均 |

**定義は `chain` 診断の残存・全滅勝ちと同じにする**（比較できるようにするため）。
**`chain` を書き換えず、定義だけ写すこと。** 写した箇所を報告書に明記する。

**会戦でも同じ4つを出す**（最後の波を勝ったときの生存数）。

### A-1c. 並べ方

**「勝率」と「勝ち方」は別の列にする。** 混ぜて1つの指標にしない。

> **この期は目標値を決めない。** 「残存が何体なら良いか」「圧勝率が何%あるべきか」を先に決めない。
> **まず分布を見る。**

## 6. 申し送り（**第101期以降の入口**）

### 傷軸について（第99期の画面から）

- **供給者が盤で一番守れない場所に固定されている。** X字5枠で単体攻撃から守られるのは
  中央・後1・後3 の3枠。前列2枠は必ず埋まるので、**体と火力を優先すると
  キリ（攻12→1・HP44）が前列に押し出される。** 敵に傷を書けるのはキリとノミの2枚だけ
- **読み手は動いている。量が届いていない。** 画面の実測でエグは 攻12→18（傷2つ × 3点）。
  同じ試合でリィカの層は 攻5→89
- **方針（ポンの判断）**: **(b) 傷を「他の通貨を通す鍵」として読む形を試す。**
  13期で唯一天井を越えたのが第87期のミオの着火。**駄目なら (c) 単価を上げる、(d) 縮小も視野**

### 泥仕合について

- **連鎖の燃料が自軍の損害に偏っている。** 味方の死を読むのが4枚（リィカ・ゾト・ムグ・ヴェル）、
  敵の死を読むのが2枚（ハギ・エグ）。**一番大きい払い出し（リィカの三角数 5/15/30/50/75/105）が
  自軍の全滅と引き換え。** だから噛み合っても「なんとか勝った」になる
- **爆発が1枚の中で閉じている。** 条件付き倍率（ホタ ×4・ウツ ×3・セロ ×2・カド ×2・トメ ×2・
  ベニ ×2）はあるが、**化けるのは常に1枚**。**複数枚が同時に化ける形が無い**
- **候補**: 敵の撃破を燃料にする連鎖を厚くする／既存の駒の燃料を敵の死へ振り替える

### 会戦について

- **境界に回復は1点も無い**（第99期。`Engagement.cs` に `Heal` も `Hp +=` も0箇所）。
  **HP・Slot・`HasFallenBack` はそのまま、状態異常9本と `AtkBonus` は全消し。**
  **損害は持ち越し、積み上げはクリア** ——**育つ駒は会戦で二重に不利**
- **A-2（境界の回復ノブを置いて掃引）は A-1 の分布を見てから**
