## 0. 主題

### 0-1. 第84期が残した問い

第84期は棘に傷を載せて**採用しなかった**。機構は動いた（供給 3.67回/戦・在庫 6倍・読み手発火）のに
相乗が +0.04pt しか動かなかった。切れたのは供給でも在庫でも読み手でもなく、
**傷1つ = 3点という単価が、それを運ぶ出来事（反撃の打点 22〜45）に対して 7〜14% の添え物だった**こと。

**この期の前提**: 味方側では収支が逆になるはずである。

- **受け皿が壊れない。** 敵側でカドの傷が積まなかったのは、同じ反撃が22〜45点で相手を落とすから。
  味方への巻き込みは攻11 × 50% = 5点（惨禍で7）で、味方のHPは34〜150。**相手が残る。**
- **供給が厚い。** 反撃1回で敵に1、味方には隣接数ぶん（前1なら3）。
  棘守りで庇った相手は入れ替え後も必ず隣にいるので確実に載る。
- **運ぶ出来事の打点が小さい。** 5点の巻き込みに傷1（＝ハリが読めば3回復）が乗る。
  **比が 60% で、敵側の 7〜14% とは桁が違う。**

### 0-2. 何を変えるか

**縫いのハリ（`SutureTrait`）が糸を引く先を、殴った相手だけでなく味方にも広げる。**

現行: 「**傷が最も深い敵を狙い、その傷1つにつき最も傷ついた味方を3繕う**／
繕うたび、糸を通した**敵**の傷がひとつ塞がる」

新: 「傷が最も深い敵を狙い、**殴った相手か、傷がいちばん深い味方か、深いほうの傷口から糸を引く**。
その傷1つにつき最も傷ついた味方を3繕う／繕うたび、**糸を通した傷**がひとつ塞がる」

**1文は2文にならない。** 読む対象が2つに増えるのではなく、**1つの選び方の候補が広がる**だけ。
**選べない（深いほうが自動）のが代金**で、カドの隣では味方側が深くなり、敵の傷を塞げなくなる。

**標的選択（`SeverTrait.Prefers`）は触らない。** ハリは今までどおり傷が最も深い敵を狙う。
**狙う先と糸を引く先がずれる**のは意図した非対称で、そこから配置の問いが出る（§0-4）。

### 0-3. 供給側 —— ANDゲートを踏まないための3段

味方の傷の書き手は現状 **0 枚**。カドだけを書き手にすると
**書き手1・読み手1 の AND ゲート**（第57期の燃焼で踏んだ形）になって分解できない。
そこで供給を2段に分けて梯子にする。

| 段 | 供給 | ハリ | 内容 |
|---|---|---|---|
| **W0（対照）** | `ThornWound.None` | 片側 | 現行 |
| **W1** | `ThornWound.Both` | **両側** | 味方に傷を書くのは**カドだけ** |
| **W2** | `ThornWound.Foe` ＋ **巻き込み則** | **両側** | 味方に傷を書くのが**6枚**になる |

**巻き込み則**: `BattleEngine.ApplyDamage` で `isFriendlyFire == true` のダメージが通り、
**対象が生きていれば傷を1つ書く**。既存の呼び出し口は6箇所ある（Phase 0-2 で全数を確定させること）。
現時点で分かっているのは 余波（ボルグ）／生贄（リィカ・開戦時1回）／吸い（ゴルム・毎ターン）／
破裂の味方巻き込み（ゾト・死亡時）／棘の巻き込み（カド）／置き去りの削り（ナラ・毎ターン）。

**W2 でカドの `ThornWound` を `Foe` に落とすのは重複を避けるため**——巻き込み則がカドの巻き込みも拾うので、
**カドの味方側供給は W1 と W2 で同数**になる。したがって **W2 − W1 = ボルグ・リィカ・ゴルム・ゾト・ナラの寄与**
にきれいに割れる。**これが分解の要**なので、二重に書いていないことを自己検査で必ず確かめる。

### 0-4. 期待している新しい問い（**測る対象であって前提ではない**）

1. **カドの隣にハリを置くと、ハリだけが損をする。** `MostHurtAlly` は `self` を除くので
   （`BattleEngine.MostHurtAlly`: `a != self && a.AcceptsSupport && a.Hp < a.MaxHp`）、
   ハリが巻き込まれて負った傷はハリ自身では引けない。
   **カドの隣には別の駒を置き、ハリはそこから糸を引く**という配置の問いが立つ。
2. **第39期の「ハリとナタは同居させない」が崩れる可能性。**
   当時の理由は「ハリの塞ぎ 1/T が供給 1/T と等速なので敵側在庫が天井1に張り付き、
   `SeverTrait.Threshold`（2）に構造的に届かない＝ナタが永久に沈黙する」。
   **塞ぎが味方側へ逸れれば敵側の在庫は減らない。**
   **カド × ハリ × ナタ を診断のローカル台で必ず組んで測ること。**

## 2. 変更の定義（**測る前に固定。数字を見てから動かさない**）

### 2-1. ノブ

既存の作法（`ThornRule` / `ThinBladeRule` / `SeverRule`）と同じ形。
**`BattleContext` / `BattleEngine.Run` に省略可能引数として通し、既定はすべて現行。**

```csharp
public enum SutureSide { Foe, Both }
public readonly record struct SutureRule(SutureSide Side)
{
    public static SutureRule Default => new(SutureSide.Foe);       // 測定中はここ
}

public readonly record struct SpillWoundRule(bool Enabled)          // 巻き込み則（W2）
{
    public static SpillWoundRule Default => new(false);             // 測定中はここ
}
```

### 2-2. ハリの書き方

`SutureTrait.OnAfterAttack` を書き換える。**`SeverTrait.Prefers` と標的選択は1文字も触らない。**

```
糸口の候補:
  敵側 = target（殴った相手。介入で逸れたならその相手。現行どおり）
  味方側 = 生存する味方のうち self を除き、傷がいちばん深い者
           （同数のタイブレークは ctx.PickOne。候補0個・1個では Roll を消費しない）
選び方: 深いほうを取る。同数なら敵側（現行挙動を保つ）
w <= 0 なら何もしない（現行どおり）
patient = ctx.MostHurtAlly(self)（現行どおり。self は含まれない）
ctx.Heal(patient, PerWound * w)（窓口は必ず ctx.Heal。渇きに課税されること自体が第39期の目的）
Seal を持つなら、糸を通したほう の傷を 1 つ引く
```

- **`AcceptsSupport` の判定は増やさない。** 現行どおり `ctx.Heal` と `MostHurtAlly` に任せる。
  **糸口の候補では `AcceptsSupport` を見ない**——傷を塞ぐのは支援ではなく、相手のマイナスを取り除く操作。
  **第42期からの「`AcceptsSupport` が5経路で3通りに割れている」件には触らない**（§6）。
- **味方側の糸口に `self` を含めない。** これが §0-4 の配置の問いの本体。**含めたくなっても含めない。**
- ログは糸口が敵か味方かで文言を分ける（`LogKind.Trigger`）。**どちらから引いたかを必ず出す**
  ——Q3 の帰属をログではなく `Events` から引くにしても、目視の監査に要る。

### 2-3. 巻き込み則（W2）の書き方

`ApplyDamage` の**HP を引いた後・死亡判定の後**に置く。

- **対象が生きているときだけ書く**（書き手側の作法。死体には刻まない）。
- **数は定数 1。** ダメージ量に比例させない。
- **`burnTick` 由来のダメージには書かない**（燃焼の毎ターンの目減りは刃ではない）。
- **中継（巨躯・分かち・転嫁）は Phase 0-1 の判断に従う。** 推奨は書かない。
- カドの `ThornWound` は W2 では `Foe`。**二重に書いていないことを自己検査 (c) で確かめる。**
