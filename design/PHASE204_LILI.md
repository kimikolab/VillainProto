### Q0-2 吸い取りのダメージの入口

- 術のダメージの前例は **紅蓮の直撃（`GurenStrikeTrait`・`ctx.ApplyDamage(foe, share, self)`）** と破裂（ゾト）。どれも `PerformAttack` を通らず `ApplyDamage` を直に呼ぶ。吸い取りも同じ形にする（`source` = リリ、`pattern` = null）。
- **効かないもの**: 庇い・後備え・殉教・標的の横取り（どれも `SelectTarget` の段なので通らない）／ 受け流し（ガルドの味方側の段。敵には無い）／ 逸らし（`pattern == Single` のときだけ）／ **呪いの共有**（`singleHit` が偽なので起きない）／ 反撃（敵の反応札は断罪 `Condemn` だけで、`InReaction` のときしか動かない）。
- **効くもの**: 敵の破片（HP の前に削られる）・軛の上限（第四波は1回 25 まで）・§1 の敵の標の +50%（「相手陣営の出どころ・刻みでも徴収でもない」に当たる。ソラ・ザンの標が敵に載っている行だけ）。
- 撃破者はリリになる（`OnKill` はリリの札に無い）。

### Q0-4 状態の「書き手」を読む箇所

- **毒と燃焼には駒の側に書き手の記録が無い**。書き手は書いた瞬間の計数（`SoakPoisonWrites` など）と台本の `StatusGain.ActorId` にしか残らず、刻みは出どころ null で走る。だから「書き手は元のまま」は構造的に成り立つ（移しても誰も書き手を読み直さない）。
- ベニの結界（反転・啜り・紅蓮）は「隣にベニがいるか」だけを見て書き手を見ない。ラウの伝染も層の数だけを見る。痺れ毒の印の値（1 吐き ／ 2 殴られ）は計数の帰属用で、大きい方を取るので残る。
- 紅蓮の計数用キー（`gurenHeld` など）は敵に残る（計数だけで規則は読まない）。

### Q0-5 呪いの攻撃力低下とウツ

- ネルの「呪い持ち全員 −4」は **`ctx.Dull`（`AtkBonus`）**で、状態キーではない。`Curse` キー（0/1）は呪いの共有（ムドの段）と「まだ呪われていない敵」の選別にしか使われない。
- ウツが読むのは受けた弱体（`Dull` の量）。**移すのは状態キーだけなので、ウツとの組み合わせは成立しない**（ウツが呪いを受け取っても攻撃力も手数も増えない）。

### Q0-6 `MostHurtAlly`

- 自分を除き、`AcceptsSupport` が偽の駒（ガルドの `Stoic`）を**飛ばし**、HP 割合が最小の味方を返す。同値は `PickOne`（候補 1 以下なら乱数を引かない）。**全員満タンなら null** → 指示書どおりリリ自身が受け取る。
- だから**リリ自身は、ほかの味方が全員満タンのときしか受け取らない**（自分がどれだけ傷ついていても）。

### Q0-7 粛と「祝福が還る」

- 粛が止めるのは `CanActOutOfTurn` を通る 8 本だけ。墓守（リィカ `OnAnyDeath`）・還し（ゴルム）など既存の「死亡時の回復」は通らず、粛に止められない。**祝福が還るもそれに揃え、粛では止めない**。渇きは `Heal` の入口で止まる（溢れにも数えない）。

### Q0-8 破片の上限・減衰が無い前提

- `StatusKeys.Armor` の doc は「供給源がヒビだけ」と書いているが、**実装では既に4本ある**——砕け（ヒビ `ShatterTrait`）・引き受け（ウケ・`Dull` の中）・身構え（ササ `BraceTrait`）・鱗（ウロ `ScaleTrait`・倒れた味方から）。消費する側は `ApplyDamage` の破片の段と、礫（ガレ `ShrapnelTrait`・最大保持者を砕いて 0 に）。**リリは5本目**になる（doc の文は第138期から古い・R151 の再発）。
- 上限を前提にした**コード**は無い（コメントだけ）。

### Q0-9 過去の類似

- 「サキュバス」「ドレイン」は `design/` に指示書以外 0 件。**状態を移す**前例は業のゴウ（第49期・棄却）——味方から自分へ状態のカウンタを 1 ずつ取り上げる。除外の作法（`Armor` / `IdleTurn` を外す）と「燃焼を `Ignite` に通さない」はここから引いた。
- 回復の余りを別の資源にする前例は啜り・紅蓮（第193・197期）。溢れの定義（`Healed` / `Full` のときだけ）はそこに揃える。

## 2. 実装（予測をコミットしてから）

- **駒**: `UnitCatalog.Lili`（`Id = "lili"`・施しのリリ・HP78／攻3／速6・`Actions = [Skill]`・札 `Kiss` ＋ `KissSpill`）。**ノノはその場で転生**——`All` の同じ位置をリリにし、旧ノノは `UnitCatalog.Nono` に対照として残した（`All` にも `Retired` にも入れない）。`Presets` の 8 行（＋交差帯 1 行）はリリを引き、行名 `耐久 (ガルド×ノノ)` → `耐久 (ガルド×リリ)`、`傷×被弾 (カド×ノミ×ノノ)` → `(カド×ノミ×リリ)`。**行の中身（席）は1つも変えていない。**
- **札**（`KissTrait`・`MenderTrait` / `SealTrait` は1文字も触っていない）:
  - `Kiss`（規定）——手番の頭に生きている敵全員が聖痕を持てば祝福の儀、そうでなければ 聖痕の無い敵のうち最大HP最大（同値は `PickOne`）に聖痕 → 最大HPの 20% を `ApplyDamage(foe, n, リリ)` で吸う（**`PerformAttack` を通らない**＝庇い・受け流し・逸らし・呪いの共有・反撃は起きない）→ **受け取り手を吸った後に選ぶ**（`MostHurtAlly`・null ならリリ。吸い取りで敵が倒れると「還る」が先に走るため）→ 代金の札があれば状態を移す → 与える。溢れ（`Heal` が `Healed` / `Full` のときの、HP が増えなかった分）は受け取り手の破片。`OnAnyDeath` で祝福が還る（聖痕の敵が倒れたら最大HPの 10%）。
  - `KissSpill`（代金の札・本体なし）——外すと「移さない」の版（`yP`）。
  - `KissBare`（吸うだけ・保持者 0 枚）——儀式と還るなし。**全員に聖痕が付いたら消して一巡目に戻る**（指示書に無かったのでこう決めた）。
  - `Kiss30`（30% の版・保持者 0 枚）。
- **状態キー `stigma`（聖）**を `StatusKeys.All` に足した（会戦の境界で消える）。移すキーは `KissTrait.Moved`（`All` から `KissTrait.Excluded` の 8 本を引いた形。キーが増えれば自動で入る）。燃焼は `Ignite` を通さず残りターンの大きい方、量のキー（毒・傷・濃縮・破片）は足す、二値は大きい方。**傷の刻み手（`WoundWriters`）も一緒に移す**（再行動は刻み手と倒れた駒の陣営が違うときしか走らないので、味方に移った傷で刻み手が動くことは無い）。
- **儀式の吸い取りで倒れた敵は、倒れた時点でまだ聖痕を持っているので「還る」が走る**。聖痕を消すのは吸い終わってから施す前。
- **engine（`BattleEngine.cs`）に足したのは、聖痕のキー・表示名と、表示専用の `EmitKiss` / `EmitStatusTransfer` の2本だけ**。判定は1本も足していない。`Run` の引数も増やしていない（版は札の差し替え）。
- 帳簿は `UnitTally` の計数専用のフィールド（`Kiss*` / `Rite*` / `Return*` / `KissMovedBy` / `ArmorPeakSeen`）。**`ArmorPeakSeen` はリリの手番の頭の走査とリリが破片を足した直後にしか更新しない**（ヒビ・ウケが足した破片は次のリリの手番まで見えない＝最大値は下振れしうる）。
- 診断の表（`TraitKeyMap.TraitKeys` / `TraitHooks`・`checkup` の分類表）に4枚を登録した（第179期に `checkup ideal` が止まった穴を先に塞いだ）。
- 旧ノノを `"nono"` / `UnitCatalog.Nono` で引いていた診断（38 ファイル）は `"lili"` / `UnitCatalog.Lili` に置き換えた（**過去の繕いの診断はいまリリを測る**——転生の期の通常の扱い）。DemoApp は攻撃音の分類に `lili` を1語、作戦マップの隊の説明文を1語（「リリの**吸い取り**で保たせる」）。
