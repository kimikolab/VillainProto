# 第112期 —— 文書の期：CLAUDE.md を時系列に分割する

起点: `CLAUDE.md` が **240,698 字 / 4,912 行**。Claude Code の自動読み込み上限（150,000 字）を超えており、
起動のたびに警告が出て、**知見が読まれないまま指示書が書かれる事故**が起きうる状態。

**この期は機構を1つも変えない。`BattleCore` は1文字も触らない。盤面は1ビットも動かない。**
`BattleSim/Program.cs` に触るのは (T3) の1箇所だけで、それも**生成物の列の定義**であって測定ではない。

**この指示書は自己完結させてある。** 規約は `CLAUDE.md` の (G1)〜(G13)。

## 0. 主題

### 0-1. 肥大の正体（実測）

| 節 | 行 | 字 |
|---|--:|--:|
| 概要 | 8 | 236 |
| **コマンド** | **4,340** | **209,850** |
| └ うち `dotnet run` などのコマンド行 | 648 | 53,675 |

| 設計判断の蓄積 | **6** | **289** |

> **全体の 65% が「コマンド一覧に差し込まれた各期の知見」。**
> 診断を足すたびにその期の発見を隣に書いてきた結果で、
> **「設計判断の蓄積」という節が 6 行しかないのは、その中身が全部コマンド節に散っているから。**

### 0-2. 何を残し、何を出すか（**この線が全部**）

> **「則」は残す。「その則を導いた実測と経緯」を出す。**

指示書を書くときに**毎回当てる**もの（規約・一般則・アーキテクチャ・コマンドの索引）は `CLAUDE.md` に残す。
**特定の期の測定値・台の内訳・棄却の理由・数値の履歴**は `design/LESSONS_*.md` へ移す。

判定に迷ったら**残す側**に倒す。この期の目的は「読まれない知見を作らないこと」であって、削減量ではない。

### 0-3. 時系列で割る（軸別にしない）

軸（傷／毒／弱体…）で割ると、**軸の定義が変わるたびに文書ごと引っ越し**が要る。
時系列なら「その期の知見はその期のファイル」で割り方が機械的に決まり、追記は常に末尾の1本だけ。
軸で引きたい要求は **`CLAUDE.md` の主題別索引**（§1-3）が受け持つ——索引の1行なら軸が変わっても書き換えが安い。

### 0-4. この期で**やらないこと**

- **本文の書き換え・要約・更新**。移すのは**逐語**（§4 の自己検査 (c) で機械照合する）
- **古くなった記述の訂正**。矛盾を見つけたら §5 の「矛盾リスト」に**記録するだけ**で直さない
  （直すのは内容の判断であって、この期は場所の移動だけ）
- **`README.md`（617,950 字）の分割** — 自動読み込みされないので緊急性が違う。別の期
- **`design/` の既存文書（`PHASE*.md`）の統廃合**

## 1. (T1) 分割の形

### 1-1. ファイル名（**`PHASE` で始めてはいけない**）

`docs/rules.md` の `期` 列は `design/PHASE*.md` を走査して期番号を拾う（`Program.cs` の `DvPhases`）。
`PHASE` 接頭辞を使うと**期の初出が化ける**。

    design/LESSONS_001_040.md
    design/LESSONS_041_060.md
    design/LESSONS_061_080.md
    design/LESSONS_081_100.md
    design/LESSONS_101_.md        ← 現行。以後の期はここに追記する

### 1-2. 境界（**分量の実測から引いた。等分が目的**）

コマンド節の散文を、行に現れる期番号（無ければ直前の期を引き継ぐ）で按分した累積:

| 期 | この帯の字数 |
|---|--:|
| 〜40 | 約 24,000 |
| 41〜60 | 約 34,000 |
| 61〜80 | 約 51,000 |
| 81〜100 | 約 64,000 |
| 101〜 | 約 35,000 |

**5本ともおおむね 25〜65k 字に収まる。**帯の境界は分量から引いたもので、意味の切れ目ではない
（意味は索引が担う）。**期番号が読めない散文の扱いは §2-2。**

### 1-3. `CLAUDE.md` に残す形（**目標 100,000 字以下**。上限 150,000 に対して余裕を持たせる）

    ## 概要
    ## 構成と絶対のルール          （現状のまま）
    ## アーキテクチャ              （現状のまま・29k 字）
    ## 規約 (G1)〜(G13)            ★新設。散らばっている全文を1箇所に集める（§1-4）
    ## 指示書を書くときに当てる一般則 ★新設（§1-5）
    ## コマンド                    コマンド行と1行説明だけ（54k 字）
    ## 知見の索引                  ★新設（下）

**知見の索引**は2つの表を持つ:

| 表 | 内容 |
|---|---|
| **主題別** | 「傷軸」「毒・燃」「弱体・強化」「被弾・移動」「手番」「会戦」「器具と測り方」「波ルール」…… → **どのファイルの第何期を読むか** |
| **期別** | 期番号 → ファイル。第84〜111期は**1行要約つき**（直近ほど参照頻度が高い） |

各 `LESSONS_*.md` の冒頭には **`description:` を1行**置く（「この帯で何が確定したか／いつ読むか」）。

### 1-4. 規約 (G1)〜(G13) は1箇所に集める

現状は本文のあちこちで引かれている。**Phase 0 で全文の所在を洗い出し、逐語で1節に集める。**
**内容は1文字も変えない。**（G14）は保留のままで、その旨だけ書く。

### 1-5. 一般則の節（**移すのではなく、既にある箇条書きを集める**）

第84〜110期の引き継ぎで「**指示書を書くとき必ず当てる**」として並んでいた則（測り方7項目・設計10項目）は、
**`CLAUDE.md` に残す**。各項目の末尾に**由来の期**を括弧書きし、詳細は `LESSONS_*.md` の該当期へ送る。

> **則は残す。則の根拠になった実測は出す。**

## 2. (T2) 移し方

### 2-1. 手順（**1コマンドずつ**）

コマンド節を上から順に、各診断のブロックについて:

1. **コマンド行**（`dotnet run …`）と、その**1行説明**は `CLAUDE.md` に残す
2. **それ以外の散文**を、その診断が属する期の `LESSONS_*.md` へ**逐語で**移す
3. 移した先に **`### 第nn期 — <診断名>`** の見出しを付ける（**見出しは新規に足してよい唯一のテキスト**）
4. `CLAUDE.md` 側のコマンド行の末尾に **`→ LESSONS_081_100.md 第84期`** の形で行き先を書く

### 2-2. 期番号が読めない散文

期が特定できない散文は **`CLAUDE.md` に残す**（則の可能性が高い）。
**移した／残した／判定できなかった の3分類で字数を報告する。**

### 2-3. 順序は保つ

`LESSONS_*.md` の中は**期番号の昇順**。同じ期の中は `CLAUDE.md` での出現順。並べ替えない。

## 3. (T3) `docs/rules.md` の「CLAUDE.md」列（**先に決めておく地雷**）

`derive rules` は **ノブの型名が `CLAUDE.md` の本文に出現するか**で ○ を付けている（`Program.cs` 206・260 行）。
散文を出すと**多数の行で ○ が消える**。盤面は動いていないのに `docs/` に大きな差分が出るので、
必須4項目の報告で事故に見える。**2段階でやる:**

| 段 | 内容 | コミット |
|---|---|---|
| **段1** | **生成器を触らずに** `docs/rules.md` を再生成し、**○ が消えた行を全部列挙する** | 1本目 |
| **段2** | 走査対象を **`CLAUDE.md` ＋ `design/LESSONS_*.md`** に広げ、**列名を `CLAUDE.md / LESSONS` に変える**。再生成して **段1 で消えた ○ が全部戻ること**を確認 | 2本目 |

**段1 の列挙がそのまま「移動で落ちたノブが無いこと」の証拠**になる（段2 で戻らない行があれば、そのノブの記述は移動中に消えた）。
この2段を飛ばして段2 だけやってはいけない。
