## 0. 出発点

第6〜8期で、**攻撃パターンによる代金の向きは結果に届かない**ことが確定した。代金では ±8pt 開くのに突破度の順位相関は 0.83〜0.94、群差が出るのは境目（合計代金 113%）だけで +0.125 波。しかも体数を減らすと向きが一緒に消えるので、難度を動かさずに向きだけ開く方法が無い。**攻撃パターン軸はここで打ち切る。**

### 6期分を通して見えた一番大きな事実

**どの指標で測っても編成の序列がほとんど同じ。** 逆順列も勾配列も反転列も、平坦列との順位相関を取ると変わらない。**いま支配的な次元が1本（編成の地力）しかない。** 配分判断が生まれないのはその帰結で、波の側をどういじっても地力の順位を崩せていない。

崩すには、**攻撃パターンではなく編成の内部構造に課金する**必要がある。第5期に見つかった「自傷の固定費」（死の連鎖系・惨禍系が第1波でも代金 50% 付近、逆しま系・移動系は 13〜22%）はまさにそれで、攻撃型ではなくエンジンの形に課金している。**この作業はその軸が本物かを確かめる。**

### 測定台が定まった

**合計代金 113%（部隊容量 約100% の少し上）が、結果が敏感になる唯一の帯。** 今後どんな軸を試すときも 136% で測ってはいけない。第8期の `bridge` の 113% 列をそのまま台として使う。

## 2. Phase X — 代金の分解 `bill`

### 2-1. 分解の式

代金は「定義上の最大HPのうち、部隊戦の終わりまでに失った割合」。その内訳を3つに割る。

```
失ったHP  =  敵由来の被ダメ  +  味方由来の被ダメ  −  回復  +  残差
```

- **味方由来の被ダメ = 自傷分。** `UnitTally.TakenFromAlly` が既にある（`ApplyDamage` で `isFriendlyFire || 同チーム` のとき加算）。破裂・生贄・吸いはここに出る
- **敵由来の被ダメ = `DamageTaken − TakenFromAlly`**
- **回復は現在 tally が無い。** `UnitTally` に `Healed` を足し、`ctx.Heal` で実際に増えた分（`target.Hp - before`）を加算する。`UnitTally.Add` にも足すこと
- **残差**は、`ApplyDamage` / `Heal` を通らずに HP を直接動かしている経路と、過剰殺傷（HP が 0 未満に沈む分）を吸う

### 2-2. 残差を必ず出すこと

**残差は誤差ではなく検出器。** 大きければ「代金の一部が tally の外で動いている」ということで、分解そのものが信用できない。

編成ごとに `残差 / 定義上の総最大HP` を出し、**全編成の最大値を報告に書く**。目安として **5% を超えたら止まって報告する**（§5-7）。

### 2-3. 測ること

第8期の 113% 列（反転列(低)）で、味方1部隊の会戦を seed 200 で回す。編成ごとに:

| 編成 | 代金合計 | 敵由来 | **自傷分** | 回復 | 残差 | **自傷率** |
|---|--:|--:|--:|--:|--:|--:|

- **自傷率 = 自傷分 / (敵由来 + 自傷分)**。「払った HP のうち何割を自分で削ったか」。編成を群分けするときの連続量として使う
- すべて定義上の総最大HPに対する割合（第5期以来の分母の判断と揃える）

### 2-4. 会戦を通した積み上げ

**自傷分が部隊戦ごとに繰り返し発生するのか、初戦だけなのか**を見る。HP は会戦を跨ぐ唯一の持ち越し資源なので、自傷型は**単発戦では成立しても会戦では二重に課金される**可能性がある。

編成ごとに、第1戦・第2戦・第3戦それぞれの自傷分を出す（到達した試行だけの平均、到達率を併記）。**第5期の `cost` は単発戦の値なので、会戦での積み上がりは誰も測っていない。**

### 2-5. 受け入れ条件

- `compare` / `chain` / `pulse` / `ablate` / `dump` / `engage` / `seats` / `handoff` / `cost` / `gradient` / `aim` / `flip` / `bridge` の差分 **ゼロ**。**`Healed` を足しても既存の出力に出さないこと**（`dump` が tally を印字しているなら、`Healed` は印字対象に入れない）
- 検算: 分解の合計（敵由来 + 自傷 − 回復 + 残差）が、`cost` / `bridge` で使っている代金と一致すること
- 残差の最大値を報告に明記

## 3. Phase Y — 群を入れ替えて橋を測り直す

### 3-1. やること

**第8期の `bridge` をそのまま使い、群の定義だけ差し替える。** 列も物差しも変えない（比較可能性を保つため）。

- 群: **`HasAoe`（範囲/単体）→ 自傷率（Phase X で測った連続量）**
- 列: 第8期の4本（反転列 138.8% / 中 124.7% / 低 113.2% / 平坦列(低) 110.7%）をそのまま
- 指標: 突破度（第8期で導入したもの）

出すもの:

1. **自傷率と Δ突破度の相関**（連続量どうし。群平均より情報量が多い）
2. **自傷率の三分位で群分けした Δ突破度**（高自傷 / 中 / 低）。第8期の範囲/単体の群差 **+0.125 波**と直接比べられる形で
3. 各列での順位相関（第8期と同じ計算方法。**方法を変えない**）
4. **自傷率の分布そのもの。** 連続的に散っているか、二山に割れているか、それともほぼ一様か

### 3-2. 判定

| 観測 | 結論 |
|---|---|
| 自傷率と Δ突破度の相関が強く、群差が +0.125 波を明確に超える | **自傷軸は結果に届いている。** 攻撃パターン軸より有望。設計（リターンの比例化）に進んでよい |
| 相関はあるが群差が +0.125 波と同程度 | 攻撃パターン軸と同じ壁。**軸を強化しないと結果に届かない**——リターン側の設計が必須という結論になる |
| 相関がほぼ無い / 自傷率がほぼ一様 | **自傷軸も存在しない。** 第5期の「自傷の固定費」は編成名から見た錯覚だった可能性。**その場合は止まって報告する**（次の方向を決め直す必要がある） |

### 3-3. 気をつけること

**自傷率と地力が交絡している可能性がある。** 自傷型が弱いのは自傷のせいではなく、たまたま弱い編成が自傷型だっただけかもしれない。**平坦列(低) での期待突破度を「地力」として、それを引いた残差で相関を取る**（差分 Δ突破度 を使っているのはそのためだが、明示的に確認すること）。地力と自傷率の相関も併せて出す。

### 3-4. 受け入れ条件

- `compare` ほか差分 **ゼロ**。`Columns` / `Stages` 不変
- 第8期の `bridge` の既存出力（範囲/単体の群差、順位相関）が**完全一致**すること（群の追加であって置き換えではない。**一致しないまま先へ進まない**）

## 5. 作業ルール

1. Phase X → Y → Z の順。**フェーズを跨いで1コミットにしない**（Z は文書のみ）
2. コミットメッセージに「動いた docs/ の行」を書く。動いていないなら「compare 差分ゼロ」と明記
3. コード・コメント・ログは日本語。既存の文体（**却下した案とその理由も書く**）に揃える
4. CONTRIBUTING.md のチェックリストを通す。`UnitTally` にフィールドを足すときは `Add` の更新を忘れない
5. 長時間ジョブは前景で待ち切る。`layout` は走らせない
6. **何も直さない。** 自傷型が不利と分かっても、この作業では特性を変えない
7. 以下を見つけたら**実装前に止まって報告する**:
   - 残差が定義上の総最大HPの **5% を超える**編成があった場合。**どの経路が tally の外で HP を動かしているかを特定して報告する**（推測で分解の式を変えない）
   - 第8期の `bridge` の既存出力が一致しなかった場合
   - 自傷率がほぼ一様（散らばりが小さい）だった場合。**その場合 Phase Y の判定は意味を持たないので、分布を報告して指示を仰ぐ**
