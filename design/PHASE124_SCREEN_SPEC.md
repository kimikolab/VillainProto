## 4. 段1 —— 戦績パネル（`DemoApp` のみ・`BattleCore` を1行も触らない）

ポンが2回書いた「DPS カウンターを出したい」への直答。
`BattleResult.TallyByUnit` は既に載っていて `verbose` に依存しない（Q0-1・Q0-2）ので、
**判定を1つも通さずに「誰が何をしたか」を画面に出せる。**

### 4-1. なぜ演出より先にこれをやるか

×の多くは「**機能しているのか**わからない」であって「1文が読めない」ではない。
**「1文が読めるか」と「機能しているか」は別の問い**で、後者は数字で閉じられる。
先に数字で閉じてしまえば、**演出で解くべき問題が本当に何なのかが絞れる**（P4 の判定がそれ）。

### 4-2. 出す場所

戦闘終了時に**戦績パネル**として出す。加えて、**戦闘中も見られる**こと（一時停止して開ける／常時サイドに出る、のどちらでもよい）。
既存の戦況ログを潰さないこと。

### 4-3. 列（味方5枚・敵も出せるなら出す）

**`docs/pulse.md` と同じ定義**を使う（同じ言葉で2つの表を作らない）:

| 列 | 出どころ |
|---|---|
| 振 | `Attacks` |
| 干渉 | `Interventions`（**ダメージを通した回数。活動量の本体**） |
| 与(敵) | `DamageToEnemy` |
| 与(味) | `DamageToAlly`（破裂・生贄・吸い・巻き込みがここに出る） |
| 被 | `DamageTaken` |
| 被(味) | `TakenFromAlly` |
| 回復 | `Healed` |
| 大技 | `BigAttacks` |
| 落ちた | `LastActiveTurn`（生存なら決着ターン） |

`Taillight*` / `Reader*` のような**特性専用の計数は出さない**（Q0-1 の分類の後者）。
出すと52枚ぶんの列が要る。**必要なら第125期以降に「その駒に関係する計数だけを出す」形で足す。**

### 4-4. `干渉 0` を「価値が無い」と読ませない —— **必須**

`docs/pulse.md` に既に書いてある注意を**そのまま画面に載せる**:

> **`干渉 0` は「価値が無い」ではない。** 呪詛（ネル）・萎縮（クビ）・庇い（ガルド）は
> ダメージを経由せずに盤面を変えるので、この列には最初から出ない。
> ここで測れるのは**体験の密度**であって貢献度ではない。

これを載せないと、**ポンがネル・クビ・ガルドを「無価値」と読む**。
プロジェクトは既に「そうではない」と知っている（`pulse.md`）ので、**知っている誤読を画面が作ることになる。**

同じ理由で、**Q0-3・Q0-4 で計数が無かったもの（庇い・付与）は列に `0` を出さず `—`（計数が無い）と出す。**
**`0` と `—` を必ず描き分けること。** 0 と書けば「やっていない」に読まれる。

## 5. 段2 —— 出来事に「書き手」を1フィールド足す（`BattleCore`）

第123期の最大の発見は **「窓口が無い」ではなく「窓口はあるのに誰がやったかが載らない」が過半だった**こと
（(iii) 8体 / 12体）。**新しい窓口を3本作るより、既にある出来事に書き手を足すほうが手数が小さく、効く駒が多い。**

### 5-1. 対象は6つ

| 種類 | 現状 | 足すもの | 救われる駒 |
|---|---|---|---|
| `Move` | `TargetId` のみ | `ActorId` = **移動させた駒** | ササ・バサ・セロ |
| `Revive` | `TargetId` のみ | `ActorId` = 蘇生させた駒 | ヴェル |
| `Heal` | `TargetId` のみ | `ActorId` = 回復させた駒 | ナラ・ノノ・ベニ・シオ |
| `Summon` | `TargetId` のみ | `ActorId` = 呼んだ駒 | ムグ（胞子）ほか |
| `Highlight` | `Text` のみ | `ActorId` = 見せ場の主 | 覚醒・破裂の演出全般 |
| `StatusGain`（`Dull` 経由） | `writer` が null | `writer` を通す | ネル・ウツ |

### 5-2. 実装の形（**盤面に触れないための制約**）

- 窓口（`Heal` / `Revive` / `Summon` / `SwapSlots` / `Dull`）に **末尾の省略可能引数** `UnitState? by = null` を足す。
  **既存の呼び出しは1つも壊れない。** その上で Q0-6 が列挙した呼び出し元を**全件**、原因の駒を渡すように直す
- **`Emit` の中身と引数の受け渡しだけ。** 分岐・乱数（`Roll` / `PickOne`）・順序・計数（`TallyOf` / `NoteCarry`）には一切触らない
- `HighlightOnce` は既に `UnitState u` を受け取っているので、**`Log` へ落とさず `u` を持ったまま `Emit` する経路**を足す。
  **`Log(kind: Highlight)` を `u` 無しで呼んでいる箇所が残るなら `ActorId` は null のままでよい**（そこは無理に埋めない）
- **`Emit` は `verbose` のときだけ動く**という現在の性質を変えない

### 5-3. 書き手が居ない経路の扱い（P3）

Q0-7 が名指しする engine 由来の移動（庇い・突き飛ばし・後退）には原因の駒が居ない。
**null のままにする。** 無理に「動いた本人」を入れないこと——**それは書き手ではないので、線を引くと嘘になる。**

**null のまま残った件数と割合を推奨12戦で数え、報告書に出す**（P3 の判定）。
`DemoApp` 側は **`ActorId` が null の `Move` を「原因不明の移動」として描き分ける**（線を引かない・別色にする等）。

### 5-4. 段2 の終わりにやること

- `compare` 305 セルの 0 件差分（P0）——**段2 で最も重要な検算**
- `docs/` の全再生成で差分なし（段0 の後なので `rules.md` も含めて 0 のはず）
- **ここで一度コミットする**（段3 と混ぜない）
