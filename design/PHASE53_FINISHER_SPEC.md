## 0. この期の主題

**標（`Marked`）の読み手を増やす。** 第52期で書き手が3枚になった。

| 役 | 駒 | 誰に付けるか | 発火 |
|---|---|---|---|
| 書き手 | ヒサ（囃し立て） | 隣接する最大HPの**味方** | 開戦時1回 |
| 書き手 | ソラ（逸らし・第50期） | 自分＋**敵**（最高HP） | 毎ターン |
| 書き手 | カリ（駆り立て・第52期） | 隣接する最高攻撃力の**味方** | 毎ターン |
| **読み手** | **ザン（仇討ち）だけ** | 標を持つ**味方**が殴られたとき割り込む | ターン外 |

**書き手3・読み手1。** これは第42期の弱体（供給4・読み手1）と同じ形で、
あのときは読み手を足して軸として立った。第47期のアーマー（書き手2・読み手0）も同じ。
**供給が厚くなった直後に読み手を足すのは、2回とも当たっている。**

### 空白は「敵の標」の側

**駒で敵の標を読むものは0枚である。**

- ザンが読むのは**味方**の標（`OnAllyDamaged` + `ally.Counter(Marked)`）
- engine は両陣営を読む（`MarkPullPercent`）が、これは駒ではない
- 第50期でソラが**敵に標を付けられるようになった**のに、それを読む駒がいない

そして第50期の実測で、標には特権的な性質があると判明している。

> **標だけが「前列が生きている限り後列は狙われない」を破る。** 標の段は pool ではなく foes から選ぶ

つまり**敵の標＝焦点**であり、**列の壁を無視して届く経路**である。
第50期は撃破順で 詠唱兵 −3.94T（撃破率 49.5 → 100%）を出している。
**その焦点を使い切る駒が存在しない。**

### ザンとの差別化（第51期の一般則から）

第51期で「同じ窓口を通る4本でも代金が3倍違う。**効いているのは窓口ではなく手番の持ち方**」
と確定した。粛（第二波）の下では、ターン外に動く駒は封じられる。

| | ザン | 止め（この期） |
|---|---|---|
| 読む標 | **味方**の標 | **敵**の標 |
| 手番 | **ターン外**（`ctx.CanActOutOfTurn` を通る）→ **粛に封じられる** | **ターン内**（通常攻撃）→ **粛の非対象** |

**同じ通貨を、逆の陣営で、逆の手番の持ち方で読む。** 傷軸で維持攻・消費・維持防が
波ごとに別の順位を作ったのと同じ形になる。

## 1. この期から追加する作法（第52期の発見）

### 作法: 配置探索が「代金だけ」を消していないか確認する

第49期に足した作法は「採用した席で**発火回数が 0 になっていない**こと」だった。
第52期でその上位版が必要と分かった。

> 「機構を 0 にする席」と「代金を 0 にする席」は別物。
> 同じ機構のまま席だけ変えると代金が **−12.5 → +36.8pt** と符号ごと入れ替わる

**発火していても、その効果が働かない席を配置探索は選ぶ。**
標は「もともと前列にいる駒に付けてもほぼ無料」なので、探索は自然にそこへ寄る。

**受け入れ基準に「機構の各項の寄与が 0 になっていないこと」を足す**（§6-4）。
発火回数だけでなく、**代金側の項も別々に測ること。**

### 継続する作法（第45〜52期）

- **新しい駒は `CompareBuilds()` に最低2行で入れる**
- **配置の採否閾値は 5.0pt**。`reseat` の1位を採否の根拠にしない
- **陽性対照は同数値・特性なしの素体**（ノブを 0 にする形は使わない）
- **ノブは Phase 0 と予測のあとに確定する。**
  第52期で基準が固まった——**そのノブが動かす量が1本か2本か。**
  2本動かして符号が逆なら打ち消して空振りする（第50期の (c) 型）

## 3. 実装

### 3-1. 特性 `TraitId.Finisher`（止め）

```
Finisher,    // 止め: 誰かが指を差した敵に必ず食らいつき、倍の力で仕留める。
             // 仕留めると指差しは消える（供給と消費のサイクル。差されなければただの雑魚）
```

**プラス・マイナスのどちらのブロックにも入れない。**

#### 対象の強制

自分の手番で攻撃するとき、**標（`Marked`）を持つ生存中の敵がいれば、必ずそれを狙う。**

- 複数いる場合は決定的に選ぶ——**現在HPが最も高い1体**（同値のみ `PickOne`）
- 標を持つ敵がいなければ**通常どおりの対象選択**に戻る（攻撃自体はできる）
- **既存の対象強制の窓口（ノミの執着・シガの責め苦）と同じ実装を使うこと**（Phase 0-3）

#### 倍率

標を持つ敵を攻撃するとき、攻撃力を `Multiplier` 倍にする。

- `ModifyAttack` ではなく**攻撃の解決時に適用する**（対象が標を持つかどうかで変わるため）。
  既存に同型があれば踏襲すること
- 標を持たない敵を殴るときは**素の攻撃力**（この駒のマイナス側）

#### 消費

標を持つ敵を攻撃した後、**その敵の `Marked` を 0 にする。**

- **これがこの駒の代金であり、供給とのサイクルを作る。**
  ソラが毎ターン1体に付け、止めが毎ターン1体から剥がす。**1ターン1回の制約が自然に立つ**
- **標を消すのはソラに次いで2つ目の経路**（Phase 0-1）。
  ソラは味方から外し、この駒は敵から外す
- 消すことで **engine の `MarkPullPercent` も切れる**ので、
  **味方全体の集中砲火を自分が終わらせてしまう**——
  これが「倍率」の見返りに対する構造的な代金になる

#### マイナスに特別な実装は不要

- **標を持つ敵がいなければただの通常攻撃**（条件の供給が他人）
- **標を消してしまうので、味方の集中砲火を自分で止める**
- 対象を選べないので、**倒しきれない相手に食らいつく**ことがある

**代金を軽くする細工をしないこと。** 消費を止めたり、標が無いときも倍率を乗せたりすると、
供給とのサイクルが消えて単なる高打点の駒になる。

### 3-2. 強度のノブ —— **候補を2つ挙げる。Phase 0 の後に選ぶこと**

| 候補 | 定義 | 動かす量 |
|---|---|---|
| **A: `Multiplier`** | 標を持つ敵への倍率（掃引 2 / 3 / 4） | **打点だけ**。標の消費量は変わらない → **1本** |
| B: 標を消すか | 消費の有無（対照として 有/無） | 供給サイクル。**掃引ではなく2値**なので対照 |

**指示書の推奨は A。** 第52期で「ノブが動かす量が1本なら掃引は素直に開く」と確定しており、
`Multiplier` は打点だけを動かすので条件を満たす。

**B は対照として必ず1本測ること**——消費が無ければこの駒は
「標を持つ敵を倍で殴り続けるだけ」になる。**サイクルが代金として働いているかの判定**に要る。

```
public readonly record struct FinisherRule(int Multiplier)
{
    public static FinisherRule Default => new(2);
}
```

`BattleEngine.Run` の引数に足す（既存の各 `Rule` と同型）。**static のノブは置かない**。

### 3-3. 駒 `UnitCatalog.Tome`（止めのトメ）

```
Id = "tome", Name = "止めのトメ", MaxHp = 58, Attack = 12, Speed = 6,
Traits = { TraitId.Finisher }, Pattern = AttackPattern.Single
PlusText  = "標的にされた敵を必ず狙い、倍の力で殴る（列の壁を越えて届く）"
MinusText = "殴ると標的が外れるので味方の集中砲火が止まる。誰も指差さなければただの雑魚"
Flavor    = "誰かが指を差した相手にしか本気になれない。差されれば、確実に仕留める。"
```

数値は探索段階の初期値。**掃引の対象はノブ1つだけ**で、HP・攻・速は振らない。

### 3-4. compare への追加 —— **2行**

```
("止め (トメ×ソラ)", ...)      ← 供給と消費のサイクルが閉じる台
("止め改 (トメ×◯)", ...)       ← 供給を厚くした台、または供給が細い台
```

- **ソラは必須。** 敵に標を付けられるのはソラだけなので、
  ソラ抜きではこの駒は素の攻12として振る舞う（Phase 0-5）
- **2行目の設計は Phase 0-5 の結果で決める。**
  ソラの `TargetCount` を上げた台にするか、供給が細い側を見る台にするか。
  **判断と理由を報告書に書くこと**
- **予算壁に注意。** ソラは攻6 の払い出しで、トメは攻12。土台は打点を持つ駒で組む
- 配置は §1 の作法で決める。**採用した席で発火回数も代金も 0 になっていないことを確認する**

**既存54行は1つも触らない。**

## 4. 診断モード `finisher`

`BattleSim` に追加する。**出力は `docs/` に置かない**。
`CompareBuilds()` / `Stages` / `Columns` を触らないこと。

| 列 | 中身 |
|---|---|
| 発火 | 標を持つ敵を殴った回数/戦。**0 になっていないこと** |
| 空振り | 標を持つ敵がいなくて通常攻撃になった回数/戦 |
| 対象 | **誰を殴ったか**の内訳（敵の名前ごと） |
| **列越え** | **標が無ければ狙えなかった敵**（後列・中央）を殴った回数/戦 |
| 消費 | 標を消した回数/戦 |
| **止めた砲火** | **標を消したことで味方の他の駒がその敵を狙わなくなった回数**（推定） |
| 供給 | ソラが敵に標を付けた回数/戦（供給側の計数） |
| 遊休 | 標が付いてから止めが殴るまでの平均ターン数 |
| 撃破 | **標を持つ敵を実際に倒した回数**/戦 |

**「発火」と「列越え」を分けること。** 第50期で「標だけが前列の壁を無視する」と判明した以上、
**この駒の価値は倍率ではなく列越えにある可能性がある**。
第42期以降、生成量ではなく効いた量で判断するのが標準になっている。

**「止めた砲火」が代金の実体。** 標を消すと `MarkPullPercent` が切れるので、
味方全体の集中が終わる。**これが測れないと §6-7 の判定ができない。**

**陽性対照を3本置く**:
1. 同数値・特性なしの素体（**ノブを 0 にする形は使わない**）
2. `FinisherRule` の候補B「標を消さない」版（サイクルの分離）
3. トメを外した同じ編成

**発火しなかったことは盤面の値に痕跡を残さない**ので、ログか `Events` から数えること。

## 7. 実装上の注意（既知の落とし穴）

1. **対象強制の窓口を新設しない**（Phase 0-3）。
   ノミの執着・シガの責め苦と同じ実装を踏襲する
2. **標を消すのは敵側だけ。** 味方の標には触らない（ソラの領分）
3. **倍率は攻撃の解決時に適用する。** `ModifyAttack` は対象を知らないので、
   対象が標を持つかどうかで分岐できない可能性がある。**実装方法を報告書に書くこと**
4. **供給がソラ1枚しかない。** 第47期のウロ（アーマーの供給が砕け1枚）と同じ形なので、
   **ソラ抜きの版が素の攻12として振る舞うことを確認する**
5. **標を消すと `MarkPullPercent` が切れる。** これは仕様（代金）だが、
   **ソラの効果を自分で打ち消している**ことになる。
   ソラ単独の版と、ソラ＋トメの版を比べて、**トメが入ることでソラの価値が下がっていないか**を見る。
   下がっているなら「同じ通貨の供給者と消費者が同居できない」という
   第46期（オゴとウツ）と同型の制約になる
6. **乱数列がずれる。** `PickOne` は候補2個以上で `Roll` を消費する。
   帰属は**素体との対照**で取る
7. **長時間ジョブはフォアグラウンドで1ツール呼び出し内に収める。** 背景に回さない
