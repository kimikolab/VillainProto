## 3. 実装

### 3-1. 窓口を1つも新設していない

**3つの効果を、既にある3つの場所に置いた。**

| 効果 | 場所 | 理由 |
|---|---|---|
| 対象の強制 | `SelectTargetChain` の**標の段**（`BattleEngine.cs:1295`） | 候補集合が `foes`（列を無視）でなければ**列越えが構造的に消える** |
| 倍率 | `PerformAttack` が `atk` を作った直後 | `Trait.ModifyAttack` は**対象を受け取らない**ので分岐できない |
| 消費 | `FinisherTrait.OnAfterAttack`（**駒側**） | 駒ごとのフックで書ける唯一の1つ |

**対象の強制を執着・断ちと同じ窓口（`pool` から選ぶ直前）に置かなかったのは意図的。**
指示書 §7-1 は「既存実装をそのまま踏襲する」と書いているが、
**`pool` は前列が生きている限り前列しか含まない**ので、そこに置くとこの期の主眼
（列越え＝標だけが列の壁を破る性質）が測れない。**標の段も `SelectTargetChain` の中にある
既存の窓口**なので、engine に新しい規則も新しいメソッドも足していない。

実装は「標の段を 100%・決定的にする」だけ:

```csharp
bool finisher = attacker.HasTrait(TraitId.Finisher);
UnitState? marked = finisher
    ? FinisherTrait.Preferred(this, foes)          // 現在HP最大・同値のみ PickOne
    : PickOne(foes.Where(f => f.Counter(StatusKeys.Marked) > 0).ToList());
if (marked is not null && (finisher || (marked != target && Roll(100) < MarkPullPercent)))
{
    if (marked == target) return marked;   // 差し替えていないので鎖の計数は動かさない
    ...
}
```

**止めのときは `marked == target` でも返す**（庇い・後備え・殉教を飛び越す）。
「たまたま無作為の主目標が標持ちだった」ときだけ介入を許すのは非対称になるため。

### 3-2. ノブの選択 —— **A（`Multiplier`）を採った**

指示書 §3-2 の推奨どおり。第52期の基準（**ノブが動かす量を1本にする**）を満たす:
`Multiplier` は打点だけを動かし、**標の消費量も列越えの有無も倍率に依存しない。**
候補B（標を消すか）は掃引ではなく2値なので、**`FinisherRule.Consume` として対照に回した**
（`DivertRule.SelfMark` / `GoadRule.Mark` と同じ扱い）。

```csharp
public readonly record struct FinisherRule(int Multiplier, bool Consume)
{
    public FinisherRule(int multiplier) : this(multiplier, true) { }
    public static FinisherRule Default => new(2, true);
}
```

`BattleEngine.Run` に引数で渡す。**static のノブは置いていない。**

### 3-4. compare の2行 —— **指示書の案から変えた。理由を書く**

指示書 §3-4 は2行目を「ソラの `TargetCount` を上げた台」か「供給が細い台」と指定していた。
**前者は不可能**（`TargetCount` は `DivertRule` の全体ノブで、行ごとに変えられない）。
後者を採ったうえで、**もう1本の軸を重ねた**。

> **標は単体攻撃にしか効かない**（engine の鎖が `pattern != Single` を手前で返す）。
> つまり**味方が薙ぎばかりの台では、標を消しても誰も何も失わない**
> ——**「止めた砲火」が構造的にゼロになる台が作れる。**

これが受け入れ基準7（代金の実体）を割る唯一の設計なので、そちらを優先した。

| 行 | メンバー | 何が違うか |
|---|---|---|
| `止め (トメ×ソラ)` | エグ / ゴルム / ノミ / **トメ** / ソラ | **5枚全員が単体攻撃**。ゴルムが後列を覆うので**供給が厚い** |
| `止め改 (トメ×薙ぎ)` | **トメ** / ハギ / ソラ / ドルガ / ボルグ | **単体はトメとソラだけ**（他3枚は薙ぎ）。肩代わりが無く**供給が細い** |

どちらも**既存行とメンバーが1枚しか違わない**という第21期 `swap` の作法を守っている
（`止め` は `逸らし改 (ソラ×ノミ)` のドルガをトメに差し替えただけ）。

**配置。** `止め` は仮置き（トメ後1）が粗探索 13位 / 120通りで、`confirm`（seed 200..599）の
上位5通りとの差が **+1.3〜−0.5pt** ——採否閾値 5.0pt（第46期）に届かないので**動かさない**。
`止め改` は仮置き（トメ後1）が粗探索 26位で上位5通りが全部 **+11.6〜+12.6pt** ——閾値を大きく
超えるので動かした。**採ったのは粗探索 5位**（69.9%・+12.1pt・トメ前1）。
**1位ではなく次数で読む**（第45期の残件D）——上位5のうち4通りが次数2（角）で、
その中で**発火がいちばん多い席**を採った（1位 1.37 / 4位 1.64 / **5位 1.65**）。

**ところが代金は 0 にならなかった。** 薙ぎの台でも 消費なし版は **+5.1pt** 強い。
理由は計数に出ている——**消費なし版では発火が 1.66 → 1.94・列越えが 0.63 → 0.81 と増える。**

> **消費の代金の主要部分は「味方の砲火を止めること」ではなく「自分の供給を自分で食うこと」だった。**
> 標を消せば次の手番に狙う相手が減る。供給はソラ1枚（1体/T）しかないので、
> **消費は味方の焦点を削ると同時に、自分の次の発火を削っている。**

指示書は「止めた砲火が代金の実体」と書いていた（§4・§6-7）。**半分当たっている**
——単体の台では 代金 −7.2pt のうち焦点の効き −27.2pt ぶんが乗っているが、
**薙ぎの台の −5.1pt は全部が自己消費**である。

### 5-3. 遊休は 0.00〜0.04T —— **標は溜まらない**

**標が付いたその手番のうちに使われる。** 供給（ソラの `OnTurnStart`）が
行動順ループの外側で走り、トメが同じターンに殴るため。

> **「供給 → 消費」のサイクルは1ターンの中で閉じている。** 蓄積の機構ではないので、
> 第37期の断ち（傷の在庫）で問題になった「溜まる時間を作らないと溜まらない」の逆
> ——**溜める余地が構造的に無い。** 焦点数が最大4まで増えるのは
> **トメが取りこぼした分**（発火 / 供給 = 83〜90%）だけ。

## 7. 残件

1. **`Multiplier` の全幅が 39.1pt もある。** 数値バランスは第53期の対象外（指示書 §9）だが、
   **既定 2 は「軛の Cap 25 を攻12 ですり抜ける最大値」でもある**（`Cap ÷ 攻 = 2.08`）。
   攻撃力を触るときは倍率の実効上限が動くことに注意。
2. **供給がソラ1枚のまま。** 敵に標を付けられる駒は逸らししかない
   （第47期のウロ＝砕け1枚と同じ形）。**2枚目の供給源を作るかどうかは別に決める。**
3. **`止め (トメ×ソラ)` の第三波が 3.5%。** 渇きの祭司を標にして 1.04 回/戦 殴っているのに
   勝てない（M3 で 47.0% に跳ねる）。**倍率が閾値を跨いでいない**だけの可能性が高いが未確認。
4. **「止めた砲火」の推定は上限寄り。** 「消費したターンに盤上の標が尽きていた味方の単体振り」を
   数えているので、**その振りが実際に標へ引かれたはずかどうか**は見ていない
   （engine の 75% と `p_t` を掛けた期待値ではない）。厳密な代金は対照2 との差で取ってある。
5. **ヒサを `All` から外すかどうか**（指示書 §9）は測っていない。
   標の書き手は3枚・読み手は2枚（ザン・トメ）になったので、判断材料は増えた。
6. **残り枠は 2**（うち1枠はオゴという棄却済みの素材）。
