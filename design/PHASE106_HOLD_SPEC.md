## 1. (T1) 4つ目の通貨

第105期は与ダメージ・回復・状態異常の3通貨で測り、**Q3 の外れ1枚（ヒヨ）は分類の失敗ではなく
「ヒヨの通貨（強化・弱体）が無い」のが原因**だった。

**`AtkBonus` の増減を4つ目の通貨として足す。**

- **`TraitKeyMap` の 11 キーのうち `Whet`（強化）と `Dull`（弱体）に対応する。**
  **キーの定義を新しく作らない。**
- **帰属は `ApplyDamage` の `source` と同じ考え方で、増減を起こした駒に付ける。**
  帰属できない経路（境界での一括消去など）は**「誰のものでもない」に入れる**（第105期と同じ）。
- **`AtkBonus` を動かす経路の全数を Phase 0 で列挙する**
  （分かっているのは 憤怒のムド／号令のガン／縛めのクグ／呪詛官ネル／火選りのヒヨ／
  誹り／驕り／突き返し／分かち／恩顧／怯み。**指示書の一覧を信用せず数え直すこと**
  ——手作りのずれが **8例**）。

> **Q0: 4つ目の通貨を足したうえで、第105期の Q3 が 5/5 になること。**
> **なればこの期の末尾で (G14) を `CLAUDE.md` に書く。ならなければ書かない。**

## 2. (T2) 3つの形（**測る前に固定**）

### 2-1. ムド —— 量で育つのをやめ、回数で育つ

```csharp
public enum RageMode { Amount, Count }
public readonly record struct RageRule(RageMode Mode)
{
    public static RageRule Default => new(RageMode.Amount);   // 現行。測定中はここ
}
```

**`Count` のとき、`RageTrait` は殴られた回数ごとに攻撃力 +3。**

**+3 の根拠（測る前に固定・振らない）**: **ムドの被弾は 7.21 回/戦**（第96期の実測）。
**7.21 × 3 ≒ 21.6** で、**現行の到達点 攻24 とほぼ同じ。**

> **総量を変えず、速度だけを変える。** 変数を1つに絞るため。

- **1発目から +3 なので、序盤から育つ。** 「育つ前に落ちる」への直接の手当て
- **破片との関係は変わらない**——`ApplyDamageCore` は破片で受け切ると
  「何も起きなかった」と扱い**被弾強化も反撃も走らせない**（コードに明記）。**そこは触らない**
- **`ApplyDamage` が呼ばれた回数**で数える。**巻き込み・自傷・毒や燃焼の刻みを含めるかを
  Phase 0 で決めて理由を書く**（**含めないほうが素直**——「殴られた」の絵に合う）

### 2-2. ノノ —— 等価交換をやめる

```csharp
public readonly record struct MenderCostRule(int Percent)
{
    public static MenderCostRule Default => new(100);   // 現行。測定中はここ
}
```

**`Percent = 50` のとき、繕った量の半分だけ自分が減る。**

**根拠**: 第105期で**回復の 90.3% が手番の外**から出ている。
**ノノは手番を丸ごと使って回復する数少ない駒**で、**手番のコストを既に払っている。**
**そのうえ等価の HP まで払うのは二重の代金**である。

> **上限がノノ自身の HP（78）である構造は変わらない。天井が 2 倍になるだけ。**

### 2-3. ササ —— 係数をやめ、事象にする

```csharp
public readonly record struct LooseRule(bool Shove)
{
    public static LooseRule Default => new(false);   // 現行。測定中はここ
}
```

**`Shove = true` のとき、`LooseTrait` は
「被弾したとき、隣接する味方1体を別の席へ弾く」に変わる。被ダメ −35% は残す。**

**フレーバーがそのまま機構になる**——「**誰かの隣に立つことができない。近づかれると錯乱する。**」

- **被弾クロック**（手番外型）。**第105期の「状態異常の 76% が手番の外」に沿う形**
- **自分で条件を作る。** 現行は「隣が空く」を味方の死に頼っていて **73行の会戦で一度も成立しない**
- **移動軸に読み手が1人増える**——軋みのヨミ（**動かされるたび攻撃力が上がり、その場で割り込む**）・
  押し出しのバサ・突き返しのハネ・怯みのシオ
- **弾く先の決め方は Phase 0 で決める。**
  **空きがあればそこ。空きが無いときにどうするか**（何もしない／隣接していない席と入れ替える）を
  決めて理由を書く。**`ctx.PickOne` を使わない**（第89期 (h)）。**席番号で決定的に選ぶ**
- **1ターン1回まで。** 被弾のたびに動くと盤面が読めなくなる

### 2-4. (T3) ハリは触らない

**第85期に接続を試して救えなかった**（律速は接続の質ではなく**振り回数 2.15 回/戦**）。

- **第104期の刻み手の再行動が入った後で、ハリの発火が変わったか**

## 4. Phase 0（**戦闘は (T1) の計数取得のみ**）

1. **`AtkBonus` を動かす経路の全数**（§1）。**`derive scan`（第94期）の観測で照合する。手で書かない**
2. **`RageTrait` の現行の式**（`dmg / 2`・最低1）と、**`ApplyDamage` が呼ばれる経路の全数**（§2-1）
3. **`MenderTrait` の現行の式**（`Math.Min(Amount + PerWound * w, self.Hp - 1)`・`self.Hp -= amount`）。
   **半分にするのは「引く量」であって「癒す量」ではない**ことを明示する
4. **`LooseTrait` の現行の実装**と、**弾く先の決め方**（§2-3）
5. **ハリを含む行の名前**（§2-4）
6. **`SwapSlots` の既存の呼び出し口**（セロの後退で使っている）。**1つも挙動を変えないこと**

### 予測（**測る前に書く。駒を数えて書くこと**）

- **ムドは上がるが小さい。** 到達点が同じで速度だけ変わるので、**決着が短い波ほど効く。**
  **第2波（決着が最も短い）で最も伸びるはず。**
- **ノノは上がる。** ただし**ボルグと同席する行（`燃焼 (ボルグ×ホタ)` ほか）でだけ大きい**——
  巻き込みの後始末で予算を使い切っていたのが緩む。
- **ササは勝率が動かない可能性が高い。** 被ダメ −35% を残したまま事象を足すだけなので、
  **上がるとすれば移動軸と同席する行だけ。** **Q3 は勝率で判定しない。**
- **ヨミが最も得をする。** `Displaced` は**動かされるたびに攻撃力が上がり、その場で割り込む**ので、
  **ササの弾きが毎ターンの餌になる。**
- **拒否権は立たない。** 3つとも既存の駒の中で閉じており、engine の規則を変えない。
