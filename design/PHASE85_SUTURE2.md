## 1. 何を作ったか

- `SutureSide { Foe, Both }` / `SutureRule(Side)`・`SpillWoundRule(Enabled)`（`Traits.cs`・`ThornRule` の直後）。
  `BattleContext.Suture` / `SpillWound` と `BattleEngine.Run` の両 overload に省略可能引数で通す。**既定はどちらも現行。**
- `SutureTrait.OnAfterAttack`: 糸口の候補を `Both` のとき「殴った相手」と「傷がいちばん深い味方（self を除く）」に広げ、
  **深いほうを取る・同数なら敵側**。タイブレークだけ `PickOne`（候補 0・1 個では `Roll` を消費しない）。塞ぎは**糸を通したほう**の傷を 1 つ引く。
  **`SeverTrait.Prefers`（標的選択）と `ThornsTrait` の巻き込みループ（`gained`）は1文字も触っていない。**
- 巻き込み則: `ApplyDamage` の **HP を引いた後・死亡判定の後**に「`isFriendlyFire` かつ `source` が同陣営 かつ `!burnTick` かつ `!relayed` かつ対象が生存」で傷 1。
  **`relayed` は巨躯・分かちの中継の2段に付けた札**（Phase 0-1 の判断＝中継は書き手ではない。§6-1）。
- 計数（`UnitTally`・盤面には一切影響しない）: `SutureFoe` / `SutureAlly` / `SutureDry` / `SutureHealed` / `SpillWoundsWritten` /
  `WoundsAtDeath` / `WoundsAtEnd`。`BattleEvent.Relayed`（Damage の中継の段の札。verbose のみ）。
- 診断 `suture2`（`phase0` / `run <w> [skip] [take]` / `tables <w0> <w1> <w2>` / `nata` / `check`）。器具は第84期 `thorn` の写し（A ＝ ハリ固定・B ＝ 残り 50 体・
  K 64 × 2 系列・弱い波・第2〜5波・seed 0..7）。**既存の診断は1文字も書き換えていない。** 計数は `SuStat`（`Program.cs` 末尾）。
- `SutureTrait` の doc に両側読みの段落を足した。**「ナタとは同居させない」の段落は消していない**（Q4 が動かなかったので訂正しない。追記だけ）。

### 2-2. 窓口の全数（指示書の前提の訂正）

- **`isFriendlyFire: true` の呼び出し口は 10**（指示書は「6箇所」）——特性側の刃 6（余波・生贄・吸い・破裂・棘の巻き込み・置き去りの削り）に、
  **深追いの反動（ハギ・`source` null）** と **engine の中継 3**（巨躯・分かち・転嫁の代金）が加わる。
- **中継は外す。** 転嫁の代金と深追いの反動は `source` が `null` なので「`source` が同陣営」で外れるが、
  **巨躯・分かちの中継は元の刃が味方（棘の巻き込み・吸い）だと `source` も同陣営になる**——指示書の「`source` は敵の攻撃者」は
  元の攻撃者が敵のときだけ正しい。最初の実装は札を持たず、カドの巻き込みが巨躯に中継された段を二重に数えて
  **自己検査 (c) が 2,962 対 3,104 で落ちた**。中継の2段に札（`relayed`）を付けて直した（§6-1）。
- **`StatusKeys.Wound` を読む窓口**: 第85期の追加を除くと**味方の傷を読む箇所は 0**（第84期・第68期・第49期と整合）。
  追加したのは `SutureTrait` の両側読み 3 行と、自己検査 (j) の計数 2 行（誰も読んで分岐しない）。
- **`compare` の行数**: ハリを含む行 **1**（`刻み×縫い (ノミ×ハリ)`）／カド 11／傷 8。**ハリ ∩ カド = 0 行**（W1 は原理的に `compare` を動かさない）。
  **W2 で動くはずの行 = 1**（`刻み×縫い`・ゴルム同席）——実測もこの 1 行 3 セルだけが動いた。
- 過去に同じ機構を測った期は無い。第84期 V2（味方にも傷を書いたが読み手 0）がこの期の供給側の陰性対照。

## 4. 読み

**4-1. 律速はハリの振り回数だった。** 紙の式 `min(振り, 供給)` で振り（2.15）が供給（6.48）を下回り、実測はその下限にぴたり乗った。
第84期は「傷1つの単価が運ぶ出来事に対して小さい」で切れたが、この期は単価の比を 60% まで上げても（巻き込み 5 点に傷 1 ＝ 3 点）
**読む側の手番が無い**。**供給側の性質を直しても、読み手の手番の数は変わらない**——第75期「条件が何に接続しているかは値段を決めない」の読み手側の版。

**4-2. 天井と床の両側から切られる。** 勝てる第3〜5波（素体でも 96〜100%）は 2.8〜3.7T で決着し、傷が積まれてから読める手番が 1〜2 回しか無い。
負ける第2波はカドが粛で止まり、ハリが 69% 死ぬ。**中間帯の波がこの組に無い**（第24期「天井・床のセルでは誰に注入しても 0 に潰れる」）。

**4-3. 密度が勝つ。** W2 の Δ相乗 は供給の周期と単調——毎ターン・全味方（ゴルム +5.25）＞ 攻撃ごと・隣接（ボルグ +2.54）＞
毎ターン・遅い味方（ナラ +0.63）＞ 死亡時（ゾト +0.17）＞ 開戦時1回（リィカ −0.90）。
**リィカの負は t=0 の在庫が「読まれる前に決着」の典型**——66.7% は読まれず（第2〜5波の未読 84%）、生贄の HP だけが残る。
第67・68期「時間に分布している量」の読み手側の帰結で、**分布していない供給（開戦1回・死亡時）は読み手が何枚いても値段にならない。**

**4-4. 理想台では別の答えが出る。** `刻み×縫い (ノミ×ハリ)` は W2 で第四波 47.0 → 88.5%——この行はゴルムが前列で毎ターン 4 枚から吸い、
ハリが後列で 6〜7T 振り続ける（軛の第四波は決着が長い）。**噛み合いが保証されていて決着が長い行では、巻き込み則は大きい**。
ドラフト台の 6枚平均が線に届かないのは、**書き手 6 枚のうち 4 枚が「密度が薄い」か「決着より遅い」側にいる**からで、
ゴルムとボルグだけを見れば採用線を越える。**§5 の分岐に「Q1b が 2 枚で通った」は無いので採らない。**

**4-5. 味方側の傷の代金は無かった。** 味方に傷が載っても読み手がハリ以外にいないので、W1 の y10（ハリ素体）は 24,808 セルで W0 と一致（(b)）。
「載ったが誰も読まない」は第84期 V2 の再確認で、**傷という通貨は味方側でも敵側でも、読み手が持つ手番の数だけしか値段にならない。**

## 6. 器具の記録

**6-1. 「`source` が同陣営」だけでは中継が外れない。** 巨躯・分かちの中継は `ApplyDamage(wall, blocked, source, isFriendlyFire: true)` で
`source` が**元の攻撃者**——元の刃が味方（棘の巻き込み・吸い）なら同陣営になる。**中継を外すには段に札が要る**（`relayed`。
`burnTick` と同じ計数専用の札で、盤面の判断には使わない）。指示書の「巨躯・分かちの `source` は敵の攻撃者」は敵の刃のときだけ正しい。
自己検査 (c)（W1 の棘の書き込み ＝ W2 の巻き込み則の書き込み）がこれを 2,962 対 3,104 で捕まえた。

**6-2. 2×2 の TSV の添字と指示書の y の記法は逆。** `pairs2` 以来の TSV は `[y11, A素体, B素体, y00]` で、第84期の指示書は A ＝ カドだったので
「y01（カド素体）」＝ 添字 1 だった。この期は A ＝ ハリなので「y01（ハリ本物・カド素体）」＝ **添字 2**。最初の実装は添字を第84期のまま写して
(a)(b) がどちらも落ちた（(a) 3.1pt・(b) 59.4pt）。**器具を写すときは、A・B の割り当てが変わると自己検査の添字が変わることを確かめる。**

**6-3. 自己検査 (f) の 5 件の差。** 味方の刃の着弾（`Events` の `Damage` で `FriendlyFire` かつ `!Relayed` かつ行為者が味方かつ `HpAfter > 0`）30,630 に対し
巻き込み則の書き込み 30,635。差 5 件（0.02%）の原因は特定していない（召喚枠の陣営の写し取りの縁を疑っている）。比が 1.00 から外れていないので
「打点に比例していない」の判定には影響しないが、**次に `Events` で数えるときは `Summon` の陣営の扱いを先に確かめること。**

**6-4. 紙のスループットは「深さ」を式に持たないと線を挟む。** 指示書の式は `読める回数 × 平均の傷の深さ × 3` で深さが未定だった。
下限（深さ 1）と上限（供給が全部読まれる）で挟んで出し、実測は下限に乗った。**次からは下限を紙の値とする**（供給は読まれる前に決着に消える側に倒れる）。

**6-5. ログ本文は先頭の空白を削って保存される**（`BattleContext.Log` が `Trim` して `Indent` に分ける）。`StartsWith("    …")` は当たらない。
