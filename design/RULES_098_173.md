# 一般則 R098〜R173

**`CLAUDE.md`「指示書を書くときに当てる一般則」の本文**（第160期に索引化して `design/` へ移した。**本文は1文字も変えていない**）。
**索引は `CLAUDE.md`。** ID は永続で、**欠番になっても再利用しない**。
`#### R0nn の再発` は同じ則を別の期が言い直した段落、`#### R0nn の続き` は同じ則の続きの段落（どちらも ID を新しく作らない）。

### R098 — 「指標が緩い」の出どころを、実装の形から推測しない

**「指標が緩い」の出どころを、実装の形から推測しない**（第129期・規約 (G11) を<u>欠陥の診断</u>に当てる）。
`完全勝利` の判定式（`PlayerSurvivors >= 出撃数`）は**原理的には**湧いた駒（胞子・餌）で埋められるが、
**実測では 2,115 件中 0 件**だった——胞子が湧くのはムグが落ちた戦で、その戦は他の駒も一緒に落ちている。
**緩さの実体は分母**（勝った試行だけを見る。6.7% 対 4.3%）。
**しかも数え方を1つ間違えると、その実測すら出ない**——`PlayerSurvivors > 出撃数` で数えると 0 件になり
「召喚体は数えられていない」という誤った結論が出る（あの式は「欠けた数 ≦ 湧いた数」まで要求するので、
**1枚欠けて1体湧いた戦を数え落とす**）。正しくは `PlayerSurvivors ≠ 出撃数 − 欠けた数` で 348 件。
第121期「判定の線は計数の<u>名前</u>ではなく実装が数えている出来事に当てる」の**分子の側の版。**

### R099 — 延命は時間を買うが、発火は時間に比例しない。比例の崩れ方が「鍵の供給」の種類と一致する

**延命は時間を買うが、発火は時間に比例しない。比例の崩れ方が「鍵の供給」の種類と一致する**（第129期）。
代金ゼロの器具（`TraitId.Undying`）で測った **`密度` = 発火 ÷ 生存T** の比:

    自前（ソラ・毎ターン無条件）        ×0.95   ← 買った時間がそのまま仕事になる
    自分の被弾（セロ）                  ×0.74
    撃破（ハギ）                        ×0.72
    味方の被弾（ガルド）                ×0.65
    標（トメ・書き手1枚・殴ると外れる） ×0.55   ← 時間を 1.9 倍買っても発火は +5%

### R100 — 「守れば起動する」と「守っても働きが薄まる」は、発火回数の増減だけでは区別が付かない

**「守れば起動する」と「守っても働きが薄まる」は、発火回数の増減だけでは区別が付かない**
——5 駒とも「発火と与ダメの両方が増える」線は通る。第114期「強化の価値は積んだ量ではなく
受け手が振った回数で決まる」の**時間側の版**で、**買った時間が仕事に変わる率が鍵の供給で決まっている。**
**耐久を足す前に、その駒の鍵が足りているかを測ること**——トメに要るのは HP ではなく標の供給である。

### R101 — 密度が上がる駒もある —— 鍵が戦闘後半に偏る機構

**密度が上がる駒もある —— 鍵が戦闘後半に偏る機構**（第129期）。追い打ち（ハギ）だけが、
**上の延命台ではなく `MaxHp` の掃引（62 → 92）で** **×1.10** と逆を向く
（**同じハギが延命台では ×0.72**。器具で符号が割れる——第131期）。
鍵が「味方の撃破」で、**撃破は敵が削れた戦闘後半に集まる**ので、
早く落ちる駒は**鍵が配られる時間帯に居合わせない。**
**「鍵の供給が時間軸のどこに偏っているか」を見ると、延命の値段が駒ごとに違う理由が出る。**

### R102 — 「殺さない」器具は、出口に置くだけでは足りない

**「殺さない」器具は、出口に置くだけでは足りない**（第129期。第126期の続き）。
HP が 1 に張り付くと以降の被弾が `amount <= 0` で**早期に返り、`OnDamaged` が呼ばれなくなる**
——**被弾そのものが起動条件の駒（庇い・被弾強化・棘）では、延命が機構を止める**（測りたいものの逆を測る）。
`UndyingTrait` は**ターン頭に満タンへ戻す**のを対にして解いた。
**戻しは `ctx.Heal` を通さない**——窓口を通すと渇きで止まり `Stoic` に届かず、
**いちばん測りたい2枚にだけ効かない器具**になる（回復ではなく台の初期化）。

### R103 — `MaxHp` を上げる調整は、その駒自身が `MaxHp` を読んでいないかを先に見る

**`MaxHp` を上げる調整は、その駒自身が `MaxHp` を読んでいないかを先に見る**（第129期）。
逃亡兵セロの後退は `Hp * 3 > MaxHp * 2` なので、**HP を上げると後退の閾値も一緒に上がって起動が遅れる**
——実測で `MaxHp` 62 → 72 のとき**発火が 2.08 → 1.99 と下がる**（密度も 0.365 → 0.337）。
**HP は素直な耐久のノブではない。** `Traits.cs` の `MaxHp` の読みは 10 件で、
**他人の `MaxHp` を読むのは囃し立て（ヒサ）の1箇所だけ**、残りは自分の割合を見る型である。

### R104 — 「買った時間」を量の逆算に使えないことがある

**「買った時間」を量の逆算に使えないことがある**（第129期・規約 (G11) の系）。
第126期の線（+1.0T）はハギには**届かない**——`MaxHp` を +30 しても +0.52T。
**他の期の数値を判定の線にするときは、その線がこの器具で到達可能かを先に見ること**（第118期 Q1 と同じ形）。
このときは時間ではなく**密度と代金**（拒否権・情報セル）で量を選んだ。

### R105 — `derive rules` の索引は、入れ子のクラス名まで拾って本文ごと結ぶ

**`derive rules` の索引は、入れ子のクラス名まで拾って本文ごと結ぶ**（第129期・第121期の裏返し）。
`(?:static|sealed) class (\w+)` はメソッドの中の `sealed class Acc` も拾い、
`"Acc."` が現れたモードに**そのファイル全体**を結び付ける——実測で `docs/rules.md` の `利用者` 列に
**無関係な `pairs` が付いた**（クラス名に接頭辞を付けたら消えた）。
第121期は「引けているのに結ばれない」だったが、**今度は結ばれ過ぎる。**
**診断の入れ子クラスには接頭辞を付けること。** なお `利用者` 列は
「その診断がその規則を使っている」を意味しない（本文まるごとで結ぶので、
`DivertFires` を読むだけの診断が `DivertRule` の利用者として出る）——**既定の列だけが (G8) の必須3 である。**

### R106 — 上限を持つ波に固定量の継続ダメージを持ち込むと、上限の外側だけが素通りで効く

**上限を持つ波に固定量の継続ダメージを持ち込むと、上限の外側だけが素通りで効く**（第130期）。
熾のホタに「燃えている間、攻撃するたび隣接する味方にも火が移る」を足したら、
いちばん落ちたのが**第四波（軛・1発 25 上限）で −79.0pt**、次が第三波（渇き）で −56.0pt。
燃焼は `BurnRules.Damage` = 6 の**固定量**で `burnTick` として入るので**軛に一度も触れない**
——**敵の一撃が 25 に切られる波では、味方が自分に足した 6/T だけが上限の外で効く。**
第三波は渇きなので**回復で買い戻せない。**
破片（`Armor`）が上限の外側で効くのと**同じ位置**にいるが、**符号が逆で自分に落ちる。**
**味方に継続ダメージを配る機構は、第四波で必ず重くなる**——第25期の軛の裏返し。

### R107 — 主判定に使う量は「誰の量か」まで決める

**主判定に使う量は「誰の量か」まで決める**（第130期・第121期の主判定側の版）。
「燃焼していたターンの割合が 90% を超えたら点きっぱなし」という線を引いたが、
**ホタは自分に配らない**（`ally == self` の除外）ので**ホタの燃焼率は機構に対して定数**
——実測で **69.3% → 69.3%** と小数第1位まで動かない。
動いたのは配られた側（ボルグ **0.0% → 11.2%**）だけで、**実質の主判定はボルグ1枚**だった。
**量の名前は正しいのに、誰の量かを決めていなかった。**

### R108 — 穴が空いていることと、埋めて得になることは別

**穴が空いていることと、埋めて得になることは別**（第130期）。
`CinderTrait` は `ally == self` で自分を除外するので**供給源のボルグだけが燃えず、
火選りのヒヨの強化対象になれない**——この穴は埋まった（**0 → 10,124**）が、**埋めた先が悪かった。**
ボルグは**巻き込みが本体で攻撃力への依存が薄い**（第58/60期）うえ、
**乗算を持つホタ（燃焼中ちょうど4倍）への配分が 8,484 → 7,056（−17%）と減る**
——実効では**「4倍の受け手から、倍率の無い受け手へ 1,428 点を移した」**ことになる。
**通貨の穴を埋める案は、埋めた先の倍率を先に見ること。**

### R109 — 走査は `class` だけを見てはいけない

**走査は `class` だけを見てはいけない**（第130期・第121/129期に続く3例目）。
直前の `class` 宣言だけで帰属を引くと、**`record struct` である `SoakRule` の中の `Kinds` が
手前の `ImmobileTrait` に結び付き、「棘鎧のカドが燃焼を読む」という嘘の行が出た。**
**症状は「走査が空」ではなく「静かに違う表を作る」**（第123期）ので、
第117期の「引けなかったときの分岐」では捕まらない。
**`record struct` / `struct` / `interface` も宣言として数えること。**
**他の診断が同じ穴を踏んでいないかは数えていない。**

### R110 — 能力値の変更に「測って採らなかった機構は残置」を当てない

**能力値の変更に「測って採らなかった機構は残置」を当てない**（第130期 段0）。
第129期 段3（ハギの `MaxHp` 62 → 82）は**採否条件（発火と与ダメの両方が増える）を通っていた**が、
**目視では振 0 回の戦が出た**——与ダメ 0.8 → 6.9（×8.6）の 6.9 は 200 試行の平均で、
実態は「2回に1回、1発だけ」＝**平均が上がっただけで分散が広がっていた。**
線にすべきだったのは「増えた」ではなく**「その駒が仕事をしたと言える量になったか」。**
**残置は機構の話で、能力値には当たらない**——戻さないと次の対照が汚れる
（鍵を緩める実験で「鍵が効いたのか HP が効いたのか」が混ざる）。

### R111 — 起点の厚さは枚数ではなく供給の頻度で数える

**起点の厚さは枚数ではなく供給の頻度で数える**（第130期）。
燃焼の書き手は `CinderTrait`（ボルグ）と `BomberTrait`（ゾト・`BlazeRule` の既定が `Both` なので
**破裂も着火する**）の**2枚**だが、**ゾトは `OnDeath` なので蘇生が無ければ 1.00 回/戦**
——**毎ターン供給する起点は1枚**である。**「起点が何枚あるか」は供給量を1ビットも言っていない。**
第59期「『一度きりの供給』は蘇生役がいると一度きりでなくなる」の裏返しで、
**起点を厚くするなら `OnDeath` ではなく毎ターンの口を2本目にするのが筋。**

### R112 — 同じ名前の比は、器具が変わると符号が変わる。どの器具で出た値かを必ず添える

**同じ名前の比は、器具が変わると符号が変わる。どの器具で出た値かを必ず添える**（第129期・第131期に判明）。
`密度`（発火 ÷ 生存T）は追い打ちのハギについて**2つの値を持っている**:

    代金ゼロの延命（`Undying`・生存T 3.41 → 9.51 ＝ ×2.8）  0.463 → 0.335（**×0.72**）
    `MaxHp` の掃引（62 → 92 ＝ +0.52T ＝ ×1.15）             0.463 → **0.508**（**×1.10**）

#### R112 の続き

**同じ駒・同じ通貨・同じ式で符号が逆。** 鍵（味方の撃破）が戦闘後半に集まるので、
**少し延ばすと鍵の配られる時間帯に居合わせるようになり、延ばし過ぎると鍵の尽きた尾を買う。**
**密度は延命の量に対して単調ではない**ので、**「延命と相性が良い」は量を言わないと真偽が決まらない。**
第126期「同じ機構・同じ戦で2つの『残存』が逆を向いた」（規約 (G12)）の**器具の側の版。**

### R113 — 「初出 第nn期〜」の「〜」は、その期の指示書がノブの型名に触れただけで立つ

**「初出 第nn期〜」の「〜」は、その期の指示書がノブの型名に触れただけで立つ**（第131期・第124期 段0 の積み残し）。
第124期は `docs/rules.md` から「（k 期）」を落としたが、**「〜」に同じ自己参照が1ビットぶん残っていた**
——`EmberRule` は第130期の初出なのに、`design/PHASE131_ADVANCE_SPEC.md` が名前を挙げただけで
**「第130期」→「第130期〜」に変わる**（実測。指示書を `design/` から外すと戻る）。
**規約 (G8) の必須3（触っていないノブの既定が動いていない）を `docs/rules.md` 丸ごとの差分で示す、が
指示書が既存のノブに言及した期では必ず偽になる。** **比べるなら既定値の列だけにすること。**

### R114 — 生成物は、その期の `CLAUDE.md` を書き終えてから作り直す

**生成物は、その期の `CLAUDE.md` を書き終えてから作り直す**（第131期）。
`docs/rules.md` の最終列（`CLAUDE.md` / `LESSONS_*.md` に型名が出るか）は**その2つを走査する**ので、
**`docs/` を先に再生成して後から `CLAUDE.md` を書くと、その列だけが1期ぶん古いまま commit される**
——第130期の `EmberRule` の行がそうなっていた（`docs/rules.md` は 5b41c87、`CLAUDE.md` は 0b2daa9）。
**CONTRIBUTING.md の「数値や特性を変える → 測り直す」の順序は、`rules.md` には当てはまらない。**

### R115 — 表示専用の札を割り当てる基準は、機構の向きではなく手番の絵に当てる

**表示専用の札を割り当てる基準は、機構の向きではなく<u>手番の絵</u>に当てる**（第131期）。
踏み込みの札（`UnitDef.Advances`）の基準は「その駒は**行く**のか、**来られる**のか」だが、
**この問いは機構の起動条件を読む**ので、**肩代わり3枚（ガルド・ドハ・ウケ）が「来られる」側に落ちる**
——ところが札が支配するのは**通常攻撃の絵**で、肩代わりは§「踏み込みは主目標への一撃だけ」により
**席の位置で描かれる**（＝札を通らない）。実際の割り当ては
**(a) 一度も攻撃しない ／ (b) 1文が「撒く・飛ばす・投げる・吐く・縛る・喚ぶ」と書いている ／
(c) 1文が「自分では動かない・その場で・決して出ない」と書いている**の3条件に組み直した。
**基準の文が読む対象（機構か、手番か）を決めずに割り当てると、同じ文で逆の答えが出る。**

### R116 — 総量の内訳と致命打の内訳は、駒ごとに一致したりしなかったりする

**総量の内訳と致命打の内訳は、駒ごとに一致したりしなかったりする**（第135期）。
**ガルドは範囲で死んでいない**——受けた総量の **63.0%** が単体で、**致命打も 57.1% が単体**（差 −5.9pt）。
一方で**ワタは範囲 62.8% → 91.9%（+29.1pt）**、**セッキは単体 12.6% → 28.6%（+16.0pt）**と別物になる。
**セッキのずれの正体は `lethal: false`**——総量の 49.1% は同席するゴルムの吸い（徴収）で、
**あれは原理的に殺せない量**である（ワタの自傷 31.8% も同じ）。
**「たくさん削られている」の中に殺せない量が混じっている駒では、総量で死因を読むと必ず外す。**
第134期「同じ総数が3つの違う構造から出ていた」の逆側で、**一致する駒のほうが多い**
——範囲の取り分の差が **±5.5pt 以内が 4 枚**（ガルド +3.3 / ゴルム −4.4 / カド −5.0 / ドハ +5.3）、
**±11pt 以内まで広げると 6 枚**。**大きくずれるのはワタとセッキの 2 枚だけ**である。

### R117 — 「一文が実装されていない」を疑うときは、同じ名前の機構が2つ無いかを先に見る

**「一文が実装されていない」を疑うときは、同じ名前の機構が2つ無いかを先に見る**（第135期）。
ガルドの `PlusText`「味方への攻撃を肩代わりし、**その傷のぶん強くなる**」は
**死文ではなかった**——実装は `RedirectGainTrait.OnDamaged` の `self.AtkBonus += dmg / 2` で、
実測で**庇いのたびに発火し 1戦あたり攻撃力 +7.98 を積む**。
死文なのは**傷の引き取り（`GatherRule`・第89期）のほう**で、あちらは
`StatusKeys.Wound` を移すだけで `AtkBonus` を1も動かさない（第122期に既定オフ・実測 0.00 回/戦）。
**しかも引き取りが 0 なのは規則のせいではない**——巻き込み則（`SpillWoundRule`）も同時に降りたので
**隣接する味方に傷が載る経路そのものが盤面から消えている。規則を戻しても 0 のままである。**

### R118 — 強度のノブの決め方と、採否の線を別々の集合から引かない

**強度のノブの決め方と、採否の線を別々の集合から引かない**（第135期・(G16) の強度側）。
受け流し（`ParryRule`）の N は「庇いの成立回数の実測の中央値（＝1）を上限に 1 / 中央値 / 中央値×2」で
決めたので **N ≤ 2**、線は他の期から借りた「生存T +1.0T」。
**紙で引くと +1.0T に要るのは N ≈ 2.2 で、上限のすぐ外にあった**——
**器具が線に届けるかどうかが偶然で決まっていた。**
実測は8版すべて × で最大 +0.67T だが、**同じ版が勝率を 67.6% → 82.2%（+14.6pt）動かしている。**
**「線に届かない」と「効かない」は別**である。第118期「他の期の数値を線にするときは、
その線がこの器具で到達可能かを先に見る」を、**強度の決め方の側にも当てること。**

### R119 — 「1発を丸ごと無効化する」機構はロスターに1枚も無い

**「1発を丸ごと無効化する」機構はロスターに1枚も無い**（第135期 Q0-8。14 件を全数で確かめた。**第136期に受け流しが本採用になって 1 枚になった**）。
肩代わり2・軽減4・上限1・変換1・差し替え2・致死の停止2（猶予・不死＝器具）・盤面ルール1（軛）・プール1（破片）で、
**猶予と不死は「殺さない」制約、軛と破片は「量を切る」。**
**無効化を作るなら確率ではなく回数にする**——確率だと弾いた量が敵の火力に比例し、
第五波の断罪や全体を弾いたときの価値が雑魚の一撃の何倍にもなって**難易度カーブが平坦化する**
（真の反射を却下したのと同じ理由。カドの反撃が自分の攻撃力の2倍で自己完結しているのは、
