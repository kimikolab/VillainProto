## 0. この期の主題

**弱体化を「通貨」として成立させる。** 三段でやる。

| # | 中身 | 重さ |
|--:|---|---|
| 1 | `ctx.Dull()` の窓口を作り、`AtkBonus` を負にする経路を全部通す | 軽（挙動不変のリファクタ） |
| 2 | `ドハ×ウツ` の台を1行足す —— **既存の設計意図の回収。新機構ゼロ** | 軽 |
| 3 | **集約**（隣の味方の弱体を引き受け、アーマーに変える）を作る | **本体** |

### 1 が必要な理由（第41期の指示書の判断ミスの訂正）

第41期の指示書 §8 は「弱体化の共通窓口の新設は**読み手が増えてから**」と書いた。
**これは順序が逆だった。** 集約は「弱体が入る直前に横取りする」機構なので、
窓口が無ければ実装できない。読み手を増やそうとした瞬間に窓口が要る。

ただし**全部の `AtkBonus` を通す必要は無い**。書き込み15箇所のうち**負にするのは5箇所**で、
そこだけ通せば足りる。渇きが `ctx.Heal` の入口に1つ立っているのと同じ形になる。

### 2 が効く理由（第41期の前提の訂正1の回収）

`SharerTrait.DullDivisor` の doc は**逆しま（ウツ・クビ）を名指しで「噛み合う軸」と
書いている**のに、44行の誰も組んでいない。ドハを含むのは `反撃改 (ドハ×カド)` の1行だけで、
そこにウツはいない。

しかもこの経路は第41期が突き当たった問題を全部回避する。

| | 第41期（突き返し） | 第42期（分かち） |
|---|---|---|
| 供給元 | **移動** | **被弾** |
| 供給の分布 | 過剰（喧噪 11.58）か過少（曝き 0.12）の**二値** | 必ず起きる。枯れない |
| 先着競合 | `OnTurnStart` の喧噪が毎ターン枠を先取り | 無い（上限を持たない） |
| 段数 | 供給→変換→読み手の **3枠** | 供給兼土台→読み手の **2枠** |

第41期の台は `ablate` の4体版が床（20.0〜20.7%）に落ちて測れなかった。予算壁である。
**2枠に縮むことがそのまま効く。**

### 3 が本体である理由

**肩代わりは5種類あって全部ダメージで、状態の肩代わりが1つも無い**
（庇う・分かち・巨躯・後備え・棘守り）。ここが完全な空白地。

そして集約役は**同じ通貨をウツと逆向きに使う**。

| 読み手 | 弱体を何に変えるか |
|---|---|
| 逆しま（ウツ） | **攻撃力**（下げ幅の3倍） |
| **集約（ウケ）** | **アーマー** |

傷軸で維持攻（エグ）と維持防（ハリ）が波ごとに別の順位を作ったのと同じ形を、弱体で作る。

## 2. 実装

### 2-1. 窓口 `BattleContext.Dull(UnitState target, int amount)`

```
/// 攻撃力を下げる唯一の窓口。AtkBonus を直接引かないこと。
/// 集約（引き受け）の横取りはここに立っている。回復に対する Heal と同じ位置づけ。
public void Dull(UnitState target, int amount)
```

**やることは2つだけ。**

1. `target` に隣接する生存味方に `Bear`（集約）持ちがいれば、`amount` をそちらへ移す（§2-2）
2. 最終的な受け手の `AtkBonus` から `amount` を引く

**やらないこと（重要）**:

- **`AcceptsSupport` の判定を窓口に入れない。** 5経路で扱いが揃っていないので、
  ここで統一すると既存45行が動く。**判定は呼び出し側に残したまま**、
  `AtkBonus -=` の行だけを `ctx.Dull(...)` に差し替える
- **`OnDebuffed` のようなフックを作らない。** 読み手が2枚になっただけで
  イベントを作るのは早い。**必要になったときに、そのときの読み手の数を根拠に作る**
- **ログの文言を変えない。** 各経路のログは呼び出し側に残す
  （「腕がなまる」「勢い余って体勢まで崩れた」は駒の個性であって窓口の責務ではない）

**5経路すべてを通すこと。** 敵への呪詛（#2）も通す——集約は両陣営に等しく書けるべきで、
将来敵側に集約役を置くときに窓口が分かれていると監査が二重になる。

### 2-2. 特性 `TraitId.Bear`（引き受け）

```
Bear,        // 引き受け: 隣接する味方が受ける攻撃力低下を代わりに背負い、その分だけ鎧になる
             // ただし自分の腕は落ち続ける（同上。1つの動作の表と裏）
```

**プラス・マイナスのどちらのブロックにも入れない。**

#### 横取りの条件

- `Dull` の対象が**自分に隣接している生存味方**であること
- 対象が自分自身ならば横取りしない（そのまま受ける。再帰を作らない）
- 対象が `Bear` 持ちならば横取りしない（`SharerTrait` が
  `!target.HasTrait(TraitId.Sharer)` で止めているのと同じ形）
- 候補が複数いる場合は既存の `PickOne` の慣習に従う

**隣接に限定するのが設計の中核。** 「味方全体」にすると配置の判断が消え、
ウツと同居した瞬間に必ずウケが全部持っていく。隣接に限れば
**「ウツをウケの隣に置かない」という配置解が残る**——同じ供給を2枚の読み手が
配置で分け合う形になる。

#### 変換

引き受けた `amount` に対して `amount × ArmorPerDull` を自分の
`StatusKeys.Armor` に加算する。

**攻撃力ではなくアーマーにするのは意図的。** 被ダメージを減算で直接下げると、
敵の一撃を下回った時点で無敵になって二値化する（アーマーがプールにしてある理由と同じ穴）。
アーマーは既にプールとして実装されていて HP の前に削られるので、
**上限を数値で切らずに崖を避けられる。**

`ModifyIncomingDamage` は**使わない**（実装が1つしかないフックなので増やしたくはあるが、
そこに書くと減算になって崖が戻る）。

### 2-3. 強度のノブ `BearRule`

```
public readonly record struct BearRule(int ArmorPerDull)
{
    public static BearRule Default => new(2);
}
```

- 掃引は **1 / 2 / 3**
- `BattleEngine.Run` の引数に足す（`ColossusRule` / `YokeRule` / `HushRule` /
  `MartyrRule` / `ExposeRule` / `ShoveRule` と同型）。**static のノブは置かない**
- **`ArmorPerDull = 0` は横取りだけを走らせて変換を止める。**
  第41期が確立した形（「符号を測りたい効果は、その効果だけを 0 にできるノブと対にする」）を踏襲する

### 2-4. 駒 `UnitCatalog.Uke`（引き受けのウケ）

```
Id = "uke", Name = "引き受けのウケ", MaxHp = 90, Attack = 6, Speed = 5,
Traits = { TraitId.Bear }, Pattern = AttackPattern.Single
PlusText  = "隣の味方が受ける攻撃力低下を代わりに背負い、その分だけ鎧になる"
MinusText = "背負った分だけ自分の腕は落ちる。隣に誰もいなければ何も起きない"
Flavor    = "誰の痛みでも代わりに背負う。頼まれてもいないのに。"
```

数値は探索段階の初期値。**掃引の対象は `ArmorPerDull` だけ**で、HP・攻・速は振らない。

### 2-5. compare への追加 —— **2行**

```
("分かち×逆しま (ドハ×ウツ)", ...)   ← 台。新機構ゼロ
("引き受け (ウケ×◯)", ...)          ← 集約
```

- **1行目に集約を入れないこと。** 台の値が先に無いと、集約の寄与が
  「台が良かったのか集約が効いたのか」に分離できない
- 2行目の相方は `reseat` と `ablate` で決めてよいが、**弱体の供給源を必ず1枚以上入れる**
  （ドハ／クビ／ネル／ハネのいずれか）。供給が無ければウケは1回も発火しない
- 配置は `reseat` で決める。ウケは隣接次数がそのまま守備範囲になるので、
  **中央（次数4）が上位に来るはず**——これは第41期のハネ（隣接が代金なので角が有利）と
  **逆向きの予測**になる。ここが割れるかどうかが「隣接という条件が値段として機能しているか」の検算
- 配置換えを採るときの閾値は **+2.0pt**（seed 200..599・選定に使っていない帯で `confirm`）

**既存45行は1つも触らない。**

`BattleSim` に追加する。**出力は `docs/` に置かない**。

| 列 | 中身 |
|---|---|

| 横取り | ウケが引き受けた量/戦・**取られた相手の内訳** |

| 鎧 | 生成したアーマー量/戦・**実際にダメージを吸った量**/戦 |
| 死蔵 | 生成したのに使われずに終わったアーマー量/戦 |
| ウツ攻 | ウツの `CurrentAttack` の 開戦時 / 最大 / 終戦時 |
| ウケ攻 | ウケの `CurrentAttack` の 開戦時 / 最終 |

第23期の巨躯の吐き戻し（経路は通ったが出力の総量は動かなかった。攻撃力という遅い通貨に

**陽性対照を必ず置く**: `BearRule(0)`（横取りはするが変換しない）と、
ウケを外した同じ編成の2本。

**発火しなかったことは盤面の値に痕跡を残さない**ので、ログか `Events` から数えること。

## 4. 予測（実装の前に書き、報告書に当否を載せる）

**軸の名前ではなく、窓口を通る駒の在庫で書くこと。** 第41期は3件外して、
そのうち2件は「窓口を通る量が定常状態でどう変わるか」を数え損ねていた
（喧噪が席を混ぜるので `reseat` の無料の席が消える／`ablate` が床で機能しない）。

実装の前に以下を書き出す。

1. **`ドハ×ウツ` でウツが1戦に受ける弱体の総量を計算する。**
   `肩代わり量 / 4` の切り捨てが被弾のたびに走る。ドハの肩代わりは被弾量の40%で、
   ドハのHP104が上限。**上限まで使い切ると弱体の総量はいくつか**を先に出す
2. **その結果ウツの終戦時 `CurrentAttack` がいくつになるかを波ごとに書く**（戦闘長が違う）
3. **ウケが横取りできる量の上限を計算する。** 隣接次数（角2 / 中央4）と、
   隣に置く駒が弱体を受ける駒かどうかで決まる。**ドハのなまりは「守られた駒」に乗る**ので、
   ウケの隣に誰を置くかではなく**誰が守られるか**で決まることに注意
4. **アーマーの死蔵率を予測する。** 生成したアーマーが実際に吸われるのは、
   その駒が生成後に殴られたときだけ。**ウケが狙われなければ死蔵する**
5. **`reseat` でウケの中央（次数4）が上位に来るか。** ハネは角が1位だった。逆になるはず
6. **第五波で `分かち×逆しま` が 0.0% にならないか**（Phase 0-5 の計算から）

**予測を外したら、外した理由を報告書に書く。** 当てることが目的ではない。

**同じことが起きるかを先に疑うこと。** 全点で死蔵率が同じなら、
`ArmorPerDull` も強度ノブでしかない。

## 6. 実装上の注意（既知の落とし穴）

1. **窓口の統一と挙動の統一を混同しない。** 5経路は `AcceptsSupport` の扱いが揃っていない
   （突き返しは自前で弾き、呪詛と萎縮は `SupportTargets` を通す）。
   **揃えたくなるが、揃えると既存45行が動く。** この期では揃えない。
   不揃いであることを報告書の表に残して、次に触るときの材料にする
2. **アーマーは遅い通貨かもしれない。** 第23期の巨躯の吐き戻しは
   「経路は通ったが出力の総量は動かなかった」（攻撃力という遅い通貨に変換したので
   使う前に戦闘が終わる）。アーマーも同じ性質を持ちうるので、
   **生成量ではなく吸った量で判断すること**（§3 の「死蔵」）
3. **ドハのなまりは「守られた駒」に乗る。** ウケの隣に弱い駒を置いても、
   その駒がドハに守られなければ弱体は発生しない。**窓口を通る量は
   「隣に誰がいるか」ではなく「隣の誰が守られるか」で決まる**——
   第41期に外した予測と同じ形なので注意する
4. **ウケの攻撃力は落ち続ける。** 素の攻6 に対して引き受けが積むと `AtkBonus` が負になり、
   `CurrentAttack` は `Math.Max(1, ...)` で 1 に張り付く可能性がある。
   **これは仕様**（背負うほど殴れなくなる）だが、そうなっていることを `dull` で確認する
5. **ウケが `PerverseTrait` を持たないこと。** 集約と逆しまを1枚に持たせると
   供給→横取り→3倍変換が1体で完結して、自己完結したマイナスになる。
   さらに `AtkBonus` に下限が無いので実質乗算になり、**ホタの熾火に次ぐ2つ目の乗算フラグ**が
   生まれる。**分けたままにすること**
6. **移り木（シオ）と同居できない可能性が高い。** 第41期の実測では、
   シオの `+5`（動かされた味方を強化）が突き返しの `−2` を打ち消して
