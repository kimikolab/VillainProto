## 0. やったこと（入口）

- **`EnemyWave`**（`BattleCore/Models.cs`）—— 盤の席 0〜8 を直接指定する敵専用の型。コンストラクタは private で、作るのは `Of` / `FillAll` / `FillX` だけ
- **`BattleEngine.MaterializeEnemy(EnemyWave[, EnemyScaleRule])`** —— **陣営を引数に取らない**（必ず敵陣営・陣形は X 字・倍率は既存の `Materialize` と同じ掛け方）
- **`EnemyCatalog.TestStages`** —— 検証・九 / 新兵、検証・九 / 農兵、検証・五 / 新兵（対照）。`Stages` / `Columns` / 会戦 / 作戦マップには載せない
- **プレイヤー側の `Formation`（5枠）は1文字も触っていない。盤面の表（行・隣接・薙ぎ・貫きの経路）も触っていない**
- 計数を1本だけ足した: **`BattleResult.PierceDeadEnds`**（貫きの経路に生きている駒が1体もいなくて単体1発に落ちた回数・誰も読まない）

### Q0-1 貫きの行き止まり

`SelectPierceEntry`（X 字の枝）は、生きている敵がどの経路にもいない（○前2・○後2 だけが残った）とき
**手番を捨てずに `foes[Roll(foes.Count)]` の単体1発に落ちる**（lane = −1 で `ResolvePierce` は1体だけ刺す）。
規則で選ぶ陣形（パターン2・3）の枝も `best < 0` で同じ落ち方をする。**例外にも空振りにもならない。**
回数は計数 `PierceDeadEnds` で数える（表C）。
**副次**: ○前2・○後2 は経路に入らないので、**経路に1体でも生きている敵がいる限り貫きは 7・8 に1度も届かない**。

### Q0-2 敵側の特性が席を読むか

検証の波の駒（新兵・農兵）は**特性を1つも持たない**ので、この期の波では該当なし。
本編の敵の札（処刑人・断罪・殉教・中傷・曝き・渇き・粛・軛・逆位・施し・繕い）で席を読むのは
**殉教（`Row == Front` で資格＝席 7 も前列として庇える）と曝き（`HaulOutPair`・列で選ぶ＝7 は前、8 は後）だけ**で、
どちらも席番号の決め打ちは無い。

### Q0-3 味方の特性が敵の席を読む所

**落ちる所は1つも無い**（席で引く配列は無く、盤の読み取りは全部 `RowOf` / `LanesOf` / `AreAdjacent` / `SweepTargets` / `LanePath` ＝ 9席の表）。
振る舞いが変わる所（直さない・報告だけ）:

| 所 | 9体で起きること |
|---|---|
| 雷の跳ね・感電の放電・ミオの寄せ先／運び／移り・澱みの爆発 | 9席の隣接表をそのまま引く。**同点は席番号で割るので 5〜8 は後列（3・4）より後に来る**（行とは無関係） |
| 薙ぎ | 前1 → 前3・中央・○前2 ／ 中央 → ○中1・○中3 ／ 後1 → 中央・後3・○後2（`SweepTable`） |
| 貫き | ○中1・○中3 は経路に入る（後列の手前に減衰が1段増える）。○前2・○後2 は入らない（Q0-1） |
| 突き（ソラ） | 指差した敵が 7・8 なら経路が無いので通常の貫きに落ちる（既存のコメントどおり） |
| **突き返し（ハネ）** | `Slot` が 0・1 の敵しか選ばない（`○前2 は対象外`・第189期の決め打ち）。**○前2 の敵は前列なのに突き返されない** |
| **喧噪（バサ）** | 敵側は召喚枠（X 字の 5〜8）を外して入れ替える（第144期）。**9体の波では 4 体が1度も入れ替わらない** |
| **背かれ（ソム）の餌** | 湧く席は ○前2（7）固定。**敵が 7 に立っている間は湧かない**（`Summon` が null・`BetrayBlocked` に数える）。その敵が倒れても `Respawn` でなければ死体が席を塞ぐ |
| 逃亡・後退（`FindBackSlotFor`） | 行き先は編成の席（0〜4）だけ。7 は中央へ、5・6 は後1・後3 へ、8 は行き先なし |

### Q0-4 会戦

`Engagement.cs` は敵を `Formation`（5枠）でしか受け取らないので**9体の波は構造的に入らない**。
席の決め打ち・大きさ 5 の配列・召喚の枠で落とす処理は**無い**（`CarryOver` は渡されたリストをそのまま運ぶ）。
**この期は会戦に入れない**（指示書どおり）。

### Q0-5 診断

席で引く大きさ 5 の配列は **0 件**（`new long[5]` / `st < 5` は全部「波の番号」）。
`compare` / `chain` / `route` / `life` と第214〜220期の雷の診断はどれも `EnemyCatalog.Stages[st].Enemy`（`Formation`）で敵を引くので、
**9体の波は流れない（落ちもしない）**。この期は `nine` だけが `MaterializeEnemy` を通す。
**波の番号を 5 にすると `Burst` / `Scorch` / `Shock` の `new long[5]` が添字で落ちる**ので、それらに検証の波を足すときは別の集計にすること。

### Q0-6 召喚

検証の波の敵は召喚を持たない。**敵陣が9枠とも埋まっていると `Summon` は null を返し、呼び出し側（分裂・背かれ）は null を許す**（落ちない）。
味方の召喚（胞子・亡者）は味方陣なので無関係。

### Q0-7 過去の測定

- **敵を召喚の枠に立たせた実験は1度も無い。** 第5期の「農兵6体」は**盤がまだ6枠（前3・中1・後2）だった頃**の話で、X 字化（`ee19753`）で台は全部5体以下に組み直された（`Modes/Gradient.cs` / `Modes/Convert.cs`）
- 第5期（`ENGAGEMENT_PLAN_6.md`）: 農兵の波では単体と範囲の代金の差（向き）は作れなかった（+3.1pt 前後）。**第8期（`LESSONS_001_040.md`）の結論は「体数は符号を作らず、増幅する」**——符号を決めるのは個体の HP、大きさを決めるのが体数
- 第168期（R257・R258）: 5 → 4 → 3 体で「難度」と「判断」は逆を向き、1体の効き目は体数で変わる
- R210（第151期）: 薙ぎの実効の体数は開幕の占有ではなく戦闘中の平均で取る（開幕 3 に対して平均 2.0）

### Q0-8 DemoApp の描画

`BattlefieldView3D.PawnPosition(team, slot)` は **9 席すべてに座標を持つ**（陣営で左右反転）。`Main.EnterBattle(List<UnitState>, List<UnitState>, …)` はリストを受け取るので、
`MaterializeEnemy` の 9 体をそのまま渡せる。**落ちる所は見つからなかった**（大きさ 5 の配列は味方の編成画面と演出の粒の数だけ）。
**選ぶ口が無い**——波の選択（`_stagePicker`）は `EnemyCatalog.Stages` から作られ、背景は `stageIndex == 3` で城塞を引く。ここを Codex に依頼する（`design/CODEX_BRIEF_NINE_WAVE.md`）。
