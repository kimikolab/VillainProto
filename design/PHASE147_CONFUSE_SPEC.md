# 第147期 指示書 —— バサの転倒を**混乱**に置き換える

**HEAD 前提: 第146期 `78a55fb`。**

**この期の一文**:
> 喧噪のバサの「**行が前に変わった敵は転ぶ**」（第144期・採用済み）を、
> 「**行が前に変わった敵は正気を失い、次の攻撃を自軍に向ける**」に置き換える。
> 効き過ぎるのは分かっているので、**確率と回数制のどちらが効くかを同じ期で実測して決める。**

本書は自己完結している。リポジトリ外の文書は参照しない。

## 0. なぜこれをやるか

### 転倒と混乱は質が違う

| | 中身 | 相互作用 |
|---|---|---|
| 転倒（現行・第144期） | 敵の手番を1つ**消す**。量的 | **無い** |
| **混乱** | 敵の手番が**敵に向く** | 殉教者が庇う／処刑が育つ／こちらの被弾軸が餌を失う／**ササなら供給に化ける** |

**同じトリガー（前に出た敵）に両方を載せない。** 効果が二重になるうえ、どちらが効いたか測れない。
**択一にする。** この期は混乱に置き換えて、転倒はノブとして残す。

### 第146期が確定させた事実（**この期の出発点**）

混乱そのものは engine の3箇所（`SelectTargetChain` / `TargetPool` / `SecondaryTargets`）で成立し、
`ConfusionRule` として**既定オフで残置済み**。波ルールとしては不採用だったが、
**機構は完全に動いている**。落ちた理由は「効き過ぎ」と「向きが編成の外で決まる」の2点:

| 供給の向き | 帰属（第2〜5波） |
|---|--:|
| **敵だけ**（曝きの素体） | **+42.3** |
| 両陣営（バサ） | −8.4 |
| **味方だけ** | **−41.9** |
| なし | −0.1 |

> **混乱の符号を決めているのは編成の中身ではなく、その編成が誰を動かすかである。**

**バサの転倒のトリガーは既に「前に出た＊敵＊」なので、置き換えれば自動的に「敵だけ」側**＝
**+42.3 の側に落ちる。** そのままでは確実に壊れる。

### 絞りのノブは「測って決める」

第146期は「50% にしても帰属が動かない」（厚い台は −6.4 → −6.5 と 0.1pt 悪化）を1点測って、
**確率は効かない**と結論した。理由は**供給が潤沢（5〜17回/戦）で、半分にしても在庫が 2〜8回/戦 残る**から。

**ただしその測定は両陣営版のもので、この期の条件は違う。**
第144期の実測では**前に出る組は全波で 8/10 で一定**なので、混乱の供給は**毎ターン 1.6 体前後**。
**供給が細いぶん、確率が効く可能性は残っている。**

> **だから確率と回数制を同じ期で1点ずつ測り、どちらが効くかを実測で決める。**
> 「無難だから回数制」と紙で決めない（第133期の則の、ノブの選び方への適用）。

### Q0-1. 既存の2つのノブの形を確認し、**どちらに枝を足すか決める**

- `ShufflerRule(bool Foes, ShuffleStagger Stagger)` —— 既定 `(true, Advanced)`。
  `Legacy`（味方だけ）も定義済み
- `ConfusionRule(bool Active, int Percent = 100)` —— 既定 `Active: false`。
  **`Percent` の枝が既にある**（第146期 段C で使った）

**この期の形の候補**:

| 案 | 形 | 利点 |
|---|---|---|
| (i) `ShuffleStagger` に `Confuse` を足す | `ShuffleStagger { None, Advanced, Both, Confuse }` | バサの一文の中で択一が表現される。**推奨** |
| (ii) `ShufflerRule` に別のノブを足す | `(Foes, Stagger, Confuse)` | 両方載せられてしまう（§0 で却下した形） |

**(i) を推す。** ただし `Both`（2体とも転ぶ）との直交をどうするかを決めて書く
——`Confuse` も「前に出た敵だけ」に限るなら `Advanced` と同じ条件なので、列挙で並べられる。

**絞りのノブは `ShufflerRule` 側に置く**（`ConfusionRule.Percent` は波ルール用に残置されているので
流用しない——**同じ名前の機構が2つある状態を作らない**、第135期の則）。

```csharp
public readonly record struct ShufflerRule(
    bool Foes, ShuffleStagger Stagger, int ConfusePercent = 100, int ConfuseUses = 0)
```

`ConfuseUses = 0` は無制限。**既定は第144期の値（`(true, Advanced)`）のまま**——
**この期の段Aまで `compare` 305 セルが 0 件差分**であることが検算になる。

### Q0-2. `StatusKeys.Confused` を立てる窓口は流用できるか

第146期は `SwapSlots` の `Notify`（`BattleEngine.cs:6180`）1箇所に置いた。
**この期は「前に出た敵だけ」なので、`ShufflerTrait` の中の転倒を立てている箇所と同じ場所**になる。

- **`SwapSlots` の窓口に置いたままだと、ササ・セロ・カド・ハネの移動でも混乱が立つ**
  ——それは第146期に測って落とした形。**この期はバサの `ShufflerTrait` の中だけで立てる**
- `ConfusionRule.Active` は**偽のまま**にして、`StatusKeys.Confused` を読む側
  （`SelectTargetChain` ほか3箇所）が**キーだけを見る**形になっているかを確認する。
  なっていないなら、**読む側を「キーが立っているか」だけで判断するように直す**
  （ノブは「誰が立てるか」を決め、読む側は立っていれば従う）

### Q0-3. 混乱した敵が味方を倒したときのイベント（**第146期 Q0-4 の再確認**）

- **敵の勇者候補（処刑・第三波前3／第五波前3）は陣営を見ない**ので、
  **敵が混乱して敵を倒すと敵が育つ**。この期では敵が敵を倒すので**直撃する**
- **敵の殉教者（第五波・庇い 75%）は鎖が陣営を見ないので、混乱した敵の攻撃を庇う**
- **味方の墓守（リィカ）の層は積まれない**（敵が敵を倒すので `OnAnyDeath` の味方側は無関係）。
  第146期の予測5（混乱が死軸の燃料）は**波ルール版の話**で、この期では成立しない。**予測に書く**

**これらを実測で確かめる計数を用意する**（§4-2）。

### Q0-4. 転倒の表示を混乱の表示に差し替える

第145期で `BattleEventKind.Stagger` ＋ `StaggerLabels`（付与・消費）を足した。
**混乱にも同じ形が要る**——`BattleEventKind` に `Confuse` を1種、ラベル2本
（付与＝「正気を失った」／発動＝「自軍に振った」）。

- **`StatusKeys.Confused` は窓口を持たないキーの7枚目**（第146期の申し送り4・`docs/watch.md`）。
  **この期で窓口を持つので、盲点表から1行減るはず**。減ることを確認する
- **`EmitStatusSnapshot` には載らない**（第145期の発見——ターン頭に立って同じターンに消える状態は
  写しより後に立つので載らない）。**イベントで出すしかない**
- `DemoApp` の `case` 1つ。`GodotApp` は辞書で引くので変更不要（第145期の前例）

### Q0-5. ローカル台（**第146期の台をそのまま使えるか**）

第146期は4台を**埋め草の強さを12点掃引して HP110/攻34 で帯に入れた**。
**この期は敵側だけが混乱するので、同じ台でも V0 が変わる**（バサの転倒が混乱に替わるだけ）。

**必要な台**:

| 台 | 構成 | 見るもの |
|---|---|---|
| 被弾変換が厚い | ムド ＋ ガルド ＋ ドハ ＋ バサ ＋ 1 | **餌が減る**（敵の攻撃が敵に向く）ので、転倒版より下がるか |
| 被弾変換が薄い | 打点 ＋ バサ | **純粋な得**になるか |
| ササ同席 | ササ（前1）＋ ガレ ＋ バサ ＋ 2 | 混乱は敵→敵なので**ササの供給には化けない**はず（波ルール版と違う） |
| 第五波が濃い台 | バサ ＋ 殉教者・処刑と当たる編成 | **庇う／育つ**の2つが同時に出る |

- **対照はデータ点ごとに「同じ台の転倒版（現行 `Default`）」**。V0 を「混乱なし」ではなく
  **「転倒あり」**に取ること——この期の問いは「置き換えて良くなるか」であって「足して良くなるか」ではない
- 各台の V0 が 40〜95%・情報セル 3 以上であることを先に確認する
- 埋め草は**敵の数値に触る駒（呪詛官ネル・萎縮のクビ）を外す**（第143期の則）
- **土台の駒が「自分で動き出せるか」「その席から動けるか」まで数える**（第146期の則。
  ハネは `OnMoved` しか持たず自分から動けない／セロは `Row.Back` で即 return）

## 3. 予測（**Q0-5 の台が決まってから確定させる。実装前に書き切り、外れても消さない**）

1. **段A は全台で大きく正**。第146期の「敵だけ +42.3」がそのまま出る側なので、
   **転倒版（V0）より上がる**。ただし**天井に張り付く台が出る**
2. **被弾変換が厚い台は、上がり幅が最も小さい**——敵の攻撃が敵に向くと**餌が減る**ので、
   混乱の得と被弾変換の損が相殺する。**転倒版より下がる可能性もある**（転倒は餌を減らさない）
3. **ササ同席の台では供給に化けない**。混乱は敵→敵なので**ササは殴られない**。
   第146期（波ルール版・味方も混乱する）とはここが決定的に違う
4. **第五波で殉教者が混乱した敵の攻撃を庇う**（鎖は陣営を見ない）。
   **同時に勇者候補の処刑が育つ**（陣営を見ない）ので、**第五波の効きは他の波より小さい**
5. **墓守（リィカ）の層は積まれない**（敵が敵を倒すため）。第146期の予測5 は波ルール版の話
6. **確率のノブが効く**（第146期と違って供給が 1.6 体/ターン と細いため）。
   **効かなければ回数制が効く。** どちらが効くかは予測しない——**それがこの期の問い**
7. **バサを含まない行は ±0.0**

- **味方側の `Confused` は 0**（この期はバサの中だけで立てるので、味方が混乱する経路が無いことの検算）

## 5. 採否

### 採用の条件
1. **絞ったあとの帰属が、転倒版（V0）を上回る**。上回らないなら置き換える理由が無い
2. **天井・床に張り付く台が無い**（4台とも 40〜95% の帯に収まる）
3. **拒否権が立たない**（主判定19行の第五波が歯止めを下回らない・いずれの波も −10pt 以上の
   セルが出ない）。第146期は拒否権1 が発動して落ちたので、**ここが最大の関門**
4. **特異性**: バサを含まない行が ±0.0
5. **予測3 が当たる**（ササ同席で供給に化けない）。化けたなら味方も混乱している＝実装の穴

**壊れ気味は許容する。** ただし**拒否権は許容しない**（盤面が成立しなくなるレベル）。

### 不採用のとき
**転倒（`Advanced`）に戻す。** `Confuse` はノブとして残置。
そのとき報告書に書くべきは「**混乱を成立させるには供給をどこまで細くする必要があるか**」の数字。
