## 0. 主題

### 0-1. 4期続けて同じ場所で切れている

| 期 | 何が切れたか |
|---|---|
| 第74期 | ナタが 5.70T のうち **3.40T を手番ごと捨てていた** |
| 第79期 | 撃破で育つ機構は**育ったあとに振る手番が無い**（処刑・寄与 +0.6 以下） |
| 第84期 | カドの傷は積んだが、**手番あたりの回収が足りない**（+0.04pt） |
| 第85期 | 供給・在庫・発火が全部通ったのに、**ハリが 2.15 回しか振れない**（+1.10 / +1.30pt） |

**「資源を枯らすのは消費量ではなく周期頻度」の、出力側の版。**
供給側では確立していた原則が、読み手側で同じ形をしている。

**この期はそれを判定式に入れる。** 主判定の横に**読み手の1戦あたり発火回数**を常設し、
Phase 0 の停止条件にもそれを掛ける。

### 0-2. 何を変えるか

**継ぎ当てのノノ（`MenderTrait`）が、繕う相手の傷を読む。**

現行: 「毎ターン、最も傷ついた味方を繕う（14）／繕った分だけ自分が減る。攻撃はしない」

新: 「毎ターン、最も傷ついた味方を繕う。**その味方に傷があれば、傷1つにつき繕いが増える**／
繕った分だけ自分が減る。**繕うとその傷はひとつ塞がる**。攻撃はしない」

**あわせて第85期の巻き込み則（`SpillWoundRule`）を起こす。** 第85期は読み手（ハリ）の側で落ちたが、
**書き手の側は仕事をしていた**——`compare` で唯一動いた `刻み×縫い` が第四波 **47.0 → 88.5%**、
理想台でも大きく、ゴルム（吸い）とボルグ（余波）の2枚は線を越えていた。
**落ちたのは書き手ではない。**

### 0-3. なぜノノなら通るか（**仮説。Phase 0 で紙にする**）

**ハリの発火は2つの条件の積、ノノは1つ。**

| | 発火の条件 | 発火口 |
|---|---|---|
| ハリ | 手番がある **かつ** 殴った敵に傷がある | `OnAfterAttack`（振らないと出ない） |
| **ノノ** | 手番がある | `OnAction`（**攻撃しない。繕いが手番そのもの**） |

第85期の 2×2 はドラフト台（無作為な5枚）なので、ハリの2つ目の条件（殴った敵に傷）は
**滅多に揃わない**。ノノにはその条件が無く、**巻き込み則が入れば患者はたいてい傷を負っている**
——巻き込みで削られた味方はHPも減るので、`MostHurtAlly` の選び方と自然に相関する。

**代金は係数を足さずに済む。** ノノは繕った分だけ自分が減るので、
**傷が深いほど繕いが増え、同じだけ自分が早く尽きる。** 上限は `Math.Min(amount, self.Hp - 1)` が既に持っている。

**この期は初めて `compare` で書き手と読み手が同席する。** 第84期・第85期W1 は交わり 0 行で
拒否権が原理的に立たなかったが、今回は立つ（§1-3）。**歯止めが本物の歯止めとして働く。**

## 2. 変更の定義（**測る前に固定。数字を見てから動かさない**）

### 2-1. 3段

ノブは第84・85期と同じ形。**既定はすべて現行。**

```csharp
public enum MendSide { Plain, Wound }
public readonly record struct MendRule(MendSide Side)
{
    public static MendRule Default => new(MendSide.Plain);      // 測定中はここ

```

`SpillWoundRule` は第85期のものをそのまま使う。**書き手を絞る段のために `Scope` を足す。**

```csharp
public enum SpillScope { All, Dense }        // Dense = 吸い（ゴルム）と余波（ボルグ）だけ
public readonly record struct SpillWoundRule(bool Enabled, SpillScope Scope = SpillScope.All)
```

| 段 | `SpillWound` | ノノ | 内容 |
|---|---|---|---|
| **X0（対照）** | off | `Plain` | 現行 |
| **X1（本命）** | on / `All` | `Wound` | 書き手6枚・読み手ノノ |
| **X2** | on / `Dense` | `Wound` | **吸いと余波だけ**（第85期の申し送り。未測定） |

**X2 は「絞ると上がるか」を見る段**であって、X1 の劣化版ではない。
密度の低い書き手（生贄・破裂・置き去り）が**代金だけ払っている**なら X2 が上に出る。

### 2-2. ノノの書き方

`MenderTrait.Mend` を書き換える。**患者の選び方（`ctx.MostHurtAlly`）は1文字も触らない。**

```
patient = ctx.MostHurtAlly(self)          // 現行どおり。self は含まれない
w = patient.Counter(StatusKeys.Wound)     // MendRule.Plain のときは常に 0 として扱う
amount = Math.Min(Amount + PerWound * w, self.Hp - 1)   // 上限は現行の式のまま
ctx.Heal(patient, amount)                 // 窓口は必ず ctx.Heal（渇きに課税される）
self.Hp -= amount                         // 現行どおり無条件。渇き下では一方的に減る
Seal を持ち、w > 0 なら patient の傷を 1 つ引く
```

- **`PerWound = 3`。** 抉り・縫いと同値。**新しい数字を作らない。**
- **上乗せは加算。** 倍率にしない。
- **塞ぎは `TraitId.Seal` を再利用する。** 札は「塞ぎという代金」を独立に計量するための仕組みで、
  **どこに塞ぐかは本体の特性が決める**（ハリは敵、ノノは患者）。ノノの `Traits` は
  `{ Mender, Seal }` の2つになる。**新しい札を作らない。**
- **患者の選び方に傷を混ぜない。** 「最も傷ついた味方を繕う」という1文を保つ。
  傷の深い味方を優先させる案は §6（この期で決めないこと）。
  **代わりに「患者に傷があった率」を必ず出す**——低ければそこが律速だと分かる。

## 7. 実装の注意

- **`ctx.Heal` を経由しない回復を作らない。** 渇きに課税されることが設計意図。
- **`self.Hp -= amount` の位置と無条件性を変えない。** 渇き下で一方的に減るのは仕様
  （`BattleEngine.Heal` のコメントに明記がある）。**「親切にしない」の作法。**
- **上限は既存の `Math.Min(..., self.Hp - 1)` をそのまま使う。** 新しい上限を作らない。
- **`MostHurtAlly` に触らない。** 施し・縫い・継ぎ当ての3つが共有している窓口で、
  片方だけ振りたくなった時点で分ければよい（第39期の判断）。
- **敵の従軍司祭長も `Mender` を持つ。** `ActsOnPattern` が偽なので `OnTurnStart` で繕う。
  **`MendRule.Wound` が敵側にも効く**——味方の傷を書く手段が敵側に無いので実害は無いはずだが、
  **敵の患者に傷が乗った回数を 0 として確認すること**（自己検査に足してよい）。
- **ゾトの破裂は死亡時。** 書いた直後に戦闘が終わることがある。Q5 に計上する。
- **リィカの生贄は開戦時1回・`lethal: false`。** t=0 の在庫として Q3 に出す。
