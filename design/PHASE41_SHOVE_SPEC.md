## 0. この期の主題

**第40期が作った余剰を回収し、別の通貨に変換する。**

第40期の曝き（引きずり出し）は移動の供給を大きく増やしたが（`HasFallenBack` 0.26 → 2.15回/戦、
軋みの発火 +91%）、**恩恵を受けたのは44行中3行だけ**だった。しかもその3行
（`隊列崩し (バサ×ヨミ×セロ)` / `突き出し (セロ×ヨミ)` / `移動改 (バサ×ヨミ×シオ)`）は
**全部ヨミとガルドを共有していて、実質1クラスタしかない。**

そこで**移動を読み、弱体化を書く**駒を1体足す。狙いは2つ。

1. **移動の消費先を増やす**（ヨミに依存しない移動の読み手を作る）
2. **弱体化という枯れた通貨に、初めて戦闘中の供給を作る**

### なぜ弱体化なのか（数えた結果）

現在 `AtkBonus` を負にする経路は2つしかなく、**どちらも開戦時1回きり**である。

| 供給源 | 量 | タイミング | 実装 |
|---|--:|---|---|
| 呪詛の味方漏れ（ネル） | −5 | 開戦時1回 | `CurseTrait.AllyLeak = 5` |
| 萎縮（ササ） | −9 | 開戦時1回 | `CowerTrait.AttackPenalty = 9` |

読み手は**逆しま（ウツ）1枚だけ**（`PerverseTrait`。`AtkBonus` が負なら
`baseAtk + (-AtkBonus) × 3`）。変換係数は3倍と大きいのに供給が動かないので、
**ウツの攻撃力は戦闘を通じて定数**になっている（攻9 に −5 で 24、−9 で 36 に固定）。

リィカの層もムドの怒りも戦闘中に伸びるのに、**弱体化を経由した成長だけがロスターに存在しない。**
ここを開ける。

### 落とした候補（同じ穴を掘らないために記録する）

- **被ダメージ上昇**: 読み手は6枚（被弾強化・庇う・分かち・後備え・墓守・棘）と最多だが、
  **供給側が既に飽和している**（自爆・巻き込み・瘴気・生贄・大食い・反撃・毒漏れ）。
  ここに8つ目を足しても既存の下位互換になる
- **`IdleTurn`**: 号令・据えが買い取るので形は綺麗だが、この2枚は既に主判定2行を持つ
  確立した経済圏なので、供給を足しても**既存の強い行が強くなるだけ**になりやすい

## 2. 実装

### 2-1. 特性 `TraitId.Shove`（突き返し）

```
Shove,       // 突き返し: 味方が動かされるたび、敵陣の隊列を突き崩す。
             // ただし勢い余って隣接する味方の体勢まで崩す（攻撃力が下がる）
             //（置き去り・責め苦・仇討ち・裂きと同じく、プラスとマイナスが1つの動作の表と裏）
```

**プラス・マイナスのどちらのブロックにも入れない。** 1つの動作から両方が出るため。

#### トリガー

`OnMoved`（自分が動かされた）と `OnAllyMoved`（味方が動かされた）の両方。
**自分から移動を起こす手段は持たせない。** 供給が無ければ1回も発火しないこと自体が、
この駒のマイナス側の一部になる（負の特性を自己完結させない）。

供給元は4つ: 喧噪（バサ・毎ターン味方2体を入れ替える）／臆病（削られると後列へ逃げる）／
棘守り（身代わりして位置を入れ替える）／**敵の曝き**（第40期・第五波の告発人）。

#### 流量

**1ターン1回まで。** 喧噪だけで `OnAllyMoved` が毎ターン2回走るので、切らないと供給過多になる。
上限はターン境界でリセットする。

#### 効果A —— 敵陣を突き崩す

第40期の曝き（`ExposeTrait`）と**まったく同じ選び方**を使う。

1. 敵陣の生存駒のうち `Row == Row.Back` で**現在HPが最も高い1体**
2. 敵陣の生存駒のうち `Row == Row.Front` で**現在HPが最も低い1体**
3. どちらかが 0 体なら効果Aは何もしない（効果Bは実行する）
4. `ctx.SwapSlots(1 の駒, 2 の駒のスロット)` を1回呼ぶ

**選び方を曝きと揃えるのは意図的。** プレイヤーが規則を1つ覚えれば両方読める。
**可能なら選択ロジックを共通のヘルパに切り出して1箇所定義にする**こと
（片方だけ振りたくなった時点で分ければよい）。

#### 効果B —— 隣接する味方の体勢を崩す（マイナス側）

自分に**隣接する生存味方全員**の `AtkBonus` を `Penalty` だけ引く。

- 対象は `FormationRules.AreAdjacent(self.Slot, ally.Slot)` が真の生存味方全員。自分は含めない
- `AcceptsSupport` が偽の駒（ガルドの `Stoic`）は弾かれる。**弾くこと**
- **席は動かさない。** 移動を起こすのは効果Aだけ

**なぜ全員なのか**: 対象を1体に絞ると「誰を隣に置くか」の判断が1回で終わる。
全員にすると**隣接の次数がそのまま値段になる**——角（次数2）に置けば2体、
中央（次数4）に置けば4体を巻き込む。X字の隣接表は不規則なので、そのまま配置パズルになる。

**効果Aを先に、効果Bを後に実行すること。** 効果Aは敵陣の駒を動かすので
`OnAllyMoved` は敵側にしか通知されず、味方の突き返しには戻ってこない
（＝この時点では再帰しない）。ただし**将来敵側に突き返しを持たせると再帰する**ので、
「発火中は再入しない」ガードを1つ入れておくこと。1ターン1回の上限だけに頼らない。

### 2-2. 強度のノブ `ShoveRule`

```
public readonly record struct ShoveRule(int Penalty)
{
    public static ShoveRule Default => new(2);
}
```

- `Penalty` = 効果Bで隣接味方から引く攻撃力。掃引は **1 / 2 / 3**
- `BattleEngine.Run` の引数に足す（`ColossusRule` / `YokeRule` / `HushRule` / `MartyrRule` /
  `ExposeRule` と同型）。**書き換え可能な static のノブは置かない**

**既定は無効にしなくてよい。** これは味方側の駒なので、**新駒を編成に入れない限り
既存44行は1バイトも動かない**。それ自体が回帰チェックになる（§5-1）。

### 2-3. 天井について

`AtkBonus` に下限は無く、逆しまは `-b × 3` なので原理的には無限に伸びる。
**天井は戦闘長そのもの**（1ターン1回 × 戦闘長）で、これは構造的な上限として許容する。
**回数制限や上限値のような別のノブを足さないこと**——上限を数値で切ると、
「戦闘が長引くほど伸びる」という読める規則が但し書きで壊れる。

ただし**会戦（Engagement）を跨いで持ち越さないこと**。`AtkBonus` はエンジンが
戦闘境界で 0 にしているので、追加の実装は不要なはずだが確認する。

### 2-4. 駒 `UnitCatalog.Hane`（突き返しのハネ）

```
Id = "hane", Name = "突き返しのハネ", MaxHp = 56, Attack = 11, Speed = 8,
Traits = { TraitId.Shove }, Pattern = AttackPattern.Single
PlusText  = "味方が押しのけられるたび、敵の隊列を突き崩す"
MinusText = "勢い余って隣の味方の体勢まで崩す（攻撃力が下がる）"
Flavor    = "押されたら押し返す。それしかできないし、加減も知らない。"
```

数値は探索段階の初期値でよい。**掃引の対象は `Penalty` だけ**で、
HP・攻・速は振らないこと（1変数を振るときに何を一緒に動かすかを増やさない）。

### 2-5. compare への追加

**1行だけ足す。**

```
("突き返し (ハネ×ウツ)", ...)
```

- 供給（バサの喧噪）・変換（ハネ）・読み手（ウツ）の3枚が要る。残り2枠は土台
- **配置は `reseat` で決めること。** ハネの隣接次数が値段になるので、
  手で置いた席が最適である保証は無い。`reseat` の上位帯を報告書に載せる
- 配置換えを採るときの閾値は **+2.0pt**（seed 200..599・選定に使っていない帯で `confirm`）

**既存44行は1つも触らない。**

## 3. 診断モード `shove`

`BattleSim` に追加する。**出力は `docs/` に置かない**。
`CompareBuilds()` / `Stages` / `Columns` を触らないこと。

| 列 | 中身 |
|---|---|
| 突き返し | 発火回数/戦 |
| 供給元 | 発火のトリガーの内訳（喧噪 / 曝き / 臆病 / 棘守り） |
| 空振り | 上限（1ターン1回）で弾かれた回数/戦 |
| 崩し | 効果Aが成立した回数/戦・引き出された敵の名前（上位3体） |
| よろけ | 効果Bが当たった延べ体数/戦・受け手の内訳 |
| 弾き | `Stoic` で弾かれた回数/戦 |
| **ウツ攻** | **ウツの `CurrentAttack` の 開戦時 / 最大 / 終戦時** |

**最後の行がこの期の核心。** 現在ウツの攻撃力は戦闘を通じて定数なので、
**開戦時 ≠ 最大 になること自体が新しい挙動**である。

**陽性対照を必ず置く**: `ShoveRule(0)` での同じ計数（よろけ 0 / ウツ攻が定数）。

**発火しなかったことは盤面の値に痕跡を残さない**ので、ログか `Events` から数えること。

## 4. 予測（実装の前に書き、報告書に当否を載せる）

**軸の名前ではなく、窓口を通る駒の在庫で書くこと。** この機構の窓口は3つ。

- 供給の窓口: **味方の移動が起きる回数**（喧噪 2回/T が主。曝きは第五波のみ 2.05回/戦）
- 効果Aの窓口: **敵陣の後列と前列にそれぞれ生存駒がいるか**
- 効果Bの窓口: **ハネの隣接次数**（角2 / 中央4）と、隣に `Stoic` が何枚いるか

実装の前に以下を書き出す。

1. **ハネを角に置いた場合と中央に置いた場合で、効果Bの延べ体数が何倍になるか**を先に計算する。
   `reseat` の結果がこの計算と合うか
2. **ウツの `CurrentAttack` が戦闘終了時に何になるか**を計算する。
   `9 + (開戦時の弱体 + Penalty × 発火回数) × 3`。戦闘長は波によって違うので波ごとに書く
3. **第五波だけ供給が厚くなる**（曝きが上乗せされる）。第五波の発火回数が他波より多くなるか
4. **ウツを含まない編成にとっては純損**。`突き返し (ハネ×ウツ)` からウツを外した
   仮想の編成が何ptになるかを `ablate` で確かめる予定を書いておく
5. **符号が反転する行を1つ以上名指しする**

**予測を外したら、外した理由を報告書に書く。** 第40期は2件外して、
どちらも「窓口を通る駒の在庫」を数え損ねていた（振り子と片列全滅）。当てることが目的ではない。

## 5. 受け入れ基準

**分母を必ず書くこと**（「食い違い 0 件」ではなく「220 セル中 0 件」）。

### 必須（1つでも落ちたら差し戻し）

1. **新駒を編成に入れない状態で `compare` が現在の `docs/balance.md` と完全一致する。**
   44行 × 5波 = 220 セル中の食い違い件数を書く
2. **ウツの `CurrentAttack` が戦闘中に成長する**（`shove` の「ウツ攻」で 開戦時 < 最大）。
   ここが動かなければこの期の前提が崩れているので、報告して止める
3. **効果Bが `Stoic` に弾かれる**（ガルドの `AtkBonus` が動かない）。1件でも動いたら実装バグ
4. **崖になっていない。** `突き返し (ハネ×ウツ)` の5波の勝率が
   0.0 と 100.0 だけで構成されていないこと。**崖は構造の問題であって調整の問題ではない**ので、
   出たら数値をいじる前に報告する

### 採否の判断材料（落ちても差し戻しではない）

5. **`reseat` の上位帯で、ハネの席が隣接次数と対応しているか。**
   次数の低い席（角）が上位に来るはず。**来なければ効果Bの代金より効果Aの利得が
   勝っている**ということなので、そのことを書く
6. **`ablate` でウツを抜いたときの寄与。** ウツが無いと純損になるはずで、
   その寄与が大きいほど「編成による符号反転」が実体を持っている
7. 波間相関6ペアの全部（1行足すと組成が変わるので、大きくは動かないはず。
   **動いたら組成効果か実体かを切り分ける**）。第40期の採用後は
   3×5 +0.46 / 4×5 +0.44 / 2×5 −0.25
8. 第五波の平均。第40期の採用で **40.5** まで下がっていて歯止め（40.0）の 0.5pt 上しかない。
   **1行足すだけでも平均は動く。下がったら必ず書く**
9. 固有の勝者・敗者の増減。**厳密版（=100 / =0）と緩い版（90/10）のどちらを使ったか毎回書く**

### 掃引（必須の 1〜4 を通ってから）

`Penalty` を **1 / 2 / 3** の3点で測る。**各点に対照は不要**
（このノブは敵側の盤面を1も動かさない）が、`ShoveRule(0)` の1本は全点の基準として置く。

**見るのは勝率ではなく、ウツの攻撃力の到達点と、ウツ以外の駒の目減り量の比。**
この比が編成によって符号を変えることがこの機構の設計目的で、勝率はその結果に過ぎない。

## 6. 実装上の注意（既知の落とし穴）

1. **弱体化のイベントは存在しない。** `AtkBonus` は共通窓口を持たず、20箇所以上が
   直接フィールドを叩いている。**この期でも窓口を作らない**（作るなら独立した作業として、
   既存20箇所の監査を伴う）。効果Bも直接引く
2. **ガルドは構造的に唯一の非被害者になる。** `Stoic` は回復も強化も呪いも受け付けないので、
   ハネの隣に置くと代金を1も払わない。**これは既存駒への無料の payoff であって、
   潰すべきバグではない**——「ハネの隣をガルドで固める」が正当な配置解になる。
   ただし**移動軸の既存3行が全部ガルドを持っている**ので、
   ガルドが答えとして安すぎないかは `reseat` で確かめること
3. **逆しまのマイナスと干渉する。** ウツは強化されると攻撃力が半減する。
   シオ（移り木・動かされた味方を癒し強化する）と同居すると、
   **移動が起きるたびシオがウツを強化して台無しにする**可能性がある。
   `移動改` がシオ入りなので、同居の可否を報告書に書くこと
4. **再入ガードを入れる。** 効果Aは敵陣を動かすので現状は再帰しないが、
   敵側に突き返しを持たせた瞬間に無限再帰する。1ターン1回の上限だけに頼らない
5. **乱数列はずれる。** `SwapSlots` の `PickOne` は候補が2個以上のとき `Roll` を消費する。
   帰属は必ず `ShoveRule(0)` との差か `ablate` で取ること。前後比較で帰属しない
6. **召喚枠（スロット5〜8）の扱いを明記する。** 隣接表に召喚枠が含まれるなら、
   効果Bの対象にも入る。**含めたかどうかを報告書に書く**。推奨は「含める」
7. **長時間ジョブはフォアグラウンドで1ツール呼び出し内に収める。** 背景に回すと刈られる。
   所要の目安: `compare` 約8秒 / `reseat`（1行）数十秒 / `ablate`（全編成）約26秒

## 8. この期で決めないこと

- 弱体化の共通窓口（`OnDebuffed` のようなフック）の新設。**読み手が増えてから**
- ハネを敵側に持たせる形（味方側で規則の効き方を測ってから）
- 第五波の平均を戻す作業（別の期。ただし基準8で下がったら記録する）
- 移動の読み手をさらに増やすこと（この期で1枚増える。次を決めるのは測ってから）
- 数値バランス全般。**多少強すぎる・弱すぎるは許容する。**
  基準4（崖）は「明らかに成立しなくなるレベル」の歯止めであって調整目標ではない
