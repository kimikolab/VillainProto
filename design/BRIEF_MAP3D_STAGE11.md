push はしない（ポンの指示を待つ）。

## 0. 決まっていること（ポン 2026-11-12）

- 画面の基準は **1920×1080（16:9）**。文字は 1280×720 に縮めても読める大きさ
- マップの見た目は **C: 傾けた 3D のジオラマ**（絵地図・ヘックスは採らない）
- 地形は購入済みのアセット **Bukkbeek「Nature Assets & Terrain Tools Collection」**（Godot 4.6 用・ローポリ手描き風・Path3D から道と川を作る道具・草木をばらまく道具つき・**建物は無い**・再配布禁止）
- カメラは**固定の見下ろし**（回転なし・拡大と横移動だけ）
- 隊の駒は**立ち絵の板＋台座**（仮。ポン:「先頭の駒だけではどんな隊か分かりづらいので、後で替えるかも」→ 差し替えやすく作る）
- 建物（砦・敵の本陣）は**仮の箱**でよい
- 今の 2D のマップ画面は**残す**（回帰と器具が使う）。3D は見た目の層を足すだけ

## 2. 作るもの

### 2-1. 画面の基準
- 基準 1920×1080・引き伸ばしは縦横比を保つ。窓の大きさを変えても全面を使う
- **検証用の UI は別の層**に分け、キー 1 つで出し入れ（既定は隠す）

### 2-2. 1-1 のジオラマ
盤は今の 1-1（拠点 → 北の道 3 マス・南の道 3 マス → 敵の本陣）。マスの座標は `MapGraph` から取り、**3D の位置はステージごとの表 1 つ**に置く（1-2・1-3 を後で足せる形）。

- 地形: 左に辺境の砦（墓地が隣にある）、右に討伐隊の本陣。北の道は山すそ、南の道は森と湿地を通る。中央に森と川。奥に山並み
- 道: アセットの道の道具で、マスを結ぶ線から作る。マスの位置には円い台（味方の色／敵の色／空）
- 駒: 味方の隊は立ち絵の板＋台座＋隊の名札。敵部隊は旗＋数＋名札。**駒の見た目は 1 つの場面（シーン）にまとめ、差し替えられるように**
- カメラ: 傾き 50〜55 度あたりから始め、**傾き・高さ・画角を書き出しの値にする**（ポンが動かして決める）
- 光: 夕暮れ寄り。ヴィラン側の話なので明るすぎない

### 2-3. 動き（最小）
- 隊の移動: マスからマスへ道に沿って歩く（0.4 秒ほど）
- 選んだ隊・行ける先のマスが光る。行き先までの作戦ターン数を出す（今の 2D と同じ情報）
- 戦闘に入る・拠点を取る演出は**この発注では作らない**

### 2-4. UI（仮の配置）
見本（Claude の配置図「1-1 マップの見た目 3案」の C）と同じ位置: 左上 ステージ名・作戦ターン・目標／右上 金／左下 隊の札（名前・顔ぶれ・HP）／右下 刻を進める。
中身は今の 2D の画面と同じ操作につなぐ。足りない操作（組み直し・呼ぶ・強化）は今の窓をそのまま開く。

### 7-3. §1 の答え（Claude Code が 2026-11-13 に確かめた）

1. **Godot は 4.7.2**（`project.godot` の `config/features` は "4.7"・`C:\tools\Godot_v4.7.2-stable_mono_win64`）。アセットの 4.6 より新しい。木・茂み・岩・環境は 10 月から 4.7.2 で取り込んで本編で使っている（`GodotApp/ASSET_RESEARCH_AND_PLAN.md`）。**道と川の道具を 4.7.2 で動かした記録は無い**（下の 2）。
2. **アセットは NatureBlocks v1**（Bukkbeek・PolyBlocks）。置き場所は既に決まっている: 原本 `D:\Assets\GodotAssets\PolyBlocks-NatureBlocks-[v1]`、プロジェクト内は `DemoApp/PolyBlocks/NatureBlocks/`（`.gitignore` 済み）、入れ方は `DemoApp/PrepareAssetPreview.ps1`、有無の判定は `PurchasedAssets.NatureAvailable`。
   **足りないもの: 道具（`tools/`）が DemoApp に入っていない。** 導入スクリプトが写すのは `assets/` と `source_files/` だけで、原本の `NatureBlocks/tools/`（`generator_road` ／ `generator_river` ／ `generator_lake` ／ `generator_cliff` ／ `generator_mountain` ／ `scatter_*`）は未コピー。スクリプトは既存のフォルダを上書きしないので、土台の段で「`tools/` だけ足す」口を足す。
   道具は GDScript の `@tool`（エディタのボタンで生成する作り）だが、`generate_road()` は `Path3D` を受けてメッシュを子に作る普通の関数。**土台の段で確かめた: 4.7.2 の実行時に C# から道も川も生成できる**（`--map3d-tool-check`・`tools/` は導入スクリプトに足した）。
3. **1920×1080 にして崩れるもの**（`override.cfg` で基準だけ上書きして編成・マップ・組み直し・戦闘を撮った。結果画面は撮っていない）
   - はみ出し・重なりは **0 件**。4 画面とも窓の大きさに追従する
   - **文字が小さい**: 文字の大きさが画素の決め打ちなので、基準が 1440 → 1920 になったぶん相対的に 0.75 倍になる。札の説明・席の名札・戦闘の下の帯（11〜12px）は 1280×720 に縮めると読めない。§0 の「1280×720 でも読める」を満たすには 2D 側の文字を一律に上げる必要がある（**2D の経路は 0 行の約束とぶつかる——ポンの判断が要る**）
   - **余白が偏る**: 2D のマップは盤の大きさが固定で中央に小さく残る／組み直しの窓は席の 5 マスが左上に寄る／戦闘の下の帯は左 920px だけ使う
   - **画素の決め打ち**: `BattlePawn3D.Doha.cs` の `ShareHandPoint`（画面の点 900,330）は本編の演出で位置がずれる。検査・写しの道具では `HagiEmpowerCapture`（1440×500 の切り出し）・`MudoCheck`（点 900,790 の色）が外れる（どれも Codex の持ち物）
   - **引き伸ばし**: いまは `canvas_items` で縦横比の指定なし（＝ keep・16:9 以外の窓は黒帯）。「全面を使う」なら `expand`
   - 頭なしの門（`--map-layout-capture` ほかレイアウトの検査）を 1920×1080 で回すのは未実施

### 7-4. 土台の結果（Claude Code・2026-11-13）

ポンの答え（2026-11-13）: **今回は 2D の画面の文字を触らない。**

- **画面の基準は「3D の層にいる間だけ」1920×1080 にした**（縦横比を保って窓の全面を使う）。`project.godot` は 1440×900 のまま——全体を上げると 2D の文字が 0.75 倍になり、画素を決め打ちした検査も外れる（§7-3 の 3）。3D を既定にするときに `project.godot` を上げ、2D の文字と決め打ちを一緒に直す

- 口の一覧・素材の入れ方・写しの撮り方は `design/MAP3D_ASSETS.md`。コードは `DemoApp/Map3DMode.cs` と `DemoApp/Map11Main.Map3D.cs`（`Map11Main.cs` に足したのは `_Ready` の 2 行）
