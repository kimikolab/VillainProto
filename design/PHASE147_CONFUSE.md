### Q0-1. 既存の2つのノブの形と、どちらに枝を足すか

実装から引いた現物:

| 型 | 場所 | 既定 |
|---|---|---|
| `ShufflerRule(bool Foes, ShuffleStagger Stagger)` | `Traits.cs:5945` | `(true, Advanced)`（第144期に採用） |
| `ShuffleStagger { None, Advanced, Both }` | `Traits.cs:5925` | — |
| `ConfusionRule(bool Active, int Percent = 100)` | `Traits.cs:8101` | `Active: false`（第146期・残置） |

**指示書の案 (i) を採る**——`ShuffleStagger` に `Confuse` を足す。理由は指示書 §0 のとおり
「同じトリガーに両方を載せない」で、**列挙にすれば択一であることが型で表現される**
（`Confuse` も「行が前に変わった敵だけ」に限るので `Advanced` と条件が同一＝列挙で並べられる）。

**`Both` との直交はしない。** `Both`（2体とも）は第144期に「方向が消えて『毎ターン敵の手番を2つ削る駒』になる」
として採らなかった上限測定用の値で、混乱側に同じ枝を作ると**測る前から採らないと決まっている版が1つ増える**だけである。
`Confuse` は `Advanced` と同じ「前に出た側だけ」に固定する。

絞りのノブは指示書どおり `ShufflerRule` 側に置く（`ConfusionRule.Percent` は波ルール用の残置なので流用しない）:

```csharp
public readonly record struct ShufflerRule(
    bool Foes, ShuffleStagger Stagger, int ConfusePercent = 100, int ConfuseUses = 0)
```

**`ConfuseUses` は「保持者（バサ）1体・1戦あたりに混乱を立てられる回数」**とする。0 は無制限。
**「1体につき N 回まで」（対象ごと）は採らなかった**——絞りたいのは供給の総量で、
指示書 §2 が「どちらも効かなければ**供給の口**（敵の入れ替えを2体→1体）」と続けている以上、
確率と同じ軸（総量）を振らないと2つのノブを比べられない（同じ帯・同じ台・同じ seed で比べるのが段B/B' の目的）。

### Q0-2. `StatusKeys.Confused` を立てる窓口は流用できるか

**できない。立て直す。** 第146期の窓口は `BattleEngine.cs:6309`（`SwapSlots` の `Notify`）で、
**動かした側の陣営を問わず全ての移動で立つ**——それは第146期が測って落とした形そのものである
（味方だけを動かす版の帰属は **−41.9pt**）。この期は `ShufflerTrait.Settle` の中、
**いま転倒を立てている場所**（`Traits.cs:6072` 付近）でだけ立てる。

**読む側は直す。** 現状の読み手2箇所は `Confusion.Active` を見ている:

| 場所 | 現状 |
|---|---|
| `BattleEngine.cs:4215`（`FoesOf`） | `if (Confusion.Active && attacker.RawCounter(Confused) > 0)` |
| `BattleEngine.cs:4229`（`ConsumeConfusion`） | `if (!Confusion.Active \|\| actor.RawCounter(Confused) == 0) return;` |

**ノブは「誰が立てるか」を決め、読む側は立っていれば従う**に直す。
ただし `RawCounter` を既定の経路で毎回引くのは避けたいので（`FoesOf` は1回の攻撃で複数回通る・
`compare` / `layout` は数百万戦を回す）、**`BattleContext.ConfusionLive`** を ctor で1回だけ計算する:

```
ConfusionLive = Confusion.Active || Shuffler.Stagger == ShuffleStagger.Confuse
```

これは「キーを立てうる経路が1本でもあるか」と同値で、短絡の作法（軛・受け流し）を壊さない。
**唯一の抜け穴は業（`ScapegoatTrait`）がカウンタを移す経路**だが、
あの駒は `UnitCatalog.All` に保持者 0 枚（第49期・残置）なので盤面には出ない。

### Q0-4. 表示 —— **指示書の受け入れ条件は到達不能だった**

`BattleEventKind` に1種・ラベル2本を足すのは指示書どおり（`Stagger` ＝第145期／`Stun` ＝第146期 段0 と同じ形）。

**ただし「`docs/watch.md` の盲点表から `Confused` が1行減る」は原理的に成り立たない。**
盲点表（`watch phase0` の表1）が数えているのは **`EmitStatusGain` の呼び出し元**だけで、
専用の `BattleEventKind` を持つかは1ビットも見ていない——実測で
**`Stagger` も `Stun` も、専用の種類を持っているのに × のまま**である
（`docs/watch.md:416,409`。「窓口を持たないキー **7 / 11**」）。

> **判定式の線が、同じ指示書の別の節によって到達不能になっていないかを先に確かめる**
> （第59・60・61・107・110・117・118・121期に続く**9例目**）。

しかも `StatusGain` の側には明文の規約があり（`BattleEventKind.StatusGain` の doc:
「engine の窓口を持つ4通貨だけが出す」）、第145・146期はこれを守って
**わざと `StatusGain` を使わずに専用の種類を足した**。混乱だけ `StatusGain` に載せると規約が壊れる。

**代わりに測れる形にする**——盲点表に**「専用の種類」の列を1つ足す**（`StatusKeys` の定数名と
`BattleEventKind` の名前を機械で照合する）。これで第145・146期の成果も同時に表に出る
（`Stagger` / `Stun` / `Confused` の3行が ○ になる）。**受け入れ条件はこの列で読む。**
そのために**イベントの名前は `Confuse` ではなく `Confused`**（キーの定数名と一致させる）。

`DemoApp` は `case` を1つ足す。`GodotApp` は辞書で引くので変更不要（第145期の前例）。

### Q0-5. ローカル台 —— **第146期の4台がそのまま使える**

第146期の V0 は `ConfusionRule.Default`（混乱なし）× `ShufflerRule.Default`（＝**転倒あり**）で、
**この期の V0（転倒版）と1ビットも同じ**。`confuse scan` の実測:

| 台 | 第1波 | 第2波 | 第3波 | 第4波 | 第5波 | 第2〜5波 | 情報セル | 帯 |
|---|--:|--:|--:|--:|--:|--:|--:|:-:|
| 被弾変換が厚い | 100.0 | 97.5 | 97.0 | 84.5 | 64.0 | **85.8** | 4/4 | ○ |
| 被弾変換が薄い | 100.0 | 95.5 | 90.0 | 20.5 | 34.5 | **60.1** | 4/4 | ○ |
| ササ同席 | 100.0 | 82.0 | 68.5 | 40.0 | 30.0 | **55.1** | 4/4 | ○ |
| 動かす機構なし（陰性対照） | 100.0 | 99.5 | 80.0 | 0.0 | 0.5 | **45.0** | 3/4 | ○ |

**4台とも帯（40〜95%）に入る。** 埋め草は特性を1つも持たない素体（HP110 / 攻34・第143期の則）で、
敵の数値に触る駒（呪詛官ネル・萎縮のクビ）は入っていない。
土台の駒が「自分で動き出せるか」も済み——**供給はバサ1枚に寄せてある**ので、
第146期がハネ・セロで踏んだ穴（自分から移動を起こさない／後列で即 return）はこの期には無い。

**指示書が挙げた4台目「第五波が濃い台」は足さない。** 台はどれも5波すべてと戦うので、
**第五波は既に4台ぶん測れている**（台1 の第五波 64.0% は帯のど真ん中）——
編成を1つ増やしても波は増えない。指示書の狙い（殉教者が庇う／処刑が育つ）は
**§4-2 の計数を波ごとに出す**ほうで満たす。**陰性対照（台4）は残す**——
「バサを含まない台が ±0.0」は受け入れ条件そのものである。

## §3. 予測（**実装前に書き切った。外れても消さない**）

1. **段A は全台で大きく正**。第146期の「敵だけ **+42.3**」がそのまま出る側なので転倒版を上回る。
   **ただし天井に張り付く台が出る**（台1 は V0 が既に 85.8%）。
2. **被弾変換が厚い台は上がり幅が最も小さい**——敵の攻撃が敵に向くと**餌が減る**ので、
   混乱の得と被弾変換の損が相殺する。**転倒版より下がる可能性もある**（転倒は餌を減らさない）。
3. **ササ同席の台では供給に化けない**。混乱は敵→敵なのでササは殴られない
   （第146期の波ルール版＝味方も混乱する、とはここが決定的に違う）。
4. **第五波の効きは他の波より小さい**——殉教者が混乱した攻撃を庇い、同時に処刑が育つ（Q0-3）。
5. **墓守（リィカ）の層は積まれない**（敵が敵を倒すため）。第146期の予測5 は波ルール版の話である。
6. **確率のノブが効く**（第146期と違って供給が細い）。効かなければ回数制が効く。
   **どちらが効くかは予測しない——それがこの期の問いである。**
7. **バサを含まない行は ±0.0**。
