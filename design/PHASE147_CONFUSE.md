### Q0-1. 既存の2つのノブの形と、どちらに枝を足すか

実装から引いた現物:

| 型 | 場所 | 既定 |
|---|---|---|
| `ShufflerRule(bool Foes, ShuffleStagger Stagger)` | `Traits.cs:5945` | `(true, Advanced)`（第144期に採用） |
| `ShuffleStagger { None, Advanced, Both }` | `Traits.cs:5925` | — |
| `ConfusionRule(bool Active, int Percent = 100)` | `Traits.cs:8101` | `Active: false`（第146期・残置） |

**指示書の案 (i) を採る**——`ShuffleStagger` に `Confuse` を足す。理由は指示書 §0 のとおり
「同じトリガーに両方を載せない」で、**列挙にすれば択一であることが型で表現される**
（`Confuse` も「行が前に変わった敵だけ」に限るので `Advanced` と条件が同一＝列挙で並べられる）。

**`Both` との直交はしない。** `Both`（2体とも）は第144期に「方向が消えて『毎ターン敵の手番を2つ削る駒』になる」
として採らなかった上限測定用の値で、混乱側に同じ枝を作ると**測る前から採らないと決まっている版が1つ増える**だけである。
`Confuse` は `Advanced` と同じ「前に出た側だけ」に固定する。

絞りのノブは指示書どおり `ShufflerRule` 側に置く（`ConfusionRule.Percent` は波ルール用の残置なので流用しない）:

```csharp
public readonly record struct ShufflerRule(
    bool Foes, ShuffleStagger Stagger, int ConfusePercent = 100, int ConfuseUses = 0)
```

**`ConfuseUses` は「保持者（バサ）1体・1戦あたりに混乱を立てられる回数」**とする。0 は無制限。
**「1体につき N 回まで」（対象ごと）は採らなかった**——絞りたいのは供給の総量で、
指示書 §2 が「どちらも効かなければ**供給の口**（敵の入れ替えを2体→1体）」と続けている以上、
確率と同じ軸（総量）を振らないと2つのノブを比べられない（同じ帯・同じ台・同じ seed で比べるのが段B/B' の目的）。

### Q0-2. `StatusKeys.Confused` を立てる窓口は流用できるか

**できない。立て直す。** 第146期の窓口は `BattleEngine.cs:6309`（`SwapSlots` の `Notify`）で、
**動かした側の陣営を問わず全ての移動で立つ**——それは第146期が測って落とした形そのものである
（味方だけを動かす版の帰属は **−41.9pt**）。この期は `ShufflerTrait.Settle` の中、
**いま転倒を立てている場所**（`Traits.cs:6072` 付近）でだけ立てる。

**読む側は直す。** 現状の読み手2箇所は `Confusion.Active` を見ている:

| 場所 | 現状 |
|---|---|
| `BattleEngine.cs:4215`（`FoesOf`） | `if (Confusion.Active && attacker.RawCounter(Confused) > 0)` |
| `BattleEngine.cs:4229`（`ConsumeConfusion`） | `if (!Confusion.Active \|\| actor.RawCounter(Confused) == 0) return;` |

**ノブは「誰が立てるか」を決め、読む側は立っていれば従う**に直す。
ただし `RawCounter` を既定の経路で毎回引くのは避けたいので（`FoesOf` は1回の攻撃で複数回通る・
`compare` / `layout` は数百万戦を回す）、**`BattleContext.ConfusionLive`** を ctor で1回だけ計算する:

```
ConfusionLive = Confusion.Active || Shuffler.Stagger == ShuffleStagger.Confuse
```

これは「キーを立てうる経路が1本でもあるか」と同値で、短絡の作法（軛・受け流し）を壊さない。
**唯一の抜け穴は業（`ScapegoatTrait`）がカウンタを移す経路**だが、
あの駒は `UnitCatalog.All` に保持者 0 枚（第49期・残置）なので盤面には出ない。

### 予測4 が外れた理由（**構造的に立たない**）

**混乱するのは「前へ出た敵」＝たったいま前列に上がってきた駒**で、その駒が振るときの
`pool` は**自陣の前列**である。敵の前列は2枠しかないので、
**殉教者は「その1枠の目標そのもの」になるか、前列にいないかのどちらか**
——鎖の `f.Row == Row.Front && f != target` が両方を落とす。
一方で**処刑（第三波の `Hero`）は立つ**（0.07〜0.10 回/戦）——
あちらは前列の駒が一度後ろへ流されてから戻ってくる経路がある。

**指示書 Q0-3 の「第五波前3 も処刑」は実装と食い違っていた**——`UnitCatalog.Hero2` が持つのは
`TraitId.Condemn`（断罪）で、処刑は第三波の `Hero` だけ。**同じ「勇者候補」という名前の駒が波ごとに別定義**である。
