## 0. この期の主題

**隣接を条件にする機構が3期連続で「配置の判断」を生んでいない。** 原因を切り分ける。

| 期 | 機構 | 隣接の役割 | `reseat` の結果 |
|---|---|---|---|
| 41 | 突き返し（ハネ） | **コスト**（巻き込む数） | **角**が1位。20通り中19位まで角 |
| 42 | 集約（ウケ） | 利得（守れる範囲） | **中央**が上位4通り全部。ただし非隣接が +9.1pt 強い |
| 43 | 渡し（ワタ） | 利得（横取り範囲） | **中央**が上位8通り全部。横取り量がほぼ同じで隣接に帰属できず |

X字5枠は角4つが次数2・中央が次数4で、**中央は編成の全員に隣接する**。
だから隣接を利得にすれば必ず中央が、コストにすれば必ず角が正解になる。
**どちらも置き場所が一意に決まって、判断にならない。**

一方、設計メモは近隣加害型を
「**高い。配置そのものがパズルになる**」と分類の最高評価に置いている。
既存ロスターは近隣加害型を主軸に据えており、その判断は**一度も実測されていない。**

**この期で確定させる問い**は3つ。

- **Q1. 席に値段が付いているか。** `reseat` の上位と下位の幅がどれくらいあるか
- **Q2. その値段は編成によって変わるか。** ——**これが本題。**
  同じ駒が編成Aでは中央、編成Bでは角に行くなら、隣接は判断を生んでいる。
  全編成で同じ席なら、隣接はただの定数であって判断ではない
- **Q3. 原因は特性の設計か、盤面の形状か。** 隣接を読まない駒を対照に置いて切り分ける

**Q3 で「盤面の形状」に落ちた場合、この期の結論は
「近隣加害型を設計の主軸から外す」または「盤面の次数分布を変える」になる。**
どちらも大きい判断なので、**測ってから決める。この期では決めない。**

## 1. Phase 0（調査の設計を固める）

結果は報告書の冒頭に数字で書くこと。

1. **隣接・位置に依存する特性を全部列挙する。**
   `Traits.cs` を `AreAdjacent` / `Row\.` / `DepthOf` / `IsLanePredecessor` / `Slot` で grep し、
   クラス名の一覧を作る。**「隣接を読むもの」と「列を読むもの」を分けること**
   （前者がこの期の対象、後者は参考）。
   指示書の把握では隣接を読むのは 巻き込み・生贄・毒漏れ・囃し立て・火の粉・瘴気・棘守り・
   散開・呪詛の漏れ・突き返し・集約・渡し あたりだが、**数え直すこと**
2. **盤面の次数分布を数える。** `FormationRules.AreAdjacent` の表から、
   **編成5枠だけの次数**と**召喚枠込みの次数**を両方出す。
   指示書の把握では 2/2/4/2/2 と 4/4/6/4/4（第42期の前提の訂正3）。
   **次数の取りうる値が2種類しかないなら、それ自体がこの期の答えの一部**になる
3. **角4枚が互いに対称かを確認する。** 席番号のタイブレークは第40期に乱数化済みのはず。
   乱数化後も鏡像ペアに差が出るかを、**同一編成の鏡像2通りを `confirm` で比べて**確かめる。
   **対称なら、実質の選択肢は「中央か角か」の2択しかない**
4. **対象行と対照行を選ぶ。**
   - **対象**: 1 で列挙した隣接依存の駒を含む compare 行。**駒ごとに最低2行**。
     同じ駒が複数の編成に出ていることが Q2 の前提なので、
     **2行以上に出ていない駒はこの調査から外す**（外した駒と理由を書く）
   - **対照**: 隣接も列も読まない駒を含む行を**最低3行**。
     指示書の把握では ドルガ（`Sluggish`）・ムド（`Rage`）・ハギ（`Pursuer`）あたり。
     **対照が無いと「席が動かないのは隣接のせい」と言えない**
5. **`docs/balance.md` の現在値を控える**（48行 × 5波 = 240セル）。§4-1 の回帰チェックの分母

## 2. 実装（診断モード `seats2` を1つだけ）

**既存の `seats` / `reseat` を書き換えないこと。** 新しいモードを足す。

### やること

Phase 0-4 で選んだ行それぞれについて `reseat` 相当の探索を回し、
**駒ごとに「どの席に置かれたか」を集計する。**

| 列 | 中身 |
|---|---|
| 駒 | ユニット名 |
| 行 | その駒を含む compare 行の名前 |
| 最適席 | `reseat` 1位の配置におけるその駒のスロットと**次数** |
| 上位帯 | 上位5通りにおけるその駒の席の分布（例: 中央5 / 角0） |
| 幅 | **`reseat` の1位と最下位の勝率差**（＝席の値段の大きさ・Q1） |
| 仮置き順位 | 現在 `CompareBuilds()` に書かれている配置が何位か |

そのうえで**駒ごとに1行にまとめた表**を出す。

| 列 | 中身 |
|---|---|
| 駒 | ユニット名 |
| 隣接依存 | 有 / 無（対照は無） |
| 行数 | 調べた編成の数 |
| **席の分散** | **その駒が編成によって別の席に行ったか**（例: 3行中 中央3 → 分散なし / 中央2・角1 → 分散あり） |
| 幅の中央値 | Q1 |

**「席の分散」がこの期の主要な出力。** Q2 の答えそのもの。

### 実装上の制約

- **`docs/` に何も書かない。** 標準出力だけ
- **`CompareBuilds()` / `Stages` / `Columns` / `UnitCatalog` を触らない**
- **`reseat` の探索ロジックは既存のものを再利用する。** 別実装にすると
  「`reseat` で測ったこと」にならない
- **seed 帯を明示する。** 選定に使っている帯（0..199）で探索し、
  §4-3 の確認だけ 200..599 で取る

### 実行時間の見積もりと分割

**`reseat` は1行あたり数十秒かかる。** 対象が20〜30行なら20〜30分になり、
**1回のツール呼び出しに収まらない。**

- **駒ごと・行ごとに分割して複数回に分けて実行すること。**
  **背景に回さない**（刈られる）
- **中間結果をファイルに落として集計する**（`/tmp` などの作業領域。`docs/` には置かない）
- 各回の所要時間を報告書に書くこと

## 3. 判定基準（測る前に決めておくこと）

**測ってから基準を決めないこと。** 以下を先に固定する。

### Q1: 席に値段が付いているか

**幅（`reseat` の1位と最下位の勝率差）の中央値が 5.0pt 未満なら「値段が付いていない」。**

参考値: 第41期のハネは `confirm` で角と仮置きの差が +5.6pt、
第42期のウケは仮置きが21位だった。

### Q2: 値段は編成によって変わるか —— **本題**

**隣接依存の駒のうち、「席の分散あり」が半数未満なら「隣接は判断を生んでいない」。**

- 「分散あり」の定義: 調べた行のうち、**最適席の次数が異なる行が1つ以上ある**こと
  （中央=次数4 と 角=次数2 が混在する）
- 角どうしの入れ替わりは Phase 0-3 で対称と確認できた場合、**分散として数えない**
  （対称なら同じ席と見なす）

### Q3: 原因は特性か盤面か

- **対照（隣接を読まない駒）も分散していないなら、原因は盤面の形状。**
  席がそもそも編成によって変わらない盤面だということになる
- **対照は分散しているのに隣接依存だけ分散していないなら、原因は特性の設計。**
  隣接という条件が中央/角の二択に潰れているせい

**この切り分けが調査の結論。**

## 5. 結論の書き方（Q2/Q3 の出方ごと）

**この期では設計の方向を決めない。** ただし報告書には、
**判定の結果として何が残件になるか**を書くこと。

| Q2 | Q3 | 残件として書くこと |
|---|---|---|
| 分散あり | — | 隣接は値段になっている。**3期の失敗は機構個別の問題**なので、次に隣接機構を作るときの条件（どういう場合に分散したか）を書く |
| 分散なし | 特性の設計 | 隣接を「巻き込む数」「守れる範囲」のような**単調な量**にすると二択に潰れる。**単調でない読み方**（特定の駒がいるかどうか、隣の駒の型）が候補として残る |
| 分散なし | 盤面の形状 | **次数の選択肢が2値しかないことが原因。** 残件は「盤面の次数分布を変える」か「近隣加害型を主軸から外す」の二択。**どちらも大きいので、この期では提案だけ書いて決めない** |

**どの枝に落ちても、設計メモの「近隣加害型＝配置そのものがパズルになる（最高評価）」という
分類が実測でどう扱われるかを1段落書くこと。** この分類は一度も検証されておらず、
既存ロスターの主軸になっている。
