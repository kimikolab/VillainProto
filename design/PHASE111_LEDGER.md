## 7. 分かったこと

### 7-1. 情報セルは `compare` が使う帯で数えること

**第89期は正しい作法（情報セルを 2 以上に保つ最上位を採る）を正しく当てて、
`compare` が測る帯では情報セル 1 の席を採っていた。** 割れているのは第四波の 99.8% 対 100.0%
——**400 試行のうち1試行**。第77期の「`0 < x < 100` の情報セルは天井の際で不安定」は
seed の揺れの話として書かれていたが、**実際に効いたのは「どの帯で数えたか」のほう**である。

> **席の追試は帯B（200..599）でやってよい。情報セルは帯A（0..199）で数えること。**
> **`docs/balance.md` に載る値は帯A なので、そこで 1 なら、その行は勝率表の上で 1 セルしか情報を持たない。**

### 7-2. 「唯一の観測点」は規則を切って数えられる

指示書 (b) の「その行でしか観測できない機構が無い」は、これまで手で判定していた
（第109期の `刻み×澱み` は「ミオを含む他の4行がグザ同席」という個別の読み）。
**規則を1本ずつ切って `compare` の何行が動くかを数えると、同じ判定が機械で出る**
——実際、器具は**指示書が例に挙げた `刻み×澱み` を独立に拾い直した**（陽性対照）。

**特性の数え上げ（保持者が1行しかない特性）は下限。** 4 行のうち 3 行は一致するが、
**組み合わせでしか成立しない唯一性（`刻み×澱み`）は特性の数では引けない。**
**次に行を落とす期は、規則を切る側の表を先に出すこと。**

### 7-3. ノブを 0 にする前に、その 0 が実装のどこで読まれるかを確かめる

`RageRule { Mode = Amount, Gain = 3 }` の `Gain` は **`Mode == Count` のときしか読まれない**。
`Gain = 0` を「切った版」として並べると、**動いた行 0 が「その規則は誰にも効いていない」に見える。**
実際には `RageMode.Amount`（被弾量の半分で育つ）はそのまま走っている。
**「既定を1つ変えて何も動かなかった」を機構の話として読む前に、その引数が読まれる分岐を数えること。**

### 7-4. 手作りのずれは 16 例目 —— **指示書が場所を間違えた**

指示書 §4-7 は「**CLAUDE.md の**第109期 §9-1 の記述（『強化 × 手番は空白』）」を (T4) の対象にしているが、
**CLAUDE.md にその記述は無い。** 実体は `design/PHASE109_TOMO.md` §9-1 で、
「交差帯なら **強化 × 手番** …**第92期の交差の空白表にまだ無い組**になる」と書いてある。
これは2重に誤りで:

- **`Presets.Cross` には `強化×手番 (ガン×ドルガ×バン)` が既にある**（第92期の12行の #8）。
- **トモは手番の通貨を1つも書かない**——`TraitEntryMap.Supplies[Taillight]` は **強化（Ally）だけ**。
  譲渡は他人の手番を動かすが、`IdleTurn` を書くわけではない。

**トモは新しい交差ではなく、強化軸の新しい書き手**である。**行き先が `compare` なのはそのため。**
**CLAUDE.md は誤っていなかったので、CLAUDE.md 側で訂正するのは (T4) の記録だけになる。**

### 7-5. `cross quality` の理由の文字列が条件と合っていない（**直していない**）

交差帯の席の判定は `curV.Info >= topV.Info` で「1位が情報セルを**増やさない**なら据え置き」なのに、
表示は **「1位は情報セルが減る」**。今期の差し替えで両方 2 になり、**同数なのに「減る」と出た。**
**判定（据え置き）は規則どおりで正しく、間違っているのは文字列だけ。**
指示書 §6「既存の診断は1文字も書き換えない」に従って**直していない。** 次に `cross` を触る期で直すこと。
