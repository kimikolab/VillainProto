### Q0-2. 判定式が読むセルが情報帯に入るか（**第118期の申し送り2**）

**`run` を回す前に数えた**（`ward scan probe` ＝ 5台 × 24 点 ＝ 120 点の掃引）。

**同じ埋め草を5台に当てると、帯（40〜95%）に4台以上が同時に入る点は 24 点中 0 点だった。**
役割の駒（ゴルム・リィカ・ガルド）の強さが違うので、1つの目盛りでは揃わない。
**台ごとに別の点を採った**——比べるのは同じ台の中の版どうし（素体差し替え）なので、
台をまたいで埋め草を揃える理由が無い。選び方は「帯に入る点のうち情報セルが最大」。

| 台4 支援拒否 (ノチ×ガルド) | 18 / 90 | 100.0 / 98.0 / 100.0 / 93.5 / 4.0 | 73.9 | ○ | 3 |
| 台5 陰性対照 (ノチ非在席) | 14 / 90 | 100.0 / 98.5 / 42.5 / 88.0 / 44.5 | 68.4 | ○ | 4 |

### Q0-4. 被弾を読む既存の札と、預かりが積まれる位置

`Traits.cs` の走査で **`OnDamaged` が 14 枚・`OnAllyDamaged` が 1 枚**（仇討ち＝`AvengeTrait` だけ）。

| 札 | `OnDamaged` | `OnAllyDamaged` |
|---|---|---|
| `AvengeTrait` | ○ | ○ |
| `BraceTrait` / `CondemnTrait` / `GuardianTrait` / `HexTrait` / `LooseTrait` / `NourishTrait` / `RageTrait` / `RedirectGainTrait` / `SharerTrait` / `ShatterTrait` / `ThornGuardTrait` / `ThornsTrait` / `VenomTrait` | ○ | |

**預かりは `OnAllyDamaged` の段に積む**——`ApplyDamage` が `target.Hp -= amount` を走らせた**後**、
本人の `OnDamaged` が全部終わった後に、本人以外の生存チームメイトへ流れる通知。
この段に来る `target` は**実際に HP が減った駒**なので、
**肩代わりされた駒（HP が1点も減っていない）には積まれない**（指示書 Q0-4 の決定どおり）。

> **ここで指示書に無い答えが1つ出た。**
> **ガルド（`Stoic`）には預かりが積まれるが、1点も返らない。**
> 積むのはカウンタの直接の書き込みだが、返すのは `ctx.Heal` で、あの窓口は
> `AcceptsSupport` が偽なら入口で弾く。**ロスターで最も殴られる駒が、預けた分を全部
> 没収か残額にしかできない**——これは欠陥ではなく、条件4（符号が編成で反転するか）の
> いちばん濃い標本なので、**台4 として独立に立てた。**

### Q0-5. `Forfeit` の宛先

`ctx.Heal` を通す（指示書の要件）。`by` には**ノチ自身**を渡す。
`Heal` の帰属は `Mark.Owner`（いま実行中の特性の持ち主）で決まり、
`OnAllyDeath` は `BeginTrait(t.Id, ally)` の印の中で呼ばれるので、
**没収で敵に入った回復はノチの `HealOutOffTurn` に載る**。これは正しい——ノチの代金だからである。

### Q0-6. 死亡の経路は1本か

**1本。** `HandleDeath(` の呼び出しは `ApplyDamage` の中の **1 箇所だけ**で、
`BattleCore` 全体で HP を書く 7 箇所のうち **0 に落ちうるのは `target.Hp -= amount` だけ**。

| ファイル:行 | 式 | 0 に落ちうるか |
|---|---|---|
| BattleEngine.cs:5405 | `target.Hp -= amount;` | **○（`ApplyDamage`）** |
| BattleEngine.cs:5811 | `dead.Hp = 0;` | —（`HandleDeath` の中） |
| BattleEngine.cs:6003 | `target.Hp = Math.Max(1, hp);` | ×（蘇生のクランプ） |
| BattleEngine.cs:6478 | `target.Hp = Math.Min(target.MaxHp, target.Hp + amount);` | ×（`Heal`） |
| Traits.cs:1438 | `self.Hp = Math.Min(self.Hp, self.MaxHp);` | ×（継ぎ接ぎの最大HP半減） |
| Traits.cs:2603 | `self.Hp -= paid;` | ×（`Hp <= 1` で返り、`amount ≤ Hp − 1`） |
| Traits.cs:6745 | `if (self.IsAlive) self.Hp = self.MaxHp;` | ×（不死の器具・満タンへ戻す） |

毒・燃焼のティックも自傷も吸いも置き去りの削りも全部 `ApplyDamage` を通るので、
**`OnAllyDeath` は全経路で走る。没収は1箇所で足りる**（塞ぐ経路は無い）。

## 2. 予測（**実装前に書き切った**。外れても消さない）

**Phase 0 の答えが出てから、`UnitCatalog` と台の編成表を開いて数えて書いた。**

1. **`Burst` は `Drip` より時間を買う。** 返る量が同じでも、返るタイミングが被弾の山に同期するから。
   線は「4台中3台以上で `Burst` の味方生存T が `Drip` を上回る」。
2. **第三波（渇き）でこの駒は負ける。** 積むだけ積んで1点も返らない。
   線は「第三波の帰属が、その台の4波の中で最小か負」。**4台中3台以上**で成り立つ。
   （第118期の回復系3台が −58.0 / −20.0 / −10.5 だったのと同じ向き。）
3. **タンクと同席すると `Burst` の閾値到達が早い。**
   台1 のゴルム（巨躯・自分より後ろの列への攻撃を型を問わず肩代わり）は
   **5枚中1枚に被弾を集める**ので、台2（肩代わり 0 枚・被弾が5枚に散る）より
   **閾値到達回数／戦が多い**。線は「台1 の到達回数 ≥ 台2 の 1.3 倍」。
4. **`Forfeit` は台3（リィカ）でいちばん大きく出る。**
   リィカは `Sacrifice`（開戦時に隣接する味方を削る）＋ `Necro`（味方が倒れるたび育つ）で、
   **味方が倒れることが仕事**。没収量／戦は 台3 > 台1・台2。
   **符号は台1（タンク）で正・台3（死軸）で負**——これが条件4（この期の本丸）。
5. **台5（ノチ非在席）は5波すべて ±0.0。** `Burst` / `Drip` / `Threshold` を何に振っても動かない。
6. **`Percent` を上げても比は動かない**（第118期 §1-2 の再現）。掃引するのは `Threshold`。
7. **台4（ガルド）では返った量が 0 に近い。** `Stoic` が `ctx.Heal` を入口で弾くので、
   ガルドに積んだ預かりは**没収か残額にしかならない**。
   線は「台4 の `返した量 ÷ 積んだ量` が、台1〜3 の半分以下」。
