# 第259期 指示書 —— CLAUDE.md のコンパクト化（4,807行 → 400行・以後増えない構造）

読み手は Claude Code。このリポジトリ以外の文書は参照しない。盤面は1ビットも動かさない保守の期。

## 0. 位置づけ

`CLAUDE.md` は 4,807行・882KB。毎セッション丸ごと載るので読む側の注意が薄まり、各期の末尾追記でさらに太る。原因は「規則」と「履歴」の混在（上位4節＝現状値・コマンド・BattleContext・期別で全体の87%）。

第112期（実測 → `design/LESSONS_*.md`）・第160期（則の本文 → `design/RULES_*.md`）の先例と同じ手を残りに当てる。新しい仕組みは作らない。

**原則（新 CLAUDE.md の冒頭に書く）**: 毎セッション必ず要るもの以外は置かない。履歴は `design/` へ、本文は索引で引く。

## 1. 決定済みの論点（この期はこの前提で進める）

1. **上限は 500行 / 50KB。書き直しの目標は 400行**（余白100行＝門に毎期引っかからないため）
2. **コマンド表は手書きのまま `design/COMMANDS.md` へ逐語移動**。`sweep list` からの生成化は**廃案**——`sweep` の知識源がこの手書きの表そのものなので、生成は循環する（§2-2）
3. **期別の表は全部 `design/PHASE_INDEX.md` へ（CLAUDE.md 常駐 0行）**。「直近N期だけ残す」はしない——毎期のローテが新しい雑用＝肥大経路になる。現状値ブロックの「最後に動かした期とその1行」で足りる
4. **門は `audit` に置く**。pre-commit hook はこの環境で使っていない

## 2. Phase 0（実装前の調査。結果を報告書に書く）

1. **`Sweep.cs` の読み方の確定**: コマンド表のどの書式（行頭・インデント・`<...>` / `[...]`）をパースしているか。読み先を `design/COMMANDS.md` に変えたとき、表を逐語で移せば `sweep list` が同一出力になることの確認方法を決める（移動前に `sweep list` の出力を保存しておく）
2. **CLAUDE.md を読んでいる器具の棚卸し**: `grep -rn "CLAUDE.md" BattleSim BattleCore`。少なくとも (a) `Sweep.cs`（表のパース・読み先変更が必要） (b) `Shock.cs` / `Formation2.P201.cs`（リポジトリルートの目印に使うだけ・ファイルは残るので無害） (c) `derive rules` の `CLAUDE.md / LESSONS` 列（索き先の確認）
3. **コード内コメントの引用の棚卸し**: `CLAUDE.md「…」` の形で文言を引用しているコメント（`Stacks.cs`「ctx.Heal を呼ぶのは9経路」・`Time.cs`・`Grade.cs`・`Relay.cs`・`Brace.cs` ほか）。各引用先の文が移動後どのファイルに行くかの対応表を作る
4. **節境界の確定**: 見出し構造で各節の行範囲を確定し、§3 の行き先と突き合わせる（行番号ではなく見出しで切る）

## 4. 「今後増えない」ための門

1. **`audit` に1項目**: `CLAUDE.md` が 500行 または 50KB を超えたら ×（戦闘0回・即時）。警告として「`本目` / `第\d+期に.*足した` が N 件以上」も数えて出す（R151 の機械化・こちらは × にしない）
2. **新 CLAUDE.md に追記の規則を書く**: 期が CLAUDE.md に書けるのは (a) 変わった規則 (b) 現状値ブロックの差し替え、の2つだけ。期の一行は `design/PHASE_INDEX.md` の末尾へ、測定の中身・予測の○×・踏んだ穴は `design/PHASEnnn_*.md` と `LESSONS` へ

## 5. 手順

1. 節ごとに見出し構造で切って新ファイルへ逐語で移す（行番号で切らない・R015）
2. **照合スクリプト**: 旧 CLAUDE.md を空行区切りの段落に割り（BOM・前後空白は正規化）、各段落が新ファイル群＋新 CLAUDE.md のどれかに逐語で含まれるかを数える。**0件落ち**が条件（第112期に1行落ちた前例）。スクリプトは使い捨てにせず `design/` 直下か報告書に貼る
3. 新 CLAUDE.md を書く（§3 の「残す」＋ §4-2 の規則＋冒頭の原則）
4. `Sweep.cs` の読み先変更・`derive rules` の索き先確認（壊れるなら `design/RULES_INDEX.md` 等を索き先に足す）
5. Phase 0-3 の対応表に従い、コード内コメントの `CLAUDE.md「…」` を移動先のファイル名に機械的に直す（文言自体は変えない）
6. `docs/rules.md` を再生成して差分を見る（CLAUDE.md の列が動くはず・既定値の列は動かない）

**コミットは3つ**: (i) 移動＋`Sweep.cs` 読み先（差分が「消えた行＝増えた行」になる・sweep list 同一出力） (ii) 新 CLAUDE.md の書き直し＋コメントのポインタ修正 (iii) audit の門。

## 6. 受け入れ条件

- 照合スクリプトで段落の落ち **0件**
- `wc -l CLAUDE.md` ≦ 500・ファイルサイズ ≦ 50KB
- **`sweep list` の出力が移動前後で全行一致**（本数・行とも）
- `compare` 305セル 0件・`audit` ずれ 0件（新しい門を含む）・`derive rules` 再生成で既定値の列が動かない
- `grep -rn "CLAUDE.md「" BattleSim BattleCore` の各引用が、指す先のファイルに実在する（Phase 0-3 の対応表どおり）
- 新しいセッションが CLAUDE.md だけを読んで `design/` の該当ファイルへ辿り着ける（索引の1行が全部ファイル名を持つ）
