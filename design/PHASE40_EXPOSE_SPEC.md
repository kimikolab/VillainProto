## 0. この期の主題

**敵から味方へ「状態」を書く経路を初めて作る。**

現在のロスターを数えると、敵から味方へ状態を書く経路は**断罪（`Condemn`）1つだけ**で、
しかも「反撃してきた相手を痺れさせる」という条件付きである。一方で味方側には
**入力を資産に変換する読み手**が揃っている（被弾強化・逆しま・澱み喰い・軋み・責め苦・移り木）。
つまりロスターは**読み手を持っているのに、敵からの供給源だけが存在しない。**

ここに**移動**を撒く敵を1体置く。移動を選んだのは、読み手の在庫が最も多く（下表）、
かつ**同じ1つの規則で駒の符号が反転する**ため。

| 撒く状態の候補 | 味方側の直接の読み手 | 敵側からの供給 |
|---|--:|--:|
| 弱体化（`AtkBonus` を負に） | **1**（逆しま・ウツ） | 0 |
| **移動（`SwapSlots`）** | **3**（後衛特化・軋み・移り木） | 0 |

移動はさらに、**列・隣接に依存する特性を同時に動かす**（§1 Phase 0 で数える）。

### 符号が反転する例（この期の狙いそのもの）

- **損をする側**: 後列に隠した支援役が前へ引き出される。巨躯・後備え・庇うの列条件が崩れる
- **得をする側**: 押し出された前列の駒に `HasFallenBack` が立つ（セロの後衛特化が起動する）。
  ヨミ（軋み）は動かされるほど強くなり割り込む。シオ（移り木）は動かされた味方を癒し強化する

### 波に置く理由と場所

**第五波・中央**に置く。理由は3つ。

1. 第五波の課金資源は現在「単体攻撃への依存」（殉教者）**1本しかない**。2本目を足す
2. 第3波 × 第5波 の相関が盤全体で最大（+0.58）。**片方の波に相手が持たない関門を足す**のが
   相関を下げる筋（相関を下げるのは共有資源の削除ではなく非共有資源の追加）
3. 軋みの割り込みは**ターン外の行動**なので第二波の粛に封じられる。第五波なら生きる

中央を選ぶのは渇き・軛・粛と同じ理由——**どちらの列を貫いても必ず通る**位置だから。
第五波の中央は現在 `Knight2`（巡礼騎士 71/15/7・単体）で、ここを差し替える。

## 2. 実装

### 2-1. 特性 `TraitId.Expose`（曝き）

`Traits.cs` の**盤面ルールのブロックには入れない。** 逆位・渇き・軛・粛は両陣営に等しくかかるが、
曝きは**敵陣の駒を動かす一方向の効果**なので、敵側の語彙のプラス特性として扱う
（殉教・断罪・施しと同じ場所）。

```
Expose,      // 曝き: 攻撃したあと、敵陣の後列でいちばん無傷な駒を、前列でいちばん傷ついた枠へ引き出す
```

**発火点は `OnAfterAttack`。** ターン頭の無条件発火（`OnTurnStart`）にしないこと。理由は2つ。

- 保持者の手番に紐づくので、**保持者を早く割れば止まる**という勾配が自己言及的に立つ
  （渇き・軛・粛と同じ狙い）
- 攻撃はそのまま行うので、**同数値の対照に対する差分が特性1つだけに閉じる**（§4 の対照が成立する）

### 2-2. 挙動（決定的に書く。乱数で選ばない）

保持者が攻撃を1回終えるたびに、以下を1回だけ実行する。

1. **引き出す駒**: 敵陣（＝保持者から見た相手チーム）の生存駒のうち `Row == Row.Back` のもの。
   その中で**現在HPが最も高い1体**を選ぶ
2. **引き出す先**: 同じ陣営の生存駒のうち `Row == Row.Front` のもの。
   その中で**現在HPが最も低い1体**を選ぶ
3. どちらかが 0 体なら**何もしない**（ログも出さない）
4. `ctx.SwapSlots(引き出す駒, 引き出す先のスロット)` を1回呼ぶ
5. `ctx.Log` に `LogKind.Trigger` で1行残す（誰を誰と入れ替えたか）

**なぜ「最もHPが高い後列」なのか**: いちばん無傷な駒＝いちばん隠れている駒だから。
**なぜ「最もHPが低い前列」なのか**: いちばん先に落ちる枠へ出すことで矢面の意味が最大になるから。

**この2つは決定的な規則にすること。** 乱数で選ぶと「何に課金したのか」が分離できなくなる。
プレイヤーが「後列でいちばん無傷な駒が出される」と読めることが、この機構の価値の半分を占める。
同値が並んだ場合のみ、既存の `PickOne` の慣習に従う。

**`SwapSlots` に手を入れないこと。** 移動の通知（`OnMoved` / `OnAllyMoved`）・
`HasFallenBack` の記録・イベントの発行は既に `SwapSlots` の中で正しく行われている。
`SwapSlots` はチーム非依存（`self.TeamId` で占有者を引く）なので、
敵の特性から味方側の駒に対して呼んでよい。

### 2-3. 強度のノブ `ExposeRule`

```
public readonly record struct ExposeRule(int MaxPerBattle)
{
    public static ExposeRule Default => new(0);   // 既定は無効
}
```

- `MaxPerBattle` = 1戦あたりの引きずり出しの上限回数。`0` で完全に無効
- `BattleEngine.Run` の引数に足す（`ColossusRule` / `YokeRule` / `HushRule` / `MartyrRule` と同型）。
  **書き換え可能な static のノブは置かない**（Trait は共有シングルトン・並列実行するため）
- 回数は保持者ではなく**戦闘単位**で数える。保持者が複数いても合算する

**このノブは盤面の総HPを1も動かさない**ので、掃引しても対照は1本で足りる。

### 2-4. 保持者 `EnemyCatalog.Accuser`（告発人）

```
// 第五波の中央に置く。巡礼騎士（Knight2）と数値・型・速さが1つも違わない。
// 差分は曝きを1つ足しただけ——渇き・軛・粛・殉教と同じ形で、対照を成立させるため。
public static readonly UnitDef Accuser =
    Make("accuser", "告発人", 71, 15, 7, TraitId.Expose);
```

`Knight2` は `Make("knight_v", "巡礼騎士", 71, 15, 7)`（単体攻撃・特性なし）。
**HP・攻撃力・速さ・攻撃パターンを1つも変えないこと。** ここを変えると
「壁が効いたのか規則が効いたのか」の切り分けに追加測定が要る。

### 2-5. 波への配置

`Stages[4]`（第五波 / 異端審問団）の `center` を `Knight2` → `Accuser` に差し替える。
**前1（殉教者）・前3（勇者候補）・後1（審問官）・後3（槍騎兵）は触らない。**

```
new Stage("第五波 / 異端審問団",
    Formation.Build(front1: Martyr, front3: Hero2, center: Accuser, back1: Seer, back3: Lancer))
```

`Knight2` の定義は**削除せず残す**（差し替えて盤面が元に戻ることの対照になる）。

## 3. 診断モード `expose`

`BattleSim` に追加する。**出力は `docs/` に置かない**（標準出力で読むだけ）。
`CompareBuilds()` / `Stages` / `Columns` を触らないこと。

数えるもの（44編成 × seed 0..199 / 第五波のみで足りるが、全波で出せるなら出す）:

| 列 | 中身 |
|---|---|
| 曝き | 引きずり出しの発火回数/戦 |
| 空振り | 後列または前列が 0 体で何もしなかった回数/戦 |
| 出された駒 | 引き出された駒の名前と回数（上位3体） |
| 戻り | 引き出された駒が味方の手で後列へ戻った回数/戦（喧噪・棘守り・臆病の経路） |
| 後退 | `HasFallenBack` が新たに立った回数/戦 |
| 軋み | ヨミの `OnMoved` 起点の割り込み回数/戦 |
| 移り木 | シオの `OnAllyMoved` 起点の回復回数/戦 |
| 後衛特化 | セロが「後退済み かつ 後列」を満たしていたターン数/戦 |

**発火しなかったことは盤面の値に痕跡を残さない**ので、ログか `Events` の文字列から数えること。

**陽性対照を必ず1つ置く**: `ExposeRule(0)`（無効）での同じ計数。
曝き = 0.00 になることを確認してから有効時の数字を読む。

## 4. 予測（実装の前に書き、報告書に当否を載せる）

**軸の名前ではなく、窓口を通る駒の在庫で書くこと。** この機構の窓口は
「**敵陣の後列（後1・後3）の生存駒**」と「**前列（前1・前3）の生存駒**」の2つ。

実装の前に、以下を `docs/balance.md` と編成表から引いて書き出す。

1. **44行それぞれについて、後列に何枚置いているかを数える**。後列 0 枚の行は空振りするので
   ±0.0 になるはず。**この行数が「動かない行の予測値」**になる
2. **読み手3枚（セロ・ヨミ・シオ）を含む行を数える**。何行あるか。
   主判定17行のうち `隊列崩し (バサ×ヨミ×セロ)` と `突き出し (セロ×ヨミ)` の2行は確実に当事者
3. **巨躯（ゴルム）を含む行を数える**。巨躯は「自分より後ろの列にいる味方」を庇うので、
   引き出されて列が変わると守備範囲が変わる。指示書の把握では傷軸6行すべてが巨躯を土台に持つ
4. **後備え（セッキ）を含む行**。後列の味方への攻撃を肩代わりするので、
   守る相手が前へ出ると窓が閉じる
5. **符号が反転する行を1つ以上名指しする**（得をする行と損をする行を1行ずつ）

**予測を外したら、外した理由を報告書に書く。** 当てることではなく、
どの量を見落としていたかを記録することが目的。

6. 第3波 × 第5波 の相関が +0.58 からどう動いたか（狙いは低下。**上がったら必ず報告する**。

7. 第五波の固有の勝者・敗者の数（現在: 勝者 0 / 敗者 5）。
   **定義は「厳密版（=100 / =0）」と「90/10 の緩い閾値」のどちらを使ったか毎回書く**
8. 中間帯（開区間 (0,100) のセル数）と標準偏差の増減。現在: 中間帯 22 / SD 40.1

### 掃引（必須の 1〜4 を通ってから）

**各点に対照は不要**（このノブは盤面の総HPを1も動かさない）が、

## 6. 実装上の注意（既知の落とし穴）

1. **席番号のタイブレークに偏りが残っている。** エンジンにスロット番号順のタイブレークが2箇所あり、
   後退先が常に 後1 に寄る。**鏡像は同値ではない**（鏡像ペア253組に実測で差が出ている）。
   引きずり出しはこの偏りを初めて表に出す可能性がある。
   **`expose` の「出された駒」の分布が 後1 側に偏っていたら、それは規則の性質ではなく
   このバグの可視化かもしれない**ので、報告書で切り分けること
2. **乱数列はずれる。** `SwapSlots` の `PickOne` は候補が2個以上のとき `Roll` を消費する。
   「介入の鎖に段を足しても乱数はずれない」は候補0個・1個のときの話で、ここでは成り立たない。
   規則を有効にした測定は**乱数がずれた別の世界**との比較になるので、
   帰属は必ず**同数値の対照（`Knight2` に戻す）との差**で取ること。前後比較で帰属しない
3. **`SwapSlots` は入れ替えであって一方向の移動ではない。** 引き出された駒が前へ来る代わりに、
   前列の駒が後ろへ下がる。これは仕様（下がった駒に `HasFallenBack` が立つのが
   符号反転の片側）だが、**「後列が空く」わけではない**ことを予測に織り込むこと
4. **召喚枠（スロット5〜8）を対象にしない。** `Row.Back` には召喚枠の ○後2（スロット8）も
   含まれる。仕様として含めてよいが、**含めたかどうかを報告書に明記**すること。
   指示書の推奨は「含める」（実態があるなら盤面の一部として扱う、という既存の判断と揃う）
5. **長時間ジョブはフォアグラウンドで1ツール呼び出し内に収める。** 背景に回すと刈られる。
   所要の目安: `compare` 約8秒 / `spread` 約22秒 / `ablate`（全編成）約26秒

## 8. この期で決めないこと

- 弱体化を撒く敵（読み手が逆しま1枚しかないので、**相方が増えてから**）
- 引きずり出しを味方の駒として持つ形（まず波で規則の効き方を測ってから駒に移す）
- 傷の拡散（別の残件。移動とは独立）
- 第四波・第二波への横展開（第五波で符号反転が確認できてから）
- 数値バランス全般。**多少強すぎる・弱すぎるは許容する。**
  基準3（下限 40.0%）は「明らかに成立しなくなるレベル」の歯止めであって調整目標ではない
