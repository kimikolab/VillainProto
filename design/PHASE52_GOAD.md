### 0-2. 標（`Marked`）の書き手と engine の窓口

- **書き手は1枚**: 囃し立て（`MarkerTrait`・ヒサ）。`OnBattleStart` で**開戦時1回**、隣接する最大HPの味方。
- **消し手は1枚**: 逸らし（`DivertTrait`・ソラ、第50期）。`OnTurnStart` で味方の標を全部 0 に。
- **engine の窓口**: `BattleEngine.cs:1254`（`SelectTargetChain`）。`MarkPullPercent = 75`。

**式（第50期・この期の予測に使う）:**

    p_t + (1 − p_t) × 0.75      p_t = 無作為の主目標が既に標持ちである確率

`marked != target` の但し書きがあるため 75% は下限で、味方5体なら
`p_t = 1/5 = 0.20` → 実効 **0.20 + 0.80 × 0.75 = 0.80**。
**敵の単体振りの約 80% が標持ちへ向く**（素体では 20%）＝ **被弾は約4倍**。

**鎖の順序は 標 → 後備え → 庇う → 殉教 → 棘守り で、標がいちばん先。**
引いた瞬間 `return` するので、**標は庇い・後備え・殉教をすべて飛び越す**
——指示書 §0 の「肩代わりの網に吸われない」はコードで確認した。
**`foes` から選ぶ（`pool` ではない）**ので、後列の標持ちも前列を飛び越して狙われる。
**単体攻撃にしか効かない**（薙ぎ・全体・貫きは標を1ビットも見ない）。

### 0-3. ヒサ・ソラとの干渉 —— **発火順は席番号（速さではない）**

`BattleEngine.cs:2342`:

    foreach (UnitState u in ctx.AllUnits.Where(x => x.IsAlive).ToList())
        foreach (Trait t in u.Traits.ToList())
            t.OnTurnStart(ctx, u);

`ctx.AllUnits` は `Add` の順＝**味方をスロット昇順に並べた後、敵**（`Materialize` は
`Formation.Occupied()` ＝スロット昇順）。**速さも乱数も一切入らない。**

したがって:

- **ソラの席がカリより後ろ**（スロット番号が大きい）→ カリが付けた標をその手番のうちにソラが剥がす（**打ち消し**）
- **ソラの席がカリより前** → ソラが剥がした後にカリが付け直す（**標は残る**）

**ヒサは `OnBattleStart` なので順序の問題が無い**。ヒサの標は第1ターン以降も残り、
カリは自分の前ターンの対象からしか外さないので、**同居すると標が2枚立つ**
（`p_t = 2/5 = 0.40` → 実効 `0.40 + 0.60 × 0.75 = 0.85`。総量は増え、1体あたりの取り分は薄まる）。

## 予測（実装の前に書いた。当否は §当否 に）

1. **1戦で渡す量.** 発火＝カリの生存ターン数×1。カリは HP62/攻4/速9 で中央（庇いの内側）
   に置くので **発火 5〜8 回/戦**、渡した量 `4 × 発火` ＝ **20〜32/戦**。
2. **対象の最終攻撃力.** `駆り立て (カリ×ドルガ)` は ドルガ 38 + 4×発火 → **60〜70**（第5波は短いので ~50）。
   `駆り立て改 (カリ×死軸)` は ゴルム 10 + 4×発火 → **~38**。
3. **`Boost` の掃引.** 標の危険は `Boost` に依存しないので**打ち消しは起きず、全幅は素直に開く**。
   予測 **5pt 以上**（B0 → B6 で単調増加）。開かなければ「渡した力がダメージに変わっていない」。
4. **対象の被弾増.** 第50期の式から実効 **80%**（素体 20%）＝**約4倍**。
   しかも**標は庇い・後備え・殉教を飛び越す**ので肩代わりで軽くならない。
   予測 **被弾増 +60〜+120 / 戦**。
5. **早逝と効きの収支.** 予測 **効き +10〜+40（小さい正）／早逝 −1.5〜−3.0T**。
   **勝率では代金が勝つ**——`駆り立て (カリ×ドルガ)` は機構の帰属（B4 − 素体）が
   **−5〜−20pt** と予測（ドルガが唯一の出力なので、それを殺すと台が崩れる）。
6. **2行の符号.** `駆り立て改 (カリ×死軸)` は**死ぬことが資産**なので帰属は **0〜+10pt**。
   → **2行の符号は分かれる**（基準8）。
7. **ソラとの打ち消し.** 席順で `標消え` が **0 と発火数近く**に割れる（Phase 0-3）。
   ソラが後ろなら代金だけ消えて見返りだけ残るので**勝率は上がる**はず。
8. **ウツとの干渉.** `ウツ` 回数 ≈ **1.0/戦（初回だけ）**で自己修正。ウツの与ダメは素体版より下がる。
9. **`seats2` の席.** カリは隣接を読むが**「隣に何人いるか」ではなく「隣に誰がいるか」**を読む
   （第45期のヒサ型）ので、最頻率は **60〜85%**。方向は**中央**
   （次数4なら候補が増えて最高攻撃力を確実に掴める＝利得型）。
10. **第二波の 100.0% の行数.** カリは粛の非対象だが `駆り立て (カリ×ドルガ)` はザンを含むので
    行としては課金される。**22 行から動かない**と予測。

## 結論 —— **採用した。ただし害と見返りが入れ替わった。**

機構は完全に動く。帰属は **`駆り立て (カリ×ドルガ)` で +38.9pt**（別 seed 帯 +39.1pt）で、
**第47期の鱗（+11.7 / +16.2）も第50期の逸らし（+25.6 / +27.2）も上回る、直近で最大の値**。

**ただし設計の意図とは逆になった。** 指示書は「標＝代金 / 強化＝見返り」で設計したが、実測は:

| | `駆り立て (カリ×ドルガ)` | `駆り立て改 (カリ×死軸)` |
|---|--:|--:|
| **代金の値段**（B4 − 標なし。**標の寄与**） | **+36.8pt** | **−10.0pt** |
| **見返りの値段**（B4 − 力なし。**強化の寄与**） | +3.3pt | +4.2pt |
| 機構の帰属（B4 − 素体） | **+38.9pt** | −1.6pt |
| 体の値段（素体 − 4体） | +1.8pt | +15.1pt |

**代金として設計した標が、価値のほぼ全部を作っている。**
見返りとして設計した強化は 3〜4pt の添え物で、掃引の全幅（4.8 / 6.0pt）とほぼ同じ大きさしかない。

`ScapegoatRule` の Threshold のように機構を殺すノブではないので棄却の理由にはならないが、
**「害の中に見返りを埋める」という設計目標は、達成の仕方が逆だった**——
埋まっていたのは害の中の見返りではなく、**見返りの皮をかぶった害の側の価値**である。

### **配置探索は機構ではなく代金を 0 にした**（第49期の業改との違い）

同じ5枚・同じ機構で、席だけが違う2つの版:

| | 仮置き（カリ中央 / ドルガ後3） | 採用席（ドルガ前1 / カリ後1） |
|---|--:|--:|
| 平均勝率 | 42.5% | **60.9%** |
| 機構の帰属（− 素体） | +1.0pt | **+38.9pt** |
| **代金の値段（− 標なし）** | **−12.5pt** | **+36.8pt** |
| ★ドルガの **効き** | **−76.1** | **+0.3** |
| ★ドルガの **被弾増** | +7.1 | **−0.6** |
| ★ドルガの **早逝** | **−2.91T** | −0.40T |
| 仇討ちのザンの効き | +45.9 | **+68.2** |
| 発火 | 3.69 | 3.40 |

**代金の符号が席だけで −12.5 → +36.8 と入れ替わる。**
理由は engine の鎖の性質にある——**標の代金は「前列が生きている限り後列は狙われない」を
破ることから来る**（`SelectTargetChain` の標の段は `pool` ではなく `foes` から選ぶ）ので、
**もともと前列にいる駒を押し出せば代金がほぼ消える**（被弾増 −0.6・早逝 −0.40T）。

**第49期の業改は「機構の発火を 0 にする席」を選んだが、今回は「代金だけを 0 にして
機構は残す席」を選んだ。** 前者は測定が壊れるので採ってはいけないが、後者は正当な配置解
——だから `confirm` には `発火` と `空振り` の**両方**の列を出し、
**発火が落ちた候補（1位・4位）だけを外した。**

**指示書が立てた「効き（対象の出力増）と早逝（対象の死）の収支」という枠は、
この駒については枠のほうが外れていた。** 枠が働くのは代金を払っている席のときだけで
（仮置きでは 効き −76.1 / 早逝 −2.91T と教科書どおりに出た）、
**代金が消える席を選ぶと、収支は対象からいなくなって読み手へ移る。**

## 4. 標の符号は「読み手がいるか」で決まる（この期の一般則）

## 6. 干渉（潰さずに記録する）

### 6-1. ソラ（逸らし）—— **順序に依存する。ただし `標消え` では読めない**

| 版 | 平均 | 帰属（− 素体） | 標消え |
|---|--:|--:|--:|
| ソラが**後**（カリ中央 / ソラ後3。標が同じ手番に剥がされる） | 55.5% | **+4.5pt** | 2.36 |
| ソラが**先**（ソラ前3 / カリ中央。標はその手番を生き延びる） | 49.4% | **−5.6pt** | 2.18 |

**`標消え` は2つの席順を区別できなかった**（2.36 対 2.18）。
理由は測り方にある——`GoadMarkLost` は「**次の発火の時点で**前ターンの対象に標が無いか」を
数えるが、ソラは**どちらの席順でもカリの次の発火より前に1回走る**ので、カリから見れば
標はどちらでも消えている。**違いは「その手番のあいだ標が効いたか」で、そこは勝率にしか出ない。**

> **順序に依存する打ち消しを数えるカウンタは、「消えたか」ではなく
> 「効く窓のあいだ立っていたか」を数えないと順序を検出できない。**
> 診断のコメントに但し書きとして残した（修正はしていない——
> 勝率の差 6.1pt が同じことを、余分な計数を足さずに測っている）。

### 6-2. ウツ（逆しま）—— **カリはウツの呪いを「治して」殺す**

`逆しま (ネル×ウツ)` を土台にしたローカル台（`CompareBuilds()` は触らない）:

| **帰属** | 0.0 | −3.5 | −0.5 | **−98.0** | 0.0 | **−20.4** | **−99.2** |

**ウツの与ダメが 127.7 → 28.5 と 78% 落ちる。** 第4波は 98.0% → 0.0%。

**潰さない。** 同じ通貨が駒によって逆符号になる実例で、

## 10. 実装の判断（コードに残した選択）

1. **強化側に窓口を新設しなかった**（Phase 0-1）。既存 14 箇所と同じく `AtkBonus` を直接叩く。
2. **候補は `AcceptsSupport` で絞った**（指示書に記述なし。縛め＝`BindTrait` に揃えた）。
   **1つの動作なので標と強化で候補集合を分けない**——力を渡せない相手（ガルド）は押し出しもしない。
3. **強化は累積・標は付け替え。** 前ターンの対象の `Marked` を 0 にしてから今ターンの対象に 1 を立てる。
   前ターンの対象は `Counters["goadTarget"]` に `InstanceId + 1` で覚え、
   **`OnCarryOver` で必ず捨てる**（執着の `FixateTrait.MemoryKey` と同じ理由）。
4. **選択は `CurrentAttack`**（素の `Def.Attack` ではない）。強化が積むと選択が固定されるのが設計意図で、
   **逆しま（ウツ）だけが自己修正する**（§6-2）。
5. **`GoadRule` は `Run` に引数で渡す。static のノブは置かない**（`Trait` は共有シングルトン・
   `layout` は戦闘を並列実行する）。
6. **`GoadRule.Mark` はノブではなく対照**（`DivertRule.SelfMark` と同型。既定は常に `true`）。
7. **engine に規則を1つも足していない。** 標の窓口は第50期までに揃っているので、
   `OnTurnStart` で `Marked` と `AtkBonus` を書くだけで済んだ。
   engine 側の追加は**計数フック（`NoteGoadFire` / `NoteGoadIdle`）だけ**で、盤面には触らない。

## 11. 残件

- **A. 標の側にノブが無い。** `Boost` の全幅は 4.8 / 6.0pt に対して標の寄与は +36.8 / −10.0pt。
  強度を触るなら `Mark` の 2値ではなく**確率**にする必要がある（`MarkPullPercent` を
  駒ごとに上書きする形か、付ける頻度を落とす形か）。**この期では決めない。**
- **B. `GoadMarkLost` は順序に依存する打ち消しを検出できない**（§6-1）。
  直すなら「効く窓のあいだ標が立っていたか」を数える必要があり、
  それは engine の行動順ループに計数を足すことになる。**勝率の差で足りているので直していない。**
- **C. ヒサとの同居を測っていない。** Phase 0-3 で「標が2枚立つ」ことは確認したが、
  `p_t = 0.40` の版は測っていない（`CompareBuilds()` に入れるとヒサの2行が動く）。
  指示書 §9 の「ヒサを `All` から外すかどうか」と一緒に別の期で。
- **D. 標の読み手が仇討ち1枚しかない。** §4 の一般則（読み手がいれば収入・いなければ代金）は
  **n = 1 の読み手で立てている**ので、2枚目の読み手が出るまでは仮説。
