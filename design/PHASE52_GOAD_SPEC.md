## 0. この期の主題

**「味方を盾にする」駒を、貢献する形で作る。**

設計の出発点は囃し立てのヒサ（44/攻2/速10）だった。ヒサは
`PlusText` が「隣接する味方1体に敵の攻撃を集中させる」——**プラス欄に書いてあるのが味方への害**で、
発火は開戦時1回・対象は「隣接する最大HPの味方」に固定。**盤上で何も起きず、拾う理由が無い。**

対して縛めのクグ（54/攻3/速10）は「毎ターン味方1体を縛る」という害の中に
**「その味方の攻撃+16」**が埋まっている。害と見返りが同じ動作から出るので、
`縛め収入型 (クグ×バン×ガン)` という行が主判定に立っている。

**この期で作るのはクグ側の構造である。** 矛先を集めると同時に、
**集めた相手に力を渡す**。乱暴だが前線を作る駒にする。

### 設計原則として記録すること

**マイナスは編成のフックであって、その駒を入れる動機ではない。動機は別に要る。**

味方を犠牲にするだけの駒は、盤面を弱くするので打点で釣り合わせても
「入れるほど損」になりやすい。**害の中に見返りを埋めるのが、この盤面で機能している唯一の形**
（クグが前例）。

### この駒が踏まない穴（第50・51期の実測から）

| 穴 | 内容 | この設計が避ける理由 |
|---|---|---|
| **粛**（第二波） | 介入機構は封じられる。0.0% の7行は全部カド持ち | `OnTurnStart` は行動順の**外側**。介入ではない（Phase 0-5 で確認） |
| **肩代わりの網**（5枚） | 「狙われる」系のマイナスは網に吸われる（第50期のソラ） | 標は**攻撃が発生する前の選択段**で働く。網が走る前に相手が決まっている |

## 3. 実装

### 3-1. 特性 `TraitId.Goad`（駆り立て）

```
Goad,        // 駆り立て: 隣のいちばん殴れる味方を前に押し出し、自分の力を全部渡す。
             // 押し出された側は狙われる（1つの動作の表と裏。クグの縛め＋攻撃+16 と同じ構造）
```

**プラス・マイナスのどちらのブロックにも入れない。**

#### 発火点 —— `OnTurnStart`

1回の発火で以下を順に行う。

1. **選ぶ**: 隣接する生存味方のうち、**`CurrentAttack` が最も高い1体**。
   同値が並んだ場合のみ `PickOne`。隣接に生存味方がいなければ**何もしない**
2. **標を付ける**: 選んだ相手の `Marked` を 1 にする
3. **力を渡す**: 選んだ相手の `AtkBonus` に `Boost` を加算する

**選び方を「最高攻撃力」にするのは意図的。**

- **一番殴れる駒を前に出す**という判断が1行で説明できる
- ヒサ（最大HP）と対象条件が違うので差別化される
- **強化するほどその駒が選ばれ続ける**ので、**強化と危険が同じ1体に集中する**。
  前線が1枚できる代わりに、その1枚が死ぬ

#### 強化は累積させる

**毎ターン加算し、対象が変わっても前の強化は消さない。**

- 上限を数値で切らないこと。**天井は戦闘長**（第41期の突き返し・第47期の鱗と同じ）
- 標は毎ターン付け替える（前ターンの対象から外し、今ターンの対象に付ける）。
  **強化は残るが標は移る**——「一度渡した力は返らないが、矛先は移る」

#### マイナスに特別な実装は不要

- 標を集めた味方は狙われて死ぬ（`MarkPullPercent = 75`）
- **隣に誰もいなければ何も起きない**（自己完結しない）
- カリ自身の打点は低い（§3-3）。**貢献は他人を強くすることなので、自分が強い必要がない**

**代金を軽くする細工をしないこと。** 押し出した相手への被害を肩代わりしたり、
標の効果を弱めたりすると、押し出しが無償の強化になって符号が反転しなくなる。

### 3-2. 強度のノブ —— **候補を2つ挙げる。Phase 0 の後に選ぶこと**

| 候補 | 定義 | 何を切るか |
|---|---|---|
| **A: `Boost`** | 1回に渡す攻撃力（掃引 2 / 4 / 6） | **見返りの大きさ。** 標の危険は `Boost` に依存しないので、**打ち消しが起きにくい** |
| B: 標を付けるか | 代金の有無（対照として 有/無） | 危険の寄与。**掃引ではなく2値**なので対照 |

**指示書の推奨は A。** ただし **B は対照として必ず1本測ること**——
「強化を配るだけ」と「矛先も集める」を分離できないと、
この駒がクグ型（害の中に見返り）なのか単なるバッファーなのかが判定できない。

第50期は「効きを13.5pt動かしたのに全幅1.2〜1.6pt」という**打ち消し型の空振り**だった。
`Boost` は強化を増やすが標の危険を増やさないので、**打ち消しは起きにくいはず**。
予測（§5-3）でそれを確かめてから確定すること。

```
public readonly record struct GoadRule(int Boost)
{
    public static GoadRule Default => new(4);
}
```

`BattleEngine.Run` の引数に足す（既存の各 `Rule` と同型）。**static のノブは置かない**。

### 3-3. 駒 `UnitCatalog.Kari`（駆り立てのカリ）

```
Id = "kari", Name = "駆り立てのカリ", MaxHp = 62, Attack = 4, Speed = 9,
Traits = { TraitId.Goad }, Pattern = AttackPattern.Single
PlusText  = "毎ターン隣のいちばん殴れる味方に自分の力を渡す（攻撃力が上がり続ける）"
MinusText = "渡した相手を前に押し出すので、その味方は狙われる。隣に誰もいなければ何もできない"
Flavor    = "前に出ろとしか言えない。言い方を知らないだけで、渡せるものは全部渡している。"
```

数値は探索段階の初期値。**掃引の対象はノブ1つだけ**で、HP・攻・速は振らない。
攻4 と低いのは、**貢献が他人を強くすることだから**である。

### 3-4. compare への追加 —— **2行**（隣に置く駒を変える）

```
("駆り立て (カリ×◯)", ...)      ← 高攻撃力の駒を隣に置く台
("駆り立て改 (カリ×◯)", ...)    ← 死軸の台（押し出された駒が死ぬことが資産になる）
```

- **2行の狙いは「渡す相手の性格を変えること」。**
  硬くて殴れる駒に渡せば前線ができ、柔らかい駒に渡せば死ぬ。
  **同じ駒が編成で符号を変えるか**を見る
- 相方は Phase 0-4 の攻撃力分布から選ぶ。**ドルガ（攻38・HP85）が第一候補**だが、
  カリが選ぶのは `CurrentAttack` なので、**強化が積むと選択が固定される**ことに注意
- **予算壁に注意。** カリは攻4 の払い出しなので、土台は打点を持つ駒で組むこと
- 配置は §1 の作法で決める。**採用した席で発火回数が 0 になっていないことを確認する**

**既存52行は1つも触らない。**

## 4. 診断モード `goad`

`BattleSim` に追加する。**出力は `docs/` に置かない**。
`CompareBuilds()` / `Stages` / `Columns` を触らないこと。

| 列 | 中身 |
|---|---|
| 発火 | 駆り立ての発火回数/戦。**0 になっていないこと**（§1 の作法） |
| 空振り | 隣接に生存味方がいなくて何もしなかった回数/戦 |
| 対象 | **誰に渡したか**の内訳・**対象が何回入れ替わったか** |
| 渡した量 | `AtkBonus` の累積付与量/戦 |
| **効き** | **対象が実際に与えたダメージの増加量**（対照との差） |
| 被弾増 | **標が原因で対象が余分に受けた被弾**（推定） |
| 早逝 | 対象が倒れたターン（対照との差） |
| ウツ干渉 | ウツを隣に置いた版で、強化が逆しまの半減側に落とした回数 |
| ソラ干渉 | ソラと同居した版で、標が打ち消された回数 |

**「渡した量」と「効き」を分けること。** 第42期は「生成したアーマー」ではなく
「実際に吸った量」、第43期は「流した量」ではなく「効き」、第47期は「貫き」ではなく
「後列到達」、第49期は「転写」ではなく「転写の効き」、第50期は「焦点」ではなく
「撃破順」で判断した。**渡した量は成果ではない**——
対象が渡した直後に死ぬなら、`AtkBonus` はダメージに変わっていない。

**「効き」と「早逝」を対で見ること。** この駒の本質は
**「強くなるが死にやすくなる」**なので、収支がどちらに振れるかが性格を決める。

**陽性対照を3本置く**:
1. 同数値・特性なしの素体（**ノブを 0 にする形は使わない**）
2. `GoadRule` の候補B「標を付けない」版（危険の分離）
3. カリを外した同じ編成

**発火しなかったことは盤面の値に痕跡を残さない**ので、ログか `Events` から数えること。

## 5. 予測（実装の前に書き、報告書に当否を載せる）

第44・46・47・49期は4期連続で「供給が実際に流れるか」を数え損ねて外し、
第50期は「代金が代金にならない」（肩代わりの網に吸われる）を外した。
**今回は代金が網の外にあるので、外すとしたら別の理由になるはず。**

実装の前に以下を書き出す。

1. **1戦で渡す `AtkBonus` の総量。** 発火はカリの生存ターン数 × 1。
   **カリは攻4・HP62 なので狙われにくいが、範囲攻撃では死ぬ**。何ターン生きるか
2. **対象の最終攻撃力**を波ごとに計算する（素の攻撃力 + `Boost` × 発火回数）
3. **`Boost` を上げたときに打ち消しが起きるか。**
   標の危険は `Boost` に依存しないので、**掃引の全幅は素直に開くはず**。
   開かなければ「渡した力がダメージに変わっていない」ことになる
4. **対象の被弾増。** 第50期の式 `p_t + (1 − p_t) × 0.75` から、
   標を持った駒が受ける攻撃の割合を計算する
5. **早逝と効きの収支。** 対象が早く死ぬぶん、渡した力の何割が無駄になるか
6. **ソラとの打ち消し**（Phase 0-3）。同居すると何も起きなくなるか
7. **ウツとの干渉**（Phase 0-6）。ウツを隣に置くと、
   カリの強化が逆しまの半減側に落として**ウツを弱くする**はず
8. **`seats2` で2行の席**（参考値。カリは隣接を使うので、
   第45期の隣接依存の最頻率85%に近づくはず）

**予測を外したら、外した理由を報告書に書く。**

## 7. 実装上の注意（既知の落とし穴）

1. **強化側に窓口を新設しない**（Phase 0-1）。既存の強化と同じく `AtkBonus` を直接叩く。
   窓口を作るなら既存の全経路を監査する独立した作業になる
2. **`OnTurnStart` の発火順。** ソラも `OnTurnStart` で標を操作するので、
   **どちらが先に走るかで結果が変わる**。engine の実装を確認し、
   **順序に依存する挙動であることを報告書に明記する**
3. **強化は累積、標は付け替え。** 実装を取り違えると挙動が変わる
4. **ウツへの強化は害になる。** `PerverseTrait` は `AtkBonus` が正だと攻撃力半減。
   **潰さずに測る**（同じ通貨が駒によって逆符号になる実例）
5. **選択は `CurrentAttack` で行う。** 素の `Def.Attack` ではない。
   **強化が積むと選択が固定される**のが設計意図（強化と危険が1体に集中する）
6. **ヒサとの重複。** ヒサは開戦時1回・最大HPに標。カリは毎ターン・最高攻撃力に標。
   **同居させると標が2枚になる**。第50期の式（`p_t + (1 − p_t) × 0.75`）が
   2枚のときどう働くかを確認すること
7. **乱数列がずれる。** `PickOne` は候補2個以上で `Roll` を消費する。
   帰属は**素体との対照**で取る
8. **長時間ジョブはフォアグラウンドで1ツール呼び出し内に収める。** 背景に回さない
