## §A. (T1) —— `刻み×縫い (ノミ×ハリ)` → `刻み×澱み (ノミ×ミオ)`

### A-1. 指示書の候補2枚は、どちらも既存行の作り直しにしかならない

`刻み×縫い` は {ドルガ, ゴルム, ノミ, ヴェル, **ハリ**}。ハリの席に入れると:

| 候補 | 出来る5枚組 | 判定 |
|---|---|---|
| 抉りのエグ | {ドルガ, ゴルム, ノミ, ヴェル, **エグ**} | **`刻み×抉り (ノミ×エグ)` と一文字も違わない**（席だけ違う） |
| 断ちのナタ | {ドルガ, ゴルム, ノミ, ヴェル, **ナタ**} | **`刻み×断ち (ノミ×ナタ)` と一文字も違わない**（席だけ違う） |
| **澱みのミオ** | {ドルガ, ゴルム, ノミ, ヴェル, **ミオ**} | **一意** |
| 継ぎ当てのノノ | {ドルガ, ゴルム, ノミ, ヴェル, **ノノ**} | 一意（ただし下の理由で不可） |

第39期が `裂き×縫い (キリ×ハリ)` を**冗長**（`裂き` と r = +0.978）として落としたのと同じ形になる。

### A-2. ミオを採った理由は1つ —— **敵の傷を読む読み手が他にいない**

傷の読み手は5枚（エグ・ナタ・ハリ・ミオ・ノノ）。ハリを除き、重複せず、
**この行の意図（「ノミが刻んで、読み手が読む」）を保てる**のはミオだけ。

**ノノの繕いは患者が必ず同陣営**（`TraitEntryMap.Reads[Mender] = (傷, Ally)`）なので、
**ノミが敵に刻んだ傷を1つも読まない。** 5枚組としては一意だが、行の主題が消える。

ミオは傷を**毒**に変える3段を1行に載せる:

    着火（`IgniteRule`・第89期・既定 on）  「傷を持ち毒を持たない敵」に毒 1 を置く
    滲み則（`SoakRule.Poison`・第90期）    「傷を持つ相手には毒が +1 深く入る」
    澱み本体（`AmplifierTrait`）           毎ターン敵の毒を +4 層

しかも**この行はグザ（瘴気）を含まない初めてのミオの行**である。
第87期は「ミオを含む4行が全部グザ同席で、キリ／ノミとの交わりは 0 行」なので着火が
構造的に 0 回（毎ターン敵全体に毒が撒かれていて「毒を持たない敵」が存在しない）と測っていた
——**その空白がこの1行で埋まる。**

## §C. (T3) —— `TaillightTrait` の実装と、Phase 0 で決めた3点

> **PlusText**: 毎ターン、自分を除いて最も遅い味方に灯をともす（攻撃力 +5・累積）
> **MinusText**: 灯は1体にしか灯らない。対象が変わると前の灯は消える。
> 自分の手番より前に敵が倒れていたら、灯した味方に手番を譲る。自分は動けない

| | 値 |
|---|--:|
| MaxHp / Attack / Speed | **54 / 0 / 3** |
| Pattern | 単体（`Actions = [Skill]` なので**実質使わない**） |
| Traits | `Taillight` 1つ |

**発火口は3つ**——`OnTurnStart`（灯す）／ `OnAction`（譲る）／ `OnAnyDeath`（敵が倒れたターンを記録）。
**engine の判定は1つも足していない。** `WhetRoute` を1本と再入ガード（`BattleContext.Yielding`）だけ。

### C-1. `AtkBonus` の触り方 —— **点灯は窓口、消灯は直接**

**点灯は `ctx.Whet(pick, 5, WhetRoute.Taillight)`。**
他者強化の**供給の観測は `Whet` の中の1行にしか無い**（`NoteCarry` の強化キー・`BattleEngine.cs`）。
`AtkBonus` を直に足すと、`derive scan` からも `whet` / `carry` / `spend` からも**この駒が見えなくなる**
——第94期に手写しの表で 29 件の誤りが出たのと同じ穴に、実装の側から入ることになる。

**消灯は `ctx.Dull` を通さない。直接引く。** 理由は2つ:

1. **`Dull` は集約（ウケ）と転嫁（ワタ）の横取りが立っている窓口**なので、通すと
   **「自分の灯を消した」が第三者の破片や敵への弱体に化ける**——尾灯が書くつもりのない通貨を書く
2. 受け手は**素の攻撃力より弱くなっていない**（自分が配ったぶんを引き上げただけ）ので、
   **弱体の供給者として数えるのは事実に反する**

**前例は墓守の層の引き直し**（`NecroTrait` の `AtkBonus += desired - applied`）で、
あちらも「自分で積んだ自分のボーナスの再計算であって強化ではない」として両方の窓口を通していない。
**4つ目の通貨（第106期 (T1)）の観測点は `AtkBonus` の setter** なので、**消灯もそこでは符号を問わず数えられている**
——「窓口だけを見ると自己強化の9本がまるごと落ちる」という第106期の判断がそのまま効いている。

> **系: 通貨の「供給」は窓口で、通貨の「量」は setter で数える。配ったものを引き上げる機構は、
> 供給としては1回・量としては2回（+ と −）現れるのが正しい。**

### C-2. 1ホップ —— `BattleContext.Yielding`

`Encoring` / `Relaying` / `Shoving` と同じ形の再入ガード。**`Trait` の static に置いてはいけない**
（Trait は共有シングルトンで `layout` は戦闘を並列実行する）。

**トモ1枚では往復しない**（譲った相手が敵を倒すと `OnAnyDeath` がそのターンの印を立て直すが、
トモの手番はもう終わっている）が、**2枚同席すると互いに譲り合って無限に往復する**ので構造で止めた。
実測で **82 回**止まっている（(f) の台・200 戦）。

手番の譲渡そのものは**第104期に切り出した `ctx.TakeTurn` をそのまま使う**
——「通常攻撃をもう1回」ではなく**手番まるごと**なので、灯した相手が `Actions` を持っていれば術も溜めも乗る。

### C-3. 帳簿を持つ特性との衝突 —— 無い

- **`UnitState.WhetReceived` は消灯で減らさない。** 第67期の明文の規則（「閾値は**累積の床**であって
  在庫ではない」）どおりで、`Dull` が減らさないのと同じ扱い
- **境界（`Engagement.CarryOver`）とは `OnCarryOver` で灯の累計も捨てて衝突を避ける。**
  境界は `AtkBonus` を一括で 0 に戻すので、灯の累計だけ持ち越すと次の戦闘で**二重に引く**
  ——第102期に墓守（`NecroTrait`）が踏んだ形の裏返し
- **横流し（`FunnelTrait`）とは干渉しない。** `Whet` は横流しが宛先を差し替えうるが、
  **保持者のヌキは `All` に居ない**ので `FunnelActive` が立たず、灯の帳簿と実際の受け手はずれない。
  **横流しをロスターへ戻すなら、帳簿を受け手側へ移す必要がある**（コードの doc に明記した）

### C-4. その他の設計判断

- **自分は対象外**（第84期以降の原則）。含めると「速さ3 の自分が最も遅い」局面で灯が自分に落ち、
  供給者と受け手が同じ駒の上で重なる（第96期のムドと同じ形）
- **候補は自前で `AcceptsSupport` 濾しする（隣へ漏らさない）。** 駆り立て・縛め・移り木・火選りと同じ側。
  `SupportTargets` で漏らすと**「灯は1体にしか灯らない」という規則そのものが破れる。**
  支援拒否（ガルド）が最も遅い側にいる局面では、**それを飛ばして次に遅い味方**へ灯る（自己検査 (b) で実測）
- **`ctx.PickOne` を使わない**（第89期 (h)）。同速は**席番号の昇順**で決定的に割る
- **上限を数値で書かない。** 灯は累積するが、**対象が変わると消える**ことと**決着が 3〜7 ターン**であることで
  構造的に止まる。**ただし第104期の反省（「上限は壊れてから付ける」の根拠は付ける前に数え直す）に従い、
  第109期で数え直すこと**

### C-5. 確認用の診断 `taillight`（指示書 §4 の「最小の確認用モード」）

**測定ではない**（第109期に `tomo` を作る）。トモは `Presets` のどこにも入っていないので、

| (b) 一意（ゴルム3 が最遅） | 6.1 | 20.5 | 9.0 | 0.55 | 0.98 | 0.01 | **1** | 0 |

### C-6. 器具の直しが2つ（**どちらも照合の側で、盤面ではない**）

1. **`ctx.Log` は先頭の空白を落として `LogLine.Indent` に分けて持つ**（`BattleEngine.Log`）。
   消灯の行から駒名を切り出す位置が **4 文字ずれていて**、(c)(c')(d) の3つが落ちていた。
   **直すと3つとも通る。** 落ちていたのは実装ではなく検査のほうだった
2. **(c)(c') は「トモ1枚の台」でだけ判定する。** この照合は**駒名をキーにした帳簿**なので、
   **同名のトモが2枚いると2つの灯を分離できない**（2枚とも同じ「最も遅い味方」を照らすと
   帳簿に両方の灯が混ざり、片方が消した量＝自分のぶんだけ と食い違う）。
   **表A で (f) の台にだけ ずれ（消の照合 105 件 / 収支 81 戦）が出ていることが器具の限界であることの証拠**
   ——1枚の台 600 戦では **ずれ 0 件**

> **同じ `UnitDef` を2枚置く台では、駒名をキーにした帳簿が使えない。**
> 分離が要るなら `InstanceId` を持つ計数（`UnitTally`）の側で数えること。
