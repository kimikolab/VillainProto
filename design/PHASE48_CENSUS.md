## 0. 前提の訂正

指示書の前提とリポジトリが食い違った点。**止めずに進めた**（指示書の指示どおり）。

### (1) 残り枠は「3枚前後」ではなく、分母の取り方で **3 と 5 に割れる**

指示書 §0 は「味方の `UnitDef` は現在49前後なので、残りは3枚前後」としている。
実測は **定義49 / `UnitCatalog.All` は47**で、差の2枚は 胞子（`spore`）と 驕りのオゴ（`ogo`）。
**この2枚を分母に数えるかどうかで残り枠が 3 と 5 に割れる**（判断は §8）。

### (2) 表D（一度も compare に載っていない駒）は **空になる**

指示書 §3 は表Dを「事実上すでにリストラされている駒」と位置づけ、
§4-9 で「compare に載っていない かつ 唯一性もない」駒を統合・転職の第一候補としているが、
**`All` の47体は全員が `CompareBuilds()` の50行のどこかに出ている**（最少はハネ・ハリ・ホタ・
ナタ・ササ・シオ・ウケ・ワタの1行）。**味方側では母集団が空**になる。

代わりに**敵側に21体の未使用駒がある**（`census` の付表3）。指示書は敵を主表に入れることを
求めているので、敵側の同じ集計を表D' として出した。

### (3) CLAUDE.md の「毒 6書き/4読み」等は**呼び出し箇所の数**で、駒の数ではない

CLAUDE.md 第47期の節にある「7キーの内訳は 毒 6書き/4読み・標 1/1・痺 7/1・燃 1/1・
IdleTurn 3/2・破片 2/0・傷 4/4」は `SetCounter` / `Counter` の**呼び出し行数**を数えたもの
（毒の6は 毒撃2 + 瘴気2 + 澱み1 + 疫1、痺の7は 痺れ1 + 怯み1 + 責め苦1 + 抉り1 + 断罪1 + 縛め2）。

**表Aは駒で数える**（表Bが駒単位で、表Cがそこから引かれるため）ので、値が一致しない。
どちらが正しいという話ではなく、**単位が違う**。表Aの各行に呼び出し箇所数も併記した。

### (4) `Traits.cs` だけを grep すると、窓口が engine 側にある機構が落ちる

指示書 §1 の判定式（`ctx.Dull(...)` を呼ぶ / `Counter(StatusKeys.X)` を読む）を

### (5) §1 の判定語（空白/薄い/適正/飽和）は10通貨のうち **2つを覆っていない**

破片（書き手3・読み手1）と 傷（書き手4・読み手4）は、4語のどれにも当てはまらない。

- 空白 = 書き手か読み手が 0 → 該当しない
- 薄い = 書き手・読み手ともに 1〜2 → 書き手が3以上なので該当しない
- 適正 = 書き手1〜2 かつ 読み手2〜3 → 同上
- 飽和 = 書き手か読み手が 5 以上 → 該当しない

**語は測る前に固定したので変えていない。**「該当語なし」として表Aに出してある。

## 1. 数え方（測る前に固定した規則）

指示書 §1 の判定式に、上記 (3)(4) を塞ぐ規則を3つ足した。**足したのはここだけで、
判定式そのものは変えていない。**

1. **単位は駒**（`UnitDef`）。呼び出し箇所ではない。同じ駒が複数の経路で書いても1と数える。
2. **窓口が engine にある機構は、engine 側の1行をその駒の書き/読みとして数える。**
   肩代わり・据え・横取りは駒ごとのフックでは書けないので、`Traits.cs` だけの grep では落ちる。
3. **自分が書いた値の読み直しは「読み」に数えない。** 対象は3種——
   read-modify-write（裂きの `Counter(Wound) + Wounds`）／ログのための読み直し（毒撃）／
   二重適用のガード（縛めの `Counter(Stun) == 0`）。
   **消費は「書き」に数える**（断ちの `SetCounter(Wound, 0)`・澱み喰いの `SetCounter(Poison, 0)`）
   ——盤面の値を変えているので。

**兼ねる駒は両方に数える**（表Bで「書く通貨」「読む通貨」の両方に出る）。
`All` に載っていない2体（胞子・オゴ）は**表Aの数から外した**（表Bには別枠で載せてある）。

## 8. 残り枠の計算（§4-6）

### 判断: **分母は `All` の47。残り枠は 5。**

理由は2つ。

1. **胞子（`spore`）は編成に置けない。** `Ephemeral` で、`Formation` に配置する手段が
   コード上どこにも無い（分裂の召喚先としてしか `Add` されない）。
   **「プレイヤーが選べる札」を52枚に制限するという話なので、選べない駒は札ではない。**
2. **驕りのオゴ（`ogo`）は第46期に測って棄却済み。** `All` にも `CompareBuilds()` にも
   載っておらず、診断 `overbear` のローカルからしか参照されない
   （誹り・逆位・まどろみと同じ「対照として残置」の扱い）。
   **棄却した駒を席に数えると、棄却のたびに残り枠が減る。**

**ただしオゴは「予約席1」として控える。** 驕りは機構が棄却されただけで、
`ogo` という駒（HP/攻/速/名前/文言）は再利用できる形で残っている。
残り5枠のうち1枠を新規で使うか、オゴを転職させて使うかは**選択肢が2つある**という意味で、
**残り5のうち1は既に素材がある**。
