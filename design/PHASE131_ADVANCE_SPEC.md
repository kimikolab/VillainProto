### 0-1. 踏み込みの札とは何か

ポンの要望:

> 駒が近接攻撃か遠距離攻撃かを定義しておいて、それに従って戦闘中の演出を変えたい。
> 演出と言っても**敵の目の前まで移動して攻撃して戻るか、移動せずその場から攻撃するか**くらい。

**engine に距離の概念は無い。** 攻撃の到達は**席**と `AttackPattern`（前列規則・薙ぎの列・貫きの経路）で
完全に決まっていて、射程という軸は存在しない。**だからこの札は判定に一切影響しない。**

**定義は「その場から動くか動かないか」**にする（ポンの決定）。
「遠距離＝遠くから届く」ではなく「**踏み込まない**」という演出の言葉そのものにする。
これにより:

- **攻撃しない駒**（ヒヨ「贔屓が手番そのもの」）も**踏み込まない側**で筋が通る
- `Immobile`（カド）・`Pursuer`（ハギ）のような「自分では動かない」駒も迷わない
- **2値で足りる**（列挙にする必要がない）

### 0-2. 割り当ての基準 —— **1文から引く**

> **その駒は行くのか、来られるのか。**

2枚で確かめてある:

| 駒 | | 1文の根拠 |
|---|---|---|
| 追い打ちのハギ | **踏み込む** | 「同じターンに続けて**踏み込む**ほど自分が傷つく」／「止めを刺した者の背後から**現れる**」 |
| 仇討ちのザン | **踏み込む** | 「殴った者へ**割り込んで**刃を返す」 |
| 棘鎧のカド | 踏み込まない | 「**自分からは決して攻撃しない**」／「**命令しても動かない**」 |
| 軋みのヨミ | 踏み込まない | 「**その場で**割り込んで攻撃する」 |

反撃（カド）は**相手が来た**ので踏み込まない。追撃（ハギ）・割り込み（ザン）は**自分が行った**ので踏み込む。

### 0-3. **敵にも付ける**

`EnemyCatalog` も同じ `UnitDef` を使うので、札を足せば敵も対象になる。

これは演出の都合ではなく**必要**である。ポンの指摘:

> カドが中衛・後衛で被弾してカウンターでその場で棘を刺すと、**棘が届いていない感**が出る。

**カドが動かないのが問題ではなく、殴りに来た敵が来ていないのが問題。**
敵の近接（城塞の重装兵・戦斧兵・槍騎兵ほか）がカドの前まで踏み込めば、
**カドは1歩も動かないまま接触した絵になる**——一文（「命令しても動かない」）を壊さずに解ける。

### 0-4. **演出側の制約（この期で決めて、指示書に残す）**

巻き込みは**席**で決まる（薙ぎ＝標的と同じ列の全員＋中央／隣接＝席の隣接）。
**踏み込みを入れると、席で決まる効果と絵の位置がずれる。**
ボルグが前に出て薙ぎを振ると、巻き込む味方は**ボルグが離れた後の元の席の隣**になる。

> **踏み込みは「主目標への一撃」だけの演出にする。**
> **席で決まる効果（巻き込み・隣接・伝播）は、席の位置で描く。**

踏み込みは**勢いの表現**であって当たり判定の表現ではない、という割り切り。
**これを先に決めておかないと、後から全部の駒の演出を直すことになる。**

**この制約は `DemoApp` 側（Codex の担当）への申し送りなので、`design/PHASE131_ADVANCE.md` に明記する。**
**この期に `DemoApp` は1行も触らない。**

## 2. 予測（実装の前にここに書いてある。後から書き換えない）

### P0 —— 台本も勝敗も1ビットも変わらない

札は**誰も読んで分岐しない**。**`compare` の 305 セルは `docs/balance.md` と 0 件差分**で、
**`docs/` の全再生成で差分は `units.md` の1列だけ**になるはず。
**それ以外が動いたら止めて報告する。**

### P1 —— 割り当ては1文から引ける。**判断に迷う駒は5枚以下**

§0-2 の基準（行くのか、来られるのか）で、**52枚のうち迷うのは5枚以下**のはず。
**6枚以上迷ったら基準が足りない**ので、迷った駒を全部挙げてポンに回す。

### P2 —— 踏み込まない側のほうが少ない

**既定を「踏み込む」にして、踏み込まない駒だけを列挙する**のが短いはず（§3-1）。
撒く・繕う・呪う・囃す駒と、`Immobile` / `Pursuer` / `Displaced` の駒を足して **15〜20枚**程度。
**25枚を超えたら既定の向きが逆**なので、その旨を報告する。

### P3 —— 敵は型と素直に一致する

貫き（狙撃手）・全体（詠唱兵・審問官）を持つのは**敵の踏み込まない側だけ**になるはず。
**「遠くから広く届く」という絵の文法が敵側で成立している**ことの確認になる
（味方の常時の貫き・全体は0枚）。

### 3-1. 段1 —— 札

`UnitDef` に**表示専用のプロパティを1つ**足す。

- **`bool`**（列挙にしない。§0-1 のとおり2値で足りる）
- **既定は「踏み込む」**（P2。`required` にせず既定値を持たせれば、既存の52＋敵の定義を1つも壊さない）
- **名前に判定上の意味を持たせない。** `IsMelee` は「近接＝射程が短い」と読まれる余地がある——
  **射程は engine に存在しない**。`Advances`（踏み込むか）のような**演出の言葉のままの名前**にする。
  最終的な名前は Claude Code が決めてよいが、**「距離・射程・間合い」を含む名前は使わない**
- **どの規則もこのプロパティを読まない。** 走査して**参照件数が定義と出力だけ**であることを示す（A4）

**`docs/units.md` に1列足す**（`dump` の側を直す。**手で編集しない**）。
**Q0-1 で自己検査が壊れると分かった場合は、`units.md` に列を足さず**、
`docs/` に別ファイルを新設する（第126期の `quality.md`・第128期の `stock.md` と同じ判断）。
**`docs/balance.md` は1文字も触らない。**

### 3-2. 割り当て

**Claude Code が1文から案を出し、報告書に全件を並べる。ポンが確認する。**

- **根拠を1行ずつ書く。** 「◯◯（1文の該当箇所）」の形。**根拠が書けない駒は迷った駒として別枠にする**（P1）
- **味方52枚 ＋ 敵の全件**（Q0-4）
- **既定は「踏み込む」なので、実際に書くのは踏み込まない駒だけ**（P2）
- **迷った駒はポンに回す。勝手に決めない**

### 3-3. 段0 —— 則の取り込み

第128〜130期で立ったもののうち、**まだ `CLAUDE.md` / `LESSONS` に入っていないもの**を入れる。
**既に入っているものは重複させない**（Phase 0 で確認する）。

候補:

- **上限を持つ波に固定量の継続ダメージを持ち込むと、上限の外側だけが素通りで効く**（第130期）。
  燃焼 6/T は `burnTick` なので軛の 25 に一度も触れない。**今後 `軛` に何かを持ち込むたびに効く**
- **型ごとに上限との相性が逆を向く**（第128期）。
  全体は1発が大きいほど切られる量が増えるので**軛と最も相性が悪い**。
  **硬い1体には効かず、柔らかい複数体に効く**
- **鍵が他人依存の駒は、時間を買っても働かない。要るのは時間ではなく鍵の供給**（第129期。
  延命台の密度が鍵の種類と並んだ。トメ ×0.55 ／ ハギ ×0.72）
- **鍵を増やす先を間違えると総出力が下がる**（第130期。
  乗算の受け手から倍率の無い駒へ実効を移した）
- **「延命と相性が良い」と「延命すれば働く」は別**（第129期。
  ハギは延命で密度が上がる唯一の駒だったが、素の密度は下から3番目だった）
- **予測が読む量が、実装のどこから来るかを1回たどる**（第130期。
  主判定にホタの燃焼率を置いたが、ホタは自分に配らないので定数だった。
  第129期の「分母が2つあった」と同じ形）
- **起点は枚数ではなく供給の頻度で数える**（第130期。
  `BlazeRule` の既定が `Both` なので起点は2枚だったが、
  ゾトは `OnDeath` で 1.00回/戦なので「毎ターン供給する起点は1枚」は残った）

**入れる先（`CLAUDE.md` の節か `LESSONS_101_.md` か）は Claude Code が既存の形に合わせて決めてよい。**
**索引の実在しない参照先を増やさないこと**（第112期に16件見つかっている）。

## 7. この期では決めない・記録して次期へ渡すもの

1. **ボルグの倍率案（第132期の第一候補）。**
   `StatusKeys.Burn` を読んでいるのは **ホタ（自分が燃えている）とヒヨ（味方が燃えている）の2箇所だけ**で、
   **敵が燃えていることを読む駒が1枚も無い**。ボルグは唯一の常時着火役なのに、撒いた火に価値が無い。
   案: **「燃えている敵を薙ぐと威力が上がる」**。
   - 着火と発揮が1ターンずれるので自給にならない（間に敵が落ちれば無駄になる）
   - 薙ぎなので複数体に届き、「燃えている敵が何体いるか」が威力になる
   - **倍率を持つので、ヒヨの `+gain` が乗算で乗るようになる**
   - **順序が重要**: 倍率が先。倍率ができてから `EmberRule.On`（第130期の残置）を測り直す。
     第130期でボルグを燃やして損をしたのは、**ボルグが倍率を持っていなかったから**
   - **ボルグが燃える必要は無い。** ヒヨの対象は「燃えている**味方**」なので、
     倍率だけではヒヨの強化対象にはならない。**(i) ボルグを強くする**と
     **(ii) ヒヨでボルグを強化する**は別の話である
2. **`CinderTrait` の `ally == self` は残してよい**（第130期の結論）。
   ボルグが燃えないのは設計として正しかった
3. **カドの反撃の描き方。** 反撃が薙ぎ扱いなので、踏み込んでいない隣の敵に「届いていない感」が残りうる。
   逃げ道は**線ではなく伝播で描く**（刺さったところから隣へ広がる）。
   カドの一文「**反撃は隣の敵にも届き**」とも噛み合う。
   **まず踏み込みだけ入れてポンが見る。消えなかったときの手札として持っておく**
4. **カドの身代わりは動く**（「その味方と位置を入れ替える」）。
   ガルドの庇い（前に出て戻る）と違い**戻らない**ので、別の演出になる
5. **ハギの処遇。** (a) 転生（鍵を「味方が攻撃すると。1戦にN回」＝アーチャー型）／(b) 差し替え。
   **(b) は第119期に「差し替えは拒否権1 が全部止める」と記録があるので拒否権1 を触る期になる**。
   (a) は第110期の「ハギ台は撃破の起点を持たない台だった」を Phase 0 で拾うこと
6. **トメの鍵（標）。** 書き手がヒサ1枚で、**トメが殴ると外れる**。
   3期連続で ×・落ち率100%・密度 ×0.55（最下位）
7. **段の載せ先をもう1枚**（`docs/stock.md` で**ザンが首位 11.42 なのに読み手を持たない**）
8. **`GodotApp` の削除**（7期連続で開かれていない）
9. **バサの配置交換がランダムなので初期配置を狙って組めない**（4期連続）
