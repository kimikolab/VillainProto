# 第278期 指示書 —— sweep の応答改善(計時・指紋照合・並列化)

読み手は Claude Code。転生段の合間の整備の期。盤面・駒・規則・札・各器具の**出力内容は1行も変えない**——変えるのは実行の速さと要否判定だけ。

## 0. 問題

sweep が 828 本・実測2〜5時間。対照残置の作法(測って採らなかった機構を削除しない)により、転生のたびに本数が線形に増える。転生段はまだ続くので、キャラ変更ごとの回帰確認が律速になっている。

## 1. Phase 0 —— まず測る

1. **計時の内訳**: sweep 全本の所要時間を本ごとに記録し、上位20本・器具種別ごとの合計・分布を出す(1回の full 実行で取れる。直近の実行ログから取れるならそれでよい)
2. sweep の実行構造: 直列か並列か・1本の独立性(本同士が出力ファイルを共有していないか)
3. **固定済み器具の洗い出し**: 版を固定した対照器具(SomS0 固定の類・旧版診断)と、現役の主判定系(compare・bosswave・checkwave・relic 系)を仕分けし、本数と時間の割合を出す
4. 既存の指紋機構(shockdigest 等)の仕組み——流用できるか

## 2. 施策(Phase 0 の内訳を見て、効果の大きい順に適用)

### A. 指紋照合化(本命)

- 対照器具は入力(コード)が変わらなければ出力も変わらない。**BattleCore(+BattleSim の当該器具)のビルド成果物またはソースのハッシュが前回 full 実行時と同一なら、その本をスキップし、保存済みの指紋を照合結果として報告する**
- ハッシュが1つでも動いたら該当層は全実行(安全側に倒す。部分適用の影響グラフは作らない——複雑化は次の手)
- 指紋と前回ハッシュの保存場所・形式を決め、`sweep` の出力に「実行 n 本・指紋照合 m 本(ハッシュ一致)」を明記して、何が省かれたかを常に見えるようにする

### B. 並列化

- seed 固定・本同士が独立なら、器具単位のプロセス並列は出力を変えない。コア数に応じた並列度(環境変数等で調整可)
- 並列化後の full の出力が、直列の full と**全行一致**することを1回確認(順序依存が無いことの証明)

### C. 層別の運用(作法の改定)

- `sweep fast`: 主判定系のみ(期中の判定用)。`sweep full`: 全量(コミット前に1回)
- CLAUDE.md の作法を「期中は fast・コミット前に full(A/B 適用後の full)」に1行で改定

## 3. 受け入れ条件

- **改善後の `sweep full` の出力が、改善前の出力と全行一致**(所要時間の行を除く)
- 指紋照合が働いた状態で BattleCore に1文字変更を入れると、該当の本が再実行に戻ること(自己検査に1項目)
- 所要時間: 改善前後を報告に併記(目標は「転生1駒の期で回帰確認が1時間以内」だが、未達でも構造が入っていれば可)

## 4. 作法

- 器具の出力内容・測定の意味は不変。報告 `design/PHASE278_SWEEP_SPEEDUP.md`
- CLAUDE.md は作法の1行と現状値のみ。新コマンド(fast/full)は COMMANDS.md へ
- この期では転生・札・波に触らない

## 5. この期に決めないこと

- 影響グラフによる部分実行(複雑化はまず A〜C の効果を見てから)・対照器具の削除(残置の作法は変えない)・3駒目(トウ)の中身
