## 0. この期の狙い

### 0-1. 何を出すか

> **「ノノは会戦で何戦保つのか」を数字にする。**
> そして同じ器具で、**駒1枚のステージ単位の帰属**を 61 行ぶん出せるようにする。

第156期の調査で、**器具（素体差し替え）も目的変数（突破度）も既にあり、繋いだ診断が1本も無いだけ**と判明した。
この期はその1マスを埋める。

### 0-2. なぜ要るか

現在のロスター評価（`compare` 61行・`checkup` 1,326組）は**単発戦の勝率**しか見ていない。
本編は HP が持ち越し、倒れた駒はステージ中リタイア、部隊は複数——
**駒の価値が単発戦の勝率では表せない例が既に複数ある。**

- **継ぎ当てのノノ**——2〜3回繕うと尽きる。単発戦では勝率に出るが、
  ステージ単位では「駒1枚を失う」というコストであり、`compare` に1ビットも現れない
- **爆ぜるゾト**——単発戦では燃焼用のライターかリィカの餌でしかないが、
  持ち越しがあるなら**特攻・玉砕部隊として敵を削る**という独立した使い道が立つ
- **継ぎ接ぎのヴェル**——蘇生1回ごとに `MaxHp` が半分になり、**境界を越えて戻らない**（実測 46 → 11）。
  単発戦では「蘇生2回ぶんの価値」、会戦では**「駒1枚を捨てる」**

第153〜155期はヒーラーの設計で3期続けて空振りした。判定の単位が合っていなかった可能性が高い。

### 0-3. この期でやらないこと

**ロスター（駒の在庫）を engine に入れない。** 第156期 §7 の段5 で、規模は中〜大。
いま engine を触ると**測っていない量についての読みで構造を変える**ことになる（第41〜43期と同じ形）。
段1〜3を測ってから判断する。

## 1. 段1 —— 台の帯を先に決める（**これが無いと以下が全部 0 で並ぶ**）

### 1-1. 問題

**いまの会戦は 73行中 72行が突破率 0% である**（第100期 `run`・地点3波で 0.97%）。
`compare` の 61 行をこのまま載せると**ほぼ全行が床で並ぶ**——
第26・28期の「`reseat` の120通りが 20.0% で並んだら台が死んでいる」と同じ絵になる。

**実測されている帯の両端**（第101期）:

| 設定 | 突破率 | 0% の行 |
|---|--:|--:|
| 現行（境界に回復なし） | 0.97% | 72 / 73 |
| `RecoverRule(100, false)` ＝ 生存者を全快 | 5.81% | 46 |
| `RecoverRule(100, true)` ＝ 倒れた駒も全員復帰 | **52.06%** | — |

**帯は R100 と RFull のあいだにある。** 第102期は `BoundaryRule` で同じことをもう一度やり、
「帯には届かなかった」で終わっている——**「境界を緩めるノブ1本では測定帯に入らない」は2期かけて実測済み**。

> **したがってこの期は「ノブ1本」で探さない。** 下の3つの軸を**組み合わせて**探す。

### 1-2. 探す軸（3つ。組み合わせてよい）

1. **`RecoverRule(HpPercent, ReviveDead)`** —— `HpPercent` は 0〜100 の連続値。
   **`ReviveDead = true` と低い `HpPercent` の組み合わせ**が未探索
   （第101期は 100 の2点しか測っていない）
2. **`BoundaryRule`** —— `Revive`（倒れた1体を `MaxHp/2` で戻す）/ `Heal` / `Carry`。
   **`RecoverRule` とは併用できない**（engine が禁じている。`RecoverRule.Active` が真なら無視される）
3. **敵の列の長さ・中身** —— これは規則ではなく**台の設計変数**。
   短い列（2地点）なら突破度の分母が小さくなる

### 1-3. 目的変数は勝率ではなく突破度

**`突破度 = EnemySquadsCleared + LastBattleAttrition`**（列長を超えさせない）。
**連続量なので「床・天井」の概念は「0 / 列長」に置き換わる。**

### 1-4. 採る点の条件

61 行（`CompareBuilds()`）を回して、次を満たす点を1つ選ぶ。

| # | 条件 |
|---|---|
| 1 | **突破度が 0 の行が 61 行中 15 行以下** |
| 2 | **突破度が列長ちょうど（全抜き）の行が 15 行以下** |
| 3 | **61 行の突破度の標準偏差が最大**（同率なら 1・2 の余裕が大きいほう） |

> **条件1・2 の 15 行は仮の線である。** 満たす点が1つも無ければ**線を下げず、
> 「どの軸をどこまで振っても届かなかった」を数字で報告すること**——
> それ自体が第101・102期に続く3つ目の実測になる。
> **結果を見てから線を緩めない。**

### 1-5. 走らせ方

`recover` / `choice` は既存の診断なので**回すだけ**。`engage` は `compare` の4倍の戦闘を12秒で回しており、
**計算量は問題ではない**（第156期 §3-1）。刻みは粗く広く取り、当たりを見てから細かくする。

**選んだ点を `StageRule`（仮）として1箇所に置くこと。** 段2・段3 はこの点の上で回す。

## 2. 段2 —— `ablate` の会戦版（仮 `stage`）

### 2-1. やること

`CompareBuilds()` の各行から**駒を1枚ずつ素体（特性を持たない同数値の駒）に差し替え**、
**突破度の差**を出す。単発戦の `ablate` と同じ器具を、目的変数だけ突破度に替える。

- 台は段1 で選んだ点
- seed は `compare` と同じ 0..199
- **素体は既存のもの**（新しい数値の駒を作らない）

### 2-2. 出すもの

| 列 | 内容 |
|---|---|
| 行 | `CompareBuilds()` の行名 |
| 駒 | その行の5枚それぞれ |
| **会戦帰属** | 突破度（本体） − 突破度（その駒を素体に） |
| **単発帰属** | 既存の `ablate` の値（**同じ表に並べる**） |
| **差** | 会戦帰属 − 単発帰属 |

> **「差」の列がこの期の本体である。** 大きい駒が「単発戦の評価が見落としていた駒」。

### 2-3. 予測（**実装前に書き切る。外れても消さない**）

第156期 §8 が実測5枚・推測6枚を挙げている。**それぞれについて符号の向きを先に書くこと。**
以下は §8 からの引き写しで、**数値は入れず向きだけ**。

| 駒 | 予測の向き | 理由 |
|---|---|---|
| ヴェル | **会戦 < 単発** | 蘇生ごとに `MaxHp` が半減し境界を越えて戻らない（実測 46 → 11） |
| ノノ | **会戦 < 単発** | 尽きると駒1枚を失う。単発では勝率にしか出ない |
| ムド・ウツ | **会戦 < 単発** | 境界で `AtkBonus` が全部消える |
| ヒビ・ウロ・ガレ | **会戦 < 単発** | 破片は `StatusKeys.All` なので境界で全部消える |
| ゾト・ムグ | **会戦 > 単発** | 湧いた駒は持ち越さないが、**部隊戦の数だけ使える** |
| クグ・ネル・クビ | **会戦 > 単発** | 開戦時1回の全体供給が**境界ごとに掛け直される**＝毎戦の収入 |
| ガルド | **会戦 > 単発** | 受け流しの在庫がターン頭に戻る＝**HP を1点も払わずに時間を買う** |
| バン・ガン | **会戦 ≒ 単発** | `IdleTurn` と `ActionIndex` は Battle スコープに閉じている |
| ハギ・トメ | **符号が割れる** | 鍵の供給が後半に偏るが、自分が先に落ちれば同じ |

**予測を書いてから回すこと。**
