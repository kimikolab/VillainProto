## 背景

現在のユニットは、基本的に毎ターン同じ攻撃・スキルを繰り返している。

例：

```
全体攻撃
↓
全体攻撃
↓
全体攻撃
↓
...
```

これにより挙動は分かりやすいものの、戦闘展開が単調になりやすく、「何ターン目に何が起きるか」という時間軸の戦術性が薄い。

そこで、プリコネ等のような**固定された行動パターン（Action Pattern）**を導入する案を検討する。

必殺技・TPゲージ等は現時点では導入しない。

---

## 基本方針

各ユニットが1種類の行動を毎ターン行うのではなく、複数のActionを決められた順番で繰り返す。

例：

```
スキルA
↓
通常攻撃
↓
スキルB
↓
通常攻撃
↓
スキルA
...
```

または、

```
スキルA
↓
スキルB
↓
スキルA
↓
スキルB
...
```

行動はプレイヤーが戦闘中に選択するのではなく、あらかじめユニットごとに決められている。

現在の「編成・配置を考え、戦闘自体はオート」という基本コンセプトは維持する。

---

## パッシブとの分離

アクティブ行動とパッシブ能力は別物として扱う。

### Active Action

自分の手番に実行するもの。

例：

```
通常攻撃
毒攻撃
回復
範囲攻撃
チャージ
```

### Passive

条件成立時または常時発動するもの。

例：

```
味方死亡時に攻撃力上昇
被ダメージ時に攻撃力上昇
毒状態の敵死亡時に毒を拡散
隣接味方にバフ
```

---

## 行動パターン例

### 単純型

従来通り。

```
Attack
Attack
Attack
...
```

全ユニットを複雑にする必要はなく、単純なユニットも残す。

---

### 交互型

```
SkillA
Attack
SkillA
Attack
...
```

または、

```
SkillA
SkillB
SkillA
SkillB
...
```

---

### 3ターン周期

```
Attack
Attack
StrongAttack
Attack
Attack
StrongAttack
...
```

大技感を出せるが、TP・必殺技システムは不要。

---

## 敵のチャージ攻撃

特に敵側の範囲攻撃・貫通攻撃に有効。

現在：

```
全体攻撃100
↓
全体攻撃100
↓
全体攻撃100
```

変更案：

```
Charge
↓
全体攻撃200
↓
Charge
↓
全体攻撃200
```

平均火力は大きく変えず、攻撃タイミングにメリハリを付ける。

これにより、

- 強攻撃が来るターンを予測できる
- 回復する猶予が生まれる
- 強攻撃までに倒す速攻編成が成立する
- 大ダメージを利用する味方特性とのシナジーが生まれる
- ボスや強敵の攻撃に「予告」が生まれる

などの効果を期待する。

TPゲージではなく、単純に `Charge` というActionとして扱う。

---

## Chargeは通常Actionとして扱う

例：

```
ActionPattern:
  Charge
  AoEAttack
```

Charge自体に追加効果を持たせてもよい。

例：

```
魔力集中
このターン攻撃しない。
次の魔法攻撃の威力+100%。
```

あるいは、

```
狙撃準備
対象を指定する。
次ターンその対象へ貫通攻撃。
```

ただし初期実装では、単純な「次ターン強攻撃」の予告だけでもよい。

---

## 初手専用行動（将来的な拡張候補）

ループとは別に、戦闘開始時だけ特殊行動を行う仕組み。

例：

```
開幕バフ
↓
通常攻撃
↓
通常攻撃
...
```

または、

```
開幕強攻撃
↓
Attack
↓
Attack
...
```

必須ではないが、敵やユニットの個性を低コストで増やせる。

---

## HPによるパターン変更（ボス向け拡張候補）

ボス・勇者等のみ、

```
HP > 50%
Attack → Attack → Pierce
```

から、

```
HP <= 50%
Charge → StrongPierce
```

へ変更する。

雑魚敵には基本的に使用せず、ボスのフェーズ変化表現として利用する。

---

## 条件付き行動差し替え（将来的な拡張候補）

複雑なAIにはせず、

**基本ActionPattern + 1個程度の優先条件**

とする。

例：

```
基本:
Attack → Heal → Attack → Heal

例外:
味方HP30%以下なら Heal
```

「毎ターン最適行動を選ぶAI」にはしない。

敵の行動が予測できることを重視する。

---

## 設計上重視すること

このゲームでは戦闘中の操作ではなく、

```
編成
×
配置
×
マイナス特性
×
行動タイミング
```

による事前の試行錯誤を重視する。

Action Pattern導入によって、

```
誰と誰を組み合わせるか
```

だけでなく、

```
何ターン目にシナジーが成立するか
```

という時間軸を追加する。

例：

```
1T 毒付与
2T 毒拡散
3T 自爆
3T 味方死亡をトリガーにリィカ強化
```

のような連鎖を狙える。

---

## 現時点では導入しないもの

以下は複雑化を避けるため保留。

```
TPゲージ
必殺技
MP
スキルクールダウン
プレイヤーによる戦闘中のスキル発動
複雑な敵AI
多数のスキルから毎ターン選択
```

まずは固定Action Patternによる戦闘への影響を見る。

---

## 最初の実験案

既存ユニットを大量に変更せず、数体のみAction Pattern化する。

特に現在毎ターン全体攻撃を行う敵を、

```
Charge
↓
威力約2倍の全体攻撃
```

へ変更。

毎ターン貫通攻撃する敵も、

```
通常攻撃
↓
Charge
↓
強貫通攻撃
```

などを試す。

そのうえで、

- 突破率
- 戦闘ターン数
- 編成ごとの有利不利
- 戦闘ログの分かりやすさ
- シナジーの増加
- 戦闘が間延びしないか

を確認する。
