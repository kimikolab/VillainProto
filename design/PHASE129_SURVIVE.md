## 1. Phase 0 の答え（`survive phase0`）

### Q0-1 —— 現行「完全勝利」の実装と、`PlayerSurvivors` が数えているもの

判定式（`BattleSim/Program.cs`・**1 件**）と定義（`BattleCore/BattleEngine.cs`・**1 件**）:

    if (r.PlayerSurvivors >= qParty[bi]) qPerf[bi]++;
    PlayerSurvivors = ctx.LivingMembers(BattleContext.PlayerTeam).Count(),

`LivingMembers` は盤上の味方を全部数えるので、`TraitId.Ephemeral` 持ち **2 種**（胞子・背いた獣）も入る。
**原理的には「出撃5枚のうち3枚が落ちて胞子が3体湧いた戦」が完全勝利として通る。**

**実測（`compare` 61 行 × 第2〜5波 × seed 0..199 ＝ 48,800 試行）:**

| 量 | 実測 |
|---|--:|
| 勝った試行 | 31,539 |
| 現行の「完全勝利」 | 2,115（勝った試行の 6.7%） |
| **そのうち出撃した駒が1枚以上欠けている試行** | **0 件** |
| 決着時に湧いた駒が盤上に残っていた試行（`PlayerSurvivors` ≠ 出撃数 − 欠けた数） | 348 件（0.7%） |
| `PlayerSurvivors` > 出撃数 の試行 | **0 件** |
| 出撃した駒が1枚も欠けずに勝った試行 | 2,115（全試行の 4.3%） |

> **召喚体は現行の「完全勝利」に1件も混ざっていない。**
> 湧いた駒が決着時に残る戦は 348 件あるが、**「湧いた数 ≧ 欠けた数」には一度もならない**
> ——胞子が湧くのはムグが落ちた戦で、その戦は他の駒も一緒に落ちている。
> **指示書 §3-1 の前提のうち「召喚体が欠けを埋める」は実測では起きていなかった。**
> **残る緩さは分母だけ**（勝った試行 6.7% 対 全試行 4.3%）。

**`> 出撃数` で数えると数え落とす。** 最初その式で実証を書いたら 0 件になり、
「召喚体は数えられていない」という誤った結論が出た——あの式は「欠けた数 ≦ 湧いた数」まで要求するので、
**1枚欠けて1体湧いた戦を数え落とす。** 正しい式は `PlayerSurvivors ≠ 出撃数 − 欠けた数` で、
そちらで 348 件が出る。

### Q0-2 —— 駒ごとの生死が取れるか

**第128期までは引けなかった。**

| 候補 | 引けるか | 理由 |
|---|:-:|---|
| `PlayerSurvivors` | × | 数だけ。しかも湧いた駒を含む |
| `TallyByUnit[id].Deaths` | △ | **倒れた回数**なので蘇生で戻った駒も 1 以上。キーは `Def.Id` |
| `TallyByUnit[id].LastActiveTurn` | △ | 生存なら決着ターン。**決着ターンちょうどで倒れた駒と区別が付かない** |

**計数を1本足した**——`BattleResult.PlayerStarterFallen`（出撃した `UnitState` のうち
決着時に生存していないものの `Def.Id`）。**誰も読んで分岐しない・`verbose` に依存しない。**

### Q0-3 —— 「意図した犠牲」の駒（リフレクションで引く）

| | 札 | 味方の保持者 |
|---|---|---|
| **`OnDeath`**（自分の死が起動条件）**7 本** | `Splitter` / `Bomber` / `Colossus` | 胞子体ムグ / 爆ぜるゾト / 大喰らいゴルム |
| | `Inversion` / `Drought` / `Yoke` / `Hush` | **0 枚**（敵側の盤面ルール） |
| **`OnAnyDeath` / `OnAllyDeath`**（他人の死を読む側）**6 本** | `Necro` / `Contagion` / `Pursuer` / `Taillight` / `Reviver` / `Scale` | 墓守リィカ / 疫みのラウ / 追い打ちのハギ / 尾灯のトモ / 継ぎ接ぎのヴェル / 鱗のウロ |

**免除に使うのは `OnDeath` の 3 枚だけ。** `OnAnyDeath` 側を混ぜると死軸が丸ごと免除される。
`compare` 61 行のうち**免除対象を1枚以上含む行は 25 行（41.0%）**（規約 (G4)）。

**大喰らいゴルムが免除対象に入るのは機械的な帰結である。** `ColossusTrait.OnDeath` は
還し（腹の中身を味方へ返す）なので、定義上「自分の死が起動条件」に当たる。
**25 行のうち 21 行はゴルム由来**で、設計上の「意図した犠牲」（ゾト・ムグ）とは性格が違う
——**報告書に書いて残す**（次に免除の集合を作るときの判断材料）。

### Q0-6 —— 延命台の作り方

| 札 | 効き | 味方の保持者 | 延命台に使えるか |
|---|---|--:|---|
| `Regen` | 毎ターン自分を回復（`ctx.Heal` を通る） | 0 枚 | **×** 渇きで止まり `Stoic`（ガルド）に届かない |
| `Reprieve` | 致死の一撃を1戦に1度だけ HP1 で耐える | 0 枚 | **×** 1度きりでは決着まで守れない |
| `Tempered` | `AtkBonus` が閾値超の間だけ被ダメ減 | 0 枚 | **×** 対象の4枚は自己強化を1本も持たない |
| **`Undying`** | **ダメージでは HP が 1 未満にならない ＋ ターン頭に満タンへ戻す** | 0 枚 | **○** この期の器具として足した |

**`MaxHp` を極端に上げる形は採らなかった。** `Traits.cs` で `MaxHp` を読む行は 10 件あり、
**他人の `MaxHp` を読むのは囃し立て（ヒサ）の1箇所**だが、残りの自己参照の中に
**逃亡兵セロの後退（`Hp * 3 > MaxHp * 2`）**がいる——HP を膨らませると**セロ自身の起動条件が壊れる。**

**出口のクランプだけでは足りなかった。** HP が 1 に張り付くと以降の被弾が `amount <= 0` で
早期に返り、**`OnDamaged` が呼ばれなくなる**。庇い（ガルド）のように**被弾そのものが起動条件**の駒では、
延命したつもりで機構を止める——**測りたいものの逆を測る。**
だから**ターン頭に満タンへ戻す**のを対にした。戻しは `ctx.Heal` を通さない
——窓口を通すと渇きで止まり `Stoic` に届かず、**いちばん測りたい2枚にだけ効かない器具**になる。

### Q0-7 —— トメの鍵（標）の供給

**指示書の「標の書き手はヒサ1枚」は誤り。書き手は3枚ある。**

| 書き手 | 対象 | 周期 | トメの鍵になるか |
|---|---|---|---|
| 囃し立てのヒサ（`Marker`） | 隣接する**最大HP**の味方 | 開戦時1回 | **×** 味方に付く |
| 逸らしのソラ（`Divert`） | **敵の現在HP最大 1 体** ＋ 自分 | 毎ターン | **○** 敵に立てる唯一の書き手 |
| 駆り立てのカリ（`Goad`） | 隣接する `CurrentAttack` 最大の味方 | 毎ターン | **×** 味方に付く |

`compare` でトメを含む行は **2 行**で、**どちらもソラを含む**（`止め (トメ×ソラ)` / `止め改 (トメ×薙ぎ)`）。
**鍵は配られている。足りないのは量である**（ソラ1枚・`TargetCount = 1`・トメが殴ると外れる）。

### Q0-8 —— ガルドの `Stoic` は HP を弾くか

`Stoic` が効くのは `AcceptsSupport`（`ctx.Heal` と支援の窓口）で、`UnitDef.MaxHp` は
**窓口ではなく数値**なので通らない。**段3 で `MaxHp` を上げるのは弾かれない。**
同じ理由で `Undying`（窓口を通さない）もガルドに効く。

### Q0-9 —— 過去に延命して起動を測った期

`design/` 228 ファイルの走査で `不死` 0 件・`Undying` 0 件。
**第126期（`time`）が「時間を買う3案」を測っているが、あれは代金つきの<u>機構</u>の案**で、
「代金ゼロで落ちなくしたら起動するか」は測っていない。
この期の `Undying` は**採否を持たない測定器**であって、案ではない。

**P1 の外れ方が重要。** 判定式（`PlayerSurvivors >= 出撃数`）は**原理的には**召喚体で埋められるが、
**実測では 2,115 件中 0 件**だった。**「実装の形から緩さの出どころを推測した」のが外れの中身**で、
実際に緩かったのは分母（勝った試行だけを見る）である。規約 (G11)「線を引く前に対照側の実測を見る」の系。

**P2 の中身は予想と半分違う。** 指示書が挙げた最有力3つのうち、
`死の連鎖 (リィカ軸)` は 0.0% → 25.5% で当たったが、
**`毒爆弾 (ラウ×ヴィオ)` は 0.2% → 0.2% で1ミリも動かない**（ラウは `OnAnyDeath` 側で、
この行に `OnDeath` の保持者が1枚もいない）。`置き去り×死の連鎖` も 0.0% → 0.0%
（ムグ・ゾトを免除しても他の駒が落ちている）。

**P4 の外れは分母の取り違え。** 指示書の「与ダメ 0.8/戦」は**`止め改` の1席の値**で、
段2 の延命台は**在席5行の通算**（43.8 → 78.0）。**違う分母の数を比べていた**（規約 (G12)）。
段3 後に同じ席で測り直すと **0.8 → 6.9**。

**P6 の「半分」。** 「鍵の供給を必要としないので生きてさえいれば働く」は成り立たなかった
——庇いの条件は**味方が単体攻撃を受けること**で、**味方が先に落ちれば鍵も尽きる。**
実測でガルドの密度は ×0.65 に落ちる（自前のソラは ×0.95）。

## 4. 段2 —— 延命台（`survive run`）

**器具は `TraitId.Undying`**（保持者は `UnitCatalog.All` にも `EnemyCatalog.Stages` にも **0 枚**）。
**代金を付けない。閾値を掃引しない。** 素の効き方だけを見る。

| 駒 | 鍵の供給 | 在席行 | 生存T V0 → V1 | 発火 | **密度** | 与ダメ(敵) |
|---|---|--:|--:|--:|--:|--:|
| 逸らしのソラ | 自前（毎ターン無条件） | 6 | 3.09 → 7.24 | 2.80 → 6.25（×2.23） | 0.906 → 0.863（**×0.95**） | 36.4 → 75.6（×2.07） |
| 廃棄聖騎士ガルド | 不要（味方が単体攻撃を受ける） | 35 | 3.48 → 7.60 | 1.67 → 2.36（×1.41） | 0.479 → 0.310（**×0.65**） | 34.7 → 95.5（×2.75） |
| 追い打ちのハギ | 撃破（希少） | 5 | 3.41 → 9.51 | 1.58 → 3.18（×2.01） | 0.463 → 0.335（**×0.72**） | 43.8 → 78.0（×1.78） |
| 止めのトメ | 標（ソラ1枚・殴ると外れる） | 2 | 4.46 → 8.52 | 2.96 → 3.12（**×1.05**） | 0.665 → 0.367（**×0.55**） | 83.6 → 135.6（×1.62） |
| 逃亡兵セロ | 自分の被弾（HP の 1/3） | 12 | 4.77 → 9.74 | 1.83 → 2.78（×1.52） | 0.383 → 0.285（**×0.74**） | 91.7 → 151.6（×1.65） |

**`発火` は駒ごとに実装から引いた計数**（ソラ `DivertFires` ／ ガルド `UnitTally.Intercepts` ／
ハギ `UnitTally.Attacks`（自分の手番では振らない型なので全数が追い打ち）／ トメ `FinisherFires` ／
セロ `UnitTally.SniperSwings`（**この期に足した計数専用の1本**））。
**発火 0 回の駒は1枚も無い**（A4）。

> **5 駒とも「発火と与ダメの両方が増える」という事前に固定した線は通った。**
> **だが `密度`（発火 ÷ 生存T）は鍵の供給の種類ときれいに並ぶ**
> ——自前のソラ ×0.95（時間がそのまま仕事になる）から、
> 標に縛られたトメ ×0.55（**時間を 1.9 倍買っても発火は 5% しか増えない**）まで。
> **「延命すれば起動する」と「延命しても働きが薄まる」は、線の上では区別が付かない。**

**指示書 P3 は字の上では外れ、中身では当たっている。** トメは「起動しない」のではなく
**「守っても鍵が増えないので、時間あたりの仕事が半分になる」。**
**トメに要るのは HP ではなく標の供給**（`TargetCount` を上げる／敵に標を立てる2枚目／消費をやめる）。

## 5. 段3 —— 追い打ちのハギの `MaxHp` を 62 → 82

## 7. この期で分かったこと（則）

### 7-1. 「指標が緩い」の出どころを、実装の形から推測しない

判定式 `PlayerSurvivors >= 出撃数` は**原理的には**召喚体で埋められるが、
**実測では 2,115 件中 0 件**だった。緩さの実体は**分母**（勝った試行だけを見る）。
**規約 (G11)（線を引く前に対照側の実測を見る）を、線ではなく<u>欠陥の診断</u>に当てる。**

**数え方を1つ間違えると、その実測すら出ない。** 最初 `PlayerSurvivors > 出撃数` で数えたら 0 件で、
「召喚体は数えられていない」という誤った結論が出た——あの式は「欠けた数 ≦ 湧いた数」まで要求する。
正しくは `PlayerSurvivors ≠ 出撃数 − 欠けた数`（348 件）。
**「その計数が実際に数えている出来事」を先に書くこと**（第121期）。

### 7-2. 延命は時間を買うが、発火は時間に比例しない。比例の崩れ方が鍵の供給の種類と一致する

**`密度` = 発火 ÷ 生存T。** 代金ゼロの延命（`Undying`）で測ると:

    自前（ソラ・毎ターン無条件）        ×0.95   ← 時間がそのまま仕事になる
    自分の被弾（セロ）                  ×0.74
    撃破（ハギ）                        ×0.72
    味方の被弾（ガルド）                ×0.65
    標（トメ・書き手1枚・殴ると外れる） ×0.55   ← 時間を 1.9 倍買っても発火は +5%

**「守れば起動する」と「守っても働きが薄まる」は、発火回数の増減だけでは区別が付かない。**
第114期「強化の価値は積んだ量ではなく受け手が振った回数で決まる」の**時間側の版**で、
こちらは**買った時間が仕事に変わる率が、鍵の供給で決まっている。**

### 7-3. 密度が上がる駒がある —— 鍵が戦闘後半に偏る機構

追い打ち（ハギ）だけが **×1.10** と逆を向く。鍵が「味方の撃破」で、
**撃破は敵が削れた戦闘後半に集まる**ので、早く落ちる駒は鍵が配られる時間帯に居合わせない。
**「鍵の供給が時間軸のどこに偏っているか」を見ると、延命の値段が駒ごとに違う理由が出る。**

### 7-4. 「殺さない」器具は、出口に置くだけでは足りない

HP が 1 に張り付くと以降の被弾が `amount <= 0` で**早期に返り、`OnDamaged` が呼ばれなくなる。**
**被弾そのものが起動条件の駒（庇い・被弾強化・棘）では、延命が機構を止める**
——測りたいものの逆を測る。**ターン頭の満タン戻しと対にすること。**
第126期「『殺さない』制約は出口にしか置けない」の続きで、**出口に置いた後に何が消えるかまで見る。**

### 7-5. `MaxHp` を上げる調整は、その駒自身が `MaxHp` を読んでいないかを先に見る

逃亡兵セロの後退は `Hp * 3 > MaxHp * 2` なので、**HP を上げると後退の閾値も一緒に上がり、起動が遅れる。**
実測で `MaxHp` 62 → 72 のとき**発火が 2.08 → 1.99 と下がる**（密度も 0.365 → 0.337）。
**HP は素直な耐久のノブではない。**

### 7-6. 「買った時間」を量の逆算に使えないことがある

第126期の線（+1.0T）はハギには**届かない**——`MaxHp` を +30 しても +0.52T。
**他の期の数値を判定の線にするときは、その線がこの器具で到達可能かを先に見ること**
（規約 (G11) の系。第118期 Q1 と同じ形）。

### 7-7. `derive rules` の索引は、入れ子のクラス名まで拾って本文ごと結ぶ

`(?:static|sealed) class (\w+)` はメソッドの中の `sealed class Acc` も拾い、
`"Acc."` が現れたモードに**そのファイル全体**を結び付ける。
実測で `docs/rules.md` の `利用者` 列に**無関係な `pairs` が付いた**（クラス名を変えて消えた）。
第121期「引けているのに結ばれない」の裏返しで、**今度は結ばれ過ぎる。**
**診断の入れ子クラスには接頭辞を付けること。**
