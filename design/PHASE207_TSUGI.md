### Q0-2 燃焼のダメージは破片で止まるか → **止まる**

- 燃焼の刻み（`BurnTickOnce`）は `ApplyDamage(u, 6, null, burnTick: true)` を通り、**破片の段で吸われる**（`BurnSoaked` という計数が既にある）。
- 例外は2つ: 熾のホタ（刻みそのものが起きない・第178期）と、ベニの隣（反転で回復になる・`ApplyDamage` を通らない）。
- **だから「長く燃える」は板が残っている間は HP を削らない ——代わりに板を 6 ずつ削る。** しかも §2.4 の在庫は「味方の破片が砕けた量」を拾うので、**燃えている板は削れるたびにツギの在庫を 3 ずつ増やす**（燃焼 → 板が減る → 在庫 → 次の板が厚い、の小さな循環）。仕様は変えない。

### Q0-3 破片を配る既存の窓口は支援拒否・渇きを通るか → **どちらも通らない（届く）**

- 砕け（ヒビ `ShatterTrait.Distribute`）は `SetCounter(Armor)` を直に書き、**`AcceptsSupport` を見ない**（コメントで明示: 「誰の助けも届かない駒に唯一届く支援」）。`MostHurtAlly` を使わないのもそのため（あれは `AcceptsSupport` を通してガルドを飛ばす）。
- 身構え（ササ `BraceTrait.Deliver`）も `SetCounter` の直書き。
- 渇きは `BattleContext.Heal` の入口だけで、破片の書き込みはどこも `Heal` を通らない。
- **ツギの板も同じ形にする**（`SetCounter` 直書き・`MostHurtAlly` は使わない）。

### Q0-4 燃焼が付く経路 → **2本。`Ignite` と、リリの移し**

- `BattleContext.Ignite` の呼び出し口は 7 箇所（破裂の敵・味方／火の粉の敵・味方／火選りの配布／ベニの火を分ける／紅蓮）。**点け直しも同じ `Ignite`**（残りを `BurnRules.Turns` に上書き）。
- `SetCounter(StatusKeys.Burn, …)` を書くのは **`Ignite` の末尾（1239 行）と刻みの減算（630 行）だけ**。
- **`Ignite` を通らない付与はリリの移し（`KissSpill`）1本**——燃焼を「残りターンの大きい方」で直に書く（`Ignite` を通すと複製になるため・第49期）。
- **倍は2箇所で掛ける**: `Ignite` の中（残りターンを決めた直後）と、リリの移しの燃焼の枝。1箇所には寄せられない。

### Q0-5 「破片が砕けた」量を拾える窓口 → **`UnitState.SetCounter` の1点**

- 破片が減る箇所は3つ: `ApplyDamage` の破片の段（敵の一撃・味方の巻き込み・燃焼や毒の刻みのすべて）／礫（ガレが最大保持者を砕いて 0 に）／鱗（ウロが攻撃で破片を払う）。**リリの移しで敵の破片が 0 になる経路もある**（敵の陣営なので拾わない）。
- 3つとも `SetCounter(Armor, 減った値)` を通る。**`SetCounter` が減った分を1回だけ `BattleContext` へ流す**形にすれば二重に数えない（各箇所に足すと、ガレの砕き → 砕いた破片で撃つ の中で数え方が割れる）。
- 会戦の境界は `Counters.Remove` なので `SetCounter` を通らない（境界で消えた破片は拾わない）。
- **板の印を消すのも同じ1点**（破片が 0 になった瞬間）に置く。

## 2. 実装（予測をコミットしてから・ec42875 の後）

- **駒**: `UnitCatalog.Tsugi`（`Id = "tsugi"`・HP62／攻9／速8 はナラのまま・`Actions = [Skill]`・`Advances = false`）。札は **`Plank`（板）・`PlankTinder`（燃えやすい）・`Scrap`（瓦礫拾い）** の3枚で、T1 ＝ `[Plank]` ／ T2 ＝ `[Plank, PlankTinder]` ／ **T3（規定）＝ 3枚**。旧ナラは `UnitCatalog.Nara` に対照として残した（`All` にも `Retired` にも入れない・`ForsakeTrait` は触っていない）。
- **行名**: `置き去り×被弾強化` / `置き去り×分散回復` / `置き去り×死の連鎖` → **`継ぎ当て×…`**（中身は変えていない）。`BattleSim` の 19 ファイルの `UnitCatalog.Nara` / `"nara"` / 行名を機械的に置き換えた（第204期のリリと同じ作法）。`Baseline.PrimaryRows` の `継ぎ当て×分散回復` の軸名（「置き去り／回復」）は触っていない。
- **状態キー**: `StatusKeys.Plank`（表示「板」・`All` に足したので会戦の境界で消える）。値は **1 ＝ 燃えにくい板（T1）／ 2 ＝ 燃えやすい板**——札を持つツギが倒れた後も、貼った板は燃えやすいまま残る。リリの移し（`KissTrait.Excluded`）からは外した。
- **板を貼る**（`PlankTrait.OnAction`）: 味方全員（自分・召喚枠を含む）から破片が最小 → HP 割合が最小 → `ctx.PickOne`。量は `max(6, 生きている敵の CurrentAttack の最大) ＋ 在庫`。`SetCounter` の直書き（`Heal` も `AcceptsSupport` も通らない）。
- **破片の減りの1点**（Q0-5）: `UnitState.SetCounter` が `Armor` の減りを `BattleContext.NoteArmorLost` に1回だけ流す。そこで (1) 破片が 0 なら板の印を消す、(2) 同じ陣営の生きている `Scrap` の保持者が拾う。保持者がいなければ `_scrapHolders.Count == 0` の比較1つで抜ける。
- **燃焼の倍**（Q0-4）: `BattleContext.PlankFlare` を `Ignite` の中（残りターンを決めた直後）とリリの移しの燃焼の枝の2口から呼ぶ。印が 2 でなければ何もしない。
- **瓦礫拾い**（`ScrapTrait`）: 在庫は私有キー `tsugiScrap`（1/100 単位）。砕けた破片は `量 × 50`、倒れた駒は `5 × 100`（`OnAnyDeath`・自分の死は拾わない）。貼るときに切り捨てて 0 に戻す。会戦の境界で 0。
- **台本**（表示専用）: `BattleEventKind.Plank` の1種類に `PlankLabels.Paste`（板を貼った・`Slot` ＝ うち在庫）／ `Scrap`（瓦礫を拾った・`Slot` 0 砕け ／ 1 倒れ・`StatusRemaining` ＝ 在庫の合計）／ `Flare`（板が燃えた・`Amount` ＝ 倍にした後の残りターン）。
- **`Run` の引数は増やしていない**（ノブは `PlankTrait.PlankFloor` / `ScrapTrait.ScrapRate` / `ScrapPerFall` の `const`）。
- 表: `checkup` の札の分類（`hcLabel`）・`Program.cs` の書き込みとフックの表・`lili phase0` の状態キーの分類に3枚と `plank` を足した（第132期 段0-a・第179期の踏み穴）。DemoApp は状態アイコン（`StatusIconArt`）に板の図案と、攻撃音の分類に `tsugi` を足しただけ（立ち絵・演出は Codex 側）。
