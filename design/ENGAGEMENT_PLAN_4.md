## 0. 何を疑っているか

第3期の `docs/engage.md`（順路・5波）を並べると、**部隊を1つ足したときの突破数の増分が、編成によらずほぼ +1.00 で固定されている**。

| 編成 | 期待突破数(1) | (2) | (3) | 増分 |
|---|--:|--:|--:|--:|
| 毒 (グザ×ミオ×ラウ) | 1.00 | 2.00 | 3.00 | +1.00 / +1.00 |
| 突き出し (セロ×ヨミ) | 1.00 | 2.01 | 3.01 | +1.01 / +1.00 |
| 逆しま (ネル×ウツ) | 1.95 | 3.00 | 4.00 | +1.05 / +1.00 |
| 燃焼 (ボルグ×ホタ) | 1.99 | 3.00 | 4.00 | +1.01 / +1.00 |
| 後衛特化+後備え | 2.00 | 3.00 | 4.00 | +1.00 / +1.00 |
| 澱み喰い (グザ×ヴィオ) | 1.91 | 2.99 | 3.99 | +1.08 / +1.00 |
| 耐久 (ガルド×ノノ) | 1.58 | 2.90 | 3.88 | +1.32 / +0.98 |
| 速攻 (ボルグ×ムド) | 1.08 | 2.52 | 3.67 | +1.44 / +1.15 |

1部隊目が 1.00 の編成も 2.00 の編成も、**2部隊目・3部隊目の貢献はどちらも 1**。第3期の `非線形` 列が 0.75〜1.16 の狭い帯に収まっているのも同じ現象を別の角度から見たもの。

これが問題なのは、**「戦力集中か分散か」という判断が発生しないから**（`design/concept_wave_engagement.md` §7 の狙い）。限界効用が全編成一律なら、どこに何部隊置くかは単純な足し算で決まり、編成の性格が配分判断に効かない。

### 対立する2つの説明

- **仮説 P（拾えていない）**: 第1部隊は敵をほとんど削らずに全滅しているので、第2部隊は実質「仕切り直しで1波を抜く」だけになっている。複数部隊制の「削り残しを拾う」設計が働いていない
- **仮説 Q（波が重くなるので相殺）**: 拾えてはいるが、第2部隊が担当するのは第3〜5波（重い側）なので、無傷スタートの有利と波の重さが相殺して +1 になる。**この場合は degenerate ではなく、単に列の難度勾配が急なだけ**

**この2つは今のデータでは区別できない。** この作業でどちらかに決める。

## 2. Phase K — 交代の実態を計測する

診断モード `handoff` を足す。**`docs/` には出さない**（`seats` と同じ扱い。標準出力に出して読む）。

```
dotnet run --project BattleSim -c Release 0 handoff [絞り込み]
```

列は **順路（5波）** を使う。地点（3波）は 3部隊でほぼ全編成 100% に飽和していて勾配が見えないので、診断には向かない。

### 2-1. 交代台帳（仮説 P の直接の検査）

味方2部隊で会戦を回し、**味方部隊が交代した瞬間**の敵の状態を集計する。`EnemyEntries` は既に verbose 非依存で積まれているので、新しい計測は要らない——**交代が起きた battleIndex を `Pairings` の `PlayerSquad` の変化から特定し、その battle の `EnemyEntries` を読む**だけ。

編成ごとに出す:

```
逆しま (ネル×ウツ)
  交代の発生: 198/200（交代せず終わった試行 2）
  交代時に敵が居た波: 第3波 181 / 第4波 17 / 第5波 0
  交代時の敵の残り: 4.2体 / 5.0体、HP 78%（定義上の総最大HPに対する割合）
```

- 敵の HP% の分母は `DefMaxHpSum`（`SquadEntry` に既にある）
- 交代が複数回起きる試行（3部隊のとき）は、**1回目の交代だけ**を数える。台帳を複雑にしない
- 交代せずに終わった試行（第1部隊が最後まで生き残った / 第1部隊が最終波で全滅して会戦が終わった）は分母から外し、件数を出す

### 2-2. 部隊別の内訳

同じ2部隊の走行から、**どの部隊が何波を抜いたか**を出す。

```
  部隊1が抜いた波数: 1.95（第1波 200 / 第2波 195 / 第3波 0 …）
  部隊2が抜いた波数: 1.05
```

「部隊1が 1.95、部隊2が 1.05」なのか「部隊1が 1.50、部隊2が 1.50」なのかで、話がまったく違う。前者なら第2部隊が明確に不利な位置から始めている。

### 2-3. 対照実験（仮説 Q の直接の検査）— **ここが本題**

**「無傷の1部隊が第 i 波から始めたら何波抜けるか」**を測り、第2部隊の実績と比べる。

順路の**接尾列**を BattleSim 内でその場で組む（`EnemyCatalog.Stages.Skip(i)`）。

| 列 | 中身 | 1部隊での期待突破数 |
|---|---|---|
| 順路[1..5] | 第1〜5波（＝順路そのもの） | 既知（`docs/engage.md`） |
| 順路[2..5] | 第2〜5波 | 測る |
| 順路[3..5] | 第3〜5波 | 測る |
| 順路[4..5] | 第4〜5波 | 測る |
| 順路[5..5] | 第5波のみ | 測る |

出力は編成 × 開始波の表:

```
| 編成 | [1..5] | [2..5] | [3..5] | [4..5] | [5..5] |
```

**読み方（判定の中心）**:

- **第2部隊は「敵が削れた第 i 波」から始める**。対照は「無傷の敵の第 i 波」から始める。
- 2-2 の「部隊2が抜いた波数」が、対照の「[i..5] の期待突破数」（i = 2-1 で最頻だった交代波）を**明確に上回る** → **仮説 Q**。拾えてはいる。+1 に見えるのは波の勾配のせい
- **ほぼ等しい、または下回る** → **仮説 P**。第1部隊の削りが第2部隊の役に立っていない

### 2-4. 実装上の注意

- 試行数 200、`verbose: false`。`Pairings` / `EnemyEntries` / `PlayerEntries` はすべて verbose 非依存なので読める。**`Openings` は使わない**（verbose 専用）
- 接尾列は診断モードのローカル変数で組む。`EnemyCatalog.Columns` に足さない
- 実行時間の見積り: `engage` が全編成×3列×部隊数1-3で約15秒。`handoff` は 2部隊×1列 + 1部隊×接尾列4本なので同程度。前景で待ち切れる
- **盤面を触らない。読むだけ。** 受け入れ条件は `compare` ほか差分ゼロ

### 2-5. 受け入れ条件

- `compare` / `chain` / `pulse` / `ablate` / `dump` / `engage` / `seats` の差分 **ゼロ**
- 検算: 接尾列 `[1..5]` の1部隊の期待突破数が、`docs/engage.md` の順路×1部隊と**完全一致**すること（接尾列の組み方が正しいことの検出器。**一致しないまま先へ進まない**）
- 2-1 / 2-2 / 2-3 の実出力を、代表編成（少なくとも 逆しま・毒・速攻・耐久・逆しま改）について報告に貼る

## 3. Phase L — 記録と報告

### 3.1 README に書くこと

「検証で分かったこと」の会戦の項に追記する。

- **部隊の限界効用が一律 +1.00 である**という観測（§0 の表）
- 仮説 P / Q のどちらだったか、`handoff` の数字を根拠に
- 対照実験の表（無傷の1部隊が第 i 波から始めたときの期待突破数）。これは今後どんな部隊列を組むときにも効く基礎データなので、**表そのものを README に残す**

「未解決の課題」:

- P だった場合: 「第1部隊の削りが第2部隊に届いていない。交代の設計（何を引き継ぐか）を見直す」
- Q だった場合: 「限界効用が一律なのは波の難度勾配の帰結。列の勾配設計そのものが課題」
- どちらでも、**第3期からの持ち越し2件（D5 の再検討 / 部隊戦間の回復）はそのまま残す**

### 3.2 報告してほしいこと

1. **P か Q か。** 2-2 の「部隊2が抜いた波数」と 2-3 の対照値を並べて、数字で
2. **交代時に敵はどれだけ削れているか**（2-1）。全編成の平均と、最も削れている編成・最も削れていない編成
3. **交代が起きる波はどこか**（2-1）。第3波に集中しているか、編成でばらけるか
4. **接尾列の表から見える、波の難度勾配。** 第1〜5波のどこで難度が跳ねているか。第2期に「消耗の発生源は第二波」と記録したが、**無傷スタートでも第2波は重いのか**（つまり第二波が高いのは消耗のせいか、波そのものの強さか）
5. **P/Q の判定が編成によって割れるか。** 割れるなら、割れ方に規則があるか（積み上げ系 / 耐久系 / 移動系など）
