### R174 — 「向き」を作る器具では、その札が自分で動き出せるかとその席から動けるかまで数える

**「向き」を作る器具では、その札が<u>自分で動き出せるか</u>と<u>その席から動けるか</u>まで数える**（第146期・第117期の3例目）。
混乱の符号を「敵だけ／味方だけ」で割ろうとして、**ハネ（突き返し）とセロ（逃亡）で組んだ台が第2〜4波とも発火 0.00** になった。
原因は2つとも実装に明文で書いてある——**ハネは `OnMoved` / `OnAllyMoved` しか持たず自分から移動を起こさない**
（第41期「供給が無ければ1回も発火しないこと自体がマイナス側の一部」）ので他に動かす札の無い台では構造的に 0 回、
**セロは `if (self.Row == Row.Back) return;`** なので後列に置くと即 return。
第117期は「土台が測る対象の入力を 0 にしていないか」だったが、**今回は器具そのものが 0 を出した。**
**「その駒は誰を動かすか」だけでは足りない。**
なお**「敵だけを動かす」供給は既存の駒では作れない**（`ShufflerRule` に enemies-only の枝が無く、味方側の入れ替えは無条件）
ので、**診断のローカルに曝き（`TraitId.Expose`）を持つ同数値の駒を置いた**——曝きは `Opponent` を引きずり出すので
**味方が持てば敵だけが動く**（第118期の糧タンクと同じ扱い）。

### R175 — 符号が割れる軸は、指示書が名指しした軸とは別のところにありうる

**符号が割れる軸は、指示書が名指しした軸とは別のところにありうる**（第146期）。
混乱の判定は「被弾変換が厚い台と薄い台で符号が逆」だったが、**実測は両方負**（−6.4 / −31.9）で ×。
ところが**移動の供給の向きで測り直すとほぼ対称に割れる**（敵だけ **+42.3** / 両陣営 −8.4 / 味方だけ **−41.9** / なし −0.1）。
**「符号が割れない」で止めると、割れている軸を見ないまま機構を捨てる。**
**× が出たら、その軸の分母を作っている量を1つ下の層で分けてみること**——ここでは
「被弾変換の厚さ」の下に「誰を動かすか」があり、**台を作った時点で供給が両陣営に等量だったので符号が打ち消されていた。**
第61期「符号を割りたければ、代金と資産に別々のノブが要る」の**供給の向きの版。**

### R176 — 供給が潤沢な機構は、確率のノブでは弱められない

**供給が潤沢な機構は、確率のノブでは弱められない**（第146期・段C）。
混乱の発火を 100% → 50% にしても帰属はほとんど動かない（−6.4 → −6.5 ／ −31.9 → −25.8 ／ −7.9 → −6.9）
——供給が 5〜17 回/戦 あるので、半分にしても在庫が 2〜8 回/戦 残って損が飽和したままである。
**「効き過ぎたら確率で薄める」は、供給の回数を先に数えてから言うこと。** 触るなら供給の口である。

### R177 — 保持者を置かない波ルールは、「その波を含まない行」を消す

**保持者を置かない波ルールは、「その波を含まない行」を消す**（第146期・第107/110期の選択の帰結としての版）。
混乱は第五波の5枚（告発人＝敵由来の混乱の唯一の源／殉教者＝測る相手）をどちらも外せないので
**保持者を立てずノブだけで掛けた**が、そのぶんノブが全波に掛かるので
**受け入れ条件「この波を含まない行が ±0.0」が原理的に到達不能**になった。
代わりに読める陰性対照は「**混乱が1件も立たない行が ±0.0**」だが、
**実測でそれは 1 / 61 行しか無い**——告発人がどの編成に対しても味方を引きずり出すので、
**移動を起こす札を1枚も入れていない編成でも第五波では必ず混乱する。**
**保持者を省く判断をしたら、その期の受け入れ条件を1本ずつ読み直すこと。**

### R178 — `sweep` はコマンド表の行をそのまま走らせる。穴埋めの引数も引数である

**`sweep` はコマンド表の行を<u>そのまま</u>走らせる。穴埋めの引数も引数である**（第144期・(G17) の系）。
`CLAUDE.md` のコマンド表は `brace log "台名 N seed"` のように**穴埋めの形**で本を書くが、
`sweep`（第141期）はその行を子プロセスへ verbatim で渡すので、
**`int.Parse("N")` が例外を投げて全診断の exit 検査が不合格になる**
——第143期に足った行が、第144期の走査で初めて出た（**376 本中の異常終了 1 本がこれ**）。
**診断は引数で落ちてはいけない**——読めない引数は使い方を出して `return` する
（第117期「引けなかったときの分岐を必ず書く」の**引数の側**）。
**入れ子の角括弧も書かない**——`scan [probe [台名]]` は `sweep` の側で `scan ]` に化ける
（この期に実際に化けた。例外は出ないので**静かに違うものを測る**・第123期）。

### R179 — 位置を無作為に入れ替える機構は、敵側でも期待値ゼロではない——符号が台で割れる

**位置を無作為に入れ替える機構は、敵側でも期待値ゼロではない——符号が台で割れる**（第144期）。
入れ替えは**2つのことを同時にする**: 後列の脆い駒を**前へ出す**（＝露出）のと、
前列の硬い駒を**後ろへ下げる**（＝**単体攻撃が届かない場所へ隠す**）。
削り合いで勝つ台（ササの破片・ゴルムの肩代わり）では後者が勝って、
**敵を乱すだけの版は 7 台中 2 台で負ける**（−7.5 / −3.1pt）。
**曝き（第40期）と突き返し（第41期）が「選んで引きずり出す」形なのは、この裏側を踏まないためだった**
——どちらも `HaulOutPair(Opponent)` の1箇所を共有していて、後列からしか引き出さない。
**向きを決めるには罰か報酬を片側に付けるしかない**（第144期は前へ出た側だけを転ばせた）。
第41期「符号を測りたい効果は、その効果だけを 0 にできるノブと対にして作る」の、
**同じ動作の中に逆向きの2つが入っている**版。

### R180 — 波ごとの効き方を生の pt で比べると、測っているのはその波に残っている余地である

**波ごとの効き方を生の pt で比べると、測っているのはその波に残っている余地である**（第144期）。
同じ第5波が、台によって **+55.0pt** にも **+2.0pt** にもなる（V0 が 24.0% か 94.0% かの違い）。
**`(版 − V0) ÷ (100 − V0)` で割り直すと波の差はほとんど消える**（7 台平均で 0.504 / 0.580 / 0.465 / 0.454）。
第24期「天井・床のセルでは誰に注入しても 0 に潰れる」の**判定の側の版**で、
**「どの波で効くか」を予測するときは、余地に対する取り分で線を引くこと。**
なお第144期の予測はここで外れた——**敵の構成（後列の脆さ・特性持ちの数）から順位を書いたが、
Q0-4 の表自身が「前に出る組は全波で 8/10 で一定」を示していた**（＝機構は全波で同じ回数だけ発火する）。
**分母を数えた表を作りながら、予測をその表の別の列から書いていた。**

**`compare` に1行も無い駒が作る穴は、`compare` を何回回しても見えない**（第144期）。

### R182 — 駒を転生させた期は、その駒を含む行の席が必ず古くなる

**駒を転生させた期は、その駒を含む行の席が必ず古くなる**（第143期）。

### R183 — `Cap = 0` で全部止まるとは限らない。ノブの1本ずつについて「何に付いているか」を書く

**`Cap = 0` で全部止まるとは限らない。ノブの1本ずつについて「何に付いているか」を書く**（第143期）。

### R184 — 同じ供給量まで絞っても、確率と回数制では値段が違う

**同じ供給量まで絞っても、確率と回数制では値段が違う**（第147期）。
混乱の絞りを `確率 100/50/25` と `回数 0/3/1` で**同じ台・同じ seed・同じ波**に当てると、**両方効く**
——ところが**供給量を揃えて比べると回数制が 5.6〜8.8pt 優る**
（供給 1.06 回/戦 の「確率 25%」が **−10.1pt** に対し、供給 1.00 回/戦 の「回数 1」は **−4.4pt**）。
**確率は「何もしないターン」を戦闘全体に一様に撒くが、回数制は使える分を前半に寄せる**
——混乱は敵の陣形が崩れる前ほど値打ちがあるので、**同じ量でも置き場所で値段が変わる。**
第146期は「確率は効かない。触るなら供給の口」と申し送ったが、**あれは供給が 5〜17 回/戦 あって
半分にしても在庫が残る版の話**で、供給が 2〜3 回/戦 の版では確率も回数制も素直に効く。
> **絞りのノブを選ぶときは、まず供給の回数を数える。**
> **そのうえで、2つのノブを同じ供給量の点で比べること**——別々の点で比べると
> 「どちらのノブが効くか」ではなく「どちらを強く絞ったか」を測ってしまう。

### R185 — 「その札が陣営を見ない」ことと「その経路が実際に立つ」ことは別

**「その札が陣営を見ない」ことと「その経路が実際に立つ」ことは別**（第147期・第39期の行の側の版）。
処刑も殉教も陣営を見ないので「混乱した敵の攻撃は敵の殉教者が庇う」は**機構としては成立する**が、
**実測は 4 台 × 第2〜5波 × 200 seed のすべてで 0.00 回/戦**だった。
理由は構造にある——**混乱するのは「前へ出た敵」＝たったいま前列に上がってきた駒**で、
その駒が振るときの `pool` は**自陣の前列**である。敵の前列は2枠しかないので、
**殉教者は「その1枠の目標そのもの」になるか、前列にいないかのどちらか**
——鎖の `f.Row == Row.Front && f != target` が両方を落とす。
一方で**処刑は立つ**（0.07〜0.10 回/戦・第三波）——**あちらは前列の駒が一度後ろへ流されてから
戻ってくる経路がある**ため。**「陣営を見ない」を数えたら、次にその駒が立てる席を数えること。**

### R186 — 指示書が名指しした敵の札は、波ごとに実装から引き直す

**指示書が名指しした敵の札は、波ごとに実装から引き直す**（第147期）。

**第五波の前3（`Hero2`）が持つのは処刑ではなく断罪**である（`UnitCatalog.Hero2` は `TraitId.Condemn`）。

第五波用は `Id = "hero_v"` の別物——**名前で数えると必ず外す**（第39期「駒の説明文から数えると必ず抜ける」の敵側）。

### R187 — 列挙に枝を1つ足すことと、その枝を読む側を開けることは別の作業である

**列挙に枝を1つ足すことと、その枝を読む側を開けることは別の作業である**（第148期）。
混乱を立てる口を `ShuffleStagger.ConfuseOnAction` として足したが、
engine の短絡 `ConfusionLive = Confusion.Active || Shuffler.Stagger == ShuffleStagger.Confuse` を直さなかったので、
**読み手 2 箇所（`FoesOf` / `ConsumeConfusion`）がその枝では開かない**——
症状は「動かない」ではなく**「立つのに何も起きない」**で、帳簿には
**敵に立った 2.27〜3.38 回/戦 ／ 敵が振った 0.00 回/戦**と出る（勝率は 5 台で −38.9〜−53.5pt）。
**`compare` では絶対に捕まらない**（既定を動かしていないので 305 セルは 0 件のまま通る）。
**捕まえたのは「立った数」と「振った数」を<u>同じ表に並べた</u>ことだけ。**
**供給側の帳簿だけを見ていると「機構は動いている」と読める。**
直しは短絡の条件を**列挙の値の比較から述語（`ShufflerRule.Confuses`）へ**移すこと
——次に枝が増えても同じ穴は開かない。第122期「規則を降ろすと説明文が静かに嘘になる」の**枝を足す側**の版。

### R188 — `record struct` のノブに計算プロパティを足すと、`docs/rules.md` の「既定値」の列が動く

**`record struct` のノブに計算プロパティを足すと、`docs/rules.md` の「既定値」の列が動く**（第148期）。

**「検算の側が壊れる」の4例目**で、今度は**型の書き方**が原因である。

### R189 — 手番を売る駒を作るときは、買い手が払う通貨を売り手が使えるかを先に見る

**手番を売る駒を作るときは、買い手が払う通貨を売り手が使えるかを先に見る**（第148期）。
号令（ガン）が毎ターン払うのは**攻撃力 +8** で、しかも「動かなかった味方全員」ではなく
**差し出した駒それぞれに個別に**飛ぶ（`RallyTrait.OnTurnStart` の `SurrenderedTurn` の門）。
`Actions = [Skill]` にしたバサは**一度も攻撃しない**ので、受け取った **3.53 量/戦が丸ごと死蔵**になる
（`WhetToByRoute` で実測。V0 ＝ 通常攻撃のバサでは毎Tの払いが **0.00**）。
**値段が安いのではなく、市場そのものが成立しない**——第36期「安い手番は売っても安い」の極端な例。
**据え（バン）は被ダメ側なので成立する**が、それでも帰属は −13.6pt（売れた手番 2.14 回/戦）で足りなかった。
**「手番が余る駒」と「手番を買う駒」を同席させる前に、払う通貨と受け取る駒の出口を突き合わせること。**

### R190 — 供給の律速が「供給側の周期」か「盤面に相手がいるか」かを、移設の前に数える

**供給の律速が「供給側の周期」か「盤面に相手がいるか」かを、移設の前に数える**（第148期・第133期の上限の側の版）。

**供給は 1.94〜2.62 → 1.93〜3.63 回/戦 としか増えない**——

**「上限を外せば供給が増える」は、上限が実際に当たっている回数を数えてから言うこと。**

### R191 — 攻撃を半分残す周期 `[Attack, Skill]` は「半々」ではなく「両方の悪いほう」に落ちる

**攻撃を半分残す周期 `[Attack, Skill]` は「半々」ではなく「両方の悪いほう」に落ちる**（第148期）。
`ActionIndex++` は `CanAct` 通過**後**なので、**撃てないターンは `Skill` の位置に留まって次のターンを待つ**
——攻撃が半分になるだけでなく**供給も半分になる**（1.93〜3.63 → 0.84〜1.95）。
実測で **V1（全部捨てる）−5.9〜−23.0pt に対し V3（周期）は −18.3〜−32.9pt** と、**5 台すべてで周期のほうが悪い。**
**周期は「両方できる」ではなく「どちらも半分しかできない」形である。**

### R238 — 判定の線は、値ではなく量の定義で1つに決める

**判定の線は、値ではなく<u>量の定義</u>で1つに決める**（第159期・第121期の線の側の版）。

#### R238 の再発（第160期・第161期）

**線は「値」ではなく「<u>量の定義</u> ＋ <u>単位</u> ＋ <u>その値が出た対照</u>」の3点セットで決める。**

    第159期  **量の定義**が欠けた（帰属SD か台SD か）  両方が偶然ちょうど 0.162 になり、2期ぶん見えなかった
    第160期  **単位**が欠けた（文字かバイトか）        混ぜた表から目標を引いたので、到達不能な目標になった
    第161期  **その値が出た対照**が欠けた              0.162 は第157期 §1-2 の**台の水準**の値で、
