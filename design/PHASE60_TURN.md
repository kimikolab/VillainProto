## 4. 実装（§2-1）

継ぎ当て（`MenderTrait`・ノノ）の形をそのまま踏襲した。**engine には1行も足していない。**

```csharp
public override void OnAction(BattleContext ctx, UnitState self, UnitAction action)
    => Apply(ctx, self);

// 行動パターンを持たない保持者は従来どおりターン頭に発火する。
public override void OnTurnStart(BattleContext ctx, UnitState self)
{
    if (!ActsOnPattern(self)) Apply(ctx, self);
}
```

**保持者が1枚でも `ActsOnPattern` の分岐を残した。** 継ぎ当てが記録している事故
（味方のノノと敵の従軍司祭長が同じ特性を共有していて、無条件に移すと司祭長の回復だけが静かに消えた）
と同じ形が、後で敵側にこの特性を配ったときに再発する。

`UnitDef.Actions` は **`[Skill]` 1要素**（ノノ・ミオと同じ）。
`ActionIndex` は 1 要素を回すだけなので空回りしない。

**受け入れ基準1の検算**——特性に分岐を足した直後・`UnitCatalog` を触る前に `compare` を回し、
**`docs/balance.md` と 305 セル 0 件**で一致した（保持者が `Actions` を持たない限り分岐は不活性）。

`StatusSnapshot` の `痺` を数えた（痺れは付いた次のターンの頭に立ち、その手番の先頭で消費される）。

    20 セルすべてで  V0 0.00 回/戦  →  V1 0.00 回/戦

Phase 0-2 の予測どおり——**縛めの保持者が4行に 0 枚・痺れの保持者が5波に 0 枚**で、
唯一届きうる断罪（第5波・2枚）は攻撃者を罰する型なので**振らなくなったヒヨには当たらない**。

`生存T − 撃った` の差（0.00〜1.00 回/戦）は**死亡と決着**である
——ヒヨが自分の手番の前に落ちたか、その手番が回る前に決着して行動順ループが `break` した回数で、
**移設に固有ではない**（移設前も同じだけ攻撃が出ていなかった）。

> **`OnTurnStart` から手番へ降ろすと「止められる」ようになるが、
> 止める側が盤上にいなければ何も起きない。** 副作用は**機構としては生まれ、盤面では発火しない。**

## 13. この期に分かったこと

### 13-1. 発火口を移すのは、係数では届かない代金を消す唯一の手段

第58期は `Gain` を 2 → 4 に上げても `撒いた` が 1 も動かなかった
（代金の相手が「構造的に非燃焼の相手」だったので、見返りを厚くしてもその集合は縮まない）。
**移設はその集合そのものを動かす**——`撒いた` は4行とも下がり（−1.87〜−4.18）、
**第1ターンにちょうど載っていた 2.00 が2つとも消えた。**

> **係数が動かせない量があるときは、フックの位置を疑う。**
> ターンの順序（`TickStatuses` → `OnTurnStart` → 行動順ループ）に対して
> **供給がどこにあるかで、機構が読める在庫が決まる。**

### 13-2. 代金の大きさは「量」ではなく「誰に落ちるか」で決まる

`Loss` を 2 → 4 にすると `撒いた` は**きっちり倍**になる（0.56 → 1.16 / 6.55 → 13.03）のに、
勝率への効きは第58期の **6〜12 分の1**（−11.9 → −1.0pt）。
移設で残った受け手が**ボルグ**（火の粉の供給者・巻き込みが本体で攻撃力への依存が薄い）に寄ったため。

> **弱体の帳簿を「撒いた総量」で読むと、値段を1桁間違える。**
> 第43期の「隣に置きたい駒は『弱体を受けると困る駒』ではなく『弱体を受ける駒』」の逆側で、
> **同じ量の弱体でも、受け手によって値段が桁で違う。**

### 13-3. 手番へ降ろすと止められる経路が増える、とは限らない

移設で新しく効くようになるのは痺れだけで、**痺れの供給者は4行に 0 枚・5波に 0 枚**。
一方、**移設は経路を1つ閉じる**——断罪（第5波・2枚）は殴ってきた攻撃者を罰する型なので、
**振らなくなった駒には原理的に当たらない。**

> **`OnTurnStart` → 手番は「無敵の機構を可傷にする」変更だと思われがちだが、
> 実際には「殴ることで踏んでいた地雷」も同時に手放す。**
> 交絡の勘定は増える側と減る側の両方を数えること。

### 13-4. `reseat` の採否閾値は「測れる席」を守る歯止めとしても働く

`死軸×ヒヨ` の粗探索1〜3位はどれもヒヨを中央（次数4）へ動かす席で、
勝率は +2.6〜+4.3pt 上がるが**情報セルが 3 → 1** に落ちる（第3・4波が天井に張り付く）。
**閾値 5.0pt に届かなかったので、席は動かなかった。**

> 第46期が閾値を 2.0 → 5.0 に上げたのはノイズ避けだったが、
> **その閾値は「勝率を最大化する席を採り過ぎない歯止め」としても効いている**（第59期の再現）。

### 13-5. 「盤面ルールが効かない」と「その波のセルが動かない」は別

粛は移設の前後で1ビットも変わっていない（`CanActOutOfTurn` の呼び出し元は特性側の4本だけで、
行動順ループは1度も呼ばない）のに、**第2波のセルは2行で動いた**——
ヒヨが第2波でも殴らなくなり、その手番が贔屓に変わったぶん。

> **予測は機構の側（封じる本数）で書くこと。波のセルには他の全部が入ってくる。**

### 13-6. 採用で既定が動いた診断は、検算の相手が V0 から V1 へ移る

移設を採用すると `UnitCatalog.Hiyo` の側が V1 になるので、
**診断のローカルに置くのは「移設前の姿」（V0）**であり、
**V1 が `docs/balance.md` と一致することが診断そのものの検算**になる。
第36期の `gullet belly4`（採用で既定が V0 → V3 へ動いた）とまったく同じ形。

> **採用したら、その期のうちに診断の V0 を作り直すこと。**
> そうしないと次に走らせたとき V0 と V1 が同じものを指す（実際に1度そうなった）。
