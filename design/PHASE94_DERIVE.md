## 1. (T1) ノブの一覧を生成物にした —— `docs/rules.md`

`docs/` は **9 → 10 ファイル**になった。生成は `derive rules`（**戦闘0回**）。

    測った診断             `BattleSim/Program.cs` を `focusId == "..."` で区間に割り、型名が現れる区間

**指示書の一覧を信用せず `grep -rn "record struct .*Rule"` で洗い直した**結果、
指示書が挙げた 15 個に対して**実際は 30 本**あった（`MartyrRule` / `ExposeRule` / `BearRule` /
`RelayRule` / `SlanderRule` / `OverbearRule` / `ScapegoatRule` / `DivertRule` / `GoadRule` /
`FinisherRule` / `FavorRule` / `BlazeRule` / `FunnelRule` / `WhetMask` / `CreakRule` が漏れていた）。
**指示書の一覧を信用しない、が正しかった。**

> **第93期のずれ（既定 on/off の取り違え）は、この1ファイルで消える。**
> `GatherRule { Enabled = True }` / `IgniteRule { Enabled = True }` と書いてある。

**`= default(T)` の列は「その規則が既定で何もしない」の機械的な手がかりであって、判定ではない。**
採否は既定値そのものを読む——`ThornRule { Wound = None }` は残置、
`SoakRule { Poison = True, Burn = False }` は毒側だけ採用、と既定値が全部を語る。

**この生成物には1つ弱いところがある**（記録として残す）——
`測った診断` と `期` は `Program.cs` と `design/` の**本文**から引くので、
**説明文が型名に触れるだけで列が動く。**
実際この期のあいだに `GoadRule` の行が `guard / whet / goad` → `derive / guard / whet / goad` へ動き

## 7. (T4) 規約4本を `CLAUDE.md` に書いた

**(G5)** 2×2 の A は「設計上の主役」ではなく「その機構の入力を実際に供給している駒」から選ぶ。
供給の過半を engine の規則が占めているなら **A に置ける駒は存在しない**ので、

**根拠**: 第93期。供給の 95.0% が巻き込み則だったのに A をノミ・キリに固定し、主判定が 0/6 枚で落ちた。

**4つとも単独では採否を決められない**（持続係数 17.97 で否決＝第87期／稼働率 70.6% で拒否権2本＝第93期）。

**(G7)** 紙の分子について3つ目の軸「**分母を削るか**」を足した。
**自分の分母を削る機構では、紙は下限ではなく上限になる**（第93期・実測 ÷ 紙 = 0.79）。

**(G8)** 測定の重さを **甲（engine の規則）／乙（既存駒への1機構追加）／丙（新しい駒1体）**の3段に分けた。
**丙は測らない**——採って外れたときの戻しはノブ1行＋`docs/` 再生成で済み、
測って落とすほうが1〜2時間かかる。バランス完成段階ではない。

あわせて **`docs/` の一覧を 10 ファイルに直し**、`derive` の3モードをコマンド一覧に足した。
