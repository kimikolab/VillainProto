## 1. 画面の起動

```bash
dotnet build GodotApp
```

（`Main.tscn` が起点。エディタが無くても上のコマンドで C# のビルドだけは通る）。

## 4. 見つからなかったもの・出ないもの（**次期の入口**）

### (1) 散開のササは、73 行の会戦で一度も成立しない

会戦（seed 0）では **0 / 73 行**。分母を広げて単発戦 **7,300 戦**（73 行 × 5 波 × seed 0..19）を回すと、

    成立した行: 1 / 73   `置き去り×分散回復` / 第5波 / seed 1 / T4

の**1 件だけ**だった。ササを含む行はロスターに `置き去り×分散回復` の1行しか無く、
そこでも「隣に味方がいない」が立つのは**味方が3枚以上倒れた後**なので、
勝てる波では最後まで条件が揃わない。

> **第82期はドラフト台で散開に +2.61pt を測っている。あれは床が厚い台の値だった。**
> 理想台（`compare` 61 行）は5枠が最後まで埋まっているので、
> **同じ特性が、台を変えると「一度も発火しない」に変わる。**
> 申し送りの「ササは B（効果が動く駒）だった」は、**理想台では A（装備）と区別が付かない**と言い直せる。

### (2) なまりに書き手の線が出ない

`ctx.Dull` は **writer を引数に取らない**（呪詛も萎縮も突き返しも、窓口の中では出どころが分からない）ので、
`StatusGain` の `ActorId` は必ず null になる。**札は出るが線は出ない。**
線まで出したければ `Dull` に writer を足す必要があり、それは engine の窓口の署名を変えることになるので
この期ではやらなかった。

### (3) 引き取り（ガルド）は「隣から移る線」にならない

`GatherRule` は `ctx.Wound(self, 1, self, WoundRoute.Gather)` で**受け取る側だけ**を窓口に通す
（donor 側の減算は第93期の設計どおり窓口を通らない）。だから
**ガルドに「+傷」の札は出るが、誰から移ったかは画面に出ない。**
出すには「傷が減った」側のイベントが要る——**減算の窓口はまだ無い**（次期以降）。

### (4) 痺・標・破片には `StatusGain` が出ない

指示書 §2-2 のとおり **engine の窓口を持つ4通貨（傷・毒・燃・なまり）だけ**を出した。
残り3つは `Traits.cs` の16箇所から直に `SetCounter` される。
**窓口を作れば札も線も自動で出る**——第90・93期と同じ形で3本。

### (5) 全体攻撃は第四波と第五波にしかいない

全体持ちは **詠唱兵（第四波）と 審問官（第五波）の2枚だけ**で、どちらも溜めてから撃つ。
会戦で部隊4 まで到達する行が少ないので、**73 行を通しても会戦では 1 行でしか出ない。**
単発戦なら 73 / 73 行で出る（画面には単発戦の入口が無い——次期の候補）。

### (6) `Damage` の 37% には攻撃型が載らない

`Pattern` を渡すのは **攻撃型が分かる経路だけ**（主目標・副次目標・貫きの各段）。
残りは反撃・毒燃の刻み・肩代わりの中継・呪いの共有で、**設計どおり `null`＝「型なし」として描く。**
実測で 13,811 / 22,011（62.7%）が型付き。

### (7) 追い打ち（ハギ）は「反撃」として描かれない

`Reaction` の札が立つのは **`ctx.Reaction` / `ctx.Interrupt` に包まれた段だけ**で、
棘・仇討ち（`Reaction`）と軋み（`Interrupt`）が入る。
**追い打ちは `OnAnyDeath` から `ctx.PerformAttack` を直に呼ぶ**ので、
台本の上では普通の一振りと見分けが付かず、**単体の線として描かれる。**

> これは実装の抜けではなく、**追い打ちは本当に「攻撃」で、棘は「攻撃ではない」**という違いがそのまま出ている
> （第51期の「肩代わりはダメージの再分配であって行動ではない」と同じ線）。
> 画面で区別したいなら、engine 側に「ターン外だが攻撃」の札がもう1つ要る。

### 4 の照合

73 行 × 5 波を `verbose: true` で回し（365 セル）、台本の `StatusGain` の件数と `UnitTally` の計数を突き合わせた。
**計数は窓口の分岐より手前で数えているので、emit と同じ回数になるのが正しい。**

    傷    件数 == Σ WoundWrites          365 / 365 セル一致
    毒    件数 == Σ SoakPoisonWrites     365 / 365 セル一致
    燃    件数 == Σ (BurnLit + BurnRelit) 365 / 365 セル一致
    なまり 量   <= DullTotal              365 / 365 セル成立

**なまりだけ不等号なのは転嫁（`RelayThrough`）が窓口の中から窓口を呼ぶから**で、
`DullTotal` は外側でも内側でも足すのに、`AtkBonus` が実際に減るのは内側だけ。

## 7. 申し送り（第98期の入口）

1. **ポンの主観の課題リスト。** §3 の手順書を見ながら「編成してみたくならない駒」を挙げてもらう。
   第96期の申し送りどおり、**A ＝「プラス側の効果が戦闘中に一度も切り替わらない」駒**で数え直す。
   **§4 の (1) を先に読むこと**——ササは「B のはずが理想台では A に見える」駒で、
   **その判定は台に依存する。**
2. **痺・標・破片の窓口**（§4 の (4)）。第90・93期と同じ形（加算だけを通す）で3本。
   作れば `StatusGain` が全通貨で出る。
3. **減算の窓口**（§4 の (3)）。引き取り・断ち・縫い・塞ぎは「通貨が減った」を1件も残さないので、
   **画面では在庫が黙って消える。**
4. **`ctx.Dull` に writer を足すか**（§4 の (2)）。足すと呼び出し口7本の署名が動く。
   足さないなら「なまりは書き手が見えない通貨」だと割り切る。
5. **単発戦の入口**（§4 の (5)）。画面は会戦しか回せないので、
   第四波・第五波の全体攻撃や、勝てない編成の負け方が見られない。
6. **`docs/rules.md` は報告書を置いた後にもう一度再生成する**（§5 の 2）。
