## 4. 段1 —— 介入を台本に載せる（`BattleCore`）

### 4-1. 表示専用のイベントを1種足す

`BattleEventKind` に **`Intercept`（介入）** を足す。**介入の鎖の全段（Q0-1）で1件出す。**

| フィールド | 中身 |
|---|---|
| `ActorId` | **割り込んだ駒**（庇った側・後備え・棘守り・殉教者・標的で吸った駒） |
| `TargetId` | **本来の標的**（庇われた側） |
| `Text` | どの段か（庇う／後備え／標的／棘守り／殉教） |

- **1種で全段をまかなう。** 段ごとに種類を分けない（描き分けは `Text` でできる）
- **`Emit` は `verbose` のときだけ動く**という現在の性質を変えない
- **既存の `Log(... を庇った ...)` は残す**（戦況ログの文字列は今までどおり）
- **どの規則もこのイベントを読まない。** `Reaction` / `Relayed` と同じ「表示専用」の扱いにし、
  `Models.cs` のコメントにそう明記する

### 4-2. 計数（パネルの `—` を数字にする）

Q0-2 で既存の計数で代用できるならそれを使う。**無ければ `UnitTally` に足す**:

- **介入した回数**（割り込んだ側）
- **肩代わりした量**（引き受けたダメージの合計。`Relayed` の段で数えられるはず）

**誰も読んで分岐しない計数**にすること（`HpRemoved` と同じ扱い）。既存の計数の意味は1つも変えない。

戦績パネルの「庇い」列を `—` から数字に切り替える。**Q0-2 で計数が足せなかった項目は `—` のまま**にし、
**`0` と描き分ける規則は変えない**（第124期 §4-4）。

### 4-3. 段1 の終わり

`compare` 305 セルの 0 件差分 ／ `docs/` 全再生成で差分なし ／ **コミット**。

## 5. 段2 —— 手番の外を「手番の外」として見せる（`DemoApp`）

**この段がこの期の本体。** 情報は既にあるので、**問題は時間軸の作り**である（§0-2・§0-3）。

### 5-1. 原則

> **手番の中の出来事と、手番の外の出来事を、同じ流れで流さない。**

いま全部が「ターン順に1体ずつ」の1本の時間軸に並んでいるので、割り込みも肩代わりも介入も
「そういう順番で起きた1件」に見える。**割り込まれたことが分かる形にする。**

具体の作りは Claude Code が Q0-8 を踏まえて決めてよいが、**次を満たすこと**:

1. **手番の主（いま自分の番の駒）が画面上で分かる。** 誰の番かが分からないと「割り込み」が成立しない
2. **`Reaction` / `Intercept` / `Relayed` が立つ出来事は、手番の流れを一度止めて割り込んで見える**
   （間を空ける・手番の主を暗くする・専用の合図を出す 等。**演出の作り込みではなく区別が付くこと**が目的）
3. **`TurnStart` 直後の一括発火（Q0-5 の駒）は「誰の手番でもない時間」として束ねて見える。**
   いまは誰の番でもないタイミングで文字列が湧くだけになっている
4. **`Intercept` は「本来の標的 → 割り込んだ駒」に矢が逸れたことが見える。** 攻撃の線をそのまま
   ガルドへ引くだけでは「ガルドが殴られた」にしか見えない
5. **`Relayed` は「1発が分割されて中継された」ことが見える。** ゴルムの「耐久している感がない」に直接効く

### 5-2. 触ってはいけないもの

- **`BattleCore` を1行も触らない**
- 再生の**総尺を大きく伸ばさない**。1戦が長くなると6行を見る作業が重くなる。
  間を足すなら、**手番の中を詰めて手番の外に配る**（合計をほぼ変えない）
- 第124期に入れた表示（戦績パネル・書き手の細線・同時着弾・巻き込みの紫の輪 ほか）を壊さない

### 5-3. 段2 の終わり

`compare` 305 セルの 0 件差分（`DemoApp` のみなので自明だが確認する）／ **コミット**。
