# 第116期 —— 積み過ぎ（`Overload`）を据えのバンに載せる

起点: 第115期。`TraitId.Overload`（`AtkBonus >= 5` のあいだ単体の一撃が薙ぎになる）を**判定だけ**して、
**盤面には1ビットも入れていない**（`ReaderRule.Default` は `Threshold = 0` で不活性、`UnitCatalog` にも入っていない）。
Q1〜Q5 すべて ○。載せる駒は**据えのバン**。

**この期は「載せる」期。** 第107期の作法どおり、**採用と席の再判定を対でやる。**

**この指示書は自己完結させてある。** 規約は `CLAUDE.md` の規約節（(G1)〜(G16)）。

---

## 0. 主題

### 0-1. これまでの帳簿の期と違う点（**先に読むこと**）

第111期（トモを `compare` へ）・第114期（W2 の採用）は**1行しか動かなかった**。今回は違う。

> **バンは既に `Presets` の5行にいる。**
> `compare` 4 行 —— `溜め改 (クグ×バン×ガン)` / `反撃改2 (ガン×カド)` / `縛め収入型 (クグ×バン×ガン)` / `追撃×据え (ハギ×バン)`
> 交差帯 1 行 —— `強化×手番 (ガン×ドルガ×バン)`
>
> **差し替えではなく、既存5行の中身が一斉に変わる。**

**変数が5つ同時に動く**ので、**「何が効いたか」は行ごとに切り分けて読む**（第113期「計測器と測定対象を同時に動かさない」の親戚）。
**5行が同時に動くこと自体は避けられない**（バンを含む行を減らすのは行の差し替え＝別の判断）が、
**Phase 0 で行ごとに予測を立ててから測る**ことで切り分ける。

### 0-2. 閾値の当落は「量」ではなく「席」で決まる（第115期の台1'）

第115期の最大の発見:

> 号令の配りは **+4** なのに台1 の `AtkBonus` は常に **8.00**。
> **中央のガルド（`Stoic`）が全体強化を隣へ流すので、隣接する読み手に二重に届いていた。**
> 中央だけウケに替えた台1' では 4.00 一定・到達率 **0.000**・帰属 **0.0pt**。

実装で確認した盤面の規則（`BattleContext.SupportTargets` / `StoicTrait`）:

- **`BlocksSupport` を持つのはガルド 1 体だけ**
- 流れるのは**ばら撒き型だけ**（`SupportTargets` を通る＝**号令開戦・号令毎T・吐き戻し**）。
  **1体を選ぶ型（継ぎ当て・縛め・移り木）は流れない**
- **隣接数は席で違う**——**前2 なら 3 枠、前3 なら 1 枠**。**ガルドの席がそのまま拡散量になる**

> **したがって席の判定条件に「ガルドがどの席にいるか」を明示的に入れる。**
> 従来の席探索は平均と情報セルしか見ていないので、**この行では席が閾値の当落を決めていることを見落とす。**

### 0-3. この期で触らないもの

- **`Overload` の閾値 5**（掃引しない。第115期 §0-2 の理由がそのまま生きている）
- **バンの数値**（HP88 / 攻5 / 速2）と `Bulwark`（据え）。**`Overload` は2本目の特性として足す**
- **`Presets` の5枚組**（席は動かすが、駒は差し替えない）
- **R2（`Whet` の通知フック）** —— 第115期の分岐どおり測っていない。この期でも測らない

## 1. 手順

### (T1) 載せる

1. `UnitCatalog.Ban` の `Traits` に **`TraitId.Overload` を足す**（`Bulwark` は残す）
2. `ReaderRule` の既定を **`Threshold = 5`** にする（不活性 0 から）
3. **`PlusText` / `MinusText` を書き直す**——**1文で読めること**。
   `TraitId.Overload` のコメント（「外から積まれた力が一定を越えると、据えたまま薙ぎ払う」）が既にその文になっている。
   **フレーバー（「動かない者を守ることしかできない。動く者は守れない。」）は動かさない**

**`docs/units.md` が動くのは何期ぶりか**を報告書に書く（第111・112・114期はいずれも 0 バイト差だった）。

### (T2) 5 行を測る（**この期の本体**）

`compare` 61 行 × seed 0..199 × 5 波。**行ごとに**:

| | 内容 |
|---|---|
| **到達率** | バンの `AtkBonus >= 5` だったターン数 ÷ 決着T |
| **発火** | 薙ぎとして振った回数/戦 |
| **巻き込み** | 薙ぎで増えた被害体数/戦 |
| **`AtkBonus` の分布** | ターン別。**5 が分布のどこに来るか** |
| **中央が誰か** | **ガルドなら隣接数（前2 = 3 / 前3 = 1）も書く**（§0-2） |
| **Δ** | 素体（`Threshold = 0`）との差・波別 |

**交差帯 `強化×手番` も同じ表で出す**（12 行の1つ。行の性格が変わる可能性がある）。

### (T3) 席の再判定（**採用と対で。ただし全行はやらない**）

**測る前に、席を測り直す行の条件を固定する:**

> **(i) 情報セルが減った行 ／ (ii) 第五波が 95% を超えた行 ／ (iii) 第2〜5波平均が +10pt 以上動いた行。**
> このいずれかに当たる行だけ `reseat` を回す。**当たらない行は席を触らない。**

席の探索の線と採る条件（**同じ集合で書く**——(G16)）:

> **粗探索 seed 0..49 → 追試 seed 0..199（帯A）。
> 狙（その行の既存の狙）を満たし、かつ情報セル 2 以上を満たす席の中で、情報セル 4 → 3 → 2 の順、
> 各段の中で平均が最上位。現行席との差が 5.0pt 未満なら情報セルの多い側。**

**情報セルは帯A（seed 0..199）で数える**（(G14)）。

**加えてこの行では、候補の各席について「ガルドの隣接数」と「バンの到達率」を併記する**（§0-2）。
**席を採った理由に到達率が効いたかどうかを書く。**

### (T4) 帳簿

- `docs/` **10ファイル全再生成**（`units.md` を含む）。差分表
- **`Baseline`**: 主判定19行／全61行を併記。**`反撃改2` と `縛め収入型` が `PrimaryRows` に入っているかを Phase 0 で確認する**——
  入っていれば**主判定19行が6期ぶりに動く**。歯止め 33.2% との余裕を必ず書く
- **61 行の情報セル合計**（第114期は 164）と分布

## 2. Phase 0（**§2-2 の予測より先に。戦闘は分布の測定のみ**）

1. **バンを含む行の全数**（`compare` 4 行・交差帯 1 行）を `Presets` から**実装で数える**。指示書の記述を信用しない
2. **その5行それぞれの中央の駒**と、**ガルドがいるなら隣接数**（前2 = 3 枠 / 前3 = 1 枠）
3. **各行でバンに届く強化の経路**（号令開戦・号令毎T・縛め・吐き戻し・駆り立て・移り木・火選り・尾灯のどれか）と、
   **そのうちばら撒き型（`SupportTargets` を通る）はどれか**
4. **素体（`Threshold = 0`）でのバンの `AtkBonus` 分布**をその5行で測る。**閾値 5 が分布のどこに来るか**
5. **`Baseline.PrimaryRows` にその5行のどれが入っているか**
6. **バンが `ModifyAttack` / `ModifyPattern` を二重に持たないこと**（`Bulwark` は被ダメ側なので衝突しない、を実装で確認）
7. **過去にバンの機構を変えた期が無いか** `design/` を grep（第89期 (P2) が `溜め改` の席を更新している）

---

## 3. 予測（**Phase 0 の後・本測定の前に書く。行ごとに**）

**5 行それぞれについて、到達率と Δ の方向を先に書く。** 目安:

1. **`縛め収入型`** は縛め +16 が入るので**到達率が最も高い**。ただし縛めは**無作為に1体**を選ぶので**連続しない**
2. **`溜め改` / `強化×手番`** は号令（+8）が入る。**中央がガンなのでガルドの拡散は効かない**——
   **台1 の +44.1pt はそのまま再現しないはず**
3. **`反撃改2`** は前3 にバン・中央にカド。号令はガン（後3）から。**到達率は中位**
4. **`追撃×据え`** は強化の供給者がいない（ハギ・ゴルム・リィカ・ヴェル）。**ゴルムの吐き戻しが唯一の経路**で、
   **庇った相手にしか届かない**＝バンに届くかは席次第。**到達率は最低**
5. **拒否権**: バンを含まない 57 行（`compare` 61 − 4）は **±0.0**

**外れた項目は「何を数えていなかったか」の形で書く。**

## 4. 判定

| | 内容 | 線 |
|---|---|---|
| **Q1** | **拒否権**: バンを含まない 57 行が **±0.0** | 1セルでも動けば実装の事故 |
| **Q2** | **行によって到達率が割れるか**（第115期 Q2 の `Presets` での再現） | 4 行の最大と最小の差 **0.2 以上** |
| **Q3** | **壊れていないか**（(G1)(G2)） | −10.0pt 以上落ちた行が **0**。第五波 95% 超の行が **増えて 2 行以内** |
| **Q4** | **`Baseline`**（主判定19行・全61行）と歯止め 33.2% の余裕 | **余裕が +5pt 以上残る** |
| **Q5** | **情報セル合計**が 164 から**減っていない**（席の再判定の後） | ±0 以上 |
| **Q6** | **バンの1文が読めるか**（`PlusText` / `MinusText` が1文ずつ。フレーバー不変） | 目視 ＋ `docs/units.md` の差分 |

**この段階では勝率を揃えない。** 多少強すぎ・弱すぎは許容する。
**「明らかにゲームが成立しない壊れ方」だけを Q3 で見る。**

## 6. 結論と分岐

報告書 `design/PHASE116_LOAD.md` の冒頭に、**1つの引用ブロック**で
Q1〜Q6 の○×・動いた行と Δ・席を測り直した行・`Baseline` の2値・情報セル。

- **Q1・Q3・Q4 を通る**: **採用**。席を (T3) の条件どおり測り直して確定
- **Q3 が落ちる**（−10pt 以上の行が出る／95% 超が3行以上増える）: **バンに載せるのをやめる。**
  `Overload` は残置し、**`Presets` に居ない駒か、居る行が1つだけの駒**へ載せ替える期を次に立てる。
  **機構は否決しない**——第115期でローカル台では通っている
- **Q2 が落ちる**（4 行で到達率が割れない）: 機構は採るが、**「編成では動かない読み手」**として記録する。
  第115期 Q2 が `Presets` で再現しなかったことになるので、**ローカル台と `Presets` で結論が変わった理由を書く**
- **主判定19行が動く**（`PrimaryRows` に該当行がある）: **6期ぶり。**歯止めとの余裕を必ず書き、
  Q4 を落とすなら**席で戻せるか**を先に見る（第114期の形）
- **席の候補が (T3) の線を満たさない**: 席を触らず、**情報セルが減ったまま採るかを Q5 で判断**して代金を明記する
