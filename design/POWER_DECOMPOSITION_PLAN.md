## 1. なぜこれをやるか

10期分の測定はすべて同じ壁に当たった。

| 期 | 試した軸 | 順位相関 | 群差 |
|---|---|--:|--:|
| 第4期 | 部隊列の順序（逆順） | — | 第五波の勝率の言い換え |
| 第6〜8期 | 攻撃パターンの向き（範囲/単体） | 0.83〜0.94 | +0.125 波 |
| 第9期 | 自傷率 | 0.83〜0.94 | −0.131 波 |
| 第10期 | 敵のチャージ（時間軸） | 0.91 | 0.064 波 |
| 第11期 | 味方スキルのタイミング | 0.90〜1.00 | ほぼゼロ |

**何を作っても編成の序列が同じ順位で出てくる。** 支配的な次元が1本あり、それを「地力」と呼んできた。

**ところがその1本を一度も測っていない。** 総HPなのか、総攻撃力なのか、その積なのか、特定の駒の存在なのか、盤面配置なのか——分からないまま2本目を探し続けている。

**この作業は地力の中身を特定する。** 分解できれば、「地力に効かず、別のものに効く」設計を狙って作れる。次の作業（閾値を動かす効果の設計）は、その結果を前提にする。

## 3. Phase CA — 特徴量を出す `power`

診断モード。**`docs/` には出さない**（既存の診断と同じ扱い）。

### 3-1. 何を出すか

編成ごとに、**定義から計算できる量（静的）**と**戦闘から測れる量（動的）**の両方。31編成 × 各特徴量の表。

**静的（`Formation` と `UnitDef` から。戦わなくても分かる）**

| 特徴量 | 定義 |
|---|---|
| 体数 | 編成の駒数（4 or 5） |
| 総HP | 定義上の最大HPの合計 |
| 総攻撃力 | `Attack` の合計 |
| 積 | 総HP × 総攻撃力 |
| 最薄HP | 編成中いちばん HP の低い駒の HP。**閾値仮説の候補** |
| 後列HP | 後列（`back1` / `back2`）の HP 合計 |
| 平均速度 | `Speed` の平均 |
| 範囲枚数 | `Def.Pattern` が薙ぎ／全体の駒の数（既存の区分をそのまま使う） |

**動的（`UnitTally` から。既存フィールドで足りる）**

| 特徴量 | 出どころ |
|---|---|
| 与ダメ/戦 | `DamageToEnemy` の編成合計 ÷ 戦闘数 |
| 被ダメ/戦 | `DamageTaken` の合計 |
| 撃破数/戦 | `Kills` の合計 |
| 干渉数/戦 | `Interventions` の合計（**活動量の本体**とコメントにある） |
| 回復/戦 | `Healed` |
| 自傷率 | `TakenFromAlly ÷ DamageTaken`（第9期の定義をそのまま） |
| 与ダメ効率 | 与ダメ ÷ 撃破数。**オーバーキルの指標**。閾値仮説に直結する |

**目的変数**は突破度（第8期で導入したもの）。**測定台は第10期 AB-0 で新設した台（`bridge` の7列目）を主とし、既存5波を従とする。** 第8期の「136% で測ると何も見えない」は引き続き有効。

### 3-2. 注意

- **新しい tally フィールドを足さない。** 上の表は既存フィールドで足りるはず。足りないものがあったら、**足す前に報告する**
- 既存の出力に列を増やさない（`Healed` / `BigAttacks` のコメントにあるとおり、`pulse` の表を増やすと過去の出力と diff が出る）
- 静的特徴量は**定義値**から取る。会戦中の目減り（継ぎ接ぎの最大HP半減）は動的側の話

### 3-3. 受け入れ条件

- 15モードすべての差分 **ゼロ**（`power` は読むだけの追加）
- 特徴量の定義が報告かコメントで読めること

## 4. Phase CB — 分解

### 4-1. やること

**n = 31 しかない。** 多変量回帰を回すと確実に過学習するので、次の順で単純にやる。

1. **各特徴量と突破度の単相関**を全部出し、|r| で並べる
2. **最も強い1つを「地力の第一近似」とする。** その残差（実測の突破度 − その特徴量からの線形予測）を計算する
3. **残差と他の特徴量の相関**を出す。1段だけ。ここで残る2番目が「地力とは別に効いているもの」の候補
4. **残差が大きい編成 上位・下位5つずつ**を名前で出す。**予測より強い編成が、地力以外の何を持っているか**——ここが次の設計の入口になる

多変量は **2変数まで**。3変数以上は n=31 では意味を持たないので**やらない**。

### 4-2. 一緒に確かめること

- **静的だけでどこまで説明できるか。** 戦わずに分かる量（総HP・総攻・積・最薄HP）だけで突破度がどれだけ予測できるか。**静的で 0.8 以上説明できるなら、「編成を組んだ時点で結果がほぼ決まっている」ことになる**——これは設計上とても重い意味を持つので、はっきり出す
- **台による違い。** 主の台と既存5波で、最も強い特徴量が入れ替わるか。入れ替わるなら「地力」は台ごとに違うものを指していたことになる
- **与ダメ効率（オーバーキル）の位置。** 閾値仮説が正しければ、これが上位に来るはず。来なければ閾値仮説の再考が要る

### 4-3. 注意

- 相関はすべて**計算方法を明記**する（ピアソンかスピアマンか）。第8期以降の順位相関はスピアマンなので、**目的変数が突破度（連続量）ならピアソンも併記**する
- **因果を主張しない。** 「総HPが高い編成が強い」は「総HPを上げれば強くなる」を意味しない。報告では相関として書き、推測は推測と明記する

### 4-4. 受け入れ条件

- 15モード差分ゼロ
- 単相関の全一覧（上位だけでなく全部）
- 残差の上位・下位5編成を名前で

## 5. Phase CC — 記録と報告

### 5.1 README に書くこと

- **地力の第一近似は何か。** 単相関の順位と、最も強い特徴量の r
- **静的だけでどこまで説明できるか。** これが高いなら、**「編成した時点で結果が決まる」ゲームになっている**という事実を、良し悪しの評価抜きで記録する
- **残差の大きい編成**と、それらが共通して持っているもの（あれば）
- **与ダメ効率（オーバーキル）の位置。** 閾値仮説を支持したか
- 10期分の壁の総括: どの軸も順位相関 0.83〜1.00 だった一覧（§1 の表）

### 5.2 「未解決の課題」に足すこと

- **のろまの `SurrendersTurn`。** `SluggishTrait` は `SurrendersTurn` を上書きしていない（既定 true）ので、**「2ターンに1回しか動けない」という欠点が号令・据えに買い取られ、味方に収入を生んでいる**。一方チャージは `IdleTurn` を書かない（第10期 AA）。**同じ「動かないターン」が2つの異なる扱いを受けている**。整合を取る価値があるが、`compare` が動くので独立作業
- **特性が味方と敵で共有されている**（継ぎ当てがノノと敵の従軍司祭長で共有）。アクティブ/パッシブ分離を進めるたびに踏む。`Trait.ActsOnPattern` の分岐は暫定
- **順位相関は突破度が同一でも動く**（第11期で `charge`/`flip`/`bridge` の非該当行が示した）。順位を主指標にした8期分の測定すべてに効く注意点

既存の課題（自傷のリターン設計 / 味方パターン化の残り / 将来拡張 / `ctx.Revive` / 第二波の司祭ダミー / D5 / 部隊戦間の回復）は**そのまま残す**。

### 5.3 報告してほしいこと

1. **単相関の全一覧。** 最も強い特徴量とその r
2. **静的だけの説明力。** 戦わずにどこまで分かるか
3. **残差の上位・下位5編成。** 予測より強い / 弱い編成は何を持っているか
4. **与ダメ効率（オーバーキル）の位置。** 閾値仮説は支持されたか
5. **台による違い。** 主の台と既存5波で第一近似が入れ替わるか

## 6. 作業ルール

1. マージ → CA → CB → CC の順。**フェーズを跨いで1コミットにしない**（CC は文書のみ）
2. コミットメッセージに「動いた docs/ の行」を書く。**全フェーズ差分ゼロのはず**
3. コード・コメント・ログは日本語。既存の文体（**却下した案とその理由も書く**）に揃える
4. CONTRIBUTING.md のチェックリストを通す
5. 長時間ジョブは前景で待ち切る。`layout` は走らせない
6. **何も直さない。** 分解の途中で明らかな不整合を見つけても、記録して報告する
7. 以下を見つけたら**実装前に止まって報告する**:
   - 既存の `UnitTally` で表現できない特徴量があった場合（**足す前に報告**）
   - どの特徴量とも相関が低く（最大 |r| が 0.5 未満）、地力が既存の量で表せない場合。**その場合は「地力は測れなかった」という結論になるので、次の方向を決め直す必要がある**
   - `docs/` が動いた場合
