## 0. この期の狙いと、前提の説明

### 0-1. なぜこの期を立てるか

ロスターの回復役は4枚（継ぎ当てのノノ・毒喰らいのベニ・移り木のシオ・置き去りのナラ）だが、
**4枚とも「HPを戻す」という同じ1つのことを、発火条件だけ変えてやっている**。
「最も傷ついた味方」「敵の毒を数えて」「動かされた味方を」「速い味方を」——
違うのは宛先の選び方だけで、**次元が分かれていない**。

対してタンク3枚は次元が分かれている：ガルド＝**回数**（受け流し N 回）／
ゴルム＝**総量**（吸った累計）／ササ＝**単発上限**（超過を切って破片に）。
だから同席しても食い合わない。

この期は**回復に「時間」の次元を1本入れる**。
被弾した量の一部を「預かり」として積み、後から本人へ返す駒を作る。

### 0-2. 第118期（糧タンク）の申し送りを先に踏まえる

`design/PHASE118_TANK.md` を読むこと。この期に直接効く項目が3つある。

1. **§6-1 が否定したのは糧（`NourishTrait`）であって、回復そのものではない。**
   「自己回復だけの版」は素体比 **+1.55〜1.71T** で時間を買えていた。路線は生きている。
2. **§1-2「代金は係数で薄まらない」**——回復を厚くする → 生存が伸びる →
   殴られる回数が増える → 供給量が増える。**`Amount` を掃引しても比が動かない。**
   **この期の掃引は量ではなく「返す条件」のノブで行う。**
3. **§6-3 の申し送り2**——**判定式が読むセルが情報帯に入るかを、`run` を回す前に数える。**
   第118期は第四波が4台とも床か天井で、判定式が原理的に成立しなかった。

### 0-3. 渇き（第三波）との関係は、既存の実装でそのまま出る

`BattleEngine.Heal`（`BattleCore/BattleEngine.cs`）が**回復の単一窓口**で、
渇き（`DroughtBinding`）はその入口1箇所で止めている。

この機構は **積むときは `Heal` を通らず、返すときだけ通る**。したがって
**渇きの下では預かりは積まれ続けるが1点も返らない**。これは意図した挙動で、
「渇きの祭司を先に割れば預かりが一気に戻る」という回避判断が生まれる。
**実装で何かを足す必要はない。既存の構造がそのまま出るだけである。**

## 1. 作るもの

### 1-1. 札2枚（**分けて実装する**）

`BattleCore/Traits.cs` に追加する。

| 札 | 側 | 内容 |
|---|---|---|
| `TraitId.Ward` | プラス | 味方が被弾したとき、その量の `Percent`% をその味方の**預かり**に積む。返し方は `WardRule.Return` |
| `TraitId.Forfeit` | マイナス | **預かりを抱えたまま倒れた味方がいると、その預かりの全額が敵全体へ回復として渡る** |

**2枚に分けるのは器具の要件である。** `checkup` の `yP`（マイナスを外した版）は
`Traits` の配列から代金の札を抜いて作る。1枚に畳むと (ii)（分離できない駒）になり、
プラス値が測れない。**第74期に 裂き → `Rend` + `ThinBlade`、断ち → `Sever` + `Await` を
切り出したのと同じ作法**で、挙動は畳んだ版と1ビットも変わらない。

`checkup` の表P（`BattleSim` の走査）に載るよう、enum のブロック位置に注意すること
（`Ward` はプラス側、`Forfeit` はマイナス側）。

### 1-2. 状態キー `Ward`

`BattleEngine.cs` の `StatusKeys` に1本足す。**`StatusKeys.All` にも必ず足すこと**
（会戦が部隊戦の境界で状態異常を一律に消すために使う。既存の doc に明記されている）。

**既存のキーを流用しない。** 破片（`Armor`）は `ApplyDamage` の側で消費されるプールで、
預かりは `Heal` を通る別資源である。混ぜると帳簿が閉じない
（第143期に転倒が痺れを流用しなかったのと同じ理由）。

減衰は無い。上限も置かない（供給が被弾に縛られるので自然に止まる）。

### 1-3. 返し方のノブ（**2枝を並べて測る**）

```csharp
public enum WardReturn { Burst, Drip }

public readonly record struct WardRule(WardReturn Return, int Percent, int Threshold, int Drip)
{
    public static WardRule Default => new(WardReturn.Burst, 50, 40, 10);
}
```

| 枝 | 返す条件 |
|---|---|
| **`Burst`（本命）** | 預かりが `Threshold` に達した瞬間、**全額を返して 0 に戻す** |
| `Drip`（対照） | 毎ターン頭に `Drip` だけ返す。プールが尽きたら止まる |

**`Burst` を本命に置く理由**: 蓄積機構は周期ではなく**出来事の閾値**で区切る、
という既存の判断がある（`Charge` が明示的に棄却され、その理由が特性のコードに記録されている）。
加えて `Burst` は**殴られ続けないと返ってこない**ので、タンクには早く返り、
殴られない後衛には返らない——**席が判断になる**。

**`Drip` は捨てない。** 同じ台・同じ seed で並べる（第147期「2つのノブは同じ供給量の点で比べる」、
第152期の `ParrySwing` 2枝と同じ作法）。

## 4. 段取り

### 段0 —— 台の用意

判定に使う台を Q0-2 の手順で決める。**顔ぶれは台の名前が意味を保つ範囲で固定し、
埋め草の強さだけを掃引して 40〜95% の帯に入れる**（第152期 段0 と同じ）。
埋め草は**特性を1つも持たない素体**を使い、敵の数値には触らない。

最低限、次の4台を用意する。

| 台 | 目的 |
|---|---|
| **タンク同席**（ガルド or ゴルム or ササ を1枚） | 予測3 |
| **タンク無し** | 対照 |
| **死軸同席**（リィカ or ゾト or ムグ を1枚） | 予測4・`Forfeit` の帰属 |
| **陰性対照**（ノチ非在席） | 予測5 |

**素体差し替えで測る**（第69期の標準器具）——ノチの席を、特性を持たない同数値の素体に
差し替えた版を対照に取る。**第118期 §6-3 の申し送り1**（他の期の数値を線にするときは、
その数値がどの対照で出たかを書く）に従い、**この期の線はこの期の対照で引く**。

### 段A —— 実装（既定は `All` の外）

札2枚・状態キー1本・`WardRule` を足す。**engine に新しい規則や窓口を足さない**
（`OnAllyDamaged` / `OnTurnStart` / `OnAllyDeath` は既にある）。

**回帰**: `compare` 305 セルが `docs/balance.md` と **0 件差分**であること。
ノチは `All` の外なので、ここが 0 件でなければ実装がどこかで既定を動かしている。

### 段B —— 2枝の比較

`Burst` と `Drip` を**同じ台・同じ seed**（0..199）で並べる。
第2〜5波。段0 で帯に入らなかった波は判定から外す（外したことを報告書に書く）。

**帳簿**（1戦あたり平均）を取ること。

- 積んだ総量／返した総量／返らずに消えた量（＝没収された量＋戦闘終了時の残額）
- 閾値到達回数（`Burst`）
- 渇き下で止まった回数（`NoteDroughtBlocked` が既にある）
- `Forfeit` の発火回数と敵へ渡った量

> **収支が閉じること**（積んだ量 ＝ 返した量 ＋ 没収 ＋ 残額）を自己検査に入れる。
> 第118期は「発火 × `Gain` ＝ 渡した量 ＝ 窓口を通った量」で1点もずれなかった。同じ水準を要求する。

### 段C —— `Threshold` の掃引

**`Percent` ではなく `Threshold` を掃引する**（第118期 §1-2）。
7〜9 点。帯に入る範囲を先に見てから刻むこと。

**`Drip` 側も同じ点数で `Drip` 値を掃引し、供給量を揃えた点で `Burst` と比べる**

## 9. 書き方の規約（この期で守ること）

1. **行ごとの順位は Δ と取り分（Δ ÷ (100 − V0)）を併記する。** Δ だけの表で判断しない
2. **線に条件を書いたら、その条件で分母が何行に割れるかを先に数える。** 割れないなら線として機能しない
