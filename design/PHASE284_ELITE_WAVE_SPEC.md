# 第284期 指示書 —— 精鋭波（1000/300）を耐久と火力の評価軸として正式化する

この指示書は自己完結している。リポジトリ（`design/` の過去報告・`docs/`・コード）以外は参照しないこと。

## 0. 目的

**HP1000% ／ 攻300% のスケールを掛けた「精鋭波」を、ボス（標軸の解答確認）とは別の、耐久と火力を測る評価軸として正式化する。**

ポンの位置づけ: ボスでも雑魚でもない、難易度の高い精鋭部隊。移動軸のテコ入れで「9体の波（HP200%／攻200%）の全員生存」を指標にしたのと同じ使い方を、全軸に対して持てるようにする。

背景（Web 側 Claude が一時器具で先行測定した事実。§7 に照合用の値がある）:

- HP1000%／攻300% では、compare 64 行のうち全滅（第1〜5波＋九体2本の全7列 0%）が 24 行。生き残るのは**乗算（燃焼の脆さ・鱗）か蓄積（爪痕・ムド／カドの攻撃力上昇）を持つ行だけ**で、解法は燃焼・被弾強化・標（止め改）・カド反撃・鱗と複数に割れる（唯一解ではない）
- 回復耐久（耐久 ガルド×リリ）は 0%——「耐えてちまちま削る」が自然に消える
- 移動改は 56〜98% の勾配の上にいる——卒業指標として適切な難度
- **毒軸 4 行が全滅**（第1波スケール版のみ勝ち）——層も蓄積のはずなのに落ちる。原因の一次切り分けを本期で行う（§5-3）
- `BattleEngine.MaxTurns = 30` で打ち切り・打ち切りは敗北扱い。九・農兵 ×10 の総HPは 2,700（30×10×9）でボス（3,000）と同じオーダー——精鋭は実質「30ターンで削り切れるか」の DPS 下限も兼ねる

## 1. 範囲

**やること**: 精鋭波の定義（素の構成 × スケール）／器具 `elite`（compare 全行 × 精鋭 × seed 0..199）／生成物 `docs/elite.md`／毒軸全滅の一次切り分け（診断のみ・駒は触らない）。

**やらないこと**: 駒・特性・数値の変更は一切しない。Stages・波ルール・Presets に触らない。毒軸のテコ入れ（原因の記録まで。直すのは別の期）。難易度カーブへの組み込み（本編にどう出すかはバランス段階の仕事）。

## 2. 設計（測る前に固定する）

### 2-1. 精鋭波の定義

**素の構成にスケールだけを掛ける**。既存の第2〜5波に掛けると波ルール（粛・渇き・軛・断罪）と二重課税になり、特に軛（単発上限25・両陣営対称）は敵の攻300%をほぼ切ってしまうので、スケールが効かない列が混ざる。精鋭は「スケール1つだけが差分」の波として独立に切る。

| 波 | 構成 | スケール |
|---|---|---|
| **精鋭・五** | `EnemyWave.FillX(Recruit)`（討伐隊の新兵 45/11/6 × 5・X字） | HP 1000% ／ 攻 300% |
| **精鋭・九** | `EnemyWave.FillAll(Levy)`（駆り出された農兵 30/8/6 × 9・全席） | HP 1000% ／ 攻 300% |

- 2本置く理由: 体数は独立した軸（五=単体高倍率の土俵・九=薙ぎ・撒きの土俵）。精鋭でも符号が割れるかを見る
- 新兵・農兵は特性なしの既存敵。**新しい駒・数値は作らない**（対照の成立条件）
- 実効値: 精鋭・五 = HP450・攻33 ×5（総HP 2,250）／精鋭・九 = HP300・攻24 ×9（総HP 2,700）
- `Stages` には載せない（`Stage` は5枠 `Formation` で、数える器具が数百ある——第265期のボス波と同じ扱い）。`TestStages` の隣に精鋭用の置き場を作るか、`elite` 器具内の定義で閉じるかは Claude Code の判断でよい。**読むのは `elite` だけ**にする
- スケールの掛け方: 敵は `BattleEngine.MaterializeEnemy(wave, new EnemyScaleRule(1000, 300))` → `BattleEngine.Run(UnitState版)` で回る（第283期 `Boss283.cs` の `FightLite` と同じ口。`EnemyScaleRule` は `MaterializeEnemy` に直接渡せる）

### 2-2. 数値の宣言

**1000／300 で固定して測る**（Web 側の先行測定で、1000/200 → 250 → 300 の勾配上でも生き残りの顔ぶれがほぼ変わらないことを確認済み）。参考の刻み（1000/200・1000/250）は §5-2 の参考表として出すが、**採否には使わない**（escale fine と同じ扱い）。

### 2-3. 名前

器具名・生成物は `elite` ／ `docs/elite.md`。波の日本語名は仮に「精鋭・五」「精鋭・九」とし、**正式名はポンが決める**（報告書に候補を1〜2個添えてよい）。

## 3. Phase 0（実装前に調べ、報告書に書く）

1. **桁の安全**: `EnemyScaleRule(1000, 300)` で MaxHp・Attack の丸め（int 演算）に桁あふれ・ゼロ丸めがないか。`BattleEngine.cs` の `_cache.GetOrAdd((d, HpPercent, AtkPercent), ...)` がこの倍率でも正しくキャッシュを分けるか
2. **打ち切りの扱い**: MaxTurns=30 到達時の `PlayerWon`・`Turns`・集計（life 等）の値。精鋭では打ち切り負けが多発するはずなので、「負け」と「30T打ち切り」を器具で区別して数える（勝率と別列）
3. **乱射の長期戦累積**: トメ（T1n）の乱射（標なし時・敵味方へ 6×3発）が 30T 級の戦で味方をどれだけ削るか、ログ1本で確認（止め改 × 精鋭・五 × seed 0）。数えるだけで直さない
4. **`TestStages` を読む器具**: `nine` ほか `TestStages` を数える器具があるか grep。精鋭の置き場を `TestStages` に足す場合、既存器具の分母が動かないこと
5. **過去の類似**: `design/` の各期報告書を grep（「スケール」「escale」「200%」「精鋭」）。escale（第187期・S0〜A3 の7版）との関係を1行で整理（あちらは本編カーブの選定・こちらは評価軸。版の追加はしない）
6. **決定性**: 新兵・農兵は単体攻撃なので標的乱数を引く。ボス（全体・決定的）と違い seed で割れるはず——seed 0..19 で勝率が 0/100 に張り付かない行が存在することを確認（張り付くなら seed の意味を報告書に書く）

## 4. 段1 —— 器具 `elite`

- `BattleSim/Modes/Elite.cs`（`elite`）を新設。コマンドは既存の分岐（`Program.cs` の `focusId`）に足す
- **本体**: `Presets.Compare` 全 64 行 × {精鋭・五, 精鋭・九} × seed 0..199。出力は行ごとに: 勝率／平均決着T（勝ち試行）／打ち切り率／全員生存率
- **参考の刻み**: 同じ表を 1000/200・1000/250 でも出す（採否には使わない・見出しに明記）
- **`docs/elite.md`**: 器具から生成。`docs/` の再生成網（15ファイル）に入れるかは既存の作法に従う（`rules.md` の器具一覧には載せる）
- `sweep` の現役網に入れるかは Claude Code の判断（boss283 と同じく凍結庫側でよい）
- 自己検査: (a) スケール 100/100 に戻すと精鋭・五／九が検証・五／九（既存 TestStages）と全戦一致 (b) §7 の照合値と一致（seed 0..49・同じ行で ±数pt 以内。乱数系列が同じなので原則一致するはず） (c) 本編 compare が1セルも動かない（`elite` は戦闘を回すだけ）

## 5. 段2 —— 測定と読み

### 5-1. 主表（採否に使う）

- 全 64 行 × 精鋭・五／九 × seed 0..199
- **勝つ編成の集合が compare 本編と区別できるか**: 精鋭の勝率と本編第5波の勝率の r と max|Δ| を併記
- **唯一解でないこと**: 0% を離れた行を軸で分類し、3軸以上あることを確認（先行測定では燃焼・被弾強化・標・カド反撃・鱗・移動）
- **五と九で符号が割れた行の数**（体数軸が精鋭でも独立している証拠）

### 5-2. 参考の刻み（採否に使わない）

1000/200・1000/250 の同じ表。勾配の滑らかさ（0/100 の二値に張り付かず、移動改のように中間の行があるか）だけを見る。

### 5-3. 毒軸全滅の一次切り分け（診断のみ）

毒 (グザ×ミオ×ラウ) × 精鋭・九 × seed 0 のログ1本で、次のどちらかを確定する:

- (a) **層は積めているが隊が先に溶ける**（攻300%との寿命競争に負けている）→ 毒軸の課題は「守り」側
- (b) **層自体が積めない**（敵が死なず飛び火が起きない・30Tで層の総量が足りない）→ 課題は「積む速さ」側

数字（最終ターンの層の総量・毒による与ダメ・隊の崩れT）を報告書に書く。**直さない**。

## 6. 受け入れ基準と採否

| 基準 | 合格ライン |
|---|---|
| 精鋭と本編第5波の r | 低い（目安 r < 0.5。高いなら精鋭は第5波の焼き直しで不要） |
| 解法の軸 | 0% を離れた行が3軸以上に分布 |
| 勾配 | 中間（10〜90%）の行が1行以上ある |
| 回帰 | 本編 compare 64行 310セルが1セルも動かない |

- **A4**: 合格 → 精鋭・五／九を評価軸として採用。`docs/elite.md` を標準の生成物にし、**軸テコ入れの期は ELITE の該当行を卒業指標として見る**作法を `CLAUDE.md`（または作法置き場）に1行足す
- **B4**: r が高い → 精鋭は第5波と同じものを測っている。器具は対照として残置し、スケール以外の差分（体数・構成）を検討する残件を立てる
