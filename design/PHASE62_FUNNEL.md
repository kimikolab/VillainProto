### 1-2. `Whet` の窓口と `Dull` の横取り（鏡にする形）

`Dull`（`BattleEngine.cs:2363`）の横取りは次の形をしている:

1. `target` 自身が横取り役（`Bear` / `Relay`）なら**横取りしない**（再帰を作らない）
2. 候補は `LivingMembers(target.TeamId)` から `u != target` かつ横取り役かつ `AreAdjacent`
3. 候補が複数のときだけ `PickOne`——**候補 0 / 1 個では `Roll` を消費しない**
4. 横取り役が1枚もいない行では**乱数列が1ビットも動かない**（これが第43期の受け入れ基準）

`Whet`（同 2535）の `receiver` の位置には、第56期のコメントが
「読み手を作る期が来たら receiver を差し替える形で同じ位置に立てられる」と席を空けてある。
**この期はそこに立てるだけで、engine に新しい窓口は1つも足さない。**

### 1-3. `AcceptsSupport` の扱い（決めた理由）

**自前で濾す側に揃える**（駆り立て・縛め・移り木・火選りと同じ）。
`SupportTargets` で隣へ流す側（号令2本・吐き戻し）には**揃えない**。理由は火選り（第58期）と同型:
横流しは「**自分の隣で一番遅い味方**」という規則そのものが宛先を決めているので、
`SupportTargets` で漏らすと**流れた先が「一番遅い隣」とは限らず、規則が破れる**。
受け取れない相手（ガルドの `Stoic`）は候補から外し、**次に遅い隣**が宛先になる。
**積み残し7（`AcceptsSupport` の統一）はこの期でも触らない。**

## 4. 作ったもの

### 4-1. engine（`Whet` の窓口の中・**新しい窓口はゼロ**）

`BattleContext.Whet` の `receiver` の位置に、`Dull` の集約・転嫁と**同じ位置・同じ形**で立てた。

```
if (FunnelActive)                                   // 盤上に横流し役がいるときだけ通る短絡
    funnel = target が横流し役なら target 自身
             そうでなければ target に隣接する横流し役（複数なら PickOne）
    if (funnel != null)
        cands = funnel に隣接する生存味方
                { u != funnel, u.AcceptsSupport, !u.HasTrait(Funnel) }   // 1ホップで止める
        if (cands.Count > 0)
            want = Slowest ? cands.Min(Def.Speed) : cands.Max(Def.Speed)
            dest = PickOne(cands.Where(Speed == want))                   // 同速のみ Roll
            if (dest != null && dest != target)
                receiver = dest
                FunnelTaken / FunnelByRoute / FunnelFrom / FunnelTo を数える
```

- **量は加算のまま**（減衰も倍率も無い）。**強度のノブが無い**ので振るのは選択子だけ
- `WhetRoute` は**足していない**（供給ではなく横取り。`DullTakenByRoute` と同じ扱い）
- `WhetToPerverse` / `WhetPerverseFlips` は **`receiver` に対して**数えている（既存のまま）
- `FunnelDead`（回した先が `PerformAttack` を1回も通らなかった量）は
  `BattleResult` の構築時に `TallyByUnit` と突き合わせて引く（`ScaleLeftover` と同型）
- 差分は BattleCore 4ファイルで **+273 行 / −9 行**、うち engine の判定は 40 行

## 11. 分かったこと（後の期が引くもの）

### 11-1. **`reseat` の帯の峰は、機構ではなく台の配置感度を測っている**（第62期・**第58期 Q6 の訂正**）

素体（同数値・特性なし）の帯を並べると、**峰の数は同数か素体のほうが多い**（3/3・1/2・1/2）。
帯は「その5枚をどう置くと勝てるか」の分布で、**機構が無くても編成そのものの配置感度が全部乗る。**
**第58期の Q6（「行1と行3は多峰」）はこの対照を取っていない。**

> **「配置の判断が生まれたか」を測るなら、席ごとの帰属（現行 − 同じ席の素体）の符号を見ること。**
> 実測でこの2つは逆の答えを出す——帯が単峰の2行でも、席ごとの帰属は
> **+12.2 / -2.7** と **+8.9 / -9.5** で明確に符号が割れている。

### 11-2. **「行き先を書き換える」機構の値段は、行き先に立っている駒の性質がすべて**（第62期）

同じ規則・同じ5枚で、**ヌキの席を1つ動かすだけで帰属が 18.4pt 動く**（火選り行の 前1 -9.5 / 前3 +8.9）。
動いているのは**量ではない**——前1（宛先ムド・流量 89.9%）のほうが前3（宛先ホタ・流量 46.1%）より
**2倍流している**のに 9.5pt 負ける。**流量と価値が逆を向く。**

    宛先が 熾のホタ（燃焼中は乗算 4 倍）        → +8.9pt
    宛先が 泥人形ムド（攻3・被弾強化）          → -9.5pt
    宛先が 棘鎧のカド（不動・一度も振らない）   → 回した全部が死蔵（100.0%）
    宛先が 大喰らいゴルム（吐き戻しの出どころ） → 自己循環し、-9.5pt

**第60期 13-2「弱体の帳簿を『撒いた総量』で読むと値段を1桁間違える」の強化側の版**で、
しかもこちらは**同じ駒・同じ規則の中で**符号が入れ替わる。

### 11-3. **選択子の向きは本体ではない。本体はその端に誰が立っているか**（第62期・指示書 §4 の二択の否定）

指示書は V1（遅い）と V2（速い）の対照に
「反転すれば**遅さに流す**のが本体・反転しなければ**集める**のが本体」という二択を置いたが、
**実測は行ごとに違う答えを出した**（V1 → V2 で +1.8→-0.4 / +12.2→-3.4 / **+8.9→+10.4**）。
**行3では V2 のほうが強い**——V2 の宛先が焼け残りのボルグ（攻18・薙ぎ）だからで、
「速いほうが得」でも「遅いほうが得」でもない。
**選択子は宛先を1体に決める関数にすぎず、値段はロスターの側にある。**

### 11-4. **供給者は自分の取り分を横取りできない。だから「自分は育たない」は自動で立つ**（第62期）

横流し量のうち**ヌキ自身から取り上げた分**は 0.35 / **11.26** / **4.82** / **4.00** 量/戦で、
供給が「味方全体」型の行（号令）では**横流し量の半分以上が自分の取り分**だった。
ヌキが受け取った強化は **0.00〜0.03 量/戦**——ただし**厳密な 0 ではない**。
隣接する生存味方が全員 `Stoic` か死亡で候補集合が空になると、自分の取り分がそのまま残る。
**「必ず 0」を規則として書くなら、候補が空のときに捨てる分岐が要る**（今回は入れていない
——強化が消える挙動のほうが読めないため）。

### 11-5. **`Stoic`（ガルド）は「候補にすら入らない」ので、宛先の選択を静かに1段ずらす**（第62期）

`AcceptsSupport` を自前で濾す設計にした結果、**ガルドは速4 でロスター3番目に遅いのに一度も宛先にならない。**
縛め行の仮置き（ヌキ 後1・隣がガルドとガン）では候補がガン1枚に潰れ、
**V1 と V2 が同じ宛先になって選択子が測れなくなっていた**（`funnel phase0` の §3 で実装前に検出）。

> **「一番◯◯な隣」型の選択子を作るときは、`AcceptsSupport` で落ちる駒を除いた候補集合の
> 大きさを実装前に数えること。** 候補が1枚に潰れる席では選択子そのものが観測できない。

### 11-6. **判定式の自己検査は4期連続で「分母」を捕まえている**（第59〜62期）

第59期（条件節が分母の全部を選ぶ）・第60期（条件が原理的に成立しない）・第61期
（分母の割合が小さすぎて発動しない）に続いて、第62期は**事前に**2つ捕まえた——
**Q5（ウツを含む試験行が 0 行）と Q8（主判定19行にヌキを含む行が 0）。**
**新駒の期は、試験行を複製として作る限り歯止め（Q8）は構造的に発動しない。**
**歯止めが拒否権になるのは、既存の主判定行そのものを差し替える期だけである。**
