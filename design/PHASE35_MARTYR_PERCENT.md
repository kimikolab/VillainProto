### 0-3. 発火の上限（外挿）

    発火/戦 ≒ 勇者候補が生きているターン数 × 味方が前列へ振る単体攻撃の頻度 × p

p50 の実測は **1.12 回/戦**（HP52・全42行平均）。**p に線形なら p75 で 1.68・p100 で 2.24。**
掃引で実測と突き合わせる。**伸びていなければ 0-4 のどれかが効いている。**

### 0-4. 線形仮定が崩れる要因（事前に列挙）

1. **p=100 は判定が決定的になる。** `Roll(100) < 100` は必ず真なので、
   庇いの成否から乱数が消える。**seed 間の分散が変わる**ので、勝率の動きが
   「密度が上がった」だけでなく「ばらつきが減った」を含む
2. **発火増 → 殉教者の成長加速 → 殉教者が早く割れる。** 逸れた被弾がそのまま
   殉教者の HP を削るので、p を上げると**窓の閉じ方が (i)「殉教者が落ちる」側に戻る**。
   第34期に律速だった (ii)「勇者候補が落ちる」から (i) へ逆戻りする可能性がある
   ——**この場合、発火は p に対して飽和する**
3. **`Roll` の消費回数が変わる。** p を変えても `Roll(100)` は必ず1回消費するので
   ここは不変。ただし**庇いが成立するかどうかで以降の盤面が変わる**ので、
   同じ seed でも展開は別物になる（線形外挿はあくまで平均の話）
4. **介入分が正の行**（刻み +4.0・毒+耐久 +4.0・刻み×抉り +2.0・縛め収入型 +1.0）は
   p を上げると**さらに上がる**。庇うを資産に変換している行なので、
   密度を上げると波が易しくなる方向に働く

### 0-5. 事前の見立て

**採用基準1（庇うが作った新規の固有の敗者 ≥1）を満たす可能性があるのは
p75 の 裂き 1 行のみ**で、しかも外挿値が閾値ちょうど（10.0）。
**線形が崩れれば（0-4 の 2 が最有力）届かない。**

**したがって本期は「立たない」に転ぶ確率が高いと事前に見る。**
その場合の結論は指示書の文言どおり——
**「この盤面で介入の試験は窓の長さでも密度でも立たない」。**

## Phase 1: 実装

### 1-1. 敵側の割合の分離

`GuardianTrait.RedirectPercent` は**味方ガルドと共有**なので、そのまま振ると
**ガルドを含む 28 行が全部動いて交絡が戻る**（第34期に HP が波の総HPを一緒に動かしたのと同型）。
分離した。

**「定義は1箇所」を保つため、重複ロジックは共通の基底に寄せた。**

    RedirectGainTrait（新設・abstract）
      ├ DamagePerGain = 2 / PendingKey = "guardPending"
      ├ OnDamaged   肩代わりで受けた分だけ攻撃 +dmg/2（source が null の継続ダメージでは育たない）
      └ OnCarryOver 部隊戦の境界で印を消す
        ├ GuardianTrait : RedirectGainTrait   RedirectPercent = 50（味方ガルド。1文字も触っていない）
        └ MartyrTrait   : RedirectGainTrait   DefaultPercent（敵の殉教者）

`GuardianTrait` から**中身を丸ごと基底へ移し、残ったのは `RedirectPercent` と `Id` の2行だけ**。
挙動は 1 行も変わっていない（`PendingKey` の値も `"guardPending"` のまま共有）。

> **`PendingKey` を両者で共有したのは意図的。** 介入の鎖は最初に成立した段で `return` するので
> 一度に立つ印は必ず1つ。別キーにすると「どちらの段で逸れたか」を engine が覚える必要が出て、
> 窓口が増える。

**割合は `MartyrRule` で外から差す**（既定 `MartyrTrait.DefaultPercent`）。
**書き換え可能な static のノブは置いていない**——Trait は共有シングルトンで `layout` は
戦闘を並列実行するので、static だと版が他スレッドへ漏れるし `Run` の
「副作用も外部依存もない」が壊れる（`ColossusRule` / `YokeRule` / `HushRule` と同じ判断。
指示書の「診断専用の setter 等」の「等」をこの形で満たしている）。

### 1-2. 介入の鎖への追加

`BattleEngine.SelectTargetChain` の**庇うの段の直後**に殉教の段を足した。
同じ `Row.Front` 条件・同じ `f != target` 条件。

    標的(590) → 後備え(598) → 庇う(607・ガルド) → **殉教(新設・殉教者)** → 棘守り

**ガルドの段の直後に置いた。** 前に置くと、味方が庇うを持つ盤面で殉教がガルドを
差し置くことになる（ガルドが 50% の専任である以上、先の権利は残す——棘守りを
ガルドの後ろに置いたのと同じ理由）。実際には `foes` が攻撃者の相手陣営 1 つだけなので
両者が同時に立つ局面は無く順序は観測できないが、既存の鎖の作法に合わせた。

**`Stages[4]` の殉教者の特性を `Guardian` → `Martyr` に差し替え。**

### 1-3. 同値検証（実装の受け入れ条件）—— **通過**

    p=50 の compare 全42行 × 全5波 = docs/balance.md と **完全一致（1バイトも違わない）**

**乱数はずれなかった。** `PickOne` は**候補 0 個・1 個では `Roll` を消費しない**
（`BattleEngine.cs:472-477` の `switch`）ので、段を1つ足しても呼び出し回数が変わらない:

| 局面 | 変更前 | 変更後 |
|---|---|---|
| 味方が第五波を殴る | 庇う段 `PickOne([殉教者])`（Roll 0）→ `Roll(100)` | 庇う段 `PickOne([])`（Roll 0）→ 殉教段 `PickOne([殉教者])`（Roll 0）→ `Roll(100)` |
| 敵が味方（ガルド入り）を殴る | 庇う段 `PickOne([ガルド])` → `Roll(100)` | 同左。逸れなければ殉教段 `PickOne([])`（Roll 0） |

**ガルドの段への diff はゼロ**（`git diff` で `guardian` を含む変更行が 0 行）。

`docs/units.md` は 1 行増える（`| Martyr | - |`）。特性一覧に新しい `TraitId` が載っただけで、
`Executioner` / `Ephemeral` と同じ「味方側の保持者なし」の行。

### 2-5. Phase 0 の外挿との照合

| 量 | 外挿（線形） | 実測 | 差 |
|---|--:|--:|---|
| 発火/戦 p75 | 1.68 | **1.56** | **−0.12（下振れ）** |
| 発火/戦 p100 | 2.24 | **1.95** | **−0.29（下振れ）** |

**発火の下振れは 0-4 の要因 2 が正体。** 事前に「発火増 → 殉教者の成長加速 →
殉教者が早く割れて窓が (i) 側に戻る」と書いたとおり、
**殉教者の生存Tが 1.82 → 1.68 → 1.57 と縮んでいる**（p を 2 倍にして −14%）。
密度の増加が長さの減少に一部食われて、発火は p に対して**逓減**する。

**律速はやはり勇者候補。** その生存Tは 3.02 → 3.06 → 3.09 と、
**p を 2 倍にして +0.07 ターンしか動かない**（対照 2.87 からでも +0.22）。
第34期の「窓を閉じるのは (ii) 勇者候補が落ちること」がここで再確認された
——**庇うで守っても、勇者候補は 0.2 ターンしか長生きしない。**

## 結論 —— 介入の試験は **密度でだけ立った**

| | 窓の長さ（第34期・HP） | 窓の密度（第35期・p） |
|---|---|---|
| 振った量 | 52 → 145（2.8倍） | 50 → 100（2.0倍） |
| 庇うが作った固有の敗者 | **0**（HP145 の 2 行は停止条件を3つとも踏む） | **1（裂き）@ p75** |
| 交絡 | **あり**（波の総HPが +26%。用量反応の82%が体） | **無し**（総HPは1も動かない） |
| 発火の伸び | 1.12 → 1.66（1.5倍。生存T 2.1倍に対して逓減） | 1.12 → 1.95（1.7倍。同じく逓減） |
| 律速（勇者候補の生存T） | 動かない | **3.02 → 3.09。動かない** |

**両期で同じことが確認された——庇いの窓を閉じているのは勇者候補で、
そこは体でも密度でも動かせない。** それでも密度なら交絡が無いので、
**わずかな差（裂き 11.5 → 9.5）がそのまま帰属できる形で残った。**

**立った幅は狭い。** 42 行のうち 庇うに帰属する敗者は 1 行だけで、
最大の課税対象である 毒+ベニ+ラウ（介入分 −27.5）は
他波最小 0.0 のため判定に 1 度も乗らない。**この構造は割合では動かせない。**

## 手法として残るもの

- **共有する定数は、片方だけ振りたくなった時点で分ける。**
  `RedirectPercent` を味方ガルドと共有したままなら、殉教者の割合を振るたびに
  28 行が一緒に動いて何を測ったか決まらなかった。**分けるときは挙動を基底へ寄せて
  「定義は1箇所」を保つ**——`GuardianTrait` に残ったのは 2 行だけ
- **介入の鎖に段を足しても乱数はずれない。`PickOne` が候補 0 個・1 個で `Roll` を
  消費しない**ように作ってあるおかげで、`compare` が 1 バイトも動かない同値検証が通る。
  **段を足す変更の受け入れ条件はこの一致でよい**
- **交絡の有無で、同じ大きさの効果の価値が変わる。**
  第34期の HP145 は −25.0pt 動かしたが 82% が体だったので帰属できず、
  第35期の p75 は −0.4pt しか動かしていないのに 1 行を帰属できた。
  **「どれだけ動いたか」ではなく「何が動かしたか」で採る**
- **窓を持つ機構の律速は、窓を閉じる条件のうち**動かせないほう**が握る。**
  庇いの窓は「庇い手が落ちる」と「守る相手が落ちる」で閉じ、
  体（第34期）でも密度（第35期）でも後者は動かなかった（生存T +0.2）。
  次に効かせるなら**守る相手を増やす**（前列を3枚にする）しかないが、
  それは波の総HPを動かすので第34期の交絡に戻る
- **密度を上げると、その機構を資産に変換している行の取り分も増える。**
  縛め収入型 +1.0 → +8.0 / 毒爆弾 −1.5 → +5.0 / 仇討ち×砕け −1.0 → +2.0。
  **課税の強化は一様ではなく、符号が反転する行がある**
