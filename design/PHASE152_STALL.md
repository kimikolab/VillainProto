### Q0-5. 「在庫が満タン」の判定をどこに置くか —— **指示書の定義は成立しない**

**いまガルドが殴らないのは `ParryTrait.CanAct` で落としている**（`Actions` ではない）:

```csharp
public override bool CanAct(BattleContext ctx, UnitState self, ActionKind kind)
    => kind != ActionKind.Attack || ctx.Parry.Uses <= 0;
```

指示書 §Q0-5 は「**満タン ＝ 在庫が `Uses`**」と定義したが、
**この定義は膠着では1回も成立しない。**

| 駒 | 速さ |
|---|--:|
| 継ぎ当てのノノ | 6 |
| **戦斧兵（敵）** | **5** |
| **廃棄聖騎士ガルド** | **4** |
| 棘鎧のカド | 4 |

行動順は速さ降順なので、**戦斧兵はガルドより先に振る**。膠着の1ターンは:

```
ターン頭  OnTurnStart  在庫 1 → 2（構え直し）
          戦斧兵(速5)  ガルドを薙ぐ → 受け流し → 在庫 2 → 1
          ガルド(速4)  ここで CanAct(Attack) が問われる。**在庫 = 1 ≠ Uses = 2**
```

**`demo` のログがそのまま証拠**——毎ターン頭の構え直しが `0 → 2` ではなく **`1 → 2`** である
（＝前のターンの終わりに在庫が 1 だった＝その手番では満タンでなかった）。

> **指示書 §0 の前提「膠着の局面（在庫が減らない＝殴られていない）」は事実として誤り。**
> **膠着とは「在庫が 0 まで落ちない」ことであって「在庫が減らない」ことではない。**
> 膠着の条件は指示書自身が正しく書いている——**「敵の1ターンの攻撃回数 ≤ 在庫 N」**。
> つまり在庫は毎ターン減っており、**0 に届かない**だけである。

**判断（ポンに諮って決めた）**: **厳密版と緩い版を両方ノブの枝にして、同じ台・同じ seed で並べる**
（第147期「2つのノブは同じ供給量の点で比べる」の作法）。

```csharp
public enum ParrySwing { Off, WhenFull, WhenStocked }
```

| 枝 | 条件 | 意味 |
|---|---|---|
| `Off` | —— | **既定。いまと1ビットも違わない** |
| `WhenFull` | 在庫 ≧ `Uses` | **指示書の字面。** そのターンまだ誰にも殴られていない手番だけ振る |
| `WhenStocked` | 在庫 > 0 | **指示書の意図。** 受け流す余裕が残っているうちは振る |

**中継（`Relay`）で在庫が戻った直後の扱い**: **区別しない**（どちらの枝も現在値だけを読む）。
理由は2つ——(1) 在庫の出どころ（構え直し／庇いの見返り）を判定が読み分けると、
**`SurrendersTurnIn` が「殴ったのに手番を差し出した」状態を作れてしまう**（同じ札の3面が食い違う）。
(2) 庇いの見返りで戻るのは**身に受けた**ときだけなので、
「戻った直後」は**被弾した直後**であり、緩い版では元から振る条件を満たしている。

**`SurrendersTurn` との整合**: 振ると決めたターンは `IdleTurn` が立たないので、
中継（段3）は**そのターンだけ**売るものが無くなる。**これは代金であって不整合ではない**
——engine は `CanAct` が偽の駒にだけ `IdleTurn` を立てる（第103期）ので、自動的に揃う。

## 段B —— `ParrySwing` の実装（既定 `Off`）

`ParryRule` に4つ目の枝を足した。**engine に規則も窓口も1本も足していない**
（`ParryTrait.CanAct` の中身を書き換えただけ）。

```csharp
public enum ParrySwing { Off, WhenFull, WhenStocked }

public override bool CanAct(BattleContext ctx, UnitState self, ActionKind kind)
{
    if (kind != ActionKind.Attack || ctx.Parry.Uses <= 0) return true;
    return ctx.Parry.Swing switch
    {
        ParrySwing.WhenFull    => self.RawCounter(StockKey) >= ctx.Parry.Uses,
        ParrySwing.WhenStocked => self.RawCounter(StockKey) > 0,
        _ => false,
    };
}
```

**`CanAct` にログも計数も置かなかった**——この窓口は行動順ループのほかに
`BattleContext.CanActNow`（灯の動的な濾し・第113期）からも問われるので、**1ターンに複数回呼ばれる。**
計数（`UnitTally.ParrySwings` / `ParrySwingsFull`）は `TakeTurnCore` が**1手番に1度だけ**数える
（第115期「同じ比を作る2つの計数は同じ瞬間に取る」）。**どの規則も読んで分岐しない。**

回帰: `compare` 305 セル **0 件差分**。`docs/` 14 ファイルのうち動いたのは
`rules.md` と `harm.md` の `ParryRule` の `ToString` だけ（＋ `rules.md` の enum 一覧に1行）。

> **`docs/watch.md` は `watch` ＋ `watch phase0` の2本で作る。**
