# Godot向けアセット調査と今後の計画案

調査日: 2026-10-10

この文書は、既存の素材・エフェクト・開発支援ツールを活用して、VillainProtoの表現と制作効率を改善するための相談メモ。
**NatureBlocksとEffectBlocksはユーザーが購入済み。草原D・敵の燃焼・ホタの火球5連撃・炎貫通CをDemoApp本編へ適用。**

- 評価は配布元の説明・価格・利用条件、掲載画像、既存コードと保存済み戦闘画像に基づく。見た目の相性と導入負担は暫定的な判断。

## 利用条件のメモ

以下は公開説明の要約であり、採用時は取得した版に同梱されたライセンスを確認・保存する。

- **NatureForge:** 商用利用可、クレジット不要。素材単体や素材パックとしての再販売・再配布は禁止。
- **Medieval Houses:** 独自のEmacEArt Asset License。掲載ページは同梱の`LICENSE.txt`を参照する形なので、採用前に全文を確認する。
- **NatureBlocks／EffectBlocks:** 商用・非商用のプロジェクトで利用可。素材自体の再販売・再配布は禁止され、改変した素材も対象。
- **Effekseer:** Godot用プラグインはMIT。公式配布サンプルにはCC0のものが多いが、旧作品には「Effekseerと一緒に使用する場合のみ」という別条件がある。ツールと個々の素材の条件を分けて確認する。
- **MITのツール:** 採用したコードの著作権表示・ライセンス文を保持する。
- **Ovani Sound:** 商用利用向けの独自ライセンス。素材を採用する時に同梱条件を確認する。

素材の公開リポジトリへの同梱可否は、ゲームに組み込んで配布できるかとは分けて確認する。
採用した素材は、製品名・作者・取得元URL・取得日・版・ライセンス・使用箇所を記録する。

## 改善の方向性

保存済みの戦闘画像からは、木の形、草のまとまり、地面の変化を整える効果が大きそうだと判断した。
背景の密度を上げる場所は画面の奥と左右を中心にし、戦闘域の中央は駒・足元の輪・HP表示を読みやすく保つ。

エフェクトは、現在の固有演出の意味を保ちながら、着弾・煙・火の粉・破片などの部品を補う。
派手さだけで選ばず、「誰が誰に何をしたか」が読み取れることを優先する。

## 今後の計画案

以下は当初の段階案。無料デモの外観評価と購入を終え、現在は段階2の背景比較と、段階3に向けたエフェクト部品比較を進めている。本編への適用はまだ行っていない。

### 1. 無料デモで背景とエフェクトを比較する

1. NatureForgeのデモとNatureBlocksの無料デモを見て、背景の方向性を比較する。
2. EffectBlocksの無料デモから、着弾・煙・雷を中心に確認する。
3. 配布デモの見栄えと、自分たちの画面で使える素材・設定を区別する。
4. 「無料背景で十分」「有料背景を試したい」「エフェクトだけ試したい」のどれに進むか決める。

比較する項目:

- キャラクターとの画風の馴染み。
- 木・草・地面などの質感と、色や明るさの調整しやすさ。
- 個々の素材を必要な場所だけに使えるか。
- 現在の制作方法で扱いやすいか、追加の制作手順がどれだけ必要か。

無料デモが閲覧用実行ファイルだけの場合は、プロジェクトへの組み込みまでは確認できない。
その段階の結論は「外観の候補選定」に留める。

### 2. 草原の戦場1つで背景を試す

対象はまずDemoAppの草原戦場1つ。別の検証シーンで、既存版と比較できる形にする。

- カメラ位置と駒の配置を揃える。
- 木・岩・草・地面を一度に全部替えず、効果を比較できる単位で試す。
- 背景に合わせて照明と色を調整する。配布デモの照明設定を重複して持ち込まない。
- 中央の見通しと、足元の輪・HP表示の読みやすさを確認する。
- 同じ条件で画像とフレーム時間を比較する。作者のデモの性能をそのまま自分たちの性能と扱わない。

この段階で、背景1セットの採否を決める。村・城門・作戦マップへの展開はその後にする。

### 3. エフェクトを少数だけ実戦に組み込んで比較する

初回は「通常攻撃の着弾」「炎の煙・火の粉」「雷の着弾」など、既存版と差を見やすい数例に絞る。

- 色・大きさ・持続時間を現在の戦闘に合わせる。
- 単発だけでなく、複数の駒が同時に発動する場面を確認する。
- 一時停止・再開・倍速に同期し、演出だけ進んだり残ったりしないか確認する。
- 駒の死亡、シーン終了、戦闘の再開始で演出が残らないか確認する。
- 駒やHP表示が隠れないこと、対象と発動者が読み取れることを確認する。
- 再生側だけで完結させ、戦闘結果やBattleCoreの判定を変えない。

EffectBlocksで不足する専用演出が具体化したら、Effekseerのサンプル1つを使った検証に進む。
最初から両方の制作方式を全面導入しない。

### 4. 必要が明確になった支援ツールを追加する

- カメラ演出の調整が増えたらPhantom Camera。
- 会話・仲間加入イベントを作るならDialogue Manager。
- 作戦マップの地形編集が必要になったらTerrain3D。
- AnimationPlayerによる粒子演出の編集を始めたらVfx Animation Player。
- 環境音・UI音が不足したらOvani Soundのパック。
- エディタ内の素材配置や画面確認が作業上の負担になったらGodot AI。

### 起動

購入素材は `DemoApp/PolyBlocks/` へローカルコピー済み。このフォルダ全体をGit管理から除外する。
別環境では購入した原本を用意してから、リポジトリ直下で次を実行する。

```powershell
# 初回だけ。既存のコピーがある場合は上書きせず停止する。
./DemoApp/PrepareAssetPreview.ps1 -AssetRoot 'D:\Assets\GodotAssets'
# ビルド・インポート・比較画面の起動
./DemoApp/RunAssetPreview.ps1
```

上部ボタンで背景、効果、一時停止、1倍/2倍/0.25倍を切り替える。「もう一度再生」で演出を最初から見られる。
燃焼状態では「燃焼：あり／なし」「燃焼対象：敵1体／3体」を切り替え、継続表示と解除後を比較できる。
右上の「視点を調節」でカメラを動かした後も、そのままの視点でA/Bを比べられる。
一時停止は駒・粒子・Tweenが対象。草木の風など、シェーダー内のTIMEによる環境アニメーションは停止対象外。
FPS表示はその場の参考値で、定常状態の性能測定ではない。背景4種類をメモリに置く比較画面なので、製品版のメモリ使用量とも異なる。

### 初回比較の感想と反映（2026-10-10）

ユーザーの評価:

- 背景は既存の隆起・起伏のほうが見栄えがよい。
- 木や茂みは購入素材のほうが自然。
- 炎は購入素材のほうが自然で、敵側の燃焼状態として検討したい。

初回の購入背景は比較コードが平面を置いていたため、素材の違いに加えて地形の違いも混ざっていた。
平坦さはNatureBlocks自体の制約ではない。今回の背景Cは既存の地形生成と高さ関数を再利用し、木・茂み・岩を斜面の高さに合わせて配置した。
既存の地面・草・起伏はそのまま。通常の草原の生成設定は変更していない。

敵の燃焼候補は `AssetBurnPreview.cs`。購入素材の小さな炎を左右の足元に置き、煙と火の粉を抑えて顔・HPバー・陣営の輪を読めるようにする。
駒の子ノードとして配置し、粒子も駒のローカル座標で動かす。両候補で既存の燃焼時の立ち絵・熱表現を共通に保ち、炎本体を切り替える。
素材原本と共有マテリアルは変更せず、試着用インスタンスだけを調整する。
現時点では表示だけの試作であり、燃焼の量・残りターン・ダメージを新たに計算するものではない。

### 背景D：草原の完成イメージ（2026-10-10）

背景Cの方向性を踏まえ、`DemoApp/NatureMeadowPreview.cs` に独立した候補を追加した。初版Dでは購入素材の地面と草を使ったが、ユーザーから「Cのほうが草感があり、沢山の草が風に揺れる演出も分かりやすい」と評価されたため、地面・草・風をCと同じ構成へ戻した。

- 地形は既存の起伏を再利用。中央の戦闘領域を平らに、周囲を丘にする。
- 地面は既存の草原シェーダーを使用。Cと同じ細かな草地の質感を維持する。
- 草はCと同じ6,200株の細長い草をMultiMeshで配置し、同じ風のシェーダーで揺らす。中央は短く、周囲は長い設定をそのまま使用する。初版Dの購入草を点在させる処理は撤去した。
- 購入素材の木・茂み・岩に小さな白／黄の花を加え、左右の近景と奥の林で距離を分ける。
- 収録のcartoon環境にあるProceduralSkyを複製し、青空・地平線の色・霞・環境光を調整。空はグラデーション方式で、雲画像を追加したものではない。
- 購入原本・共有マテリアル・通常の草原の既定値は維持する。方向性は採用決定、本編への接続は未実施。

収録の環境プリセットは8種類（default / cartoon / sunset / night / atmospheric / cemetery / dune / alien）。確認範囲では専用の雲・HDRI・パノラマ画像はなく、今回の青空は収録設定を基に作れる範囲で構成した。

### 採用方針と空の残課題（2026-10-10）

調整後Dについて、ユーザーから「空が明るくなったのは良い」「空は課題として、この方向で採用するのは良い」と評価された。
草原の基本構成は、既存の起伏・地面・風に揺れる草と、購入素材の木・茂み・岩、および明るい空を組み合わせる。

雲は今後の検討項目。空用シェーダーで描く、雲を含む空画像を使う、雲の素材を重ねる、といった方法を候補とする。別の有償素材の購入が必須という意味ではない。現在の空を当面使用し、雲の見た目・動き・描画負荷は後の比較で判断する。
この記録時点では採用方針を確定した段階で、本編への接続や雲の追加は行っていない。敵の燃焼エフェクトは引き続き別の検討項目とする。

### 第4波・城塞への適用調査（2026-10-10）

購入済みNatureBlocks v1とEffectBlocks v4の実ファイル、および `DemoApp/FortressEnvironment3D.cs` を確認した。
第4波は `stageIndex == 3` で城塞を選択し、城壁・塔・門・石畳・旗・かがり火を個別に生成しているため、部分的な置換や装飾の追加が可能。

| 対象 | 購入済み素材の適用見込み |
|---|---|
| 城壁・塔・城門・石畳 | NatureBlocksに対応する建築一式は見当たらない。現状の形状を残して質感を調整するか、別の建築素材を検討する。自然地面のテクスチャは石積み・舗装の直接の代用品ではない。 |
| 壁際・城外の装飾 | NatureBlocksのivy・vines・草・低木・岩を追加できる。現役の守備隊の城なので、ツタや瓦礫は控えめにする案。 |
| 門前のかがり火 | 現在の自作の炎をEffectBlocksの `fire_light.tscn` に置き換える候補。煙・火の粉・光の強さを現場で調整する必要がある。 |
| 空・遠景 | 草原Dで調整した青空の設定を城塞にも使える。城壁の石の色との釣り合いは城塞の比較画面で確認する。 |

EffectBlocksには展示用の `source_files/meshes/props/wall.tres` と `FirePit.tres` も含まれる。壁メッシュをGodotで単体描画して確認したところ、崩れた低い石壁と瓦礫の形で、現状の城門・塔を含む城塞一式の代わりにはならない。廃墟・損傷箇所の小物としての候補に留める。画像は `.tmp/effectblocks-wall.png`、確認ログは `.tmp/inspect-effectblocks-wall.log`。

今回の結論は「購入済み素材で城塞の周辺・炎・空は改善できるが、建築全体の置換には不足」。次の比較案は既存の城塞を土台に、明るい空・少量の壁際の植生・購入素材のかがり火を加える形。本編の城塞は未変更で、組み合わせた表示と動作は未検証。

### ホタの5連撃：火球と爆炎の比較（2026-10-10）

ユーザーから、ホタの5連撃が光弾の連射に見えるため、ファイアーボールの連弾と爆炎の着弾へ変えたいとの要望。
対象は `FireLevelLabels.EmbersHit`（残り火）。本編と同じ `PlayFireAttack` の入口で旧演出Aと候補Bを切り替える比較を追加した。

- 候補Bの飛行はEffectBlocksの `fire_light.tscn` を調整した炎の塊。炎の方向を進行方向の後ろへ向けて尾を作り、従来の細い光の線を外す。
- 着弾は `explosions/explosion_light.tscn`。炎が外へ広がって暗くなり、煙と火の粉が残る。発光を抑え、白い閃光ではなく橙色の炎が見えるよう調整。
- 1件の攻撃につき1発。元の飛行時間0.11秒と命中通知を維持し、比較では同じ敵へ5発を連続再生する。ダメージ計算は変更しない。
- 一時停止中に命中待ちが進まないようにし、比較画面の切り替え・再再生では世代番号で旧攻撃を中断する。
- 候補は比較画面だけで有効。本編の既定は従来の演出で、採用後に接続する。購入素材は原本を変更せず、インスタンスの粒子設定だけ調整する。

起動は既存の `RunAssetPreview.ps1`。「表示」で「ホタの5連撃」を選び、効果ボタンでA/B、速度ボタンで1倍→2倍→0.25倍を切り替える。約5秒の再生時間ごとに反復するため、0.25倍では周期も長くなる。「もう一度再生」で即座に撃ち直せる。
自動確認は `res://AssetPreview.tscn -- --hota-capture`。画像は `.tmp/asset-preview-captures/hota-*.png`、ログは `.tmp/hota-preview-run.log`。5発の命中・一時停止・倍速・粒子の後片付け・途中切り替えを確認する。実台本での候補Bの再生はまだ未検証。
